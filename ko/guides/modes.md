# 하나의 저널. 네 가지 수집 모드. 여덟 가지 검증 수준.

Canonical page: https://phishdestroy.github.io/TgWitness/ko/guides/modes.html

모드, 시나리오 및 증거 수준

TgWitness 연결된 계정이 관찰한 내용을 기록합니다. 제3자는 독립적으로 신뢰할 수 있는 키를 기준으로 기록의 무결성을 검증할 수 있습니다.

[수집 모드](https://phishdestroy.github.io/TgWitness/ko/guides/modes.html#scope)[시나리오](https://phishdestroy.github.io/TgWitness/ko/guides/modes.html#scenarios)[증거 수준](https://phishdestroy.github.io/TgWitness/ko/guides/modes.html#levels)

3~5분 개요 · 가상의 예시 · 현재 구현 현황

1. **텔레그램**

   계정에서 확인 가능한 업데이트
2. **컬렉터**

   서로 연결된 레코드, 각각 서명됨
3. **검증자**

   신뢰할 수 있는 키 + 유지된 경계

`h₁ → h₂ → h₃ · Ed25519`무결성은 검증됩니다. 텔레그램의 출처와 메시지의 진실성은 별개의 문제입니다.

## 관찰 범위를 선택하십시오

세 가지 범위와 하나의 조사 사전 설정. 제외 항목 및 활성화된 소스 유형은 여전히 적용됩니다.

기본값**선택된 채팅**

기록

오직 수작업으로 선별된 출처만 사용합니다.

새로운 채팅

자동으로 추가되지 않습니다.

다음 중 선택하십시오

알려진 채널 또는 그룹 집합. 고정된 채팅 수용 인원은 명시되지 않았습니다.

**다음은 수행하지 않습니다** 이 도구는 다른 채팅을 탐지하지 않으며, 이전 기록을 소급하여 채우지도 않습니다.

계정 폴더**텔레그램 폴더**

기록

폴더 포함 항목 및 카테고리, 구성 시 제외 항목 및 보관된 채팅은 제외됩니다.

새로운 채팅

활성 채팅 일치; 1시간 이내의 폴더 변경 사항.

다음 중 선택하십시오

분석가는 이미 사건 폴더를 관리하고 있습니다. 전용 계정에서 수집 사실을 확인하십시오.

**다음은 수행하지 않습니다** 이 문서는 폴더의 변경되는 muted/read 조건은 적용되지 않습니다.

범위 확인**전체 계정**

기록

선택된 유형 내의 계정에서 볼 수 있는 채팅(비공개 대화 및 봇 포함).

새로운 채팅

첫 번째 업데이트가 제공되면 추가될 예정입니다.

다음 중 선택하십시오

사건에 참여하는 계정을 포함한 전용 관찰 계정.

**다음은 수행하지 않습니다** 이 도구는 자동으로 채팅에 참여하거나 소스 접근을 우회하지 않습니다.

전체 계정 사전 설정**조사 모드**

기록

모든 소스 유형, 자체 작업, 소스 프로필 및 새로 발견된 소스의 최근 200개 가시 메시지.

새로운 채팅

새로운 채팅이나 봇은 프로필과 기록 스냅샷을 부여받습니다.

다음 중 선택하십시오

패널을 통해 팀에 가입하거나 봇과 상호작용하십시오. 사전 설정을 검토하고 저장하십시오.

**다음은 수행하지 않습니다** 이 도구는 기존의 모든 채팅을 스냅샷으로 저장하지 않으며, 다른 클라이언트에서 누른 콜백을 관찰하지도 않습니다.

이 카드들은 실시간 수집기 제어 기능이 아닌 로컬 비교용입니다. 계정에 어떠한 변경도 가하지 않습니다.

**다음은 수행하지 않습니다** 어떤 모드에서도 비밀 채팅을 읽거나, 프로세스가 중지된 상태에서 기록하거나, 스스로 소스에 참여하거나, 요청된 범위를 넘어선 이전 기록을 검색해서는 안 됩니다. snapshot/export.

## 보유한 권한만 사용하십시오

각 계정은 고유한 작업 공간, 저널, 서명 키, 경로 및 큐를 갖습니다.

### 전화번호 + 코드

이 기능을 활성화할 때는 2FA 를 입력하십시오.

### QR code

인증된 기기에서 스캔하십시오; 2FA 여전히 필요할 수 있습니다.

### Telethon .session

계정의 세션 파일을 가져옵니다.

### Pyrogram .session

지원되는 Pyrogram 세션 형식을 가져오십시오.

### TData ZIP

지원되는 데스크톱 계정은 하나이며, 설정된 경우 로컬 비밀번호가 적용됩니다.

### StringSession text

다음 내용을 붙여넣으십시오. Telethon StringSession.

### .session + .json

세션과 이에 상응하는 관련 메타데이터를 선택하십시오.

### 인증 키 HEX + DC ID

계정 인증 정보를 데이터 센터 식별자와 함께 가져오십시오.

**API pair**

사용자 정의 API 페어는 선택 사항입니다. 페어가 없는 경우, TgWitness 공용 페어 풀(공식 텔레그램 데스크톱의 페어 포함)을 사용합니다.

`Direct · SOCKS5 · HTTP CONNECT · MTProxy`MTProxy 는 실험적 기능이며, 내장된 공개 MTProxy 목록을 사용할 수 있습니다. 프록시 경로가 실패하더라도 직접 연결로 대체되지 않습니다.

한 대의 컴퓨터에 있는 두 개의 작업 공간은 두 명의 독립적인 증인이 아닙니다.

**다음은 수행하지 않습니다** import는 텔레그램 인증 절차를 우회하지 않으며, 2FA 지원되지 않는 세션 형식도 우회하지 않습니다. 계정은 여전히 애플리케이션 프로세스를 공유합니다.

## 복구 및 연속성

누락된 부분은 숨기지 않고 표시합니다.

### 저장된 위치에서 계속하기

## 7단계. 각기 다른 질문들.

각 메커니즘은 한정된 질문에 답합니다. 외부 서비스는 별도로 구성하고, 해당 서비스의 신뢰 앵커는 수집기 외부에 유지하십시오.

1. ### 기록

   SHA-256 체인 + Ed25519 이벤트당; 첫 번째 previous_hash 64개의 0으로 구성됩니다.

   **제3자 검증** 고정된 수집기 키 하에서의 순서 지정 및 서명.

   **다음은 수행하지 않습니다** 이는 텔레그램의 출처나 완전성을 입증하지 않습니다.

   **검증 명령어**

   ```
   python -m tgwitness.verify evidence.zip --fingerprint TRUSTED_SHA256
   ```
2. ### 컨테이너

   manifest.json 파일 해시를 나열하며; manifest.sig 이에 서명합니다. media.saved 첨부 파일 바이트를 이벤트에 바인딩합니다.

   **제3자 검증** 제공된 파일들은 서명된 매니페스트 및 미디어 수령증과 일치합니다.

   **다음은 수행하지 않습니다** 별도로 다운로드한 CSV, HTML 파일이나 스크린샷에는 서명하지 않습니다.

   **검증 명령어**

   ```
   python -m tgwitness.verify evidence.zip --fingerprint TRUSTED_SHA256
   ```
3. ### 유지된 경계

   시작 시 체크포인트를 생성하고, 기본적으로 5분마다 체크포인트를 생성하며, 질서 있게 종료하십시오. 사본을 다른 곳에 보관하십시오.

   **제3자 검증** 후속 내보내기 결과는 이전에 유지된 길이 및 헤더와 일치하며, 롤백 여부를 감지할 수 있습니다.

   **다음은 수행하지 않습니다** 저널과 모든 보존된 체크포인트가 모두 대체된 경우는 감지하지 않습니다.

   **검증 명령어**

   ```
   python -m tgwitness.verify evidence.zip --fingerprint TRUSTED_SHA256 --checkpoint checkpoint.json
   ```
4. ### 외부 시간

   증거 모드는 체크포인트를 전송합니다 SHA-256 를 RFC 3161 당국(FreeTSA, DigiCert) 및 OpenTimestamps 캘린더로 전송합니다.

   **제3자 검증** 검증된 TSA 응답은 해당 바이트의 생성 시점을 기록하며, 확인된 OpenTimestamps 증명은 해당 바이트를 비트코인에 고정시킵니다.

   **다음은 수행하지 않습니다** 이 문서는 미리 준비된 요청이나 처리 대기 중인 캘린더 수신 내역을 확정된 타임스탬프로 간주하지 않습니다.

   **검증 명령어**

   ```
   python -m tgwitness.verify evidence.zip --fingerprint TRUSTED_SHA256 --tsa-ca trusted-ca.pem
   ots upgrade checkpoint.ots
   ots verify checkpoint.ots
   ```
5. ### 독립적인 위트니스

   호스트, 범위 지정된 읽기 전용 엔드포인트, 새로운 챌린지, 그리고 자체 key/journal 및 TGW1 채널 게시물을 구분하십시오.

   **제3자 검증** 이전에 수락된 헤드; 상태: ok, key_changed, 롤백, 포크, 무효 및 no_response.

   **다음은 수행하지 않습니다** 이는 하나의 수집기 호스트에 있는 두 개의 작업 공간을 독립적인 증인으로 만들지 않습니다.

   **검증 명령어**

   ```
   python -m tgwitness.verify evidence.zip --fingerprint TRUSTED_SHA256 --witness witness.zip --witness-fingerprint WITNESS_SHA256 --channel result.json
   ```
6. ### 오프사이트 복제본

   S3- 호환되는 복사본은 AES-256-GCM; Object Lock 로 암호화된 호환 가능한 사본.

   **제3자 검증** 복원 기능은 저널, 체크포인트 및 보존된 미디어의 검증이 성공한 후에만 파일을 게시합니다.

   **다음은 수행하지 않습니다** 내보낸 키 없이는 복원하지 않으며, 저장소 응답을 확인하지 않고는 보존을 가정하지 않습니다.

   **검증 명령어**

   ```
   python -m tgwitness.replica restore --key-file KEY.json --out EMPTY_DIR
   ```
7. ### 출처 추적 실행

   서명된 실행 영수증: 소스 해시, 종속성 버전 및 프로세스 컨텍스트. 자체 보고.

   **제3자 검증** 서명 수집기가 자체 실행에 대해 보고한 내용.

   **다음은 수행하지 않습니다** 이 문서는 독립적인 프로세스 인증을 제공하지 않으며, 기록 전의 보안 침해 가능성을 배제하지도 않습니다.

   **검증 명령어**

   ```
   python -m tgwitness.verify evidence.zip --fingerprint TRUSTED_SHA256
   ```

### 레코드 2를 변경해 보십시오

다음 레코드는 이전에 저장된 링크를 유지합니다. 텍스트를 변경하면 레코드 2의 계산된 해시가 변경됩니다.

기록 2의 본문

기록 1`h1`64개의 0으로 시작합니다.

기록 2`h2`저장된 내용을 포함합니다. h1

기록 3`h3`저장된 내용을 포함합니다. h2

정적 예시: h2 “11:00에 만나자”를 다룹니다. 해당 텍스트를 변경하면 h2; 기록 3은 여전히 저장된 내용을 참조합니다. h2.

**전체 다이제스트를 확인하십시오**

저장된 기록 2 해시

`SHA-256(e₂)`

재계산된 레코드 2의 해시

`SHA-256(e₂)`

이 예제는 서명이 아닌 해시를 계산합니다. 실제 검증기는 모든 서명과 링크를 신뢰할 수 있는 키와 대조하여 확인합니다.

## 증거를 통해 경로를 선택하십시오

가상의 상황. 관련 사건이 발생하기 전에 수집을 시작하고, 콘텐츠와 함께 경계와 공백도 그대로 보존하십시오.

### 채널의 결제 세부 정보가 변경됩니다

모드 → 이벤트

선택한 채팅 → 메시지, 수정, 삭제.

출력

해시 값을 기준으로 게시물 버전 및 첨부 파일을 관찰합니다.

검증

서명됨 ZIP + 보존된 체크포인트 + 검증된 TSA 응답.

**다음은 수행하지 않습니다** 한 번도 캡처된 적이 없는 원본은 복구할 수 없습니다.

### 사건 발생 후 메시지는 사라집니다

모드 → 이벤트

폴더 또는 전체 계정 → 모든 이벤트 카테고리.

출력

저장된 원본, 삭제 알림 및 누락된 부분.

검증

서명됨 ZIP + 독립적인 위트니스 저널.

**다음은 수행하지 않습니다** 행위자가 명시되지 않은 알림의 경우, 이를 통해 삭제자를 식별할 수 없습니다.

### 쇼핑 봇 조사하기

조사 사전 설정 → 버튼, 링크 미리보기 및 명시적인 봇 시작.

출력

서명된 상호작용 수신증, 반환된 콜백 및 저장된 프로필.

검증

서명됨 ZIP; 모든 문서를 다음을 기준으로 검증하십시오. ZIP.

**다음은 수행하지 않습니다** 이 도구는 봇 웹 앱을 열거나, 결제를 수행하거나, 다른 클라이언트의 콜백을 기록하지 않습니다.

검증

도큐멘트 JSON 서명된 내용과 대조하여 확인됨 ZIP.

## 증거와 함께 한계를 유지하십시오

검증은 그 범위가 명확하게 유지될 때 유용합니다.

- 비밀 채팅은 사용할 수 없습니다.
- 프로세스가 중지된 동안에는 아무것도 기록되지 않으며, 복구 기능에는 한계가 있습니다.
- 검증된 기록이 그 내용이 사실이라는 증거는 아닙니다.
- 키를 보유한 운영자는 임의의 콘텐츠에 서명할 수 있습니다. 독립적인 증인과 타임스탬프는 나중에 내용을 대체하는 것을 제한할 뿐, 초기 캡처 시 부정행위를 방지하지는 않습니다.
- 주 계정이 아닌 전용 계정을 사용하십시오.
- 텔레그램은 요청량에 따라 계정을 제한할 수 있습니다.

**다음은 수행하지 않습니다** 어떤 모드나 증거 수준도 법적 증거 능력, 텔레그램의 완전한 전달, 또는 실제 신원을 입증하지 않습니다.
