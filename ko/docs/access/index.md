# 사례 공유하기

Canonical page: https://phishdestroy.github.io/TgWitness/ko/docs/access/

누군가에게 필요한 사례를 공유하세요. 나머지는 직접 관리하세요.

01**증거 선택**

계정 전체의 작업 공간 또는 개별 기록된 채팅을 선택하세요.

02**작업 선택**

사용자에게 필요한 조회, 내보내기 또는 특정 운영 권한을 부여할 수 있습니다.

03**한도 설정**

만료 기간, 세션 제한 및 선택적 IP 제한이 적용된 개인 토큰을 발급합니다.

수집 범위에 따라 기록되는 내용이 결정됩니다. 접근 범위에 따라 사용자가 볼 수 있는 내용과 수행할 수 있는 작업이 결정됩니다.

## 사용자 접근 권한 부여

1. 관리자로 로그인한 후 **‘Access’를** 열어주세요.
2. 접근 권한을 지정하고 작업 공간 및 채팅을 선택하십시오.
3. 검토자를 위해 **‘보기’ 기능을** 유지하십시오. 검토자가 기록을 다운로드해야 하는 경우 **‘내보내기’ 기능을** 추가하십시오.
4. 한도를 설정한 후 **‘액세스 생성’을** 누르세요.
5. 표시된 토큰을 한 번 복사하십시오. 패널 주소와 함께 비공개로 전송하십시오.
6. 전달하기 전에 별도의 브라우저 세션에서 허용된 보기를 확인하십시오.

## 그들이 수행해야 할 업무부터 시작하세요

| 인물 | 접근 | 결과 |
| --- | --- | --- |
| 검토자 | 선택된 채팅; 보기 전용 | 수집된 내용을 변경하지 않고 캡처된 대화를 읽어보세요. |
| 분석가 | 선택한 채팅: 보기 및 내보내기 | 사건 조사에 필요한 기록을 검토하고 다운로드하십시오. |
| 운영자 | 선별된 전체 작업 공간; 출처 및 수집 | 관찰된 내용을 관리하고 수집기를 시작하거나 중지하세요. |

이는 사용자가 선택하는 구성 사항이며, 고정된 역할이 아닙니다. 계정 전체 설정 및 전체 기록부 내보내기 기능은 다른 권한이 활성화되어 있더라도 채팅 제한 액세스 범위에서는 계속 비활성화된 상태로 유지됩니다. 전체 워크스페이스 액세스 권한에는 향후 생성될 계정도 포함됩니다.

## 언제든지 마음을 바꿀 수 있습니다

접근 권한을 편집하여 후속 요청에서 수행할 수 있는 작업을 변경할 수 있습니다. 하나의 세션을 종료하거나 전체 접근 권한을 취소하여 모든 세션을 종료할 수 있습니다. 이미 다운로드된 파일은 되돌릴 수 없습니다. 패널 세션을 종료해도 수집은 중단되지 않습니다.

**세션 및 IP 제한**

동시 세션 및 성공적인 로그인 횟수를 제한하고, 절대 종료일을 설정하며, IP 주소나 서브넷을 허용하거나, 첫 로그인 주소로 접근을 제한할 수 있습니다. 세션 만료는 비활성 상태를 기준으로 하며, 열린 패널의 폴링은 활동으로 간주됩니다. 프록시나 터널을 통해 애플리케이션이 실행될 때 표시되는 클라이언트 주소를 확인하십시오.

**마스터 키 및 활동 로그**

관리자는 메인 패널 토큰을 보관합니다. 부여된 접근 권한으로는 타인의 접근 권한을 관리하거나 관리자 콘솔을 열 수 없습니다. 콘솔에는 워크스페이스 전반의 현재 프로세스 활동이 표시되며, 서명된 접근 기록은 토큰 없이도 권한 부여 및 세션 이벤트를 보관합니다. 워크스페이스는 호스트 프로세스를 공유하며, 서버 관리자로부터 데이터를 격리하지 않습니다.

7가지 권한, 세션 규칙 및 관리자 경계에 대한 [전체 권한 참조](https://phishdestroy.github.io/TgWitness/ko/docs/reference/access/)를 사용하십시오.
