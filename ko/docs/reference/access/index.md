# 접근 및 권한

Canonical page: https://phishdestroy.github.io/TgWitness/ko/docs/reference/access/

계정 및 채팅에 대한 접근 권한을 제한하고, 권한을 선택하며, 세션 및 IP 주소를 제한하고, 접근 권한을 철회할 수 있습니다.

검토자에게는 하나의 채팅에 대한 접근 권한을, 분석가에게는 사건 내역 내보내기 권한을, 운영자에게는 선택된 계정에 대한 관리 권한을 부여할 수 있습니다. 각 사용자는 고유한 토큰을 부여받습니다. 메인 패널 토큰은 관리자가 보유합니다.

[계정 설정](https://phishdestroy.github.io/TgWitness/ko/docs/reference/accounts/) · [연결 경로](https://phishdestroy.github.io/TgWitness/ko/docs/reference/connection/) · [보안 모델](https://phishdestroy.github.io/TgWitness/ko/docs/reference/security/)

## 두 가지 범위, 두 가지 서로 다른 업무

**수집 범위에** 따라 계정이 기록하는 대상(선택한 채팅, 텔레그램 폴더 또는 전체 계정)이 결정됩니다. **접근 범위에** 따라 다른 사람이 기록된 계정 및 채팅 중 어떤 것을 보고 사용할 수 있는지가 결정됩니다. 접근 권한을 부여한다고 해서 텔레그램 채팅에 참여하거나, 수집이 시작되거나, 텔레그램 계정 권한이 부여되는 것은 아닙니다.

접근 권한을 통해 선택한 워크스페이스, 그 안의 특정 채팅, 또는 모든 워크스페이스를 열 수 있습니다. **나중에 추가된 워크스페이스를 포함한 모든 워크스페이스는** 향후 계정도 포함합니다. 특정 사건에 대한 접근을 해당 워크스페이스로만 제한해야 할 경우, 워크스페이스를 명시적으로 선택하십시오.

## 사용자 접근 권한 부여

1. 주 관리자로 로그인한 후 **‘Access’를** 열어주세요.
2. **'사용자 접근 권한 부여**' 항목에서 로그에서 쉽게 알아볼 수 있는 이름을 입력하세요.
3. 작업 공간을 선택하고, 필요한 경우 개별 채팅방을 선택하십시오.
4. 이 사람이 수행할 수 있는 작업을 선택하십시오. **‘보기’는** 항상 포함됩니다.
5. 필요에 따라 만료 기간, 로그인/세션 제한 및 허용된 주소를 설정하십시오.
6. **'생성'을** 클릭하여 **액세스 권한을 생성하세요**. 토큰을 지금 복사하세요: 토큰은 한 번만 표시됩니다.
7. 패널 주소와 토큰을 비공개로 전송하십시오. 수신자는 일반 로그인 페이지에서 해당 토큰을 입력하면 되며, 귀하의 메인 패널 토큰이나 텔레그램 세션은 필요하지 않습니다.

발급된 토큰이 포함된 패널을 별도의 브라우저 세션에서 열고, 전달하기 전에 표시된 채팅과 허용된 작업을 확인하십시오.

## 권한 선택

| 사용 권한 | 이 도구의 기능 |
| --- | --- |
| `view` | 허용된 채팅, 캡처된 메시지, 프로필, 파일 및 필터링된 기록부를 확인할 수 있습니다. 항상 포함되어 있습니다. |
| `export` | 허용된 채팅 기록 및 자료 모음을 내보낼 수 있습니다. 전체 작업 공간의 증거 자료를 내보내려면 해당 작업 공간 전체에 대한 접근 권한이 필요합니다. |
| `sources` | 소스, 스냅샷 및 프로필 캡처를 관리합니다. 채팅 제한 액세스는 허용된 채팅에서만 작동하며, 계정 전체의 소스 검색 및 범위 설정은 비활성화된 상태로 유지됩니다. |
| `collect` | 수집기를 시작하거나 중지합니다. 수집 작업이 계정에 영향을 미치므로 전체 작업 공간에 대한 접근 권한이 필요합니다. |
| `interact` | 접근 권한 범위 내에서 지원되는 텔레그램 상호작용을 수행하십시오. 채팅 제한 접근 권한의 경우 계정 전체 링크 미리보기를 사용할 수 없습니다. |
| `settings` | 수집 설정, 타임스탬프, 알림, 외부 백업 및 매개변수를 변경할 수 있습니다. 전체 워크스페이스에 대한 접근 권한이 필요합니다. |
| `account` | 텔레그램에 로그인하거나 로그아웃하고 연결 경로를 관리할 수 있습니다. 전체 작업 공간에 대한 접근 권한이 필요합니다. |

권한과 적용 범위는 함께 확인됩니다. 특정 권한을 선택한다고 해서 다른 채팅이 열리거나, 채팅 제한형 액세스 권한에 대해 워크스페이스 전체에 적용되는 작업이 활성화되지는 않습니다. 병렬 내보내기의 경우, 선택한 모든 계정에서 내보내려는 채팅에 대한 접근 권한이 포함되어야 합니다. 부여된 접근 권한으로는 새로운 접근 권한을 생성하거나, 타인의 세션을 관리하거나, 관리자 콘솔을 열 수 없습니다.

### 세 가지 유용한 설정 방법

| 인물 | 범위 | 권한 |
| --- | --- | --- |
| 검토자 | 한 사례의 기록된 채팅 내용 | `view` |
| 업무 인계를 준비 중인 분석가 | 조사 및 내보내기 대상 채팅 | `view`, `export`; 텔레그램을 통해 조치를 취해야 하는 경우에만 `interact`를 추가하십시오. |
| 수집 운영자 | 선별된 전체 작업 공간 | `view`, `sources`, `collect`; 필요한 경우에만 `settings` 또는 `account`를 추가하십시오. |

이것들은 고정된 역할이 아니라, 권한 선택 상자를 통해 구성할 수 있는 예시입니다.

## 제한 사항 및 세션

| 설정 | 작동 원리 |
| --- | --- |
| 병행 세션 | 동시 세션 수를 1~100개로 제한합니다. 한도에 도달하면 다음 로그인을 거부하거나 가장 오래된 세션을 종료합니다. |
| 로그인 허용 | 세션 시작을 위한 토큰의 사용 횟수를 제한합니다. 허용된 마지막 로그인이 사용되었다고 해서 기존 세션이 종료되지는 않습니다. |
| 유효 기간: | 접근 권한에 대한 절대 만료일이 적용됩니다. 만료된 접근 권한으로는 로그인하거나 요청을 계속할 수 없습니다. |
| 활동이 없는 시간 | 세션 비활성 타임아웃은 5분에서 30일까지 설정 가능합니다. 요청이 성공하면 타임아웃 시간이 연장되며, 열려 있는 패널은 폴링을 통해 활성 상태를 유지할 수 있습니다. |
| 허용된 주소 | 특정 IP 주소 또는 CIDR 서브넷을 허용합니다. 첫 로그인 바인딩이 활성화되지 않은 경우, 빈 상태로 두면 모든 주소를 허용합니다. |
| 첫 로그인 시 연결 | 첫 번째 성공적인 로그인 시 해당 접속에 허용된 주소가 확정됩니다. |

IP는 애플리케이션이 인식하는 클라이언트 주소입니다. 리버스 프록시나 터널을 사용하는 경우, IP 규칙을 적용하기 전에 **‘열린**세션’에 표시된 주소를 확인하십시오. 그렇지 않으면 여러 사용자가 프록시의 주소를 공유하는 것처럼 보일 수 있습니다.

## 변경 또는 접근 권한 철회

**'액세스(Accesses)**' 항목에서 항목을 편집하여 범위, 권한 또는 제한 사항을 변경할 수 있습니다. 범위 및 권한 변경 사항은 후속 요청 시 확인되며, 여기에는 이미 열려 있는 세션에서 발생하는 요청도 포함됩니다. 액세스 권한을 취소하면 해당 세션이 종료되고 발급된 토큰은 더 이상 사용할 수 없게 됩니다. 또한 관리자는 **열려 있는 세션에** 대해 전체 액세스 권한을 취소하지 않고도 개별 세션을 종료할 수 있습니다.

권한 취소 기능으로는 사용자가 이미 다운로드한 파일을 복구할 수 없습니다. 로그아웃, 패널 잠금 또는 세션 종료는 실행 중인 수집기를 중지시키지 않습니다.

## 관리자가 확인할 수 있는 내용

**시작 시점부터 기록된** 로그에는 모든 워크스페이스의 프로세스 로그와 저널 활동(로그인, 거부, 경로 변경 및 운영자 조치 등)이 결합되어 있습니다. 이는 현재 프로세스에 대한 인메모리 콘솔이며, 모든 메시지의 영구적인 사본은 아닙니다. 빈번하게 발생하는 메시지 이벤트는 콘솔을 채우지 않고 저널에 남게 됩니다.

접근 권한의 발급, 변경 및 취소, 세션 시작 또는 종료 시에도 서명된 `access.*` 저널 기록이 생성됩니다. 토큰은 해당 기록에 포함되지 않습니다. 발급된 토큰과 세션 인증 정보는 암호화된 볼트에 해시 형태로 보관됩니다.

****주 관리자 및 신뢰 경계**** 메인 패널 토큰은 제한 없이 사용됩니다. 이 토큰을 사용하여 브라우저에 로그인하면 관리자가 설정한 세션 제한이 적용되는 세션이 생성됩니다. 메인 토큰을 직접 전송하는 스크립트는 전체 액세스 권한을 유지하며 브라우저 세션으로 집계되지 않습니다. 이는 단일 설치 환경 내의 애플리케이션 수준 접근 제어입니다. 모든 작업 공간은 서버 프로세스를 공유하며, 이는 호스트 관리자로부터의 격리를 의미하지 않습니다. 메인 토큰, 텔레그램 세션, 서명 키 및 데이터 디렉터리는 비공개로 유지하십시오. 위트니스 토큰은 패널 접근 토큰이 아닌 별도의 체크포인트/정상 작동 확인 자격 증명입니다.
