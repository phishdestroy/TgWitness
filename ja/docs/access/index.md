# 事例を共有する

Canonical page: https://phishdestroy.github.io/TgWitness/ja/docs/access/

必要なケースを共有し、それ以外の情報は管理下に置いておきましょう。

01**証拠を選択してください**

ワークスペース全体、または個別のチャット。

02**操作を選択してください**

閲覧、エクスポート、または必要な操作だけ。

03**制限を設定する**

必要に応じて有効期限、セッション制限、IP ルールを付けた個人用トークン。

収集範囲によって、何が記録されるかが決まります。アクセス範囲によって、ユーザーが何を閲覧・操作できるかが決まります。

## アクセス権を付与する

1. 管理者として**アクセス**を開きます。
2. 名前を付け、ワークスペースとチャットを選びます。
3. レビュー担当者には**表示**だけで十分です。ダウンロードが必要なら**エクスポート**を加えます。
4. 制限を設定し、「**アクセスを作成」**をクリックしてください。
5. トークンをコピーし（表示は 1 回だけ）、パネルのアドレスと一緒に非公開で送ります。
6. まず別のブラウザーセッションで、相手に何が見えるかを確認します。

## まず、彼らが遂行すべき業務から始めましょう

| 人物 | アクセス | 結果 |
| --- | --- | --- |
| レビュー担当者 | 選択されたチャット；閲覧専用 | チャットを閲覧するだけで、何も変更できません。 |
| アナリスト | 選択したチャット：表示およびエクスポート | ケースに必要なものを閲覧し、ダウンロードします。 |
| オペレーター | 選択されたワークスペース全体、ソースおよび収集内容 | 観察対象を決め、コレクターを開始・停止します。 |

これは例にすぎず、固定の役割ではありません。チャットに限ったアクセスには、アカウント設定やジャーナル全体のエクスポートは付きません。全ワークスペースへのアクセスには、後から追加したアカウントも含まれます。

## いつでも考えを変えることができます

アクセスはいつでも編集でき、次のリクエストから適用されます。1 つのセッションを終了することも、すべて取り消すこともできます。ダウンロード済みのファイルは取り戻せません。収集は続きます。

**セッションおよびIPアドレスの制限**

同時セッション数とログイン数の制限、終了日の設定、IP やサブネットの許可、最初のログイン IP への固定ができます。有効期限は非アクティブな時間で数え、開いているパネルはアクティブとみなされます。プロキシの背後では、アプリがどのクライアント IP を見ているかを確認してください。

**メインキーとアクティビティログ**

メインのトークンは管理者が持ちます。発行したアクセスでは、他の人のアクセスを管理したり管理コンソールを開いたりできません。アクセスの変更とセッションは、トークンを含めずにジャーナルへ署名付きで記録されます。サーバーの管理者は引き続きすべてを見られます。

7 つの権限とセッションのルールすべて：[アクセスのリファレンス](https://phishdestroy.github.io/TgWitness/ja/docs/reference/access/)。
