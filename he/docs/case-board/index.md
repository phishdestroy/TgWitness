# הקימו לוח תיקים

Canonical page: https://phishdestroy.github.io/TgWitness/he/docs/case-board/

הפכו את תצפיות ה-Telegram השמורות לתיק שהצוות שלכם יוכל לסקור יחד.

Case Board שומר סימניות, הדגשות של טקסט מדויק, קטעים שנשמרו ודיונים לצד הפניות המקור שלהם. אוסף מעניק לתיק מבנה עבודה; גרסאות חתומות משמרות את אופן פיתוחו על ידי הצוות.

## מהודעה לכרטיס תיק

1. פתח את **"חקירה" → "לוח התיק"** במצב "סטנדרטי" או "מומחה". צור אוסף עבור התיק ובחר את היקף הצ'אט שלו.
2. ב-**Journal** או בצ'אט שנשמר, בחרו באפשרות **"To board"**, או סמנו את הרשומה ולחצו על **B**. הכרטיס יועבר לתיבת הדואר הנכנס; תנו לו כותרת מתאימה והעבירו אותו לאוסף שלכם.
3. בחר קטע מתוך הודעת צ'אט שנשמרה ובחר **'הדגש' → 'לוח'** כדי לשמור את הציטוט המדויק ואת גרסת ההודעה. הוסף הערה המסבירה מדוע הדבר חשוב.
4. יש לדון בכרטיס, להקצות לו סטטוס בדיקה ולחזור להקשר המקורי שלו בכל פעם שיש צורך לבדוק טענה. יש להשתמש **ב-Presentation** כדי לעבור על האוסף יחד עם עמיתים.

### יש לעקוב אחר קישור תשלום אחד ששונה

דוגמה סינתטית · איור מקומי

1. **לכידה.** פתח את התצפית השמורה מס' 142 ואת גרסת ההודעה שלה.
2. **סימניה.** שמור את הציטוט, הפניה למקור והשאלה שלך על כרטיס.
3. **בדיקה.** הוסף הערה של הצוות והעבר את הכרטיס ל"בדיקה".
4. **הצג.** עבר על תהליך האיסוף ופתח את הקשר של המקור המצוטט.

#### תצפית שמורה מס' 142

"השתמש בקישור התשלום החדש."

צ'אט תפעולי · הודעה 38 · נצפה ב-09:12 UTC

#### כרטיס: יעד שונה

> יש להשתמש בקישור התשלום החדש.

שאלה: איזה יעד הופיע בגרסה הקודמת?

#### בדיקת צוות

אנליסט: השווה לתצפית מס' 101.

סטטוס: סקירה · הגרסה הנוכחית נשמרה

#### הקשר המקור

כרטיס → גרסה שמורה → תצפית קודמת

ההערות ותצפיות ה-Telegram נותרות ניתנות לזיהוי בנפרד.

## שמור טווח שימושי פעם אחת

לחצו על Shift תוך לחיצה על שני רשומות בצ'אט אחד כדי **לבצע** **"חיתוך" ביניהן**, בחרו **באפשרות** **"חיתוך לפי זמן**", או שמרו את מסנני ה-Journal הנוכחיים. בדקו את מספר הרשומות לפני השמירה. פתחו מחדש את החיתוך כדי להחיל את השאילתה שנשמרה; האפשרות **"הצג רשומות שנוספו מאז הסימניה"** חושפת תוספות מאוחרות יותר.

"פרוסת זמן" עוקבת אחר זמן התצפית של האספן. "פרוסת מזהה הודעה" יכולה לעקוב אחר ההודעות שנבחרו ככל שמתקבלים שינויים מאוחרים יותר. "גבול היצירה" השמור מאפשר למקבל להשוות את הבחירה המקורית למצב המאוחר יותר שלה.

## הקצו לכל עמית את התפקיד המתאים

**הבוחן** קורא את לוח המקרים; **האנליסט** מוסיף כרטיסים והערות; **המפעיל** מנהל גם את האיסוף ואת החלטות הבדיקה. הרשאות סביבת העבודה והצ'אט חלות על כרטיסים, הקשר המקור ודיונים. יש להשתמש בהרשאות גישה שמותיות לצורך ייחוס ברור.

## הפוך את העבודה לתוצר סופי

יש לייצא קטע כקובץ JSON חתום, או להשתמש ב-CSV עבור גיליון אלקטרוני. הגדרות הדוח יכולות לכלול סימניות וקטעים, עם הערות צוות כאשר נבחר. יש לבחור תוכן זה ב[-Report Studio](https://phishdestroy.github.io/TgWitness/he/docs/reports/); קטע שנשמר אינו מגדיר דוח באופן אוטומטי. עבור נמען מוגבל, יש להשתמש [בבקרי המסירה](https://phishdestroy.github.io/TgWitness/he/docs/handover/) הנפרדים.

יש לקרוא את [המדריך של Case Board](https://phishdestroy.github.io/TgWitness/he/docs/reference/case-board/) בנוגע לגרסאות חתומות, התאמת ציטוטים מדויקת, אימות בחירות והרשאות.
