# Управління групою облікових записів

Canonical page: https://phishdestroy.github.io/TgWitness/uk/docs/groups/

Керуйте декількома обліковими записами для збору даних одночасно, зберігаючи при цьому окремі записи та ідентифікаційні дані для підписання для кожного облікового запису.

Група облікових записів об’єднує стан з’єднання, елементи керування спостереженням, спільні налаштування та експорт у єдине робоче вікно. Це корисно, коли кілька облікових записів використовуються в рамках одного розслідування або потребують узгоджених робочих налаштувань.

## Відкрити огляд групи

У розділі **«Акаунти**» відкрийте групу. Для кожного акаунта відображається стан спостереження, маршрут з’єднання, останнє виміряне затримка маршруту під час успішної перевірки та останнє збережене повідомлення. Посилання **«Потребує уваги»** вказують на акаунти, що потребують роботи; **кнопка «Виправити»** відкриває відповідну робочу область та панель керування.

**Функції «Запустити все»** та **«Призупинити все»** діють на відповідні облікові записи після підтвердження. **Групові налаштування** дозволяють застосовувати вибрані параметри до всіх облікових записів; облікові записи з власними значеннями зберігають їх, доки ви не вирішите їх замінити.

### Переглянути зміну маршруту в групі

Синтетичний приклад · ілюстративні перевірки та результати

1. **Виберіть.** Оберіть групу та перегляньте, які облікові записи зазнають змін.
2. **Підготуйте текст.** Зберігайте окремий маршрут для кожного облікового запису, коли це необхідно.
3. **Перевірте.** Протестуйте запропоноване з’єднання та проаналізуйте отримані результати.
4. **Подайте заявку.** Перед збереженням перевірте текст ще раз і перегляньте результат для кожного облікового запису.

#### Команда, що веде справу

Колектор каналів · Колектор груп · Довідковий обліковий запис

3 окремі робочі простори

#### Переглянутий вибір

2 акаунти дотримуються запропонованого підходу.

Довідковий обліковий запис має власний маршрут.

#### Перевірка підготовки

Колектор каналів: час передачі даних у Telegram — 84 мс

Груповий колектор: час передачі даних Telegram — 91 мс

Ці цифри є вигаданими показниками, наведеними для прикладу.

#### Результати застосування

Колектор каналів: маршрут збережено, спостереження відновлено.

Груповий колектор: повторна перевірка завершилася невдало, відновлено попередні налаштування.

Довідковий обліковий запис: збережено власний маршрут.

## Змінити маршрут, додавши етап перевірки

1. Виберіть **«Змінити маршрут групи**», а потім оберіть тип з’єднання та налаштування.
2. Виберіть **«Перегляд вибору**». Перегляньте перелік облікових записів та їхні індивідуальні налаштування маршрутів.
3. Виберіть **«Підготувати та перевірити**». Під час перевірки використовується новий канал передачі даних Telegram; підтримувані HTTP-маршрути також повідомляють про перевірку виходу через HTTPS.
4. Виберіть **«Застосувати перевірене з’єднання»** та перевірте результати для кожного облікового запису. Попередньо запущене спостереження поновлюється там, де додаток працює успішно; неактивні облікові записи залишаються неактивними.

Затримка описує виміряний час встановлення з’єднання з Telegram. Перевірка вихідної IP-адреси описує цей маршрут на момент запису перевірки. Авторизація облікового запису та стан спостереження мають власні показники; зміна групи може мати різні наслідки для кожного облікового запису.

## Використовуйте перекривний доступ

**У розділі «Чати, які бачать кілька облікових записів»** відображаються спільні джерела та доступний обсяг спостереження за робочим простором. Відповідні канали та супергрупи можуть використовувати функцію **«Експортувати з … обліковими записами»**, щоб розділити збір історії одного чату. Приватні чати та звичайні групи залишаються прив’язаними до початкового облікового запису, оскільки номери їхніх повідомлень належать до історії цього облікового запису.

## Експортувати групу як пакет

**Функція «Експорт групи»** створює один ZIP-файл, що містить підписаний експорт кожного облікового запису та підписаний перелік цих файлів. Оригінальні ідентифікатори робочого простору та відбитки залишаються доступними для перевірки. Створіть міжоблікову розповідь, використовуючи ці посилання; єдину об’єднану хронологію все ще складають окремо.

Продовжуйте роботу з [оформленням звітів](https://phishdestroy.github.io/TgWitness/uk/docs/reports/), [дошкою справ у робочому просторі](https://phishdestroy.github.io/TgWitness/uk/docs/case-board/) або [перевіркою експорту](https://phishdestroy.github.io/TgWitness/uk/docs/exports/).
