安全性與資料處理

威脅模型、存取模型、靜態機密資料、網路暴露風險、會話匯入，以及如何回報漏洞。

TgWitness 運行於您自己的電腦或伺服器上。預設情況下，唯一從系統發出的連線 是該帳號與 Telegram 之間的連線；通知、時間戳記、異地備份及 見證功能則需分別啟用。本頁面列出受保護的內容、保護方式，以及 哪些事項需由操作者自行決定。

領域 簡而言之
存取 每個工作區由一個面板代幣控制；該面板預設在 127.0.0.1 監聽
靜態資料的隱私 會話、API 配對、簽名金鑰及代理伺服器設定均採用 Fernet 進行加密
訊息與媒體 資料以未加密形式儲存：請啟用磁碟加密並設定嚴格的存取權限
完整性 每筆記錄均附有 SHA-256 雜湊鏈及 Ed25519 數位簽名
未涵蓋 系統管理員、外洩的控制面板憑證、擷取的完整性

有關漏洞通報，請參閱安全政策。

存取模式#

TgWitness 是一款單一操作員收集工具。任何持有控制面板憑證的人員皆可讀取及 匯出日誌、變更收集範圍，並授權 Telegram 帳戶。 本系統不設角色、使用者權限或租戶隔離機制。工作區會隔離 會話與證據儲存，但所有工作區皆由同一組控制面板憑證進行控制。

該面板預設在 localhost 上監聽。資料與控制 API 端點需要 一個 Bearer 憑證。不使用任何驗證 Cookie。該憑證儲存於瀏覽器的 sessionStorage 中，並由「鎖定工作區」功能移除。關閉瀏覽器或鎖定面板並不會 暫停收集器。請使用「暫停監測」功能來停止它。

每個客戶端地址的代幣請求失敗次數均設有上限。當同一代理伺服器地址下的另一客戶端達到該上限時，有效的 面板代幣與見證代幣 仍可繼續使用。 面板代幣與見證代幣仍分別賦予不同的權限。

試用存取#

/api/demo-access 是一個刻意未經身份驗證的引導程式，專用於明確 啟動且隔離的合成示範環境。它會發出一個獨立於進程生命週期的權限， 絕不會發出真實的面板代幣或 TGWITNESS_TOKEN 覆寫代幣。 其發行與使用需具備 迴路對等節點及主機，不得包含轉發標頭，亦不得進行跨來源請求。若存在 其他工作區或已授權的會話，則此路徑將被停用。活躍工作區絕不會 發行此權能。此示範無法連結帳戶或變更資料蒐集設定。

面板內容與匯出功能#

本頁面未使用任何外部字型、分析工具、CDN 資源或嵌入式遠端媒體。 來自 Telegram 的文字以純文字形式插入，而非 HTML。下載的附件 以二進位附件形式提供。JSONL 匯出檔保留原始字串；HTML 則會對其進行 轉義；可能成為公式的 CSV 儲存格會加上單引號作為前綴。

匯出檔案不包含驗證與簽署密鑰，但會刻意保留 所收集的來源元資料、識別碼，以及可能包含的個人或敏感內容。 原始來源元資料中可能包含 Telegram 存取雜湊值與檔案參照。

靜態資料的隱私#

Telegram API 憑證、StringSession 以及 Ed25519 私鑰均採用 Fernet 進行加密。預設情況下，其金鑰儲存於同一受保護的資料目錄中。 此舉可降低意外洩露明文的風險；但無法防範 能讀取整個目錄的攻擊者。TgWitness 不會對訊息內容及媒體檔案進行加密 。請使用磁碟加密並設定嚴格的作業系統權限。Unix 私鑰 檔案以權限模式 0600 建立；新建立的資料目錄則採用權限模式 0700。 現有目錄的權限不會被變更。Windows 會繼承目錄的存取控制清單 (ACL)：請將其 限制為服務帳戶及經授權的管理員。

外部主金鑰#

對於新的資料目錄，TGWITNESS_VAULT_KEY_FILE 可提供外部隨機 主金鑰。 系統會透過 HKDF-SHA256 及獨立的隨機鹽值，為每個工作區衍生出不同的 Fernet 金鑰。 為進行復原，必須保留 vault.external.json 檔案。若主金鑰遺失或 錯誤，系統將無法運作。現有的本地金庫不會被靜默遷移。 正在執行的程序可存取該金鑰；此非 HSM 隔離機制。控制面板會 顯示所選模式，並明確說明訊息／媒體儲存內容不會 由應用程式進行加密。完整威脅模型請參閱「連線」、「代理伺服器」及「資料保護」 章節。

代理伺服器與網路路由#

代理伺服器設定會透過 network.enc 進行加密。代理伺服器的密碼、使用者名稱及 MTProxy 密鑰均不會由 API 傳回，也不會寫入證據事件中。每個 工作區皆擁有專屬的路由。未配置任何自動直接備援機制。此設定僅適用於 Telegram 傳輸，不涵蓋所有機器流量或代理伺服器主機的 DNS 解析。 SOCKS 及一般 HTTP CONNECT 代理伺服器驗證，並未受到 代理伺服器協定本身提供的 TLS 保護。偽造的 TLS MTProxy 密鑰將被拒絕。

登入與會話匯入#

轉換後的 .tgwitness-session 檔案在 載入並儲存至金庫之前，會包含明文授權密鑰。離線命令列介面 (CLI) 接受經過審核的 Telethon 資料結構。 面板匯入功能另支援 Pyrogram SQLite、現代單一帳戶 TData ZIP， 以及已建檔的 JSON 輸入格式。此功能需經身份驗證，限四個檔案／8 MiB， 並在記憶體中處理上傳內容，無需解壓縮存檔或儲存原始檔案。 正規化的憑證僅會回傳給發出請求且已驗證的瀏覽器； 在 Telegram 授權成功後，這些憑證會儲存於加密的保管庫中。 請保護原始檔案與轉換後的檔案，並避免多個客戶端同時複製同一組授權憑證。

資料處理過程會驗證容器校驗和、本地解密雜湊值以及結構 長度。系統會暫時使用使用者提供的桌面版本地通行碼，且不會儲存該密碼。 此有限解析器無法保證所有桌面版皆相容。 QR 圖像在本地端生成，包含短效期的 Telegram 登入憑證，且 絕不會傳送至外部渲染服務。鎖定裝置、切換工作區、重新登入， 以及路由變更都會取消待處理的 QR 嘗試。重新載入或關閉分頁可能會導致 該嘗試維持待處理狀態直至過期。成功的 QR 登入仍會強制執行帳戶綁定。 一般 API 請求體仍限制為 16 KiB；經認證的匯入路徑接受 最多 12 MiB 的編碼 JSON，並會另行強制執行較小的解碼檔案限制。

登入代碼及 Telegram 兩步驟驗證密碼均不會被永久儲存。電話號碼／代碼雜湊狀態僅在 授權期間暫存於記憶體中。Telegram 連線會話賦予帳戶存取權限；切勿 將資料目錄、會話、憑證、金庫金鑰或私人簽署金鑰上傳至 GitHub。

日誌與傳輸#

預設的 API 驗證回應已進行替換，以避免回傳憑證 值。應用程式存取記錄功能已停用。請勿設定反向代理伺服器 以記錄 Authorization 標頭或請求正文。HTTP 會以明文傳輸憑證 和登入密鑰：只要連線離開 localhost，請務必使用 HTTPS 或 SSH 隧道。

完整性限制#

哈希鏈、資料庫觸發器及簽名機制可偵測特定修改； 但無法阻止本地系統管理員重寫並重新簽署日誌。 請將簽名檢查點及公鑰指紋儲存於獨立系統中。 「證據模式」與「異地副本」（兩者預設皆為關閉）會將檢查點雜湊值傳送至 時間戳記服務，並將加密副本傳送至 S3 相容儲存空間；詳見證 據格式說明。透明度日誌、HSM 支援的簽名以及正式 證據鏈認證功能尚未實作。

若您懷疑有問題#

請保留原始資料目錄，並使用另一份副本進行分析。請勿 在公開問題中包含私人的 Telegram 資料或憑證。本工具未聲稱 具備任何獨立的安全認證。
