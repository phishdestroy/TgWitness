Live server journal inventory · 1 November 2026#

At approximately 19:15 UTC, sequential read-only SQLite query_only queries counted events in ten workspace databases on a running server. Collection continued during the queries, so this is not an atomic snapshot across workspaces.

These are event counts, not unique messages, people or media files. The same message can appear in more than one workspace, and an edit or deletion can produce another journal event. media.failed counts historical failure events, not the current media queue. The queries did not newly verify signatures and the full hash chain of all 1,610,818 records, measure delivery or throughput, or establish that every Telegram event was captured. No message content, account or chat IDs, workspace labels, credentials or private files are published here.

At this review, the separately configured public monitor covered three sources: one capture response was OK and two reported no_response. That monitor is not a ten-workspace health summary. no_response means the observer could not obtain a response at that check; it does not establish message loss. The smaller 29 October test below has its own explicit signature and hash-chain verification.

Recent offline and fault-injection checks · 1 November 2026#

These checks use fictional data and local files; they add regression evidence for the current source, not another live Telegram delivery measurement:

بررسی What it exercised
Source archive Two builds with identical source bytes but changed file times produced the same ZIP and checksum. Exact archived bytes and file hashes matched; private test files stayed out. A simulated write failure left the previous archive and checksum intact.
Account export recovery A simulated disk error on the second ZIP member left no published or partial ZIP. Resume kept every signed receipt byte-identical, produced an independently verifiable archive using the expected signing fingerprint, and retained the synthetic coverage gap as a partial result. Scale assertions guard against repeated task and receipt scans as histories grow.
Minimized disclosure privacy Synthetic Unicode names and aliases, nested metadata, unknown senders and media fields were checked in all three identity modes and with text omission. A masking-limit failure did not silently weaken redaction; the original signed account export stayed unchanged.
Linux media decoder and OCR A Linux Docker CI check at commit 5a9e0814 passed generated Ogg/Opus, MP3, M4A, MP4 with video, WAV and FLAC inputs; forged-duration and secondary-file-reference controls; and 48 mutated parser fixtures (34 rejected, 14 decoded within bounds). Real Tesseract OCR ran with original bytes unchanged. The decoder and OCR ran in network-isolated containers without a Whisper model.

The checks run in the pull-request and full Checks workflows. They test these failure boundaries, not every possible storage failure or whether a disclosure is automatically safe to publish. The media check does not measure speech recognition accuracy or Telegram delivery. Review each derivative before sharing.

خروجی محافظت‌شده با رمز عبور با libarchive باز شد · ۲۹ اکتبر ۲۰۲۶#

یک آرشیو که با کد رمزگذاری خروجی (WinZip AES-256، فرمت قابل‌خواندن توسط 7-Zip و WinRAR) نوشته شده بود، با Windows tar (bsdtar 3.6.2, libarchive) باز شد. با رمز عبور صحیح، فایل استخراج‌شده با SHA-256 اصلی مطابقت داشت؛ رمز عبور اشتباه با پیام «Incorrect passphrase» (عبارت عبور نادرست) رد شد. خود برنامه‌های 7-Zip و WinRAR اجرا نشدند.

این ابزار مسیر محلی ضبط/صادرات سریالی را در این میزبان ویندوز اندازه‌گیری می‌کند. این ابزار اندازه‌گیری، تحویل MTProto، حساب‌های همزمان، محدودسازی تلگرام، رسانه‌ها، بار کاری طولانی‌مدت یا تعداد تضمین‌شده‌ای از چت‌های واقعی را انجام نمی‌دهد. این اندازه‌گیری مربوط به قبل از ابزارهای نهایی مهر و موم زمانی آفلاین است، که مسیر پیام اندازه‌گیری‌شده را تغییر نمی‌دهد.

صلاحیت‌های باقی‌مانده#

ژورنال زندهٔ نگهداری‌شده، ثبت واقعی جمع‌آوری، ویرایش‌ها، اعلان‌های حذف، پیوست‌ها، بازبینی‌های مجدد و مدیریت محدودیت نرخ را فراهم می‌کند. این ابزار سوابق جامع تحویل، ماتریس کنترل‌شده دیده‌بانی نقش‌ها، واکنش‌دهندگان، انتظار سیل طولانی‌مدت (FloodWait)، مسدودسازی حساب‌ها و بازیابی پس از وقفه شبکه/فرآیند را ثبت نمی‌کند. صدور توکن QR از تأیید QR موبایلی تکمیل‌شده مستقل است.

ساخت/اجرای Docker، نصب لینوکس/macOS، تحمل بار بالا و مداوم، بازبینی امنیتی مستقل، پاسخ واقعی و مستقل به TSA، اعتبارسنجی لغو/آرشیو گواهی و گواهی‌نامه قانونی (forensic) خارج از محدوده صلاحیت‌های ثبت‌شده باقی می‌مانند. وضعیت MTProto ذخیره شده و قابلیت جبران (catch-up) پیاده‌سازی شده‌اند؛ اما بازپخش اتمی پایدار (atomic durable replay) هنوز پیاده‌سازی نشده است. جمع‌آوری لاگ‌های ادمین، لیست‌های ری‌اکتور اضافی و پینگ کوتاه‌مدت اولویت‌دار همچنان ویژگی‌های جداگانه‌ای هستند. برای مشاهدهٔ ماتریس صلاحیت کنترل‌شده، به پذیرش زنده مراجعه کنید.

رسیدهای محلی و اسکرین‌شات‌های دقیق در مسیر test-results/ (توسط Git نادیده گرفته شده) قرار دارند. اسکرین‌شات عمومی در docs/assets/ فقط حاوی داده‌های نمایشی خیالی است.
