ส่งออกข้อมูลที่บัญชีสามารถอ่านได้ในขณะนี้: ขอบเขตการเข้าถึง, งานที่สามารถต่อได้, ไฟล์เก็บถาวรที่ลงนามแล้ว และสำเนาที่แชร์ในโหมดย่อ

TgWitness / เอกสารประกอบ · Evidence and verification

การส่งออกบัญชีจะจองบัญชีนั้นไว้แต่เพียงผู้เดียว ก่อนเริ่มหรือทำต่อ ให้หยุดการเฝ้าติดตามหรืองานเก็บข้อมูลอื่นชั่วคราวอย่างชัดเจน แอปจะไม่หยุดงานเหล่านั้นให้อัตโนมัติ

ในฐานะผู้ดูแลระบบการติดตั้ง ให้เลือก เริ่มจากที่นี่ → ส่งออกบัญชีของฉัน หรือ การส่งออก → บัญชี Telegram → ตั้งค่าการส่งออกบัญชี ลงชื่อเข้าใช้หากจำเป็น ตรวจสอบขอบเขต และเริ่มการส่งออกอย่างชัดเจน ไม่จำเป็นต้องเฝ้าติดตามอย่างต่อเนื่อง ข้อสังเกตที่บันทึกไว้ เป็นการส่งออกแยกต่างหากของบันทึกที่มีอยู่ ส่วน ZIP ครอบคลุมแหล่งข้อมูลทั้งหมดโดยไม่คำนึงถึงตัวกรองของบันทึก ทุกพื้นที่ทำงานมีงาน (jobs) ตัวตนการลงนาม และพื้นที่จัดเก็บข้อมูลเป็นของตัวเอง สิทธิ์การเข้าถึงแผงควบคุมที่ได้รับการมอบหมาย รวมถึงสิทธิ์การส่งออกทั่วไปแบบไม่จำกัด ไม่สามารถเปิดเส้นทางระดับบัญชีเหล่านี้ได้

ตัวกรองผู้ส่งและข้อความจะขยายออกใต้ กรองตามผู้ส่งหรือข้อความ ข้อมูลบัญชีและวิธีการเชื่อมต่อ มีหมวดหมู่บัญชี (ตามตัวเลือก) และตัวเลือก Takeout/regular-session; ส่วนสรุปจะแสดงตัวเลือกที่กำลังใช้งานอยู่แม้เมื่อปิดส่วนนี้แล้ว การปิดส่วนเหล่านี้จะรักษาการตั้งค่าไว้ ร่างการส่งออกและรายงานจะยังคงอยู่ในเซสชันของแผงปัจจุบันเมื่อเปลี่ยนมุมมอง; แต่จะไม่ถูกบันทึกเมื่อรีโหลดเบราว์เซอร์ งานที่มีอยู่ยังคงสามารถเข้าถึงได้จากตัวเลือกการส่งออกทั้งสอง

กระบวนการทำงานนี้ส่งออกข้อมูลที่บัญชีที่เชื่อมต่อสามารถเข้าถึงได้ในขณะนี้ การตั้งค่าเริ่มต้นใช้ Telegram Takeout; นี่ไม่ใช่การสำรองข้อมูล Telegram ที่ไม่สามารถเข้าถึงได้หรือถูกลบไปแล้ว การสนทนาลับ ประวัติการสนทนาที่ไม่สามารถเข้าถึงได้ และการแก้ไขก่อนหน้านี้จะไม่ถูกกู้คืน Telegram อาจกำหนดช่วงเวลาการรอคอยก่อนที่ Takeout จะเริ่มทำงาน แผงควบคุมจะแสดงช่วงเวลาการรอคอยนั้น; มันจะไม่เปลี่ยนวิธีการส่งข้อมูลโดยเงียบๆ ตัวเลือก API ปกติที่ระบุไว้อย่างชัดเจนมีขอบเขตการบันทึกที่ต่างออกไป และบันทึกหมวดหมู่ที่ไม่ได้รับการสนับสนุน

Takeout is the official export API also used by Telegram Desktop. TgWitness can write Desktop-compatible JSON directly from its own acquisition; importing someone else's archive is not required. Chat and message IDs are available through both transports. A public chat or permission to forward does not guarantee a faster export or remove Takeout's approval delay. Measure the same scope and media settings before comparing speed.

For up to 20 explicitly selected chat IDs, regular-API export resolves those peers directly before considering the account's complete dialog inventory. A readable public channel can therefore be exported without joining it, even when it is absent from the dialog list. Uncached peers fall back to the ordinary inventory. The archive filter remains enforced: if Telegram does not return a dialog and archived chats are excluded, the unknown archive status is recorded as an omission. Takeout keeps its split-range inventory procedure. Neither path joins chats or changes forwarding permissions. In Desktop-compatible JSON, channels that Telegram marks left appear under left_chats, including readable public channels the account has not joined.

Both FLOOD_WAIT and FLOOD_PREMIUM_WAIT pause requests for the full server-requested period. The account's deadline is persisted across reconnects and restarts; a shorter later wait cannot shorten it. Retries are bounded, cancellation preserves sealed pages, and API credentials are not rotated to bypass a rate limit. No Premium purchase is made.

เลือกข้อมูลที่จะเก็บรวบรวม#

บริบท ความหมาย
วัตถุประสงค์ บันทึกเหตุผลที่การซื้อข้อมูลนี้จำเป็น อย่าใส่ชื่อที่ไม่จำเป็นหรือรายละเอียดคดีที่ละเอียดอ่อนที่นี่
ภาษาของรายงาน เลือกภาษาของป้ายกำกับในรายงานที่อ่านได้ ข้อความต้นฉบับของข้อความจะยังคงไม่เปลี่ยนแปลง ส่วนป้ายกำกับของแม่แบบที่ยังไม่แปลจะใช้ภาษาอังกฤษ ภาษาจะถูกกำหนดไว้ด้วยตัวเลือกงานที่ลงนามแล้ว
ประเภทการสนทนา / ID การสนทนา สามารถเลือกทุกประเภทที่ระบุไว้ หรือเพียงการสนทนาที่แสดงในรายการเท่านั้น; "ข้อความที่บันทึกไว้" เป็นส่วนหนึ่งของการสนทนาส่วนตัว ส่วนการสนทนาที่เก็บไว้ในคลังสามารถเลือกได้แยกต่างหาก
วันที่ UTC. วันที่ในปฏิทิน "From" และ "Through" ของแผงนี้ถูกรวมไว้ทั้งสองวัน API นี้ใช้ช่วงวันที่แบบรวม from_utc และไม่รวม to_utc; แผงจะส่งวันที่เริ่มต้นของวันถัดไปหลังจากวันที่ Through. ขอบเขตที่ว่างจะปล่อยให้ด้านนั้นไม่มีข้อจำกัด
ID ผู้ส่ง แสดงเฉพาะข้อความจากผู้ส่งที่ระบุไว้เท่านั้น; หากรายชื่อว่าง จะแสดงข้อความจากผู้ส่งทั้งหมด
ข้อความประกอบด้วย วลีตัวอักษรที่ไม่ได้แยกแยะตัวพิมพ์ใหญ่-เล็ก จะถูกจับคู่ด้วย OR ส่วนเงื่อนไขผู้ส่ง/วันที่/ข้อความของตนเอง จะถูกจับคู่ด้วย AND
ข้อความส่วนตัว เก็บไว้เฉพาะข้อความที่ส่งออกไปเท่านั้น
ประเภทสื่อ เลือกประเภทไฟล์แนบ หรือล้างทั้งหมด เพื่อหลีกเลี่ยงการดาวน์โหลดไฟล์ข้อความ
ขีดจำกัดไฟล์ / สื่อทั้งหมด MiB ต่อไฟล์และ GiB ของสื่อที่ดาวน์โหลดทั้งหมด ข้อความ ใบเสร็จ รายงานที่อ่านได้ และพื้นที่ว่างสำหรับZIP ต้องการพื้นที่ดิสก์เพิ่มเติม
ประเภทบัญชี โปรไฟล์ รายชื่อผู้ติดต่อ รูปโปรไฟล์ สตอรี ข้อมูลเมตาดาต้าของเซสชัน และข้อมูล Takeout อื่นๆ มีตัวควบคุมแยกกัน

การตั้งค่าล่วงหน้าของคอลเลกชัน Minimize จะปิดการใช้งานไฟล์และข้อมูลเมตาของบัญชี ตัวกรองผู้ส่ง/เนื้อหาจะถูกนำไปใช้ก่อนที่จะเก็บหน้าข้อความและดาวน์โหลดสื่อ Telegram ยังคงส่งหน้าประวัติ API ที่มีข้อความที่จำเป็นสำหรับการประเมินตัวกรองเหล่านั้น: การกรองไม่ใช่การรับประกันว่าข้อความที่ไม่ได้เลือกจะไม่เข้าสู่หน่วยความจำของระบบ การสังเกตการณ์อื่นๆ ที่กำลังดำเนินอยู่ในพื้นที่ทำงานมีขอบเขตและการตั้งค่าการเก็บรักษาข้อมูลเป็นของตัวเอง

ประวัติรูปโปรไฟล์และสตอรีไม่ถูกเลือกไว้เป็นค่าเริ่มต้น ให้ปิดรูปโปรไฟล์และรายชื่อผู้ติดต่อด้วย เมื่อเคสต้องการเฉพาะข้อความเท่านั้น หากไฟล์แนบหรือข้อมูลเมตาไม่จำเป็น การยกเว้นพวกมันระหว่างการเก็บข้อมูลจะช่วยหลีกเลี่ยงการเก็บสำเนาส่วนตัวเพิ่มเติมในไฟล์ส่งออกนี้

Photo payloads use the still-image variant identified in their metadata and hash manifests, including photos with an animated avatar variant. That animation is not substituted for the selected still image. A shorter or longer payload than the observed size is recorded as a failed attachment, and a changed representation during file-reference renewal is rejected. These failures leave the archive partial while retaining the message records. Independent verification also rejects saved attachments whose signed length contradicts their observed size or representation, including in older archives.

สรุป, ครอบคลุม และตรวจสอบ#

แต่ละงานจะล็อกตัวเลือกและข้อมูลประจำตัวบัญชีไว้คงที่ รายการและหน้าเว็บที่บันทึกไว้จะได้รับการลงนาม; ใบยืนยันหน้าเว็บจะบันทึกค่าแฮช ตำแหน่งเคอร์เซอร์ เวลา ผลลัพธ์ของไฟล์แนบ และใบยืนยันก่อนหน้านั้น เฉพาะหน้าเว็บที่ได้รับการยืนยันแล้วเท่านั้นที่จะนับเป็นความคืบหน้า การเริ่มต้นใหม่/การต่อจากจุดหยุดจะตรวจสอบบันทึกเหล่านั้นก่อนที่จะดำเนินการต่อ บัญชีที่เปลี่ยนแปลง หน้าเว็บที่ลงนามแล้วถูกแก้ไข หรือห่วงโซ่ใบยืนยันที่ไม่สอดคล้องกันจะถูกปฏิเสธ ตัวเลือกไม่สามารถแก้ไขได้ระหว่างกระบวนการบันทึก: ให้เริ่มงานใหม่สำหรับขอบเขตอื่น

Pause จะหยุดการทำงานของบัญชีที่กำลังทำงานอยู่ การเริ่มต้นแอปพลิเคชันใหม่จะเก็บงานที่ยังไม่เสร็จไว้เพื่อให้สามารถดำเนินการต่อได้โดยต้องระบุอย่างชัดเจน เซสชัน Takeout ที่หมดอายุจำเป็นต้องดำเนินการต่อโดยต้องระบุอย่างชัดเจน การเปลี่ยนช่วงการแบ่งของ Telegram อาจจำเป็นต้องทำการเก็บข้อมูลใหม่ การดำเนินการต่อจะเก็บข้อมูลการสังเกตการณ์ก่อนหน้านี้ไว้ ดังนั้นการส่งออกที่ทำงานเป็นเวลานานจึงไม่ใช่ภาพถ่ายแบบอะตอมิกเพียงครั้งเดียว การดำเนินการอื่น ๆ ที่เปลี่ยนบัญชีและการส่งออกที่ขัดแย้งกันจะถูกบล็อกระหว่างการเก็บข้อมูล รอจนกว่าการแพ็กเกจจะเสร็จสิ้นก่อนที่จะลบพื้นที่ทำงาน

Resume จะตรวจสอบเนื้อหาที่บันทึกไว้แล้วก่อนที่จะดำเนินการต่อ ไฟล์เก็บถาวรขนาดใหญ่บนพื้นที่จัดเก็บข้อมูลที่ช้าอาจเกินเวลาที่กำหนดไว้สำหรับ พารามิเตอร์ → เวลาหมดอายุของการดำเนินการบนแผงควบคุม (ค่าเริ่มต้นคือ 120 วินาที) ให้เพิ่มค่าการตั้งค่านี้ก่อนที่จะลองใหม่ การยกเลิกหรือการหยุดชะงักของพื้นที่จัดเก็บข้อมูลจะทิ้งงานไว้ในสถานะหยุดชั่วคราว ส่วนการตรวจสอบความสมบูรณ์ที่ล้มเหลวจะทิ้งงานที่ล้มเหลวพร้อมคำอธิบาย การตรวจสอบต้องเสร็จสิ้นหรือหยุดลงอย่างปลอดภัยก่อนที่จะสามารถปิดไฟล์ได้ การตรวจสอบแบบจำลองยังไม่ได้ยืนยันข้ออ้างเกี่ยวกับปริมาณงานของบัญชีขนาดใหญ่

แผงควบคุมจะแยกแยะขอบเขตที่เลือกและเสร็จสิ้นแล้วออกจากอาร์ไคฟ์บางส่วน และบันทึกการละเว้นและการอ่านที่ล้มเหลว ไฟล์ที่ถูกยกเว้นโดยเจตนาแตกต่างจากไฟล์ที่ล้มเหลวหรือไม่สามารถเข้าถึงได้ ตรวจสอบความครอบคลุมแม้เมื่อการตรวจสอบความสมบูรณ์สำเร็จแล้ว ไม่มีโปรแกรมอ่านในเครื่องใดที่สามารถพิสูจน์ได้ว่า Telegram ได้ส่งคืนทุกข้อความที่เคยมีอยู่

ZIP ที่เสร็จสิ้นแล้วจะยังคงสามารถดาวน์โหลดซ้ำได้และดาวน์โหลดตามช่วง HTTP ได้ต่อไป ส่วนคลังข้อมูลบัญชีจะประกอบด้วย manifest.json, manifest.sig, ที่ได้รับการลงนาม job.json, inventory.json, receipts/, มีผลบังคับใช้ data/*.jsonl, ที่ถูกเลือก media/, HTML ที่อ่านได้ และตัวตรวจสอบ ให้ตรึงลายนิ้วมือของตัวเก็บรวบรวมผ่านช่องสัญญาณอิสระ แล้วตรวจสอบโดยใช้การติดตั้งที่เชื่อถือได้:

python -m tgwitness.verify account-export.zip --fingerprint TRUSTED_SHA256

สำหรับอาร์ไคฟ์ที่มีเนื้อหาเมื่อขยายแล้วเกิน 4 GiB ให้กำหนดขนาดที่เพียงพออย่างชัดเจน --max-gib. แผงควบคุมจะตรวจสอบความถูกต้องของไฟล์เก็บถาวรท้องถิ่นที่ได้รับการยืนยันและเสร็จสมบูรณ์ โดยใช้ขนาดที่ขยายตัวตามที่ประกาศไว้และค่าสรุป (digest) ที่เผยแพร่ผ่าน ZIP; ส่วน CLI ภายนอกจะรักษากำหนดขนาดจำกัดของตัวเองไว้ โปรดตรวจสอบก่อนเปิดไฟล์ HTML ที่สามารถอ่านได้ เครื่องมือตรวจสอบที่มาพร้อมกับไฟล์เก็บถาวรนั้นสะดวกใช้ แต่การใช้เครื่องมือตรวจสอบที่ดาวน์โหลดมาอย่างอิสระจะช่วยหลีกเลี่ยงการเชื่อถือโค้ดที่สามารถรันได้ซึ่งมาพร้อมกับหลักฐาน

ลายเซ็น Ed25519 และแฮชSHA-256 ใช้เพื่อตรวจจับการเปลี่ยนแปลงหลังจากที่ผู้เก็บข้อมูลได้บันทึกไบต์ที่เกี่ยวข้องแล้ว อย่างไรก็ตาม สิ่งเหล่านี้not ไม่สามารถพิสูจน์ได้ว่า Telegram ได้ลงนามในข้อความเหล่านั้นแล้ว ผู้ดำเนินการเก็บข้อมูลมีความซื่อสัตย์ ประวัติของบัญชีนั้นครบถ้วน หรือศาลจะยอมรับหลักฐานดังกล่าว เวลาการบันทึกใช้ตามนาฬิกาของผู้เก็บข้อมูล ต้องประเมินเวลาประทับตราอิสระและที่มาของการเก็บข้อมูลอย่างอิสระแยกกัน

เตรียมเอกสารเปิดเผยข้อมูลสำหรับทนายความหรือผู้รับอื่น#

หลังจากดาวน์โหลดไฟล์ส่งออกที่เสร็จสมบูรณ์แล้ว ให้เก็บภาพต้นฉบับ ZIP ไว้และเปิด index.html จากสำเนาที่แยกออกมา รายงานนี้อธิบายขอบเขต ความครอบคลุมที่มีอยู่ และ ข้อจำกัด การอ้างอิงบันทึกของมันรวมการอ้างอิงจากคลังข้อมูล เส้นทางเอกสาร และ หมายเลขบันทึก เพื่อให้ผู้รับสามารถค้นหาข้อมูลเดียวกันใน HTML หรือเอกสารที่พิมพ์ออกมาได้ สำหรับตัวอย่างที่ใช้งานได้จริง ดูที่ เปิดรายงานสมมติ

จากไฟล์ส่งออกบัญชีที่เสร็จสมบูรณ์ ให้เลือก เตรียมสำเนาเพื่อแบ่งปัน ซึ่งจะสร้างไฟล์อนุพันธ์ที่ลงนามแยกต่างหาก ไฟล์ต้นฉบับ ZIP จะยังคงไม่เปลี่ยนแปลงและเป็นส่วนตัว; อย่าส่งไฟล์นี้ร่วมกับไฟล์อนุพันธ์ที่ถูกลดขนาด เว้นแต่ผู้รับจะได้รับอนุญาตให้รับเนื้อหาทั้งหมด ให้เลือกภาษาของรายงานแยกต่างหาก การเปลี่ยนภาษาหรือการตั้งค่าการเลือกใด ๆ ก็ตาม ต้องดูตัวอย่างอีกครั้งก่อนการสร้าง

  1. ป้อนวัตถุประสงค์การเปิดเผยข้อมูล และเลือกวันที่, ID ผู้ส่ง และเกณฑ์ข้อความตามตัวอักษร
  2. เลือกว่าจะเก็บรักษาตัวตนจริง, เปิดเผยเฉพาะผู้เข้าร่วมที่ระบุไว้, หรือใช้ชื่อปลอมสำหรับทุกคน ในโหมดใช้ชื่อปลอมทั้ง ID/ชื่อผู้สนทนาและ ID ข้อความจะถูกแทนที่ด้วยชื่อปลอม ชื่อปลอมจะคงที่ภายในข้อมูลที่เปิดเผยแต่ละชุด และจะเปลี่ยนไปเมื่อมีการเตรียมข้อมูลที่เปิดเผยชุดใหม่
  3. สามารถเก็บข้อความไว้ ละเว้นทั้งหมด หรือเพิ่มชื่อ/วลีตามตัวอักษรเพื่อปิดบัง ในโหมดส่วนตัว เครื่องมือนี้ยังปิดบังชื่อผู้ส่งที่ซ่อนอยู่และชื่อผู้ใช้ทางเลือกที่ทราบ ID ผู้ส่งแบบโทเคนทั้งตัว ชื่อการสนทนาแบบส่วนตัว ลิงก์ ที่อยู่อีเมล และสตริงที่คล้ายหมายเลขโทรศัพท์ การจับคู่ชื่อที่ทราบจะจัดการการแปลงตัวอักษร Unicode รวมถึง Straße/STRASSE. ชื่อกลุ่ม/ช่องทั่วไปจะไม่ถูกลบออกจากข้อความโดยอัตโนมัติ หากเกินขีดจำกัดการปิดบังตัวตนที่รู้จัก ให้จำกัดการส่งออกข้อมูลต้นทางหรือละเว้นข้อความ; เครื่องมือนี้จะไม่ข้ามชื่อที่ปรากฏในภายหลังโดยไม่แจ้งเตือน กฎเหล่านี้เป็นกฎที่พยายามทำให้ดีที่สุด ไม่ใช่การทำให้ไม่ระบุตัวตนแบบทั่วไป
  4. อย่าเพิ่มไฟล์เข้าไปในบันทึก เว้นแต่ผู้รับจะต้องการไฟล์เหล่านั้น ไฟล์ต้นฉบับที่ถูกเพิ่มเข้าไปจะรักษาพิกเซล เสียง ข้อความ และข้อมูลเมตาไว้ครบถ้วน เครื่องมือนี้ไม่ทำการทำให้ข้อมูลเป็นนิรนาม
  5. ดูตัวอย่างจำนวนข้อความ คำเตือน และข้อความตัวอย่างที่ผ่านการแปลง แล้วยืนยันการสร้างอย่างชัดเจน ตัวอย่างจำกัดอยู่ที่ 12 ข้อความ และ 2,000 ตัวอักษรต่อข้อความ นี่เป็นตัวอย่าง ไม่ใช่การตรวจสอบผลลัพธ์อย่างครบถ้วน การเปลี่ยนแปลงการตั้งค่าต้องดูตัวอย่างใหม่ ตัวอย่างจะหมดอายุหลังจาก 15 นาที และผูกติดกับเซสชันของผู้ดูแลระบบนั้นและZIP ต้นฉบับอย่างแม่นยำ; ไม่สามารถใช้ซ้ำได้หลังจากสร้างแล้ว ตัวอย่างใหม่จะทำให้ตัวอย่างเดิมสำหรับงานและเซสชันเดียวกันเป็นโมฆะ
  6. ตรวจสอบผลลัพธ์ที่สมบูรณ์ index.html และ messages.jsonl ในเครื่องก่อนส่งต่อ หากพบข้อมูลที่ไม่จำเป็น ให้สร้างการเปิดเผยข้อมูลใหม่พร้อมการยกเว้นที่เข้มงวดขึ้น อย่าแก้ไข ZIP ที่ได้รับการลงนามแล้วโดยตรง

ข้อความที่ถูกตัดออกจากการคัดเลือก#

ตัวอย่างแสดงผล การเปิดเผยข้อมูลจะดูไม่ครบถ้วนหากยังไม่เสร็จสมบูรณ์ ในทุกการสนทนาที่มีข้อความที่ถูกเปิดเผยอย่างน้อยหนึ่งข้อความ ข้อความที่การเลือกไม่รวมไว้จะปรากฏเป็นเครื่องหมาย [withheld by selection — rule: sender] (หรือ text, period). เลือก "ข้อความที่ถูกตัดออกจากการเลือก": หนึ่งเครื่องหมายสำหรับแต่ละชุดข้อความที่ถูกระงับติดต่อกัน (ค่าเริ่มต้น) หรือหนึ่งเครื่องหมายสำหรับแต่ละข้อความ เครื่องหมายจะแสดงเพียงกฎและจำนวนเท่านั้น ไม่แสดงข้อความ ผู้ส่ง วันที่ หรือไฟล์ การสนทนาที่ไม่มีข้อความที่ถูกเปิดเผยจะถูกตัดออกทั้งหมด ดังนั้นแพ็กเกจจึงไม่เปิดเผยว่ามีการสนทนาดังกล่าวอยู่

ข้อความตอบที่ถูกเปิดเผยจะระบุสิ่งที่มันตอบ: ข้อความที่รวมอยู่ในสำเนานี้, ข้อความที่ถูกยกเว้นจากการเลือก, หรือข้อความที่ไม่มีอยู่ในไฟล์ส่งออกต้นฉบับ (ถูกลบก่อนการส่งออกหรือไม่เคยถูกส่งออก; ไฟล์ส่งออกไม่สามารถระบุได้ว่ากรณีใด) ข้อความที่ถูกระงับซึ่งคำตอบที่เปิดเผยตอบกลับจะได้รับเครื่องหมายเฉพาะเสมอ ดังนั้นคำตอบจึงชี้ไปยังบันทึกที่อธิบายว่าทำไมข้อความนั้นจึงว่างเปล่า สามสถานะนี้แตกต่างจากการลบและช่องว่างในการเก็บรวบรวม ซึ่งอยู่ในไฟล์ส่งออกต้นฉบับ

ใน messages.jsonl (รูปแบบ tgwitness-account-disclosure-v2) แต่ละข้อความมี state: disclosed, หรือ withheld พร้อมด้วย rules และ count. คำตอบที่เปิดเผยมี reply_to มีเป้าหมาย id และและ. ข้อความตอบกลับที่เปิดเผยมีกับเป้าหมาย ). รายการจะนับข้อความที่เปิดเผย state (disclosed, withheld, not_in_source). รายการจะนับข้อความที่เปิดเผย, การสนทนา, สื่อ และ withheld ข้อความ. verify.py ปฏิเสธมาร์กเกอร์ที่นำเนื้อหาและคำตอบที่ชี้ไปยังบันทึกที่ขาดจากแพ็กเกจ; แพ็กเกจเวอร์ชัน 1 ตรวจสอบตามเดิม

รูปแบบที่ถูกลดขนาดลงนี้จะละเว้นโปรไฟล์บัญชีที่มีโครงสร้าง รายชื่อผู้ติดต่อ อวาตาร์ เซสชัน สตอรี อ็อบเจกต์ Telegram แบบดิบ หัวเรื่องของการส่งต่อ ข้อความตอบกลับที่อ้างอิงถึงข้อความเดิม บัตรผู้ติดต่อ และข้อมูลเมตาดาต้าเกี่ยวกับตำแหน่ง มันไม่รวมไฟล์ JSONL ต้นฉบับ การตั้งค่าตัวกรองส่วนตัว กุญแจนามแฝง และแผนที่อัตลักษณ์ ข้อความที่เลือกไว้ อัตลักษณ์ที่เก็บไว้อย่างชัดเจน และไฟล์ที่รวมอยู่ยังคงอาจมีชื่อ ID หรือวลีเดียวกันกับที่ใช้ในตัวกรองเหล่านั้น; จึงจำเป็นต้องตรวจสอบแยกต่างหาก นโยบายส่วนตัวและกุญแจนามแฝงจะถูกเก็บรักษาไว้ในรูปแบบเข้ารหัสในคลังข้อมูลท้องถิ่นสำหรับงานนั้น; การลบงานจะลบข้อมูลการเปิดเผยส่วนตัวที่เกี่ยวข้องด้วย ส่วนบันทึกนโยบายสาธารณะจะบันทึกจำนวนตัวกรองแทนค่าตัวกรอง วัตถุประสงค์ที่ระบุไว้จะเปิดเผยในไฟล์ manifest และ HTML: เกณฑ์ส่วนตัวที่ระบุไว้อย่างชัดเจน และในโหมดนามแฝง ตัวตนที่ซ่อนอยู่แต่เป็นที่รู้จักจะถูกปกปิดไว้ที่นั่นด้วย รวมถึงเมื่อข้อความถูกตัดออก ให้รักษาวัตถุประสงค์ให้ปราศจากข้อมูลส่วนตัวที่ไม่จำเป็น; บริบทการระบุตัวตนที่ไม่ทราบสามารถคงอยู่ได้

ไฟล์ manifest ของมันจะผูกไฟล์ที่สร้างขึ้นจากต้นฉบับ นโยบายสาธารณะ และค่าแฮชของไฟล์ต้นฉบับ ZIP การตรวจสอบสามารถยืนยันความสมบูรณ์ของข้อมูล และหากแหล่งที่มาถูกจัดเตรียมไว้อย่างท้องถิ่น ก็สามารถยืนยันความสอดคล้องของลิงก์แหล่งที่มาได้:

python -m tgwitness.verify minimized-disclosure.zip --fingerprint TRUSTED_SHA256
python -m tgwitness.verify minimized-disclosure.zip --fingerprint TRUSTED_SHA256 --evidence account-export.zip

การเชื่อมโยงแหล่งที่มาไม่สามารถพิสูจน์ได้อย่างอิสระว่าการแปลงข้อมูลได้เลือกทุกองค์ประกอบที่จำเป็นหรือลบทุกรายละเอียดที่สามารถระบุตัวตนได้ ข้อความต้นฉบับในรูปแบบข้อความธรรมดาไม่ได้ถูกฝังไว้เป็นหลักฐาน จำเป็นต้องมีการตรวจสอบใหม่เพื่อตัดสินในเรื่องนี้

GitHub Actions supports full-account and selected-chat exports through Takeout or the regular API, plus a one-chat event journal. The hosted capture guide explains settings verification and the 120-minute limit. To verify a sharing copy derived from hosted capture, check its source hash against the original archive and verify that archive's attestation with the mode-specific checks.
