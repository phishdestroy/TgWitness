# Локальное распознавание текста и транскрипция

[Руководство по рабочему процессу](https://phishdestroy.github.io/TgWitness/docs/archive/) · [Вики](../wiki/Archive-and-Integrations.md)

Откройте запись журнала `media.saved`, выберите **Распознать вложение**, затем выберите
OCR или транскрипцию в разделе **Дополнительные инструменты → Спросить у архива** (называется **Машинное распознавание**,
если ИИ архива отключен). Обработка осуществляется вручную и локально.
Режим облачных носителей и автоматическая загрузка отсутствуют. Исходные байты вложения и
элемент `media_sha256` остаются неизменными; распознанный текст явно помечается как результат
автоматического распознавания и хранится отдельно с указанием хэша исходного файла, версии движка/модели,
языка, параметров и времени завершения. В транскрипциях сохраняются возвращённые временные метки.

Выполните поиск по этим результатам с помощью функции **«Поиск по распознанному тексту»** и фильтра OCR/транскрипции,
или выберите распознанный текст в качестве источника для поиска по наилучшему совпадению в **Журнале**.
Оба варианта сопоставляют формы слов с помощью [индекса в памяти](../SEARCH.md#recognized-text). Это
отдельный поиск по производным данным; он не преобразует автоматическое распознавание
в исходный текст Telegram и не добавляет его к подписанным событиям.

<a id="set-up-the-optional-worker"></a>
## Настройка дополнительного рабочего процесса

Для версии 1 требуется хост под управлением Linux с локальным демоном Docker. На компьютерах с Windows
TgWitness можно запустить в виртуальной машине Linux или в среде WSL с собственным локальным демоном.
Панель никогда не декодирует недоверенные вложения самостоятельно.

```sh
docker build -f deploy/media-worker/Dockerfile -t tgwitness-media:local .
export TGWITNESS_MEDIA_IMAGE=tgwitness-media:local
```

Задайте эти переменные в среде службы TgWitness и перезапустите её. По умолчанию
сокет демона имеет значение `/var/run/docker.sock`; при развёртывании без прав root можно задать
`TGWITNESS_DOCKER_SOCKET`. Рабочий процесс явно использует этот сокет Unix, а
не удалённый контекст Docker. Не предоставляйте доступ к API Docker пользователям панели управления и не монтируйте
его сокет внутри контейнера распознавания.

Для транскрипции необходимо отдельно установить модель Whisper, совместимую с CTranslate2,
а затем указать `TGWITNESS_WHISPER_MODEL_DIR` в качестве пути к её каталогу. Рабочий процесс загружает её с помощью
`local_files_only=True`; выбранная модель и входные данные монтируются в режиме «только для чтения».
См. [документацию по загрузке моделей](https://github.com/SYSTRAN/faster-whisper) для данного движка.
Предоставленное изображение для OCR содержит обучающие данные на английском и русском языках. При необходимости добавьте в изображение другой
язык; коды языков указаны в
[документации по CLI Tesseract](https://tesseract-ocr.github.io/tessdoc/Command-Line-Usage.html).

При обработке модели не загружаются. При сборке/загрузке установочного пакета может использоваться сеть;
в каждом контейнере фактического распознавания сетевые функции отключены. Установите образ
перед тем, как включить их; в среде выполнения используется `--pull=never`.

<a id="bounds-and-recovery"></a>
## Пределы и восстановление

Контейнер запускается от имени пользователя без привилегий с корневым каталогом, доступным только для чтения, с ограниченными
возможностями, `no-new-privileges`
, одним процессором, 2 ГБ памяти, ограничением на количество PID и ограниченной
временной файловой системой. Монтируются только проверенная копия выбранного файла и, по желанию,
каталог модели. База данных коллектора, хранилище и сессия
не монтируются. Флаги среды выполнения Docker ](https://docs.docker.com/reference/cli/docker/container/run/)
обеспечивают соблюдение этих ограничений; это остаётся границей контейнера, а не аппаратным анклавом.

Размер файлов ограничен 50 Мбайт, изображений — 20 миллионами пикселей, аудиозаписей — 30 минутами при
известной продолжительности, а время обработки — пятью минутами. Одновременно работает только один рабочий процесс,
при этом в очереди или в процессе выполнения может находиться не более 20 заданий, а в рабочей области — не более 100 сохраненных заданий.
Команда «Cancel» останавливает контейнер; команда «retry» создаёт новое задание, связанное с предыдущей попыткой.
Прерванные задания помечаются после перезапуска. Обработка может завершиться сбоем, если модель
не укладывается в заданные ограничения; без изоляции она не выполняется в фоновом режиме.
