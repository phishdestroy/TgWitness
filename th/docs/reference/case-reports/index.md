# การตั้งค่าและตรวจสอบรายงาน

Canonical page: https://phishdestroy.github.io/TgWitness/th/docs/reference/case-reports/

ตัวกรองรายงาน, แปดแบบออกแบบ, การตั้งค่าเนื้อหาล่วงหน้า, ประวัติการเปลี่ยนแปลงที่บันทึกไว้ และการประเมินผลที่รวมอยู่ในไฟล์ส่งออกที่ลงนามแล้ว

แปลงข้อสังเกตที่เลือกไว้เป็นรายงานคดีที่อ่านได้: คำถามของคดี, ขอบเขต, การเปลี่ยนแปลงที่บันทึกไว้, แผนภูมิ, ผลการค้นพบ และแหล่งอ้างอิง แต่ละรายงานให้ ผู้รับสามารถตรวจสอบข้อมูลที่ส่งมาและประเมินความครบถ้วน ของการเก็บรวบรวมข้อมูลได้

ส่วน **“พื้นฐานของความเชื่อถือและข้อจำกัด”** ปรากฏในรายงานบันทึกประจำวัน รายงานการส่งต่อ รายงานแชท รายงานบัญชี และรายงานการแบ่งปัน ไฟล์ PDF ของรายงานบันทึกประจำวันและรายงานการส่งต่อใช้การประเมินเดียวกันกับ `report.json` ที่ลงนามแล้ว รายการ ZIP มี `case_assessment` ใน manifest ที่ลงนามแล้ว การประเมินนี้จะถูกส่งไปพร้อมกับข้อมูลที่ส่งออก ส่วน การสังเกตการณ์ต้นฉบับจะรักษาลายเซ็นที่มีอยู่เดิม

## รูปแบบเอกสารและลำดับการอ่าน

### Report Studio

เปิด **Exports → Configure และดูตัวอย่าง**. ดำเนินการผ่าน **Data → Design & contents → Preview**:

1. ใช้พื้นที่ทำงานทั้งหมดหรือเลือกการสนทนา ผู้ส่ง ข้อความ รวมถึงวันที่สังเกตการณ์ตาม UTC และประเภทเหตุการณ์ โหลดแคตตาล็อกเพื่อค้นหาการสนทนาและผู้ส่ง หรือป้อน ID Telegram ของพวกเขา ตัวกรองผู้ส่งจะตรงกับ ID ผู้ส่งที่บันทึกไว้; การแจ้งเตือนการลบ ที่ไม่มีผู้ส่งจะไม่ตรงกับตัวกรองผู้ส่ง
2. เลือกแบบหน้า จากนั้นเลือกแผนภูมิ ป้ายชื่อผู้เข้าร่วม บทถอดความ และ ผลการวิเคราะห์ที่เขียนไว้ การเปลี่ยนแบบหน้าจะรักษาตัวเลือกเหล่านี้ไว้
3. สร้างตัวอย่างแสดงผล (preview) ซึ่งจะแสดงจำนวนจริง กิจกรรม ผู้เข้าร่วม ตัวอย่าง บันทึก การเปลี่ยนแปลงที่บันทึกไว้ และช่วงหมายเลขข้อความที่ขาดหายไป การเปลี่ยนตัวเลือก จะทำให้ตัวอย่างแสดงผลไม่ทันสมัยอีกต่อไป ให้บันทึกก่อนดาวน์โหลด HTML, PDF ที่มีลายเซ็น, JSON ที่มีลายเซ็น หรือไฟล์ ZIP ของหลักฐาน

การดูตัวอย่างข้อมูลนับจากส่วนนำของบันทึกที่เสถียรทั้งหมด ไม่ใช่ตัวอย่างเริ่มต้น มีเพียงแถวตัวอย่างที่แสดงและรายการยาวเท่านั้นที่ถูกจำกัด; จำนวนที่ถูกตัดออกจะ แสดงไว้ การส่งออกในภายหลังจะสร้างภาพถ่ายสแนปช็อตที่เสถียรใหม่ ดังนั้นการเก็บรวบรวมที่ยังดำเนินอยู่ อาจทำให้ตัวเลขเพิ่มขึ้น ขอบเขต จำนวน และตัวตนของแหล่งข้อมูลถูกรวมอยู่ใน รายงานที่ลงนามแล้ว การเปิดหรือดูตัวอย่างแบบฟอร์มจะไม่บันทึกข้อมูล

**เลือกสำเนาสำหรับผู้รับ** แผนภูมิและบันทึกการถอดความใช้ข้อมูลที่เลือกไว้ ความสมบูรณ์ การเก็บรักษา และขอบเขตการครอบคลุม อธิบายบันทึกต้นฉบับทั้งหมด ไฟล์ ZIP ของหลักฐาน ประกอบด้วยข้อมูลต้นฉบับและไฟล์แนบ [ใช้การส่งต่อข้อมูลแบบจำกัด](https://phishdestroy.github.io/TgWitness/th/docs/reference/evidence/#handover-extract) เมื่อผู้รับควรได้รับเฉพาะข้อมูลที่เลือกและได้รับอนุญาตเท่านั้น

### อ่านการแก้ไข การลบ และ ID ที่ขาด

การแก้ไขจะแสดงข้อความ **"ก่อน**" และ **"หลัง"** ที่บันทึกไว้ และเน้นคำที่เปลี่ยนแปลง การลบจะแสดงเวอร์ชันล่าสุดที่บันทึกไว้ก่อนการแจ้งเตือน หากไม่มีเนื้อหา ก่อนหน้านี้ที่ถูกบันทึกไว้ รายงานจะระบุไว้อย่างชัดเจน เมื่อคุณเลือกเฉพาะการแก้ไขหรือการลบ เวอร์ชันก่อนหน้าจะยังคงใช้งานได้ในฐานะบริบทที่ระบุไว้อย่างชัดเจนนอก ตัวกรอง ข้อความที่ไม่เกี่ยวข้องจะไม่ถูกเพิ่มเข้าไปในประวัติเหล่านี้

**ID ข้อความที่ยังไม่ถูกสังเกตคือ**ช่องว่างระหว่างหมายเลขที่ทราบในแชทที่เลือกและ ช่วง ID ที่กำหนดจากวันที่ ทุกบันทึกแหล่งที่มาที่ทราบจะถูกตรวจสอบก่อนที่จะประกาศ หมายเลขใดเป็น "ยังไม่ถูกสังเกต": การกรองผู้เขียนอื่น ประเภทเหตุการณ์ หรือวันที่ออก ไม่สามารถสร้างช่องว่างที่ผิดพลาดได้ ข้อความที่บันทึกไว้ที่อยู่ติดกันจะถูกกำหนดเป็นบริบท (context) การขาดหายไปของ หมายเลขหนึ่งไม่ได้หมายความว่าข้อความนั้นเคยมีอยู่หรือถูกลบ; การแจ้งเตือนการลบ และการตรวจสอบซ้ำที่ไม่สำเร็จยังคงเป็นประเภทเหตุการณ์ที่แยกกัน

### เลือกแบบออกแบบ

มีแบบออกแบบ 8 หน้าสำหรับรายงาน HTML ของบันทึกและแชทเดี่ยว รวมถึงรายงาน PDF ที่ลงนาม รายงานเหล่านี้ใช้ข้อมูลและวิธีการคำนวณเดียวกัน แต่มีหน้าปก รูปแบบตัวอักษร หัวข้อบท ตาราง และระยะห่างที่แตกต่างกัน

| การออกแบบ | สไตล์การอ่าน |
| --- | --- |
| แบบคลาสสิก | แฟ้มเอกสารแบบดั้งเดิมที่มีปกสีเข้มและส่วนต่าง ๆ ที่มีการกำหนดหมายเลข |
| บรรณาธิการ | หน้าชื่อหนังสือแบบ serif ในกรอบ มีขอบกระดาษกว้าง และแถบแบ่งบทที่แคบ |
| ข้อมูลสรุป | หน้าปกที่กะทัดรัดด้วยสันสีน้ำเงินเข้ม หัวข้อสั้น และตารางที่จัดวางชิดกัน |
| วิเคราะห์ข้อมูล | หน้าปกแบบแบบสำรวจ แผนภูมิแบบโมดูลาร์ และรูปภาพแบบตัวอักษรความกว้างคงที่ |
| ด้านเทคนิค | สมุดบันทึกที่มีเส้นบรรทัด, แถบอ้างอิงที่มีหมายเลข และตารางเปรียบเทียบที่แม่นยำ |
| ภาพรวม | หน้าปกแบบพาโนรามา, ระยะห่างระหว่างบรรทัดที่กว้างขวาง และรูปภาพสรุปที่โดดเด่น |
| ชุดบทความ | ใช้ส่วนแบ่งเนื้อหาและจัดกลุ่มบทสำหรับผลการค้นพบ ขอบเขต การเปลี่ยนแปลง และบันทึกการสังเกต |
| Ledger & margin | บทที่มีหมายเลขพร้อมขอบกระดาษกว้าง ตารางและแผนภูมิที่แม่นยำ รวมถึงข้อความบันทึกการสนทนาที่แยกออกมาเป็นหน้าต่างหาก |

การออกแบบจะถูกบันทึกตามพื้นที่ทำงานและบันทึกไว้ในไฟล์ manifest การส่งออกที่ลงนามแล้ว HTML ทำงานได้แบบออฟไลน์ รองรับธีมสีอ่อนและสีเข้ม และปรับให้เหมาะกับหน้าจอแคบ และภาษาที่เขียนจากขวาไปซ้าย PDF แบบเนทีฟใช้ฟอนต์ที่รวมมาในตัว; การออกแบบ Editorial รวมถึง Noto Serif ภายใต้ใบอนุญาต SIL Open Font License ที่รวมมาในตัว ชุดการอ่านและ Ledger & margin ยังใช้กับภาพรวมบัญชี การสนทนาในบัญชี และสำเนาที่แชร์ด้วย

ไฟล์ PDF ภาษาจีน ภาษาญี่ปุ่น และภาษาเกาหลี ยังจำเป็นต้องมีฟอนต์ที่เหมาะสมบนเซิร์ฟเวอร์, เช่น Noto Sans CJK ที่ติดตั้งทั่วระบบหรือวางไว้ในโฟลเดอร์ `TGWITNESS_FONT_DIR` หากฟอนต์ดังกล่าวไม่มีอยู่ ไฟล์ ZIP จะเก็บรายงาน HTML และ JSON ไว้

การออกแบบทั้งสองนี้รวมถึงบันทึกที่อ่านได้โดยไม่ต้องใช้ JavaScript สำหรับการ ส่งออกข้อมูลขนาดใหญ่ มุมมองนี้สามารถแสดงได้สูงสุด 500 รายการเต็มภายในงบประมาณข้อมูลเข้า 8 MiB; รายงานจะระบุขีดจำกัดและลิงก์ไปยังตัวดูข้อมูลแบบเต็มและบันทึกต้นฉบับ ไดเรกทอรีบัญชีและดัชนีความสัมพันธ์อธิบายตัวอย่างการอ่านเดียวกันนั้น ไม่ใช่ผู้เข้าร่วมทั้งหมด แผนภูมิบันทึกเต็มรูปแบบยังคงรักษาขอบเขตที่ระบุไว้แยกต่างหาก

### เลือกเนื้อหา

| เนื้อหาที่กำหนดไว้ล่วงหน้า | รวมไว้ตามค่าเริ่มต้น |
| --- | --- |
| แฟ้มคดี | กิจกรรม เวลาการสังเกต ผู้เข้าร่วม การสนทนา และข้อความบันทึกการสนทนา |
| ข้อมูลสรุป | ภาพรวมกิจกรรมโดยไม่รวมอันดับผู้เข้าร่วมหรือข้อความบันทึกการสนทนา |
| การตรวจสอบกิจกรรม | กิจกรรม เวลาการสังเกต ผู้เข้าร่วม การสนทนา และเนื้อหา พร้อมด้วยแหล่งอ้างอิงและตัวเลขที่แม่นยำ |
| รายงานตามสั่ง | คุณสามารถจัดรวมแผนภูมิ บทถอดความ และตัวอย่างแสดงผลตามความต้องการของคุณเอง |

การเปลี่ยนค่าตั้งล่วงหน้าจะรักษาการออกแบบ รายละเอียดคดี และวิเคราะห์ที่เขียนไว้ไว้ครบถ้วน การตรวจสอบความสมบูรณ์ การครอบคลุม ข้อจำกัด และคำแนะนำการตรวจสอบจะยังคงอยู่ในทุกการออกแบบ บันทึกต้นฉบับในไฟล์ ZIP จะไม่เปลี่ยนแปลงเมื่อซ่อนแผนภูมิหรือข้อความถอดเสียง

**หมาย**เหตุการตรวจสอบ (**Examination notes**) ที่เป็นตัวเลือกประกอบด้วยคำถาม วิธีการ ผลการตรวจสอบ และ ข้อสรุปที่เขียนโดยผู้เขียนรายงาน ให้อ้างอิงไฟล์ต้นฉบับและหมายเลขบันทึก ในผลการตรวจสอบ ลายเซ็นจะรักษาข้อความที่ผู้เขียนเขียนไว้เหล่านี้ไว้พร้อมกับ รายงาน; การสังเกตจากแหล่งข้อมูลและคำอธิบายของผู้เขียนยังคงสามารถระบุได้ การส่งต่อที่ถูกลดขนาดจะละเว้นบันทึกส่วนตัวเหล่านี้และแผนภูมิบันทึกเต็มรูปแบบ ตัวเลือกแผนภูมิและ การตรวจร่างกายใช้กับรายงานบันทึก

เลือกกิจกรรมตามช่วงเวลา, แผนที่ความร้อน UTC ตามวันในสัปดาห์/ชั่วโมง, อันดับผู้เข้าร่วม, อันดับการสนทนา และองค์ประกอบของบันทึก เลือกกลุ่มที่จัดอันดับ 5–30 กลุ่ม และชื่อแทนผู้เข้าร่วมที่เป็นกลาง หรือ ID บัญชี ผู้ส่งที่ไม่ทราบตัวตนและผู้เข้าร่วมที่เหลือจะอยู่ใน แถวแยกต่างหาก ชื่อแทนมีผลต่อแผนภูมิเท่านั้น; บันทึกต้นฉบับยังคงเก็บรักษาตัวตนของผู้ส่งไว้

ตัวอย่างการออกแบบจะอัปเดตจากฉบับร่างที่ยังไม่บันทึก โดยใช้ส่วนหน้าปก ส่วนการตรวจสอบ และ ส่วนแผนภูมิสำหรับการผลิต ซึ่งจำกัดให้แสดงเฉพาะข้อมูลที่ตรงกันใน 50,000 บันทึกต้นฉบับแรกเท่านั้น ตัวอย่างข้อมูลด้านล่าง จะคำนวณการเลือกทั้งหมด โดยไม่มีการลงนาม และไม่บันทึกการแก้ไข ปุ่มหน้าปกและแผนภูมิจะสลับส่วนที่เกี่ยวข้อง นี่ไม่ใช่การดูตัวอย่าง PDF ที่สมบูรณ์ **การบันทึกการตั้งค่ารายงาน**จะนำตัวเลือกไปใช้กับ การส่งออกในอนาคต; ไฟล์ที่ลงนามแล้วไม่สามารถเปลี่ยนแปลงได้ PDF ใช้หน้าปกที่เลือกไว้, รูปแบบตัวอักษร, การจัดวางบท และข้อมูลรวมที่เลือกไว้เช่นเดียวกับ HTML และ JSON ที่ลงนามแล้ว

การประเมินความน่าเชื่อถือ ข้อจำกัดการครอบคลุม และคำแนะนำการตรวจสอบยังคงอยู่ การซ่อนกราฟหรือข้อความถอดความที่อ่านได้จะไม่ลบแถวข้อมูลแหล่งที่มาที่มีอำนาจ ออกจากไฟล์ ZIP ซีรีส์กราฟที่ถูกปิดใช้งานจะถูกตัดออกจาก JSON วิเคราะห์; ใช้ การส่งออกแบบย่อเพื่อจำกัดการเปิดเผยข้อมูลบันทึกแหล่งที่มา

ตัวกรองการเลือกข้อมูลใช้กับรายงานแบบบันทึกประจำวัน; การส่งออกบัญชีและการแชร์จะรักษา ขอบเขตการเก็บรวบรวมและการเปิดเผยข้อมูลของตนเองไว้

การตั้งค่าการออกแบบ/แผนภูมิที่ใช้ร่วมกันจะถูกตรึงไว้ในการส่งออกแชท/บัญชีใหม่และ ตัวอย่างการแชร์บัญชี การตั้งค่าภาษาและความเป็นส่วนตัวของบัญชี/การแชร์ยังคงเป็นอิสระ; บันทึกคดีส่วนตัวและบันทึกการตรวจสอบจะไม่ถูกคัดลอกเข้าไปในการส่งออกเหล่านี้ รายงานบัญชีและ การแชร์ยังคงอยู่ในรูปแบบ HTML ที่ได้รับการปกป้องโดยไฟล์แมนิเฟสต์ของไฟล์เก็บถาวรที่ลงนามแล้ว Journal, การส่งต่อ Journal แบบย่อ และชุดเครื่องมือแชทเดี่ยว ยังให้ไฟล์ PDF ที่ลงนามแล้วด้วย

### ข้อมูลที่แสดงในแผนภูมิ

กิจกรรมใน Journal และ heatmaps นับ**การสังเกตการณ์**ใหม่, ในอดีต, ที่กู้คืนได้, ที่แก้ไข, ที่ลบ และ ที่หายไประหว่างการตรวจสอบซ้ำ ตามเวลาการสังเกตการณ์ของผู้เก็บข้อมูลใน UTC. Heartbeats และใบยืนยันการรับไฟล์แนบถูกยกเว้น การจัดอันดับผู้เข้าร่วมนับเฉพาะการสังเกตข้อความใหม่, ประวัติ และที่กู้คืนได้: ผู้ส่งไม่ถูกประกาศว่าเป็นผู้แก้ไขหรือ ผู้ลบ การสังเกตที่ซ้ำกันอาจอธิบายข้อความ Telegram เดียวกัน

การวิเคราะห์บันทึกจะเก็บรักษาจำนวนตามประเภท, การอ้างอิงบันทึกแรก/สุดท้าย และ SHA-256 ของไฟล์ `events.jsonl` ที่แหล่งที่มา รูปภาพแสดงค่าที่แม่นยำใน HTML และ PDF กลุ่มข้อมูลรายวัน จะเปลี่ยนเป็นกลุ่มข้อมูลรายเดือนเมื่อเกิน 366 วันที่มีการบันทึก; กราฟจะรวมข้อมูลเหล่านี้เป็นช่วงสูงสุด 36 ช่วงที่มีความกว้างเท่ากัน เมื่อมีตัวระบุที่ไม่ซ้ำกันมากกว่า 100,000 ตัว หรือ 1,200 เดือน แผนภูมิที่เกี่ยวข้องจะไม่สามารถใช้งานได้ แต่จำนวนรวมที่แม่นยำยังคงสามารถดูได้

แผนภูมิ Snapshot และแผนภูมิการแบ่งปันบัญชีจะนับเฉพาะแถวข้อความที่ไม่ใช่บริการที่รวมอยู่ โดยใช้เวลาข้อความที่บันทึกไว้ การคำนวณค่ารวมจากการแบ่งปันจะดำเนินการหลังจากการลบข้อมูลที่ละเอียดอ่อน และการกรอง แผนภูมิเหล่านี้ใช้ช่วงเวลา UTC ที่มีความกว้างเท่ากันสูงสุด 90 ช่วง และเก็บรักษา ค่าการจัดกลุ่มได้สูงสุด 10,000 ค่า; จำนวนที่เกินจะถูกระบุอย่างชัดเจนและปรับให้สอดคล้องกัน ช่วงสุดท้ายอาจสั้นกว่าได้ วันที่ไม่ทราบหรือวันที่ไม่ถูกต้องจะไม่ถูกนำเข้าสู่แผนภูมิเวลา

ช่วงที่ว่างหมายความว่าไม่มีการสังเกตการณ์ใดถูกรวมไว้; โปรดตรวจสอบความครอบคลุมเพื่อหาช่องว่าง. แผนภูมิเหล่านี้ อธิบายกิจกรรมที่บันทึกไว้ ผู้ส่งที่ไม่ทราบตัวตนยังคงอยู่ในหมวดหมู่แยกต่างหาก และ การตรวจสอบแต่ละครั้งถูกรายงานแยกกัน

เมื่อรวมไฟล์ `analytics.json` เข้าไป ไฟล์นี้จะได้รับการปกป้องโดยแฮชไฟล์ที่ลงนามของอาร์ไคฟ์ `report.json` ของ Journal จะฝังข้อมูลรวมที่เลือกไว้เดียวกัน การตรวจสอบลายเซ็น จะตรวจจับไบต์ที่เปลี่ยนแปลง เพื่อตรวจสอบตัวเลข ให้คำนวณข้อมูลรวมของ Journal ใหม่ด้วย `report_analytics.Analytics` และ `selected` หรือ คำนวณข้อมูลรวมของ snapshot ด้วย `snapshot_analytics.collect` และ `project`

### Anomaly indicators

**Preview.** Evidence reports add an **Anomaly indicators** section computed by registered processors (`tgwitness/metrics/`, one file per metric). The report names every processor that ran with its version, and prints its method under its table, so the computation can be repeated from `events.jsonl` with `tgwitness.metrics.run`.

| Processor | สิ่งที่แสดง |
| --- | --- |
| `first_time_posters_over_time` v1 | First-time posters and messages per UTC day. A flag requires at least five first-time posters and three times their median, with message volume at most 1.5 times its median. The baseline uses at least seven observed days within the previous 14 calendar days, after seven days of warm-up. |
| `service_vs_message_ratio` v1 | Distinct saved message numbers per chat and the share used by service messages. It describes a numbering; it does not explain a particular missing number. |
| `join_leave_per_month` v1 | Joins, departures and removals or bans per month, one per person, chat, change and day. |
| `pinned_per_month` v1 | Pin service messages, unpin notices, and pinned messages added or removed between chat-state snapshots, per month. |

**Parameters → Report metrics** selects processors and the number of displayed rows, including in filtered reports. Daily and monthly tables show recent rows, service-share tables rank chats by saved message count. Totals cover every row.

จากแหล่งที่มาที่ตรวจสอบแล้ว ให้สร้างแบบทั้งแปดแบบที่กล่าวถึงข้างต้นจากนิตยสารสมมติเดียวกัน:

```
python tools/build_report_styles.py --output test-results/report-styles
```

เปิดไฟล์`index.html` ที่สร้างขึ้นเพื่อเปรียบเทียบรายงาน HTML แบบครบถ้วน, PDF ที่ลงนามแล้ว และ ไฟล์ ZIP ทุกการออกแบบใช้แหล่งข้อมูลต้นฉบับเดียวกัน ให้ใช้โฟลเดอร์ผลลัพธ์ใหม่สำหรับ การรันแต่ละครั้ง เพื่อให้ตัวอย่างที่ลงนามไว้ก่อนหน้านี้ยังคงถูกเก็บรักษาไว้

![แฟ้ม HTML สมมติ](https://phishdestroy.github.io/TgWitness/assets/dossier-en.png)

หน้า HTML เปิดด้วยหน้าปกคดีและข้อมูลสำคัญ แผนที่หลักฐานที่มีหมายเลขเชื่อมโยง ไปยังแต่ละผลการค้นพบ ข้อเท็จจริงที่สนับสนุน ข้อจำกัด และการตรวจสอบอิสระ บันทึกที่สามารถค้นหาได้ และอ้างอิงบันทึกที่เสถียรยังคงใช้งานได้ในตัวดูแบบออฟไลน์ การออกแบบปรับให้เหมาะสมกับหน้าจอแคบ ทั้งธีมและเบราว์เซอร์ที่ไม่มี JavaScript

ไฟล์ PDF ที่ลงนามมีหน้าปก A4 เฉพาะ, หมายเลขอ้างอิงรายงานและ QR, บทสรุปสำหรับผู้บริหาร, แผนที่หลักฐาน, ข้อค้นพบที่มีหมายเลข และบุ๊กมาร์กเอกสาร ส่วน หัวและท้ายหน้าช่วยระบุตัวตนของรายงาน QR ใช้เพื่อระบุเนื้อหา; ไม่ใช่ ผลการตรวจสอบอิสระ การพิมพ์จากเบราว์เซอร์เป็นเอกสารที่แยกต่างหากจาก ไฟล์ PDF ที่ลงนามด้วยระบบเข้ารหัสนี้

เส้นเวลาการสังเกตการณ์จัดวางช่วงเวลาการสังเกตการณ์ที่บันทึกไว้และการหยุดชะงัก บนแกน UTC เดียวกัน พื้นที่ว่างไม่ได้หมายความว่ามีข้อมูลครอบคลุม; ตารางรายละเอียด รักษาช่วงเวลาที่แม่นยำไว้ ZIP ดังกล่าวประกอบด้วยรายงานที่อ่านได้ JSON ที่ลงนาม บันทึกต้นฉบับ และคำแนะนำการตรวจสอบ

สร้างแฟ้มข้อมูลใหม่ที่สมมติขึ้นในภาษาอังกฤษ/รัสเซีย/เยอรมัน พร้อมติดตั้ง สภาพแวดล้อมการพัฒนา:

## การอ่านกรณีตัวอย่าง

สำหรับบันทึกที่มี 1,200 รายการ พร้อมด้วยเวลาประทับที่ได้รับการยืนยันที่รายการที่ 1,000 รายงานจะระบุรายการ 200 รายการที่เกิดขึ้นภายหลัง ซึ่งอยู่นอกขอบเขตของเวลาประทับดังกล่าว นี่เป็น ขอบเขตบนของการมีอยู่ของจุดตรวจสอบ (checkpoint) ไม่ใช่หลักฐานของเวลาส่ง ของข้อความแต่ละข้อความ หากไฟล์เวลาประทับอีกสามไฟล์ไม่ผ่านการตรวจสอบความถูกต้องหรือไม่สามารถตรวจสอบได้ ไฟล์เหล่านั้นจะถูกนับแยกต่างหาก และไม่สามารถให้ข้อสรุปที่แน่ชัดได้

เวลาประทับที่ใช้งานได้ต้องผ่านทุกการตรวจสอบต่อไปนี้: ลายพิมพ์ของมันต้องตรงกับ จุดตรวจสอบ (checkpoint), ลายเซ็นของมันต้องเชื่อมโยงเป็นห่วงโซ่ไปยังราก TSA ที่เชื่อถือได้ในเวลาที่ประทับ, และ ลายเซ็น, กุญแจ, จำนวน และส่วนหัวของจุดตรวจสอบต้องตรงกับคำนำหน้าของบันทึก (journal prefix) อย่างแม่นยำ การวิเคราะห์เวลาประทับเพียงอย่างเดียวหรือการมีใบเสร็จรับเงิน OTS นั้นไม่เพียงพอ ผู้อ่าน ต้องเลือกราก TSA ที่เชื่อถือได้ด้วยตนเองและทำการตรวจสอบซ้ำ OTS จำเป็นต้อง มีการตรวจสอบการยืนยัน Bitcoin ของตัวเอง

| สถานะรายงาน | ความหมาย |
| --- | --- |
| ตรวจสอบระหว่างการส่งออก | เครื่องมือส่งออกได้ดำเนินการตรวจสอบตามที่ระบุไว้แล้ว แต่ยังจำเป็นต้องมีการตรวจสอบซ้ำอย่างอิสระ |
| บันทึกแล้ว; ต้องตรวจสอบ | การสังเกตหรือคำชี้แจงของผู้ดำเนินการที่อยู่เบื้องหลังจะถูกบันทึกไว้; นี่ไม่ใช่การยืนยันอย่างอิสระ |
| ไม่รวมในฉบับนี้ | ข้อความนี้ไม่มีหลักฐานสนับสนุนสำหรับคำกล่าวนี้ แต่ไม่ได้ระบุว่าไม่มีหลักฐานดังกล่าวในที่อื่น |
| ยังไม่ได้รับการตรวจสอบอย่างอิสระ | รายงานนี้ไม่ให้ผลการตรวจสอบอย่างอิสระ |
| ไม่ครบถ้วนหรือไม่มี | ข้อมูลหรือการตรวจสอบที่จำเป็นขาดหายไป ไม่ครบถ้วน หรือไม่สำเร็จ |

ตรวจสอบแต่ละข้อตรวจสอบแยกกัน พร้อมกับข้อมูลความครอบคลุมของการเก็บรวบรวมที่บันทึกไว้

## สิ่งที่การกำหนดค่าที่แข็งแกร่งต้องรักษาไว้

1. ก่อนที่จะพึ่งพาการเก็บรวบรวมข้อมูล ให้เก็บรักษาลายนิ้วมือของกุญแจผู้เก็บรวบรวมผ่าน ช่องทางที่เชื่อถือได้แยกต่างหาก แล้วเปรียบเทียบข้อมูลอ้างอิงนั้นกับกุญแจลงนามของไฟล์ที่ส่งออก
2. รักษาจุดตรวจสอบที่มีเวลาประทับอย่างอิสระ และหากมี ให้รักษา บันทึกพยาน (witness journal) ที่อยู่นอกการควบคุมทางบริหารของผู้เก็บรวบรวมข้อมูล เปรียบเทียบกับ บันทึกที่ส่งออกเพื่อตรวจสอบขอบเขตก่อนหน้านี้ของมัน
3. บันทึกขอบเขตการเก็บรวบรวมข้อมูล ช่องว่าง ตัวกรอง ข้อจำกัด และการเปลี่ยนแปลงในกระบวนการเก็บรวบรวม อธิบายช่วงเวลาที่ขาดหายไปซึ่งเกี่ยวข้องกับข้อกล่าวหาจริง โดยแยกแยะให้ชัดเจนระหว่าง ID ข้อความที่ไม่ได้สังเกตเห็น ประกาศการลบ และผลการตรวจสอบซ้ำที่ไม่สำเร็จ
4. รักษาไฟล์ ZIP ต้นฉบับและค่าแฮชของพวกมันไว้ บันทึกผู้ถือแต่ละราย การโอนย้าย วันที่ และวัตถุประสงค์ เก็บรักษาคำชี้แจงของผู้ดำเนินการและบันทึกคดีที่ระบุไว้พร้อมกับข้อมูลเหล่านั้น
5. สำหรับ VM ที่เป็นความลับ ให้รักษาและตรวจสอบอย่างอิสระต่อคำเสนอราคา, การท้าทาย, ห่วงโซ่ใบรับรอง Intel, การวัดค่า, แหล่งที่มาที่แม่นยำ และเงื่อนไขการจัดการกุญแจ เก็บผลการตรวจสอบการรับรองไว้พร้อมกับหลักฐานที่ได้รับการตรวจสอบแล้ว

See [verification scope](https://phishdestroy.github.io/TgWitness/th/docs/reference/evidence/#verification-scope) for the checks of acquisition, archive integrity, time and collection coverage in each mode.

## การตรวจสอบของผู้รับ

ใช้การติดตั้ง TgWitness ที่เชื่อถือได้และลายนิ้วมือ (fingerprint) ที่ได้รับมาอย่างอิสระ:

```
python -m tgwitness.verify evidence.zip --fingerprint TRUSTED_SHA256
python -m tgwitness.verify evidence.zip --fingerprint TRUSTED_SHA256 --tsa-ca tsa-root.pem
python -m tgwitness.verify evidence.zip --fingerprint TRUSTED_SHA256 --witness witness.zip --witness-fingerprint WITNESS_SHA256 --require-witness
python -m tgwitness.verify evidence.zip --fingerprint TRUSTED_SHA256 --check-drand
```

ไฟล์ ZIP ของพยานต้องมาจากแหล่งที่เชื่อถือได้อย่างอิสระ; ต้องรักษาคีย์ และที่มาของไฟล์ไว้ด้วย ให้คงไว้ซึ่งคำสั่ง เวอร์ชันของเครื่องมือ ผลลัพธ์ ค่าแฮชของข้อมูลเข้า ที่ได้รับการตรวจสอบ และคำถามที่ยังไม่ได้รับการแก้ไข การตรวจสอบ Beacon เป็นการตรวจสอบออนไลน์ที่แยกต่างหาก; ตัวสร้างรายงานจะไม่ติดต่อกับบริการใด ๆ เพียงเพื่อแสดงรายงาน

ในกรณีที่มีข้อพิพาทเกี่ยวกับข้อความเฉพาะ ให้อ้างอิงถึงข้อมูลอ้างอิงของคลังข้อมูล, ไฟล์และข้อมูลอ้างอิงที่มีอำนาจ จากนั้นอธิบายช่วงเวลาที่เกี่ยวข้อง, ช่องว่างในการครอบคลุม, การเลือกข้อมูล และข้อมูลสนับสนุน สำหรับสำเนาที่แบ่งปัน ให้ตรวจสอบด้วย การเปลี่ยนแปลงที่บันทึกไว้และข้อมูลอ้างอิงไปยังคลังข้อมูลต้นฉบับ ตัวกรองส่วนตัวและการ แมปข้อมูลประจำตัวจะอยู่นอกขอบเขตการประเมินสาธารณะ

การตรวจสอบ PDF ที่ลงนามจะตรวจจับการเปลี่ยนแปลงในไบต์ที่อยู่ในขอบเขตการตรวจสอบ ให้เก็บรักษา ไฟล์ดิจิทัลต้นฉบับและผลการตรวจสอบไว้พร้อมกับภาพหน้าจอหรือสำเนาที่พิมพ์ออกมา
