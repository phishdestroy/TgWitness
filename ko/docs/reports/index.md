# 보고서 설계

Canonical page: https://phishdestroy.github.io/TgWitness/ko/docs/reports/

독자를 사건의 질문에서 저장된 기록으로 곧장 안내합니다.

Report studio는 귀하가 고른 데이터, 변경 기록, 차트, 조사 결과를 한데 모읍니다. 여덟 가지 디자인, HTML과 네이티브 PDF. 모든 HTML, PDF, JSON 보고서는 귀하의 키로 봉인됩니다.

## 3단계로 보고서 작성하기

1. **내보내기 → 구성 및 미리 보기 → 데이터**: 작업 공간 전체, 또는 채팅, 작성자, 날짜(UTC, TgWitness가 기록을 본 시각), 기록 유형을 고릅니다.
2. **디자인 및 내용**: 디자인과 들어갈 내용을 고릅니다: 차트, 참여자, 대화록, 변경, Case Board 항목, 사건 세부 정보와 메모.
3. **미리 보기**: 개수, 활동, 샘플, 빠진 ID 범위를 확인합니다. 저장한 다음 필요한 형식을 다운로드합니다.

### 독자가 이해하기 쉽도록 저장된 자료를 체계적으로 정리하십시오.

합성 예시 · 개략적인 레이아웃이며, 실제 생성된 보고서가 아님

1. **선택.** 해당 사건에 대한 두 개의 채팅과 관찰 기간을 선택하십시오.
2. **작성해 주십시오.** 레이아웃을 선택하고 질문에 답하는 섹션을 골라주세요.
3. **미리 보기.** 선택된 개수와 저장된 변경 전후 텍스트를 검토하십시오.
4. **검증하십시오.** 최종 파일을 생성하고, 신뢰할 수 있는 작업 공간 지문과 대조하여 서명을 확인하십시오.

#### 주요 사항

채팅 2건 · 관찰일 1일

메시지, 수정 내역 및 삭제 알림

#### 보고서 구조

##### 결제 수취처 변경

사건 질문 → 범위 → 조사 결과 → 기록 참조

**메시지 맥락**

관찰 사항 #142: “새로운 결제 링크를 사용하세요.”

**저장된 변경 사항**

변경 전: old.example.invalid → 변경 후: new.example.invalid

#### 선택 사항 검토

18건의 검토 의견 · 2건의 저장된 수정 사항

전송, 편집 및 확인 시간에는 각각 별도의 라벨이 지정되어 있습니다.

#### 최종 결과물

서명된 PDF + 서명된 JSON, 또는 읽기 가능한 보고서가 포함된 서명된 ZIP 파일

수신자는 파일과 신뢰할 수 있는 지문을 확인합니다.

## 읽기 스타일 선택

**Classic, Editorial, Briefing, Analytics, Technical, Overview, Reading series, and Ledger & margin**: 같은 기록, 다른 모습. 바꿔도 선택과 메모는 유지됩니다. 25개 언어 중 어느 것이든.

PDF는 내장 글꼴로 만들어지며 브라우저가 필요 없습니다. 중국어, 일본어, 한국어에는 서버에 Noto Sans CJK 같은 글꼴(시스템 전체 또는 `TGWITNESS_FONT_DIR`)이 필요하며, 없으면 HTML과 JSON만 나옵니다.

## 변경 사항을 맥락과 함께 파악하십시오

편집은 전후를, 삭제는 마지막으로 저장된 버전을 보여 줍니다. 답장, 전달, 반응, 버튼, 첨부 파일은 참조를 유지합니다.

디자인 미리 보기는 처음 50,000개 기록을 쓰고, 데이터 미리 보기는 모든 것을 정확히 셉니다. 최종 페이지 배치는 PDF를 생성해서 보십시오.

## 수신자용 사본을 신중하게 선택하십시오.

필터는 보고서 모양만 바꾸며, 증거 ZIP에는 여전히 전체 저널과 파일이 들어 있습니다. 받는 사람이 더 적게 받아야 하면 [최소화된 인계](https://phishdestroy.github.io/TgWitness/ko/docs/handover/)를 사용하십시오. 더 보기: [보고서 내용](https://phishdestroy.github.io/TgWitness/ko/docs/reference/case-reports/), [내보내기 검증](https://phishdestroy.github.io/TgWitness/ko/docs/exports/).
