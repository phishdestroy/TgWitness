エクスポートと検証

受信者が、収集ワークスペースおよびその保存履歴と照合できるファイルを提供してください。

参照情報を保持する署名付きZIPファイルをエクスポート受信者が検証します

署名やチェックポイントについて初めてお知りになる方へ。サンプルレコードを変更して、どのチェックがその変更を検知するかを確認してみてください。

収集者とは別の場所にコピーを保管したいですか？ S3の設定、オブジェクトロック、または検証済み復元をご覧ください。

信頼できる参考資料としてご利用ください

ワークスペースの公開鍵のフィンガープリントは、コレクターの外部に保存してください。収集中は、署名済みのチェックポイントを別の場所に保管するか、独立した証人（ウィットネス）を使用してください。これらの参照情報により、受信者は鍵および以前のジャーナルの境界を確認することができます。

署名付きZIPファイルをダウンロードする

「エクスポート」を開き、署名付き証拠用ZIPファイルを作成してください。これには、ワークスペースのジャーナル全体と署名付きファイルマニフェストが含まれます。「Report Studio」を使用して読みやすいレポートを作成するか、引き渡し用抽出機能を使用して、選択した最小限のデータのみを提供してください。

HTML、PDF、JSON形式のレポートにはそれぞれ独自の署名付きシールが付与されており、個別に検証が可能です。CSVは分析に便利なコピーです。検証済みのZIPファイル内に含まれる正確なCSVファイルを使用して、その完全性を確認してください。受信者がソースレコードや添付ファイルも必要とする場合は、署名付きZIPファイルを保管しておいてください。

信頼できるTgWitnessのコピーで検証してください

インストール済みのプロジェクト環境において、サンプルとなるフィンガープリントおよびファイルパスを以下のように置き換えてください：

python -m tgwitness.verify evidence.zip --fingerprint TRUSTED_PUBLIC_KEY_SHA256 --checkpoint retained-checkpoint.json

両方の参照が有効である場合、結果として「key_pinned: true」および「checkpoint_checked: true」が報告されます。検証結果は元のアーカイブと共に保管してください。保持するチェックポイントは、エクスポートの境界点以前でなければなりません。

検証結果を使用する

  • 納品されたファイルを確認してください。マニフェストには各ファイルのハッシュ値が紐付けられており、レコードの署名には保存されたログが紐付けられています。ファイルの変更やレコードチェーンの破損が検出されます。
  • ワークスペースのIDを確認してください。独立して保持されているフィンガープリントにより、期待した署名鍵であることが確認されます。
  • 以前の境界と比較してください：保持されたチェックポイントは、引き渡し前に保存されたジャーナルプレフィックスと照らし合わせてエクスポート内容を検証します。
  • 収集範囲を確認してください。収集漏れ、取得結果、および「送信→編集→削除」の制御テストにより、この設定で捕捉された事象が説明されます。

これらの結果は、受領者のコピーに含めてください。検証によって、チェックの範囲、およびソースの主張と収集範囲に関する個別の評価がどのように確定されるかを確認してください。

S3 オフサイトコピーの設定

実行中のワークスペースで、「エクスポート」→「オフサイトコピー」を開いてください。このオプション機能は、AWS S3 およびその他の S3 互換サービスに対応しています。この機能により、ジャーナルのセグメント、保存された写真やファイル、タイムスタンプ付き応答を含むチェックポイント、および完了したチャットのエクスポートデータがコピーされます。すべてのオブジェクトは、アップロード前にコレクター上で AES-256-GCM を使用して暗号化されます。

オンラインデモでは、アップロード機能を無効にした状態で、同様の操作画面をご覧いただけます。ストレージの認証情報は、ご自身が実行しているワークスペース内でのみ入力してください。

「エクスポート」→「オフサイトコピー」の保存設定
分野入力内容
エンドポイントバケットパスや認証情報を含まない、ストレージサービスのURLです。架空の例：https://s3.example.invalid。
地域ご利用のプロバイダーが指定する地域です。アプリケーションのデフォルトは「us-east-1」です。

アクセスキーID / シークレットアクセスキーストレージの認証情報を両方とも同時に入力してください。これらはワークスペースの保管庫に保存されます。保存済みのペアを維持するには、以降の保存時には両方を空欄のままにしてください。
パス形式のアドレスプロバイダーの設定に応じて、有効化されている場合は「endpoint/bucket」、無効化されている場合は「bucket.endpoint」を使用してください。
コピー間隔1分から1,440分まで設定可能です。デフォルトは5分です。スケジュールされたバックアップを行うには、アプリケーションが実行されている必要があります。
オブジェクトロックの保持期間Object Lockをサポートするバケットの保存期間と保存モードについてです。「0日」に設定すると、バケットのデフォルトの保存期間が適用されます。
  1. プロバイダーでバケットを作成し、保存先と認証情報を入力してください。準備中は「オフサイトコピーを保持する」のチェックを外したままにし、その後「オフサイトコピーを保存」を選択してください。
  2. 「接続テスト」を選択してください。これにより、暗号化されたテストオブジェクトがアップロードされ、ストレージからの応答が確認されます。
  3. 「暗号化キーのダウンロード」を選択してください。そのファイルはコレクターとは別に保管してください。復元に必要となります。
  4. 「オフサイトコピーを保持する」チェックボックスを有効にして、再度保存してください。「今すぐコピー」を選択して手動で実行するか、スケジュールを実行したままにしておいてください。

保存状況とコピー進捗の確認

[詳細オプション] から、保存期間を選択し、バケットがオブジェクトロックに対応している場合は [GOVERNANCE] または [COMPLIANCE] を選択してください。TgWitness は、アップロードされたオブジェクトの保存モードと期限を読み取ります。個別の保存結果（「確認済み」、「保存対象外」、または「チェック失敗」）を確認してください。

パネルには、前回の処理結果、オブジェクト数、転送されたバイト数、コピーされたジャーナルの境界、およびエラーがあればその内容が報告されます。ローカルメディアが欠落または変更されている場合は報告され、次の処理で再試行されます。そのメディア以降のファイル、チェックポイント、およびエクスポートキューに追加されたデータは、引き続きコピー可能です。

アップロードには、ワークスペースの「Direct」、「SOCKS5」、または「HTTP」ルートを使用します。S3へのコピーにはこれらのルートのいずれかを選択してください。MTProxyのみのルートを選択した場合、コピーはエラーとなり保留状態となります。

復元キーは別の場所に保管してください

ダウンロードされたJSONには、復号鍵、保存先設定、ワークスペースオブジェクトプレフィックス、および署名鍵のフィンガープリントが含まれています。復旧には、この鍵ファイルと、バケットへの読み取りアクセス権を持つ別のストレージ認証情報の両方が必要です。これらを復旧計画に含めておいてください。

エンドポイント、バケット、またはフォルダプレフィックスを変更した場合は、キーファイルを再度ダウンロードし、保存先の設定が一致するようにしてください。アプリケーションは、ローカルに保持されているジャーナル、ファイル、およびチェックポイントの新しいコピーを、新しい保存先で開始します。ローカルのアップロードキューからすでに削除された、完了済みのチャットのエクスポートデータは、以前の保存先に残ります。

別のマシンでの復元と検証

信頼できるTgWitnessのインストール環境、ダウンロードしたJSONキー、読み取り権限のあるストレージ認証情報、および空の出力ディレクトリをご用意ください。以下の架空の認証情報のプレースホルダーを実際の情報に置き換えてください。

Windows PowerShell

$env:TGWITNESS_S3_ACCESS_KEY = 'YOUR_READ_ACCESS_KEY'
$env:TGWITNESS_S3_SECRET_KEY = 'YOUR_READ_SECRET_KEY'
python -m tgwitness.replica restore --key-file tgwitness-replica-key.json --out restored-evidence

Linux / macOS

export TGWITNESS_S3_ACCESS_KEY='YOUR_READ_ACCESS_KEY'
export TGWITNESS_S3_SECRET_KEY='YOUR_READ_SECRET_KEY'
python -m tgwitness.replica restore --key-file tgwitness-replica-key.json --out restored-evidence

ダウンロードされたファイルおよび復号化されたオブジェクトは、ジャーナル全体、保持されているチェックポイント、保存されたメディアのハッシュ値およびサイズが検証される間、非公開の一時ストレージに保管されます。安全でないパス、矛盾するジャーナルセグメント、およびチェックポイントよりも短いジャーナルは拒否されます。検証に失敗した場合、復元されたファイルは公開されません。

復元に成功すると、コピー内に存在するデータに対して、events.jsonl、media/、checkpoints/、exports/が生成されます。復元されたデータとともに、コマンドのJSON形式の結果も保管しておいてください。

復元された資料を、独自に保持しているチェックポイントや証言記録と比較し、必要な期間について記録された収集範囲を確認してください。
