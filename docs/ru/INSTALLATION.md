<a id="install-with-one-command"></a>
## Установка с помощью одной команды

Официальный сервис загрузки проекта, `get.destroy.tools`, предоставляет инсталлятор с пошаговыми инструкциями и подписанные файлы выпуска. Он включает в себя частную среду выполнения Python и перед установкой проверяет хеши пакетов и подписи выпусков. Каждый выпуск обновляет скрипты запуска, хеши, подписи и информацию о сборке одновременно; каждая сборка также имеет неизменяемый URL-адрес выпуска.

Выберите инсталлятор с пошаговыми инструкциями для быстрой настройки или воспользуйтесь [выпусками на GitHub, исходным кодом либо Docker](QUICKSTART.md). Все это — поддерживаемые способы установки одного и того же проекта с открытым исходным кодом. Для развертывания, требующего утверждения конкретной сборки перед запуском, воспользуйтесь [функцией Проверить перед запуском](#verify-before-running) с помощью независимо хранящегося отпечатка ключа выпуска и неизменяемого URL-адреса сборки. Обновление службы загрузки не приводит к автоматическому обновлению установленной панели.

**Linux / macOS (Bash):**

```sh
curl -fsSL https://get.destroy.tools/install.sh | bash
```

На сервере Ubuntu запустите программу от имени пользователя root для установки фонового сервиса. На настольном компьютере запустите программу от имени обычного пользователя.

**Windows (PowerShell или командная строка):**

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -Command "irm https://get.destroy.tools/install.ps1 | iex"
```

В Windows права администратора не требуются. Дочерний процесс PowerShell оставляет ваш терминал открытым с отображением результата. Python и зависимости остаются в установке.

В Ubuntu выберите **Этот компьютер**, **Временная ссылка HTTPS** или **Собственный домен**. Установщик выведет адрес панели и ключ доступа. Для временной ссылки откройте указанный HTTPS-адрес в браузере и введите ключ. При локальном доступе к удалённому серверу воспользуйтесь перенаправлением SSH с вашего компьютера (`ssh -L 8787:127.0.0.1:8787 user@server`) и откройте `http://127.0.0.1:8787`. В macOS и Windows локальная панель открывается в браузере; оставьте терминал работающим.

Войдите в Telegram через панель и выберите, какие данные собирать. Сама по себе установка не запускает сбор данных Telegram.

<a id="where-everything-runs"></a>
## Где всё работает

`get.destroy.tools` — это **Cloudflare Worker, обслуживающий статические загрузки**. На нём отсутствует панель TgWitness, сеанс Telegram или база данных с доказательствами пользователей. Он не подключён к VPS проекта. Приложение работает на том компьютере, на котором вы выполняете команду.

| Установка | Программа | Данные |
| --- | --- | --- |
| Ubuntu с правами root | `/opt/tgwitness` | Системная служба: `/var/lib/tgwitness-<installation ID>`; для уточнения пути воспользуйтесь списком `tgwitness paths`. |
| Пользователь Linux / macOS | `~/.local/share/tgwitness` | `data/live` в рамках данной установки. |
| Пользователь Windows | `%LOCALAPPDATA%\TgWitness` | `data\live` в рамках данной установки. |

Установите переменную `TGWITNESS_INSTALL_DIR`, чтобы выбрать другую папку. Установленные версии и данные хранятся отдельно. Установщик не загружает ваши аккаунты, сообщения или ключи на сайт загрузки. При выборе туннеля Cloudflare трафик панели проходит через Cloudflare; использование собственного домена направляет трафик на ваш собственный сервер.

При использовании параметра `TGWITNESS_TRUSTED_PROXIES` панель принимает единственный заголовок `X-Forwarded-Proto: https`, полученный от доверенного прокси-сервера, для установки защищённых файлов cookie загрузки.

Каждая установка включает **файлы START-HERE.html** и **START-HERE.txt** с локальными путями, командами и ссылками на репозиторий. Запустите команду `tgwitness guide`, чтобы открыть руководство. В Windows используйте команду `& "$env:LOCALAPPDATA\TgWitness\bin\tgwitness.cmd" guide` в PowerShell.

<a id="full-text-search-settings"></a>
## Настройки полнотекстового поиска

[Полнотекстовый поиск](SEARCH.md) (предварительная версия) не требует настройки. Его индекс создаётся в фоновом режиме после обновления.

| Переменная или команда | Эффект |
| --- | --- |
| `TGWITNESS_FULLTEXT=disk` | По умолчанию: индекс хранится в файле `search/fulltext.sqlite3` каждой рабочей области |
| `TGWITNESS_FULLTEXT=memory` | Файл индекса отсутствует; индекс перестраивается при каждом запуске |
| `TGWITNESS_FULLTEXT=off` | Индекса нет; доступен только поиск по точному тексту |
| `tgwitness index status` | Состояние индекса каждой рабочей области |
| `tgwitness stop`, `tgwitness index rebuild`, `tgwitness start` | Перестроить каждый индекс на основе подписанного журнала |

Выбор администратора в меню **Журнал → Фильтры → Поисковый индекс** имеет приоритет над значением переменной для данной рабочей области. Команды находят каталог данных той установки, в которой они запускаются; в остальных случаях добавьте параметр ``--data-dir`` с указанием пути из списка ``tgwitness paths``. Для получения полного украинского словаря (данные под лицензией GPL-3.0) установите пакет ``pymorphy3-dicts-uk`` в среду Python данной установки.

<a id="command-line-access"></a>
## Доступ через командную строку

[Командная строка](CLI.md) (предварительная версия) считывает архив для скриптов и агентов.

| Переменная | Эффект |
| --- | --- |
| `TGWITNESS_URL` | Адрес панели для команд `tgwitness search`, `context`, `messages`, `stats` и `export`; по умолчанию `http://127.0.0.1:8787`, если установлен токен |
| `TGWITNESS_MCP_TOKEN` | Токен подключения к архиву из раздела **Дополнительные инструменты → Интеграции → MCP**, совместно используемый с клиентами MCP; параметр `--token-file` считывает его из файла |
| `TGWITNESS_DATA` | Каталог данных считывается напрямую, если не указаны параметры `--data-dir`, URL или токен |

<a id="verify-before-running"></a>
## Проверка перед запуском

Установщик встраивает открытый ключ выпуска проекта и проверяет SHA-256 и RSA-подписи пакета приложения и списка зависимостей перед их установкой. Как Bash, так и PowerShell останавливаются в случае сбоя необходимой проверки. Начальный скрипт доставляется по HTTPS и имеет собственную отдельную подпись; приведённые ниже команды также позволяют вам проверить этот скрипт перед его выполнением.

Открытый ключ выпуска — [release-signing.pub](../../deploy/installer/release-signing.pub). Его SHA-256:

```text
039d98a658ccda14253e45a00335b4a68d840976d8ec18b8d4355cc7c458447d
```

Сохраните этот отпечаток из ревизии репозитория, которому вы доверяете. Контрольная сумма с того же сервера загрузки позволяет обнаружить несоответствие; именно независимый доверенный открытый ключ служит для аутентификации подписи выпуска.

Используйте новый пустой каталог для загрузки файлов, необходимых для проверки, указанных ниже.

**Linux / macOS — запустите в новом пустом каталоге для загрузки** (требуются curl и OpenSSL):

```sh
curl -fSLO https://get.destroy.tools/install.sh &&
curl -fSLO https://get.destroy.tools/install.sh.sig &&
curl -fSLO https://get.destroy.tools/release-signing.pub &&
test "$(openssl dgst -sha256 release-signing.pub | awk '{print $NF}')" = \
  '039d98a658ccda14253e45a00335b4a68d840976d8ec18b8d4355cc7c458447d' &&
openssl dgst -sha256 -verify release-signing.pub -signature install.sh.sig install.sh &&
bash install.sh
```

Цепочка `&&` останавливается перед выполнением, если загрузка, проверка отпечатка ключа или проверка подписи завершаются с ошибкой. Если между загрузкой скрипта и проверкой его подписи произошла публикация, загрузите и то, и другое заново. Старые установщики сохраняют неизменяемые URL-адреса пакетов.

**Windows — проверьте SHA-256 перед запуском:**

```powershell
Invoke-WebRequest https://get.destroy.tools/install.ps1 -OutFile install.ps1 -UseBasicParsing
Get-FileHash .\install.ps1 -Algorithm SHA256
Invoke-RestMethod https://get.destroy.tools/SHA256SUMS.txt
```

Сравните хеш с строкой в файле ``install.ps1``. Для независимой проверки подписи используйте OpenSSL (например, из Git Bash) и тот же отпечаток открытого ключа, указанный выше:

```sh
curl -fSLO https://get.destroy.tools/install.ps1 &&
curl -fSLO https://get.destroy.tools/install.ps1.sig &&
curl -fSLO https://get.destroy.tools/release-signing.pub &&
test "$(openssl dgst -sha256 release-signing.pub | awk '{print $NF}')" = \
  '039d98a658ccda14253e45a00335b4a68d840976d8ec18b8d4355cc7c458447d' &&
openssl dgst -sha256 -verify release-signing.pub -signature install.ps1.sig install.ps1 &&
powershell.exe -NoProfile -ExecutionPolicy Bypass -File install.ps1
```

Сама система установки Windows использует верификатор .NET для проверки подписей пакетов и не требует использования OpenSSL. Речь идет об отдельных подписях RSA-3072 / SHA-256, а не о подписях Authenticode. В [манифесте](https://get.destroy.tools/manifest.json) указаны версия программного обеспечения, точный коммит Git, неизменяемый идентификатор выпуска и SHA-256 каждого артефакта. На странице имеются ссылки на соответствующий исходный код. Манифест и список контрольных сумм также имеют отдельные подписи (`manifest.json.sig` и `SHA256SUMS.txt.sig`).

<a id="update-an-existing-installation"></a>
## Обновление существующей установки

**Новая публикация обновляет сайт загрузки; установленные программы обновляются при повторном запуске установщика.** Автоматического обновления или автоматического перезапуска запущенной коллекции не предусмотрено. Текущий канал установщика — **preview**; он использует опубликованные и проверенные сборки из ветки `main`, коммит которых может быть более поздним, чем последний пронумерованный релиз на GitHub. Версия, указанная на странице, берется из файла `pyproject.toml`; её коммит и идентификатор сборки позволяют различать обновления в рамках одной и той же версии «preview».

Публикация происходит автоматически после того, как данная коммит проходит проверки приложения и безопасности, а подписанный пакет проходит аутентификацию, устанавливается и проверяется в средах Ubuntu и Windows. Пулл-реквесты, изменяющие установщик, также дважды запускают скрипты ``install.sh`` и ``install.ps1`` на локальной копии сайта. Во время выполнения проверок или в случае их сбоя эти же команды продолжают устанавливать предыдущую проверенную сборку. Манифест сборки показывает, какой коммит доступен в данный момент; сам номер версии может оставаться неизменным между обновлениями предварительной версии.

Используйте ту же папку установки и того же пользователя ОС, что и ранее. Сделайте резервную копию всего каталога данных при остановленном сборе данных; его можно определить по пути `tgwitness paths`. Подписанный экспорт не является полной резервной копией установки.

**Установка в корневой каталог Ubuntu по адресу `/opt/tgwitness`:**

```sh
curl -fsSL https://get.destroy.tools/install.sh | TGWITNESS_INSTALL_DIR=/opt/tgwitness bash -s -- --no-start
```

После успешной установки:

```sh
/opt/tgwitness/bin/tgwitness restart
/opt/tgwitness/bin/tgwitness status
/opt/tgwitness/bin/tgwitness open
```

Для установки пользователем в Linux/macOS используйте исходную переменную `TGWITNESS_INSTALL_DIR` или значение по умолчанию и запустите первую команду установки заново. Перед обновлением закройте панель, работающую в фоновом режиме, а после обновления запустите её снова. Для настроенной пользовательской службы в Linux выполните команду `tgwitness restart`.

**Windows:** закройте запущенную панель, повторно выполните команду установки для Windows, а затем откройте файл `bin\tgwitness.cmd` в той же установке. Установщик сохраняет данные, сеансы, настройки доступа и ключи подписи. Он переключает программу запуска только после того, как новая среда пройдет проверки; в случае неудачной установки предыдущая программа запуска остаётся на месте. Сохраните резервную копию, созданную до обновления, на случай изменения формата хранения.

<a id="everyday-commands-on-ubuntu"></a>
## Повседневные команды в Ubuntu

| Команда | Результат |
| --- | --- |
| `tgwitness open` | Текущий URL панели и ключ доступа. |
| `tgwitness paths` | Точные пути к программам, данным и руководствам. |
| `tgwitness guide --print` | Инструкции по эксплуатации в автономном режиме. |
| `tgwitness status` / `tgwitness logs` | Журналы доступности / обслуживания. |
| `tgwitness stop` / `tgwitness start` | Остановка / возобновление работы службы; сохранение данных. |
| `tgwitness token rotate` | Замена ключа администратора и завершение сеансов браузера. |
| `tgwitness tunnel off` | Отключение общедоступного быстрого туннеля; сохранение локальной панели управления. |
| `tgwitness tunnel on` / `tgwitness tunnel restart` | Создание ссылки на быстрый туннель / замена его адреса. |

См. раздел [Доступ](ACCESS.md) для получения информации о токенах коллег, сеансах и ограничениях по IP-адресам, а также [о публикации установщика](../../deploy/installer/README.md#automatic-publication-from-github) в рамках рабочего процесса выпуска GitHub-to-Cloudflare.

<a id="remove-tgwitness"></a>
## Удаление TgWitness

Деинсталлятора нет: вам необходимо остановить работу панели и удалить её папки. Удаление папки с данными приведёт к безвозвратной потере журналов, ключей подписи, сеансов Telegram и сохраненных файлов. Перед этим:

1. Экспортируйте необходимые данные (**Экспорт → Скачать подписанный ZIP-файл**) и сохраните отпечаток ключа подписи и контрольные точки за пределами данного компьютера. Чтобы сохранить самою рабочую область, скопируйте всю папку с данными при остановленном сборе данных.
2. Удалите серверы, созданные в разделе **Дополнительные инструменты → Дополнения → Сервер 24/7** в разделе **Ваши серверы** или с помощью команды ``python -m tgwitness.cloud destroy``; провайдер будет выставлять счета за них до тех пор, пока они не будут удалены.
3. Завершите сеанс каждого аккаунта в Telegram в разделе **Настройки → Устройства**. Удаление файлов не приводит к выходу из сеанса на стороне Telegram.

**Установка с правами root в Ubuntu.** Запомните расположение папки с данными, остановите службу, затем удалите службу, папки и ярлык:

```sh
/opt/tgwitness/bin/tgwitness paths
/opt/tgwitness/bin/tgwitness stop
systemctl list-unit-files 'tgwitness-*'
systemctl disable tgwitness-<ID>
rm /etc/systemd/system/tgwitness-<ID>.service
systemctl daemon-reload
rm -rf /opt/tgwitness /var/lib/tgwitness-<ID> /usr/local/bin/tgwitness
```

**Установка для пользователей Linux или macOS.** Закройте панель. Настроенный пользовательский сервис Linux останавливается с помощью команды ``systemctl --user disable --now tgwitness-<ID>``; его модуль находится в папке ``~/.config/systemd/user/``. Затем удалите папку ``~/.local/share/tgwitness`` (или ваш ``TGWITNESS_INSTALL_DIR``) и ярлык ``~/.local/bin/tgwitness``.

**Windows.** Закройте панель и удалите папку `%LOCALAPPDATA%\TgWitness` (или папку, соответствующую вашему `TGWITNESS_INSTALL_DIR`). Установщик не добавляет ни службы, ни запланированной задачи, ни ярлыка.
