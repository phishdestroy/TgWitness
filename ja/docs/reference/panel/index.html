パネルガイド

パネルのすべての画面：チャット、ジャーナル、ソース、エクスポート、エクストラ、保護モード、コードチェック。

初期設定と設定 · アカウント · エクスポートと検証 · 事例レポート

各画面の機能、署名付きジャーナルへの書き込み内容、および詳細な ガイドの場所について説明します。パネルには一度に1つのワークスペースが表示されます。これは、独自の ソース、ジャーナル、署名鍵を持つ1つのTelegramアカウントです。サイドバー上部のセレクターで ワークスペースを切り替えます。アドレスにはワークスペース情報が含まれます（?ws=…）を識別します。アドレス、 セレクター、および読み込まれたアカウントのいずれかが一致しない場合、操作はブロックされたままになります。

使い方のガイド#

サイドバーの上部には「Daily」セクションがあり、「Accounts」 は「Workspace」 の下に、 その他すべての項目は「More tools & settings」 の下にあります。上部バーにある「Interface level」 スイッチで、表示されるセクションの数を切り替えることができます：

レベル サイドバーのセクション
シンプル ホーム、チャット、変更履歴、アーカイブ、設定
標準 また、Case Board、アカウントとアクセス
エキスパート その他、「ソース」、「エクストラ」、「アーカイブへの質問」、「パラメータ」、「アカウント」、「システムログ」、「統合機能」があります。

「Simple calls」は「Start here」、「Journal」、「Exports Home」、「Changes」、「Archives」から始まります。 「Level」はセクションを非表示にするだけです。非表示にされた機能は引き続き動作し、サーバーが すべての権限を独自にチェックします。「Level」、「言語」、「テーマ」、「タイムゾーン」は オペレーターおよびワークスペースごとに保存されます。詳細は設定を参照してください。

トップバーには以下の機能もあります：

  • セクションに移動（Ctrl+K、Macの場合は⌘K）：チャット、パラメータ、またはジャーナル レコードを #number。矢印キーで移動、Enterキーで開く、Escキーで閉じる。
  • 通知：ジャーナルから抽出された問題やチャットの変更事項。 すべて既読にするを選択するとカウンターがリセットされ、通知ルールをクリックするとルール設定画面が開きます。 Telegram、Discord、またはメールへの配信設定は、 [Extras] → [Notifications] で行います。
  • このワークスペースの接続インジケーター。トップバーの下にある「Collectorのヘルス」 は、Telegram接続、イベントの取り込み、ソース、添付ファイルキューに分類されています。
  • 「ロック」：このブラウザ上のパネルを閉じます。「コレクション」はサーバー上で引き続き実行されます。
  • バージョン番号の隣にある保護モード。保護モードを参照してください。

デモ用ワークスペースには架空のメッセージが含まれており、Telegramには一切接続されません。 実際のワークスペースを変更するような操作は、ここでは拒否されます。

ここから始めましょう#

タスクを選択してください。「アカウントをエクスポート」を選択すると、そのアカウントが現在閲覧可能なコンテンツがダウンロードされます。 「調査をフォロー」を選択すると、選択したチャットからの新しいメッセージ、編集履歴、削除通知が記録されます。 セットアップカードには、アカウントの接続、 ソースの選択、監視の開始という3つの手順が表示されます。「目標」の質問は、回答またはスキップするまで このページに表示されたままになります。新しいワークスペースを開くと、代わりに最初のセットアップ画面が表示されます。

チャット#

保存された会話は、デフォルトで読み取り専用です。

  • 名前またはIDでリストを検索できます。「選択」で、ウォッチリストにチャットを追加または削除できます。 「Telegramリンクを開く」では、ユーザー名または招待リンクを入力すると、プレビューが ジャーナルに保存されます。「参加／開く」を選択すると、チャットに参加してソースに追加されます。 ボットを開くと、そのボットにメッセージが送信されます。 /start.
  • チャットヘッダーには、メッセージ削除済み、テキストは保持、保存前に削除されました および再確認しても見つかりませんでしたが表示されます。チャットリストと通知でも同じ 定義が使用されています。削除されたメッセージは赤色で表示され、保存されたテキストは保持されます。編集されたメッセージは 保存されたすべてのバージョンが保持されます。各削除には、既知の情報が記載されています。つまり、いつ閲覧されたか、 Telegramが誰が削除したかを報告しないこと、あるいは通知のみが届いたことなどです。
  • 「履歴を読み込む」では、直近の 100、250、または 500 件のメッセージをこのビューおよび ジャーナルに読み込みます。有効になっているすべてのソースを読み込むには、「ソース」→「全履歴」を使用してください。
  • 「チャットのエクスポート」では、表示されている履歴全体を署名付きで chat.json かつ chat.htmlとしてダウンロードします。複数の連携アカウントで作業を分担できます。各アカウントは、それぞれが担当する メッセージ番号の範囲をダウンロードしてその部分を署名し、エクスポートを開始した アカウントがアーカイブ全体に署名します。「1つのチャットをエクスポートする」を参照してください。
  • 「People」には、このチャットに保存されたメッセージを持つすべてのユーザーが表示されます。ユーザープロフィールは、 第三者に関する個人情報であるため、デフォルトではオフになっています。チャットで オンになっている場合、プロフィールには名前とユーザー名の履歴、Telegramのフラグ、アバターのハッシュ、アクティビティ、 誰が誰に返信したか、その他の監視対象チャット、および言及されたウォレット、電話番号、ユーザー名 、リンクが表示されます。 すべての情報は、その記録にリンクしています。「プロフィールのエクスポート」を行うと、署名付きファイルが保存され、 オプションでパスワードZIPを設定できます。プロフィールをオフにすると、プロフィールファイルが削除されます。詳細については、「 ユーザープロフィール」を参照してください。
  • 今すぐプロフィールを保存するは、チャットやボットのプロファイル（説明、 メンバー、招待リンク、ボットコマンド）のスナップショットを記録します。

読み取り専用、送信、およびシークレット#

メッセージの上にある2つのスイッチは、アカウントと閲覧者を保護します：

  • チャットを開いたときは「読み取り専用」モードが有効になっています。 メッセージを送信したり、ボットの ボタンを押したりするには、この設定をオフにしてください。各操作を行う際、「@アカウントとして送信しますか？」または「このボットボタンを @アカウントとして押しますか？」と確認が表示されます。これは、チャットのメンバーにその操作が表示され、署名済みの ジャーナルに記録されることを示しています。「このチャットでは10分間再確認しない」を選択すると、しばらくの間、この確認が スキップされます。「ケースの証拠」という目標については、パネルおよびAPIにおいて、送信機能は無効になっています。
  • 「Mask secrets」は、パスワード、ログインコード、APIキーや ハッシュ、ボットトークン、セッション文字列、秘密鍵、JWT、またはクレジットカード番号 （カード番号はルーン和で検証されます）のように見える情報を隠します。「Show」を選択すると1つの値が表示され、その表示内容は ジャーナルに記録されます。このブラウザでのマスキングの無効化も記録されます。 表示のみが変更されます。元の記録およびすべてのエクスポートには、全文が保持されます。

ジャーナル#

ワークスペースが署名したすべての記録を、新しい順に表示します。

  • 「概要」では、監視対象のメッセージ数、記録された編集内容、削除通知、および 選択された情報源の数が表示されます。
  • イベントのタイムラインは、イベントの種類（すべて、編集、削除、リアクション、 メンバーシップ、カバレッジ）、テキスト、およびソースでフィルタリングします。以前のイベントを読み込むは前のページに戻ります。
  • レコードを開くと、その詳細、ハッシュ、ペイロードを確認できます。このレコードへのリンクは、 同じレコードを開くためのアドレスです。このプレビューでは機密情報がマスクされていますが、 エクスポートデータには元の情報が保持されます。
  • ジャーナルは追記専用です。パネル内のどの操作でも、記録の編集や削除は行われません。 エクスポート → ジャーナルの検証または python -m tgwitness.verifyで確認してください。 エクスポートと検証を参照してください。

出典#

このワークスペースがどの会話を記録し、そこからどのような情報を保持するかを示します。変更は 今後のアクティビティに適用されますが、保存済みの記録はそのまま残ります。

「チャットリストの更新」は、アカウントのチャットとフォルダを読み込みます。メッセージはダウンロードされません。

範囲#

  • このアカウントが記録する内容 ：選択されたチャット （追加したチャットのみ）、 Telegramフォルダ （アカウントのフォルダの一つ。後から追加されたチャットも 含まれる）、または記事全文 （すべてのチャット、および新しいチャット、グループ、プライベートチャット、 ボットが追加されるたびに記録）。調査モード は専用アカウント用です。このアカウントが 閲覧するすべての内容、自身のメッセージやボタン操作を記録し、新しい チャットのプロファイルや以前に表示されたメッセージを即座に保存します。 専用アカウントガイド は、 メインアカウントを決して使用してはならない理由を説明しています。
  • ソースタイプにより、フォルダモードおよびアカウント全体モードの対象は、チャンネル、グループ、プライベート チャット、ボットに限定されます。「自身のアクション」では、そのアカウント自身のメッセージ、編集、 返信時のキーボード入力などが追加されます。
  • 新しいチャットやボットが表示されたら、そのプロファイルと、指定した数までの 最新の表示可能なメッセージを保存します。

制限事項：シークレットチャットはTgWitnessには一切記録されません。TgWitnessが 実行されていない間は何も記録されません。再起動後は、Telegramがまだ返しているデータのみを 追跡し、レポートにはその間の空白期間が表示されます。チャットリストの上限（[Parameters]で変更されていない限り 1,000件のダイアログ）を超えるチャットは、次にアクティブになった時点で追加されます。別のアプリ内で 押されたインラインボットボタンは表示されませんが、ボットの返信は記録されます。

対象となるチャット#

ステータス（有効、一時停止、優先度、除外、未確認の アクセス、無視）やタイプでフィルタリングし、選択した項目に対して有効化、一時停止、優先度の設定または解除、 範囲からの除外、削除などの操作を行うことができます。ステータスバッジには状態のみが表示されますが、操作は 各行のメニューにあり、その機能の説明が記載されています。 一時停止や除外を行う際は、 確認が求められます（一括操作時も同様です）。ソースを削除する際はソース名の入力が求められ、関連する人物 プロフィールが削除されますが、保存された記録はジャーナルに残ります。

アカウントのチャットリストには表示されないが、記録が引き続き届いている状態を示すのは更新の受信（チャットリストには表示されない）であり、それ以外の場合はアクセス未確認です。利用可能なチャットは、選択した項目を追加または一致するすべてを追加とのチャットを追加します。

全履歴#

有効になっているすべてのソースの利用可能な履歴を、「チャット」と「ジャーナル」に読み込みます。 進行状況は再起動後も保持され、添付ファイルはメディア設定に従います。 ソース履歴を参照してください。

記録#

  • 保存する変更内容を選択してください：新しいメッセージ、編集、削除通知、 表示されているリアクション、参加および退出。プリセットを選択するとフォームが変更され、 「記録設定を保存」をクリックすると適用されます。カテゴリを再度有効にしても、 見逃したイベントは復元されません。
  • 利用可能な場合はメディアを保存します：添付ファイルは1ファイルあたりのサイズ制限内でダウンロードし、 ファイルタイプごとに1～2,000 MiBの範囲で設定し、動画の長さを秒単位で制限します（0は制限なしを意味します）。 ダウンロードの試行ごとに、その結果が記録されます。
  • 再確認：優先チャットは数分おきに、その他のチャットはめったに確認しないため、アカウントは TelegramのFloodWait制限に引っかからないようにしています。0に設定するとグループが無効になります。優先チャットは リスト内の星マークでマークしてください。1回の処理で処理するチャット数とチャット間の休止時間は 「パラメータ」で設定できます。コレクションを参照してください。

設定、アカウント、接続#

  • 設定：目標、接続、記録対象、およびインターフェース。 初期設定と設定を参照してください。
  • アカウント：各ワークスペースの状態、ソース、イベント、添付ファイルキューが表示されます。 要確認、収集、オフラインまたは一時停止中、または未接続でフィルタリングしたり、選択範囲の一時停止や再開を行ったり、アカウントファイルを一括インポートしたり、 グループを管理したりできます。アカウントを参照してください。
  • アカウント：ログインおよびこのアカウントの接続経路。ダイレクト、WireGuard プロファイル、独自プロキシ、パブリック MTProto プール、または WARP。経路を準備・確認し、 このアカウント、グループ、またはすべてのアカウントに適用します。 「接続」および「プロキシ」を参照してください。

目的と保護レベル#

4つの質問：

  1. これは何に使うのですか？ 個人の記録、調査、または事件の証拠。
  2. どの程度の範囲を監視しますか？ 少数のチャット（最大約50件）、多数のチャット（最大約 500件）、あるいはアカウント全体。これにより、チャットリストの上限が1,000件、3,000件、または20,000件に設定されます。
  3. 写真やファイルは？ テキストのみ、写真や短いメディア（写真 20 MB、動画 100 MB）、またはすべて（動画やドキュメントはそれぞれ最大 1 GB）。アカウント全体を 含む「すべて」を選択しても、4 GiB のディスク空き容量は確保されます。
  4. どこで実行されるのか？このコンピュータ、または常時稼働しているサーバーです。

提案リストには、独立したタイムスタンプ、drand、Telegramのデバイスリストが記載されており、それぞれ 追加される内容について1行ずつ説明があります。タイムスタンプは、個人用 記録、調査、または証拠として、60分、30分、または10分ごとに開始されます。drandとデバイスリストにはタイムスタンプが必要です。変更を 適用するのは、これら、添付ファイルポリシー、および上記の2つのパラメータのみです。各 変更はジャーナル記録となり、さらに setup.applied。通知、オフサイトコピー、 サーバー、ゲートウェイDNS、コードチェック、および証人は、次のステップとして、それぞれ 専用のフォームとともに提供されます。

2つのスケールは、目標値ではなく、設定された値に基づいて算出されます：

スケール ポイント
信頼性 署名付きジャーナル 1、タイムスタンプ 3、drand 1、デバイスリスト 1、一致するコードチェック 1、ウィットネスポーリング 1、認証済みサーバー 2、ゲートウェイ DNS ログ 1
信頼性 常時稼働サーバー 3、オフサイトコピー 3、オブジェクトロック 1、問題通知 1

「読み取り」が最大で80%以上、50%以上なら「高」、25%以上なら「中」、それ以下は「基本」と評価されます。 信頼性は現在、質問4の回答にある常時稼働サーバーを基準として算出されており、 他のサーバーがチェックされる前の段階での評価となります。

通知#

通知はAppriseを経由して、Telegram、Discord、Slack、ntfy、メール、Matrix、および その他100以上のサービスに送信されます。サービスを選択し、1～2つのフィールドに入力してテスト送信を行うか、 Appriseのアドレスを直接貼り付けてください。

  • 問題点：ディスク容量がほぼ満杯、アカウントからログアウト、コレクション、コピー、またはタイムスタンプ に関するエラー。シールされたサーバー上では、SSHポートが開いていることやログインも問題となります。
  • 変更点：監視対象のチャットにおける削除済み、編集済み、および欠落したメッセージを、 チェックごとに1つの通知にまとめます（[Parameters]で変更されていない限り、1分ごとにチェックが行われます）。
  • 完了したタスク：履歴、エクスポート、保存用コピー。
  • サーバー時間に基づき、指定した時刻に日次サマリーが配信されます。

通知にはチャット名と件数が表示されます。メッセージの抜粋表示はデフォルトでオフになっていますが、 これをオンにすると、メッセージ本文がこのマシンから外部に送信されます。

オペレーターボットとは、@BotFatherから作成した独自のボットであり、以下の質問に回答します /status 、 /stats、およびオプションで /pause, /resume および /copyに対応します。リストされたチャットおよび TelegramユーザーIDのみがこれを利用でき、会話のテキストはワークスペース内に残ります。別のアプリケーションがすでにそのコマンドを受信している場合は、別の ボットを使用してください。 通知およびオペレーターボットを参照してください。

証拠とバックアップ#

  • 独立したタイムスタンプは、署名済みの各チェックポイントのSHA-256のみを、5分から1,440分ごとにRFC 3161 認証機関およびOpenTimestampsカレンダーへ送信します。Anchorは現在 1回のパスを実行中です。タイムスタンプを参照してください。
  • さらに多くの「ウィットネス」が存在しますが、これらは選択されるまでは非アクティブ状態です。最新の drand ラウンド、Telegram の IP アドレスを含まないログイン済みデバイス一覧、および Cloudflare Gateway のサーバーの DNS クエリログなどです。オプションの記録を参照してください。
  • 暗号化バックアップでは、ジャーナル、ファイル、チェックポイント、チャットのエクスポートデータを S3互換のストレージ（Wasabi、Amazon S3、Backblaze B2、Cloudflare R2、MinIO）にコピーします。 すべてのデータはまずこのマシン上で暗号化されます。暗号化キーをダウンロードし、 別の場所に保管してください。これがないと、バックアップを読み取ることができません。ガバナンスまたはコンプライアンスモードの「オブジェクトロック」機能は、 オブジェクトが設定された日数間削除されないようにします。「オフサイトコピー」を参照してください。

コードチェック#

インストールされたプログラムが公開されているバージョンと一致するかどうかを確認します。

  1. GitHub リポジトリ（公式のリポジトリは既に入力済み）と、タグ、ブランチ、またはコミットを入力してください。
  2. 「Check now」は、このワークスペースの外部リクエスト用ルートを通じて GitHub の API に問い合わせ、 そのコミットのファイル一覧を取得します。そして、測定対象の各プログラム ファイルの git blob ID をコミットと照合します。改行コードが変換された Windows 環境でのチェックアウトでも、照合は成立します。
  3. 結果には、変更されたファイル、追加されたファイル、欠落しているファイル（それぞれ最大50件）が一覧表示され、 ジャーナル記録として保存されます。 source.checked ジャーナル記録として保存されます。

結果は、実行中のプログラムファイルに変更がない間のみ最新のものとして扱われます： 更新後は再度確認してください。トークンは不要で、パブリックリポジトリのみが対象となります； チャットや認証情報はアップロードされません。一致判定はディスク上のコードを識別するものです。これは ハードウェアによる認証ではありません。それについては、Phala Cloudを参照してください。

保護モード#

バージョン番号の横にあるスイッチャーは、選択されているモードと、18の 保護レイヤーのうちいくつが有効になっているかを示します。例えば、 🟠 Witnessed 9/18。Change modeを 追加情報 → Protection levelで開くと、選択画面が表示されます。モードは対象を定義し、 まだ不足している項目を一覧表示します。記録、署名、保存された設定は、どのモードでも同じです。

モード For 追加機能
🟢 簡単 チャットの監視とコピーの保存 「Chats」には、ジャーナルとチャットのエクスポートが含まれます。署名処理はバックグラウンドで実行されます。
🟡 署名済み プラットフォーム、ホスト、または不正利用対応窓口への報告 署名付きアーカイブ、ジャーナルチェック、チェックポイント、引き継ぎ用抽出データ
🟠 ウィットネス済み 記録が改ざんされたと主張される可能性のあるケース 署名済みのジャーナルヘッダーを投稿する独立したウィットネス
🔴 法廷での使用に対応 弁護士、警察、または裁判所向けの証拠資料 タイムスタンプ、暗号化されたオフサイトコピー、レポート内のケース詳細
🟣 GitHub 認証済み そのソフトウェアは誰でも確認できるものでなければならない記録 コードチェックと GitHub Actions のキャプチャ
⚫ モサド 資金力のある相手に対する、重大な案件 24時間365日稼働の密閉型サーバー、隠されたIPアドレス、全18層

構成要素：すべての記録は署名され、チェーン化される；署名付き実行レシート；SHA-256 を使用して保存された添付ファイル；署名付きチェックポイント；再チェック；問題アラート；読み取り専用のウィットネスアクセス； スケジュールに従ってチェックを行うウィットネス；RFC 3161 タイムスタンプ；OpenTimestamps 証明；検証済みの 最新タイムスタンプ；暗号化されたオフサイトコピー；レポート内のケース詳細；コードの一致 チェック； TelegramがこのマシンのIPを一切認識しないこと；プロキシ経由の外部リクエスト；コピーへの オブジェクトロック；プロバイダーの記録を保持する封印されたサーバー。オフになっているレイヤーには「 セットアップ」があり、そのフォームが開きます。より低いモードを選択すると確認を求められ、 何も削除されません。

その他のツール#

  • アーカイブに問い合わせてみましょう：保存された観察結果を検索し、出典を確認した上で、 それらをAIモデルに送信するかどうかを決定します。アーカイブ分析および ローカルでのOCRと文字起こしを参照してください。
  • パラメータ：収集の制限とペース、再確認、ダウンロード、プロファイル、 通知、エクスポート。「名前で検索」、「変更された値のみを表示」機能、および 「デフォルトを復元…」によるデフォルト設定の下書き作成。パラメータの保存を行うと、 次回使用時からその値が適用され、変更のたびにログ記録が残ります。
  • アクセス権限：レビュー担当者、アナリスト、オペレーターごとに個別のトークンが発行され、選択された ワークスペース、チャット、権限に限定されます。アクセス権限についてはこちらをご覧ください。
  • システムログ ：このプロセスが起動してから行った操作（接続、プロキシの変更、 ログイン、拒否、設定の変更）を、IPアドレスを非表示にして記録します。「改行を追跡」機能により、 最新の行が常に表示されます。メッセージはジャーナルにのみ残ります。
  • 連携機能：AI プロバイダー、読み取り専用の MCP 接続、および 署名付き Webhook。
  • Case Board：証拠の横に表示される、チーム専用のメモ、ブックマーク、スライス。 Case Boardを参照。
  • 「エクスポート」内のGitHub Actions capture：あなたのフォークから取得したチャットが1つ表示されています。 シールドキャプチャを参照してください。
