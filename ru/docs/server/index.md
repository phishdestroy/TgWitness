# Постоянная работа на сервере

Canonical page: https://phishdestroy.github.io/TgWitness/ru/docs/server/

Держите сборщик в работе, а данные — в сохранности при перезапусках.

## Выберите способ запуска

Нативно: [лаунчер](https://phishdestroy.github.io/TgWitness/ru/docs/start/) плюс шаблоны служб в [deploy/](https://github.com/phishdestroy/TgWitness/blob/main/deploy/README.md). Docker, из папки проекта:

```
docker compose up -d --build --wait
docker compose exec tgwitness cat /data/panel-token.txt
```

Панель слушает localhost:8787. Открывайте локально или через SSH-туннель, с токеном из второй команды.

## Сохраните весь каталог данных

Нативно: `data/live`. Docker: том `tgwitness-data`. Журналы, сессии и ключи должны храниться вместе. Подписанный экспорт — это доказательство, а не резервная копия.

1. Сначала остановите сбор.
2. Скопируйте всю папку данных в надёжное место вне хоста.
3. Попробуйте восстановить её на отдельной установке, прежде чем ей доверять.

## Проверьте после перезапуска

Проверьте пространство и ключ, подключение, источники и то, что новые сообщения приходят. TgWitness догоняет то, что ещё хранит Telegram, а не всё, что произошло, пока он был выключен.

«Здоровый» контейнер значит, что веб-сервер отвечает. Работает ли сбор, покажут тестовое сообщение и свидетель.

## Публикуйте только то, что намереваетесь

HTTPS, тома, обновления и восстановление — в справочнике по развёртыванию. Что реально проверено: [журнал проверок](https://phishdestroy.github.io/TgWitness/ru/docs/reference/verification/).
