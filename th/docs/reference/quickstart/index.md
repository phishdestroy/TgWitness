TgWitness เป็นแอปพลิเคชันแบบสแตนด์อโลน สำหรับการติดตามกลุ่มและช่อง Telegram ที่บัญชีของคุณสามารถเข้าถึงได้ มันทำงานแบบท้องถิ่นด้วยไดเรกทอรีข้อมูลของตัวเอง

**มาครั้งแรก?** [ลองดูเดโม](https://phishdestroy.github.io/TgWitness/th/docs/reference/quickstart/#explore-the-interface)ก่อนที่จะเชื่อมต่อบัญชี [เลือกคู่มือ](https://github.com/phishdestroy/TgWitness/blob/main/docs/README.md)สำหรับพร็อกซี, Witness, การส่งออกข้อมูล หรือการตั้งค่าเซิร์ฟเวอร์

## ติดตั้งและเริ่มใช้งาน

[รวบรวมผ่าน GitHub Actions (รุ่นทดลอง)](https://github.com/phishdestroy/TgWitness/blob/main/docs/SEALED-ACTIONS.md)

เลือกวิธีหนึ่ง การดาวน์โหลดแบบพกพาจะพร้อมใช้งานหลังจากที่มีการเผยแพร่เวอร์ชันที่สร้างขึ้นแล้ว:

| ผู้ดูแล | ไม่ต้องติดตั้งอะไรทั้งสิ้น | จากแหล่งที่มา: Python 3.11+ | Docker: Engine/Desktop พร้อม Compose 2.20+ |
| --- | --- | --- | --- |
| Windows | คัดลอก `TgWitness-<version>-windows-amd64-portable.zip` จาก GitHub Releases แล้วคลิกสองครั้งที่ `TgWitness.cmd` | คลิกสองครั้งที่ `Start.cmd` | คลิกสองครั้งที่ `scripts\Docker.cmd` |
| Linux / macOS | — | `sh start.sh` | `sh scripts/docker-start.sh` |

สำหรับวิธีการใช้โค้ดต้นฉบับ ให้ดาวน์โหลดและแตกไฟล์ ZIP จาก GitHub Releases หรือคัดลอก รีโพสิตอรี `Start.cmd` จะเสนอให้ติดตั้ง Python 3.12 สำหรับผู้ใช้ Windows หากไม่ พบ Python ที่เหมาะสม (winget หรือตัวติดตั้ง python.org ที่ลงนามแล้ว) `start.sh` จะแสดง คำสั่งติดตั้งที่ถูกต้องสำหรับระบบปฏิบัติการ Linux หรือ macOS ของคุณ หาก Python ยังไม่ติดตั้ง การรันโค้ดต้นฉบับครั้งแรกจะสร้าง `.venv` และติดตั้งไลบรารีที่จำเป็นโดยอัตโนมัติ

Docker สร้างแอปพลิเคชันและเริ่มทำงานในพื้นหลัง; ไม่จำเป็นต้องใช้ Python บนเครื่องโฮสต์ `scripts\Docker.cmd` และ `scripts/docker-start.sh` จะแสดงที่อยู่ของแผงควบคุมและโทเค็นเมื่อ คอนเทนเนอร์ทำงานปกติ คำสั่ง Docker ที่เทียบเท่ากันบนทุกเครื่องโฮสต์ที่รองรับคือ:

```
docker compose up -d --build --wait
docker compose exec tgwitness cat /data/panel-token.txt
```

เปิด **http://127.0.0.1:8787** ใช้โทเค็นที่พิมพ์โดย Docker helper หรือคำสั่ง Docker ที่สอง หรืออ่าน**ไฟล์ data/live/panel-token.txt** สำหรับการติดตั้งแบบพกพาหรือจากซอร์สโค้ด ต่อที่ **Connect Telegram** ด้านล่าง การติดตั้งแบบเนทีฟและ Docker ใช้พื้นที่จัดเก็บข้อมูลแยกกัน; การเริ่มต้น Docker จะไม่นำเข้าบันทึกแบบเนทีฟที่มีอยู่

สำหรับเซิร์ฟเวอร์ [การติดตั้ง](https://phishdestroy.github.io/TgWitness/th/docs/reference/deployment/)รวมถึง HTTPS อัตโนมัติ การรีสตาร์ท การเผยแพร่ภาพ การอัปเดต และการสำรองข้อมูล

## สำรวจอินเทอร์เฟซ

1. เรียกใช้ **TgWitness-Demo.cmd** ในแพ็กเกจแบบพกพา, **scripts\Demo.cmd** ในโฟลเดอร์แหล่งที่มาของ Windows หรือ `sh start.sh --demo` บน Linux/macOS การเรียกใช้จากแหล่งที่มาจะสร้าง `.venv` ก่อนและติดตั้งส่วนที่จำเป็น
2. เปิด **http://127.0.0.1:8787**.
3. การสาธิตในเครื่องจะเปิดสมุดบันทึกตัวอย่างโดยอัตโนมัติ ไม่จำเป็นต้องคัดลอกโทเค็นเพื่อเข้าถึงโดยตรงในเครื่อง

ข้อความตัวอย่างเป็นข้อความสมมติ โหมดสาธิตไม่สามารถเชื่อมต่อกับบัญชี Telegram ที่จริงได้

## เชื่อมต่อ Telegram

> [!WARNING] **อย่าใช้ข้อมูลใดที่คุณไม่สามารถรับความสูญเสียได้** เราขอแนะนำอย่างแรงว่าอย่าเชื่อมต่อ บัญชีส่วนตัวหรือบัญชีที่มีค่า และอย่าสร้าง API ID / hash บนบัญชีที่คุณให้ความสำคัญ Telegram อาจระงับบัญชีได้โดยไม่คาดคิดและมักเป็นการระงับถาวร ไม่ว่าใช้แอปพลิเคชันใด การทดสอบที่ราบรื่นขึ้นอยู่กับ Telegram ไม่ใช่ TgWitness และไม่รับประกันอะไรสำหรับอนาคต

1. หากเดโมในระบบกำลังทำงานอยู่ ให้หยุดมันลงและเรียกใช้ **Start.cmd** หรือ `sh start.sh` หากไม่เช่นนั้น ให้ปล่อยให้การติดตั้งแบบสดที่เปิดไว้ข้างต้นทำงานต่อไป
2. ใช้โทเค็นของแผงควบคุมที่สอดคล้องกับวิธีการติดตั้งของคุณเพื่อเปิดแผงควบคุม
3. หากต้องการใช้พร็อกซี ให้บันทึกไว้ที่ **บัญชี → การตั้งค่า → การตั้งค่าการเชื่อมต่อ → เปลี่ยนเส้นทางเชื่อมต่อ**
4. ในส่วน **Account (บัญชี**), ป้อนหมายเลขโทรศัพท์ของคุณแล้วกด **Continue (ต่อ**), เลือก **QR code → Show QR code (แสดงรหัส** QR), หรือเลือกไฟล์แล้วกด **Connect account (เชื่อมต่อบัญชี)**. **API ID + Hash** เป็นตัวเลือก: พื้นที่ทำงานจะใช้คู่ที่บันทึกไว้หรือนำเข้า, หรือคู่ที่ใช้งานได้จากกลุ่มที่สร้างไว้ล่วงหน้า. เพื่อใช้แอปของคุณเอง, ให้วางคู่ `API ID:API Hash` ลงใน API ID. สำหรับกุญแจการอนุญาตแบบครบถ้วน ให้เลือก "**กุญแจการอนุญาต**" (**Auth key**) วางตัวอักษรฐานสิบหกทั้งหมด 512 ตัว และเลือก DC ID ที่ให้มา User ID เป็นตัวเลือกและจะถูกทำเครื่องหมายถูกหากมีการกรอก
5. ดำเนินการตามวิธีการลงชื่อเข้าใช้ที่คุณเลือก: โทรศัพท์/รหัส/2FA, การยืนยันจาก แอป Telegram ที่ลงชื่อเข้าใช้แล้วสำหรับ QR, หรือการนำเข้าเซสชันที่ได้รับอนุญาตและรองรับ
6. ตรวจสอบ ID บัญชีที่แสดงอยู่ **แหล่งข้อมูล**เปิด: การสนทนาของคุณจะโหลดอัตโนมัติ; เพิ่มกลุ่มของคุณ
7. ในส่วน **“เลือกการเปลี่ยนแปลงที่จะเก็บรักษา**” ให้เลือกหมวดหมู่เหตุการณ์หรือตัวเลือกที่ตั้งไว้ล่วงหน้า **“ข้อความ การแก้ไข และการลบ**” แล้วบันทึกการตั้งค่าการติดตาม
8. เลือกการตั้งค่าไฟล์แนบแต่ละรายการ แล้วกด "**เริ่มการสังเกตการณ์**"

ข้อมูลรับรอง API ใช้เพื่อระบุตัวตนของแอปพลิเคชันของคุณ; ข้อมูลเหล่านี้ไม่ ให้สิทธิ์การเข้าถึงบัญชีด้วยตัวมันเอง กลุ่มส่วนตัวไม่จำเป็นต้องมีชื่อผู้ใช้สาธารณะ แต่บัญชีของคุณต้องมีสิทธิ์การเข้าถึง

สำหรับบัญชีที่มีอยู่แล้ว ให้ดู[รูปแบบบัญชีและเซสชัน](https://phishdestroy.github.io/TgWitness/th/docs/reference/accounts/): แผงควบคุมนี้รองรับ Telethon StringSession, Telethon/Pyrogram SQLite, TData ZIP สำหรับบัญชีเดียว และ JSON ของบัญชีที่ได้รับการสนับสนุน ให้เลือกเซสชันและไฟล์ JSON ที่เกี่ยวข้องพร้อมกัน แล้วกด **"Connect account**" การเข้าสู่ระบบด้วย QR Code ก็ใช้งานได้เช่นกัน พร้อมกับการตั้งค่า API ที่เลือกได้เช่นเดียวกัน TDLib, บอท และรายชื่อบัญชีจำนวนมาก ไม่ได้รับการสนับสนุน

เพื่อเพิ่มบัญชีอีกบัญชี ให้กด **+** ข้างตัวเลือกรายชื่อบัญชี หรือเปิด **บัญชี → การตั้งค่า → การตั้งค่าการเชื่อมต่อ → พื้นที่ทำงาน** หรือใช้ **Accounts** พื้นที่ทำงานมีเซสชัน บันทึก กุญแจ แหล่งข้อมูล และคิวที่แยกกัน การเปลี่ยนมุมมองจะไม่ทำให้ตัวเก็บข้อมูลอื่นหยุดทำงาน บัญชี Telegram เดียวกันไม่สามารถกำหนดให้กับพื้นที่ทำงานสองแห่งในระบบติดตั้งนี้ได้ ไม่มีจำนวนพื้นที่ทำงานที่กำหนดไว้; พื้นที่ทำงานทั้งหมดใช้กระบวนการเดียวกัน ดังนั้นความจุจึงขึ้นอยู่กับเครื่อง

โทเค็นแผงสด (live panel token) ปกป้องการเข้าถึงสิทธิ์ Telegram ของคุณและ ข้อมูลที่บันทึกไว้; โทเค็นนี้แยกต่างหากจากข้อมูลรับรอง API ของ Telegram มีเพียงการสาธิตท้องถิ่นที่ ถูกเริ่มต้นอย่างชัดเจนและเข้าถึงโดยตรงเท่านั้นที่จะได้รับการเข้าถึงอัตโนมัติ ส่วนการสาธิตจากระยะไกลหรือผ่านพร็อกซีจะยังคงใช้ `data/demo/panel-token.txt`

## ตรวจสอบและส่งออก

- **บันทึก:** ค้นหาและกรองข้อมูลการสังเกตตามแหล่งที่มาและประเภทเหตุการณ์
- เลือกเหตุการณ์เพื่อตรวจสอบบันทึกต้นฉบับ แหล่งที่มา และเวอร์ชันที่เก็บไว้
- รายละเอียดการแก้ไขแสดงเนื้อหาที่มีอยู่ก่อนและหลังการแก้ไข ส่วนรายละเอียดการลบแสดง เนื้อหาที่ถูกบันทึกไว้ครั้งสุดท้าย (หากมี); ส่วนผู้กระทำที่ไม่ทราบตัวตนจะยังคงไม่ทราบตัวตน
- **รูปแบบการส่งออก:** ZIP ที่มีลายเซ็น, JSONL, CSV และ HTML สำหรับใช้งานแบบออฟไลน์
- **การส่งออกบทสนทนาแบบเต็ม** (Sources → Full chat export): ดาวน์โหลดประวัติการสนทนาทั้งหมดที่มองเห็นได้ ของบทสนทนาหนึ่งบทในรูปแบบแพ็กเกจที่ลงนามด้วย `chat.json` (สไตล์ Telegram-export) และ `chat.html` ที่อ่านได้ บทสนทนาส่วนตัวจะทำงานได้เมื่อบัญชีนั้นเป็นสมาชิก นี่เป็น ภาพถ่ายปัจจุบัน ไม่ใช่การสร้างใหม่ของข้อความที่ถูกลบหรือแก้ไขไปแล้ว ตรวจสอบ สำเนาด้วย `python verify.py chat-export.zip --fingerprint TRUSTED_SHA256`.
- **จุดตรวจสอบ:** รักษาขอบเขตของบันทึกที่มีลายเซ็นให้อยู่นอกตัวเก็บข้อมูล
- **ดาวน์โหลดใบยืนยันการดำเนินการที่ลงนาม:** เพื่อเก็บรักษาบันทึกโปรแกรม/เวอร์ชันของผู้เก็บข้อมูล
- **เตรียมคำขอเวลาประทับ:** เตรียมคำขอแบบออฟไลน์ไปยังหน่วยงานออกเวลาประทับ; ทำตาม [TIMESTAMP.md](https://phishdestroy.github.io/TgWitness/th/docs/reference/timestamp/) เพื่อรับและตรวจสอบคำตอบ
- **ตรวจสอบบันทึก:** ตรวจสอบลายเซ็นของเหตุการณ์และลิงก์ในห่วงโซ่ ZIP export ยังตรวจสอบสื่อด้วย

เบราว์เซอร์ที่รองรับสามารถบันทึกไฟล์ส่งออกขนาดใหญ่ได้โดยตรงไปยังไฟล์ที่เลือกไว้ ส่วนเบราว์เซอร์อื่น ๆ จะบัฟเฟอร์ได้สูงสุด 128 MiB ในขณะที่เซิร์ฟเวอร์กำลังทำงาน CLI แบบสตรีมมิ่งจะรองรับ การดาวน์โหลดไฟล์ขนาดใหญ่ได้โดยไม่ต้องบัฟเฟอร์ข้อมูลตอบกลับทั้งหมด:

```
python -m tgwitness.download --token-file data/live/panel-token.txt --out evidence.zip
```

สำหรับพื้นที่ทำงานอื่น ๆ ให้เพิ่ม `--profile ID` โดยใช้ **Exports → Workspace ID** สำหรับเซิร์ฟเวอร์ระยะไกล ให้เพิ่ม `--url https://your-server` ขีดจำกัดการถ่ายโอนข้อมูลตามค่าเริ่มต้นคือ 5 GiB; `--max-mib` สามารถปรับเปลี่ยนได้ เนื้อหา ZIP ที่ลงนามมีขีดจำกัดการตรวจสอบแบบไม่บีบอัด แยกต่างหาก 4 GiB ตามค่าเริ่มต้น (**Parameters** สามารถเพิ่มขีดจำกัดนี้ได้; ตรวจสอบไฟล์เก็บถาวรดังกล่าวด้วย `verify.py --max-gib N`) ตรวจสอบไฟล์เก็บถาวรโดยใช้สำเนาของตัวตรวจสอบที่เชื่อถือได้และ ลายนิ้วมือ/จุดตรวจสอบของกุญแจที่เก็บรักษาไว้อย่างอิสระ

## ตรวจสอบการติดตั้ง

```
python start.py --setup-only
python start.py --check
python start.py --check --json
```

`--check` ตรวจสอบการพึ่งพาในระบบท้องถิ่น การสนับสนุนการลงนาม การจัดเก็บข้อมูล การตั้งค่ากุญแจ และ ที่อยู่รับฟัง มันไม่ติดตั้งอะไรทั้งสิ้นและไม่เชื่อมต่อกับ Telegram หากพอร์ต ถูกใช้งานอยู่ อาจหมายความว่ามีอินสแตนซ์อื่นกำลังทำงานอยู่ ให้ใช้ `--port` ที่ต่างออกไป หรือหยุดการทำงานของมันก่อน

โปรแกรมติดตั้งจะติดตั้งลงใน `.venv` คำสั่งเสริม `python -m tgwitness...` ต้อง ใช้ `.venv\Scripts\python.exe` บน Windows หรือ `.venv/bin/python` บน Linux/macOS, เว้นแต่สภาพแวดล้อมนั้นได้ถูกเปิดใช้งานแล้ว

## เซสชัน การป้องกัน และการดำเนินงาน

ไฟล์ Telethon SQLite `.session` ที่ปิดและมีความสม่ำเสมอสามารถแปลงได้บนเครื่องท้องถิ่นด้วย `python -m tgwitness.sessions account.session --out account.tgwitness-session` แล้ว โหลดเข้าสู่ Account ได้ นอกจากนี้ยังมีตัวเลือกการนำเข้าไฟล์โดยตรงและการเข้าสู่ระบบด้วย QR Code ด้วย ดู [CONNECTION-SECURITY.md](https://phishdestroy.github.io/TgWitness/th/docs/reference/connection/) เพื่อทราบรูปแบบการเข้าสู่ระบบ SOCKS5, HTTP CONNECT, MTProxy และกุญแจหลักภายนอก

**การหยุดการสังเกตการณ์**จะหยุดการเก็บข้อมูล การล็อกจะปิดการเข้าถึงผ่านเบราว์เซอร์เท่านั้น การปิดแท็บจะไม่หยุดกระบวนการเก็บข้อมูล การหยุดกระบวนการจะขัดจังหวะ การเก็บข้อมูล; ภาพถ่ายประวัติไม่สามารถสร้างใหม่การแก้ไขหรือการลบทั้งหมดที่พลาดได้ ดู[วิธีการทำงานของการเก็บ](https://phishdestroy.github.io/TgWitness/th/docs/reference/collection/)ข้อมูลสำหรับนโยบายเหตุการณ์, แถวรอไฟล์แนบ, การแยกบัญชี และพฤติกรรมเมื่อเริ่มต้นใหม่

เซสชันและข้อมูลลับได้รับการเข้ารหัส เนื้อหาข้อความ สื่อ และข้อมูลที่ส่งออกจำเป็นต้องใช้ ดิสก์หรือโวลุ่มที่เข้ารหัส ลายเซ็นช่วยยืนยันความสมบูรณ์ของข้อมูลเมื่อเทียบกับกุญแจที่เชื่อถือได้; แต่ไม่ยืนยันแหล่งที่มาของ Telegram หรือป้องกันการปลอมแปลงโดยผู้ดำเนินการที่ ควบคุมเครื่องมือเก็บข้อมูลและกุญแจของมัน
