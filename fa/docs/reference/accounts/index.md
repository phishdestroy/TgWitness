# فرمت‌های حساب کاربری و جلسه

Canonical page: https://phishdestroy.github.io/TgWitness/fa/docs/reference/accounts/

ورود با شماره تلفن، کد QR یا کلید احراز هویت، وارد کردن جلسات تله‌تون، پایروگرام یا تلگرام دسکتاپ و اجرای چندین حساب کاربری.

[TgWitness](https://github.com/phishdestroy/TgWitness/blob/main/README.md) / [مستندسازی](https://github.com/phishdestroy/TgWitness/blob/main/docs/README.md) · [شروع کار](https://phishdestroy.github.io/TgWitness/fa/docs/reference/quickstart/)

![شروع کار](https://phishdestroy.github.io/TgWitness/assets/chapter-start.svg)

TgWitness به عنوان یک **حساب کاربری تلگرام** (نه یک ربات) از طریق MTProto، با استفاده از Telethon، وارد می‌شود. هر حساب در **فضای** کاری خود (که در API و ابزارهای خط فرمان به آن *workspace* گفته می‌شود) با جلسه، منابع، دفترچه یادداشت و کلید امضای مخصوص به خود قرار دارد.

فایل‌های جلسه، رشته‌های جلسه و کلیدهای احراز هویت، **مجوزهای حساب کاربری** هستند: هر کسی که یکی از آن‌ها را در اختیار داشته باشد می‌تواند به‌عنوان آن حساب کاربری عمل کند. آن‌ها حاوی تاریخچه پیام‌ها نیستند.

> [!هشدار] **از هر چیزی که تحمل از دست دادن آن را ندارید، استفاده نکنید.** ما قویاً توصیه می‌کنیم که حساب‌های شخصی یا هر حساب باارزش دیگری را متصل نکنید و روی حسابی که برایتان ارزش دارد، شناسه API / هش API ایجاد نکنید. این موضوع به معنای آزمایش‌نشده بودن TgWitness نیست: تلگرام حساب‌ها را به طور غیرقابل پیش‌بینی محدود و برای همیشه مسدود می‌کند — به دلیل حجم درخواست‌هایی که آن را بیش از حد می‌داند، صرف‌نظر از کلاینت یا هدف، و بدون هیچ‌گونه مستندات کافی. بسیاری از این مسدودسازی‌ها برگشت‌ناپذیر هستند. از حساب‌های اختصاصی استفاده کنید. اجرای روان تست‌ها به تلگرام بستگی دارد، نه به نرم‌افزار، و هیچ تضمینی برای آینده ندارد.

TgWitness فایل‌ها را بر اساس **محتویات**شان شناسایی می‌کند، نه بر اساس نامشان. تغییر نام یک فایل هرگز آن را تبدیل نمی‌کند.

## قبل از شروع: شناسهٔ API و هش API

شما می‌توانید بدون ایجاد یک اپلیکیشن API تلگرام وارد شوید. هنگامی که هیچ جفتی وارد نشده، وارد نشده یا از قبل در فضای کاری ذخیره نشده باشد، TgWitness یک جفت را از مجموعه داخلی خود از 50 جفت API عمومی (`tgwitness/api_pool.py`) انتخاب می‌کند، و برای ورود جدید، ابتدا به تلگرام دسکتاپ اولویت می‌دهد و یک جفت ذخیره شده را نگه می‌دارد؛ سایر گزینه‌ها به صورت تصادفی انتخاب می‌شوند. اگر تلگرام یک جفت را رد کند (`API_ID_INVALID`، `API_ID_PUBLISHED_FLOOD`، `UPDATE_APP_TO_LOGIN`)، جفت بعدی امتحان می‌شود، تا هشت جفت در هر ورود؛ جفت‌های رد شده تا راه‌اندازی مجدد نادیده گرفته می‌شوند. جفتی که با آن وارد شده است با حساب کاربری ذخیره شده و برای آن دوباره استفاده می‌شود. یک **شناسه API** و **هش API**، اپلیکیشن را به تلگرام معرفی می‌کنند؛ آنها به خودی خود حساب کاربری را تأیید اعتبار نمی‌کنند.

fields of connection missing use a deterministic device/OS pair from the bundled [opentele2 2.0.0 catalogs](https://github.com/DedInc/opentele2/tree/7e973bc71cd7a714ad13ac703c0895a90d36a735): Desktop `2040`, Android `6`, Android X `21724`, iOS `10840`, macOS `2834`, and Web `2496`. Android's source-build ID `4` also uses the Android catalog, as identified in [Telegram Android's BuildVars](https://github.com/DrKLO/Telegram/blob/master/TMessagesProj/src/main/java/org/telegram/messenger/BuildVars.java). وب به‌صورت پیش‌فرض روی A است؛ یک پسوند نسخه-اپلیکیشن وارداتی `K` یا بسته زبانی `macos`، K را انتخاب می‌کند، و نسخه `0.7.0`، Webogram را انتخاب می‌کند. شناسه‌های اپلیکیشن ناشناخته، پیش‌فرض‌های میزبان Telethon را حفظ می‌کنند. فیلدهای وارداتی همیشه برنده می‌شوند، از جمله نسخه قدیمی‌تر اپلیکیشن و بسته زبانی خالی. کاتالوگ هرگز شناسه/هش API را تغییر نمی‌دهد. نسخه اسنپ‌شات آن صراحتاً بررسی می‌شود، نه اینکه در حین ورود (لاگین) دریافت شود. یک پروفایل ذخیره شده پس از به‌روزرسانی‌ها پایدار باقی می‌ماند.

توابع `account.getAuthorizations` متادیتای مجوزهای ذخیره‌شده تلگرام را گزارش می‌کند؛ این تابع بازتاب هر `initConnection` جدید نیست. آن را با پروفایل ارسال‌شده واقعی مقایسه کنید. اتصال یک مجوز موجود، هش API همراه آن را اعتبارسنجی نمی‌کند: تابع `initConnection` شناسه API را ارسال می‌کند، در حالی که هش توسط درخواست‌های ورود استفاده می‌شود.

پس از احراز هویت با تلفن جدید یا QR، TgWitness پیکربندی، نزدیک‌ترین DC، وضعیت آنلاین، زبان‌ها (وقتی بسته زبان خالی نیست)، به‌روزرسانی‌های برنامه و به‌روزرسانی‌های شرایط خدمات را درخواست می‌کند، با فاصله 0.3–1.5 ثانیه بین درخواست‌ها. به‌روزرسانی وضعیت، به‌طور موقت حساب را آنلاین نشانه‌گذاری می‌کند. این توالی یک‌بار پس از تکمیل ورود اجرا می‌شود، نه در هنگام وارد کردن داده‌ها، اتصال مجدد یا راه‌اندازی مجدد. ابتدا احراز هویت ذخیره می‌شود؛ یک درخواست ناموفق، توالی را بدون تلاش مجدد یا رد ورود متوقف می‌کند. نتایج به صورت `account.initialized` ثبت می‌شوند، با نام‌های خطا به جای بدنه پاسخ‌ها. این توالی تضمینی در برابر محدودیت‌های حساب نیست.

برای `tdesktop` ، در صورت عدم وجود `tz_offset` ، از جابجایی UTC محلی سرور استفاده می‌شود که با استفاده از [الگوریتم opentele2](https://github.com/DedInc/opentele2/blob/7e973bc71cd7a714ad13ac703c0895a90d36a735/crates/opentele2-core/src/fingerprint.rs) (MIT؛ مجوز در `tgwitness/client_profiles.LICENSE` ) به 900 ثانیه گرد شده است. این مقدار در هر اتصال به‌روزرسانی می‌شود تا تغییرات ساعت تابستانی در آن منعکس شود. `tz_offset` واردشده در هر پلتفرمی اولویت دارد و دقیقاً، از جمله صفر، حفظ می‌شود. سایر موارد موجود در `initConnection.params` حفظ می‌شوند. فرم ورود HTTP، منطقه زمانی عددی بازگشتی از وارد کردن فایل را می‌پذیرد؛ مقادیر بولی، کسری و آفست‌ها خارج از محدوده پشتیبانی‌شده رد می‌شوند.

مسیرهای مستقیم، SOCKS5 و HTTP CONNECT از `ConnectionTcpObfuscated` (MTProto کوتاه‌شده و مبهم‌شده) تل‌تون استفاده می‌کنند. HTTPS CONNECT، TLS را تا پروکسی حفظ می‌کند و از همان انتقال مبهم‌شده در داخل تونل استفاده می‌کند. MTProxy، انتقال میانی تصادفی و پردازش مخفی خود را حفظ می‌کند. سوئیچ‌های مسیر از همان گزینه‌ها استفاده می‌کنند. ابهام‌سازی، قالب‌بندی بسته را تغییر می‌دهد؛ این کار حساب کاربری یا متادیتای کلاینت آن را از تلگرام پنهان نمی‌کند و به معنای مصونیت در برابر محدودیت‌ها نیست.

پس از اتصال یک کلاینت مجاز، TgWitness پیکربندی، نزدیک‌ترین مرکز داده (DC)، مجوز فعلی، خط پایه بررسی‌شده لایه، زبان‌ها، به‌روزرسانی‌های برنامه و به‌روزرسانی‌های شرایط خدمات را بررسی می‌کند. این تشخیص‌ها یک‌بار برای هر نمونه کلاینت، قبل از جمع‌آوری اجرا می‌شوند و به همراه زمانشان در زیر جزئیات اتصال نمایش داده می‌شوند. `account.connection_checked` نتیجه را بدون هش‌های جلسه، آی‌پی‌ها، توکن‌ها یا هش‌های API ثبت می‌کند. آنها هرگز شرایط را قبول نمی‌کنند یا به‌روزرسانی‌ها را نصب نمی‌کنند. یک خطای درخواست یا توقف به دلیل FloodWait، درخواست‌های بعدی را متوقف می‌کند؛ یک نتیجه گمشده نامشخص باقی می‌ماند. بررسی‌های محلی همچنان می‌توانند نتایج خود را گزارش دهند، در حالی که بررسی‌های شبکه نادیده گرفته می‌شوند.

تشخیص‌های FloodWait، روش TL ناموفق، هرگونه روکش‌های Takeout/range، انتظار درخواست‌شده توسط سرور و مهلت نهایی مؤثر را در `telegram.backoff` حفظ می‌کنند. جزئیات اتصال، در حالی که درخواست‌ها متوقف شده‌اند، روش و مهلت نهایی را نشان می‌دهند. این تشخیص شامل شمارنده‌های تماس کلاینت برای هر روش از زمان ایجاد آن کلاینت است؛ این شمارنده‌ها حل اختلاف هم‌تراز (nested peer resolution) را به صورت جداگانه می‌شمارند، اما بسته‌ها یا تلاش‌های داخلی برای تکرار (internal retry attempts) تل‌تون را نمی‌شمارند. شمارنده‌های فعلی نیز به عنوان `collector.rpc_activity` در API وضعیت در دسترس هستند. هیچ یک از آرگومان‌های درخواست، نام‌های کاربری، هش‌های دسترسی یا متن استثنا گنجانده نشده‌اند. آخرین گزارش تشخیصی و مهلت کامل پس از راه‌اندازی مجدد نیز باقی می‌مانند. وقفه‌های قبلی بدون رکورد روش، به صورت گذشته‌نگر قابل انتساب نیستند. برای بررسی منبع و تمایز بین کشف و استخراج تاریخچه، به [محدودیت‌های خروجی](https://github.com/phishdestroy/TgWitness/blob/main/docs/EXPORT-LIMITS.md) مراجعه کنید.

`official_app=True` یا `False` پرچم مجوز فعلی تلگرام است. هیچ‌کدام از این مقادیر مشخص نمی‌کنند که حساب کاربری محدود، مورد اعتماد یا تحت نظارت است. اسنپ‌شات‌های موجود `account.devices` در حالت شواهد، تاریخچه تمام دستگاه‌های واردشده را حفظ می‌کنند؛ در حالی که تشخیص‌های اتصال فقط توصیف دستگاه فعلی را نگه می‌دارند.

پیش از اتصال، بررسی‌های مشاوره‌ای، پلتفرم API، بسته زبانی، فرمت‌های دستگاه/سیستم‌عامل و نسخه برنامه، لوکال سیستم موبایل و لایه اسکیمای واقعی تل‌تون را با خط پایه کاتالوگ بررسی‌شده مقایسه می‌کنند. هشدارها در لاگ سرور و متادیتای وضعیت حساب ظاهر می‌شوند؛ آنها هرگز مقادیر واردشده را جایگزین نمی‌کنند یا لایه اسکیما را تغییر نمی‌دهند. یک لایه متفاوت، سیگنال بررسی سازگاری است، نه مدرکی بر یک حساب کاربری خراب یا محدود. این بررسی‌ها و `official_app` تأیید نمی‌کنند که تلگرام این حساب کاربری را از محدودیت‌ها در امان می‌داند. وضعیت حساب کاربری قطع‌ارتباط‌شده به جای تولید یک توضیح دستگاه دیگر، از پروفایل ذخیره شده استفاده می‌کند.

برای استفاده از برنامهٔ خود به جای آن (حساب کاربری که آن را ثبت می‌کند در معرض خطر است؛ ببینید: [چرا استخر API داخلی؟](https://github.com/phishdestroy/TgWitness/blob/main/docs/PROJECT-GUIDE.md#connect-a-telegram-account)):

1. [وب‌سایت my.telegram.org](https://my.telegram.org) را باز کنید و با هر شماره تلفنی که مالک آن هستید وارد شوید. کد به اپلیکیشن تلگرام ارسال می‌شود، نه از طریق پیامک.
2. **ابزارهای توسعهٔ API را** انتخاب کنید.
3. یک برنامه ایجاد کنید: هر عنوان و نام کوتاه (۵–۳۲ حرف)، پلتفرم **دسکتاپ**. URL و توضیحات می‌توانند خالی بمانند.
4. **ID اپلیکیشن api_id** (یک عدد) و **هش اپلیکیشن api_hash** (۳۲ کاراکتر هگزادسیمال) را کپی کنید.

در پنل، **شناسه API + هش** را زیر فرم ورود پیدا کنید. می‌توانید یک جفت `api_id:api_hash` را در **شناسه API** بچسبانید و هر دو فیلد پر می‌شوند. یک جفت می‌تواند برای تمام حساب‌های کاربری شما استفاده شود. پس از ورود موفقیت‌آمیز، این جفت فقط در همان فضای کاری ذخیره و رمزگذاری می‌شود و هرگز به مرورگر بازگردانده نمی‌شود.

سه اعتبارنامه‌ی متفاوت درگیر هستند:

| مخفی | باز می‌کند | محل استقرار |
| --- | --- | --- |
| توکن پنل | پنل وب TgWitness | `panel-token.txt` در دایرکتوری داده‌ها، یا `TGWITNESS_TOKEN` |
| شناسه API + هش | هیچ‌چیز به‌تنهایی؛ اپلیکیشن را شناسایی می‌کند | جفت پیش‌ساخته، تنظیمات واردشده، یا اپلیکیشن خودتان در my.telegram.org |
| مجوز حساب | حساب تلگرام | ایجادشده از طریق ورود با تلفن/QR یا واردشده به‌عنوان یک جلسه |

اگر تلگرام باید از طریق یک پروکسی دسترسی پیدا کند، ابتدا آن را در **حساب کاربری → تنظیمات → تنظیمات اتصال → تغییر مسیر اتصال** تنظیم کنید.

## شماره تلفن

1. **حساب کاربری را** باز کنید، به برگه **«تلفن»** بروید و شماره را به فرمت بین‌المللی وارد کنید، برای مثال `+44 7700 900123`. فاصله‌ها و خط‌های تیره به طور خودکار حذف می‌شوند.
2. روی **ادامه** کلیک کنید. شناسه API و هش می‌توانند خالی بمانند.
3. کدی را که تلگرام ارسال می‌کند وارد کنید (معمولاً به اپلیکیشن تلگرام؛ ارسال از طریق پیامک تضمین‌شده نیست).
4. اگر حساب کاربری احراز هویت دو مرحله‌ای داشته باشد، آن رمز عبور را وارد کنید. این توکن پنل نیست و کد عبور دستگاه نیز نیست.
5. شناسه حساب کاربری نمایش‌داده‌شده پس از ورود را بررسی کنید، سپس منابع را انتخاب کنید.

کدهای ورود و رمز عبور احراز هویت دو مرحله‌ای هرگز روی دیسک ذخیره نمی‌شوند.

## کد QR

از این زمانی استفاده کنید که حساب کاربری قبلاً در یک تلفن یا رایانه دیگر وارد شده باشد.

1. زبانه‌ی **کد QR** → **نمایش کد QR**. شناسهٔ API + هش می‌توانند خالی بمانند.
2. روی دستگاه وارد‌شده: **تنظیمات → دستگاه‌ها → اتصال دستگاه دسکتاپ**، کد را اسکن کرده و تأیید کنید.
3. در صورتی که تلگرام درخواست کند، رمز عبور ۲FA را در TgWitness وارد کنید.

تصویر QR به‌صورت محلی تولید می‌شود. کدها منقضی می‌شوند؛ برای تلاش مجدد روی **«تولید کد QR دیگر»** کلیک کنید. قفل کردن پنل، تغییر فضای کاری یا شروع ورود دیگری، کد در انتظار را لغو می‌کند.

## کلید اuth + شناسه DC

کلید احراز هویت (Auth Key) یک مجوز خام ۲۵۶ بایتی است که پشت هر جلسه تلگرام قرار دارد و به صورت **۵۱۲ کاراکتر هگزادسیمال**، به همراه شماره مرکز داده **DC 1–5** نوشته می‌شود.

1. **کلید احراز هویت** تب. کلید کامل را الصاق کنید؛ کلید کوتاه‌شده حاوی `…` کار نخواهد کرد.
2. شناسه DC ارائه‌شده همراه با کلید را انتخاب کنید.
3. اختیاری: **شناسه کاربری** را وارد کنید. در غیر این صورت، اگر تلگرام حساب متفاوتی را گزارش کند، TgWitness از اتصال خودداری می‌کند.
4. روی **حساب Connect** کلیک کنید.

یک کلید احراز هویت (۵۱۲ کاراکتر) با هش API (۳۲ کاراکتر) یکسان نیست. همین کلید همچنین می‌تواند به صورت JSON وارد شود، به [JSON حساب کاربری](https://phishdestroy.github.io/TgWitness/fa/docs/reference/accounts/#account-json) مراجعه کنید.

## فایل‌های حساب

**گزینه «حساب جدید» را** باز کنید **→ «فایل‌ها» را** انتخاب کرده و تا **چهار فایل متعلق به یک حساب** (در مجموع **۸ مگابایت**) را برگزینید، سپس دکمه **«اتصال حساب» را** فشار دهید.

فرم‌های **فایل‌ها**، **کلید احراز هویت** و واردات انبوه هشدار جلسه موازی را قبل از اتصال نمایش می‌دهند. به طور پیش‌فرض، مجوزهای وارد شده دوباره استفاده می‌شوند. در حالی که کلید یک کلاینت اصلی در اینجا در حال استفاده است، آن کلاینت را بسته نگه دارید. **فایل‌ها** و **کلید احراز هویت** همچنین گزینه **ایجاد یک مجوز مستقل** را ارائه می‌دهند که در زیر توضیح داده شده است. واردات انبوه همچنان از حالت مستقیم استفاده می‌کند. ورود با تلفن و ورود با QR تعاملی، مجوزهای جداگانه‌ای ایجاد می‌کنند. سربرگ هشدار در فرم وارد کردن فایل‌ها، کلید و فرم‌های بارگذاری انبوه، قبل از اتصال، هشدار جلسه موازی را نمایش می‌دهد. به طور پیش‌فرض، مجوزهای وارد شده دوباره استفاده می‌شوند. تا زمانی که کلید آن در اینجا در حال استفاده است، کلاینت اصلی را بسته نگه دارید. فایل‌ها و کلید همچنین امکان ایجاد یک مجوز مستقل را که در زیر توضیح داده شده است، فراهم می‌کنند. بارگذاری انبوه همچنان از حالت مستقیم استفاده می‌کند. ورود با تلفن و QR تعاملی، مجوزهای جداگانه‌ای ایجاد می‌کنند.

- فایل‌ها **در حافظه‌ی** سرور TgWitness شما تبدیل می‌شوند. بارگذاری‌ها ذخیره نمی‌شوند، فایل‌های ZIP روی دیسک استخراج نمی‌شوند و هیچ سرویس خارجی‌ای درگیر نمی‌شود.
- سپس جلسهٔ حاصل با تلگرام بررسی می‌شود. اگر یک فایل شناسهٔ کاربر را مشخص کند، باید با حسابی که تلگرام گزارش می‌کند مطابقت داشته باشد.
- فایل‌هایی که حساب‌های مختلف یا اعتبارنامه‌های API متفاوت را توصیف می‌کنند، به جای انتخاب یکی، رد می‌شوند.
- **کد عبور یا متن جلسه**، فیلد رمز عبور محلی TData را در بر می‌گیرد، یک کادر برای چسباندن یک StringSession و **فایل‌های Read بدون نیاز به ورود** (فرم را بدون تماس با تلگرام پر می‌کند).

### ایجاد یک مجوز مستقل

**ایجاد یک مجوز مستقل را** قبل از اتصال فایل‌های وارد شده یا یک کلید احراز هویت (Auth Key) انتخاب کنید. TgWitness اجمالاً به اهداکننده وارد شده متصل می‌شود، از آن برای تأیید توکن ورود با QR کلاینت جدید استفاده می‌کند و بلافاصله پس از تأیید، اتصال به اهداکننده را قطع می‌کند. کلاینت جدید دارای کلید احراز هویت خود و یک پروفایل دسکتاپ جداگانه است. اعتبارنامه‌های API و پروفایل دستگاه ارائه‌شده توسط اهداکننده فقط برای اتصال اهداکننده استفاده می‌شوند. هیچ مجوز موجودی خارج نمی‌شود یا لغو نمی‌گردد.

**در طول این مرحله، کلاینت اصلی اهداکننده را کاملاً بسته نگه دارید.** اتصال اولیه همچنان از کلید کپی‌شده خود استفاده می‌کند، بنابراین این حالت نمی‌تواند آن خطر استفاده موازی اولیه را از بین ببرد. پس از اتصال مجوز جدید، مالک می‌تواند کلاینت اصلی را دوباره باز کند و از هر دو به طور مستقل استفاده نماید. ورود تعاملی با **کد QR** به کلاینت اصلی اجازه می‌دهد تا ورود را بدون کپی یا اتصال کلید خود در اینجا تأیید کند.

اگر تلگرام درخواست احراز هویت دو مرحله‌ای (2FA) کند، این حالت در صورت وجود، از `twoFA` انتخاب‌شده در JSON استفاده می‌کند، یا درخواست رمز عبور می‌کند. یک رمز عبور واردشده‌ی ردشده به فرم رمز عبور بازمی‌گردد. رمزهای عبور ذخیره نمی‌شوند. کلید کاندیدای ذخیره شده در `independent_login.enc` به‌صورت رمزگذاری‌شده، از جمله تغییرات حین مهاجرت به مرکز داده، ذخیره می‌شود. پس از یک وقفه، برای از سرگیری کاندیدای ذخیره شده، همان اهداکننده و این گزینه را انتخاب کنید. فضای کاری برای آن حساب کاربری رزرو شده باقی می‌ماند؛ عدم موفقیت در تکمیل، فضای کاری جدید را حذف نمی‌کند. دایرکتوری داده و کلید گاوصندوق آن را حفظ کنید. اعتبارنامه‌های نهایی و رکورد مجله `account.authorized` شامل روش وارد کردن، فرمت‌های ورودی و شناسه API اهداکننده هستند، بدون کلید یا رمز عبور اهداکننده.

در 5 نوامبر 2026، یک حساب کاربری اختصاصی بررسی‌های زنده را با اهداکنندگان Telethon، Pyrogram و TData پشت سر گذاشت: 2تکمیل احراز هویت دو مرحله‌ای، کلیدهای احراز هویت جدید و مجزا، دسترسی همزمان اهداکننده و مشتری جدید، و خواندن یک کانال عمومی. مورد تله‌تون همچنین یک کاندیدای ذخیره شده را پس از یک وقفه در مرحله رمز عبور از سر گرفت. هر احراز هویت جدید شش درخواست اولیه پس از ورود را تکمیل کرد و ژورنال امضا شده آن تأیید شد. جلسه اصلی در هر چهار فرمت ارائه‌شده قابل استفاده باقی ماند.

تلگرام [پایگاه داده خطاهای RPC](https://core.telegram.org/api/errors.json) وابسته `FRESH_CHANGE_ADMINS_FORBIDDEN` با تغییر مدیران، `FRESH_CHANGE_PHONE_FORBIDDEN` با تغییر شماره تلفن، و `FRESH_RESET_AUTHORISATION_FORBIDDEN` با لغو سایر جلسات، تغییر مدت‌زمان عمر آنها یا ثبت یک کلید عبور. `SESSION_TOO_FRESH_*` و `PASSWORD_TOO_FRESH_*` مربوط به انتقال مالکیت و برداشت درآمد یا هدیه است. این‌ها عملیات جمع‌آوری نیستند؛ ورود جدید به معنای یک ممنوعیت کلی ۲۴ ساعته برای خواندن نیست. خروجی می‌تواند به طور جداگانه بازگرداندTAKEOUT_INIT_DELAY_*. TgWitness مکث‌های درخواست‌شده توسط سرور را حفظ می‌کند و به طور خودکار برای پذیرش توکن دوباره تلاش نمی‌کند یا برای دور زدن محدودیت‌ها، جلسات را لغو نمی‌کند. 24ممنوعیت خواندن برای مدت -ساعته. Export می‌تواند به طور جداگانه بازگرداند `TAKEOUT_INIT_DELAY_*`. TgWitness تعلیق‌های درخواست‌شده توسط سرور را حفظ می‌کند و به‌طور خودکار پذیرش توکن را مجدداً امتحان نمی‌کند یا جلسات را برای دور زدن محدودیت‌ها لغو نمی‌کند.

### تله‌تون `.session`

|  |  |
| --- | --- |
| چیست | پایگاه دادهٔ SQLite که ابزارهای مبتنی بر Telethon ایجاد می‌کنند، برای مثال `my_account.session` |
| مورد تأیید | جدول‌ها `sessions` (با `dc_id`، `server_address`، `port`، `auth_key`) و `version` = ۷ یا ۸ |
| پیش‌نیازها | دقیقاً یک ردیف جلسه مجاز؛ یک پایگاه دادهٔ بسته و کامل |

ابتدا برنامه‌ای را که فایل را ایجاد کرده است ببندید. اگر فایل‌های `my_account.session-journal` یا `my_account.session-wal` در کنار آن وجود داشته باشد، پایگاه داده نهایی نشده است: کلاینت اصلی را به درستی باز و ببندید. حذف این فایل‌های جانبی (sidecar) می‌تواند یک نسخه خراب به جا بگذارد.

### پایروگرام `.session`

|  |  |
| --- | --- |
| چیست | پایگاه دادهٔ SQLite که ابزارهای مبتنی بر Pyrogram ایجاد می‌کنند |
| مورد تأیید | جدول `sessions` با `dc_id`، `auth_key`، `test_mode`، `user_id`، `is_bot`؛ `version` = ۲ یا ۳ |
| پیش‌نیازها | یک جلسهٔ **کاربر** مجاز در شبکهٔ تولید. جلسات بات و DC آزمایشی رد می‌شوند. |

شناسه کاربری ذخیره‌شده هنگام ورود با تلگرام بررسی می‌شود.

### جفت جلسه + JSON

حساب‌ها اغلب به صورت دو فایل با نام یکسان توزیع می‌شوند، برای مثال `447700900123.session` و `447700900123.json`. **هر دو را** همزمان انتخاب کنید.

- از روی JSON، TgWitness از `app_id`/`api_id` و `app_hash`/`api_hash` استفاده می‌کند، بنابراین معمولاً نیازی به وارد کردن اعتبارنامه‌های API ندارید.
- پروفایل اتصال از `device_model` (با نام مستعار `device`)، `system_version` (با نام مستعار `sdk`)، `app_version`، `lang_code`، `system_lang_code` (با نام مستعار `system_lang_pack`)، `lang_pack` و `tz_offset` اختیاری (ثانیه‌ها از UTC، از -43200 تا 50400) استفاده می‌کند. میدان‌های ارائه‌شده بر پیش‌فرض‌های تولیدشده و زبان پنل/مرورگر اولویت دارند. نام‌های مستعار تداخلی رد می‌شوند. پروفایل حل‌شده در اعتبارنامه‌های فضای کاری رمزگذاری‌شده ذخیره می‌شود و پس از راه‌اندازی مجدد، از جمله نسخه اپ آن، دوباره استفاده می‌شود.
- توکن‌های `phone`، تنظیمات پروکسی و توکن‌های دستگاه **نادیده** گرفته می‌شوند. `twoFA` فقط قابل خواندن است وقتی **ایجاد یک مجوز مستقل** انتخاب می‌شود؛ وارد کردن مستقیم آن را نادیده می‌گیرد.
- یک JSON بدون فیلد احراز هویت پشتیبانی‌شده تنها شامل اطلاعات متادیتا است. فایل جلسه آن را اضافه کنید یا با ورود با تلفن یا QR ادامه دهید. یک JSON حاوی یک جلسه پشتیبانی‌شده یا کلید احراز هویت (Auth Key) می‌تواند به‌تنهایی احراز هویت کند؛ به [JSON حساب کاربری](https://phishdestroy.github.io/TgWitness/fa/docs/reference/accounts/#account-json) مراجعه کنید.

### تلگرام دسکتاپ (TData)

TData پوشهٔ `tdata` در اپلیکیشن Telegram Desktop (اپلیکیشن چندسکویی از desktop.telegram.org) است.

| سیستم | مکان پیش‌فرض `tdata` |
| --- | --- |
| ویندوز | `%APPDATA%\Telegram Desktop\tdata` (تلگرام قابل حمل: در کنار `Telegram.exe`) |
| لینوکس | `~/.local/share/TelegramDesktop/tdata` |
| macOS | `~/Library/Application Support/Telegram Desktop/tdata` |

برای وارد کردن آن:

> **هشدار جلسه موازی.** واردات مستقیم TData از کلید مجوزدهی Telegram Desktop استفاده مجدد می‌کند. از آن کلید به طور همزمان در Desktop و TgWitness استفاده نکنید. تلگرام می‌تواند با خطای `AUTH_KEY_DUPLICATED` مجوز را باطل کند و هر دو نسخه را تا زمان ورود مجدد غیرقابل استفاده سازد.
>
>
>
> Desktop را به طور کامل، شامل فرآیند سینی (tray) آن، ببندید و در حالی که TgWitness از جلسه وارد شده استفاده می‌کند، آن نسخه را بسته نگه دارید. **خروج کنید، اما از سیستم خارج نشوید یا جلسه را لغو نکنید:** لغو همچنین نسخه وارد شده را باطل می‌کند. اگر به اجرای همزمان هر دو کلاینت نیاز دارید، گزینه **ایجاد یک مجوز مستقل را** انتخاب کرده و Desktop را تا زمانی که ورود جدید با موفقیت انجام شود بسته نگه دارید، یا با تلفن یا QR به TgWitness وارد شوید. استفاده از یک حساب کاربری اختصاصی توصیه می‌شود، اما این کار، کلیدهای کپی‌شده را برای استفاده همزمان ایمن نمی‌سازد.
>
>
>
> این امر در مورد موارد وارد شده نیز صدق می‌کند `.session` فایل‌ها، متن StringSession و هگز Auth Key. سایر کلاینت‌ها با مجوزهای مستقل خود می‌توانند به حالت ورود باقی بمانند. به [مستندات AUTH_KEY_DUPLICATED تلگرام](https://core.telegram.org/api/errors#406-not-acceptable) مراجعه کنید.

1. کاملاً از تلگرام دسکتاپ خارج شوید.
2. یک فایل ZIP ایجاد کنید که **فقط** شامل این دو مورد از `tdata` باشد:

   - `key_datas`
   - پایان فایل ۱۶ کاراکتری که با `s` خاتمه می‌یابد، در کنار آن، معمولاً `D877F783D5D3EF8Cs`

   زیپ کردن کل پوشه به همراه کش رسانه‌ای آن معمولاً از محدودیت‌ها (۵۱۲ مورد، ۳۲ مگابایت بدون فشرده‌سازی) فراتر می‌رود. ۳. در بخش **«فایل‌ها**»، زیپ را انتخاب کنید. اگر تلگرام دسکتاپ **رمز عبور محلی** دارد، ابتدا آن را در قسمت **«رمز عبور» یا متن جلسه** وارد کنید. این رمز عبور احراز هویت دو مرحله‌ای (2FA) نیست.

پشتیبانی‌شده: یک حساب در هر آرشیو، ذخیره‌سازی مدرن `key_datas`/`key_data0`/`key_data1`، رمز عبور محلی. پشتیبانی‌نشده: پوشه‌هایی با چندین حساب واردشده، طرح‌بندی‌های قدیمی‌تر دسکتاپ، فایل‌های ZIP محافظت‌شده با رمز عبور، و اپلیکیشن بومی جداگانه macOS به نام «Telegram for macOS».

### جلسه رشته‌ای تله‌تون

یک خط متن، معمولاً با شروع با `1` و با طول حدود ۳۵۰ کاراکتر. آن را به عنوان یک فایل `.txt` یا `.tgwitness-session` (حداکثر ۴ کیلوبایت) بارگذاری کنید، یا آن را زیر **متن رمز عبور یا جلسه** قرار دهید. فقط رشته‌های تله‌تون پذیرفته می‌شوند؛ رشته‌های Pyrogram و TDLib از فرمت‌های متفاوتی استفاده می‌کنند.

### JSON حساب

یک شیء JSON، حداکثر **۶۴ کیلوبایت**، در فایلی با پسوند **`.json`**.

| میدان (نام‌های مستعار) | معنی |
| --- | --- |
| `api_id` (`app_id`) | شناسهٔ برنامه، یک عدد مثبت |
| `api_hash` (`app_hash`) | هَش برنامه، ۳۲ کاراکتر هگزادسیمال |
| `string_session` (`session_string`, `session_str`; `session` قدیمی) | متن Telethon StringSession، نه نام فایل |
| `auth_key` (`auth_key_hex`) + `dc_id` | کلید احراز هویت ۵۱۲ کاراکتری و DC 1–5 را تکمیل کنید |
| `user_id` (`id`) | اختیاری؛ پیش از ذخیرهٔ مجوز، با تلگرام بررسی می‌شود |
| `device_model` (`device`) | توضیحات دستگاه اتصال |
| `system_version` (`sdk`) | نسخه سیستم‌عامل اتصال |
| `app_version` | نسخهٔ اپلیکیشن ارسال‌شده به تلگرام |
| `lang_code`, `system_lang_code` (`system_lang_pack`), `lang_pack` | زبان کلاینت، زبان سیستم و بسته زبان کلاینت؛ یک `lang_pack` خالی مجاز است |
| `tz_offset` | تغییر ساعت اختیاری UTC به ثانیه، ارسال‌شده در `initConnection.params`؛ رشته عدد صحیح یا عدد صحیح اعشاری |

اگر هم نام مستعار و هم نام اصلی وجود داشته باشند، باید با هم مطابقت داشته باشند. فیلدهای صریح جلسه تل‌تون بر یک بلوب عمومی `session` در قالب دیگری اولویت دارند. اگر هر دو حاوی جلسات قابل تشخیص تل‌تون باشند، باید همان مجوز را توصیف کنند. در صورت عدم وجود فیلد صریح، `session` باید یک StringSession معتبر تل‌تون باشد. مثال‌ها:

```
{ "app_id": 1234567, "app_hash": "0123456789abcdef0123456789abcdef" }
```

```
{
  "api_id": 1234567,
  "api_hash": "0123456789abcdef0123456789abcdef",
  "auth_key": "REPLACE_WITH_ALL_512_HEXADECIMAL_CHARACTERS",
  "dc_id": 2,
  "user_id": 123456789
}
```

اولین مثال فقط اطلاعات اعتبارنامه‌ی API را پر می‌کند؛ با تلفن یا QR وارد شوید، یا یک فایل جلسه اضافه کنید. فهرست‌های دسته‌ای (یک آرایه‌ی JSON از حساب‌ها) پذیرفته نمی‌شوند.

## شناسایی کنید که چه چیزی در اختیار دارید

| می‌بینید | این است | استفاده |
| --- | --- | --- |
| `*.session`؛ باز کردن آن در یک ویرایشگر متن، `SQLite format 3` را در بالا نشان می‌دهد | تله‌تون یا پایروگرام اس‌کیوالایت | **فایل‌ها** (به‌طور خودکار شناسایی‌شده) |
| یک پوشهٔ `tdata` حاوی `key_datas` | تلگرام دسکتاپ TData | دو فایل را فشرده کنید، سپس **Files** |
| یک خط متن با شروع `1`، حدود ۳۵۰ کاراکتر | جلسه رشته‌ای تله‌تون | **فایل‌ها** |
| `*.json` با `app_id`/`app_hash` | متادیتای همراه | **فایل‌ها**، همراه با جلسهٔ آن |
| `*.json` با `auth_key` یا `string_session` | JSON حساب | **فایل‌ها** |
| ۵۱۲ کاراکتر `0-9a-f` | کلید رمزنگاری | **کلید رمزنگاری** |
| ۳۲ کاراکتر `0-9a-f` | هَش API | **شناسهٔ API + هَش** |
| `td.binlog` یا `db.sqlite` از یک اپلیکیشن TDLib | ذخیره‌سازی TDLib | پشتیبانی نمی‌شود |
| `123456789:AA…` | توکن بات | پشتیبانی نمی‌شود |

## فرمت‌های پشتیبانی‌نشده

| قالب | جایگزین |
| --- | --- |
| ذخیره‌سازی TDLib (`td.binlog`) و خروجی‌های TDLib | ورود با تلفن یا QR |
| **رشته‌های** جلسه Pyrogram | از فایل Pyrogram `.session` استفاده کنید، یا تلفن/QR |
| TData با چندین حساب کاربری واردشده | از حساب‌های دیگر در تلگرام دسکتاپ خارج شوید، یا از فایل جلسهٔ اختصاصی هر حساب استفاده کنید |
| توکن‌های بات | پشتیبانی‌نشده: TgWitness به‌عنوان یک حساب کاربری مشاهده می‌کند |
| فهرست‌های CSV/JSON از حساب‌های متعدد | فایل‌های نشست پشتیبانی‌شده را از طریق **حساب‌ها → وارد کردن حساب‌ها** وارد کنید، یا در فضاهای کاری مجزا با شماره تلفن/QR وارد شوید |
| جلسات Test-DC یا بات | از یک حساب کاربری تولید استفاده کنید |

## حساب‌های متعدد

روی **+** در کنار انتخابگر حساب کاربری ضربه بزنید، یا مسیر **حساب کاربری → تنظیمات → تنظیمات اتصال → فضاهای کاری را** باز کنید، یک برچسب وارد کرده و وارد شوید.

- هر تعداد فضای کاری، از جمله فضای اصلی. هر کدام دارای جلسه، مسیر پروکسی، منابع، سیاست ضبط، دفترچه شواهد، کلید امضا، نقاط کنترل و خروجی‌های خود هستند.
- تغییر فضای کاری نمایش‌داده‌شده، سایر فضاها را متوقف نمی‌کند.
- یک ژورنال به حساب کاربری که آن را ایجاد کرده متصل می‌ماند. ورود به سیستم با حساب کاربری متفاوت نیازمند یک فضای کاری دیگر است و یک حساب نمی‌تواند به دو فضای کاری اختصاص یابد.
- توکن پنل اصلی بر تمام فضاهای کاری کنترل دارد. [دسترسی صادرشده](https://phishdestroy.github.io/TgWitness/fa/docs/reference/access/) می‌تواند افراد دیگر را به حساب‌ها و چت‌های منتخب محدود کند، با مجوزهای جداگانه و محدودیت‌های جلسه.
- **حساب‌ها** یک فضای کاری را بازنامه‌گذاری می‌کند و یکی از فضاهای کاری افزوده‌شده را همراه با جلسه، دفترچه، منابع و کلید امضای آن حذف می‌کند. فضای کاری اصلی را نمی‌توان از پنل حذف کرد.

### ورود دسته‌ای و گروه‌های حساب

برای افزودن چندین حساب، جفت کردن فایل‌ها بر اساس نام پایه و مشاهده نتیجه هر ورود، از مسیر **حساب‌ها → وارد کردن حساب‌ها** استفاده کنید. هر حساب فضای کاری مخصوص به خود را دریافت می‌کند.

یک گروه حساب‌های مرتبط را بدون ادغام جلسات، کلیدها یا شواهدشان در کنار هم نگه می‌دارد. **باز کردن گروه** در **بخش حساب‌ها** به صفحهٔ آن در `/groups/<id>`:

- **حساب‌ها:** مسیر اتصال، مشاهده و آخرین پیام هر عضو، با شروع**همه** و **توقف همه**.
- **نیاز به توجه:** حساب‌هایی که از آن‌ها خارج شده‌اند، در دسترس نیستند یا مشکل اتصال، دریافت، منبع یا رسانه دارند؛ هر نام به کارت مربوطه منتهی می‌شود.
- **چت‌ها در چندین حساب قابل مشاهده‌اند:** منابع مشترک، حساب‌هایی که آن‌ها را مشاهده می‌کنند و وقفه‌ها در دورهٔ مشاهدهٔ فضای کاری موجود (تا هفت روز). **خروجی‌گیری با N حساب،** خروجی یک کانال یا ابرگروه را بین آن‌ها تقسیم می‌کند و یک آرشیو را امضا می‌کند.
- **صادرات گروه:** یک ZIP با خروجی امضا‌شده هر حساب زیر `accounts/` و `manifest.json` که شامل امضاهای SHA-256 و اثرانگشت کلیدهای هر حساب است، امضا شده توسط فضای کاری اصلی در `manifest.signature.json`. هر آرشیو حساب را به طور جداگانه با `python -m tgwitness.verify` و اثر انگشت معتبر آن حساب.

اعضا تنظیمات گروه را به اشتراک می‌گذارند؛ یک حساب می‌تواند مقادیر خود را حفظ کند. به [تنظیمات مشترک](https://phishdestroy.github.io/TgWitness/fa/docs/reference/settings/#account-groups)، [راهنمای وارد کردن و گروه‌ها](https://github.com/phishdestroy/TgWitness/blob/main/docs/wiki/Accounts.md#import-accounts-and-share-settings) و [داشبورد استخر MTProxy](https://github.com/phishdestroy/TgWitness/blob/main/docs/wiki/Proxies.md#pool-dashboard-and-custom-sources) مراجعه کنید.

## خروج

**گزینه حساب → خروج از تلگرام** (با توقف مشاهده) از تلگرام می‌خواهد که جلسه را پایان دهد، بنابراین این جلسه از بخش **تنظیمات → دستگاه‌ها** در حساب کاربری نیز ناپدید می‌شود و از گاوصندوق فضای کاری حذف می‌گردد. دفترچه یادداشت، منابع، تنظیمات و کلید امضا باقی می‌مانند و دفترچه یادداشت، خروج را ثبت می‌کند. محیط کاری همچنان متعلق به حساب کاربری خود است: فقط همان حساب کاربری می‌تواند دوباره به آن متصل شود. اگر تلگرام پاسخی ندهد، جلسه همچنان در اینجا حذف می‌شود و پنل این موضوع را اعلام می‌کند؛ جلسه را در تلگرام تحت **«تنظیمات → دستگاه‌ها»** پایان دهید.

## حفظ امنیت فایل‌های حساب

- با هر `.session`، فایل ZIP TData، StringSession، کلید احراز هویت و JSON حساب کاربری مانند یک رمز عبور رفتار کنید. TgWitness مجوز واردشده را در گاوصندوق رمزگذاری‌شده خود نگه می‌دارد؛ شما می‌توانید بعداً فایل‌های اصلی را حذف کنید.
- یک مجوز را همزمان در دو برنامه اجرا نکنید. تلگرام ممکن است آن را لغو کند (`AUTH_KEY_DUPLICATED`)، و هر دو نسخه از کار می‌افتند.
- یک جلسه منقضی‌شده یا لغوشده را نمی‌توان با تبدیل احیا کرد. دوباره وارد شوید.
