# 케이스 보드 구축하기

Canonical page: https://phishdestroy.github.io/TgWitness/ko/docs/case-board/

저장된 메시지를 팀이 함께 작업하는 사건으로 바꿉니다.

북마크, 정확한 인용, 슬라이스, 토론이 각각 출처에 연결됩니다. 모든 변경은 서명된 수정본입니다.

## 메시지에서 사건 카드로

1. **조사 → 케이스 보드**(표준 또는 전문가 모드). 사건용 컬렉션을 만듭니다.
2. **저널**이나 채팅에서 **보드에 추가**(또는 **B**)를 누릅니다. 카드는 받은편지함에 들어가며, 제목을 붙이고 옮깁니다.
3. 메시지에서 텍스트를 선택하고, **하이라이트 → 보드**가 정확한 인용과 버전을 보관합니다. 왜 중요한지 적어 둡니다.
4. 토론하고, 상태를 정하고, 필요할 때마다 출처로 돌아갑니다. **프레젠테이션**으로 팀에게 차례로 보여 줍니다.

### 변경된 결제 링크 하나를 따라가세요

합성 예시 · 현지화 예시

1. **캡처.** 저장된 관찰 기록 #142와 해당 메시지 버전을 엽니다.
2. **북마크.** 인용문, 출처 참조 및 질문을 카드에 저장해 두세요.
3. **검토.** 팀 코멘트를 추가하고 카드를 ‘검토’ 상태로 이동하십시오.
4. **현재.** 수집 과정을 단계별로 안내하고 인용된 출처의 맥락을 열어보세요.

#### 저장된 관찰 기록 #142

“새로운 결제 링크를 사용하세요.”

운영 채팅 · 메시지 38 · 확인 시간 09:12 UTC

#### 카드: 수신처 변경

> 새로운 결제 링크를 사용해 주십시오.

질문: 이전 버전에는 어떤 대상이 등장했나요?

#### 팀 검토

분석가: 관찰 사항 #101과 비교하십시오.

상태: 검토 · 수정 내용 유지

#### 원문 맥락

카드 → 저장된 버전 → 이전 관찰 내용

주석과 텔레그램 관찰 내용은 별도로 식별 가능합니다.

## 유용한 범위를 한 번에 저장하세요

두 메시지를 Shift+클릭해 **사이 슬라이스**, **시간별 슬라이스**를 사용하거나 현재 저널 필터를 저장합니다. **북마크 이후 추가된 기록 표시**로 나중에 들어온 것을 봅니다.

시간 슬라이스는 관찰 시각을 쓰고, 메시지 ID 슬라이스는 그 메시지가 바뀌는 대로 따라갑니다.

## 각 동료에게 적절한 역할을 부여하십시오

**검토자**는 읽고, **분석가**는 카드와 댓글을 추가하며, **운영자**는 컬렉션과 결정도 관리합니다. 채팅 권한은 카드에도 적용됩니다.

## 이 작업을 결과물로 완성해 주십시오.

슬라이스는 서명된 JSON이나 CSV로 내보냅니다. 보고서에는 북마크, 슬라이스, 댓글을 넣을 수 있으며, [Report studio](https://phishdestroy.github.io/TgWitness/ko/docs/reports/)에서 설정합니다. 제한된 수신자에게는 [인계](https://phishdestroy.github.io/TgWitness/ko/docs/handover/)를 사용하십시오.
