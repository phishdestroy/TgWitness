# Проверка архива без ввода команды

Оставьте исходный ZIP-файл без изменений. Распакуйте весь архив и дважды щелкните файл `VERIFY.cmd` в Windows. В качестве альтернативы перетащите исходный ZIP-файл на файл `VERIFY.cmd`. В macOS/Linux запустите команду `sh VERIFY.sh` из терминала.

Если ровно один из находящихся поблизости ZIP-файлов имеет тот же манифест, что и извлечённая копия, верификатор отобразит его путь и запросит подтверждение. В противном случае он запросит путь к исходному ZIP-файлу. Обнаружение не является проверкой: полные проверки всё равно выполняются. Перемещение или переименование ZIP-файла не приводит к признанию архива недействительным. Распакованные файлы не являются объектом проверки. Проверка печати, основанная исключительно на HTML, не заменяет проверку ZIP-архива.

Программа запуска запрашивает отпечаток ключа подписи, полученный **отдельно** из источника, которому доверяет получатель. Допускаются пробелы, двоеточия и шестнадцатеричные символы в верхнем регистре. Ввод данных без отпечатка оставляет подписи неподтверждённой. Ключ, указанный внутри архива, никогда не принимается автоматически в качестве доверенного отпечатка. Ввод отпечатка обрабатывается на языке Python и никогда не оценивается оболочкой.

Существующий верификатор отображает цветной результат проверки целостности с пояснениями и записывает файл UTF-8 `verify-result-<UTC>-<random>.txt` рядом с исходным ZIP-архивом. Если в этот каталог нет прав на запись, верификатор пробует записать файл в каталог `~/TgWitness-verifications/`. Результаты не перезаписывают предыдущие протоколы и не становятся частью подписанного архива. В протоколе фиксируются путь к архиву и его SHA-256, путь к верификатору и его SHA-256, локальное время начала и окончания, предупреждения о доверии, проверки и статус завершения. Протокол не подписывается. Хеш архива проверяется повторно после завершения верификации для выявления изменений, произошедших в ходе выполнения. Верификатор, предоставленный злонамеренным отправителем, по-прежнему может вводить в заблуждение: в случае необходимости независимой проверки следует получить код и среду выполнения из независимых источников.

Статус завершения 0 означает, что запрошенные проверки целостности прошли успешно. Информацию о привязке подписавшего лица, покрытии и проверке временных меток можно найти в соответствующих разделах отчёта. Статус 1 означает, что проверка завершилась неудачно; 2 означает, что рабочий процесс не был завершён (например, отсутствие среды выполнения, отмена, недопустимые входные данные или невозможность сохранения транскрипта). Отсутствие отпечатка приводит к вынесению «желтого» вердикта. Привязанный ключ может привести к вынесению «зелёного» вердикта **о целостности,** хотя ограничения, связанные с охватом или независимым временем, остаются видимыми.

<a id="runtime-and-language"></a>
## Среда выполнения и язык

Программа запуска для Windows сначала пробует запустить встроенный интерпретатор в каталоге `python/`, затем — в каталоге `verifier/python/`, а после этого — совместимую установленную версию Python. Путь к Python должен обеспечивать доступ к Python версии 3.11 и выше, а также к модулю `cryptography`. Программа не устанавливает зависимости и не загружает среду выполнения. Функция обнаружения отключает переключатели автоматической установки и тестового запуска в программе запуска Python. Python запускается с параметрами `-I -B -X utf8`: модули из папки evidence-folder и пакеты пользовательского сайта исключаются из импорта, байт-код не записывается, а ввод/вывод осуществляется в кодировке UTF-8. Ознакомьтесь с официальной [документацией по изолированному режиму](https://docs.python.org/3/using/cmdline.html#cmdoption-I) и [настройками программы запуска для Windows](https://docs.python.org/3/using/windows.html#configuration).

Автономный пакет для Windows содержит тот же файл ``verify.py``, программы запуска, встроенную официальную среду выполнения Python, а также закреплённые криптографические зависимости и их лицензии. Он не включает панель управления и не запускает сервер. Используйте собственный файл ``VERIFY.cmd`` с любым поддерживаемым исходным ZIP-файлом или скопируйте каталог ``python/`` рядом с входящей в комплект программой запуска. Получите дистрибутив и проверьте его контрольную сумму через надёжный канал, отдельный от самого процесса загрузки. В сборке используется существующая в репозитории закреплённая среда выполнения Python и файл ``deploy/constraints.txt``.

Сборка выполняется в Windows с использованием Python 3.12. На хосте сборки не требуется предварительная установка прикладных зависимостей: генерация запускающего модуля происходит внутри вновь скомпилированной встроенной среды выполнения.

```powershell
python tools/build_verifier.py
```

В результате собирается файл `dist/TgWitness-verifier-<version>-windows-<arch>-all.zip` и сопутствующий файл SHA-256. Скрипт `VERIFY.cmd` перечисляет все названия языков и принимает номер или код языка. Команда «Enter» выбирает обнаруженный язык системы. Например, опция `--language de` запускает сборку с фиксированным значением по умолчанию; при этом каждая сборка по-прежнему содержит все языки. Локализованные инструкции также находятся в файле `languages/START_HERE-<code>.txt`. Сборка проверяет общедоступный вымышленный демонстрационный архив с помощью встроенной среды выполнения; параметр `--validation-archive PATH` позволяет выбрать другой сохраненный архив. Он запускает реальный запускающий файл .bat для проверки чистых и подделанных ZIP-архивов, а затем запускает его на всех языках при отсутствии системного Python в PATH. Сборка не приводит к публикации релиза. Публикация в GitHub Releases или на get.destroy.tools по-прежнему является отдельной операцией выпуска.

Инструкции запуска, подсказки, метки проверок, пояснения, сводки об ошибках и сохраненные стенограммы поддерживают все 25 языков панели: английский, русский, украинский, испанский, португальский, турецкий, арабский, персидский, урду, хинди, индонезийский, вьетнамский, упрощённый китайский, французский, немецкий, итальянский, узбекский, корейский, традиционный китайский, малайский, польский, японский, тайский, иврит и бенгальский. Генерируемые запускающие программы архивов используют язык отчёта; неизвестные коды языков отклоняются, а не заменяются запускающей программой на английском языке без уведомления. Автономный верификатор принимает любой код панели с параметром `--lang`, включая региональные псевдонимы, такие как `pt-BR` и `zh-TW`. Параметры `--choose-language --interactive` открывают меню. Имена файлов, хеши, исходные записи и исходная техническая диагностика сохраняются дословно; их перевод мог бы изменить доказательную базу или затруднить выявление ошибки. Подробные описания опций командной строки остаются частью технической документации на английском языке. Новый графический интерфейс пользователя не требуется. Среда выполнения Windows отличается от среды выполнения macOS/Linux; для работы скрипта `VERIFY.sh` необходимы уже установленные совместимые версии `python3` и соответствующие зависимости.

Каталог исходных текстов доступен для чтения в файле `tgwitness/verifier_languages.json`. Существующие переводы панелей содержат устоявшуюся терминологию, относящуюся к доказательствам; сообщения рабочего процесса для получателей переводятся в этом каталоге. Сжатая копия встроена в файл `verify.py`, благодаря чему он работает без файла каталога, установки приложения, сетевого сервиса перевода или импорта из каталога доказательств. После редактирования переводов запустите `python tools/sync_verifier_languages.py`; опция `--check` проверяет, синхронизирована ли встроенная копия. Проверка каталога требует точного набора языков панели, полных ключей и неизменённых заполнителей. Пояснения на языках CJK, индийских языках и языках с направлением письма справа налево сохраняют полные абзацы Unicode, а не вставляют разрывы строк внутри формирующих последовательностей; конечный вид по-прежнему зависит от используемых шрифтов.

## Дополнительные входные данные для проверки

При двойном щелчке по умолчанию выполняется проверка ZIP-архива локально. При этом не устанавливается доверие к центрам сертификации временных меток и не доверяется автоматически контрольная точка внутри того же ZIP-архива. Опытные пользователи могут предоставить независимо сохраненные входные данные для того же кода:

```text
python -I verify.py archive.zip --interactive --lang en --checkpoint retained.json
python -I verify.py archive.zip --pretty --explain --fingerprint TRUSTED_SHA256
python -I verify.py archive.zip --pretty --explain --fingerprint TRUSTED_SHA256 --tsa-ca trusted-root.pem
python -I verify.py archive.zip --pretty --explain --witness witness.zip --witness-fingerprint TRUSTED_WITNESS_SHA256 --require-witness
```

Используйте `python/python.exe` вместо `python` для встроенной среды выполнения Windows. Для проверки по RFC 3161 требуется доверенный корневой сертификат центра сертификации (`--tsa-ca`); OpenSSL не требуется. Аутентификация Bitcoin с помощью OpenTimestamps остаётся отдельной проверкой. Максимальный размер распакованного ZIP-архива по умолчанию составляет 4 ГиБ; параметр `--max-gib` явно изменяет это значение. Параметр `--jobs N` задаёт количество процессов, совместно проверяющих большой архив; значение `auto` (по умолчанию) использует по одному процессу на каждый процессор (не более 16), а `--jobs 1` — проверку в одном процессе. Параметр `--json` сохраняет машинно-читаемый формат, в том числе при указании параметра `--explain`. Параметры `--plain --explain` предоставляют читаемые пояснения без цветовой разметки.

В интерактивном режиме также сохраняются параметры `--strict`, `--require-tier`, `--check-bitcoin`, `--bitcoin-source` и параметры, связанные с запечатанным подтверждением. Несоблюдение строгих требований к надежности или их невыполнение возвращает статус 2; аутентифицированный формат более новой версии возвращает статус 3 при использовании параметра `--strict`. Параметры `--check-drand`, `--check-bitcoin` и соответствующие требуемые уровни могут использовать сетевые службы. `--check-bitcoin` извлекает заголовки блоков из двух общедоступных эксплореров и требует их совпадения; `--bitcoin-source URL` вместо этого использует API Esplora вашего собственного узла (повторите этот параметр, чтобы потребовать совпадения нескольких источников). Для проверки аттестации требуется установленный верификатор запечатанных данных TgWitness и `gh`; автономный архив не предоставляет этих инструментов.

Файлы `VERIFY.cmd`, `VERIFY.sh` и `START_HERE.txt` генерируются перед подписанием манифеста для экспорта доказательств, чата, передачи, аккаунта, раскрытия информации и свидетелей. Они хешируются и подписываются как обычные элементы архива. Зашифрованные транспортные оболочки необходимо сначала разархивировать, чтобы получить исходный подписанный ZIP-файл. Более ранние ZIP-файлы остаются поддающимися проверке без повторной упаковки; используйте верификатор, полученный отдельно.

Устаревший верификатор, ограничивающий элементы раскрытия фиксированным списком, может отклонять новые ZIP-архивы раскрытия, содержащие эти программы запуска. Используйте обновленный верификатор из независимого доверенного источника. Не удаляйте файлы из подписанного ZIP-архива, чтобы заставить устаревший верификатор принять его.
