# Экспорт аккаунта и минимизация раскрытия данных

Экспорт аккаунта резервирует слот для его сбора. Наблюдение в режиме реального времени может продолжаться, пока архив обнаруживается, загружается, проверяется и упаковывается. Перед запуском конкурирующего сбора приостановите другое задание по истории или экспорту. Приостановка архивирования не прерывает наблюдение, а приостановка наблюдения сохраняет задание по архивированию.

Экспорт данных из разных аккаунтов может выполняться одновременно. Задание, предназначенное исключительно для Takeout и ожидающее утверждения, освобождает свой аккаунт, поэтому отдельный экспорт в рамках обычного сеанса может начаться, пока утверждение находится на рассмотрении. Активный сбор данных по-прежнему резервирует этот аккаунт.

В качестве администратора установки выберите **Главная → Экспорт моего аккаунта** или **Экспорт → Аккаунт Telegram → Настроить экспорт аккаунта**. При необходимости войдите в систему, проверьте объем данных и явно запустите экспорт. Непрерывное наблюдение не требуется. **Сохраненные наблюдения** представляют собой отдельный экспорт существующего журнала; его ZIP-архив включает все источники независимо от фильтров журнала. Каждая рабочая область имеет собственные задания, идентификатор для подписи и хранилище. Предоставленный доступ к панели, включая разрешение на неограниченный обычный экспорт, не позволяет открыть эти маршруты, действующие на уровне всех аккаунтов.

Фильтры по отправителю и тексту сообщений раскрываются в разделе **Фильтр по отправителю или тексту сообщения**. Раздел **Данные аккаунта и способ подключения** содержит дополнительные категории аккаунтов и выбор между «Takeout» и «обычной сессией»; в его сводке отображаются активные настройки даже после закрытия. При закрытии этих разделов их настройки сохраняются. Черновики экспорта и отчётов остаются в текущем сеансе панели при смене представлений; они не сохраняются при перезагрузке браузера. Доступ к существующим заданиям сохраняется при выборе любого из вариантов экспорта.

Данный рабочий процесс экспортирует данные, доступные в данный момент для подключённого аккаунта. Метод **Автоматический** по умолчанию запускается с помощью [Telegram Takeout](https://core.telegram.org/api/takeout), который возвращает доступную историю в её текущем состоянии, включая покинутые каналы, сохранённые контакты и другие данные аккаунта. Если Telegram устанавливает период ожидания перед запуском Takeout, режим «Автоматический» сразу же переходит к обычному сеансу; в журнале фиксируется `account_export.transport`, а в подписанном отчёте указывается использованный метод и изменение отражается как пропуск. **Сеанс Telegram Takeout**, напротив, ожидает **только** подтверждения, а **Обычный сеанс** никогда не запрашивает данные через Takeout. Секретные чаты фиксируются в режиме реального времени модулем [Секретные чаты](PSEUDO-SECRET.md), а изменения — посредством наблюдения в реальном времени. «Обычный» сеанс имеет иной объем охвата и фиксирует неподдерживаемые категории.

**Главная → Экспортировать всё** запускает экспорт всех типов чатов, всех типов вложений, профиля, контактов, фотографий профиля, историй, метаданных сеанса и других данных аккаунта во всех форматах: подписанный архив TgWitness с представлениями Telegram Desktop в форматах JSON и HTML. **Выбор пункта Что экспортировать** открывает форму ниже с теми же настройками по умолчанию.

Takeout — это официальный API экспорта, который также используется Telegram Desktop. TgWitness может записывать JSON-файлы, совместимые с Desktop, непосредственно на основе собственных данных; импорт чужого архива не требуется. Идентификаторы чатов и сообщений доступны через оба канала передачи данных. Скорость экспорта и задержка одобрения со стороны Takeout зависят от ограничений Telegram для данного аккаунта, а также от того, является ли чат публичным или доступным для пересылки. Перед сравнением скорости убедитесь, что вы используете одинаковые настройки объёма данных и медиафайлов.

При наличии до 20 явно выбранных идентификаторов чатов экспорт через стандартный API сначала обрабатывает данные по этим участникам, а уже затем рассматривает полный перечень диалогов аккаунта. Таким образом, общедоступный канал, доступный для чтения, можно экспортировать, не вступая в него, даже если он отсутствует в списке диалогов. Участники, не сохраненные в кэше, обрабатываются на основе общего списка диалогов. Фильтр архива по-прежнему применяется: если Telegram не возвращает диалог, а заархивированные чаты исключены, неизвестный статус архива фиксируется как пропуск. Takeout сохраняет свою процедуру обработки диалогов с разбиением диапазона. Ни один из способов не предполагает вступление в чаты или изменение разрешений на пересылку. В формате JSON, совместимом с Desktop, каналы, которые Telegram помечает как `left`, отображаются в разделе `left_chats`, включая общедоступные каналы, к которым аккаунт не присоединился.

Как `FLOOD_WAIT`, так и `FLOOD_PREMIUM_WAIT` приостанавливают запросы на весь период, запрашиваемый сервером. Срок ожидания аккаунта сохраняется при повторных подключениях и перезапусках; более короткое последующее ожидание не может сократить его. Количество повторных попыток ограничено, отмена сохраняет запечатанные страницы, а учетные данные API не меняются с целью обхода ограничения по частоте запросов. Покупка Premium не осуществляется.

## Выберите, какие данные будут собираться

| Параметр | Значение |
| --- | --- |
| Цель | Укажите, для чего требуется данное сбора данных. Не указывайте здесь ненужные имена или конфиденциальные сведения о деле. |
| Язык отчёта | Выберите язык меток в отчёте для чтения. Текст исходного сообщения остаётся без изменений; непереведённые метки шаблона отображаются на английском языке. Язык фиксируется с помощью параметров подписанного задания. |
| Типы чатов / идентификаторы чатов | Все выбранные типы или только перечисленные чаты; раздел «Сохраненные сообщения» относится к личным чатам. Архивированные чаты можно выбрать отдельно. |
| Даты | UTC. В панели учитываются обе даты календаря: «С» и «По». API использует значения `from_utc` (включительно) и `to_utc` (исключительно); панель отправляет начало дня, следующего за датой «По». Пустой предел оставляет эту сторону неограниченной. |
| Идентификаторы отправителей | Только сообщения от указанных отправителей; пустой список включает всех отправителей. |
| Текст содержит | Буквальные фразы без учета регистра, сопоставляемые с помощью оператора «ИЛИ». Условия «отправитель», «дата» и «собственное сообщение» комбинируются с помощью оператора «И». |
| Собственные сообщения | Сохранять только исходящие сообщения. |
| Типы медиафайлов | Выберите категории вложений или снимите все отметки, чтобы избежать загрузки файлов из сообщений. |
| Ограничения по файлам и общему объему медиафайлов | МиБ на файл и GiB для общего объёма загруженных медиафайлов. Текст, квитанции, отчёты для чтения и накладные данные ZIP-архивов требуют дополнительного дискового пространства. |
| Категории аккаунтов | Для профиля, контактов, фотографий профиля, историй, метаданных сеансов и других данных Takeout предусмотрены отдельные настройки. |

Предустановка **«Минимизировать сбор** данных» отключает файлы и метаданные аккаунтов. Фильтры отправителей и контента применяются до сохранения страниц сообщений и загрузки медиафайлов. Telegram по-прежнему передаёт страницы истории API, содержащие сообщения, необходимые для оценки этих фильтров: поэтому невыбранные сообщения всё равно могут попасть в оперативную память. Другие текущие наблюдения в рабочих областях имеют собственные настройки области действия и сроков хранения.

История фотографий профиля, истории, метаданные сеансов и другие данные аккаунта выбраны по умолчанию. Отключите их, а также профиль и контакты, если в данном случае требуются только сообщения. Если вложения или метаданные не нужны, их исключение во время сбора позволит избежать сохранения ещё одной частной копии в данном экспорте.

Полевые данные фотографий используют вариант неподвижного изображения, указанный в их метаданных и хеш-манифестах, включая фотографии с анимированным вариантом аватара. Эта анимация не заменяется выбранным неподвижным изображением. Поле данных, размер которого меньше или больше наблюдаемого, регистрируется как неудачное вложение, а измененное представление при обновлении ссылки на файл отклоняется. Эти сбои приводят к неполноте архива, однако записи сообщений сохраняются. Независимая проверка также отклоняет сохраненные вложения, длительность которых с учётом подписи не соответствует их наблюдаемому размеру или представлению, в том числе в более старых архивах.

В случае временного сбоя выделенного медиасоединения при чтении вложений используется стандартное файловое соединение. Через одну минуту в фоновом режиме производится повторная попытка установления выделенного маршрута, при этом загрузка продолжается. При таком восстановлении сохраняется настроенный лимит соединений, и оно применяется отдельно к каждому центру обработки данных. Ожидания, связанные с перегрузкой Telegram, и сбои авторизации по-прежнему распространяются.

## Номера сообщений и карта активности

Архив каждого аккаунта содержит файлы ``message-gaps.json`` и ``map.html``. Каналы и супергруппы нумеруют свои сообщения по чатам, поэтому каждый отсутствующий номер между первым и последним экспортированным сообщением соответствует сообщению из данного чата. Личные чаты, боты и базовые группы используют одну последовательность номеров для всего аккаунта: отсутствующий номер в этом случае принадлежал какому-либо чату. Принадлежность к конкретному чату подтверждается, если экспортированный ответ или закреплённое сообщение указывает на этот номер; если ответы в двух разных чатах указывают на один и тот же номер, его принадлежность считается спорной и он не присваивается ни одному из них. В противном случае определяется, какие чаты были активны в промежутке времени между соседними сообщениями, а остальные сообщения относятся к чатам, не включённым в экспорт. Каждый прогон сопровождается указанием временного окна, соседних сообщений, доли каждого чата и меткой достоверности. Указывается ограниченная область охвата (фильтры, невыбранные чаты), поскольку в этом случае отсутствующие номера включают сообщения, не входящие в выборку. Область охвата также указывает, когда страница личного чата, бота или обычной группы не была просмотрена до конца, либо когда были прочитаны только собственные сообщения аккаунта.

На странице `map.html` отображается календарь, динамика чатов во времени, а также сетки по дням недели и часам суток для сообщений и отсутствующих номеров, включая таблицы по каждому чату и крупнейшим прогонам. Страницы чатов содержат собственный календарь, динамику участников для групп, а также отметку в транскрипте в местах отсутствия сообщений. Скрипт `verify.py` пересчитывает файл `message-gaps.json` на основе подписанных страниц и отклоняет изменившийся файл.

На карте активности перечислены наибольшие пробелы в каналах и супергруппах, включая диапазоны их номеров и время соседних сообщений. Откройте диапазон, чтобы перейти к отмеченной позиции в страничной транскрипции. Эти отметки фиксируют отсутствующие номера между сохраненными соседними записями; события удаления, их время и тексты сообщений поступают исключительно из сохраненных записей. Широкие таблицы прокручиваются внутри своих карточек на небольших экранах.

Объёмные стенограммы содержат указатель страниц с диапазонами дат сообщений и календарь. Выберите месяц, чтобы открыть его первую запись в порядке захваченных страниц. Подсчёт месяцев основан на датах сообщений, зафиксированных в формате UTC; записи без даты остаются в стенограмме. Навигация по страницам включает переход к первой, последней и соседним страницам, а также позволяет напрямую открыть раздел сообщений. Указатель работает в автономном режиме без использования JavaScript.

<a id="resume-coverage-and-verification"></a>
## Возобновление, охват и проверка

Каждое задание фиксирует свои настройки и идентификатор аккаунта. Перечень и захваченные страницы подписываются; в квитанциях страниц фиксируются хеши, курсоры, время, результаты обработки вложений и предшествующая квитанция. Только зафиксированные страницы увеличивают прогресс. При перезапуске/возобновлении выполняется проверка этих записей перед продолжением. Измененный аккаунт, измененная подписанная страница или несогласованная цепочка квитанций отклоняются. Параметры нельзя редактировать в середине процесса сбора данных: для другого диапазона запустите новое задание.

Функция «Пауза» освобождает выполняемую операцию с аккаунтом. Перезапуск приложения оставляет незавершённую работу доступной для явного возобновления. Сеанс Takeout с истекшим сроком действия требует явного возобновления; изменение диапазонов разбиения в Telegram может потребовать нового сбора данных. Функция «Возобновить» сохраняет предыдущие наблюдения, поэтому длительный экспорт не представляет собой единый атомарный снимок. Другие операции, изменяющие аккаунты, а также конфликтующие экспорты блокируются во время сбора данных. Дождитесь завершения упаковки, прежде чем удалять рабочую область.

Функция «Возобновить» сразу отображает **сообщение Проверка сохраненных данных экспорта…** и проверяет сохраненное содержимое в фоновом режиме перед отправкой в Telegram. Панель остается доступной во время проверки. Функция «Приостановить» дожидается безопасного завершения работы процесса проверки перед освобождением аккаунта; она также работает при нажатии сразу после запуска или возобновления задания. На медленном хранилище это ожидание может затянуться. Неудачные проверки целостности приводят к созданию задания с пометкой «Неудача» и объяснением причины, при этом файлы сохраняются. Экспорт, завершившийся неудачей по причине, отличной от отклоненного запроса или настройки, также записывается в журнал процесса вместе с трассировкой под логгером `tgwitness.export`; на панели отображается только текст ошибки.

В процессе выполнения задания отображаются **оставшиеся чаты** (выбранные чаты, обработка которых ещё не завершена), а после выполнения как минимум трёх задач и по прошествии 30 секунд — **Ориентировочное оставшееся время**, рассчитанное на основе завершённых задач. Оценка не отображается, пока задание ожидает ответа от Telegram, находится в режиме паузы или уже завершено; кроме того, она может изменяться в зависимости от размера чатов.

Экспорт, прерванный досрочно, указывает в своём отчёте все пропущенные чаты, сообщения которых не были прочитаны полностью, в формате `title · ID N`, с указанием степени выполнения: **«Ни одно сообщение этого чата не было** прочитано» или **Сообщения с номерами ниже N не были прочитаны**, за чем следует причина остановки экспорта или *сообщение Сбор данных был остановлен до завершения этого чата*, если причина не была зафиксирована. **Фраза Непрочитанная часть этого чата не зафиксирована** заменяет указание на позицию в тех случаях, когда не был сохранен курсор. Чат без названия обозначается по его идентификатору. Задача, завершившаяся сбоем, указывается с указанием её категории, чата и возвращённой ошибки. Пробел в перечёте, который также фиксируется как пропуск, отображается один раз. Пустой список пропусков сам по себе не означает, что ничего не было упущено; см. разделы [Охват и Отсутствующий материал](COVERAGE.md).

Если Telegram прекращает авторизацию аккаунта во время инвентаризации, получения истории или вложений, задание приостанавливается без пометки незавершённой страницы как завершённой. Повторно авторизуйтесь в том же аккаунте и возобновите процесс, чтобы продолжить с последней сохраненной страницы. Заполнители недоступных сообщений продвигают курсор истории, но не завершают чтение: более старые доступные сообщения по-прежнему запрашиваются, а заполнитель не отображается как захваченное сообщение или подтверждённое удаление.

Панель различает завершённую выбранную область и частичный архив, а также фиксирует пропуски и неудачные попытки чтения. Как в отчёте отображаются охват, пробелы и номера отсутствующих сообщений: [Охват и отсутствующий материал](COVERAGE.md). Намеренно исключённые файлы отличаются от файлов, чтение которых завершилось неудачей или которые недоступны. Проверяйте охват даже в случае успешной проверки целостности. Ни один локальный считыватель не может доказать, что Telegram вернул все сообщения, которые когда-либо существовали.

Готовые ZIP-архивы остаются доступны для повторной загрузки и загрузки с помощью HTTP-range. Архив аккаунта содержит файлы `manifest.json`, `manifest.sig`, подписанный `job.json`, `inventory.json`, `receipts/`, авторитетные `data/*.jsonl`, выбранные `media/`, читаемый HTML-код и верификатор. Зафиксируйте отпечаток сборщика через независимый канал, а затем проверите его с помощью надёжной установки. Панель сохраняет архив как `tgwitness-account-export-EXPORT_ID.zip`; запечатанная копия помещает его в свой архив доказательств как `account-export.zip`. Используйте имя имеющегося у вас файла:

```sh
python -m tgwitness.verify tgwitness-account-export-EXPORT_ID.zip --fingerprint TRUSTED_SHA256
```

Для архивов, размер содержимого которых после распаковки превышает 4 ГиБ, явно задайте соответствующее значение параметра ``--max-gib``. Панель проверяет свои аутентифицированные и завершённые локальные архивы, используя их заявленный размер после распаковки и опубликованный дайджест ZIP; внешний интерфейс командной строки (CLI) сохраняет собственное ограничение по размеру. Проверьте архив перед открытием читаемого HTML-файла. Встроенный в архив верификатор удобен, однако использование независимого верификатора позволяет избежать доверия к исполняемому коду, поставляемому вместе с доказательствами.

Подпись Ed25519 и хеши SHA-256 позволяют обнаружить изменения, произошедшие после того, как сборщик зафиксировал соответствующие байты. Проанализируйте этот результат вместе с зафиксированной областью сбора, интервалами сбора, внешними квитанциями с временными метками и проверками происхождения, доступными для выбранного развертывания. Более поздние наблюдения регистрируются отдельно, при этом сохраняются ранее зафиксированные версии.

<a id="prepare-a-disclosure-for-a-lawyer-or-another-recipient"></a>
## Подготовьте материалы для передачи юристу или другому получателю

После загрузки готового экспорта сохраните исходный ZIP-файл и откройте файл `index.html` из извлечённой копии. В отчёте объясняются его объем, доступный охват и ограничения. Ссылки на записи в отчёте объединяют ссылку на архив, путь к документу и номер записи, благодаря чему получатель может найти соответствующую запись в HTML-файле или на распечатке. Для ознакомления с практическим примером [откройте вымышленный отчёт](https://phishdestroy.github.io/TgWitness/demo/report/).

В готовом экспорте аккаунта выберите **Подготовить копию для передачи**. Это создаст отдельный подписанный производный файл. Исходный ZIP-файл остаётся неизменённым и конфиденциальным; не отправляйте его вместе с сокращённым производным файлом, если получатель не уполномочен получать его полное содержание. Выберите язык отчёта отдельно. Изменение языка или любых настроек выбора требует повторного предварительного просмотра перед созданием.

1. Укажите цель раскрытия информации и выберите даты, идентификаторы отправителей и критерии по тексту сообщений.
2. Выберите, следует ли сохранить идентификационные данные, раскрыть только перечисленных участников или заменить имена всех участников псевдонимами. В любом режиме псевдонимизации идентификаторы/названия чатов и идентификаторы сообщений также заменяются. Псевдонимы остаются неизменными в пределах одного раскрытия информации и меняются при переходе между независимо подготовленными раскрытиями.
3. Сохраните текст сообщений, полностью опустите его или добавьте конкретные имена/фразы для маскировки. В режимах конфиденциальности инструмент также маскирует известные скрытые имена отправителей и альтернативные имена пользователей, идентификаторы отправителей в виде целых токенов, имена в прямом чате, ссылки, адреса электронной почты и строки, похожие на телефонные номера. Сопоставление известных имен учитывает преобразование регистра символов в Unicode, включая `Straße`/`STRASSE`. Общие названия групп/каналов не удаляются автоматически из текста сообщений. Если превышен лимит маскировки известных идентификаторов, сузьте исходный экспорт или опустите текст; инструмент не пропускает последующие имена без предупреждения. Это правила, основанные на принципе «наилучших усилий», а не на полной анонимизации.
4. Оставляйте файлы исключенными, если они не нужны получателю. Включенные исходные файлы сохраняют свои пиксели, аудио, текст и метаданные. Инструмент **не** анонимизирует их.
5. Просмотрите предварительный просмотр с указанием количества, предупреждений и образцов преобразованных сообщений, а затем явно подтвердите создание. Количество образцов ограничено 12 сообщениями, каждый из которых может содержать не более 2 000 текстовых символов. Это лишь пример, а не полный обзор результата. Для изменения настроек требуется повторный предварительный просмотр. Срок действия предварительного просмотра истекает через 15 минут; он привязан к данному сеансу администратора и конкретному исходному ZIP-файлу; его нельзя повторно использовать после создания. Новый предварительный просмотр аннулирует предыдущий для того же задания и того же сеанса.
6. Перед передачей файлов тщательно проверьте на локальном компьютере полные итоговые файлы ``index.html`` и ``messages.jsonl``. Если в них обнаружится ненужная информация, создайте новое раскрытие с более строгими критериями исключения. Не редактируйте подписанный ZIP-архив на месте.

<a id="messages-left-out-by-the-selection"></a>
### Сообщения, исключённые при отборе

**Предварительный просмотр.** Раскрытие не выглядит полным, если таковым не является. Внутри каждого чата, в котором сохранилось хотя бы одно раскрытое сообщение, сообщения, исключённые в результате отбора, отображаются в виде маркеров: `[withheld by selection — rule: sender]` (или `text`, `period`). Выберите **Сообщения, исключённые в результате отбора**: по одному маркеру для каждой последовательности удержанных сообщений (по умолчанию) или по одному для каждого сообщения. Маркеры содержат только правило и количество, но никогда не содержат текст, отправителя, дату или файлы. Чаты, в которых ничего не раскрыто, исключаются полностью, поэтому пакет не показывает, что они существуют.

Раскрытые ответы указывают, на что они отвечают: на сообщение, включённое в данную копию, на сообщение, исключённое при выборе, или на сообщение, которого нет в исходном экспорте (удалённое до экспорта или никогда не экспортированное; экспорт не позволяет определить, что именно). У скрытого сообщения, на которое отвечает раскрытый ответ, всегда появляется собственный маркер, поэтому ответ указывает на запись, объясняющую, почему он пуст. Эти три состояния отличаются от удалений и пробелов в наборе данных, которые относятся к исходному экспорту.

В файле ``messages.jsonl`` (формат ``tgwitness-account-disclosure-v2``) каждое сообщение имеет поле ``state``: ``disclosed`` или ``withheld`` с указанием ``rules`` и ``count``. Раскрытый ответ содержит поле ``reply_to`` с идентификатором адресата (``id``) и состоянием (``disclosed``, ``withheld``, ``not_in_source``). Манифест подсчитывает раскрытые сообщения, чаты, медиафайлы и сообщения, не подлежащие раскрытию (`withheld`). Скрипт `verify.py` отклоняет маркер, содержащий контент, а также ответ, указывающий на запись, отсутствующую в пакете; пакеты версии 1 проверяются так же, как и ранее.

В сокращённом формате опущены структурированные профили аккаунтов, контакты, аватары, сеансы, истории, исходные объекты Telegram, заголовки пересылки, цитаты из ответов, карточки контактов и метаданные о местоположении. Из него исключены исходные файлы JSONL, настройки частных фильтров, ключ псевдонима и карта идентификаторов. Выделенный текст, явно сохраненные идентификаторы и включённые файлы по-прежнему могут содержать те же имена, идентификаторы или фразы, что и в указанных фильтрах; они требуют отдельной проверки. Политика конфиденциальности и ключ псевдонима хранятся в зашифрованном виде в локальном хранилище для данного задания; удаление задания приводит к очистке связанных с ним записей о раскрытии конфиденциальной информации. Записи публичной политики фильтруют количество, а не значения фильтров. Указанная цель публично отражена в манифесте и HTML: явные частные критерии, а также — в режимах псевдонимизации — известные скрытые идентичности там также маскируются, в том числе в случае, когда текст сообщения опущен. Не включайте в описание цели ненужные личные данные; неизвестный идентифицирующий контекст может оставаться.

Манифест связывает производные файлы, публичную политику и хеш исходного ZIP-архива. Проверка позволяет установить целостность и, если исходный файл предоставляется локально, подтвердить соответствие исходной ссылки. Панель сохраняет копию для обмена как `tgwitness-disclosure-DISCLOSURE_ID.zip`:

```sh
python -m tgwitness.verify tgwitness-disclosure-DISCLOSURE_ID.zip --fingerprint TRUSTED_SHA256
python -m tgwitness.verify tgwitness-disclosure-DISCLOSURE_ID.zip --fingerprint TRUSTED_SHA256 --evidence tgwitness-account-export-EXPORT_ID.zip
```

Связь с источником показывает, из какого архива и с помощью какого ключа сборщика было получено раскрытие. Раскрытие содержит только выбранное содержимое; сверьте выбор и удаление идентифицирующих сведений с исходным экспортом.

<a id="sharing-and-hosted-capture"></a>
## Совместное использование и хранение на хостинге

Выберите сообщения и файлы, необходимые получателю, проверьте полную копию для обмена и сохраните исходные данные отдельно. Запишите хеш доставленного ZIP-архива, чтобы получатель мог идентифицировать и проверить именно эту копию. В ходе псевдонимизации выбранные идентификаторы заменяются; включённый текст и исходные файлы остаются частью проверки.

GitHub Actions поддерживает экспорт данных для всех аккаунтов и для выбранных чатов через Takeout или стандартный API, а также журнал событий одного чата. В [руководстве по хостируемому сбору данных](https://phishdestroy.github.io/TgWitness/docs/capture/) объясняется, как проверить настройки и ознакомиться с 120-минутным ограничением. Чтобы проверить копию для обмена, полученную из хостируемого сбора данных, сравните хеш её источника с хешем исходного архива и проверьте подтверждение подлинности этого архива с помощью [проверок](EVIDENCE.md#verification-scope), [соответствующих конкретному режиму](EVIDENCE.md#verification-scope).
