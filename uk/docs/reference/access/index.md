## Дві сфери застосування, дві різні посади

**Обсяг збору даних** визначає, що саме записує обліковий запис: вибрані чати, папку Telegram або весь обліковий запис. **Обсяг доступу** визначає, які з цих записаних облікових записів та чатів може переглядати та використовувати інша особа. Надання доступу не означає приєднання до чату Telegram, початок збору даних або надання дозволів на доступ до облікового запису Telegram.

Доступ може відкривати вибрані робочі простори, вибрані чати в них, усі робочі простори або кожен обліковий запис у [групі облікових записів](https://phishdestroy.github.io/TgWitness/uk/docs/reference/accounts/#bulk-import-and-account-groups). Доступ **до всіх робочих просторів, включно з тими, що будуть додані пізніше**, також поширюється на майбутні облікові записи. Груповий доступ також поширюється на облікові записи, додані до цієї групи пізніше. Явно вибирайте робочі простори, коли справа має обмежуватися лише ними.

## Надати комусь доступ

1. Увійдіть як головний адміністратор і відкрийте розділ **«Доступ**».
2. У розділі **«Надати комусь доступ**» введіть ім’я, яке ви зможете впізнати в журналі.
3. Виберіть робочі простори та, за потреби, окремі чати.
4. Виберіть, що ця особа може робити. Опція **«Переглянути»** завжди включена.
5. Налаштуйте термін дії, обмеження на входи/сесії та дозволені адреси відповідно до потреб.
6. Натисніть **«Створити доступ**». Скопіюйте токен зараз: він відображається лише один раз.
7. Надішліть адресу панелі та токен у приватному повідомленні. Одержувач вводить цей токен на звичайній сторінці входу; йому не потрібен ваш основний токен панелі чи сесія Telegram.

Відкрийте панель із виданим токеном в окремій сесії браузера та перевірте доступні чати та дозволені дії, перш ніж передати його.

## Виберіть права доступу

Для публічної демонстрації, що містить лише текст, використовуйте **«Публічну вітрину»** замість звичайного доступу рецензента. Вона показує явно вибрані публічні канали, збережені редагування та видалення, а також підписану статистику, при цьому поля автора замальовані, а файли закриті на межі API. [Створіть та перевірте вітрину](https://phishdestroy.github.io/TgWitness/uk/docs/reference/showcase/).

| Дозвіл | Що це дозволяє |
| --- | --- |
| `view` | Переглядайте дозволені чати, збережені повідомлення, профілі, файли та відфільтровані записи журналу. Завжди включено. |
| `export` | Дозволено експортувати історію чатів та досьє. Для експорту доказів з усього робочого простору необхідний доступ до всього робочого простору. |
| `sources` | Управління джерелами, знімками екрана та збереженням профілів. Доступ, обмежений чатами, діє лише для дозволених чатів; функції пошуку джерел та налаштування сфери дії для всього облікового запису залишаються недоступними. |
| `collect` | Запустити або зупинити колектор. Потрібен доступ до всього робочого простору, оскільки збір даних впливає на обліковий запис. |
| `interact` | Виконуйте підтримувані дії в Telegram у межах наданого доступу. При обмеженому доступі до чату неможливо використовувати попередній перегляд посилань для всього облікового запису. |
| `settings` | Змінюйте налаштування збору даних, часові мітки, сповіщення, зовнішні копії та параметри. Потрібен доступ до всього робочого простору. |
| `account` | Увійдіть або вийдіть із Telegram та керуйте маршрутами з’єднання. Потрібен доступ до всього робочого простору. |
| `board.read` | Читайте нотатки на дошці справ лише в межах дозволеного робочого простору та чатів. |
| `board.write` | Додавайте закладки, виділення, фрагменти, коментарі та статуси «відкрито»/«переглянуто». Також потрібна функція ``board.read``. |
| `board.manage` | Керуйте колекціями, остаточними статусами команди та картками інших учасників. Також потрібні права на читання/запис у дошці. |

Права доступу та їхній обсяг перевіряються одночасно. Встановлення галочки біля права доступу не відкриває інші чати та не розблоковує операції на рівні робочого простору для доступу, обмеженого одним чатом. Для паралельного експорту доступ повинен охоплювати експортований чат у кожному вибраному обліковому записі. Наданий доступ не дозволяє створювати нові доступи, керувати сесіями інших користувачів або відкривати консоль адміністратора.

### Три корисні налаштування

| Особа | Сфера застосування | Дозволи |
| --- | --- | --- |
| Рецензент | Записані чати з однієї справи | `view` |
| Аналітик, який готує передачу справ | Чати для розслідування та експорту | `view`, `export`; додайте `interact` лише в тому випадку, якщо їм потрібно діяти через Telegram |
| Оператор збору даних | Вибрані цілі робочі простори | `view`, `sources`, `collect`; додавайте `settings` або `account` лише за потреби |

Початкові налаштування форми доступу також включають «Дошку справ»: рецензент може читати, аналітик може читати та писати, а оператор може керувати нею. Налаштування залишаються редагованими, а існуючі права доступу не розширюються автоматично. Див. [«Дошку справ»](https://phishdestroy.github.io/TgWitness/uk/docs/reference/case-board/) для інформації про успадковані обсяги чатів та конфіденційність експорту.

## Обмеження та сесії

| Налаштування | Як це працює |
| --- | --- |
| Паралельні сесії | Обмежте кількість одночасних сеансів до 1–100. При досягненні межі відхиліть наступний вхід або завершіть найстаріший сеанс. |
| Доступний вхід у систему | Обмежте кількість успішних використань токена для запуску сеансів. Існуючі сеанси не завершуються лише через те, що було використано останній дозволений вхід. |
| Дійсно до | Абсолютний термін дії доступу. Користувач із простроченим доступом не може увійти в систему або продовжувати надсилати запити. |
| Протоколи без активності | Тайм-аут неактивності сесії — від 5 хвилин до 30 днів. Успішні запити подовжують цей час; відкрита панель може підтримувати свою активність за допомогою періодичних запитів. |
| Дозволені адреси | Дозвольте використання конкретних IP-адрес або підмереж CIDR. Залиште поле порожнім, щоб дозволити будь-яку адресу, якщо не ввімкнено прив’язку до першого входу. |
| Прив’язати до першого входу | Після першого успішного входу система фіксує дозволену адресу для цього доступу. |

IP-адреса — це адреса клієнта, яку бачить додаток. Якщо ви перебуваєте за зворотним проксі-сервером або тунелем, перш ніж покладатися на правила, пов’язані з IP-адресами, перевірте адресу, вказану в **розділі «Відкриті сесії**»: інакше може здатися, що кілька користувачів використовують одну й ту саму адресу проксі-сервера.

## Змінити або скасувати доступ

Відредагуйте запис у **розділі «Наданий доступ»**, щоб змінити його сферу дії, дозволи або обмеження. Зміни сфери дії та дозволів перевіряються під час наступних запитів, зокрема запитів із сеансів, що вже відкриті. Скасування доступу припиняє відповідні сеанси та робить виданий токен непридатним для використання. **Функція «Відкриті сеанси»** також дозволяє адміністратору завершити окремий сеанс без скасування всього доступу.

Збережені копії експорту зберігають інформацію про їхнього творця, робочу область, обсяг чату та необхідні дозволи. Користувач, якому надано доступ, може переглядати або завантажувати власні копії лише доти, доки ці дозволи залишаються чинними; копії, що містять Case Board, також вимагають дозволу ``board.read``. Адміністратор може отримати всі копії. Старіші копії без цих метаданих та групові пакети доступні лише адміністратору. Завантаження квитків та підготовлених файлових відповідей передбачає повторну перевірку доступу після підготовки файлу, перед надсиланням його байтів.

Скасування не дозволяє відкликати файли, які хтось уже завантажив. Вихід із системи, блокування панелі або завершення сеансу не зупиняють роботу колектора.

## Що бачить адміністратор

Рецензенти та аналітики отримують інформацію про хід збору даних без кінцевих точок проксі, діагностики пулу, шляхів до серверів або необроблених помилок з’єднання. Для діагностики з’єднання потрібен дозвіл `account` для всього робочого простору. Для читання сповіщень, копіювання поза майданчиком та налаштування параметрів потрібен дозвіл `settings`.

Повні рядки браузера User-Agent не зберігаються в сеансах доступу. Оновлення також видаляє їх із кешу сеансів, що підлягає зміні. Журнал процесів панелі маскує літерали IP-адрес, облікові дані URL та секрети з мітками. Локальні журнали служб та раніше підписані записи журналу не перезаписуються. Правила доступу та підписані записи входу все ще використовують адресу клієнта.

### Замінити головний ключ

Використовуйте **Access → Мої обмеження → Перевипустити ключ адміністратора** або запустіть `tgwitness token rotate` з керованої інсталяції під час роботи панелі. Усі існуючі сесії браузера завершуються, включаючи сесії, відкриті за допомогою токенів колег. Браузер, що надсилає запит, отримує нову сесію; збережіть новий ключ адміністратора, перш ніж приховати його. Видані токени колег залишаються дійсними, доки їх окремо не скасують. Установка, що використовує `TGWITNESS_TOKEN`, повинна змінити це налаштування середовища та перезапуститися.

### Межі запитів та проксі-серверів

API допускає до 600 запитів на хвилину з кожної IP-адреси клієнта. Десять відхилених аутентифікацій протягом хвилини запускають експоненціальне охолодження, тривалість якого становить від однієї секунди до п’яти хвилин. Невдала спроба після закінчення охолодження збільшує його тривалість; десять хвилин без невдалих спроб скидають ескалацію. Відмови повертають коди HTTP 429 та `Retry-After`. Обмеження зберігаються в пам’яті та є спільними для всіх робочих просторів у одному процесі панелі; перезапуск очищає їх. Кількість прямих трансляцій обмежена до чотирьох на токен носія та 32 для процесу панелі. Відкриття трансляції також витрачає ліміт запитів до API.

Термін прийому тіл запитів становить 60 секунд (8 секунд для MCP). Кожна програма обмежує незавершені тіла до 32 запитів та 64 МіБ зарезервованого трафіку. Надто великі тіла повертають код 413, тіла, для яких закінчився час очікування, повертають 408, а вичерпання ємності для тіл повертає 503 із параметром «`Retry-After`».

Переадресовані заголовки IP ігноруються, якщо фактичний TCP-партнер не належить до `TGWITNESS_TRUSTED_PROXIES` (IP-адреси, розділені комами, або CIDR). Встановіть `TGWITNESS_PROXY_HEADER` на `x-forwarded-for` або `cf-connecting-ip`. XFF проходить від найближчого проксі до першого ненадійного партнера. Неправильно сформовані або дубльовані метадані надійних адрес відхиляються, тому вони не можуть успадкувати проксі-адресу з білого списку . Керуваний швидкий тунель довіряє локальному коннектору Cloudflare; налаштування у власному домені довіряє локальному Caddy. Прямі розгортання за замовчуванням не довіряють жодному проксі-серверу. Якщо ви запускаєте Uvicorn самостійно, вимкніть обробку заголовків проксі, щоб ця межа отримувала фактичний вузол.

`TGWITNESS_PANEL_ALLOWED_IPS` обмежує доступ до панелі, у тому числі адміністратора, лише переліченими IP-адресами або CIDR-діапазонами. Проба маршрутизаційної ідентичності інсталятора залишається публічною і не повертає даних облікового запису. Включіть необхідний локальний адміністративний маршрут перед увімкненням списку дозволених. Посібник **START-HERE** для керованої інсталяції містить інструкції щодо конфігурації служби та відновлення.

Селектор запиту API `ws` повинен ідентифікувати робочу область у шляху запиту; невідомі, невідповідні та дубльовані селектори відхиляються з кодом 404.

Скрипти та стилі панелі містять метадані цілісності SHA-384. Карта імпорту також охоплює локально імпортовані модулі JS у браузерах, що підтримують цілісність import-map. Динамічно згенерована мовна відповідь є окремою. Ці перевірки виявляють підміну ресурсів відносно наданої сторінки; вони не встановлюють довіру до скомпрометованого сервера, який може замінити як саму сторінку, так і її хеші.

**Журнал з моменту запуску** поєднує журнали процесів із записами активності з кожного робочого простору: входи, відмови, зміни маршруту та дії оператора. Це консоль у пам’яті для поточного процесу, а не постійна копія кожного повідомлення. Події, що повторюються часто, залишаються в журналі, а не заповнюють консоль.

Надання, зміна та скасування доступу, а також початок або закінчення сеансів також створюють підписані записи в журналі `access.*`. Токени не включаються до цих записів. Видані токени та облікові дані сеансів зберігаються у вигляді хеш-значень у зашифрованому сховищі.

****Головний адміністратор та межа довіри****

The main panel token remains unrestricted. Browser sign-ins with it create sessions subject to the administrator's configured session limits. Scripts sending the main token directly retain full access and are not counted as browser sessions.

This is application-level access control in one installation. All workspaces share the server process; this is not isolation from the host administrator. Keep the main token, Telegram sessions, signing keys and data directory private. A witness token is a separate checkpoint/health credential, not a panel access token.
