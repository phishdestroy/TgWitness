내장된 공개 MTProxy 목록 · 2026년 10월 29일#

이 문서는 초기 수동 선택 빌드의 테스트 기록입니다. 현재의 자동 풀 및 IP 모드에 대해서는 연결 설정을 참조하십시오. 아래의 카운트 및 지원되지 않는 기능은 테스트된 해당 버전에 해당합니다.

SoliSpirit/mtproto 및 zakky8/mtproto-proxy-pro에서 번들된 공개 스냅샷과 명시적인 HTTPS 새로고침 기능을 추가했습니다. 이 호스트에서 애플리케이션 다운로더는 2026년 10월 29일 12:58 UTC에 두 피드를 성공적으로 가져왔습니다: 필터링, 중복 제거 및 소스당 64개 항목 제한을 적용한 후 118개의 고유한 호환 엔드포인트가 확인되었습니다. 이는 목록 검색 기능만 검증한 것이며, 해당 엔드포인트를 통한 연결성이나 메시지 전달을 검증한 것은 아닙니다. 이 작업 동안 목록에 포함된 프록시에 실제 계정이 연결된 적은 없습니다. 운영자 및 사용자 가이드.

오류가 발생했거나, 내용이 비어 있거나, 호환되지 않는 소스 응답의 경우 이전 항목과 날짜가 유지됩니다. 업데이트 선택된 경로는 변경되지 않습니다. 공개 주소는 유효성 검증을 거치며, 선택 시 IP 주소가 고정됩니다. 운영자/수동 경로는 별도로 유지됩니다. 이제 계정 로그인 전 패널에서 연결 테스트를 사용할 수 있습니다. 가짜 TLS ee 및 자동 프록시 선택은 여전히 지원되지 않습니다. 운영자 카탈로그는 구독 설정을 완전히 재정의합니다.

  • 전체 테스트 스위트: 366개 통과, 3개 건너뜀, 287.94초. 기존 종속성 경고 및 플랫폼 건너뜀 항목은 그대로 남아 있습니다. 최종 공개 목록/현지화 회귀 테스트: 36개 통과, 여기에는 유효하지 않은 다운로드 프록시 포트에 대한 거부도 포함되며, 이는 전체 테스트 스위트와 중복됩니다.
  • 영어/러시아어, 라이트/다크 모드에서 390/1440 픽셀 해상도로 브라우저 호환성 테스트 통과: 기본 제공 옵션, 설정 열 때 외부 데이터 불러오기 없음, 명시적 새로고침, 오류 발생 시 경로 및 캐시 유지, 로그인 전 프로브, 응답 지연 시 작업 공간 격리, 소스 세부 정보 및 레이아웃/명암비. 자바스크립트 오류나 외부 브라우저 요청 없음.
  • 총 13개 언어에 대한 최종 정적 번역 검수가 모두 통과되었으며, 새 콘텐츠는 러시아어로 번역되었고, 그 외 언어에서는 영어로 명확하게 대체 표시됩니다. 업데이트된 내장 가이드가 두 테마 모두에서 레이아웃 및 대비 검사를 통과했습니다.

선택적 추가 기능 소개 · 2026년 10월 29일#

  • 현지화, Witness 설정 및 게시 검증을 위한 30가지 집중 테스트를 통과했습니다.
  • 영어/러시아어, 라이트/다크 모드, 390/1440 픽셀 해상도에서 크로미움 설정 승인 테스트 통과: 키보드 포커스 및 리턴 키 작동, 추가 기능 선택 시 암시적 연결 없음, 초안 보존, 고정된 구성/토큰 다운로드, 잠금 시 토큰 삭제, 그리고 정상 작동하는 로컬 가이드 앵커. 레이아웃 및 단색 배경 텍스트 대비 검사 통과.

직접 인증 키(Auth Key) 흐름은 실제 가져오기 및 인증 엔드포인트를 통해 합성된 자격 증명으로 테스트되었습니다. 점검 항목에는 불완전한 키, 누락된 DC, 부정확한 사용자 ID, 계정 신원 불일치, 저장된 API 자격 증명, 표시되는 요청 진행 상황, 비밀 정보 삭제, 편집 또는 메서드 변경 후 지연된 응답 등이 포함됩니다. 네 가지 로그인 방식 모두 320, 390, 1440 픽셀 해상도에서 검증되었습니다. 파일 선택기는 형식 안내보다 먼저 표시되며, ‘연결’ 버튼은 API 설정이 접힌 상태에서 초기 844픽셀 뷰포트에 적절히 표시됩니다. 이번 UI 수용 테스트에서는 실제 인증 키를 사용한 인증 시도는 수행되지 않았습니다.

두 브라우저 제품군을 사용하여 패널 새로 고침을 다시 확인한 결과, 페이지 자바스크립트 오류나 외부 요청은 관찰되지 않았습니다. 계정 제품군은 이제 하나의 API ID/해시 쌍을 붙여넣는 기능, 필드를 대체하지 않고 형식이 잘못되었거나 중복된 쌍을 거부하는 기능, 메타데이터 전용 안내, 그리고 로그인 방법 변경 또는 수동 자격 증명 편집 후 유효 기간이 지난 가져오기 응답을 무시하는 기능을 포함합니다. 설정 가이드, 명시적 시작/일시 중지, 빈 검색 복구, 최종 연결/로컬 가이드 레이아웃 및 320, 390, 1440 픽셀에서의 확실한 텍스트 대비에 대한 6가지 추가 집중 점검을 통과했습니다. 직접 로그인 업데이트에는 단일 전화번호/코드 요청 기능이 추가되었으며, 전화번호, QR 및 세션 로그인 시 현재 작업 공간에 저장된 API 쌍을 재사용합니다. 위의 전체 Python 테스트 모음에는 새로운 지속성, 부분 자격 증명 거부 및 작업 공간 격리 테스트가 포함되어 있습니다. 브라우저 점검 항목에는 직접 전화번호 입력, 저장된 자격 증명 재사용, 메타데이터 전용 라우팅, 원클릭 파일 승인, 중복 계정 거부 기능이 포함됩니다. 간소화된 패널 토큰 및 전화번호 양식도 320, 390, 1440 픽셀 해상도에서 초기 스크롤 없이 검증되었습니다. 호환성 검사 결과, 기존 프로세스가 여전히 실행 중인 상태에서도 직접 전화번호 양식이 이전 구성/코드 엔드포인트를 사용할 수 있음이 확인되었습니다.

사용자가 제공한 계정 하나에 대해서는 공개 테스트 환경 외부에서 별도로 확인했습니다. 해당 계정의 Telethon, Pyrogram 및 TData 입력 데이터는 모두 동일한 인증 정보로 확인되었으며, 함께 제공된 JSON 파일에는 API 인증 정보가 포함되어 있었습니다. 네 개의 파일 모두 0.6.0 패널을 통해 불러왔으며, 텔레그램에서 예상된 숫자형 계정 ID가 확인되었습니다. 원본 파일은 변경되지 않은 상태로 유지되었습니다. 소스는 선택되지 않았으며 관찰 기능은 비활성화된 상태로 유지되었습니다. 이는 실시간 수집, 복구 또는 처리 능력이 아닌, 하나의 가져오기/로그인 예시에 해당합니다.

텔레그램은 실제 QR 토큰도 발행했으나, 스캔되지 않은 상태에서 취소되었습니다. 전체 QR 확인 및 2단계 인증(2FA) 절차는 시뮬레이션된 클라이언트를 통해 테스트되었으며, 실제 텔레그램 앱을 통한 모바일 확인은 별도의 승인 단계로 남아 있습니다. 공개 파일에는 실제 계정 식별자, 비밀 정보 또는 스크린샷이 포함되어 있지 않습니다.

런처 업그레이드가 완료되었습니다. 소스, 설치된 메타데이터 및 준비 상태 마커는 0.6.0을 보고하며, QR코드는 8.2이고 pip check 검증을 통과했습니다. 설치된 휠은 패널과 가이드를 제공했으며, 인증되지 않은 API 요청을 거부하고, 직접 및 스트리밍된 32개 이벤트 합성 내보내기 데이터를 독립적으로 검증했습니다. 업데이트된 오프라인 가이드는 320, 390, 1440 픽셀 해상도에서 확인되었습니다. 공개 스크린샷은 여전히 합성된 것입니다.

소스 릴리스에는 허용 목록에 포함된 107개의 파일이 포함되어 있습니다. 로컬 문서 링크는 정상적으로 작동합니다. Docker/Caddy 실행, 원격 CI/패키지 게시, ARM64 런타임, 지속적 수집 및 전체 실시간 텔레그램 호환성 매트릭스에 대해서는 본 문서에서 다루지 않습니다.

실제 프로젝트인 pythonw.exe는 격리된 합성 패널을 실행하여 HTTP 200을 반환하고 logs/server.log에 시작 진단 정보를 보관했습니다. 로그에는 생성된 패널 토큰이나 HTTP 액세스 기록이 포함되어 있지 않았습니다. 테스트는 자신의 합성 프로세스만 종료했습니다. 작업 스케줄러 작업은 등록되지 않았으며, 로그온/로그아웃, 절전 모드 및 서비스 복구는 여전히 별도의 검증 항목으로 남아 있습니다.

설치 및 배포 업데이트#

집중 설치 프로그램, 패키징 및 준비 상태 점검은 14개의 테스트를 통과했으며, 사용할 수 없는 심볼릭 링크 생성으로 인해 1개 항목은 건너뛰었습니다. 네이티브 래퍼 점검은 공백이 포함된 경로, 인수 전달, 설정/데모 모드 및 0이 아닌 종료 코드 전파를 다룹니다. Git Bash 검사는 시뮬레이션된 데몬을 사용하여 Docker 셸 헬퍼를 테스트하며, 여기에는 Docker 미설치, Compose 미설치, 상태 대기 실패, 대체 포트에서의 성공적인 시작 등이 포함됩니다. 이러한 시뮬레이션된 검사는 Docker 런타임 호환성을 보장하지 않습니다.

공식 소스 코드의 전체 사본을 경로에 공백이 포함된 새로운 Windows 디렉터리에 설치했습니다. scripts\Setup.cmd는 새로운 환경을 생성하고 고정된 런타임을 설치했으며, Start.cmd --check --json는 대상 데이터 디렉터리를 생성하지 않은 채 준비 완료 상태를 보고했습니다. pip check는 테스트를 통과했습니다. 재빌드된 휠도 직접 및 스트리밍 방식의 32개 이벤트 내보내기를 포함한 설치된 패키지 검사를 통과했습니다.

셸 구문과 5개의 워크플로우/Compose YAML 파일이 파싱되었습니다. 소스 및 이미지 Compose 구성은 저장소 및 런타임 설정에 대해 일치합니다. 이 단계에서 23개의 마크다운 문서에 걸쳐 있는 총 139개의 로컬 링크가 모두 해결되었습니다. 공개 소스 선택 항목에는 99개의 파일이 포함되어 있습니다.

CI 정의는 이제 Windows/Linux/macOS에서의 새로운 네이티브 설정, 컨테이너 재생성 시의 Compose 상태/액세스 제어/지속성, 그리고 Caddy 구성을 적용합니다. 릴리스 워크플로는 이러한 점검을 통과해야만 배포가 이루어지도록 제한하며, 에뮬레이트된 ARM64 스모크 테스트를 추가합니다. 이 호스트에서는 Docker를 사용할 수 없습니다. 실제 Compose/Caddy 실행, 인증서 발급, ARM64 실행, 원격 워크플로우/패키지 게시 는 로컬에서 여전히 제한됩니다. 애플리케이션/UI 코드는 이번 업데이트로 변경되지 않았으며, 이전 전체 Python 및 브라우저 테스트 결과는 재실행되지 않았습니다.

버전 0.5.0#

전체 고정 런타임 테스트 모음이 통과되었습니다: 81개 통과, 1개 건너뛰기, 소요 시간 22.00초, 기존 Starlette 경고가 발생했습니다. Windows에서는 POSIX 권한 검사가 건너뜁니다. 새로운 핸들러 테스트는 다양한 정책을 통해 메시지 전송, 편집, 범위 지정/비지정 삭제, 반응, 참가자 업데이트 및 멤버십 서비스 메시지를 테스트합니다. 비활성화된 카테고리는 해당 실시간 관측 결과를 생성하지 않으며, 커버리지 진단 및 명시적 스냅샷은 계속 사용할 수 있습니다. 테스트는 지속된 정책, 작업 공간 분리, 서명된 전후 감사 기록, 정책 변경 없음 동작, 엄격한 유효성 검사 및 다음 프로세스 수신에의 포함 여부를 검증합니다.

데모 항목 테스트를 통해 이 도구의 기능이 구성된 패널 토큰과 다르다는 점이 확인되며, 실제 작업 공간에 대한 인증이 불가능하고, 수집 설정을 변경할 수 없으며, 원격, 전달, 크로스 오리진 또는 유효하지 않은 호스트 요청에 대해서는 발급되거나 수락되지 않습니다. 명시적인 데모 플래그 없이 저장된 데모를 열어도 자동 항목 등록은 활성화되지 않습니다.

크로미움 수용 테스트에서 39가지 시나리오를 통과했으며, 여기에는 토큰 입력 없이 로컬 데모에 접속하는 경우, 모니터링 사전 설정, 소스 선택에서 정책으로의 전환, 계정별 독립성, 데스크톱/320/390픽셀 레이아웃 및 텍스트 대비 검사 등이 포함됩니다. 페이지에서 자바스크립트 오류는 발생하지 않았습니다. 호스트의 AdGuard가 삽입한 요청은 수신 내역에 그대로 남아 있습니다. 다운로드 HTTP 테스트 케이스에서는 클라이언트가 연결을 종료한 후 연결 재설정이 기록되었으나, 어설션은 여전히 통과했습니다. 이는 실제 서비스 운영 환경에서의 결과가 아닙니다.

일반 런처의 격리 환경이 0.5.0으로 업그레이드되었으며, 소스 버전과 설치된 버전이 일치하고 pip 검사가 통과되었습니다. 기존 비밀 금고 암호화, 잘못된/누락된 키 거부 및 서명/미디어 변조 검사가 전체 테스트 스위트에서 통과되었습니다. 메시지 내용이나 첨부 파일에 대한 새로운 애플리케이션 암호화 기능은 제공되지 않는다고 명시되어 있습니다.

업데이트된 UI를 사용할 수 있도록 로컬 데모가 재시작됩니다. 기존에 생성된 기록은 유지되며, 기존 백그라운드 데모 프로세스를 중지하면 다음 시작 시 오프라인 경계가 생성됩니다. 이러한 확인 과정에는 실제 텔레그램 세션이 사용되지 않습니다.

실행 중인 localhost:8787 패널은 버전 0.5.0, 자동 데모 액세스, 5가지 모니터링 제어 기능 및 33개의 보존된 합성 저널 이벤트를 표시했습니다. 별도로 설치된 0.5.0 휠은 모든 패널/가이드 자산을 제공했으며, 인증되지 않은 API 접근을 거부하고, 직접 및 스트리밍 다운로드 도우미를 통해 검증된 32개 이벤트가 포함된 ZIP 파일을 생성했습니다. 런타임 패키지 버전은 0.4 버전에서 기록된 대로 고정되어 있습니다.

버전 0.4.0#

전체 고정 런타임 테스트 모음이 통과되었습니다: 78개 통과, 1개 건너뜀, 소요 시간 19.77초. 건너뛴 검사 항목은 POSIX 권한을 필요로 하며, 업스트림 Starlette TestClient의 사용 중단 경고는 여전히 남아 있습니다. 새로운 테스트 항목으로는 스트리밍 다운로드/워크스페이스 라우팅, 인증 헤더, 덮어쓰기 거부, 리디렉션, 잘린 응답, 공지된/실제 크기 제한, 제한된 읽기, 정리, 하드 링크가 없는 파일 시스템, 준비 상태 오류, 그리고 패키지를 설치해서는 안 되는 런처 모드 등이 포함됩니다. 내보내기 테스트를 통해 워크스페이스 내 임시 파일 및 선택적 고아 파일 정리가 확인되었습니다.

크롬ium 호환성 테스트에서 나열된 36가지 시나리오를 모두 통과했으며, 페이지 자바스크립트 오류는 발생하지 않았습니다. 이 도구는 모의 전화/코드/2단계 인증(2FA) 로그인, 변환된 세션, 두 개의 작업 공간 및 별도의 경로/상태, 관측값, 서명, 체크포인트 및 타임스탬프 요청을 실행하며, 그 외에도 다음을 수행합니다:

  • 데스크톱 및 320/390픽셀 레이아웃, 가로 방향 넘침 없음, 명확한 내비게이션, 그리고 초기 844픽셀 뷰포트 내에 첫 번째 로그인 필드가 표시됨.
  • WCAG AA 텍스트 기준에 따른 단색 배경과의 텍스트 대비가 확보되어 있습니다. 비활성화된 컨트롤, 불투명도 및 이미지/그라데이션 배경은 제외되었으며, 이는 완전한 WCAG 감사가 아닙니다.
  • 모의 OS 파일 선택기/쓰기 가능 기능을 통해 작성된 실제 로컬 내보내기 응답, 그 후 독립적인 ZIP 검증; 취소 시 내보내기 요청이 전송되지 않습니다.
  • 쓰기 오류가 발생하면 대상 처리가 중단되며, 128 MiB 폴백은 일치하는 페이로드를 할당하지 않은 채 지정된 응답 크기보다 큰 응답을 거부합니다.
  • 데스크톱 및 두 가지 좁은 화면 너비에 대한 영어 현지화 가이드.

OS 저장 대화 상자와 실제 멀티 기가바이트 규모의 브라우저 쓰기 작업은 자동화되거나 검증되지 않았습니다. 파이썬 다운로드 테스트는 제한된 청크와 루프백 고정 장치를 사용합니다. 실제 텔레그램을 활용한 전체 배포 승인 테스트는 별도로 진행됩니다.

일반 설치 프로그램을 통해 .venv가 0.4.0으로 업그레이드되었습니다. 소스 코드와 설치된 메타데이터가 일치하며, pip check는 테스트를 통과했습니다. python start.py --check --json는 데이터 디렉터리를 생성하지 않은 채 새로운 합성 경로에서 준비 완료 상태를 보고했습니다. 로컬 키 저장소 관련 경고는 여전히 유효합니다: journals/media는 애플리케이션에 의해 암호화되지 않습니다.

0.4.0 휠이 빌드되어 별도의 디렉터리에 설치되었습니다. 총 23개의 애플리케이션 파일이 소스 파일과 바이트 단위로 일치합니다. 설치된 패키지는 패널 및 영어 가이드/자산을 제공했으며, 인증되지 않은 API 액세스를 거부하고, 검증에 통과한 32개 이벤트가 포함된 합성 ZIP 파일을 내보냈습니다. 또한 스트리밍 다운로드 명령을 통해 실행 중인 설치된 애플리케이션에서 독립적으로 검증된 ZIP 파일을 가져왔습니다.

공개 문서와 로컬 가이드는 영어로 제공되며, 로컬 문서 링크는 정상적으로 작동합니다. PowerShell은 Windows 작업 템플릿을, Python은 macOS plist 파일을 파싱했습니다. 이는 구문 검사일 뿐, 서비스 실행은 아닙니다. 등록된 작업/서비스는 없습니다. CI 구성에 이제 준비 상태 확인이 포함되었으나, 원격 CI는 아직 실행되지 않았습니다.

0.4 브라우저 실행 시 다시 호스트 AdGuard 삽입 및 Windows asyncio 소켓 정리 시 OSError 10022 오류가 관찰되었습니다. 브라우저 어설션은 통과되었으며, 이러한 환경적 관찰 결과는 고정된 애플리케이션 동작으로 간주되지 않고 그대로 유지됩니다. 초기 OpenSSL/브라우저/pip 샌드박스 실행 시도는 실패했으며, 성공적으로 통과한 실행은 샌드박스 외부에서 승인된 실행 방식을 사용했습니다.

  • 외부 볼트 마스터 키: 서로 다른 파생 작업 공간 키, 성공적인 재개방, 잘못되었거나 누락된 키에 대한 거부, 기존 로컬 볼트의 암시적 마이그레이션 없음.

개발 과정에서 루프백 테스트가 피어의 종료 신호를 무한정 기다리는 현상이 발생했으며, 또 다른 실행에서는 핸드셰이크 후 Windows 연결이 재설정되는 현상이 관찰되었습니다. 이제 이 테스트 환경은 전체 통신 과정을 제한하며, 핸드셰이크 완료 후 발생하는 EOF/재설정을 연결 종료로 간주합니다. 핸드셰이크/인증 어설션은 여전히 필수입니다. 이는 실제 프록시 제공업체를 배제하는 것이 아니며, 텔레그램 전송 계층의 고정된 결함을 시사하는 것도 아닙니다.

아래에 설명된 호스트 AdGuard 요청 관찰 내용은 여전히 유효합니다. 실제 텔레그램 계정, SOCKS/HTTP 프록시 외부, 또는 가동 중인 MTProxy 서버는 사용되지 않았습니다. MTProxy는 실험적 단계이며, 선택된 옵션 및 비밀 키 유효성 검사는 확인되었으나 실제 상호 운용성은 검증되지 않았습니다. 새로운 외부 키 및 세션 변환 명령어는 합성 시크릿을 통해서만 테스트되었습니다. Linux/macOS/Docker에 대해서는 아직 검증되지 않았습니다.

환경 관찰#

Windows 샌드박스 제한 사항으로 인해 기본 pytest/pip 임시 디렉터리와 Playwright 하위 프로세스가 차단되었습니다. pytest는 프로젝트 내부의 새로운 임시 디렉터리를 사용했으며, 설치 및 브라우저 프로세스는 샌드박스 외부에서 승인된 실행이 필요했습니다.

해당 기기의 AdGuard가 local.adguard.org로 전송되는 요청을 브라우저에 주입했습니다. 브라우저 기록에는 이러한 요청이 남아 있습니다. 이번 실행 결과는 수정되지 않은 브라우저 환경에서 아웃바운드 요청이 전혀 없음을 입증하는 증거가 아닙니다. 앱 소스 자체에는 외부 자산/CDN/분석 요청이 포함되어 있지 않습니다. AdGuard 설정은 변경되지 않았습니다.

최종 브라우저 실행 시 Windows asyncio 소켓 정리 과정에서 OSError 10022 오류가 기록되었습니다. 모든 브라우저 검증은 통과되었으며, 페이지 내 자바스크립트 오류는 발생하지 않았습니다. 원인은 확인되지 않았으며, 이번 실행 결과만으로는 호스트 전송 문제가 없음을 입증할 수 없습니다.

urllib의 connection-close 요청을 사용한 첫 번째 설치 패키지 HTTP 프로브에서는 샌드박스 내부와 외부 모두에서, 그리고 두 의존성 세트 모두에서 연결 재설정이 발생했습니다. 마지막 프로브는 http.client를 통해 표준 HTTP/1.1 지속 연결을 사용했으며 테스트를 통과했습니다. 브라우저 요청도 통과했습니다. 재설정의 정확한 원인은 확인되지 않았으며, 이는 애플리케이션의 고정된 결함으로 분류되지는 않았습니다.

나머지 자격 요건#

보관된 실시간 저널은 실제 수집 내역, 수정 내역, 삭제 알림, 첨부 파일, 재확인 및 속도 제한 처리를 기록합니다. 단, 이 기록은 전송 내역의 완전한 추적이나 역할별 가시성, 반응 주체, 장기간의 FloodWait, 계정 차단 및 네트워크/프로세스 중단 복구와 관련된 통제된 매트릭스를 보장하지는 않습니다. QR 토큰 발급은 완료된 모바일 QR 확인과는 별개로 처리됩니다.

Docker 빌드/실행, Linux/macOS 설치, 지속적인 고부하 처리, 독립적인 보안 검토, 실질적인 독립적 TSA 대응, 인증서 취소/보관 검증 및 포렌식 인증은 기록된 인증 범위에서 제외됩니다. 저장된 MTProto 상태 및 캐치업 기능은 구현되었으나, 원자적 내구성 재재생 기능은 아직 확립되지 않았습니다. 관리자 로그 수집, 추가 리액터 목록 및 우선순위 단기 폴링은 별도의 기능으로 남아 있습니다. 제어된 자격 매트릭스에 대한 실시간 승인 내용을 참조하십시오.

세부적인 로컬 영수증 및 스크린샷은 test-results/ 디렉터리에 있습니다(Git에서 무시됨). docs/assets/에 있는 공개 스크린샷에는 가상의 데모 데이터만 포함되어 있습니다.
