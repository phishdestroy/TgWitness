04 ↗

几分钟内即可开始使用

请使用示例数据试用 TgWitness，随后在 Windows、Linux 或 macOS 上启动您自己的 Telegram 监控工作区。

03 ↗

专用账号

请准备一个单独的 Telegram 账号用于数据采集。

05 ↗

连接账户

可通过二维码、电话号码或会话导入连接 Telegram。选择消息来源，并确认新消息已成功记录到您的日志中。

06 ↗

选择代理

维护自动 MTProxy 路由，或使用您自己的代理。选择 IP 模式、备用规则以及外部请求的路由。

07 ↗

导出与验证

导出捕获的 Telegram 聊天记录，验证签名，并将日志与独立见证人保留的检查点进行比对。

02 ↗

GitHub Actions 捕获

在临时 GitHub Runner 上导出一个 Telegram 聊天记录。

从保存的记录到共享报告

09 ↗

跨所有聊天记录进行调查

在频道、群组、私聊和机器人中开展端到端的 Telegram 调查：包括整个账户的捕获、历史记录、联系人、链接、文件、时间线以及经过验证的证据。

10 ↗

创建案件看板

在私人看板上收集已保存的观察结果、精确标注和操作片段，与团队讨论并提交证据集合。

11 ↗

设计报告

选择报告数据、八种设计模板之一及内容，然后预览并导出 HTML、带签名的 PDF 或完整的证据包。

12 ↗

准备一份共享副本

选择收件人可接收的记录和字段，检查最终副本，并验证其已签名的清单及源日志边界。

13 ↗

管理一组账户

比较群组工作区、查找来源、审查观察时段，并应用共享设置（可针对每个账户设置例外）。

边试用边学习

08 ↗

了解证据如何运作

追踪一条消息从捕获到检查点的全过程。修改一条示例记录，重新计算其 SHA-256 链，并查看保留的检查点会检测到什么。

14 ↗

确保安全

了解会话、密钥和证据的存储位置，哪些数据会离开您的设备，保护措施涵盖哪些内容，以及如何加强系统安全性。

16 ↗

设置 Witness 机器人

通过独立的见证节点（配备专属密钥及只读收集器访问权限），将签名的日志检查点发布至您的 Telegram 频道。

浏览存档

15 ↗

分享案例

为审查员和分析师提供对选定账户和聊天的访问权限，并设置独立的权限、会话限制和可撤销的令牌。

17 ↗

保持其运行

请在配备持久化存储、私有控制面板访问权限、备份功能以及重启后自动检查机制的服务器上运行 TgWitness。

18 ↗

查找问题所在

请使用针对各问题的正确信号，检查控制面板访问权限、Telegram 连接状态、消息缺失情况、FloodWait 状态以及见证状态。
