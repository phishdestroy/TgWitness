保护范围

✓ 已收录

  • 记录被修改、删除或重新排序：哈希链或签名会断裂。
  • 在您将检查点保存到别处之后，日志被截短或重建：检查点不再匹配。
  • 猜测令牌：256 位随机数，常量时间比较，每分钟失败 15 次即封锁该地址。
  • 恶意聊天内容：文本始终是文本，绝不作为 HTML；附件以文件形式下载；面板不从其他网站加载任何内容。
  • 数据目录被盗但保险库密钥在外部：会话和密钥仍是加密的。

! 由您决定

  • 主令牌可以做任何事。请给他人限定范围的访问权限，主令牌留给自己。
  • 机器上的管理员可以读取一切并重新签署日志。请将指纹和检查点保存在别处。
  • TgWitness 不加密消息和媒体。请加密磁盘，收紧权限。
  • 在 localhost 之外使用普通 HTTP 会泄露令牌。请使用 HTTPS 或 SSH 隧道。
  • 签名不会告诉您遗漏了什么。请在您自己的账户和来源上检查覆盖范围并测试送达。

共享案件的访问权限，可设置权限、有效期和会话限制。

强化安装安全性

已完成 0/8
  1. 请使用专用的 Telegram 账号，绝不要用主账号。
  2. 请将控制面板保留在 127.0.0.1 上。远程访问只通过 HTTPS（内置 Caddy）或 SSH 隧道。
  3. 请加密存放数据目录的磁盘，消息和媒体按原样存储。
  4. 将数据目录限制为仅服务账户可访问（Unix 上为 0700，Windows 上为文件夹权限）。
  5. 在服务器上将保险库密钥保存在别处：首次启动前设置 TGWITNESS_VAULT_KEY_FILE。
  6. 将指纹和检查点保存在另一个系统上，在另一台主机上运行见证人。
  7. 切勿将 data/、会话密钥、panel-token.txt 或保险库密钥上传至 GitHub 或聊天群组。
  8. 请勿在反向代理服务器上记录 Authorization 标头或请求正文。
我可以更改面板令牌而不丢失数据吗？

可以，它只能打开面板。停止 TgWitness，删除 panel-token.txt，重新启动。日志、会话和密钥都会保留。如果设置了 TGWITNESS_TOKEN，则以该值为准，而不是文件。

为什么消息在静止状态下不进行加密？

采集器必须读取它们才能搜索、比较和导出。放在同一台机器上的密钥挡不住本来就能读取这台机器的人。磁盘加密防的是磁盘被盗，权限防的是运行中的系统。

报告漏洞

在 GitHub 上使用 Security → Report a vulnerability。提供版本、影响以及使用虚构数据的最小复现。切勿发送凭据、账户文件夹或真实证据。如果私密报告已关闭，请开一个 issue 申请私密渠道，不要写漏洞利用细节。
