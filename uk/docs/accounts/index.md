# Підключити обліковий запис

Canonical page: https://phishdestroy.github.io/TgWitness/uk/docs/accounts/

Один простір = один акаунт, його журнал і його ключ.

## Виберіть спосіб входу

**Акаунти** → додати простір → налаштування підключення. Використовуйте для цього окремий акаунт.

- **QR-код:** відскануйте його на екрані «Пристрої» в Telegram і підтвердьте.
- **Номер телефону:** номер, код, потім пароль 2FA, якщо він є.
- **Імпорт сесії:** ваш власний файл сесії або дані Telegram Desktop.

Використовуйте вбудований профіль API або власні API ID і hash. Він лише називає застосунок — не входить в акаунт і нічого не приховує.

**Спочатку потрібен проксі-сервер?**

Ви можете [вибрати та перевірити маршрут з’єднання](https://phishdestroy.github.io/TgWitness/uk/docs/proxies/) перед входом у систему. Кожен обліковий запис має свій власний маршрут.

## Виберіть, що спостерігати

1. Оберіть потрібні чати, групи чи канали.
2. Перевірте налаштування збору, зокрема медіа.
3. Запустіть і перевірте підключення та нещодавню активність.

Акаунт повинен мати доступ. Адміни й учасники бачать різне, журнал показує те, що отримав цей акаунт.

Весь акаунт? **Джерела → Охоплення спостереження → Режим розслідування**, перевірте й натисніть **Зберегти охоплення**. Повний розбір: [розслідування по всьому акаунту](https://phishdestroy.github.io/TgWitness/uk/docs/cases/).

## Перегляньте весь шлях

У тестовій групі надішліть повідомлення з іншого акаунта, відредагуйте й видаліть його. У журналі мають з'явитися всі три події. Потім [експортуйте й перевірте](https://phishdestroy.github.io/TgWitness/uk/docs/exports/).

«Підключено» означає, що зв'язок працює. Спіймане тестове повідомлення означає, що події справді доходять.

## Додати ще один обліковий запис

Новий простір в **Акаунтах**, ті самі кроки. Запишіть відбиток ключа кожного акаунта, щоб потім розрізняти експорти.
