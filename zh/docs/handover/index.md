# 准备一份共享副本

Canonical page: https://phishdestroy.github.io/TgWitness/zh/docs/handover/

在保持原始工作区完整的同时，分享相关观察结果。

移交是一份独立的、经签名的摘录文件。需选择聊天记录和相关人员，对身份信息或文本内容进行精简，并决定哪些文件和团队笔记应包含在收件人的副本中。其清单会记录所选内容，以及未更改、已精简和已省略的记录数量。

## 准备收件人的数据提取文件

1. 打开**“导出”→“移交提取”**。填写其用途，选择聊天记录及可选的 UTC 时间段，如需指定涉案人员，请勾选**“加载所选聊天记录中的人员**”。
2. 可选择如何处理其他人员：使用化名、省略其消息，或按记录原样显示。消息正文和附件可独立设置；可选择性屏蔽电话号码和电子邮件地址。
3. 请选择是否包含“案件看板”的书签和切片，或带有评论的卡片。在本文中，调查员别名可替代团队名称。
4. 选择**“下载移交摘要**”。在本地打开生成的报告和选定的记录，验证归档文件，并在发送前检查副本。

### 一份正本，一份经授权的共享副本

合成示例 · 仅用于说明身份

1. **选择。**包含案件聊天记录，并标明该摘录涉及的对象。
2. **最小化。**选择其他参与者在共享副本中的显示方式。
3. **检查。**在发送生成的存档文件之前，请先打开其报告和记录进行**检查**。
4. **分享。**提交经核对的译文，并单独提供其可信指纹。

#### 原始观察

Nora · 用户 71002

“我已收到修订后的链接。”

源日志会保留此保存的观察记录。

#### 收件人副本

按记录显示：Nora · 用户 71002 · “我已收到修订后的链接。”

化名：P01 · “我已收到修订后的链接。”

省略：此参与者的消息未包含在译文中。

#### 检查实际文件

请阅读 report.html 和 records.jsonl 文件。

请核对身份信息、文本、附件及可选的团队评论。

#### 已签名的摘录

选定内容 + 文件哈希值 + 签名清单

一个与源日志边界关联的独立包

## 综合运用各项控件

| 控制 | 对文案的影响 |
| --- | --- |
| 人员 | 确保选定对象可识别；其他参与者可按需进行假名化处理或省略。 |
| 文本 | 可选择包含所有文本、仅包含选定人员及观察账户的文本，或省略消息正文及其包含文本的详细信息字段。 |
| 文件 | 选择指定人员和监控账户的文件、所有显示消息的文件，或不选择任何文件。 |
| 案件看板 | 请勿选用看板素材、书签和切片，也不要使用包含团队讨论的卡片。 |

请审查自由格式文本、文件内容以及身份信息：使用化名并不意味着消息或附件中出现的每个名字都会自动被移除。如果选定的保存文件不可用，请在生成提取文件之前将其恢复，或明确省略相关附件。

## 确保译文内容可独立核查

```
python -m tgwitness.verify handover.zip --fingerprint TRUSTED_PUBLIC_KEY_SHA256
```

请将原始的已签名证据存档与检查点分别保留。移交过程会记录其自身的投影，因此接收方无需接收整个工作区，即可核对已交付的副本。[“报告工作室](https://phishdestroy.github.io/TgWitness/zh/docs/reports/)”提供其阅读设计；[导出验证](https://phishdestroy.github.io/TgWitness/zh/docs/exports/)说明了可信引用。
