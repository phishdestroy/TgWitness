# MCP только для чтения

Canonical page: https://phishdestroy.github.io/TgWitness/ru/docs/reference/mcp/

Подключите клиент MCP к выбранным рабочим пространствам и чатам с ограниченным по времени и отзывным доступом.

**Текущая версия:** используйте репозиторий исходного кода; в портативной предварительной версии 0.7.0 эта функция ещё не реализована.

[Руководство по рабочему процессу](https://phishdestroy.github.io/TgWitness/docs/archive/) · [Вики](https://github.com/phishdestroy/TgWitness/blob/main/docs/wiki/Archive-and-Integrations.md)

Установите дополнительный сервер из каталога проекта TgWitness:

```
python -m pip install '.[mcp]'
```

В панели управления откройте **«Интеграции» → «MCP**». Назовите подключение, выберите его рабочие пространства и чаты, а также установите срок действия. Скопируйте токен архива один раз; его нельзя восстановить позже. Отзывайте утерянные токены и выдавайте новые. Токены панели управления и учетные данные Telegram не являются учетными данными MCP.

## Подключить клиент

Панель генерирует `.vscode/mcp.json` для **локальной среды VS Code** с использованием её [задокументированной конфигурации](https://code.visualstudio.com/docs/agents/reference/mcp-configuration). Сохраните загруженный файл в этом месте, запустите **MCP: List Servers** и запустите TgWitness. VS Code запросит токен через окно ввода пароля. Загруженный файл JSON содержит справочную информацию по запросу, а не сам токен. Используйте исполняемый файл Python из среды, в которой установлен MCP extra.

Для других клиентов stdio выполните:

```
python -m tgwitness.mcp_server --api-url http://127.0.0.1:8787
```

Установите `TGWITNESS_ARCHIVE_TOKEN` в защищённой среде клиента. Не указывайте его в аргументах команд или URL-адресах. Мост получает данные через авторизованный API архива панели управления; он не имеет прямого доступа к базе данных. Stdout передаёт только сообщения MCP.

Для удаленных клиентов запустите сервис рядом с панелью:

```
python -m tgwitness.mcp_server --transport streamable-http \
  --api-url http://127.0.0.1:8787 --port 8766 \
  --public-url https://archive.example.org/mcp
```

Перенаправьте `/mcp` через обратный прокси HTTPS на `127.0.0.1:8766/mcp`, сохраняя заголовок `Authorization: Bearer …`. Отключите регистрацию заголовков авторизации и тел запросов/ответов. Привязывайте за пределы loopback только при необходимости, используя `--host` и `--public-url`. Конечная точка использует Streamable HTTP из официального [MCP Python SDK](https://github.com/modelcontextprotocol/python-sdk). Он поддерживает явно настроенные учетные данные bearer, а не обнаружение OAuth; клиенты, требующие исключительно OAuth, не поддерживаются.

**Проверка протокола и доступ** инициируют запуск реального клиента MCP и отображают список инструментов. При этом сообщения не загружаются. Для удаленной проверки выбранный сервер MCP получает токен архива. Настраивайте только тот сервер, которым вы управляете или которому доверяете в данном контексте.

## Объем и результаты

Доступные инструменты: `list_workspaces`, `list_chats`, `search_messages`, `get_message_versions`, `get_message_context`, `get_journal_event` и `get_capture_status`. Не предусмотрены действия в Telegram, изменения настроек или инструменты для массового экспорта. При каждом прочтении повторно проверяется доступ к рабочему пространству/чату; просроченные и отозванные учетные данные перестают действовать. Ограничения: 60 запросов к API в минуту на одну учетную запись, 50 записей на страницу, размер ответа 64 КиБ и восьмисекундный тайм-аут API.

Результаты поиска сообщений включают рабочую область, идентификаторы чатов/сообщений, последовательность событий, сохраненный хеш и ссылку на панель. Пользователь, открывающий ссылку, должен иметь собственную авторизованную сессию панели . Исходные объекты Telegram, хеши доступа, ссылки на файлы, материалы сессии и ключи опущены. Поиск осуществляется по тексту сообщений, а не по исходным полям. Текст ограничен, а места усечения отмечены. Редактирования, уведомления Telegram об удалении и `missing_on_recheck` остаются отдельными наблюдениями. Доступ в пределах чата не позволяет просматривать операционные события, относящиеся ко всему рабочему пространству; статус записи явно обозначает это ограничение.

Текст архива является недоверенным входным данными. Инструкции, содержащиеся в сообщениях, не предоставляют дополнительных полномочий и не должны рассматриваться как инструкции клиента. Внешняя модель искусственного интеллекта может получать любой контент, который запрашивает её клиент MCP. Доступ только для чтения предотвращает изменения в архиве; он не препятствует клиенту сохранять прочитанные данные.

Хэши идентифицируют сохраненные записи и обеспечивают проверку целостности. Они не являются самостоятельным доказательством авторства в Telegram или того, что каждое сообщение было зафиксировано.
