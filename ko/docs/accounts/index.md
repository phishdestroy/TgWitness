# 계정 연결

Canonical page: https://phishdestroy.github.io/TgWitness/ko/docs/accounts/

하나의 작업 공간에는 하나의 계정과 해당 계정의 기록부, 그리고 서명 키가 포함됩니다.

## 로그인 방법 선택

**계정을** 개설하고, 작업 공간을 추가한 다음 연결 설정을 엽니다. 관찰을 위해 전용 계정을 사용하십시오.

- **QR 코드:** 텔레그램의 기기 설정에서 이 코드를 스캔하고 새 로그인을 확인하세요.
- **전화번호:** 번호를 입력하고, 텔레그램에서 전송한 인증 코드를 입력한 후, 2단계 인증이 활성화된 경우 해당 비밀번호를 입력하십시오.
- **세션 가져오기:** 지원되는 세션이나 본인 소유의 텔레그램 데스크톱 데이터를 가져옵니다.

내장된 API 프로필을 선택하거나 직접 API ID와 해시를 입력하세요. API 프로필은 클라이언트를 식별하는 용도로 사용되며, 계정에 로그인하거나 연결을 익명으로 만드는 기능은 제공하지 않습니다.

**먼저 프록시가 필요하신가요?**

로그인하기 전에 [연결 경로를 선택하고 테스트해 볼](https://phishdestroy.github.io/TgWitness/ko/docs/proxies/) 수 있습니다. 각 계정마다 고유한 경로가 있습니다.

## 관찰 대상 선택

1. 소스 목록을 열고 필요한 채팅, 그룹 또는 채널을 선택하세요.
2. 관찰을 시작하기 전에 미디어를 포함한 수집 설정을 검토하십시오.
3. 수집기를 시작하고 연결 상태 및 최근 활동을 확인하십시오.

해당 계정은 소스에 접근할 수 있어야 합니다. 역할에 따라 볼 수 있는 이벤트가 다르며, 기록부는 해당 계정이 수신한 내용을 반영합니다.

계정 전체에 걸친 사건을 조사하려면 **‘소스(Sources)’ → ‘관찰 범위(Observation scope)’ → ‘조사 모드**(**Investigation mode**)’를 선택하고, 설정을 검토한 후 **‘범위 저장(Save scope)’을** 누르십시오. [전체 조사 안내서는](https://phishdestroy.github.io/TgWitness/ko/docs/cases/) 표시되는 모든 채팅 유형, 과거 기록, 사용자 프로필, 채팅 간 참조 및 증거 인계 과정을 다룹니다.

## 전체 경로 확인

사용자가 관리하는 테스트 그룹에서 다른 계정을 통해 고유한 메시지를 보내고, 이를 수정하고 삭제해 보십시오. 저널에서 이 세 가지 이벤트가 모두 기록되었는지 확인한 후, 기록을 [내보내고 검증하십시오](https://phishdestroy.github.io/TgWitness/ko/docs/exports/).

'연결됨' 상태는 연결이 성공적으로 이루어졌음을 나타냅니다. 캡처된 테스트 메시지는 특정 이벤트가 이 작업 공간에 도달했음을 확인해 줍니다.

## 계정 추가

'계정(**Accounts)**'에서 또 다른 작업 공간을 생성하고 설정을 반복하십시오. 나중에 내보낸 데이터를 식별할 수 있도록 각 계정의 서명 키 지문을 보관해 두십시오.
