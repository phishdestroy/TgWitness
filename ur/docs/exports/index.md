# ایکسپورٹ اور تصدیق کریں

Canonical page: https://phishdestroy.github.io/TgWitness/ur/docs/exports/

ایک دستخط شدہ ریکارڈ شیئر کریں جسے کوئی اور چیک کر سکے۔

حوالہ برقرار رکھیںدستخط شدہ ZIP برآمد کریںموصول کنندہ تصدیق کرتا ہے

دستخطوں اور چیک پوائنٹس کے بارے میں نئے ہیں؟ [ایک نمونہ ریکارڈ میں تبدیلی کریں](https://phishdestroy.github.io/TgWitness/ur/docs/concepts/#chain) اور دیکھیں کون سی چیکیں اسے شناخت کرتی ہیں۔

کیا آپ ایک کاپی کلیکٹر سے دور محفوظ کرنا چاہتے ہیں؟ [S3 سیٹ اپ](https://phishdestroy.github.io/TgWitness/ur/docs/exports/#s3)، [آبجیکٹ لاک](https://phishdestroy.github.io/TgWitness/ur/docs/exports/#s3-retention) یا [تصدیق شدہ بازیابی](https://phishdestroy.github.io/TgWitness/ur/docs/exports/#s3-restore) پر جائیں۔

## ایک قابلِ اعتماد حوالہ محفوظ رکھیں

کلیکٹر کے باہر ورک اسپیس کی پبلک کی فنگر پرنٹ محفوظ کریں۔ کلیکشن کے دوران، دستخط شدہ چیک پوائنٹس کو کہیں اور محفوظ رکھیں یا ایک [آزاد گواہ](https://phishdestroy.github.io/TgWitness/ur/docs/witness/) استعمال کریں۔ یہ حوالہ جات وصول کنندہ کو کلید اور پہلے کے جرنل کی حد کی تصدیق کرنے کی اجازت دیتے ہیں۔

## دستیخط شدہ ZIP ڈاؤن لوڈ کریں

**ایکسپورٹس** کھولیں اور ایک دستخط شدہ ثبوت ZIP بنائیں۔ اس میں ورک اسپیس جرنل اور ایک دستخط شدہ فائل مینفیسٹ شامل ہیں۔ پینل فلٹرز اس مکمل جرنل ایکسپورٹ کو محدود نہیں کرتے: شیئر کرنے سے پہلے مواد کا جائزہ لیں۔

علیحدہ HTML اور CSV ڈاؤن لوڈز مطالعہ اور تجزیے کے لیے مفید ہیں۔ دستخط شدہ ZIP کو قابل تصدیق اصل کے طور پر محفوظ رکھیں؛ الگ HTML یا CSV فائل میں کوئی خود مختار دستخط نہیں ہوتا۔

## TgWitness کی ایک معتبر کاپی کے ساتھ تصدیق کریں

انسٹال شدہ پروجیکٹ ماحول میں، مثال کے فنگر پرنٹ اور فائل راستوں کو تبدیل کریں:

```
python -m tgwitness.verify evidence.zip --fingerprint TRUSTED_PUBLIC_KEY_SHA256 --checkpoint retained-checkpoint.json
```

جب دونوں حوالہ جات پاس ہو جائیں تو نتیجہ `key_pinned: true` اور `checkpoint_checked: true` رپورٹ کرتا ہے۔ تصدیقی نتیجہ کو اصل آرکائیو کے ساتھ محفوظ رکھیں۔ برقرار رکھا گیا چیک پوائنٹ برآمد کے حد کے اندر یا اس سے پہلے ہونا چاہیے۔

## نتیجہ سمجھیں

- **دیانتداری:** ریکارڈ شدہ تاریخ اور برآمد شدہ فائلیں اپنے دستخطوں سے مطابقت رکھتی ہیں۔
- **ابتدائی مشاہدہ:** ایک بیرونی چیک پوائنٹ آپ کو ایکسپورٹ کو پہلے سے محفوظ شدہ جرنل پری فکس کے ساتھ موازنہ کرنے کی اجازت دیتا ہے۔
- **ڈیلیوری:** ایک کنٹرولڈ سینڈ → ایڈیٹ → ڈیلیٹ ٹیسٹ مخصوص واقعات کو ریکارڈ شدہ اندراج سے تصدیق کرتا ہے۔

ایک درست دستخط اس بات کا ثبوت نہیں کہ ہر ٹیلیگرام واقعہ موصول ہوا، کہ ماخذ نے سچ کہا یا کہ جمع کرنے والے کی گھڑی درست تھی۔

## S3 آف سائٹ کاپی مرتب کریں

اپنے چل رہے ورک اسپیس میں **Exports → Off-site copy** کھولیں۔ یہ اختیاری خصوصیت AWS S3 اور دیگر S3 مطابقت رکھنے والی خدمات کے ساتھ کام کرتی ہے۔ یہ جرنل کے حصے، محفوظ شدہ تصاویر اور فائلیں، چیک پوائنٹس ان کے ٹائم اسٹیمپ جوابات کے ساتھ، اور مکمل چیٹ ایکسپورٹس کی کاپی بناتی ہے۔ ہر شے کو اپ لوڈ سے پہلے کلیکٹر پر '`AES-256-GCM`' کے ساتھ انکرپٹ کیا جاتا ہے۔

آن لائن ڈیمو میں وہی کنٹرولز دکھائے جاتے ہیں جن میں اپ لوڈز غیر فعال ہیں۔ ذخیرہ کے کریڈنشلز صرف اپنے چل رہے ورک اسپیس میں درج کریں۔

[![مکمل آف سائٹ کاپی پینل: اینڈ پوائنٹ، خطہ، بکیٹ، رسائی کیز، شیڈول، آبجیکٹ لاک اور ریکوری کی کنٹرولز](https://phishdestroy.github.io/TgWitness/assets/off-site-copy.png)](https://phishdestroy.github.io/TgWitness/assets/off-site-copy.png)

مکمل پینل جدید اختیارات کے ساتھ کھولا گیا ہے۔ کوئی اسٹوریج کی تفصیلات دکھائی نہیں گئی ہیں۔

| میدان | کیا داخل کرنا ہے |
| --- | --- |
| اِینڈ پوائنٹ | اسٹوریج سروس کا یو آر ایل، بغیر بکیٹ پاتھ یا کریڈینشلز کے۔ فرضی مثال: `https://s3.example.invalid` |
| علاقہ | آپ کے فراہم کنندہ کی جانب سے مطلوبہ خطہ۔ ایپلیکیشن کا ڈیفالٹ `us-east-1` ہے۔ |
| بکٹ | ایک موجودہ بکیٹ جس تک آپ رسائی حاصل کر سکتے ہیں۔ خیالی مثال: `example-case-backup` |
| بکٹ میں فولڈر | آبجیکٹ کا پری فکس؛ ڈیفالٹ `tgwitness`۔ ایپلیکیشن اس ورک اسپیس کی سائننگ کی فنگر پرنٹ سے ماخوذ ایک پری فکس شامل کرتی ہے۔ |
| ایکسیس کی آئی ڈی / خفیہ ایکسیس کلید | دونوں اسٹوریج کی کریڈینشلز ایک ساتھ درج کریں۔ یہ ورک اسپیس والٹ میں محفوظ ہو جاتی ہیں۔ بعد کی محفوظ کاریوں میں دونوں کو خالی چھوڑیں تاکہ محفوظ شدہ جوڑا برقرار رہے۔ |
| Path-style پتے | فراہم کنندہ کے مطابق، فعال ہونے پر `endpoint/bucket` استعمال کریں، یا غیر فعال ہونے پر `bucket.endpoint`۔ |
| کاپی وقفہ | 1 سے 1,440 منٹ تک؛ ڈیفالٹ 5 منٹ۔ شیڈول شدہ کاپیوں کے لیے ایپلیکیشن کا چلنا ضروری ہے۔ |
| آبجیکٹ لاک برقرار رکھنا | ایک بکیٹ کے لیے برقرار رکھنے کے دن اور موڈ جو Object Lock کو سپورٹ کرتا ہے۔ صفر دن بکیٹ کی ڈیفالٹ برقرار رکھنے کی مدت کو برقرار رکھتا ہے۔ |

1. مقصد اور اسناد درج کریں۔ تیاری کے دوران **آف سائٹ کاپی کو** غیر منتخب حالت میں چھوڑیں، پھر **آف سائٹ کاپی محفوظ کریں کا** انتخاب کریں۔
2. **ٹیسٹ کنکشن** منتخب کریں۔ یہ ایک خفیہ شدہ ٹیسٹ آبجیکٹ اپ لوڈ کرتا ہے اور اسٹوریج کے جواب کی جانچ کرتا ہے۔
3. **ڈاؤن لوڈ انکرپشن کلید** منتخب کریں۔ اس فائل کو کلیکٹر سے الگ رکھیں؛ یہ بازیابی کے لیے ضروری ہے۔
4. **آف سائٹ کاپی رکھنے والا** چیک باکس فعال کریں اور دوبارہ محفوظ کریں۔ دستی عمل کے لیے **ابھی کاپی** منتخب کریں، یا شیڈول کو چلتا ہوا چھوڑ دیں۔

**یہ کیا نہیں کرتا** یہ اسٹوریج بکیٹ نہیں بناتا۔ شیڈول شدہ اپلوڈز ایپلیکیشن کے بند ہونے پر رک جاتے ہیں۔

## رکارڈ برقرار رکھنے اور نقل کی پیش رفت کی جانچ کریں

**مزید اختیارات** کے تحت، برقرار رکھنے کے دن منتخب کریں اور جب آپ کا بکیٹ Object Lock کو سپورٹ کرتا ہو تو `GOVERNANCE` یا `COMPLIANCE` منتخب کریں۔ TgWitness اپ لوڈ کیے گئے آبجیکٹ کے برقرار رکھنے کے موڈ اور ڈیڈ لائن کو دوبارہ پڑھتا ہے۔ اسٹیٹس رپورٹ تصدیق، برقرار نہ رکھنے کی صورت یا چیک کی ناکامی کی اطلاع دیتی ہے؛ صرف کامیاب اپ لوڈ برقرار رکھنے کی تصدیق نہیں ہے۔

پینل آخری پاس، اشیاء کی تعداد، منتقل شدہ بائٹس، نقل شدہ جرنل کی حد اور کسی بھی خرابی کی اطلاع دیتا ہے۔ غیر موجود یا تبدیل شدہ مقامی میڈیا کی اطلاع دی جاتی ہے اور اگلی پاس میں دوبارہ کوشش کی جاتی ہے۔ اس میڈیا کے بعد فائلیں، چیک پوائنٹس اور قطار میں شامل برآمدات اب بھی نقل کی جا سکتی ہیں۔

اپ لوڈز ورک اسپیس کے Direct، SOCKS5 یا HTTP راستے استعمال کرتے ہیں۔ MTProxy کے ذریعے S3 کاپینگ دستیاب نہیں ہے؛ ایپلیکیشن براہِ راست کنکشن پر واپس نہیں جاتی۔

**یہ کیا نہیں کرتا** یہ صرف اس لیے فراہم کنندہ کو Object Lock نافذ کرنے پر مجبور نہیں کرتا کہ اپ لوڈ قبول کر لیا گیا تھا۔

## بحالی کی کلید کو الگ رکھیں

ڈاؤن لوڈ کردہ JSON میں ڈی کرپشن کلید، منزل کی ترتیبات، ورک اسپیس آبجیکٹ پری فکس اور سگننگ کلید کا فنگر پرنٹ شامل ہیں۔ اس میں S3 تک رسائی کے کریڈنشلز شامل نہیں ہیں: بحالی کے لیے علیحدہ کریڈنشلز درکار ہیں جن میں بکٹ کو پڑھنے کی اجازت ہو۔

اگر آپ اینڈ پوائنٹ، بکیٹ یا فولڈر پری فکس تبدیل کرتے ہیں تو کی فائل دوبارہ ڈاؤن لوڈ کریں تاکہ اس کی منزل کی ترتیبات میل کھائیں۔ ایپلیکیشن نئی منزل پر مقامی طور پر محفوظ شدہ جرنل، فائلوں اور چیک پوائنٹس کی ایک نئی کاپی شروع کرتی ہے۔ مکمل چیٹ ایکسپورٹس جو پہلے ہی مقامی اپ لوڈ قطار سے ہٹا دی گئی ہیں، اپنی سابقہ منزل پر ہی رہتی ہیں۔

**یہ کیا نہیں کرتا** یہ برآمد شدہ کلید کے بغیر نقل کو ڈیکرپٹ نہیں کرتا۔ اسٹوریج تک رسائی کی اسناد اس کلید کا متبادل نہیں ہو سکتیں۔

## دوسری مشین پر بحال کریں اور تصدیق کریں

TgWitness کی ایک معتبر تنصیب، ڈاؤن لوڈ کی گئی کی JSON، پڑھنے کی اجازت کے ساتھ اسٹوریج کی اسناد، اور ایک خالی آؤٹ پٹ ڈائریکٹری استعمال کریں۔ نیچے دیے گئے فرضی اسناد کے پلیس ہولڈرز کو تبدیل کریں۔

### ونڈوز پاور شیل

```
$env:TGWITNESS_S3_ACCESS_KEY = 'YOUR_READ_ACCESS_KEY'
$env:TGWITNESS_S3_SECRET_KEY = 'YOUR_READ_SECRET_KEY'
python -m tgwitness.replica restore --key-file tgwitness-replica-key.json --out restored-evidence
```

### لینکس / میک او ایس

```
export TGWITNESS_S3_ACCESS_KEY='YOUR_READ_ACCESS_KEY'
export TGWITNESS_S3_SECRET_KEY='YOUR_READ_SECRET_KEY'
python -m tgwitness.replica restore --key-file tgwitness-replica-key.json --out restored-evidence
```

ڈاؤن لوڈز اور ڈی کرپٹ شدہ اشیاء نجی عارضی اسٹوریج میں رہتی ہیں جب تک کہ پورا جرنل، برقرار رکھے گئے چیک پوائنٹس اور محفوظ شدہ میڈیا ہیشز اور سائزز چیک نہ کیے جائیں۔ غیر محفوظ راستے، متصادم جرنل کے حصے اور چیک پوائنٹ سے چھوٹا جرنل مسترد کر دیے جاتے ہیں۔ ناکام تصدیق بحال شدہ کوئی فائلیں شائع نہیں کرتی۔

کامیاب بازیافت کے نتیجے میں کاپی میں موجود مواد کے لیے `events.jsonl`، `media/`، `checkpoints/` اور `exports/` تیار ہوتے ہیں۔ بازیافت شدہ مواد کے ساتھ کمانڈ کے JSON نتیجے کو محفوظ رکھیں۔

**یہ کیا نہیں کرتا** یہ ان مشاہدات کی دوبارہ تشکیل نہیں کرتا جو کبھی جرنل تک نہیں پہنچے یا کسی آزادانہ طور پر محفوظ کردہ چیک پوائنٹ یا گواہ کی جگہ نہیں لیتا۔
