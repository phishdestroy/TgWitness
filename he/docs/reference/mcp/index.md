# MCP לקריאה בלבד

Canonical page: https://phishdestroy.github.io/TgWitness/he/docs/reference/mcp/

חבר לקוח MCP לסביבות עבודה וצ'אטים נבחרים עם גישה מוגבלת בזמן וניתנת לביטול.

**עיקרי כרגע:** יש להשתמש ב-checkout מהמקור; גרסת התצוגה המקדימה הניידת 0.7.0 קדמה לתכונה זו.

[מדריך לתהליך העבודה](https://phishdestroy.github.io/TgWitness/docs/archive/) · [ויקי](https://github.com/phishdestroy/TgWitness/blob/main/docs/wiki/Archive-and-Integrations.md)

התקן את השרת האופציונלי מתוך ספריית הפרויקט של TgWitness:

```
python -m pip install '.[mcp]'
```

בלוח הבקרה, פתחו את **"Integrations" → "MCP"**. תנו שם לחיבור, בחרו את סביבות העבודה והצ'אטים שלו, ובחרו תאריך תפוגה. העתיקו את אסימון הארכיון פעם אחת; לא ניתן לאחזר אותו מאוחר יותר. בטלו אסימונים שאבדו והנפיקו אסימונים חלופיים. אסימוני הלוח ו אמצעי הזיהוי של Telegram אינם אמצעי הזיהוי של MCP.

## חבר לקוח

הפאנל מייצר את ה-`.vscode/mcp.json` עבור **ה-VS Code Local harness** באמצעות [התצורה המתועדת](https://code.visualstudio.com/docs/agents/reference/mcp-configuration) שלו. שמור את הקובץ שהורדת במיקום זה, הפעל **את MCP: List Servers**, והפעל את TgWitness. VS Code מבקש את האסימון באמצעות הזנת סיסמה. קובץ ה- JSON שהורדת מכיל הפניה לשורת הפקודה, ולא את האסימון עצמו. השתמש בקובץ ההפעלה של Python מתוך הסביבה שבה מותקן התוסף MCP.

ללקוחות אחרים של stdio, הפעל:

```
python -m tgwitness.mcp_server --api-url http://127.0.0.1:8787
```

הגדר את `TGWITNESS_ARCHIVE_TOKEN` בסביבה המוגנת של הלקוח. אין להכניס אותו לפרמטרים של פקודות או לכתובות URL. הגשר קורא דרך ה-API המורשה של הארכיון בלוח הבקרה; אין לו גישה ישירה למסד הנתונים. Stdout מעביר רק הודעות MCP.

עבור לקוחות מרוחקים, הפעל את השירות לצד הפאנל:

```
python -m tgwitness.mcp_server --transport streamable-http \
  --api-url http://127.0.0.1:8787 --port 8766 \
  --public-url https://archive.example.org/mcp
```

העבר את `/mcp` דרך פרוקסי הפוך ב-HTTPS אל `127.0.0.1:8766/mcp`, תוך שמירה על כותרת ה-`Authorization: Bearer …`. השבת את רישום כותרות האישור וגופי הבקשות/התגובות. בצע קישור מעבר ל-loopback רק בעת הצורך, באמצעות `--host` ו-`--public-url`. נקודת הקצה משתמשת ב-Streamable HTTP מתוך ה [-SDK הרשמי של MCP ב-Python](https://github.com/modelcontextprotocol/python-sdk). הוא תומך באישורי נושא שהוגדרו במפורש, ולא בגילוי OAuth; לקוחות הדורשים OAuth בלבד אינם נתמכים.

**בדיקת הפרוטוקול והגישה** מפעילות לקוח MCP אמיתי ומציגות רשימת כלים. התהליך אינו מוריד הודעות. לצורך בדיקה מרחוק, שרת ה-MCP הנבחר מקבל את אסימון הארכיון. יש להגדיר רק שרת שאתה מפעיל או סומך עליו בהיקף זה.

## היקף ותוצאות

כלים זמינים: `list_workspaces`, `list_chats`, `search_messages`, `get_message_versions`, `get_message_context`, `get_journal_event` ו- `get_capture_status`. אין פעולות טלגרם, שינויי תצורה או כלים לייצוא המוני. בכל קריאה מתבצעת בדיקה חוזרת של הגישה לסביבת העבודה/לצ'אט; אישורים שפג תוקפם או שבוטלו מפסיקים לפעול. המגבלות הן 60 בקשות API לדקה לכל אישור, 50 רשומות לדף, תגובה בגודל 64 KiB, ומועד אחרון של שמונה שניות ל-API.

תוצאות ההודעות כוללות סביבת עבודה, מזהי צ'אט/הודעה, רצף אירועים, חתימת hash שמורה, וקישור לפאנל. על הצופה הפותח את הקישור להיות בעל פאנל מורשה משלו במסגרת הפעלה. אובייקטים גולמיים של Telegram, חתימות hash לגישה, הפניות לקבצים, חומר מהפעלה, ומפתחות אינם מופיעים. החיפוש בוחן את טקסט ההודעה, ולא שדות גולמיים. הטקסט מוגבל וקיצוצים מסומנים. עריכות, הודעות מחיקה של טלגרם ו- `missing_on_recheck` נשארים תצפיות נפרדות. גישה בהיקף הצ'אט אינה יכולה לראות אירועים תפעוליים ברמת סביבת העבודה; מצב הלכידה מסמן במפורש מגבלה זו.

טקסט בארכיון הוא קלט שאינו אמין. הוראות בתוך הודעות אינן מעניקות היקף נוסף ואסור להתייחס אליהן כהוראות של הלקוח. מודל AI חיצוני עשוי לקבל כל תוכן שהלקוח MCP שלו מבקש. גישה לקריאה בלבד מונעת שינויים בארכיון; היא אינה מונעת מלקוח לשמור את הנתונים שהוא קורא.

ה-hash מזהים את הרשומות השמורות ומאפשרים בדיקות תקינות. הם אינם מוכיחים באופן עצמאי את זהות מחבר ההודעה ב-Telegram או שכל ההודעות נלכדו.
