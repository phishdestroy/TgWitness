# Работа с архивом

Canonical page: https://phishdestroy.github.io/TgWitness/ru/docs/archive/

Найдите сообщение. Проверьте источник. Соберите доказательства.

Эти инструменты доступны в текущей основной ветке. Портативная предварительная версия 0.7.0 выпущена раньше; для работы с ней используйте выгрузку исходного кода.

01**Включить историю**

Загрузите прошлые сообщения из ваших подключенных источников в рабочую область.

02**Следите за источниками**

Выполните поиск по архиву и откройте сохраненное сообщение, соответствующее каждому результату.

03**Обеспечьте четкую передачу информации**

Сохраняйте результаты анализа отдельно и экспортируйте подписанные доказательства вместе с ними.

Зафиксированные записи, распознанный текст и выводы аналитиков четко разграничены.

## Загрузить предыдущие сообщения

1. Откройте **Источники → Чаты в охвате**, проверьте включённые чаты и начните наблюдение.
2. Выберите **«Загрузить полную историю**». При запуске используется список источников, выбранный на данный момент.
3. По мере необходимости используйте **«Историю пауз»** и **«Историю продолжений**». После перезапуска явно возобновите работу.
4. Проверьте результаты по каждому источнику и очередь вложений. Сохраните подписанный отчет о ходе работы вместе с экспортом доказательств.

Это заполняет рабочую область доступными сообщениями. Экспорт в формате HTML/JSON по каждому чату — это отдельная операция. [История и сведения о восстановлении](https://phishdestroy.github.io/TgWitness/ru/docs/reference/history/).

## Сначала выполните поиск, а потом принимайте решение об использовании ИИ

1. Для локального поиска откройте **Журнал**. Выберите рабочую область и используйте фильтры по источнику и времени.
2. Найдите фразу или домен. Откройте соответствующую запись и её сохранённые версии.
3. Для анализа с помощью ИИ администратор включает и настраивает поставщика в разделе **Интеграции**. Откройте **Спросить архив** и выберите чаты и период. Перед подтверждением запроса проверьте раздел **Данные, отправляемые в модель** и снимите отметки с ненужных выдержек.
4. Проверьте полученные ссылки. Сохраните ответ в виде отчета и добавьте свои правки или заметки.

Поиск осуществляется локально без использования ИИ. Аналитические отчеты содержат ссылки на источники и историю изменений; они хранятся отдельно от подписанного журнала. [Настройка провайдера и отчеты](https://phishdestroy.github.io/TgWitness/ru/docs/reference/analysis/).

**Какой токен доступа куда вводить?**

Доступ к панели предоставляется лицам, занимающимся рассмотрением дела. Участники программы MCP получают отдельные токены доступа к архиву только для чтения. Приемник веб-хуков использует собственный секретный ключ HMAC. Никому не требуется файл сеанса Telegram.

[Предоставьте доступ к панели](https://phishdestroy.github.io/TgWitness/ru/docs/access/) или [настройте клиент MCP](https://phishdestroy.github.io/TgWitness/ru/docs/reference/mcp/).

## Предоставление источников и выводов

Храните проанализированный отчет вместе с ZIP-архивом подписанных доказательств. Отчет объясняет ваше толкование источников; ZIP-архив позволяет получателю сверить сохраненную запись с независимым надежным отпечатком и контрольной точкой.
