# Выберите метод сбора

Начните с нужного вам результата. Эти рабочие процессы сохраняют разные наблюдения; выбор одного из них не приводит к автоматическому запуску другого и не изменяет подключение аккаунта.

| Цель | Где | Результат | Использование аккаунта |
| --- | --- | --- | --- |
| Поделиться уже сохраненными материалами | Экспорт → Сохраненные наблюдения | Архив подписанных журналов, отчёт в читаемом виде или сжатая передача данных | Отсутствие просмотров в Telegram; наблюдение может продолжаться |
| Сохранение будущих изменений | «Чаты» → Выберите, затем нажмите «Начать наблюдение» | Доставленные сообщения, версии и уведомления об удалении в рабочей области | Управление аккаунтом во время работы |
| Добавление истории переписки в рабочую область | «Дополнительные инструменты» → «Источники» → «Чаты в области действия» → «Полная история» | Текущие видимые сообщения, медиафайлы и доступные «Недавние действия» в подписанном журнале | Продолжайте наблюдение; выберите «Стандартный API» или «Takeout» |
| Создайте отдельный снимок аккаунта | Экспорт → Аккаунт Telegram | Выбранные чаты, файлы и дополнительные данные аккаунта в отдельном подписанном архиве | Работает параллельно с наблюдением; источники наблюдения не влияют на этот выбор |
| Экспорт одного чата | Чаты → Экспорт чата | Подписанная выбранная история и контекст, при необходимости разделённые между подходящими аккаунтами | Каждый выбранный аккаунт должен находиться в неактивном состоянии и уже иметь доступ |
| Защита важного аккаунта | [Доверенный клиент Telegram](TRUSTED-LIVE.md), установленный локально, или [официальный веб-клиент](OFFICIAL-WITNESS.md) в GitHub Actions | Видеозаписи и подписанные наблюдения за тем, что отображает официальный клиент Telegram | TgWitness самостоятельно не выполняет вызовы API Telegram и не импортирует сеансы; запросы выполняет официальный клиент; предварительный просмотр |
| Сохранение сеанса официального клиента | Дополнительные инструменты → Дополнительные функции → Независимый захват → Trusted Live | Защищённое видео, сохраненный исходный JSON и артефакты непрерывности | Отдельный рекордер и ручной вход в официальный клиент; предварительный просмотр |
| Запись с указанием происхождения в рамках рабочего процесса GitHub | Экспорт → Другие форматы и инструменты сбора данных → Сбор данных с помощью GitHub Actions | Зашифрованная передача данных и подтверждение рабочего процесса | Отдельный исполняющий модуль и явно авторизованный сеанс; предварительный просмотр |

<a id="existing-observations-and-fresh-reads"></a>
## Существующие наблюдения и новые данные

Архив ZIP с доказательствами экспортирует сохраненный журнал в пределах фиксированной границы. Он не запрашивает Telegram повторно и может быть подготовлен, пока сбор данных продолжается. В читаемом отчёте или сокращённом архиве можно выбрать поднабор данных; полный архив ZIP с доказательствами сохраняет задокументированный объем полного журнала.

Экспорт истории и аккаунтов/чатов теперь считывает данные из Telegram. В них отображается то, к чему выбранный аккаунт имеет доступ во время данного запуска, а не атомарная реконструкция прошлого. Изменения и удаления, которые никогда не подвергались наблюдению, могут быть недоступны.

<a id="one-acquisition-per-account"></a>
## Один цикл сбора данных на один аккаунт

Один цикл сбора полной истории или экспорт аккаунта/чата использует слот сбора данных данного аккаунта. Наблюдение в режиме реального времени продолжается параллельно с этим процессом. Элементы управления паузой работают независимо; запуск сбора данных не приводит к автоматической приостановке наблюдения. Отдельные рабочие области аккаунтов могут функционировать одновременно, имея отдельные идентификаторы и права доступа.

Во время загрузки полной истории обработчики в режиме реального времени сохраняют доставленные изменения. Последующее дозагрузка или чтение истории возвращает текущее состояние каждого сообщения. Сравнение сохраненных версий позволяет сопоставить данные наблюдений, зафиксированные при каждом проходе.

Правила приостановки, возобновления и идентификации аккаунта описаны в разделах [История](HISTORY.md), [Экспорт аккаунта](ACCOUNT-EXPORT.md) и [Распределенный экспорт](DISTRIBUTED-EXPORT.md).

<a id="official-client-capture"></a>
## Захват официальным клиентом

[Trusted Live](TRUSTED-LIVE.md) использует явно выбранный коннектор своего регистратора. Настройки сбора данных через API не превращают задачу MTProto в запись официального клиента. Нативный экспорт осуществляется вручную; данный предварительный просмотр сохраняет JSON без связанного с ним дерева вложений. Запись, содержащая только видео, не имеет структурированных идентификаторов сообщений. Гибридное сравнение требует аннотаций оператора, привязанных к сохраненным кадрам.

Аннотации непрерывности отображаются в отдельном окне чата. Отсутствующие идентификаторы или ответы являются наблюдениями, требующими расследования; об удалении сообщается на основании уведомлений Telegram об удалении. Технологии WARP и регулирования темпа снижают нагрузку на сервер, а Telegram определяет ограничения для аккаунтов.

<a id="read-the-result-before-handing-it-over"></a>
## Ознакомьтесь с результатом перед его передачей

Проверьте выбранную область источника, захваченные версии, время источника и наблюдения, результаты вложений и интервалы восстановления. Сверьте архив с достоверными исходными данными для его режима: ключ сборщика или свидетеля, сохраненная контрольная точка, внешние временные квитанции и соответствующие доказательства сбора данных из GitHub или Intel TDX. Результат должен указывать, какие проверки сбора, целостности, непрерывности и времени прошли успешно.

См. раздел [Текущие возможности и квалификация](STATUS.md) для ознакомления с тем, что было протестировано.
