# 稼働を継続してください

Canonical page: https://phishdestroy.github.io/TgWitness/ja/docs/server/

再起動後もコレクターが利用可能であり、そのデータが損なわれないようにしてください。

## 起動方法を選択してください

ネイティブインストールを行う場合は、[deploy/](https://github.com/phishdestroy/TgWitness/blob/main/deploy/README.md) ディレクトリ内の[ラン](https://phishdestroy.github.io/TgWitness/ja/docs/start/)チャーおよびサービスのサンプルをご利用ください。Docker を使用する場合は、Docker Compose をインストールし、プロジェクトディレクトリから実行してください：

```
docker compose up -d --build --wait
docker compose exec tgwitness cat /data/panel-token.txt
```

デフォルトのパネルは、ホストのループバックアドレス、ポート8787でリスニングしています。ローカルで、またはSSHトンネル経由で開いてください。2番目のコマンドで取得したトークンを使用して、パネルのロックを解除してください。

## データディレクトリ全体を保持してください

ネイティブインストールでは`data/live`を使用します。Dockerでは永続的な`tgwitness-data`ボリュームを使用します。ジャーナル、アカウントセッション、鍵、および動作状態をまとめて保管してください。署名付きエクスポートは有用な証拠となりますが、インストール全体の完全なバックアップではありません。

1. 一貫性のあるバックアップを作成する前に、データ収集を停止してください。
2. プライベートデータディレクトリ全体を、ホスト外の保護されたストレージにコピーしてください。
3. バックアップを頼りにする前に、隔離された環境での復元テストを行ってください。

## 再起動後にご確認ください

想定されるワークスペースとキー、Telegramへの接続、選択されたソース、および新規メッセージのキャプチャを確認してください。保存されたMTProtoの状態とキャッチアップ機能により、Telegramがまだ保持している更新情報を復元することができます。ただし、有効期限が切れたすべての更新情報や、キャプチャ前に削除された編集内容を復元することはできません。

コンテナの正常性とは、Webサーバーが応答していることを意味します。制御されたメッセージとウィットネスチェックを使用して、データの収集および外部への公開状況を評価してください。

## 意図した内容のみを公開してください

導入リファレンスには、HTTPS の例、パーシステントボリュームのコマンド、更新および復元の手順が含まれています。導入用の Docker コマンドも提供されており、現在の[検証記録](https://phishdestroy.github.io/TgWitness/ja/docs/reference/verification/)には実際にテストされた環境が記載されています。
