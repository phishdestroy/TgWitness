# رسائی اور اجازت نامے

Canonical page: https://phishdestroy.github.io/TgWitness/ur/docs/reference/access/

اکاؤنٹس اور چیٹس کے لیے محدود رسائی فراہم کریں، اجازت نامے منتخب کریں، سیشنز اور آئی پی پتے محدود کریں، اور رسائی واپس لیں۔

[ٹی جی وٹنس](https://github.com/phishdestroy/TgWitness/blob/main/README.md) / [دستاویزات](https://github.com/phishdestroy/TgWitness/blob/main/docs/README.md) · [Getting started](https://phishdestroy.github.io/TgWitness/ur/docs/reference/quickstart/)

![Getting started](https://phishdestroy.github.io/TgWitness/assets/chapter-start.svg)

ایک جائزہ نگار کو ایک چیٹ تک رسائی دیں، ایک تجزیہ کار کو کیس برآمد کرنے کی اجازت دیں، یا ایک آپریٹر کو منتخب اکاؤنٹس پر کنٹرول دیں۔ ہر شخص کو اپنا ٹوکن دیا جاتا ہے۔ مرکزی پینل کا ٹوکن منتظم کے پاس رہتا ہے۔

## دو دائرہ کار، دو مختلف کام

**جمع کرنے کا دائرہ کار** طے کرتا ہے کہ اکاؤنٹ کیا ریکارڈ کرے گا: منتخب چیٹس، ایک ٹیلیگرام فولڈر یا پورا اکاؤنٹ۔ **رسائی کا دائرہ کار** طے کرتا ہے کہ ان ریکارڈ شدہ اکاؤنٹس اور چیٹس میں سے کون سی دوسرا شخص دیکھ اور استعمال کر سکتا ہے۔ رسائی دینے سے کوئی ٹیلیگرام چیٹ شامل نہیں ہوتی، جمع کرنے کا عمل شروع نہیں ہوتا اور ٹیلیگرام اکاؤنٹ کی اجازتیں نہیں ملتیں۔

ایک رسائی منتخب کردہ ورک اسپیسز، ان میں موجود منتخب چیٹس، تمام ورک اسپیسز، یا [اکاؤنٹ گروپ](https://phishdestroy.github.io/TgWitness/ur/docs/reference/accounts/#bulk-import-and-account-groups) کے ہر اکاؤنٹ کو کھول سکتی ہے۔ **تمام ورک اسپیسز، بشمول بعد میں شامل کیے گئے،** مستقبل کے اکاؤنٹس کو بھی شامل کرتے ہیں۔ ایک گروپ کی رسائی بھی بعد میں اس گروپ میں شامل کیے گئے اکاؤنٹس کو شامل کرتی ہے۔ جب کسی کیس کو مخصوص ورک اسپیسز تک محدود رکھنا ہو تو انہیں واضح طور پر منتخب کریں۔

## کسی کو رسائی دیں

1. بطور مرکزی منتظم سائن ان کریں اور **رسائی** کھولیں۔
2. **'کسی کو رسائی دیں**' کے تحت وہ نام درج کریں جو آپ لاگ میں پہچانیں گے۔
3. ورک اسپیسز کا انتخاب کریں اور جہاں ضروری ہو، انفرادی چیٹس کا انتخاب کریں۔
4. منتخب کریں کہ یہ شخص کیا کر سکتا ہے۔ **ویو** ہمیشہ شامل ہوتا ہے۔
5. ضرورت کے مطابق میعاد ختم ہونے کی تاریخ، سائن ان/سیشن کی حدیں اور اجازت یافتہ پتے طے کریں۔
6. **ایکسیس بنانے کے لیے** دبائیں۔ اب ٹوکن کاپی کریں: یہ صرف ایک بار دکھایا جاتا ہے۔
7. پینل کا پتہ اور ٹوکن نجی طور پر بھیجیں۔ وصول کنندہ اس ٹوکن کو معمول کے سائن ان صفحے پر درج کرتا ہے؛ انہیں آپ کے مرکزی پینل کے ٹوکن یا ٹیلیگرام سیشن کی ضرورت نہیں۔

جاری کردہ ٹوکن کے ساتھ پینل کو ایک الگ براؤزر سیشن میں کھولیں اور اسے حوالے کرنے سے پہلے دکھائی دینے والی چیٹس اور مجاز کارروائیوں کی تصدیق کریں۔

## اجازات منتخب کریں

صرف متن پر مبنی عوامی مظاہرے کے لیے، عام ریویوئر رسائی کے بجائے **پبلک شوزکیس** استعمال کریں۔ یہ واضح طور پر منتخب کردہ عوامی چینلز، محفوظ شدہ ترامیم اور حذف شدہ آئٹمز، اور دستخط شدہ اعدادوشمار دکھاتا ہے، جس میں مصنف کے فیلڈز حذف کیے گئے ہیں اور API کی حد پر فائلیں بند ہیں۔ [ایک شوزکیس بنائیں اور اس کی تصدیق کریں](https://phishdestroy.github.io/TgWitness/ur/docs/reference/showcase/)۔

| اجازت | یہ کیا اجازت دیتا ہے |
| --- | --- |
| `view` | اجازت یافتہ چیٹس، حاصل کردہ پیغامات، پروفائلز، فائلیں اور فلٹر شدہ جرنل ریکارڈز پڑھیں۔ ہمیشہ شامل۔ |
| `export` | چٹ ہسٹری اور ڈوزیئرز کی برآمد کی اجازت ہے۔ پورے ورک اسپیس کے شواہد کی برآمد کے لیے پورے ورک اسپیس تک رسائی ضروری ہے۔ |
| `sources` | ماخذ، سنپ شاٹس اور پروفائل کیپچر کا انتظام کریں۔ چیٹ محدود رسائی صرف اجازت یافتہ چیٹس پر عمل کر سکتی ہے؛ اکاؤنٹ بھر میں ماخذ کی دریافت اور دائرہ کار کی ترتیبات بند رہتی ہیں۔ |
| `collect` | کلیکٹر شروع یا روکیں۔ پورے ورک اسپیس تک رسائی درکار ہے کیونکہ کلیکشن اکاؤنٹ کو متاثر کرتی ہے۔ |
| `interact` | رسائی کے دائرہ کار کے اندر سپورٹ شدہ ٹیلیگرام تعاملات انجام دیں۔ چیٹ محدود رسائی اکاؤنٹ بھر لنک پریویوز استعمال نہیں کر سکتی۔ |
| `settings` | جمع کرنے کی ترتیبات، ٹائم اسٹیمپز، نوٹیفیکیشنز، آف سائٹ نقول اور پیرامیٹرز تبدیل کریں۔ پورے ورک اسپیس تک رسائی درکار ہے۔ |
| `account` | ٹیلیگرام میں سائن ان یا سائن آؤٹ کریں اور کنکشن راستے منظم کریں۔ پورے ورک اسپیس تک رسائی درکار ہے۔ |
| `board.read` | صرف مجاز ورک اسپیس اور چیٹس کے اندر کیس بورڈ کے نوٹس پڑھیں۔ |
| `board.write` | بُک مارکس، ہائی لائٹس، سلائسز، تبصرے اور کھولنے/نظرثانی کی حیثتیں شامل کریں۔ اس کے لیے `board.read` بھی درکار ہے۔ |
| `board.manage` | کلیکشنز، ٹیم کی حتمی حیثیتیں اور دیگر شرکاء کے کارڈز کا انتظام کریں۔ بورڈ کو پڑھنے/لکھنے کی بھی ضرورت ہے۔ |

اجازت نامے اور دائرہ کار ایک ساتھ چیک کیے جاتے ہیں۔ کسی اجازت نامے کو چیک کرنے سے دوسری چیٹس نہیں کھلتیں اور نہ ہی چیٹ تک محدود رسائی کے لیے پورے ورک اسپیس میں آپریشن کی اجازت ملتی ہے۔ متوازی ایکسپورٹ کے لیے، رسائی ہر منتخب اکاؤنٹ میں ایکسپورٹ کی گئی چیٹ کو کور کرنی چاہیے۔ جاری کردہ رسائی نئی رسائیاں پیدا نہیں کر سکتی، دوسروں کے سیشنز کا انتظام نہیں کر سکتی یا ایڈمنسٹریٹر کنسول نہیں کھول سکتی۔

### تین مفید ترتیبات

| شخص | دائِرۂ کار | اجازات |
| --- | --- | --- |
| نظرثانی کنندہ | ایک کیس کی ریکارڈ شدہ چیٹس | `view` |
| تجزیہ کار ہینڈ اوور کی تیاری کر رہا ہے | وہ چیٹس جن کی تفتیش اور برآمد کی جائے | `view`، `export`؛ `interact` صرف اس صورت میں شامل کریں جب انہیں ٹیلیگرام کے ذریعے کام کرنا ہو۔ |
| جمع کرنے والا آپریٹر | منتخب شدہ پوری ورک اسپیسز | `view`، `sources`، `collect`؛ صرف ضرورت پڑنے پر `settings` یا `account` شامل کریں |

ایکسیس فارم کے ابتدائی پری سیٹس میں کیس بورڈ بھی شامل ہے: ریویوئر پڑھ سکتا ہے، اینالسٹ پڑھ اور لکھ سکتا ہے، اور آپریٹر اسے منظم کر سکتا ہے۔ پری سیٹس قابل ترمیم رہتے ہیں، اور موجودہ اجازت نامے خود بخود وسعت نہیں پاتے۔ وراثت میں ملنے والے چیٹ دائرہ کار اور برآمدی رازداری کے لیے [کیس بورڈ](https://phishdestroy.github.io/TgWitness/ur/docs/reference/case-board/) دیکھیں۔

## حدود اور سیشنز

| سیٹنگ | یہ کیسے کام کرتا ہے |
| --- | --- |
| متوازی سیشنز | ایک ساتھ چلنے والے سیشنز کو 1–100 تک محدود کریں۔ حد پر پہنچنے پر اگلی سائن ان کو مسترد کر دیں یا سب سے پرانا سیشن ختم کر دیں۔ |
| سائن ان کی اجازت ہے | ٹوکن کے کامیاب استعمال کو صرف سیشنز شروع کرنے تک محدود کریں۔ موجودہ سیشنز صرف اس لیے ختم نہیں ہوتے کہ آخری مجاز سائن ان استعمال ہو چکا ہو۔ |
| معتبر تک | رسائی کے لیے قطعی میعاد ختم۔ میعاد ختم شدہ رسائی سائن ان نہیں کر سکتی اور مزید درخواستیں بھیجنا جاری نہیں رکھ سکتی۔ |
| غیر فعال منٹ | سیشن غیرفعالیت کا ٹائم آؤٹ، 5 منٹ سے 30 دن تک۔ کامیاب درخواستیں اسے بڑھاتی ہیں؛ ایک کھلا پینل پولنگ کے ذریعے خود کو فعال رکھ سکتا ہے۔ |
| مجاز پتے | مخصوص IP پتے یا CIDR سب نیٹس قبول کریں۔ خالی چھوڑیں تاکہ جب تک فرسٹ-سائن-ان بائنڈنگ فعال نہ ہو، کوئی بھی پتہ اجازت یافتہ ہو۔ |
| پہلی سائن ان کے ساتھ منسلک کریں | پہلی کامیاب سائن ان اس رسائی کے لیے مجاز پتے کو طے کرتی ہے۔ |

IP وہ کلائنٹ ایڈریس ہے جو ایپلیکیشن دیکھتی ہے۔ ریورس پراکسی یا ٹنل کے پیچھے، IP قواعد پر انحصار کرنے سے پہلے **Open sessions** میں دکھایا گیا ایڈریس چیک کریں: ورنہ کئی صارفین پراکسی کے ایک ہی ایڈریس کو شیئر کرتے ہوئے دکھائی دے سکتے ہیں۔

## رسائی تبدیل یا واپس لیں

**Granted access** کے تحت کسی اندراج کو اس کا دائرہ کار، اجازت نامے یا حدود تبدیل کرنے کے لیے ترمیم کریں۔ دائرہ کار اور اجازت ناموں میں تبدیلیاں بعد کی درخواستوں پر چیک کی جاتی ہیں، بشمول ان سیشنز کی درخواستوں کے جو پہلے ہی کھلے ہوئے ہیں۔ کسی رسائی کو منسوخ کرنے سے اس کے سیشنز ختم ہو جاتے ہیں اور جاری کردہ ٹوکن ناقابل استعمال ہو جاتا ہے۔ **کھلے سیشنز** منتظم کو یہ بھی اجازت دیتے ہیں کہ وہ پوری رسائی کو منسوخ کیے بغیر ایک انفرادی سیشن کو ختم کر دے۔

محفوظ شدہ برآمدی نقول اپنے خالق، ورک اسپیس، چیٹ کے دائرہ کار اور ضروری اجازتوں کو برقرار رکھتی ہیں۔ جاری کردہ رسائی صرف اپنی نقول کو اس وقت فہرست یا ڈاؤن لوڈ کر سکتی ہے جب وہ اجازتیں اب بھی لاگو ہوں؛ Case Board پر مشتمل نقول کو بھی `board.read` کی ضرورت ہوتی ہے۔ منتظم تمام نقول بازیافت کر سکتا ہے۔ اس میٹا ڈیٹا اور گروپ بنڈلز کے بغیر پرانی نقول صرف منتظم کے لیے ہیں۔ ڈاؤن لوڈ ٹکٹ اور تیار کردہ فائل کے جوابات فائل تیار کرنے کے بعد، اس کے بائٹس بھیجنے سے پہلے رسائی کو دوبارہ چیک کرتے ہیں۔

منسوخی پہلے سے ڈاؤن لوڈ کی گئی فائلوں کو واپس نہیں لا سکتی۔ سائن آؤٹ کرنا، پینل کو لاک کرنا یا سیشن ختم کرنا چل رہے کلیکٹر کو نہیں روکتا۔

## انتظامیہ کیا دیکھ سکتا ہے

نظرثانی کرنے والے اور تجزیہ کار بغیر پروکسی اینڈ پوائنٹس، پول ڈائیگناسٹکس، سرور راستوں یا خام کنکشن کی غلطیوں کے کلیکشن کی پیش رفت وصول کرتے ہیں۔ کنکشن ڈائیگناسٹکس کے لیے پورے ورک اسپیس پر `account` کی اجازت درکار ہے۔ نوٹیفیکیشن پڑھنے، آف سائٹ کاپی اور پیرامیٹر سیٹنگز کے لیے `settings` کی اجازت درکار ہے۔

مکمل براؤزر User-Agent سٹرنگز رسائی کے سیشنز میں برقرار نہیں رکھی جاتیں۔ ایک اپ گریڈ انہیں تبدیل شدہ سیشن کیش سے بھی ہٹا دیتا ہے۔ پینل کے عمل کا لاگ آئی پی پتوں، یو آر ایل کی اسناد اور لیبل شدہ رازوں کو چھپا دیتا ہے۔ مقامی سروس لاگز اور پہلے سے دستخط شدہ جرنل ریکارڈز دوبارہ نہیں لکھے جاتے۔ رسائی کے قواعد اور دستخط شدہ سائن ان ریکارڈز اب بھی کلائنٹ کے پتے کا استعمال کرتے ہیں۔

### اہم کلید کو تبدیل کریں

**استعمال کریں: رسائی → میری حدیں → ایڈمنسٹریٹر کلید دوبارہ جاری کریں**، یا پینل کے چلنے کے دوران ایک منظم تنصیب سے `tgwitness token rotate` چلائیں۔ تمام موجودہ براؤزر سیشنز ختم ہو جائیں گے، بشمول وہ سیشنز جو ساتھی ٹوکنز کے ساتھ کھولے گئے ہوں۔ درخواست کرنے والا براؤزر ایک نیا سیشن وصول کرتا ہے؛ نئی ایڈمنسٹریٹر کلید کو چھپانے سے پہلے محفوظ کریں۔ جاری کردہ ساتھی ٹوکنز الگ سے منسوخ ہونے تک درست رہیں گے۔ `TGWITNESS_TOKEN` استعمال کرنے والی تنصیب کو وہ ماحول کی ترتیبات تبدیل کرنی ہوں گی اور دوبارہ شروع کرنا ہوگا۔

### درخواست اور پروکسی کی حدود

API ہر کلائنٹ IP پر فی منٹ 600 درخواستیں قبول کرتی ہے۔ ایک منٹ کے اندر دس مسترد شدہ تصدیقات ایک نمایاں ٹھنڈا ہونے کا وقت شروع کرتی ہیں، جو ایک سیکنڈ سے لے کر پانچ منٹ تک ہوتا ہے۔ ٹھنڈا ہونے کے بعد ایک ناکام کوشش اس وقت میں اضافہ کرتی ہے؛ بغیر کسی ناکام کوشش کے دس منٹ گزرنے پر اضافہ دوبارہ شروع ہوتا ہے۔ ردیابی کے جواب میں HTTP 429 اور `Retry-After` واپس آتے ہیں۔ حدود میموری میں ہوتے ہیں، جو ایک پینل پراسیس میں ورکنگ اسپیسز کے درمیان شیئر کیے جاتے ہیں؛ دوبارہ شروع کرنے سے یہ صاف ہو جاتے ہیں۔ لائیو اسٹریمز کو فی بیئرر ٹوکن چار اور پینل پراسیس کے لیے 32 تک محدود کیا گیا ہے۔ ایک اسٹریم کھولنے سے بھی API درخواست کا بجٹ استعمال ہوتا ہے۔

درخواست کے باڈیز کو وصول کرنے کی آخری حد 60 سیکنڈ ہے (MCP کے لیے 8 سیکنڈ)۔ ہر ایپلیکیشن نامکمل باڈیز کو 32 درخواستوں اور 64 MiB مخصوص راستے کی اجازت تک محدود کرتی ہے۔ حد سے زیادہ باڈیز 413 کی صورت میں واپس کی جاتی ہیں، وقت ختم ہونے پر 408 کی صورت میں، اور باڈی کی گنجائش ختم ہونے پر 503 کی صورت میں واپس کی جاتی ہے، جس کے ساتھ `Retry-After` بھیجا جاتا ہے۔

آگے بھیجے گئے آئی پی ہیڈرز کو نظر انداز کیا جاتا ہے جب تک کہ اصل TCP پیئر `TGWITNESS_TRUSTED_PROXIES` (کامہ سے جدا شدہ IPs یا CIDRs) سے تعلق نہ رکھتا ہو۔ `TGWITNESS_PROXY_HEADER` کو `x-forwarded-for` یا `cf-connecting-ip` پر سیٹ کریں۔ XFF کو قریب ترین پروکسی سے پہلے والے غیر معتبر پیئر کی طرف ٹریول کیا جاتا ہے۔ غلط یا دہرائے گئے معتبر پتے کا میٹا ڈیٹا مسترد کر دیا جاتا ہے، لہٰذا یہ کسی اجازت یافتہ پراکسی پتے کو وراثت میں نہیں لے سکتا۔ زیرِ انتظام فوری سرنگ مقامی کلاؤڈ فلیئر کنیکٹر پر بھروسہ کرتی ہے؛ اپنے ڈومین کے سیٹ اپ میں مقامی کیڈی پر بھروسہ کیا جاتا ہے۔ براہ راست تعیناتیات بطورِ ڈیفالٹ کسی بھی پروکسی پر بھروسہ نہیں کرتی ہیں۔ اگر آپ خود Uvicorn شروع کر رہے ہیں، تو اس کی پروکسی-ہیڈر پراسیسنگ کو غیر فعال کریں تاکہ یہ باؤنڈری اصل پیئر وصول کر سکے۔

`TGWITNESS_PANEL_ALLOWED_IPS` تمام پینل تک رسائی کو محدود کرتا ہے، بشمول منتظم کے، فہرست شدہ IPs یا CIDRs تک۔ انسٹالر کی روٹنگ-آئیڈنٹیٹی پروب عوامی رہتی ہے اور کوئی اکاؤنٹ ڈیٹا واپس نہیں کرتی۔ الاؤ لسٹ کو فعال کرنے سے پہلے ضروری مقامی انتظامی راستہ شامل کریں۔ ایک منظم تنصیب کا **START-HERE** رہنما سروس کنفیگریشن اور بحالی ہدایات پر مشتمل ہوتا ہے۔

`ws` API سوال منتخب کنندہ کو درخواست کے راستے میں ورک اسپیس کی شناخت کرنی چاہیے؛ نامعلوم، غیر مطابقت پذیر اور نقل شدہ منتخب کنندہ 404 کے ساتھ مسترد کیے جاتے ہیں۔

پینل اسکرپٹس اور اسٹائلز میں SHA-384 سالمیت میٹا ڈیٹا شامل ہوتا ہے۔ ایک امپورٹ میپ ان براؤزرز میں مقامی طور پر درآمد کیے گئے JS ماڈیولز کو بھی کور کرتا ہے جو امپورٹ-میپ سالمیت کی حمایت کرتے ہیں۔ ڈائنامک طور پر تیار کردہ زبان کا جواب الگ ہے۔ یہ چیکس فراہم کردہ صفحے کے حوالے سے اثاثوں کی تبدیلی کا پتہ لگاتے ہیں؛ یہ کسی ایسے سمجھوتہ شدہ سرور پر اعتماد قائم نہیں کرتے جو صفحے اور اس کے ہیشز دونوں کو تبدیل کر سکتا ہے۔

**شروع ہونے کے بعد سے لاگ** عمل کے لاگز کو ہر ورک اسپیس کی جرنل سرگرمی کے ساتھ یکجا کرتا ہے: سائن-ان، انکار، راستے کی تبدیلیاں اور آپریٹر کے اقدامات۔ یہ موجودہ عمل کے لیے ایک ان-میموری کنسول ہے، نہ کہ ہر پیغام کی مستقل کاپی۔ اکثر پیغامات کے واقعات کنسول کو بھرنے کے بجائے جرنل میں ہی رہتے ہیں۔

رسائی جاری کرنا، تبدیل کرنا اور منسوخ کرنا، اور سیشن شروع یا ختم کرنا بھی دستخط شدہ `access.*` جرنل ریکارڈز بناتا ہے۔ ان ریکارڈز میں ٹوکن شامل نہیں کیے جاتے۔ جاری کردہ ٹوکن اور سیشن کی اسناد انکرپٹڈ والٹ میں ہیشز کے طور پر محفوظ رکھی جاتی ہیں۔

****اہم منتظم اور اعتماد کی حد****

The main panel token remains unrestricted. Browser sign-ins with it create sessions subject to the administrator's configured session limits. Scripts sending the main token directly retain full access and are not counted as browser sessions.

This is application-level access control in one installation. All workspaces share the server process; this is not isolation from the host administrator. Keep the main token, Telegram sessions, signing keys and data directory private. A witness token is a separate checkpoint/health credential, not a panel access token.
