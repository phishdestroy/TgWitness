# اختر وكيلًا

Canonical page: https://phishdestroy.github.io/TgWitness/ar/docs/proxies/

أبقِ الحساب متصلاً، وقرر بنفسك ما إذا كان يجوز له أن يُظهر عنوان IP لخادمك.

## اختر وضع IP أولاً

01**إخفاء العنوان**

الوكيل فقط. إن لم يعمل أي وكيل، ينتظر.

02**الاتصال المباشر كملاذ أخير**

يتصل مباشرة بعد مهلة، ويعود إلى وكيل بمجرد أن يعمل أحدها.

03**خادم خلف نفق أو شبكة VPN**

الاتصال المباشر مقبول. لا يُعِدّ شبكة VPN ولا يتحقق منها نيابة عنك.

يحدد المسار نوع الاتصال. ويحدد وضع IP ما إذا كان الاتصال المباشر مسموحًا به أم لا.

## دع المجموعة تتولى إدارة المسار

1. **الحساب ← الإعدادات ← إعدادات الاتصال**.
2. اختر وضع IP و**MTProxy التلقائي**، أو مسارًا ثابتًا.
3. احفظ، ثم **اختبار اتصال Telegram** (يعمل قبل تسجيل الدخول أيضًا).
4. ابدأ الجمع وأرسل لنفسك رسالة اختبار.

تبدأ مساحات العمل الجديدة بـ MTProxy التلقائي مع **إخفاء العنوان**. يجلب المجمّع أربع قوائم عامة، ويفحص الخوادم، ويحتفظ بالجيد منها ويستبدل المعطّل.

## استخدم بروكسي خاص بك

SOCKS5 أو HTTP CONNECT أو رابط وكيل Telegram أو كتالوج مشغّل. أوقف المراقبة مؤقتًا قبل التبديل. أسرار Fake TLS (`ee`…) لا تعمل.

**إعدادات التناوب والمشاركة وإعادة المحاولة**

**المعلمات ← MTProxy التلقائي**: عتبات الفشل، وفترات التهدئة، والتدوير، وعدد الحسابات لكل وكيل. الحد 1 يعني أن الحساب ينتظر بدل المشاركة. قد تتشارك وكلاء مختلفة عنوان IP الخروج نفسه.

## فصل Telegram عن الطلبات الخارجية

MTProxy ينقل Telegram فقط. الطوابع الزمنية والإشعارات والنسخ وفحوص الشيفرة تمر عبر وكيل SOCKS5/HTTP منفصل، أو مسار SOCKS5/HTTP الخاص بالحساب، أو مباشرة إذا سمح الوضع. أو أوقفها.

`TGWITNESS_PROXY_FEED_PROXY` يحدد مسار تنزيل القوائم. لـ[الشاهد](https://phishdestroy.github.io/TgWitness/ar/docs/witness/) إعداداته الخاصة. لا شيء من هذا يمس متصفحك أو شبكة نظامك.
