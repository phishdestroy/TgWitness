# 创建案件看板

Canonical page: https://phishdestroy.github.io/TgWitness/zh/docs/case-board/

将保存的 Telegram 观察记录转化为一个案件，供您的团队共同审查。

“案件看板”将书签、精确文本高亮、已保存的片段以及讨论内容与源参考资料并列保存。一个“集合”为案件提供工作结构；带签名的修订版本记录了团队的开发过程。

## 从消息到案件卡片

1. 在“标准”或“专家”模式下，打开**“调查”→“案件看板”**。为该案件创建一个采集集，并选择其聊天范围。
2. 在**日志**或已保存的聊天中，选择**“添加到案板**”，或选中该记录并按 **B 键**。该卡片将进入“收件箱”；为其设置一个有意义的标题，然后将其移至您的收藏夹。
3. 在已保存的聊天消息中选定一段内容，然后选择**“突出显示”→“板”**以保留精确的引文和消息版本。添加一条注释，说明其重要性。
4. 讨论卡片、分配审核状态，并在需要核查主张时返回其源上下文。使用**“演示”**功能与同事一起浏览采集内容。

## 一次性保存一个有用的范围

在同一聊天中按住 Shift 键点击两条记录以**进行“切片”操作**，选择**“按时间切片**”，或保存当前日志过滤条件。保存前请核对条目数量。重新打开切片以应用其保存的查询；**点击“显示自书签添加以来的记录**”可查看后续添加的内容。

时间切片紧随采集器的观察时间之后。当后续发生更改时，消息 ID 切片可跟随所选消息进行更新。保存的创建边界使收件人能够将原始选择内容与其后续状态进行比较。

## 为每位同事分配相应的角色

**审核员**阅读案板；**分析师**添加卡片和评论；**操作员**还负责管理证据收集及审核决策。工作区和聊天权限适用于卡片、来源上下文及讨论。使用命名访问权限以确保归属清晰。

## 将工作成果整理成可交付成果

可将数据片段导出为带签名的 JSON 格式，或使用 CSV 格式导入电子表格。报告设置可包含书签和数据片段，若选中，还可包含团队评论。请在[“报告工作室](https://phishdestroy.github.io/TgWitness/zh/docs/reports/)”中选择这些内容；保存的数据片段不会自动生成报告。若收件人受限，请使用单独的[移交控制](https://phishdestroy.github.io/TgWitness/zh/docs/handover/)功能。

请参阅[“案件看板”参考](https://phishdestroy.github.io/TgWitness/zh/docs/reference/case-board/)指南，了解经签名的修订、精确引文匹配、选定内容验证及权限设置。
