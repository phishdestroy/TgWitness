# MCP แบบอ่านเท่านั้น

Canonical page: https://phishdestroy.github.io/TgWitness/th/docs/reference/mcp/

เชื่อมต่อไคลเอนต์ MCP กับพื้นที่ทำงานและห้องสนทนาที่เลือกไว้ โดยให้สิทธิ์การเข้าถึงที่มีระยะเวลาจำกัดและสามารถเพิกถอนได้

**เนื้อหาหลักปัจจุบัน:** ใช้การเช็คเอาต์จากแหล่งที่มา; เวอร์ชัน 0.7.0 portable preview ยังไม่มีคุณสมบัตินี้

[คู่มือขั้นตอนการทำงาน](https://phishdestroy.github.io/TgWitness/docs/archive/) · [Wiki](https://github.com/phishdestroy/TgWitness/blob/main/docs/wiki/Archive-and-Integrations.md)

ติดตั้งเซิร์ฟเวอร์แบบเลือกใช้ได้จากไดเรกทอรีโครงการ TgWitness:

```
python -m pip install '.[mcp]'
```

ในแผงควบคุม ให้เปิด **Integrations → MCP** ตั้งชื่อการเชื่อมต่อ เลือก พื้นที่ทำงานและแชท และกำหนดระยะเวลาหมดอายุ คัดลอกโทเค็นการเก็บถาวรเพียงครั้งเดียว เนื่องจากไม่สามารถ เรียกคืนได้ในภายหลัง ยกเลิกโทเค็นที่สูญหายและออกโทเค็นทดแทน โทเค็นในแผงควบคุมและ ข้อมูลรับรอง Telegram ไม่ใช่ข้อมูลรับรอง MCP

## เชื่อมต่อไคลเอนต์

แผงควบคุมจะสร้าง`.vscode/mcp.json` สำหรับ **VS Code Local harness** โดยใช้ [การตั้งค่าที่ระบุไว้ในเอกสาร](https://code.visualstudio.com/docs/agents/reference/mcp-configuration) บันทึกไฟล์ที่ดาวน์โหลดมาไว้ในตำแหน่งนั้น แล้วเรียกใช้ **MCP: List Servers** และเริ่ม TgWitness VS Code จะขอโทเค็นผ่านการป้อนรหัสผ่าน ไฟล์ JSON ที่ดาวน์โหลดมา มีเพียงการอ้างอิงคำสั่ง ไม่ใช่โทเค็น ใช้ไฟล์ Python ที่สามารถเรียกใช้งานได้จาก สภาพแวดล้อมที่ติดตั้ง MCP extra ไว้

สำหรับลูกค้า stdio อื่นๆ ให้รัน:

```
python -m tgwitness.mcp_server --api-url http://127.0.0.1:8787
```

ตั้งค่า `TGWITNESS_ARCHIVE_TOKEN` ในสภาพแวดล้อมที่ได้รับการป้องกันของลูกค้า อย่าใส่ ในอาร์กิวเมนต์คำสั่งหรือ URL บริดจ์จะอ่านผ่าน API การเก็บถาวร ที่ได้รับอนุญาตจากแผงควบคุม; มันไม่มีการเข้าถึงฐานข้อมูลโดยตรง Stdout ส่งเฉพาะข้อความ MCP เท่านั้น

สำหรับลูกค้าที่ทำงานจากระยะไกล ให้เรียกใช้บริการนี้ผ่านแผงควบคุม:

```
python -m tgwitness.mcp_server --transport streamable-http \
  --api-url http://127.0.0.1:8787 --port 8766 \
  --public-url https://archive.example.org/mcp
```

ส่งต่อ `/mcp` ผ่านพร็อกซีแบบย้อนกลับ HTTPS ไปยัง `127.0.0.1:8766/mcp` โดยรักษา ส่วนหัว `Authorization: Bearer …` ไว้ ปิดการบันทึกส่วนหัวการอนุญาต และเนื้อหาคำขอ/การตอบกลับ ให้ผูกการเชื่อมต่อนอกเหนือจาก loopback เฉพาะเมื่อจำเป็น โดยใช้ `--host` และ `--public-url` จุดปลายทางนี้ใช้ Streamable HTTP จาก [MCP Python SDK](https://github.com/modelcontextprotocol/python-sdk) อย่างเป็นทางการ มันสนับสนุนข้อมูลรับรองแบบ bearer ที่กำหนดไว้อย่างชัดเจน ไม่ใช่การค้นพบ OAuth; ลูกค้าที่ต้องการใช้ OAuth เท่านั้นไม่ได้รับการสนับสนุน

**การตรวจสอบโปรโตคอลและการเข้าถึง**จะเริ่มต้นไคลเอนต์ MCP ที่แท้จริงและแสดงรายการเครื่องมือ แต่ไม่ดึงข้อความมา สำหรับการตรวจสอบจากระยะไกล เซิร์ฟเวอร์ MCP ที่เลือกจะรับ โทเค็นอาร์ไคฟ์ ให้กำหนดค่าเฉพาะเซิร์ฟเวอร์ที่คุณดำเนินการเองหรือเชื่อถือได้เท่านั้นในขอบเขตนั้น

## ขอบเขตและผลลัพธ์

เครื่องมือที่มีอยู่: `list_workspaces`, `list_chats`, `search_messages`, `get_message_versions`, `get_message_context`, `get_journal_event` และ `get_capture_status` ไม่มีเครื่องมือสำหรับดำเนินการใน Telegram การเปลี่ยนแปลงการตั้งค่า หรือ เครื่องมือส่งออกข้อมูลแบบกลุ่ม ทุกครั้งที่อ่านจะตรวจสอบสิทธิ์การเข้าถึงพื้นที่ทำงาน/แชทอีกครั้ง; ข้อมูลรับรองที่หมดอายุหรือถูกเพิกถอน จะหยุดทำงานทันที ข้อจำกัดคือ 60 คำขอ API ต่อนาทีต่อข้อมูลรับรอง, 50 รายการต่อหน้า, ขนาดการตอบกลับ 64 KiB และเวลาจำกัด API 8 วินาที

ผลลัพธ์ข้อความรวมถึงพื้นที่ทำงาน (workspace), ID ของการสนทนา/ข้อความ, ลำดับเหตุการณ์, ค่าแฮชที่บันทึกไว้, และลิงก์ไปยังแผงควบคุม (panel) ผู้ดูที่เปิดลิงก์ต้องมีเซสชันแผงควบคุม ที่ได้รับอนุญาตของตนเอง อ็อบเจกต์ Telegram แบบดิบ, ค่าแฮชการเข้าถึง, การอ้างอิงไฟล์, ข้อมูลเซสชัน, และกุญแจจะถูกตัดออก การค้นหาจะตรวจสอบข้อความ ไม่ใช่ฟิลด์แบบดิบ ข้อความถูก จำกัดขอบเขตและส่วนที่ถูกตัดสั้นจะถูกทำเครื่องหมาย การแก้ไข, การแจ้งเตือนการลบของ Telegram, และ `missing_on_recheck` ยังคงเป็นข้อมูลสังเกตการณ์ที่แยกต่างหาก การเข้าถึงในขอบเขตการสนทนาไม่สามารถเห็น เหตุการณ์การดำเนินงานทั่วทั้งพื้นที่ทำงานได้; สถานะการบันทึกจะระบุข้อจำกัดนี้อย่างชัดเจน

ข้อความในคลังข้อมูลถือเป็นข้อมูลป้อนเข้าที่ไม่น่าเชื่อถือ คำสั่งภายในข้อความไม่มอบ ขอบเขตเพิ่มเติม และต้องไม่ถูกพิจารณาเป็นคำสั่งจากลูกค้า โมเดล AI ภายนอกอาจ รับเนื้อหาใดก็ตามที่ลูกค้า MCP ของมันร้องขอ สิทธิ์การเข้าถึงแบบอ่านอย่างเดียวป้องกัน การเปลี่ยนแปลงในคลังข้อมูล แต่ไม่ป้องกันไม่ให้ลูกค้าเก็บรักษาข้อมูลที่มันอ่านได้

ค่าแฮชใช้เพื่อระบุบันทึกที่เก็บไว้และสนับสนุนการตรวจสอบความสมบูรณ์ แต่ค่าแฮชเหล่านี้ ไม่สามารถพิสูจน์ได้ด้วยตัวเองว่าผู้ส่งข้อความใน Telegram เป็นผู้เขียนจริง หรือว่าข้อความทุกข้อความได้ถูกบันทึกไว้ทั้งหมด
