# 建立「案件看板」

Canonical page: https://phishdestroy.github.io/TgWitness/zh-Hant/docs/case-board/

將儲存的 Telegram 觀察記錄轉化為您的團隊可共同審閱的案件。

「案件看板」會將書籤、精確文字標示、已儲存的片段及討論內容與其來源參考資料並列保存。「彙整集」為案件提供工作架構；經簽署的修訂版本則記錄了團隊的開發歷程。

## 從訊息到案件卡片

1. 開啟「**調查」→**「**案件看板」**，並選擇「標準」或「專家」模式。為該案件建立一個收集集，並選擇其聊天範圍。
2. 在「**日誌」**或已儲存的聊天記錄中，選擇**「新增至案板**」，或選取該記錄並按下 **B** 鍵。該卡片將進入「收件匣」；為其設定有用的標題，並將其移至您的收藏夾。
3. 在已儲存的聊天訊息中選取一段文字，並選擇「**標示 → 看板」**以保留精確的引文及訊息版本。添加註解說明其重要性。
4. 討論該卡片、指派審查狀態，並在需要核實任何主張時，隨時返回其原始上下文。使用**「簡報」**功能與同事逐步檢視資料集。

### 請點擊此已變更的付款連結

綜合範例 · 本地化說明

1. **擷取。**開啟已儲存的觀察紀錄 #142 及其訊息版本。
2. **加入書籤。**將引文、來源參考資料及您的問題記錄在卡片上。
3. **審核。**新增團隊評論並將卡片移至「審核」階段。
4. **當前。**逐步引導使用者進行資料蒐集，並開啟引用的來源上下文。

#### 已儲存的觀察記錄 #142

「請使用新的付款連結。」

操作聊天室 · 訊息 38 · 觀察時間 09:12 UTC

#### 卡片：變更目的地

> 請使用新的付款連結。

問題：較早版本中出現了哪個目的地？

#### 團隊審閱

分析師：請與觀察記錄 #101 進行比對。

#### 來源上下文

卡片 → 已儲存版本 → 較早的觀察記錄

註解與 Telegram 觀察記錄仍可分別識別。

## 一次儲存一個實用的範圍

在單一聊天室中按住 Shift 鍵並點擊兩則記錄以執行**「切片」**操作，選擇**「按時間切片」**，或儲存當前的「日誌」篩選條件。儲存前請先確認記錄數量。重新開啟切片以套用其儲存的查詢；**顯示自書籤標記後新增的記錄**，即可查看後續新增的內容。

時間切片緊隨收集器的觀察時間之後。當後續變更發生時，訊息 ID 切片可跟隨所選訊息進行追蹤。透過儲存的建立邊界，收件者可將原始選取內容與其後續狀態進行比較。

## 為每位同事分配適當的角色

**審閱者**負責閱讀案件看板；**分析師**負責新增卡片與註解；**操作員**則負責管理資料蒐集及審閱決策。工作區與聊天權限適用於卡片、來源背景及討論內容。請使用命名式存取授權以明確標示來源。

## 將此工作轉化為可交付成果

可將片段匯出為已簽名的 JSON 檔案，或使用 CSV 格式匯出至試算表。報告設定可包含書籤和片段，若勾選此選項，亦可包含團隊註解。請在[「報告工作室」](https://phishdestroy.github.io/TgWitness/zh-Hant/docs/reports/)中選擇這些內容；已儲存的片段不會自動配置報告。若收件者受限，請使用獨立的[移交控制功能](https://phishdestroy.github.io/TgWitness/zh-Hant/docs/handover/)。
