Перейдіть до [налаштувань S3](https://phishdestroy.github.io/TgWitness/uk/docs/exports/#s3), функції [Object Lock](https://phishdestroy.github.io/TgWitness/uk/docs/exports/#s3-retention) або [верифікованого відновлення](https://phishdestroy.github.io/TgWitness/uk/docs/exports/#s3-restore).

## Збережіть надійне джерело інформації

Запишіть відбиток ключа простору десь поза збирачем. Під час збору теж зберігайте підписані контрольні точки деінде або запустіть [незалежного свідка](https://phishdestroy.github.io/TgWitness/uk/docs/witness/). Саме з цим отримувач звіряє ключ і попередній стан журналу.

## Завантажити підписаний ZIP-файл

**Експорт** → підписаний ZIP з доказами. У ньому весь журнал і підписаний маніфест файлів. Читабельний звіт налаштовується в [Report studio](https://phishdestroy.github.io/TgWitness/uk/docs/reports/), а якщо треба віддати лише вибране — зробіть [виписку для передачі](https://phishdestroy.github.io/TgWitness/uk/docs/handover/).

Звіти HTML, PDF і JSON мають власні печатки. CSV — лише робоча копія; для перевірки цілісності беріть CSV з перевіреного ZIP.

## Перевірте за допомогою надійної копії TgWitness

В оточенні проєкту, з власним відбитком і шляхами:

```
python -m tgwitness.verify evidence.zip --fingerprint TRUSTED_PUBLIC_KEY_SHA256 --checkpoint retained-checkpoint.json
```

У разі успіху ви побачите `key_pinned: true` і `checkpoint_checked: true`. Збережіть цей вивід поруч з архівом. Контрольна точка має бути не пізніше за кінець експорту.

## Використовуйте результат перевірки

- **Файли:** маніфест пов'язує їхні хеші, підписи — журнал. Будь-яку зміну буде помітно.
- **Ключ:** збережений вами відбиток підтверджує, що це той самий ключ.
- **Попередній стан:** контрольна точка порівнює експорт з початком журналу, збереженим до передачі.
- **Охоплення:** прогалини, результати збору й тест «надіслати → змінити → видалити» показують, що ця конфігурація справді впіймала.

Докладніше: [що перевірка доводить, а що ні](https://phishdestroy.github.io/TgWitness/uk/docs/reference/evidence/#verification-scope).

## Налаштування позасайтової копії в S3

**Експорт → Зовнішня копія** у вашому просторі. Працює з AWS S3 і будь-яким S3-сумісним сховищем. Копіює сегменти журналу, збережені файли, контрольні точки з мітками часу та готові експорти чатів, кожен шифрується `AES-256-GCM` ще на збирачі.

В онлайн-демо ці налаштування показано з вимкненим завантаженням. Справжні облікові дані вводьте лише у своєму встановленні.

[![Повна панель налаштувань поза сайтом: кінцева точка, регіон, сховище, ключі доступу, розклад, блокування об’єктів та управління ключами відновлення](https://phishdestroy.github.io/TgWitness/assets/off-site-copy.png)](https://phishdestroy.github.io/TgWitness/assets/off-site-copy.png)

Повна панель з розгорнутими розширеними налаштуваннями. Дані для входу до сховища не відображаються.

| Галузь | Що ввести |
| --- | --- |
| Кінцева точка | URL сховища, без шляху до бакета й облікових даних. Приклад: `https://s3.example.invalid`. |
| Регіон | Що вимагає ваш провайдер. Типово `us-east-1`. |
| Bucket | Наявний бакет із правом запису. Приклад: `example-case-backup`. |
| Папка у контейнері | Префікс, типово `tgwitness`. Зверху додається префікс простору. |
| Ідентифікатор ключа доступу / Секретний ключ доступу | Обидва разом, зберігаються в сховищі секретів. Щоб лишити збережені, потім залиште обидва порожніми. |
| Адреси у форматі Path | Увімк.: `endpoint/bucket`. Вимк.: `bucket.endpoint`. Залежить від провайдера. |
| Інтервал копіювання | Від 1 до 1440 хвилин, типово 5. Лише поки застосунок запущено. |
| Зберігання даних Object Lock | Дні й режим, якщо бакет підтримує Object Lock. Нуль лишає типове налаштування бакета. |

1. Створіть бакет, заповніть адресу й облікові дані зі знятою позначкою **Зберігати зовнішню копію** та натисніть **Зберегти зовнішню копію**.
2. **Перевірити підключення** завантажує зашифрований тестовий об'єкт.
3. **Завантажити ключ шифрування** й зберігайте його подалі від збирача. Немає ключа — немає відновлення.
4. Позначте **Зберігати зовнішню копію**, збережіть, потім **Копіювати зараз** або лишіть працювати за розкладом.

## Перевірка терміну зберігання та прогресу копіювання

У розділі **Додатково** оберіть термін зберігання та `GOVERNANCE` або `COMPLIANCE`. TgWitness зчитує термін із завантаженого об'єкта й повідомляє: підтверджено, відсутній або перевірка не вдалася.

Панель показує останній прохід, кількість об'єктів, байти, скопійовану межу журналу та помилки. Відсутній локальний файл потрапляє у звіт і повторюється наступного разу, решта копіюється далі.

Завантаження йде напряму, через SOCKS5 або HTTP. З маршрутом лише через MTProxy копія чекає з помилкою.

## Зберігайте ключ відновлення окремо

У JSON-ключі — ключ розшифрування, адреса, префікс і відбиток ключа. Для відновлення потрібен він і облікові дані сховища з правом читання.

Змінили адресу, бакет чи префікс? Завантажте ключ знову. У новому місці почнеться свіжа копія, старі експорти чатів лишаться там, де були.

## Відновлення та перевірка на іншому комп’ютері

Потрібні встановлення TgWitness, якому ви довіряєте, JSON-ключ, облікові дані лише для читання й порожня папка:

### Windows PowerShell

```
$env:TGWITNESS_S3_ACCESS_KEY = 'YOUR_READ_ACCESS_KEY'
$env:TGWITNESS_S3_SECRET_KEY = 'YOUR_READ_SECRET_KEY'
python -m tgwitness.replica restore --key-file tgwitness-replica-key.json --out restored-evidence
```

### Linux / macOS

```
export TGWITNESS_S3_ACCESS_KEY='YOUR_READ_ACCESS_KEY'
export TGWITNESS_S3_SECRET_KEY='YOUR_READ_SECRET_KEY'
python -m tgwitness.replica restore --key-file tgwitness-replica-key.json --out restored-evidence
```

Спершу все перевіряється в тимчасовій закритій папці: весь журнал, контрольні точки, хеші й розміри файлів. Небезпечні шляхи, конфліктні сегменти чи журнал коротший за контрольну точку — помилка, і тоді нічого не записується.

У разі успіху отримаєте `events.jsonl`, `media/`, `checkpoints/` і `exports/`. Збережіть JSON-вивід команди поруч і звірте все з контрольними точками чи записами свідка, які зберігаєте самі.
