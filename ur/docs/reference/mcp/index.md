# صرف پڑھنے کے لیے MCP

Canonical page: https://phishdestroy.github.io/TgWitness/ur/docs/reference/mcp/

ایک MCP کلائنٹ کو منتخب ورک اسپیسز اور چیٹس سے منسلک کریں، جس کی رسائی ختم ہونے والی اور منسوخ کی جانے والی ہو۔

**موجودہ مرکزی:** سورس چیک آؤٹ استعمال کریں؛ 0.7.0 پورٹیبل پریویو اس خصوصیت سے پہلے کا ہے۔

[ورک فلو گائیڈ](https://phishdestroy.github.io/TgWitness/docs/archive/) · [ویکی](https://github.com/phishdestroy/TgWitness/blob/main/docs/wiki/Archive-and-Integrations.md)

TgWitness پروجیکٹ ڈائریکٹری سے اختیاری سرور انسٹال کریں:

```
python -m pip install '.[mcp]'
```

پینل میں **Integrations → MCP** کھولیں۔ کنکشن کا نام دیں، اس کے ورک اسپیسز اور چیٹس منتخب کریں، اور میعاد ختم ہونے کی تاریخ طے کریں۔ آرکائیو ٹوکن ایک بار کاپی کریں؛ اسے بعد میں بازیاب نہیں کیا جا سکتا۔ کھوئے ہوئے ٹوکنز کو منسوخ کریں اور متبادل جاری کریں۔ پینل ٹوکنز اور ٹیلیگرام کی سائن ان معلومات MCP کی سائن ان معلومات نہیں ہیں۔

## کلائنٹ کو کنیکٹ کریں

پینل اپنی [دستاویزی تشکیلات](https://code.visualstudio.com/docs/agents/reference/mcp-configuration) کے مطابق **VS Code Local ہارنس** کے لیے o`.vscode/mcp.json` پیدا کرتا ہے۔ ڈاؤن لوڈ کی گئی فائل کو اسی مقام پر محفوظ کریں، **MCP: List Servers** چلائیں، اور TgWitness شروع کریں۔ VS Code پاس ورڈ ان پٹ کے ذریعے ٹوکن کے لیے درخواست کرتا ہے۔ ڈاؤن لوڈ شدہ JSON میں ٹوکن نہیں بلکہ ایک پرامپٹ حوالہ ہوتا ہے۔ MCP extra جس ماحول میں انسٹال ہے، وہاں سے Python ایگزیکیوٹ ایبل استعمال کریں۔

دیگر stdio کلائنٹس کے لیے، چلائیں:

```
python -m tgwitness.mcp_server --api-url http://127.0.0.1:8787
```

کلائنٹ کے محفوظ ماحول میں `TGWITNESS_ARCHIVE_TOKEN` سیٹ کریں۔ اسے کمانڈ آرگومنٹس یا URLs میں نہ رکھیں۔ برج پینل کے مجاز آرکائیو API کے ذریعے پڑھتا ہے؛ اس کی براہِ راست ڈیٹا بیس تک رسائی نہیں ہوتی۔ Stdout صرف MCP پیغامات منتقل کرتا ہے۔

دور دراز کلائنٹس کے لیے، پینل کے ساتھ سروس چلائیں:

```
python -m tgwitness.mcp_server --transport streamable-http \
  --api-url http://127.0.0.1:8787 --port 8766 \
  --public-url https://archive.example.org/mcp
```

`/mcp` کو HTTPS ریورس پراکسی کے ذریعے `127.0.0.1:8766/mcp` پر فارورڈ کریں، `Authorization: Bearer …` ہیڈر کو برقرار رکھتے ہوئے۔ authorization headers اور request/response bodies کی لاگنگ غیر فعال کریں۔ loopback سے آگے صرف ضرورت پڑنے پر `--host` اور `--public-url` استعمال کرتے ہوئے bind کریں۔ یہ اینڈ پوائنٹ سرکاری [MCP Python SDK](https://github.com/modelcontextprotocol/python-sdk) کے Streamable HTTP کا استعمال کرتا ہے۔ یہ صراحتاً ترتیب دی گئی بیئرر کریڈینشلز کو سپورٹ کرتا ہے، OAuth ڈسکوری کو نہیں؛ صرف OAuth کے لیے کلائنٹس کی حمایت نہیں کی جاتی۔

**چیک پروٹوکول اور رسائی** ایک حقیقی MCP کلائنٹ کو فعال کرتی ہے اور ٹولز کی فہرست دکھاتی ہے۔ یہ پیغامات حاصل نہیں کرتا۔ دور دراز چیک کے لیے، منتخب کردہ MCP سرور آرکائیو ٹوکن وصول کرتا ہے۔ صرف ایسے سرور کو کنفیگر کریں جسے آپ چلاتے ہوں یا جس پر آپ اس دائرہ کار کے لیے بھروسہ کرتے ہوں۔

## دائرہ کار اور نتائج

دستیاب ٹولز: `list_workspaces`، `list_chats`، `search_messages`، `get_message_versions`، `get_message_context`، `get_journal_event`، اور `get_capture_status`۔ کوئی ٹیلیگرام ایکشنز، کنفیگریشن تبدیلیاں، یا بلک-ایکسپورٹ ٹولز موجود نہیں ہیں۔ ہر پڑھنے پر ورک اسپیس/چیٹ کی رسائی دوبارہ چیک کی جاتی ہے؛ ختم شدہ اور منسوخ شدہ اسناد کام کرنا بند کر دیتی ہیں۔ حدود یہ ہیں: فی منٹ فی اسناد 60 API درخواستیں، فی صفحہ 50 ریکارڈز، 64 KiB کا جواب، اور آٹھ سیکنڈ کا API ڈیڈ لائن۔

پیغام کے نتائج میں ورک اسپیس، چیٹ/پیغام کی شناختیں (آئی ڈیز)، واقعات کا تسلسل، محفوظ شدہ ہیش، اور ایک پینل لنک شامل ہیں۔ لنک کھولنے والے ویوئر کے پاس اپنا مجاز پینل سیشن ہونا چاہیے۔ خام ٹیلیگرام آبجیکٹس، رسائی کے ہیشز، فائل کے حوالہ جات، سیشن کا مواد، اور کیز کو خارج کر دیا گیا ہے۔ تلاش پیغام کے متن کا جائزہ لیتی ہے، نہ کہ خام فیلڈز کا۔ متن محدود ہوتا ہے اور اختصار کی نشاندہی کی جاتی ہے۔ ترامیم، ٹیلیگرام کے حذف کرنے کے نوٹس، اور `missing_on_recheck` الگ الگ مشاہدات کے طور پر رہتے ہیں۔ چیٹ کی حد تک رسائی پورے ورک اسپیس کے آپریشنل واقعات کو نہیں دیکھ سکتی؛ کیپچر اسٹیٹس واضح طور پر اس حد کی نشاندہی کرتا ہے۔

آرکائیو شدہ متن غیر معتبر ان پٹ ہے۔ پیغامات کے اندر دی گئی ہدایات سے کوئی اضافی دائرہ اختیار نہیں ملتا اور انہیں کلائنٹ کی ہدایات کے طور پر نہیں لیا جانا چاہیے۔ ایک بیرونی AI ماڈل وہ تمام مواد وصول کر سکتا ہے جو اس کا MCP کلائنٹ طلب کرتا ہے۔ صرف پڑھنے کی اجازت آرکائیو میں تبدیلیوں کو روکتی ہے؛ یہ کلائنٹ کو پڑھے ہوئے ڈیٹا کو محفوظ کرنے سے نہیں روکتی۔

ہیشز محفوظ شدہ ریکارڈز کی شناخت کرتے ہیں اور سالمیت کی جانچ کی حمایت کرتے ہیں۔ یہ خود بخود ٹیلیگرام کی مصنفیت یا ہر پیغام کی گرفتاری کا ثبوت نہیں دیتے۔
