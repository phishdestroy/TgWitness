# کنیکشن، پراکسیز اور ڈیٹا کی حفاظت

Canonical page: https://phishdestroy.github.io/TgWitness/ur/docs/reference/connection/

تصدیق، خودکار پراکسی پولز، آئی پی موڈز، فال بیک پالیسی، بیرونی درخواستیں اور خفیہ ذخیرہ۔

[ٹی جی وٹنس](https://github.com/phishdestroy/TgWitness/blob/main/README.md) / [دستاویزات](https://github.com/phishdestroy/TgWitness/blob/main/docs/README.md) · [تیناری اور بحالی](https://phishdestroy.github.io/TgWitness/ur/docs/reference/deployment/)

یہ دستاویز TgWitness 0.8.0 کے طرز عمل اور اس کی حدود کو بیان کرتی ہے۔ تصدیق، ماخذ تک رسائی، نیٹ ورک کنیکٹیویٹی اور مکمل کپچر الگ الگ حالتें ہیں۔ سائن ان کے مراحل، فائل فارمیٹس، اور متعدد اکاؤنٹس کے لیے، [اکاؤنٹس اور سیشن فارمیٹس](https://phishdestroy.github.io/TgWitness/ur/docs/reference/accounts/) سے شروع کریں۔ ایونٹ پالیسیاں اور دوبارہ شروع کرنے کے طرز عمل کے لیے، دیکھیں [کہ کلیکشن کیسے کام کرتی](https://phishdestroy.github.io/TgWitness/ur/docs/reference/collection/) ہے۔

## رہنمائی شدہ کنکشن سیٹ اپ

**کنکشن** میں، منتظم **یہ اکاؤنٹ**، **ایک اکاؤنٹ گروپ** یا **تمام اکاؤنٹس** کا انتخاب کر سکتا ہے، پھر ایک راستہ منتخب کریں۔ **انتخاب کا جائزہ** متاثرہ اکاؤنٹس کی فہرست دیتا ہے۔ **تیار کریں اور چیک کریں** محفوظ شدہ راستہ تبدیل کیے بغیر تجویز کردہ راستے کا تجربہ کرتا ہے۔ **چیک شدہ کنکشن لاگو کریں** دوبارہ چیک کرتا ہے، اگر ضروری ہو تو مشاہدہ روک دیتا ہے، راستہ محفوظ کرتا ہے اور پہلے سے چلنے والے مشاہدے کو دوبارہ شروع کرتا ہے۔ یہ پہلے سے غیر فعال اکاؤنٹ میں کبھی بھی ڈیٹا اکٹھا کرنا شروع نہیں کرتا۔ ہسٹری ڈاؤن لوڈز معطل رہتے ہیں اور انہیں علیحدہ سے دوبارہ شروع کیا جا سکتا ہے۔ سوئچ کرنے سے پہلے فعال ایکسپورٹس کو معطل کریں۔

گروپ کی تبدیلیاں اکاؤنٹس کو بطورِ پیشِ فرض ان کے اپنے راستے کے ساتھ برقرار رکھتی ہیں۔ اس آپشن کو صرف تب صاف کریں جب پیش نظارہ اُن تبدیلیوں کی فہرست دے جو آپ کرنا چاہتے ہیں۔ ایپلیکیشن ہر اکاؤنٹ کے نتیجے کی رپورٹ کرتی ہے؛ یہ ڈیٹا بیسز کے مابین ایک ایسا عمل نہیں ہے جس میں سب کچھ یا کچھ نہیں ہوتا ہو۔ ایک ناکام سوئچ اس اکاؤنٹ کی پچھلی ترتیبات کو بحال کر دیتا ہے۔ دوبارہ شروع کرنے میں ناکامی واضح طور پر دکھائی جاتی ہے۔ پیش نظارے دس منٹ کے بعد ختم ہو جاتے ہیں اور کنکشن کی ترتیبات یا گروپ کی رکنیت میں تبدیلیاں ایک نئے چیک کا تقاضا کرتی ہیں۔

| روٹ | TgWitness کیا منظم کرتا ہے |
| --- | --- |
| براہِ راست | ہوسٹ سے کنکشنز؛ بیرونی ہوسٹ VPN کا پتہ نہیں چلتا یا نافذ نہیں کیا جاتا۔ |
| وی پی این | ہر اکاؤنٹ کے لیے ایک مکمل ٹنل وائر گارڈ پروفائل، جو ایک مقامی یوزر سپیس کے عمل SOCKS5 کے ذریعے چلایا جاتا ہے۔ کوئی ہوسٹ انٹرفیس یا ڈرائیور انسٹال نہیں ہے۔ |
| میرا پروکسی | SOCKS5، HTTP CONNECT یا MTProxy کی شناختی معلومات۔ ایک URL SOCKS5/HTTP کے شعبوں کو پُر کر سکتا ہے۔ متعدد اکاؤنٹس منتخب کرنے سے یہ داخل کردہ پروکسی شیئر ہوتی ہے۔ |
| پبلک MTProto | موجودہ پول رTelegram کے راستے تفویض کرتا ہے۔ بیرونی درخواستیں اس وقت تک غیر فعال ہیں جب تک کہ ایڈوانسڈ سیٹنگز میں ایک الگ مناسب پروکسی ترتیب نہ دی جائے۔ |
| WARP | ہر منتخب اکاؤنٹ کے لیے ایک الگ مقامی سرنگ، WARP رجسٹریشن کے ساتھ اور اس اکاؤنٹ کے والٹ میں محفوظ شدہ WireGuard پروفائل۔ |

موجودہ راستے کی جانچ ایک تازہ غیر مستند Telegram ٹرانسپورٹ استعمال کرتی ہے، اکاؤنٹ کے سیشن کو نہیں۔ HTTP کے قابل راستوں کے لیے یہ اسی راستے کے ذریعے Cloudflare کے HTTPS ٹریس کی بھی درخواست کرتا ہے اور اس کی رپورٹ کردہ ایگزٹ آئی پی، ملک، WARP کی حالت اور چیک کے وقت کو دکھاتا ہے۔ ماپی گئی لیٹنسی، ICMP پنگ نہیں بلکہ Telegram کنکشن کے سیٹ اپ کا وقت ہے۔ اگر ٹریس WARP فعال رپورٹ نہ کرے تو WARP کی تیاری ناکام ہو جاتی ہے۔ یہ چیکس صرف کنیکٹیویٹی قائم کرتے ہیں، نہ کہ پکڑے گئے پیغامات کی صداقت یا مکمل ہونے کو۔ صرف ایک چلتی ہوئی مقامی پراسیس کا ہونا کامیاب ایگزٹ چیک نہیں ہے۔

### پورٹیبل WARP اور WireGuard

یہ [wgcf 2.3.1](https://github.com/ViRb3/wgcf/releases/tag/v2.3.1) اور [wireproxy 1.1.3](https://github.com/windtf/wireproxy/releases/tag/v1.1.3) استعمال کرنے والا ایک **غیر سرکاری WARP انضمام** ہے۔ انتظامیہ پہلے ڈاؤن لوڈ یا WARP رجسٹریشن سے پہلے سیٹ اپ کو واضح طور پر قبول کرتا ہے۔ یہ سیٹ اپ کنکشنز براہِ راست GitHub اور Cloudflare کی طرف جاتے ہیں اور مشین کا IP ظاہر کرتے ہیں۔ عام اکاؤنٹ ٹریفک اپلی کیشن تک اپنے موجودہ راستے کو برقرار رکھتی ہے۔ Cloudflare خارجی پتہ اور ملک کا انتخاب کرتا ہے؛ الگ الگ ٹنلز ایک خارجی پتہ شیئر کر سکتے ہیں۔ ملک کا انتخاب، دورانیہ وار IP گردش اور ہوسٹ بھر کے VPN کل سوئچ اس فیچر کے ذریعے فراہم نہیں کیے جاتے۔

مددگار ڈاؤن لوڈز کی معاونت: لینکس اور میک او ایس x86-64/ARM64، اور ونڈوز x86-64۔ آرٹیفیکٹس کا موازنہ جائزہ شدہ سورس میں شامل SHA-256 ہیشز سے کیا جاتا ہے، اور کیش شدہ ایگزیکیوٹ ایبلز کو لانچ کرنے سے پہلے دوبارہ چیک کیا جاتا ہے۔ کوئی ہیلپر PATH میں شامل نہیں کیا جاتا، سسٹم سروس کے طور پر انسٹال نہیں کیا جاتا، یا اسے کوئی پبلک لسنر نہیں دیا جاتا۔ تمام فائلیں ورک اسپیس کی `portable-routes/` ڈائریکٹری اور انکرپٹڈ والٹ انٹریز کے تحت موجود ہوتی ہیں۔ لوپ بیک SOCKS5 لسنر کے لیے آزادانہ طور پر تیار کردہ کریڈینشلز درکار ہوتے ہیں۔

نجی پروفائلز اور WARP اکاؤنٹ کی اسناد موجودہ ورک اسپیس والٹ کے ساتھ خفیہ کردہ ہیں۔ چلنے کے دوران، ہیلپر کو صرف مالک کے لیے پلین ٹیکسٹ کنفیگ کی ضرورت ہوتی ہے؛ اسے معمول کے مطابق روکنے پر ہٹا دیا جاتا ہے۔ ہوسٹ کے کریش ہونے کی صورت میں یہ فائل مالک کے مخصوص ڈیٹا فولڈر میں رہ سکتی ہے۔ یہ ڈسک کو خفیہ نہیں کرتا اور نہ ہی اس کے ایڈمنسٹریٹر سے تحفظ فراہم کرتا ہے۔ سپروائزر ٹنل کو بند کر دیتا ہے اگر پینل کا پیرنٹ پائپ غائب ہو جائے۔ ایک ناکام ٹنل کبھی بھی براہِ راست فال بیک کو فعال نہیں کرتا۔ پینل کو دوبارہ شروع کرنے سے منتخب شدہ ٹنل بحال ہو جاتا ہے؛ ناکام شروعاتیں ایک محدود تاخیر کے ساتھ دوبارہ کوشش کرتی ہیں۔ **ٹنل کو روکنا** مشاہدے کو بھی معطل کر دیتا ہے اور روکی ہوئی حالت کو برقرار رکھتا ہے۔ **ٹنل شروع کرنا** ٹنل کو شروع کرتا ہے؛ تیار ہونے پر مشاہدے کو علیحدہ طور پر دوبارہ شروع کریں۔

اپلوڈ کیے گئے WireGuard پروفائلز میں ایک انٹرفیس اور ایک پیئر، مکمل IPv4 اور IPv6 روٹس، اور کوئی ہکس، شامل (includes)، ماحولیاتی متبادل (environment substitutions) یا اضافی لسنرز نہیں ہونے چاہئیں۔ پبلک اینڈ پوائنٹ کے پتے اسٹارٹ اپ سے پہلے ریزولو اور پن کیے جاتے ہیں۔ OpenVPN/IPsec اور پرائیویٹ اینڈ پوائنٹس کے لیے بیرونی VPN یا SOCKS5 گیٹ وے استعمال کریں۔

## تصدیقی طریقے

**API ID اور API ہیش ایک ایپلیکیشن کی شناخت کرتے ہیں؛ یہ اکاؤنٹ لاگ ان کا متبادل نہیں ہیں۔** یہ TgWitness میں اختیاری ہیں۔ ترجیح: فارم میں داخل کی گئی جوڑی، پھر درآمد شدہ اکاؤنٹ JSON سے، پھر ورک اسپیس میں محفوظ شدہ جوڑی، پھر 50 کی بلٹ ان پول پبلک جوڑے، جنہیں بے ترتیب ترتیب میں آزمایا جاتا ہے اور جب ٹیلیگرام کسی ایک کو مسترد کر دیتا ہے تو خودکار طور پر تبدیل کیا جاتا ہے۔ صرف ٹیلیگرام ڈیسک ٹاپ جوڑا (2040) ایک مطابقت پذیر ٹیلیگرام ڈیسک ٹاپ کلائنٹ کی تفصیل کے ساتھ بھیجا جاتا ہے۔ [my.telegram.org](https://my.telegram.org) پر موجود API ڈیولپمنٹ ٹولز سے آپ کا اپنا جوڑا آپ کے تمام اکاؤنٹس کے ساتھ استعمال کیا جا سکتا ہے؛ ہر اکاؤنٹ کی اپنی علیحدہ اجازت نامہ برقرار رہتی ہے۔

| طریقہ | ضروریات | ٹی جی وِٹنس سپورٹ |
| --- | --- | --- |
| فون، کوڈ، اختیاری 2FA | اکاؤنٹ تک رسائی؛ API جوڑا اختیاری | پینل لاگ ان |
| آتھ کی ہیکس + ڈی سی آئی ڈی | مکمل 512-حرف کی کلید اور DC 1–5 | براہِ راست **Auth کلید** ٹیب؛ اجازت محفوظ کرنے سے پہلے اختیاری صارف شناختی نمبر چیک کیا جاتا ہے |
| ٹیلی تھون سٹرنگ سیشن | ایک درست سیشن سٹرنگ | پینل لاگ ان |
| Telethon SQLite `.session` | بند، یکساں عبارت | اسکیماز 7/8 کا براہِ راست پینل امپورٹ؛ اختیاری آف لائن کمانڈ لائن انٹرفیس |
| پائیروگرام ایس کیو لائٹ `.session` | پروڈکشن صارف سیشن بند | اسکیما 2/3 کا براہِ راست پینل امپورٹ |
| ٹیلیگرام ڈیسک ٹاپ ٹی ڈی اے ٹی زیپ | ایک جدید اکاؤنٹ؛ اگر محفوظ ہو تو مقامی پاس کوڈ | چیک سم/ڈیکرپشن چیکس کے ساتھ میموری میں تبدیلی |
| اکاؤنٹ JSON | مدعومہ API/سیشن/کی فیلڈز | صرف میٹا ڈیٹا API کی شناختی معلومات کو مکمل کرتا ہے؛ سیشن/کی یا فون/QR لاگ ان اب بھی ضروری ہے۔ |
| کیو آر لاگ ان | ایک مجاز ٹیلیگرام ایپ سے تصدیق | مقامی QR جنریشن، میعاد ختم/دوبارہ کوشش، اختیاری 2FA |
| TDLib / Pyrogram StringSession | دیگر لائبریری مخصوص فارمیٹس | غیر معاونت یافتہ |
| بوٹ ٹوکن | ایک بوٹ جس کا اپنا رسائی/اپ ڈیٹ ماڈل ہے | اس جمع کرنے والے نے استعمال نہیں کیا |

ٹیلیگرام کوڈ کی ترسیل کا انتخاب کرتا ہے؛ ایس ایم ایس کی ضمانت نہیں ہے۔ ایک API ہیش منسوخ شدہ سیشن کو ٹھیک نہیں کر سکتا یا بھولے ہوئے 2FA پاس ورڈ کو تبدیل نہیں کر سکتا۔ TgWitness لاگ ان کوڈز یا ٹیلیگرام 2FA پاس ورڈ کو ڈسک پر محفوظ نہیں کرتا۔

نجی ذریعے کے لیے، اکاؤنٹ کے پاس پہلے سے ہی رسائی ہونی چاہیے۔ گروپ کا صارف نام غیر ضروری ہے۔ پروکسی یا سیشن امپورٹ سے نہ رکنیت ملتی ہے اور نہ ہی منتظم کے حقوق۔ موجودہ رکنیت سے پہلے شامل ہونے کی تاریخ تک رسائی کی ضمانت نہیں ملتی۔

## ٹیلی تھون سیشن فائل درآمد کریں

Telethon SQLite، Pyrogram SQLite، اور Telegram Desktop TData مختلف فارمیٹس استعمال کرتے ہیں۔ پینل سپورٹ شدہ ڈھانچوں کا پتہ لگاتا ہے اور انہیں تبدیل کرتا ہے؛ فائل کا نام تبدیل کرنا تبدیلی نہیں ہے۔ **Files** کے تحت ایک سیشن اور اس کے ساتھ والی JSON کو منتخب کریں، پھر **Connect account** دبائیں۔ چار تک مماثل فائلیں اور کل 8 MiB قبول کیے جاتے ہیں۔ TData/JSON کی تفصیلات کے لیے [فارمیٹ کی حدیں](https://phishdestroy.github.io/TgWitness/ur/docs/reference/accounts/) دیکھیں۔ پاس کوڈ کی بازیابی کا کوئی طریقہ نہیں ہے۔ فون/2FA یا QR لاگ ان ایک علیحدہ اجازت نامہ بناتا ہے۔

اختیاری صرف ٹیلی تھون کمانڈ لائن راستہ دستیاب ہے:

1. اصلی سیشن استعمال کرنے والے کلائنٹ کو روکیں اور ایک مستقل کاپی بنائیں۔ کنورٹر ان فائلوں کو مسترد کر دیتا ہے جن کا WAL/جرنل نامکمل ہو۔ ان فائلوں کو حذف کر کے چیک کو بائی پاس کرنے کے بجائے اصلی کلائنٹ کو مناسب طریقے سے بند کریں۔
2. TgWitness کے ماحول سے، چلائیں:

```
python -m tgwitness.sessions account.session --out account.tgwitness-session
```

1. **Add account → Files** کے تحت نتیجہ لوڈ کریں یا اس کی سٹرنگ پیسٹ کریں اور جاری رکھیں۔
2. دکھائی گئی عددی اکاؤنٹ آئی ڈی چیک کریں، ذرائع منتخب کریں اور مشاہدہ شروع کریں۔

**تبدیل شدہ فائل ایک غیر خفیہ شدہ اکاؤنٹ رسائی راز ہے۔** اسے محفوظ اسٹوریج میں رکھیں اور اسے کبھی بھی کمٹ یا کسی تیسری پارٹی کی کنورژن سروس کو نہ بھیجیں۔ TgWitness مجاز سیشن کو اپنے انکرپٹڈ والٹ میں محفوظ کرتا ہے۔ سیشن کی کاپی کرنے سے ایک علیحدہ اجازت نامہ پیدا نہیں ہوتا: کلون شدہ auth کیز کے ساتھ بیک وقت کلائنٹس نہ چلائیں اور آزادانہ اپ ڈیٹ کی ترسیل کا تصور نہ کریں۔

تبدیلی اجازت نامہ منتقل کرتی ہے، اصل پیغامات، اینٹیٹی کیش یا ایک پائیدار اپ ڈیٹ کرسر نہیں۔ یہ عمل دوبارہ شروع ہونے پر اپ ڈیٹ کی بحالی کو درست نہیں کرتی۔

## MTProto، Telethon اور پروکسیز

MTProto ٹیلیگرام کا پروٹوکول ہے۔ Telethon وہ پائتھن کلائنٹ لائبریری ہے جسے TgWitness استعمال کرتا ہے۔ MTProxy ایک ٹیلیگرام ٹرانسپورٹ پراکسی ہے؛ SOCKS5 اور HTTP CONNECT عمومی سرنگیں فراہم کرتے ہیں۔ ان میں سے کوئی بھی اکاؤنٹ کی تصدیق کا متبادل نہیں ہے۔

ہر ورک اسپیس کے لیے راستہ محفوظ کریں: **اکاؤنٹ → ترتیبات → کنکشن ترتیبات → کنکشن کا راستہ تبدیل کریں**، سائن ان کرنے سے پہلے نئے ورک اسپیسز بطورِ ڈیفالٹ **خودکار MTProxy · عوامی فہرستیں** ہیں جن میں**پتہ چھپایا گیا ہوتا** ہے۔ موجودہ ورک اسپیسز جنہوں نے واضح طور پر Direct استعمال کیا تھا، وہ ایسا موڈ برقرار رکھتے ہیں جو اسے اجازت دیتا ہے۔

## آئی پی موڈز

روٹ کنکشن کا انتخاب کرتا ہے۔ آئی پی موڈ، پینل کے اکاؤنٹ سیکشن میں **آئی پی پروٹیکشن**، یہ طے کرتا ہے کہ سرور کا پتہ کب ظاہر ہو سکتا ہے۔ یہ کنٹرولز VPN انسٹال نہیں کرتے اور نہ ہی تمام مشین ٹریفک کو روٹ کرتے ہیں۔

| موڈ | ٹیلیگرام | بیرونی درخواستیں |
| --- | --- | --- |
| پتہ چھپائیں (`hide`) | پراکسی استعمال کریں؛ اگر کوئی کام نہ کرے تو انتظار کریں۔ کوئی براہِ راست متبادل نہیں۔ | SOCKS5/HTTP درکار ہے؛ قابل اطلاق پروکسی کے بغیر درخواستیں مسترد کی جاتی ہیں۔ |
| براہ راست آخری چارہ کے طور پر (`fallback`) | خودکار MTProxy متعین کردہ تاخیر کے بعد Direct استعمال کر سکتا ہے، پھر ایک فعال پروکسی پر واپس آ جاتا ہے۔ | ترجیح دیں کہ کنفیگر شدہ بیرونی پروکسی یا اکاؤنٹ کا SOCKS5/HTTP راستہ استعمال کیا جائے؛ ورنہ Direct کی اجازت ہے۔ |
| سرور ٹنل یا وی پی این کے پیچھے (`tunnel`) | براہِ راست راستے اور فوری خودکار پول بیک اپ کی اجازت ہے۔ | براہِ راست اجازت ہے جب کوئی موزوں پروکسی ترتیب نہ دی گئی ہو۔ |

ٹنل یا VPN موڈ اس مفروضے پر مبنی ہے کہ آپ اس نیٹ ورک کو الگ سے منظم کرتے ہیں۔ اگر فعال ٹنل موجود نہ ہو تو منزل سروسر کا اپنا پتہ دیکھ سکتی ہے۔ موڈ کا انتخاب آپ کے حقیقی نیٹ ورک کے مطابق کریں، نہ کہ آپشن کے نام کے مطابق۔

### ایک راستہ منتخب کریں

| روٹ | سیٹنگز | حد |
| --- | --- | --- |
| خودکار MTProxy | بلٹ ان فہرستیں یا آپریٹر کی فہرست | ایک فعال ٹیلیگرام راستہ برقرار رکھتا ہے؛ براہِ راست بیک اپ آئی پی موڈ پر منحصر ہوتا ہے۔ |
| براہِ راست | ٹنل یا وی پی این موڈ | ٹیلی تھون میزبان کے نیٹ ورک راستے کا استعمال کرتا ہے |
| SOCKS5 | ہوسٹ، پورٹ، اختیاری صارف نام/پاس ورڈ | python-socks، ریموٹ منزل کے لیے DNS فعال |
| HTTP CONNECT | ہوسٹ، پورٹ، اختیاری صارف نام/پاس ورڈ | سادہ HTTP CONNECT؛ پروکسی کے لیے TLS نافذ نہیں کیا گیا۔ |
| MTProxy | ہوسٹ، پورٹ، سیکرٹ | تجربیاتی ٹیلی تھون ٹرانسپورٹ؛ 32 ہیکس اعداد یا `dd` + 32 ہیکس اعداد |

جعلی TLS `ee` کے راز مسترد کر دیے جاتے ہیں۔ Telethon 1.45 کی نارملائزیشن پری فکس اور ڈومین ہٹا سکتی ہے، لیکن اس میں Fake TLS نافذ نہیں ہوتا۔ `tg://proxy?server=…&port=…&secret=…` یا `https://t.me/proxy?server=…&port=…&secret=…` کو پیسٹ کریں اور **لنک سے 'فیلڈز بھرنا'** منتخب کریں۔ یہ کنکٹ یا محفوظ کیے بغیر فیلڈز کو تصدیق اور پُر کرتا ہے؛ راستے کا جائزہ الگ سے لیں اور محفوظ کریں۔ دستی فیلڈز دستیاب رہتی ہیں۔ [ٹیلیگرام پروکسی لنکس](https://core.telegram.org/api/links#proxy-links) دیکھیں۔

### آپ کی تنصیب کے فراہم کردہ عوامی پروکسیز

بلٹ ان فہرست چار ذرائع کو یکجا کرتی ہے: [SoliSpirit/mtproto](https://github.com/SoliSpirit/mtproto)، [zakky8/mtproto-proxy-pro](https://github.com/zakky8/mtproto-proxy-pro)، [kort0881/telegram-proxy-collector](https://github.com/kort0881/telegram-proxy-collector) اور [3yed-61/MTP-Collector](https://github.com/3yed-61/MTP-Collector)۔ اس کے ساتھ منسلک سنپ شاٹ میں اینڈ پوائنٹ کے حقائق، ماخذ کی شناخت اور ڈاؤن لوڈ کی تاریخیں شامل ہیں۔ کسی فراہم کنندہ کی فہرست اس بات کا ثبوت نہیں ہے کہ پروکسی کام کرتی ہے یا ہر ٹیلیگرام اپ ڈیٹ فراہم کرتی ہے۔

**خودکار MTProxy** ٹیلیگرام ٹرانسپورٹ کنیکٹیویٹی کی جانچ کرتا ہے، ایک فعال پروکسی کو برقرار رکھتا ہے اور اس کے ناکام ہونے پر دوسری پروکسی پر سوئچ کر جاتا ہے۔ جب کافی فعال اندراجات دستیاب ہوں تو ورک اسپیسز مختلف پروکسیز کو ترجیح دیتے ہیں؛ ایک منفرد ایگزٹ ایڈریس کی ضمانت نہیں دی جاتی۔ ناکام پروکسیز اگلی کوشش سے پہلے آرام کرتی ہیں۔ اگر کوئی بھی کام نہ کرے، تو IP موڈ یہ طے کرتا ہے کہ کیا کلیکشن کو انتظار کرنا چاہیے یا براہِ راست کنکشن استعمال کیا جا سکتا ہے۔ پروکسیز تبدیل کرنے سے اکاؤنٹ تبدیل نہیں ہوتا یا اس کا جرنل مٹ نہیں جاتا۔ راستے کے انتخاب اور تبدیلیاں دستخط شدہ جرنل میں ریکارڈ ہوتی ہیں۔

جب خودکار راستے فعال ہوں، فہرستیں ہر گھنٹے تازہ کاری ہوتی ہیں اور ٹرانسپورٹ چیکس ڈیفالٹ کے طور پر ہر دس منٹ بعد چلتی ہیں۔ یہ وقفے قابل ترتیب ہیں۔ **عوامی فہرستوں کو اپ ڈیٹ کرنے سے** تازہ کاری کی درخواست ہوتی ہے؛ صرف فہرست دیکھنے سے محفوظ شدہ دستی راستہ تبدیل نہیں ہوتا۔

**ٹیلیگرام ٹریفک اور HTTPS درخواستیں مختلف راستوں کا استعمال کرتی ہیں۔** فہرست کی ڈاؤن لوڈز ایک الگ HTTPS کنکشن اور فراہم کردہ external-request راستے کا استعمال کرتی ہیں۔ `TGWITNESS_PROXY_FEED_PROXY` واضح طور پر اس راستے کو ایک HTTP/SOCKS5 پروکسی کے ساتھ اووررائڈ کرتا ہے؛ دونوں collector Compose ویریئنٹس اسے آگے بھیجتے ہیں۔ بیک گراؤنڈ پول مرکزی ورک اسپیس کی پیروی کرتا ہے۔ فیڈ فراہم کنندگان کو کوئی ٹیلیگرام سیشن، API کی تفصیلات، پینل ٹوکن یا بوٹ ٹوکن بھیجا نہیں جاتا۔ فراہم کنندہ کے نام، سنپ شاٹ کی تاریخیں اور ڈاؤن لوڈ کا راستہ **'فہرست کہاں سے آتی ہے'** کے تحت ظاہر ہوتے ہیں۔

MTProxy صرف ٹیلیگرام ٹریفک منتقل کرتا ہے۔ ورک اسپیس کے HTTP آپریشنز جیسے ٹائم اسٹیمپس، نوٹیفیکیشنز، آف سائٹ کاپیاں اور سورس چیکس، جب ترتیب دیے جائیں تو ایک الگ SOCKS5/HTTP پروکسی استعمال کرتے ہیں، اور پھر اکاؤنٹ کے SOCKS5/HTTP راستے کا استعمال کرتے ہیں۔ ان دونوں کے بغیر، Hide the address درخواست مسترد کر دیتا ہے؛ دیگر موڈز Direct کی اجازت دیتے ہیں۔ بیرونی درخواستیں غیر فعال کی جا سکتی ہیں۔ ایک واضح طور پر ترتیب دی گئی فیڈ ڈاؤن لوڈ پروکسی ایک علیحدہ آپریٹر اووررائیڈ کے طور پر برقرار رہتی ہے۔ آزاد شاہد سروس اپنا راستہ خود برقرار رکھتی ہے۔

آپریٹر کے زیر انتظام نجی خدمات کے لیے، موجودہ سرور ماحول کی سیٹنگ `TGWITNESS_ALLOW_PRIVATE_DESTINATIONS=1` نجی منزلوں کی اجازت دیتی ہے اور پروکسی سائیڈ ہوسٹ نیم ریزولوشن کو برقرار رکھتی ہے۔ اسے پینل سے فعال نہیں کیا جا سکتا۔ صرف عوامی موڈ، پبلک ریزولور سے پوچھ گچھ کرنے سے پہلے `.onion` منزلوں کو مسترد کر دیتا ہے؛ ٹور آنیون سروسز کے لیے اس واضح نجی منزل کی سیٹنگ اور ایک مناسب پروکسی درکار ہوتی ہے۔ یہ DNS رویہ بیرونی HTTP آپریشنز پر لاگو ہوتا ہے، نہ کہ ٹیلیگرام کے ٹرانسپورٹ پر۔ کلود فلئیر [JSON DNS اینڈ پوائنٹ](https://developers.cloudflare.com/1.1.1.1/encryption/dns-over-https/make-api-requests/dns-json/) کو دستاویزی شکل دیتا ہے۔

****خودکار پول کے پیرامیٹرز****

**پیرامیٹرز → آٹومیٹک MTProxy** کے تحت ناکامی کی حد، کول ڈاؤن، منصوبہ بند گردش، پروکسی شیئرنگ اور اجازت یافتہ فال بیک تاخیر کو ترتیب دیں۔

| کنٹرول | ڈیفالٹ |
| --- | --- |
| متبادل سے پہلے منقطع | 3 کے اندر 10 منٹ |
| ہر کنکشن کی کوشش کے دوران آزمائے گئے پروکسیز | 3 |
| ناکامی کے بعد پہلی / زیادہ سے زیادہ آرام | 10 منٹ / 6 گھنٹے |
| منصوبہ بند گردش | غیر فعال؛ ناکامی پر فعال کریں |
| فی پروکسی اکاؤنٹس | 0: ترجیحاً الگ اندراجات استعمال کریں، ضرورت پڑنے پر شیئر کریں۔ 1 کو خصوصی اندراج کے لیے انتظار پر سیٹ کریں۔ |
| مجاز براہِ راست متبادل سے پہلے تاخیر | 10منٹ؛ Hide the address still refuses Direct |
| فیڈ ریفریش / ٹرانسپورٹ چیکس | 60/10 منٹ؛ مرکزی ورک اسپیس کی قدریں مشترکہ پول پر لاگو ہوتی ہیں۔ |

مختلف پراکسیز مختلف ایگزٹ ایڈریسز کی ضمانت نہیں دیتیں۔ یہ ترتیبات ٹیلیگرام کی حدود کو ختم نہیں کرتیں اور گمنامی ثابت نہیں کرتیں۔

پبلک لسٹ کو اپنی آپریٹر کیٹلاگ سے تبدیل کرنے کے لیے نیچے دی گئی اووررائیڈ کو کنفیگر کریں۔ یہ بیرونی سبسکرپشنز کو مکمل طور پر غیر فعال کر دیتا ہے، بشمول اس کے کہ جب اس کا `proxies` اری خالی ہو۔

[خالی کیٹلاگ کو](https://github.com/phishdestroy/TgWitness/blob/main/deploy/proxies.config.example)`proxy-config/proxies.json` پر کاپی کریں اور اپنے تعینات کردہ عوامی اینڈ پوائنٹس شامل کریں:

```
{"format": "tgwitness-proxy-catalog-v1", "proxies": [
  {"id": "project-eu", "label": "Project EU",
   "link": "tg://proxy?server=REPLACE_HOST&port=443&secret=REPLACE_SECRET"}
]}
```

مثال کے اقدار کو تبدیل کرنا ضروری ہے۔ زیادہ سے زیادہ 32 منفرد اندراجات قبول کیے جاتے ہیں۔ تصدیق شدہ فہرست لیبلز/ہوسٹس/پورٹس واپس کرتی ہے بغیر مشترکہ راز کے؛ ایک کو منتخب کرنے سے اس کی اسناد ورک اسپیس والٹ میں محفوظ ہو جاتی ہیں۔ دستیابیت ایک واضح ٹرانسپورٹ ٹیسٹ تک غیر آزمایا ہوا رہتا ہے۔ خراب ترتیب والا کیٹلاگ دستی کنفیگریشن کو دستیاب چھوڑ دیتا ہے۔

نیٹیو لانچ: مقامی JSON راستے کے لیے `TGWITNESS_PROXY_CATALOG` سیٹ کریں۔ ڈاکر:

```
docker compose -f compose.yaml -f deploy/compose/compose.proxies.yaml up -d --build
```

اوورلے صرف پڑھنے کے لیے`proxy-config` کو ماؤنٹ کرتا ہے؛ فائلوں کو کنٹینر UID 10001 کے ذریعے قابلِ مطالعہ ہونا چاہیے۔ یہ ڈائریکٹری Git، Docker بلڈ کنٹیکسٹ اور ماخذ آرکائیوز سے خارج ہے۔ یہ کیٹلاگ اکاؤنٹس کو جمع کرنے کے لیے ترتیب دیتا ہے؛ [وِٹنس بوٹ](https://phishdestroy.github.io/TgWitness/ur/docs/reference/witness/) اپنا HTTP/SOCKS5 راستہ استعمال کرتا ہے، MTProxy نہیں۔

براہِ راست واپسی اوپر بیان کردہ آئی پی موڈ کے تحت کنٹرول ہوتی ہے۔ راستہ تبدیل کرنے سے پہلے مشاہدہ معطل کریں۔ محفوظ شدہ راستہ پرانے کلائنٹس کو منقطع کر دیتا ہے اور نامکمل لاگ ان کو منسوخ کر دیتا ہے؛ ایک نیا کلائنٹ محفوظ شدہ راستے کا استعمال کرتا ہے۔ اکاؤنٹ کا جرنل/سیشن بائنڈنگ برقرار رہتا ہے۔ ترتیبات پچھلے راستے کی جگہ لے لیتی ہیں: اسے ترمیم کرتے وقت پروکسی کی تفصیلات دوبارہ درج کریں۔

سندیں '`network.enc`' میں خفیہ کردی جاتی ہیں۔ API صارف نام، پاس ورڈ یا سیکرٹ واپس نہیں کرتی۔ دستخط شدہ ریکارڈز میں راستے کی قسم اور اس بات کی نشاندہی ہوتی ہے کہ سندیں موجود ہیں یا نہیں، جبکہ اینڈ پوائنٹ اور سیکرٹس شامل نہیں ہوتے۔ آپریٹر پینل میں اینڈ پوائنٹ دیکھ سکتا ہے۔ سیکرٹ فیلڈز محفوظ کرنے، لاک کرنے یا ورک اسپیس تبدیل کرنے کے بعد صاف ہو جاتی ہیں۔

**ٹیسٹ ٹیلیگرام کنکشن**، جو لاگ ان سے پہلے بھی دستیاب ہے، راستے کے ذریعے ایک عارضی غیر مجاز ٹیلیگرام کنکشن کھولتا اور بند کرتا ہے۔ یہ کسی آئی پی چیک ویب سائٹ سے رابطہ نہیں کرتا۔ کامیابی سے صرف ٹرانسپورٹ کنیکٹیویٹی قائم ہوتی ہے، نہ کہ گروپ تک رسائی، مکمل ترسیل یا گمنامی۔

پراکسی ٹیلیگرام کلائنٹ کے کنکشنز پر لاگو ہوتی ہے، بشمول ٹیلیگرام ڈی سی میڈیا ڈاؤن لوڈز۔ براؤزر، پی آئی پی، ایس ایس ایچ اور دستی طور پر چلائے جانے والے ٹی ایس اے ٹولز کے الگ راستے ہیں۔ پراکسی ہوسٹ نیم کو مقامی طور پر حل کیا جا سکتا ہے۔ `rdns` منزل کے ہوسٹ نیمز کو متاثر کرتا ہے؛ ٹیلیگرام اکثر عددی ڈی سی آئی پیز فراہم کرتا ہے۔

SOCKS5 اور سادہ HTTP CONNECT خود پروکسی کی شناختی معلومات یا کلائنٹ سے پروکسی ٹنل کو انکرپٹ نہیں کرتے۔ MTProto الگ سے ٹیلیگرام ٹریفک کو محفوظ کرتا ہے۔ ایک غیر قابلِ اعتماد نیٹ ورک پر پروکسی کے لیے ایک مناسب محفوظ چینل استعمال کریں۔ نجی گروپس کلاؤڈ چیٹس ہیں؛ MTProto انہیں اینڈ ٹو اینڈ انکرپٹڈ سیکرٹ چیٹس میں تبدیل نہیں کرتا۔

## انکرپشن اور دستخط

| تہہ | لاگو کیا گیا | آپریٹر کی ذمہ داری |
| --- | --- | --- |
| ٹیلیگرام ٹریفک | ٹیلی تھون MTProto | پلیٹ فارم کا اعتماد، راستہ اور دستیابی |
| ویب پینل | بیئرر ٹوکن، لوپ بیک ڈیفالٹ، درخواست کی حدیں | دور دراز رسائی کے لیے HTTPS یا SSH سرنگ |
| راز | API کی شناختی معلومات، سیشن، پروکسی کی شناختی معلومات اور دستخطی نجی کلید کے لیے فرنیٹ | ڈیکرپشن کلید اور چلنے والے ہوسٹ کا تحفظ کریں |
| والٹ کی | مقامی کلید، یا نئی تنصیب کے لیے بیرونی ماسٹر کلید | محفوظ ذخیرہ اور کلید کے بیک اپ کو الگ کریں |
| پیغامات اور منسلکات | سادہ متن کی درخواست اسٹوریج | انکرپٹڈ ڈسک/والیوم |
| ZIP/JSONL/CSV/HTML | سالمیت کی جانچ، کوئی مواد انکرپشن نہیں | برآمد شدہ نقول اور منتقلیوں کا تحفظ |
| ماخذیت اور وقت | دستخط شدہ جرنل، پراسیس رسید، RFC 3161 ٹولز | اعتماد شدہ کلید، آزاد چیک پوائنٹس/TSA اور تحویل کا طریقہ کار |

اکاؤنٹ میں **اسٹوریج تحفظ** ان ریاستوں کو دکھاتا ہے۔ پینل ٹوکن ایک رسائی راز ہے، انکرپشن پاس ورڈ نہیں۔ یہ منتظم کو رسائی فراہم کرتا ہے؛ [جاری کردہ ٹوکنز](https://phishdestroy.github.io/TgWitness/ur/docs/reference/access/) کو اکاؤنٹس اور چیٹس تک محدود کیا جا سکتا ہے۔ ورک اسپیسز ہوسٹ پراسیس شیئر کرتے ہیں اور الگ الگ کرایہ دار نہیں ہوتے۔

BitLocker، LUKS، FileVault یا ایک منظم انکرپٹڈ والیوم اپنے متعلقہ خطرے کے ماڈلز کے تحت اسٹوریج کی حفاظت کر سکتے ہیں۔ ایک انلاک شدہ چلتی ہوئی مشین کا منتظم پھر بھی ڈیٹا پڑھ سکتا ہے۔ اسٹوریج کی منصوبہ بندی میں SQLite WAL/SHM، میڈیا، عارضی ایکسپورٹس، سوئپ، بیک اپس اور براؤزر ڈاؤن لوڈز کو شامل کریں۔ ایک ڈاکر والیوم صرف اس لیے انکرپٹڈ نہیں ہوتا کیونکہ یہ ایک والیوم ہے۔ TgWitness، SQLCipher یا آبجیکٹ انکرپشن کو نافذ نہیں کرتا۔

## بیرونی ماسٹر کلید

**نئی** تنصیب کے لیے، ماسٹر کی کو ڈیٹا ڈائریکٹری کے باہر رکھیں۔ یہ خودکار طور پر موجودہ لوکل-کی والٹ کو منتقل نہیں کرتا۔ ایک کی ڈائریکٹری تیار کریں جس تک صرف سروس شناختی نام کی رسائی ہو، پھر چلائیں:

```
python -m tgwitness.security create-master-key /private/keys/tgwitness-master.key
export TGWITNESS_VAULT_KEY_FILE=/private/keys/tgwitness-master.key
python -m tgwitness --data-dir /private/observations/new-case
```

پاور شیل، انسٹال شدہ پروجیکٹ ماحول استعمال کرتے ہوئے:

```
python -m tgwitness.security create-master-key E:\PrivateKeys\tgwitness-master.key
$env:TGWITNESS_VAULT_KEY_FILE = 'E:\PrivateKeys\tgwitness-master.key'
python -m tgwitness --data-dir E:\PrivateData\new-case
```

Docker میں، فائل کو `/data` کے باہر صرف-پڑھنے کے لیے ماؤنٹ کریں، مثال کے طور پر `/run/secrets/tgwitness-master.key` پر، اور ماحول کا متغیر اسی راستے پر سیٹ کریں۔ سروس UID کو اسے پڑھنے کے قابل ہونا چاہیے۔ ماحول/تشکیلاتی فائلوں کے ذریعے راستہ بھیجیں، نہ کہ کلید کے بائٹس۔

ہر ورک اسپیس کو ایک بے ترتیب عوامی سالٹ اور اپنی مخصوص فرنیٹ کلید ملتی ہے جو HKDF-SHA256 کے ذریعے حاصل کی جاتی ہے۔`vault.external.json` صرف ڈی ریویشن میٹا ڈیٹا محفوظ کرتا ہے، ماسٹر کلید نہیں۔ اگر کلید غائب ہو یا غلط ہو تو یہ خاموشی سے اسے تبدیل کیے بغیر آغاز کرنے میں ناکام رہتا ہے۔ بحالی کے لیے سالٹ میٹا ڈیٹا اور ماسٹر کلید دونوں کو محفوظ رکھیں۔

تمام ورک اسپیسز ایک ہی ماسٹر کی سے مشتق ہیں؛ اس کے سمجھوتے سے پوری تنصیب متاثر ہوتی ہے۔ چلنے والا عمل راز کو ڈیکرپٹ کر سکتا ہے۔ یہ HSM یا پاس ورڈ KDF نہیں ہے۔ بے ترتیب کلید کے متبادل کے طور پر کسی بھی انسانی پاس ورڈ کو قبول نہیں کیا جاتا۔

موجودہ تنصیبات کے لیے موجودہ کلید کو تب تک برقرار رکھیں جب تک کہ ایک جان بوجھ کر منتقلی عملدرآمد اور تصدیق نہ ہو جائے۔ `vault.key` کو حذف کرنے یا ماسٹر کلید کو تبدیل کرنے سے سیشنز/دستخطی کلیدوں تک رسائی ختم ہو سکتی ہے۔ انکرپٹڈ بیک اپ اور کلیدوں کو الگ الگ رکھیں اور ایک الگ ماحول میں بحالی کا ٹیسٹ کریں۔
