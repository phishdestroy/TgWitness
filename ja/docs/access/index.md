# 事例を共有する

Canonical page: https://phishdestroy.github.io/TgWitness/ja/docs/access/

必要なケースを共有し、それ以外の情報は管理下に置いておきましょう。

01**証拠を選択してください**

アカウント全体のワークスペース、または個別の記録済みチャットを選択できます。

02**操作を選択してください**

閲覧、エクスポート、またはその人物が必要とする特定の操作権限を許可します。

03**制限を設定する**

有効期限、セッション制限、およびオプションのIP制限を設定した個人用トークンを発行します。

収集範囲によって、何が記録されるかが決まります。アクセス範囲によって、ユーザーが何を閲覧・操作できるかが決まります。

## アクセス権を付与する

1. 管理者としてログインし、「**Access」**を開いてください。
2. アクセス権限を指定し、ワークスペースとチャットを選択してください。
3. レビュー担当者のために「**表示」**機能を残してください。記録をダウンロードする必要がある場合は、「**エクスポート」**機能を追加してください。
4. 制限を設定し、「**アクセスを作成」**をクリックしてください。
5. 表示されたトークンを一度コピーしてください。パネルのアドレスと共に、非公開で送信してください。
6. 引き渡す前に、別のブラウザセッションで表示が許可されているかご確認ください。

## まず、彼らが遂行すべき業務から始めましょう

| 人物 | アクセス | 結果 |
| --- | --- | --- |
| レビュー担当者 | 選択されたチャット；閲覧専用 | 収集内容を変更することなく、キャプチャされた会話を閲覧できます。 |
| アナリスト | 選択したチャット：表示およびエクスポート | 事件の調査に必要な記録を確認し、ダウンロードしてください。 |
| オペレーター | 選択されたワークスペース全体、ソースおよび収集内容 | 監視対象を管理し、コレクターの起動や停止を行ってください。 |

これらは固定された役割ではなく、ユーザーが選択する設定です。アカウント全体の設定およびジャーナルの完全なエクスポートについては、他の権限が有効になっている場合でも、チャット限定のアクセス権の範囲外となります。すべてのワークスペースへのアクセス権には、将来作成されるアカウントも含まれます。

## いつでも考えを変えることができます

アクセス権限を編集して、その後のリクエストで実行できる操作を変更できます。1つのセッションを終了するか、アクセス権限全体を取り消してすべてのセッションを終了させることができます。すでにダウンロードされたファイルは取り消すことができません。パネルセッションを終了しても、データの収集は停止されません。

**セッションおよびIPアドレスの制限**

同時セッション数やログイン成功回数を制限したり、絶対的な終了日を設定したり、IPアドレスやサブネットを許可したり、初回ログイン時のアドレスにアクセスを紐付けたりすることができます。セッションの有効期限は非アクティブ状態を基準としており、パネルが開いている状態でのポーリングはアクティビティとしてカウントされます。プロキシやトンネルを経由してアプリケーションを実行している場合は、アプリケーションに表示されるクライアントアドレスをご確認ください。

**メインキーとアクティビティログ**

管理者はメインパネルのトークンを保持します。アクセス権を付与されたユーザーは、他者のアクセス権を管理したり、管理者コンソールを開いたりすることはできません。コンソールには、ワークスペース全体にわたる現在のプロセス活動が表示されます。署名付きアクセス記録には、トークンを使用せずにアクセス許可およびセッションのイベントが保持されます。ワークスペースはホストプロセスを共有しており、サーバー管理者からデータを隔離することはありません。

7つの権限すべて、セッションルール、および管理者境界については、[権限リファレンスの全文](https://phishdestroy.github.io/TgWitness/ja/docs/reference/access/)をご参照ください。
