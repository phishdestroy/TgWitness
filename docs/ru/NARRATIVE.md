# Нарративы доказательств

`python -m tgwitness.narrative` создаёт изложение со ссылками на источники из **проверенного полного ZIP с доказательствами**. Сначала он подтверждает подлинность архива, затем создаёт PDF, HTML, JSON и четыре SVG-диаграммы. Переданный JSON с вердиктом он никогда не принимает в качестве доказательства. Непрошедшая проверка подписи, несогласованный манифест или противоречивые доказательства свидетеля останавливают генерацию.

```sh
python -m tgwitness.narrative evidence.zip --lang de --jurisdiction DE --out narrative-de/
python -m tgwitness.narrative evidence.zip --lang ru --fingerprint COLLECTOR_FP --witness witness.zip --witness-fingerprint WITNESS_FP --check-drand --check-bitcoin --out narrative-ru/
```

Получайте отпечатки независимо. Пакет без закреплённого ключа можно описать, но отсутствие закрепления видно как ограничение. Инструкции в отчёте используют `TRUSTED_COLLECTOR_FP` и `TRUSTED_WITNESS_FP`; встроенный ключ они никогда не превращают в независимое решение о доверии. `--tsa-ca ROOT.pem` включает существующую проверку корня RFC 3161. Внешние проверки используют существующую модель доверия верификатора; см. [FOR-THE-RECORD.md](FOR-THE-RECORD.md).

Каталог назначения должен быть пустым. Генерация подготавливает все выходные файлы целиком, прежде чем поместить их в этот каталог. Она не перезаписывает другой отчёт, не обращается к Telegram, не отправляет запросы меток времени, не отправляет почту и ничего не публикует. Сетевые проверки выполняются только по запросу. Входной ZIP не меняется. Результат — производный отчёт, а не новый пакет доказательств, независимо заверенный свидетелем.

## Сохранённые профили конфигурации

Для сохранения параметров представления и требований к проверке используйте явно указанный локальный JSON-файл. См. [пример конфигурации](../examples/narrative.json) и [инструкции на русском языке](NARRATIVE.md).

```sh
python -m tgwitness.narrative --write-config narrative-config.json
python -m tgwitness.narrative --config narrative-config.json --profile ru-html --print-config
python -m tgwitness.narrative evidence.zip --config narrative-config.json --profile ru-html --out narrative-ru/
python -m tgwitness.narrative evidence.zip --config narrative-config.json --profile de-proof --fingerprint COLLECTOR_FP --witness witness.zip --witness-fingerprint WITNESS_FP --out narrative-de/
```

Порядок приоритета: встроенные значения по умолчанию → `defaults` из файла → именованная запись из `profiles` → явные параметры CLI. Загружается только файл, указанный в `--config`; конфигурация внутри архива доказательств никогда не исполняется и не применяется. Относительные пути к архиву свидетеля и TSA CA в файле отсчитываются от каталога этого файла; пути в CLI — от каталога запуска. `--write-config` отказывается заменять существующий файл. `--print-config` показывает действующие настройки, не открывая пакет доказательств и не выполняя сетевых запросов.

| Параметр | CLI | По умолчанию / значение |
|---|---|---|
| `lang`, `jurisdiction` | `--lang`, `--jurisdiction` | `en`, без юрисдикции; `--jurisdiction none` сбрасывает юрисдикцию профиля |
| `outputs` | `--outputs html json svg` | `pdf html json svg`; требуется хотя бы один из форматов PDF, HTML или JSON |
| `diagrams` | `--diagrams timeline flow ladder files` | Все четыре; `--diagrams none` убирает рисунки, если вывод SVG не выбран |
| `max_records` | `--max-records` | 100000 на журнал, допустимо 1–1000000; при превышении генерация останавливается без усечения отчёта |
| `scene_max_records` | `--scene-max-records` | 2000, допустимо 1–10000; ограничивает число сгруппированных записей до добавления перекрёстных ссылок на перезапуски |
| `fingerprint`, `witness`, `witness_fingerprint`, `tsa_ca` | Существующие флаги с именами через дефис | Независимо переданные входные данные доверия; отпечатки должны быть шестнадцатеричными SHA-256 в нижнем регистре |
| `check_drand`, `check_bitcoin` | `--check-drand`, `--check-bitcoin` | `false`; соответствующий параметр `--no-check-…` отменяет `true` из профиля |
| `require_tier` | `--require-tier` | `self_attested`; требования не создают доказательств и неявно не включают сетевые запросы |
| `require_pinned_signer` | `--require-pinned-signer` / `--no-require-pinned-signer` | `false`; если требуется, нужно передать независимо закреплённый ключ коллектора или проверенного совпадающего закреплённого свидетеля |
| `expert`, `procedure` | `--expert` / `--no-expert`, `--procedure criminal\|civil` | `false`, `criminal`; добавляет [протокол экспертного исследования](#expert-examination-protocol) для выбранной юрисдикции и вида процесса |

Пример `de-proof` запрашивает внешние проверки и требует `witness_anchored` и доверенное закрепление. Архив без этих доказательств он отклонит. Одного лишь указания отпечатка свидетеля без соответствующего архива свидетеля недостаточно для выполнения требования о закреплении. Вывод только в JSON избавляет от требований к шрифтам для PDF. Выбор диаграмм не убирает текстовую лестницу уверенности, ограничения и ссылки на события. Форматы и языки не меняют машинную модель сцен; изменение размера сцены меняет только группировку. Сцена разрыва также ссылается на следующий записанный перезапуск, даже если эта дополнительная перекрёстная ссылка превышает предел группировки.

Каждый успешный запуск также записывает **`narrative-run.json`**: действующие настройки представления и проверок, их SHA-256, хеши входных пакетов, хеш TSA CA, если он передан, статус закрепления и достигнутый уровень. Локальные пути к архиву свидетеля и CA не включаются. Это неподписанная квитанция о запуске, а не внешняя аттестация. Она создаётся даже при выводе только в PDF или только в HTML. Хеш настроек описывает публичный объект настроек; хеши входных файлов — отдельные поля.

Коды выхода: **0** — генерация прошла успешно; **1** — сбой проверки пакета, превышение предела записей или сбой отрисовки; **2** — недопустимая конфигурация или невыполненные требования к закреплению или уровню. Неизвестные поля, повторяющиеся ключи JSON, недопустимые типы и конфигурации больше 64 КиБ отклоняются. Настроек, позволяющих пропустить проверку подписи, скрыть ограничения, повысить вердикт или отметить переводы как вычитанные, нет. Сохранённые профили и параметры CLI не изменяют подписанный входной архив.

Тесты конфигурации охватывают приоритет и пути, выборочный вывод, сохранность ограничений и ссылок без диаграмм, ограниченную группировку, переполнение по записям, недопустимые настройки, подделку архива и коды выхода CLI. Подписанные тестовые данные коллектора и свидетеля проверяют профиль с обязательным `witness_anchored` при подтверждённых, отсутствующих и несовпадающих обязательствах; внешние сетевые ответы в этих тестах синтетические.

## Как читать отчёт

Читайте введение, хронологию, проверки уверенности, ограничения и команды проверки в этом порядке. Юрисдикционная терминология необязательна. Приложение идентифицирует каждую процитированную запись по журналу, порядковому номеру и полному SHA-256. SHA-256 исходного пакета указан в начале. Порядковые номера коллектора и свидетеля относятся к разным пространствам имён.

Записанное утверждение описывается как записанное утверждение. Событие документа с `signature_claimed: qualified` и `signature_objects: 0` **не** превращается в вывод о том, что PDF не подписан, подделан или юридически недействителен. Модуль отрисовки не проверяет подписи PDF самостоятельно, не валидирует QES или DKIM и не восстанавливает более раннюю дату получения. Внешние файлы привязки засчитываются, только если верификатор их действительно проверяет. Отправленная, но ещё не подтверждённая заявка OTS остаётся неподтверждённой.

Счётчики описывают виды событий. Новые сообщения, правки, уведомления об удалении и отсутствие при перепроверке остаются разными категориями, а записи об охвате описывают непрерывность. Неизвестные события сохраняют ссылки на источники и примечание об интерпретации. Даты в сценах берутся из подписанных метаданных событий; проверенные метки времени ограничивают их извне. Даты Bitcoin — это даты заголовков блоков.

В HTML-хронологии ссылки на события доступны для фокуса с клавиатуры и наведения указателя. У каждого SVG есть заголовок и описание. PDF использует выделяемый текст и ту же геометрию рисунков; он не зависит от браузера или сервиса преобразования SVG. Генерация PDF на японском использует существующий в проекте поиск шрифтов CJK; нужен подходящий установленный шрифт. Новых зависимостей от пакетов не добавлено.

## Протокол экспертного исследования

`--expert` добавляет к нарративу черновик заключения эксперта. Эксперт запускает его на своём компьютере, со своей копией пакета и своей установкой: верификатор сначала проверяет пакет, и протокол фиксирует только то, что установил этот запуск. Протокол, составленный коллектором, был бы описанием собранного материала самой собиравшей стороной; значение имеет запуск эксперта.

```sh
python -m tgwitness.narrative evidence.zip --lang ru --jurisdiction RU --expert --procedure criminal --fingerprint COLLECTOR_FP --out protocol-ru/
python -m tgwitness.narrative evidence.zip --lang uk --jurisdiction UA --expert --procedure civil --fingerprint COLLECTOR_FP --tsa-ca tsa-root.pem --out protocol-uk/
```

Запуск создаёт `expert-protocol.html`, `expert-protocol.pdf` и `expert-protocol.json` рядом с нарративом, по выбору `--outputs`. В протоколе:

| Часть | Содержание |
| --- | --- |
| Вводная часть | Пустые поля для дела, органа, назначившего экспертизу, ФИО эксперта, образования, специальности, стажа и сроков исследования; правовые основания назначения, вопросов, содержания заключения и обязанностей эксперта; обязательное содержание заключения в юрисдикции в виде списка для отметок; предупреждение об ответственности на языке суда со строкой для подписи; декларация, если её требуют правила; SHA-256 пакета, вычисленный при исследовании |
| Методы и стандарты | Версия TgWitness и SHA-256 исходного кода использованного верификатора; SHA-256 (FIPS 180-4), Ed25519 (RFC 8032), метки времени (RFC 3161) и цепочки сертификатов (RFC 5280), OpenTimestamps по заголовкам блоков Bitcoin; стандарты цифровых доказательств, принятые в юрисдикции. Каким стандартам следовало исследование, указывает эксперт |
| Ход исследования | Команды, которые повторяют каждую проверку на другой копии. Отпечатки, переданные экспертом, подставлены; иначе в командах остаются `TRUSTED_COLLECTOR_FP` и `TRUSTED_WITNESS_FP`, потому что отпечаток из самого пакета лишь повторил бы утверждение пакета |
| Выводы | Три группы. **Установлено вычислением**: целостность и время, подтверждённое третьей стороной. **Установлено при условии**: ключ коллектора (отпечаток получен заранее по другому каналу), сохранённая контрольная точка, независимый свидетель и аттестованный запуск сбора, у каждого указано условие. **За пределами исследования**: авторство, полнота вне записанных периодов, достоверность содержания, законность сбора и личность пользователей аккаунтов. Третья группа печатается всегда |
| Подпись | Пустые поля ФИО, даты и подписи. Эксперт может добавить подпись своим сертификатом; ключ коллектора подписывает журнал, но никогда не заключение эксперта |
| Приложение A | Вопросы для постановления о назначении экспертизы: на какие пакет отвечает, с проверкой, которая даёт ответ, и на какие не отвечает, с причиной |
| Приложение B | SHA-256 файла `narrative-run.json` этого запуска |

HTML и JSON не содержат времени генерации. Та же версия TgWitness, тот же пакет и те же входные данные дают побайтово одинаковые HTML и JSON, поэтому второй эксперт может повторить исследование и сравнить файлы. PDF хранит дату создания в метаданных.

Каталог [`tgwitness/narrative/examination/`](../../tgwitness/narrative/examination/README.md) содержит по файлу на юрисдикцию: назначение эксперта, вопросы, обязательное содержание заключения, обязанности эксперта, закон о судебно-экспертной деятельности, ответственность за заведомо ложное заключение с текстом предупреждения, обязательную декларацию, стандарты цифровых доказательств, закон об электронной подписи и метках времени. У каждой записи указаны официальный источник, дата проверки и статус проверки, а в `open_questions` перечислено то, что не удалось подтвердить по официальному тексту. Записи подготовлены с помощью машинного поиска и не проверены местным юристом; протокол печатает этот статус и просит эксперта сверить каждую ссылку с действующим официальным текстом.

Каталог охватывает 53 юрисдикции: AE, AT, AU, BD, BE, BG, BR, CA, CH, CN, CZ, DE, DK, EE, ES, ET, FI, FR, GR, HK, HU, ID, IE, IL, IN, IR, IT, JP, KR, LT, LV, MX, MY, NL, NO, PH, PK, PL, PT, RO, RU, SA, SE, SG, SK, TH, TR, TW, UA, UK, US-federal, UZ, VN. `UK` означает Англию и Уэльс; `US-federal` охватывает федеральные суды. Там, где официальные порталы прочитать не удалось, записи AE, BG, GR, IT, SG, TH и VN состоят в основном из открытых вопросов, и протокол печатает эти вопросы, чтобы эксперт их проверил.

`--jurisdiction` принимает коды обоих каталогов. Раздел терминологии в нарративе выводится для 14 каталогов терминологии, перечисленных ниже; протокол эксперта берёт данные из каталога экспертиз.

## Шаблоны и юрисдикции

Есть 39 полных каталогов фраз и соответствующих глоссариев. Поддерживаемые языки: en, de, fr, es, it, pt, nl, pl, cs, sk, uk, ru, ro, bg, hu, el, sv, da, fi, no, lt, lv, et, tr, ja, zh, zh-Hant, ko, ar, he, fa, hi, ur, bn, id, ms, vi, th, uz. Отчёты на арабском, иврите, персидском и урду идут справа налево. Для PDF на китайском и корейском, как и на японском, нужен установленный шрифт CJK; HTML и JSON обходятся без него. В 14 языках, добавленных для судов, число записей сцены пишется как «записей журнала: N», что не требует форм множественного числа. Для `no` используются формулировки на букмоле. Для `pt` используется общее правило количественных числительных CLDR для португальского языка. Шаблоны поддерживают ограниченное **подмножество ICU для множественного числа**, используемое в этих каталогах, включая вложенные подстановки и ветви для точных чисел; это не полная реализация всех форматтеров ICU. Правила для количественных числительных следуют [Unicode CLDR](https://www.unicode.org/cldr/charts/48/supplemental/language_plural_rules.html).

Программа проверки сравнивает ключи и подстановки, отрисовывает формы множественного числа, проверяет длину фраз и применяет переданные списки запрещённых слов. Каждый язык, включая английский и немецкий, явно помечен как **переведённый с машинной помощью и не вычитанный**. Механические тесты проверяют ключи, подстановки и длину фраз; юридическую вычитку и вычитку носителем языка они не заменяют.

Юрисдикционные каталоги содержат терминологию и ссылки на официальные источники, проверенные 2026-11-06. Они охватывают DE, AT, CH, UK, IE, FR, ES, IT, PL, CZ, UA, NL, BE и US-federal. Каталог `UK` явно ограничен **гражданским судопроизводством Англии и Уэльса**; Шотландию и Северную Ирландию он не представляет. Для CH сейчас предоставляется терминология электронной подписи, а не полное руководство по швейцарскому процессу. Отсутствующие местные термины остаются null. Региональный орган по защите данных не угадывается. Сроки ответа на запрос доступа по GDPR не закодированы как универсальный 30-дневный срок; [руководство EDPB](https://www.edpb.europa.eu/system/files/2023-04/edpb_guidelines_202201_data_subject_rights_access_v2_en.pdf) отдельно разъясняет применимое правило одного месяца. Доказательство OTS не классифицируется автоматически как квалифицированная метка времени по eIDAS.

Смена юрисдикции влияет только на юрисдикционный раздел и его ссылки на источники. Смена языка не меняет машинную модель сцен. Раздел — справочная таблица, а не юридическое заключение и не процессуальный чек-лист.

## Требования к выпуску, которые ещё не выполнены

Списки запрещённых слов T7 и схема цепочки хранения/спецификации T13 не предоставлены. Существующие события `custody.*` получают общие описания со ссылками на источники; совместимость с отсутствующей схемой не заявляется. Глоссарий нарративов готов к повторному использованию, но общий интерфейс T7/T14 нельзя протестировать без этих спецификаций.

Проверка готовности к выпуску остаётся незавершённой, пока не задокументированы интеграция T7 и T13 и юридическая вычитка носителями языка для en/de/fr/uk/ru. Тест чтения вслух человеком и десятиминутное исследование понятности не проводились. Функция является черновиком для рецензирования, а не готовой к выпуску реализацией этих зависимостей.

Запрошенный пример включает шесть различных видов сцен и сбор по обе стороны перерыва. При сохранении этого каталога получается семь хронологических сцен, а не пять. Эталонный тестовый набор (golden fixture) фиксирует это явно, а не объединяет несвязанные события ради произвольного числа. Записанные пары остановки и запуска продлевают сцену разрыва до следующего записанного запуска; их даты остаются утверждениями по часам компьютера, а не независимо доказанным временем простоя.

Тесты охватывают эталонную модель, все 25 выводов PDF/HTML, неизменность числа сцен для разных языков, граничные случаи множественного числа, точные ссылки на записи, независимые разделы DE/AT/CH, экранированную разметку, непроверенные утверждения и ранее существовавший подписанный архив старого формата. Выходные нарративы сохраняют хеши и маскируют контакты с помощью детекторов, используемых при передаче; они не являются универсальным сервисом анонимизации произвольных имён, встречающихся в именах файлов или строках полезной нагрузки.
