# Загрузить историю источников

Canonical page: https://phishdestroy.github.io/TgWitness/ru/docs/reference/history/

Загрузка прошлых сообщений из включенных источников, приостановка и возобновление, а также проверка подписанного отчета о ходе работы.

**Текущая основная версия:** доступна из исходного кода; не включена в портативную предварительную версию 0.7.0.

В разделе **«Источники**» просмотрите включенные чаты, начните наблюдение, а затем выберите **«Загрузить полную историю**». При запуске программа фиксирует этот список источников и загружает доступные прошлые сообщения в раздел «Чаты» и в подписанный журнал наблюдения. Для мультимедиа используются существующие настройки вложений и постоянная очередь загрузки. Это отдельно от подписанного экспорта в формате JSON/HTML для каждого чата.

Для сбора данных по всему аккаунту выберите **«Весь аккаунт**», начните наблюдение, чтобы загрузить список источников, и проверьте этот список перед запуском сбора истории. Ограничение на количество диалогов по-прежнему действует (по умолчанию 1 000, настраивается в разделе «Параметры»). Успешное выполнение не гарантирует, что все диалоги аккаунта были включены в список. Для чатов, обнаруженных или включенных позже, требуется повторное выполнение.

## Приостановка, возобновление и частичные результаты

- **При нажатии «Пауза»** чтение **истории** приостанавливается. При нажатии **«Продолжить» чтение** возобновляется с последнего зафиксированного сообщения в каждом источнике; при перезапуске приложения процесс также остается в режиме паузы до момента возобновления. Сначала необходимо перезапустить наблюдение. Для возобновления требуется тот же аккаунт Telegram.
- Наблюдение за сообщением, обработка вложений и фиксация положения курсора выполняются в одной транзакции. При возобновлении выполнения уже зафиксированные наблюдения не повторяются. В режиме реального времени или в рамках отдельного, явно запущенного цикла могут независимо наблюдаться одни и те же сообщения.
- Каждый источник фиксирует максимальный идентификатор сообщения при первом чтении. Более поздние сообщения относятся к реальному мониторингу, а не к оставшимся страницам истории данного источника.
- Недоступные источники и источники, отключенные во время сбора данных, остаются видимыми как «неудачные» или «пропущенные». Работа с остальными источниками продолжается; общий результат является неполным.
- Задержки FloodWait соблюдают настройки отсрочки для сохраненных учетных записей. Таймауты при передаче данных и недостаток места на диске приостанавливают работу с сохранением курсора. Возобновление происходит после устранения причины.
- **Остановка текущего цикла обработки** сохраняет сохраненные наблюдения. Она не удаляет их и не отменяет загрузку вложений, уже находящихся в очереди. При новом цикле обработки источники, для которых включена функция считывания, обрабатываются заново.

Завершение истории описывает только чтение истории. Вложения могут оставаться в ожидании, завершиться сбоем или быть исключены в соответствии с настроенной политикой. Проверяйте подтверждения получения медиафайлов в журнале и в очереди вложений; только завершенное подтверждение с сохраненными байтами считается сохраненным вложением. Операция с историей представляет собой явный запрос на создание моментального снимка и не связана с параметрами, выбирающими категории будущих событий в режиме реального времени.

## Передача и проверка

Сохраните **подписанный отчёт о ходе работы**, а затем воспользуйтесь **функцией «Экспорт доказательств»**, чтобы загрузить журнал и сохраненные вложения. Более поздний экспорт доказательств может включать дополнительные записи; отчёт привязывает свои счетчики к префиксу журнала на момент его создания. Запустите верификатор из надёжной копии этой версии:

```
python tgwitness/verify.py tgwitness-history-report.json --evidence evidence.zip --fingerprint TRUSTED_FINGERPRINT
```

Сохраняйте ожидаемый отпечаток ключа подписи отдельно. Верификатор проверяет подпись отчета, архив доказательств, контрольную точку отчета, план источников, учетную запись и количество сохраненных/недоступных сообщений. Без `--evidence` он проверяет только подписанный отчет и его внутреннюю согласованность. Этапы выполнения, заголовки, курсоры и сводки вложений являются подписанными заявлениями сборщика, а не независимо реконструированными данными данной программой проверки отчетов. Проверяющий доказательства по-прежнему проверяет заархивированные байты мультимедиа.

Ни подписание, ни завершение доступной истории не подтверждают происхождение из Telegram, наличие «атомарного» моментального снимка или историческую полноту. Сообщения могут изменяться во время чтения; удаленные сообщения, незамеченные промежуточные правки и секретные чаты не восстанавливаются. Оператор, контролирующий ключ подписи, может сфабриковать журнал до появления внешних подтверждений. Используйте отдельно сохраненные контрольные точки или независимого свидетеля для подтверждения свойств обнаружения несанкционированного вмешательства.

Курсор сбора данных отражает состояние локальной рабочей области. Восстановление только ZIP-архива с доказательствами не приводит к восстановлению ожидающего выполнения задания на сбор данных или сеанса Telegram. Сохраните резервную копию рабочей области, если требуется продолжение выполнения исходного задания.
