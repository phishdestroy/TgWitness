যেখানে সবকিছু বাস করে

কলেক্টর, এর প্যানেল এবং প্রতিটি সংরক্ষিত রেকর্ড আপনি যে কম্পিউটার বা সার্ভারে এটি চালান সেখানেই থাকে। টেলিগ্রাম ডিফল্টভাবে একমাত্র গন্তব্য; অন্য প্রতিটি গন্তব্য একটি পৃথক সুইচ।

প্রতিটি গোপন কী খুলে

গোপনযেখানে এটি রাখা হয়এটি কী আনলক করেযদি এটি লিক করে
প্যানেল টোকেনpanel-token.txt ডেটা ডিরেক্টরিতে আছে; ব্রাউজার এটি শুধুমাত্র ট্যাবের জন্যই রাখে।প্রতিটি ওয়ার্কস্পেসে সবকিছু: পড়ুন এবং রপ্তানি করুন, স্কোপ পরিবর্তন করুন, অ্যাকাউন্টে সাইন ইন করুনTgWitness বন্ধ করুন, panel-token.txt মুছে ফেলুন, আবার চালু করুন: একটি নতুন টোকেন তৈরি হয়েছে
টেলিগ্রাম সেশনভল্ট, এনক্রিপ্টেড (credentials.enc)টেলিগ্রাম অ্যাকাউন্টটি নিজেইটেলিগ্রামে সেশনটি শেষ করতে সেটিংস → ডিভাইস-এ যান।
স্বাক্ষর কীভল্ট, এনক্রিপ্টেড (signing.enc)আপনার আঙ্গুলের ছাপের অধীনে যাচাইকৃত স্বাক্ষর রেকর্ডসমূহঅন্যান্য স্থানে রাখা চেকপয়েন্ট, একজন সাক্ষী এবং টাইমস্ট্যাম্পগুলো দেখায় আগে কী ছিল।
ভল্ট কীvault.keyডেটার পাশে, অথবা নতুন ডেটা ডিরেক্টরির জন্য একটি বাহ্যিক মাস্টার কীভল্ট ডিক্রিপ্ট করাসেশন কী এবং স্বাক্ষর কী-কেও ফাঁস হিসেবে বিবেচনা করুন।
সাক্ষী টোকেনসাক্ষী হোস্টেশুধুমাত্র পড়ার জন্য: স্বাক্ষরিত চেকপয়েন্ট এবং স্বাস্থ্যসাক্ষী পৃষ্ঠায় এটি মুছে ফেলুন; একটি নতুন তৈরি করুন।
অফ-সাইট কপি কীভল্ট; পুনরুদ্ধারের জন্য একবার ডাউনলোড করুনঅফ-সাইট কপি ডিক্রিপ্ট করাযে কেউ সংরক্ষিত বস্তুগুলোও ধারণ করে, সে সেগুলো ডিক্রিপ্ট করতে পারে: সেই অনুলিপিটিকে উন্মুক্ত বলে গণ্য করুন।

! তোমার জন্য রেখে গেছে

  • প্রধান প্যানেল টোকেন সম্পূর্ণ নিয়ন্ত্রণ রাখে। অন্যদের প্রয়োজনীয় অ্যাকাউন্ট, চ্যাট এবং ক্রিয়াকলাপে সীমিত প্রবেশাধিকার দিন; প্রধান কী ব্যক্তিগত রাখুন।
  • মেশিনের একজন প্রশাসক সবকিছু পড়তে পারে এবং জার্নাল পুনরায় লিখতে ও পুনরায় স্বাক্ষর করতে পারে। ফিঙ্গারপ্রিন্ট এবং চেকপয়েন্টগুলো অন্য একটি সিস্টেমে সংরক্ষণ করুন।
  • বার্তার টেক্সট এবং মিডিয়া TgWitness দ্বারা এনক্রিপ্ট করা হয় না। ডিস্ক এনক্রিপশন এবং কঠোর অনুমতি ব্যবহার করুন।
  • লোকালহোস্টের বাইরে সাধারণ HTTP নেটওয়ার্কে টোকেন প্রদর্শন করে। HTTPS বা SSH টানেল ব্যবহার করুন।
  • স্বাক্ষরগুলো প্রমাণ করে যে যা রেকর্ড করা হয়েছে তা পরিবর্তন হয়নি, তবে প্রতিটি টেলিগ্রাম ইভেন্ট রেকর্ড করা হয়েছে এমন নয়।

অনুমতি, মেয়াদোত্তীর্ণতা এবং সেশন সীমাসহ একটি মামলার অ্যাক্সেস শেয়ার করুন। একটি সাক্ষী টোকেন একটি পৃথক শংসাপত্র হিসেবে থাকে।

  1. একটি নিবেদিত টেলিগ্রাম অ্যাকাউন্ট ব্যবহার করুন — কখনই আপনার প্রধান অ্যাকাউন্ট নয়। প্যানেল টোকেন এবং সেশন এটিকে সম্পূর্ণ নিয়ন্ত্রণ দেয়।
  2. প্যানেলটিকে 127.0.0.1-এ রাখুন। এটি শুধুমাত্র HTTPS (সংযুক্ত Caddy কনফিগারেশন) অথবা একটি SSH টানেলের মাধ্যমে দূর থেকে অ্যাক্সেস করুন।
  3. ডেটা ডিরেক্টরি ধারণকারী ডিস্কটি এনক্রিপ্ট করুন: বার্তার টেক্সট এবং মিডিয়া যেভাবে এসেছে সেভাবে সংরক্ষণ করা হয়।
  4. ডেটা ডিরেক্টরিটি সার্ভিস অ্যাকাউন্টে সীমাবদ্ধ করুন। ইউনিক্সে নতুন ডিরেক্টরিগুলো মোড 0700 পায়; উইন্ডোজে ফোল্ডারের পারমিশন সেট করুন।

  6. স্বাক্ষর-কী ফিঙ্গারপ্রিন্ট এবং চেকপয়েন্টগুলো অন্য একটি সিস্টেমে সংরক্ষণ করুন, এবং অন্য একটি হোস্টে একজন সাক্ষী যোগ করুন।
  7. data/, সেশন, panel-token.txt বা ভল্ট কী কখনো GitHub-এ বা কোনো চ্যাটে আপলোড করবেন না।
  8. রিভার্স প্রক্সিতে Authorization হেডার বা অনুরোধের বডি লগ করবেন না।
আমি কি ডেটা হারানো ছাড়াই প্যানেল টোকেন পরিবর্তন করতে পারি?

হ্যাঁ। টোকেনটি শুধুমাত্র প্যানেলটি খোলে। TgWitness বন্ধ করুন, ডেটা ডিরেক্টরি থেকে panel-token.txt মুছে ফেলুন এবং এটি আবার চালু করুন; জার্নাল, সেশন এবং কীগুলো অক্ষত রয়েছে। TGWITNESS_TOKEN সেট থাকলে, ফাইলের পরিবর্তে পরিবেশের মান ব্যবহার করা হয়।

মেসেজগুলো বিশ্রামে কেন এনক্রিপ্ট করা হয় না?

সংগ্রাহককে সেগুলো পড়তে হবে অনুসন্ধান, সংস্করণ তুলনা এবং রপ্তানির জন্য। একই মেশিনে একটি কী দিয়ে সেগুলো এনক্রিপ্ট করলেও, সেই মেশিনটি পড়তে পারা কারো বিরুদ্ধে তা খুব একটা সুরক্ষা যোগ করবে না। ডিস্ক এনক্রিপশন বন্ধ বা চুরি হওয়া ডিস্ককে সুরক্ষিত রাখে; কঠোর অনুমতি ব্যবস্থা চলমান ডিস্ককে সুরক্ষিত রাখে।

একটি দুর্বলতা রিপোর্ট করুন

GitHub রিপোজিটরিতে Security → Report a vulnerability ব্যবহার করুন। সংস্করণ, প্রভাব এবং ন্যূনতম সিন্থেটিক পুনরুত্পাদন অন্তর্ভুক্ত করুন। কখনই ক্রেডেনশিয়াল, অ্যাকাউন্ট ডিরেক্টরি বা প্রকৃত প্রমাণের আর্কাইভ পাঠাবেন না। যদি ব্যক্তিগত রিপোর্টিং অনুপলব্ধ থাকে, তাহলে এক্সপ্লয়েটের বিবরণ ছাড়া ব্যক্তিগত চ্যানেলের অনুরোধ করে একটি ইস্যু খুলুন।
