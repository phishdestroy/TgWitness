# การเชื่อมต่อ, พร็อกซี และการคุ้มครองข้อมูล

Canonical page: https://phishdestroy.github.io/TgWitness/th/docs/reference/connection/

การยืนยันตัวตน, กลุ่มพร็อกซีอัตโนมัติ, โหมด IP, นโยบายสำรอง, คำขอจากภายนอก และการจัดเก็บข้อมูลลับ

เอกสารนี้อธิบายการทำงานและข้อจำกัดของ TgWitness 0.8.0 การยืนยันตัวตน, การเข้าถึงแหล่งข้อมูล, การเชื่อมต่อเครือข่าย และความครบถ้วนของการบันทึก เป็นสถานะที่แยกกัน สำหรับขั้นตอนการลงชื่อเข้าใช้ รูปแบบไฟล์ และบัญชีหลายบัญชี ให้เริ่มจาก [ส่วนบัญชีและรูปแบบเซสชัน](https://phishdestroy.github.io/TgWitness/th/docs/reference/accounts/) สำหรับนโยบายเหตุการณ์และพฤติกรรม เมื่อเริ่มต้นใหม่ ให้ดู[ส่วนวิธีการทำงานของการเก็บรวบรวมข้อมูล](https://phishdestroy.github.io/TgWitness/th/docs/reference/collection/)

## การตั้งค่าการเชื่อมต่อตามคู่มือ

ใน **Connection** ผู้ดูแลระบบสามารถเลือก **This account**, **An account group** หรือ **All accounts** แล้วเลือกเส้นทาง **Review selection** แสดงรายการ บัญชีที่ได้รับผลกระทบ **Prepare and check** ทดสอบเส้นทางที่เสนอโดยไม่เปลี่ยนแปลง เส้นทางที่บันทึกไว้ **Apply checked connection** ตรวจสอบอีกครั้ง หยุดการสังเกตการณ์หาก จำเป็น บันทึกเส้นทางและดำเนินการสังเกตการณ์ที่ยังทำงานอยู่ต่อ ระบบจะไม่เริ่มการเก็บข้อมูลในบัญชีที่ก่อนหน้านี้อยู่ในสถานะไม่ใช้งาน การดาวน์โหลดประวัติจะยังคง ถูกหยุดชั่วคราว และสามารถดำเนินการต่อได้แยกต่างหาก ให้หยุดการส่งออกที่กำลังทำงานอยู่ก่อนที่จะเปลี่ยน

การเปลี่ยนแปลงกลุ่มจะรักษาบัญชีให้ใช้เส้นทางเดิมตามค่าเริ่มต้น ให้ยกเลิกตัวเลือกนั้น เฉพาะเมื่อหน้าแสดงตัวอย่างแสดงการเปลี่ยนแปลงที่คุณต้องการเท่านั้น แอปพลิเคชันจะรายงานผลลัพธ์ของ แต่ละบัญชี; นี่ไม่ใช่การทำธุรกรรมแบบ "ทั้งหมดหรือไม่มีเลย" ที่ข้ามฐานข้อมูล การ เปลี่ยนที่ล้มเหลวจะคืนค่าการตั้งค่าเดิมของบัญชีนั้น การไม่สามารถดำเนินการต่อได้จะ แสดงอย่างชัดเจน การดูตัวอย่างจะหมดอายุหลังจากสิบนาที และการเปลี่ยนแปลงการตั้งค่า การเชื่อมต่อหรือสมาชิกกลุ่มจำเป็นต้องตรวจสอบใหม่

| เส้นทาง | TgWitness จัดการอะไร |
| --- | --- |
| ตรงไปตรงมา | การเชื่อมต่อจากเครื่องโฮสต์; ไม่ตรวจพบหรือบังคับใช้ VPN ของเครื่องโฮสต์ภายนอก |
| VPN | โปรไฟล์ WireGuard แบบ full-tunnel หนึ่งชุดต่อบัญชีหนึ่งบัญชี ซึ่งดำเนินการโดยกระบวนการ SOCKS5 ในพื้นที่ผู้ใช้ท้องถิ่น ไม่มีการติดตั้งอินเทอร์เฟซหรือไดรเวอร์ของโฮสต์ |
| พร็อกซีของฉัน | ข้อมูลรับรอง SOCKS5, HTTP CONNECT หรือ MTProxy. URL สามารถกรอกลงในช่อง SOCKS5/HTTP ได้ การเลือกหลายบัญชีจะแบ่งปันพร็อกซีที่กรอกนี้ร่วมกัน |
| MTProto สาธารณะ | กลุ่มที่มีอยู่จะกำหนดเส้นทางTelegram คำขอจากภายนอกจะถูกปิดจนกว่าจะมีการกำหนดค่าพร็อกซีที่เหมาะสมแยกต่างหากในส่วนการตั้งค่าขั้นสูง |
| WARP | สร้างอุโมงค์ท้องถิ่นแยกต่างหากสำหรับแต่ละบัญชีที่เลือก พร้อมการลงทะเบียน WARP และโปรไฟล์ WireGuard ที่เก็บไว้ใน vault ของบัญชีนั้น |

การตรวจสอบเส้นทางปัจจุบันใช้การขนส่งTelegram ที่ใหม่และยังไม่ได้รับการยืนยันตัวตน ไม่ใช่ เซสชันของบัญชี สำหรับเส้นทางที่รองรับHTTP มันยังขอการติดตาม HTTPS ของ Cloudflare ผ่านเส้นทางนั้น และแสดง IP ทางออกที่รายงาน ประเทศ สถานะ WARP และเวลาตรวจสอบ ความล่าช้าที่วัดได้คือเวลาการตั้งค่าการเชื่อมต่อTelegram, ไม่ใช่การ ping ICMP การเตรียม WARP จะล้มเหลว เว้นแต่การติดตามจะรายงานว่า WARP กำลังทำงาน การตรวจสอบเหล่านี้ยืนยันการเชื่อมต่อเท่านั้น ไม่ใช่ความถูกต้องหรือความครบถ้วนของ ข้อความที่จับได้ การทำงานของกระบวนการท้องถิ่นเพียงอย่างเดียวไม่ถือเป็นการตรวจสอบจุดออกที่สำเร็จ

### WARP และ WireGuard ที่สามารถพกพาได้

นี่เป็นการผสานรวม **WARP อย่างไม่เป็นทางการ** โดยใช้ [wgcf 2.3.1](https://github.com/ViRb3/wgcf/releases/tag/v2.3.1) และ [wireproxy 1.1.3](https://github.com/windtf/wireproxy/releases/tag/v1.1.3) ผู้ดูแลระบบต้องยอมรับการตั้งค่าอย่างชัดเจนก่อนการดาวน์โหลดครั้งแรกหรือการลงทะเบียน WARP การตั้งค่าการเชื่อมต่อดังกล่าวจะส่งข้อมูลโดยตรงไปยัง GitHub และ Cloudflare และ เปิดเผยที่อยู่ IP ของเครื่อง การรับส่งข้อมูลของบัญชีทั่วไปจะยังคงใช้เส้นทางเดิมจนกว่า แอปพลิเคชันจะเริ่มทำงาน Cloudflare จะเลือกที่อยู่ทางออกและประเทศ; ทันเนลที่แยกกัน สามารถใช้ที่อยู่ทางออกเดียวกันได้ การเลือกประเทศ การหมุนเวียน IP เป็นระยะ และ สวิตช์ตัดการเชื่อมต่อ VPN สำหรับทั้งโฮสต์ ไม่ได้รับการสนับสนุนโดยคุณสมบัตินี้

การดาวน์โหลดโปรแกรมช่วยที่รองรับ: Linux และ macOS x86-64/ARM64, และ Windows x86-64 ไฟล์ผลลัพธ์จะถูกตรวจสอบกับค่าแฮชSHA-256 ที่รวมอยู่ในซอร์สโค้ดที่ผ่านการตรวจสอบแล้ว, และไฟล์ปฏิบัติการที่เก็บไว้ในแคชจะถูกตรวจสอบอีกครั้งก่อนการเปิดใช้งาน ไม่มีโปรแกรมช่วยใดที่ถูกเพิ่มเข้าไปใน PATH, ติดตั้งเป็นบริการระบบ หรือได้รับตัวรับฟังสาธารณะ ทุกไฟล์ถูกจัดเก็บ ในไดเรกทอรี`portable-routes/` ของพื้นที่ทำงาน และรายการใน vault ที่ถูกเข้ารหัส ตัวรับฟัง loopback SOCKS5 ต้องการข้อมูลรับรองที่สร้างขึ้นอย่างอิสระ

โปรไฟล์ส่วนตัวและข้อมูลรับรองบัญชี WARP ถูกเข้ารหัสด้วย คลังข้อมูลพื้นที่ทำงานที่มีอยู่ ขณะทำงาน โปรแกรมช่วยต้องการไฟล์การตั้งค่าแบบข้อความธรรมดาที่เข้าถึงได้เฉพาะเจ้าของเท่านั้น; ไฟล์นี้จะถูกลบออกเมื่อหยุดทำงานตามปกติ การเกิดข้อผิดพลาดของโฮสต์อาจทำให้ไฟล์นี้เหลืออยู่ใน โฟลเดอร์ข้อมูลที่เข้าถึงได้เฉพาะเจ้าของเท่านั้น สิ่งนี้ไม่เข้ารหัสดิสก์หรือป้องกันจาก ผู้ดูแลระบบ ผู้ควบคุมจะปิดอุโมงค์หากท่อหลักของแผง หายไป อุโมงค์ที่ล้มเหลวจะไม่เปิดใช้งานการสำรองโดยตรง การเริ่มต้นใหม่ของแผง จะกู้คืนอุโมงค์ที่เลือกไว้; การเริ่มต้นที่ล้มเหลวจะลองใหม่ด้วยช่วงเวลาที่จำกัด **Stop อุโมงค์** ยังหยุดการสังเกตการณ์และรักษาสถานะที่หยุดไว้ **Start อุโมงค์** เริ่มต้นอุโมงค์; ดำเนินการสังเกตการณ์ต่อเมื่อพร้อม

โปรไฟล์ WireGuard ที่อัปโหลดต้องมี Interface หนึ่งและ Peer หนึ่ง, เส้นทาง IPv4 และ IPv6 ที่ครบถ้วน, และไม่มี hooks, includes, การแทนที่สภาพแวดล้อม หรือ listeners เพิ่มเติม ที่อยู่ปลายทางสาธารณะจะถูกแก้ไขและตรึงไว้ก่อนการเริ่มต้นระบบ ใช้ VPN ภายนอกหรือเกตเวย์ SOCKS5 สำหรับ OpenVPN/IPsec และปลายทางส่วนตัว

## วิธีการยืนยันตัวตน

**API ID และ API hash ใช้เพื่อระบุแอปพลิเคชัน; ทั้งสองไม่แทนที่การเข้าสู่ระบบบัญชี** ทั้งสองเป็นตัวเลือกใน TgWitness ลำดับความสำคัญ: คู่ที่ป้อนในแบบฟอร์ม, ตามด้วยคู่จาก ไฟล์ JSON ของบัญชีที่นำเข้า, ตามด้วยคู่ที่บันทึกในพื้นที่ทำงาน, และสุดท้ายคือกลุ่มคู่ในตัวระบบจำนวน 50 คู่สาธารณะในพูลที่สร้างขึ้นในตัว ซึ่งจะถูกทดลองในลำดับสุ่มพร้อมการหมุนเวียนอัตโนมัติเมื่อ Telegram ปฏิเสธคู่ใดคู่หนึ่ง เฉพาะ คู่ Telegram Desktop (2040) เท่านั้นที่จะถูกส่งไปพร้อมกับคำอธิบายลูกค้า Telegram Desktop ที่ตรงกัน คู่ของคุณเองจากเครื่องมือพัฒนา API ที่ [my.telegram.org](https://my.telegram.org) สามารถใช้กับบัญชีทั้งหมดของคุณได้; แต่ละบัญชียังคงมีการอนุญาตเป็นของตัวเอง

| วิธีการ | ข้อกำหนด | การสนับสนุน TgWitness |
| --- | --- | --- |
| โทรศัพท์, รหัส, 2FA (ตามความต้องการ) | การเข้าถึงบัญชี; คู่ API เป็นตัวเลือก | เข้าสู่ระบบ Panel |
| Auth Key HEX + DC ID | กุญแจเต็ม 512 ตัวอักษร และ DC 1–5 | แท็บ Direct **Auth key**; ตรวจสอบ User ID (ตามตัวเลือก) ก่อนบันทึกการอนุญาต |
| Telethon StringSession | สตริงเซสชันที่ถูกต้อง | เข้าสู่ระบบ Panel |
| Telethon SQLite `.session` | เนื้อหาที่ปิดสมบูรณ์และสอดคล้องกัน | นำเข้าสคีมาโดยตรงจากแผงควบคุม 7/8; CLI แบบออฟไลน์ (เป็นตัวเลือก) |
| Pyrogram SQLite `.session` | เซสชันผู้ใช้ในสภาพแวดล้อมการผลิตที่ปิด | การนำเข้าสคีมาแบบตรงจากแผงควบคุม 2/3 |
| Telegram Desktop TData ZIP | บัญชีเดียวแบบทันสมัย; รหัสผ่านท้องถิ่นหากมีการป้องกัน | การแปลงข้อมูลในหน่วยความจำพร้อมการตรวจสอบค่าเช็กซัมและการถอดรหัส |
| JSON ของบัญชี | สนาม API/session/key ที่รองรับ | ข้อมูลเมตาดาต้าเพียงอย่างเดียวก็เพียงพอที่จะกรอกข้อมูลรับรอง API; แต่ยังจำเป็นต้องใช้การเข้าสู่ระบบด้วยเซสชัน/คีย์ หรือหมายเลขโทรศัพท์/QR Code |
| QR code สำหรับการเข้าสู่ระบบ | การยืนยันจากแอป Telegram ที่ได้รับอนุญาต | สร้าง QR Code ท้องถิ่น, กำหนดวันหมดอายุ/ลองใหม่, ตัวเลือกการยืนยันสองขั้นตอน (2FA) |
| TDLib / Pyrogram StringSession | รูปแบบอื่น ๆ ที่เฉพาะสำหรับไลบรารี | ไม่ได้รับการสนับสนุน |
| โทเค็นบอท | บอทที่มีโมเดลการเข้าถึง/อัปเดตเป็นของตัวเอง | ไม่ถูกใช้โดยผู้รวบรวมข้อมูลนี้ |

Telegram ใช้การส่งรหัสผ่าน; SMS ไม่มีการรับประกัน API hash ไม่สามารถกู้คืน เซสชันที่ถูกยกเลิก หรือแทนที่รหัสผ่าน 2FA ที่ลืมได้ TgWitness ไม่เก็บ รหัสเข้าสู่ระบบหรือรหัสผ่าน 2FA ของ Telegram ลงบนดิสก์

สำหรับแหล่งข้อมูลส่วนตัว บัญชีดังกล่าวต้องได้รับสิทธิ์การเข้าถึงแล้ว ชื่อผู้ใช้ของกลุ่ม ไม่จำเป็น การนำเข้าผ่านพร็อกซีหรือเซสชันจะไม่ให้สิทธิ์การเป็นสมาชิกหรือสิทธิ์ผู้ดูแลระบบ การเป็นสมาชิกในปัจจุบันไม่รับประกันการเข้าถึงประวัติก่อนการเข้าร่วม

## นำเข้าไฟล์เซสชัน Telethon

Telethon SQLite, Pyrogram SQLite และ Telegram Desktop TData ใช้รูปแบบไฟล์ที่แตกต่างกัน แผงควบคุมจะตรวจจับและแปลงโครงสร้างที่รองรับ; การเปลี่ยนชื่อไฟล์ไม่ถือเป็นการ แปลงข้อมูล ให้เลือกเซสชันหนึ่งและไฟล์ JSON ที่เกี่ยวข้องภายใต้ส่วน **Files** แล้วกด **Connect account** ระบบจะรับไฟล์ที่ตรงกันสูงสุดสี่ไฟล์และ รวมทั้งหมด 8 MiB ดู[ข้อจำกัดรูปแบบ](https://phishdestroy.github.io/TgWitness/th/docs/reference/accounts/)เพื่อทราบรายละเอียดเกี่ยวกับ TData/JSON ไม่มีระบบกู้คืนรหัสผ่าน การเข้าสู่ระบบด้วยโทรศัพท์/2FA หรือ QR จะสร้างการอนุญาตแยกต่างหาก

เส้นทางบรรทัดคำสั่งเฉพาะ Telethon (แบบเลือกใช้) ยังคงใช้งานได้:

1. หยุดการทำงานของไคลเอนต์ที่ใช้เซสชันต้นฉบับ และสร้างสำเนาที่สอดคล้องกัน เครื่อง แปลงจะปฏิเสธไฟล์ที่มี WAL/journal ที่ยังไม่เสร็จสมบูรณ์ ปิดไคลเอนต์ต้นฉบับ อย่างถูกต้อง แทนที่จะลบไฟล์เหล่านั้นเพื่อหลีกเลี่ยงการตรวจสอบ
2. จากสภาพแวดล้อม TgWitness ให้รัน:

```
python -m tgwitness.sessions account.session --out account.tgwitness-session
```

1. ในส่วน "**เพิ่มบัญชี" →** "**ไฟล์**" ให้โหลดผลลัพธ์หรือ วางสตริงของมัน แล้วดำเนินการต่อ
2. ตรวจสอบ ID บัญชีแบบตัวเลขที่แสดงอยู่ เลือกแหล่งข้อมูล และเริ่มการติดตาม

**ไฟล์ที่แปลงมาคือรหัสลับการเข้าถึงบัญชีที่ยังไม่ได้รับการเข้ารหัส** เก็บไว้ในที่เก็บข้อมูล ที่ได้รับการป้องกัน และอย่าบันทึกหรือส่งไปยังบริการแปลงไฟล์ของฝ่ายที่สาม TgWitness เก็บเซสชันที่ได้รับอนุญาตไว้ในห้องนิรภัยที่เข้ารหัส การคัดลอกเซสชันจะไม่ สร้างการอนุญาตแยกต่างหาก: อย่าเรียกใช้ไคลเอนต์หลายตัวพร้อมกันด้วยกุญแจการอนุญาตที่คัดลอก และอย่าสมมติว่าการอัปเดตจะถูกส่งมาอย่างอิสระ

การแปลงข้อมูลจะโอนสิทธิ์การเข้าถึงเท่านั้น ไม่ใช่ข้อความต้นฉบับ แคชของเอนทิตี หรือ เคอร์เซอร์การอัปเดตที่คงอยู่ มันไม่แก้ไขปัญหาการกู้คืนการอัปเดตเมื่อกระบวนการเริ่มต้นใหม่

## MTProto, Telethon และพร็อกซี

MTProto คือโปรโตคอลของ Telegram ส่วน Telethon คือไลบรารีไคลเอนต์ Python ที่ TgWitness ใช้ MTProxy เป็นพร็อกซีการส่งข้อมูลของ Telegram; SOCKS5 และ HTTP CONNECT ให้บริการ อุโมงค์ทั่วไป แต่ไม่มีตัวใดที่สามารถแทนที่การยืนยันตัวตนของบัญชีได้

บันทึกเส้นทางสำหรับแต่ละพื้นที่ทำงานใน **Account → Settings → Connection settings → Change connection route** ก่อน เข้าสู่ระบบ พื้นที่ทำงานใหม่จะตั้งค่าเริ่มต้นเป็น **Automatic MTProxy · public lists** พร้อมตัวเลือก **Hide the address** พื้นที่ทำงานที่มีอยู่ซึ่งใช้ Direct อย่างชัดเจนจะยังคงรักษาโหมดที่อนุญาตให้ใช้ Direct ไว้

## โหมด IP

เส้นทางจะกำหนดการเชื่อมต่อ โหมด IP และการ**ป้องกัน IP** ในส่วน Account ของแผงควบคุม จะกำหนดว่าเมื่อใดที่อยู่ของเซิร์ฟเวอร์อาจถูกเปิดเผย การควบคุมเหล่านี้ไม่ ติดตั้ง VPN หรือกำหนดเส้นทางให้กับการรับส่งข้อมูลทั้งหมดของเครื่อง

| โหมด | Telegram | คำขอจากภายนอก |
| --- | --- | --- |
| ซ่อนที่อยู่ (`hide`) | ใช้พร็อกซี; หากไม่มีพร็อกซีใดทำงานได้ ให้รอ ไม่มีการสำรองโดยตรง | ต้องใช้ SOCKS5/HTTP; ปฏิเสธคำขอที่ไม่มีพร็อกซีที่เหมาะสม |
| ใช้ Direct เป็นทางเลือกสุดท้าย (`fallback`) | MTProxy อัตโนมัติอาจใช้ Direct หลังจากช่วงเวลาหน่วงที่กำหนดไว้ แล้วกลับสู่พร็อกซีที่ทำงานได้ | แนะนำให้ใช้พร็อกซีภายนอกที่ตั้งค่าไว้แล้ว หรือเส้นทาง SOCKS5/HTTP ของบัญชีนั้น; หากไม่มี สามารถใช้ Direct ได้ |
| เซิร์ฟเวอร์ที่อยู่หลังทูนเนลหรือ VPN (`tunnel`) | อนุญาตให้ใช้เส้นทางตรงและระบบสำรองอัตโนมัติแบบทันที | การเชื่อมต่อโดยตรงได้รับอนุญาตเมื่อไม่มีการกำหนดค่าพร็อกซีที่เกี่ยวข้อง |

โหมดอุโมงค์หรือ VPN สมมติว่าคุณจัดการเครือข่ายนั้นแยกต่างหาก หากไม่มี อุโมงค์ที่ทำงานได้ จุดหมายปลายทางจะสามารถเห็นที่อยู่ของเซิร์ฟเวอร์เองได้ ให้เลือกโหมดตาม เครือข่ายจริงของคุณ ไม่ใช่ตามชื่อของตัวเลือก

### เลือกเส้นทาง

| เส้นทาง | การตั้งค่า | ขอบเขต |
| --- | --- | --- |
| MTProxy อัตโนมัติ | รายชื่อที่สร้างไว้ล่วงหน้า หรือแคตตาล็อกตัวดำเนินการ | รักษาเส้นทาง Telegram ที่ใช้งานได้; การเปลี่ยนไปใช้เส้นทางสำรองโดยตรงขึ้นอยู่กับโหมด IP |
| ตรงไปตรงมา | โหมด Tunnel หรือ VPN | Telethon ใช้เส้นทางเครือข่ายของผู้จัดงาน |
| SOCKS5 | โฮสต์, พอร์ต, ชื่อผู้ใช้/รหัสผ่าน (ตามต้องการ) | python-socks, เปิดใช้งาน DNS ปลายทางระยะไกล |
| HTTP CONNECT | โฮสต์, พอร์ต, ชื่อผู้ใช้/รหัสผ่าน (ตามต้องการ) | ใช้ HTTP CONNECT แบบธรรมดา; TLS ไปยังพร็อกซีเองยังไม่ได้รับการนำไปใช้ |
| MTProxy | โฮสต์, พอร์ต, รหัสลับ | การส่งข้อมูล Telethon แบบทดลอง; 32 ตัวเลขฐานสิบหก หรือ `dd` + 32 ตัวเลขฐานสิบหก |

ข้อมูลลับ TLS `ee` ปลอมจะถูกปฏิเสธ การปรับรูปแบบของ Telethon 1.45 สามารถลบคำนำหน้า และโดเมนได้ แต่ไม่ได้ใช้ Fake TLS วาง `tg://proxy?server=…&port=…&secret=…` หรือ `https://t.me/proxy?server=…&port=…&secret=…` และเลือก **"Fill fields from link**" สิ่งนี้จะตรวจสอบความถูกต้องและกรอกข้อมูลในช่องโดยไม่ต้องเชื่อมต่อหรือบันทึก; ตรวจสอบและบันทึก เส้นทางแยกกัน ช่องข้อมูลที่กรอกด้วยมือยังคงใช้งานได้ ดู[ลิงก์พร็อกซี Telegram](https://core.telegram.org/api/links#proxy-links)

### พร็อกซีสาธารณะที่ระบบของคุณจัดหา

รายชื่อที่มาในตัวรวมสี่แหล่ง: [SoliSpirit/mtproto](https://github.com/SoliSpirit/mtproto), [zakky8/mtproto-proxy-pro](https://github.com/zakky8/mtproto-proxy-pro), [kort0881/telegram-proxy-collector](https://github.com/kort0881/telegram-proxy-collector) และ [3yed-61/MTP-Collector](https://github.com/3yed-61/MTP-Collector). สแนปช็อตที่รวมไว้มีข้อมูลเกี่ยวกับจุดปลายทาง (endpoint), ที่มาของข้อมูล และวันที่ดาวน์โหลด การปรากฏในรายชื่อของผู้ให้บริการไม่ใช่หลักฐานว่าพร็อกซีนั้นทำงานได้หรือส่งข้อมูลอัปเดตของ Telegram ทุกครั้ง

**MTProxy** ตรวจสอบการเชื่อมต่อเครือข่ายของ Telegram **โดยอัตโนมัติ** รักษาพร็อกซีที่ทำงานได้ และเปลี่ยนไปใช้พร็อกซีอื่นเมื่อพร็อกซีเดิมล้มเหลว พื้นที่ทำงาน (Workspaces) จะเลือกใช้พร็อกซีต่างกันเมื่อมี รายการที่ทำงานได้เพียงพอ; ไม่รับประกันว่าจะมีที่อยู่ทางออก (exit address) ที่ไม่ซ้ำกัน พร็อกซีที่ล้มเหลว จะพักก่อนที่จะลองอีกครั้ง หากไม่มีพร็อกซีใดทำงานได้ โหมด IP จะกำหนดว่าการเก็บข้อมูล ต้องรอหรือสามารถใช้การเชื่อมต่อโดยตรงได้ การเปลี่ยนพร็อกซีจะไม่เปลี่ยนบัญชี หรือลบบันทึกของบัญชีนั้น การเลือกและเปลี่ยนแปลงเส้นทางจะถูกบันทึกไว้ในบันทึกที่ลงนามแล้ว

เมื่อเส้นทางอัตโนมัติกำลังทำงาน รายการจะอัปเดตทุกชั่วโมง และการตรวจสอบการส่งข้อมูลจะดำเนินการ ทุกสิบนาทีตามค่าเริ่มต้น ช่วงเวลานี้สามารถปรับตั้งค่าได้ **การอัปเดตรายการสาธารณะจะขอ** อัปเดต; การดูรายการเพียงอย่างเดียวจะไม่เปลี่ยนแปลงเส้นทางที่ตั้งไว้ด้วยตนเอง

**การส่งข้อมูลของ Telegram และคำขอ HTTPS ใช้เส้นทางที่ต่างกัน** การดาวน์โหลดรายการใช้ การเชื่อมต่อ HTTPS แยกต่างหาก และเส้นทางคำขอภายนอกที่จัดเตรียมไว้ `TGWITNESS_PROXY_FEED_PROXY` กำหนดเส้นทางนั้นให้ใช้พร็อกซี HTTP/SOCKS5 อย่างชัดเจน; ทั้งสองเวอร์ชันของ Compose ในตัวเก็บข้อมูลจะส่งต่อข้อมูลนี้ กลุ่มพื้นหลังจะติดตามพื้นที่ทำงานหลัก ไม่มีการส่งเซสชัน Telegram, ข้อมูลรับรอง API, โทเค็นแผงควบคุม หรือ โทเค็นบอต ไปยังผู้ให้บริการฟีด ชื่อผู้ให้บริการ, วันที่ถ่ายภาพ และเส้นทางดาวน์โหลด จะปรากฏภายใต้ส่วน **“แหล่งที่มาของรายชื่อ”**

MTProxy ส่งผ่านเฉพาะการรับส่งข้อมูล Telegram เท่านั้น การดำเนินการ HTTP ของพื้นที่ทำงาน เช่น การบันทึกเวลา, การแจ้งเตือน, การคัดลอกข้อมูลนอกระบบ และการตรวจสอบแหล่งที่มา จะใช้พร็อกซี SOCKS5/HTTP แยกต่างหากเมื่อ ได้รับการกำหนดค่าไว้ จากนั้นจะใช้เส้นทาง SOCKS5/HTTP ของบัญชี หากไม่มีทั้งสองอย่าง ตัวเลือก "Hide the address" จะปฏิเสธ คำขอ ส่วนโหมดอื่น ๆ จะอนุญาตให้ใช้ Direct ได้ คำขอจากภายนอกสามารถปิดใช้งานได้ พร็อกซีดาวน์โหลดฟีดที่ กำหนดค่าไว้อย่างชัดเจนจะยังคงเป็นการแทนที่ของผู้ดูแลระบบที่แยกต่างหาก บริการพยานอิสระจะรักษาเส้นทางของตัวเอง

สำหรับบริการส่วนตัวที่ผู้ดำเนินการจัดการ การตั้งค่าสภาพแวดล้อมเซิร์ฟเวอร์ที่มีอยู่ `TGWITNESS_ALLOW_PRIVATE_DESTINATIONS=1` อนุญาตปลายทางส่วนตัวและรักษา การแปลชื่อโฮสต์ด้านพร็อกซี ไม่สามารถเปิดใช้งานได้จากแผงควบคุม โหมดเฉพาะสาธารณะ จะปฏิเสธปลายทาง `.onion` ก่อนที่จะส่งคำขอไปยังตัวแก้ปัญหาสาธารณะ; บริการ onion ของ Tor ต้องการการตั้งค่าปลายทางส่วนตัวที่ชัดเจนและพร็อกซีที่เหมาะสม พฤติกรรม DNS นี้ใช้กับการดำเนินการ HTTP ภายนอก ไม่ใช่การส่งข้อมูลของ Telegram Cloudflare มีเอกสารอธิบายเกี่ยวกับ[จุดปลายทาง DNS แบบ](https://developers.cloudflare.com/1.1.1.1/encryption/dns-over-https/make-api-requests/dns-json/) [JSON](https://developers.cloudflare.com/1.1.1.1/encryption/dns-over-https/make-api-requests/dns-json/)

****พารามิเตอร์พูลอัตโนมัติ**** ใน **Parameters → Automatic MTProxy** ให้กำหนดค่าเกณฑ์ความล้มเหลว, ระยะเวลาพัก, การหมุนเวียนตามแผน, การแชร์พร็อกซี และระยะเวลาหน่วงเวลาสำรองที่อนุญาต | การควบคุม | ค่าเริ่มต้น | | --- | --- | | ตัดการเชื่อมต่อก่อนการเปลี่ยน | 3 ครั้งภายใน 10 นาที | | จำนวนพร็อกซีที่ลองต่อครั้ง | 3 | | เวลาพักครั้งแรก / สูงสุดหลังความล้มเหลว | 10 นาที / 6 ชั่วโมง | | การหมุนเวียนตามแผน | ปิด; เปิดเมื่อเกิดความล้มเหลว | | จำนวนบัญชีต่อพร็อกซี | 0: ให้ใช้รายการแยกกันเป็นหลัก, แบ่งปันเมื่อจำเป็น ตั้งค่าเป็น 1 เพื่อรอรายการแบบเอกสิทธิ์ | | เวลารอ ก่อนอนุญาตให้ใช้ Direct fallback | 10 นาที; ซ่อนที่อยู่หากยังปฏิเสธ Direct | | การรีเฟรชฟีด / การตรวจสอบการส่งข้อมูล | 60 / 10 นาที; ค่าในพื้นที่ทำงานหลักใช้กับกลุ่มที่แชร์ | พร็อกซีที่ต่างกันไม่รับประกันว่าจะมีที่อยู่ทางออกที่ต่างกัน การตั้งค่าเหล่านี้ไม่ แทนที่ข้อจำกัดของ Telegram หรือรับประกันความเป็นนิรนาม

เพื่อแทนที่รายชื่อสาธารณะด้วยแคตตาล็อกผู้ให้บริการของคุณเอง ให้กำหนดค่าการแทนที่ด้านล่างนี้ การตั้งค่านี้จะปิดการสมัครรับข้อมูลจากภายนอกอย่างสมบูรณ์ รวมถึงเมื่ออาร์เรย์ `proxies` ของมันว่างเปล่า

คัดลอก[แคตตาล็อกที่ว่าง](https://github.com/phishdestroy/TgWitness/blob/main/deploy/proxies.config.example) ไปยัง `proxy-config/proxies.json` และเพิ่มจุดปลายทางสาธารณะที่คุณได้ติดตั้งแล้ว:

```
{"format": "tgwitness-proxy-catalog-v1", "proxies": [
  {"id": "project-eu", "label": "Project EU",
   "link": "tg://proxy?server=REPLACE_HOST&port=443&secret=REPLACE_SECRET"}
]}
```

ค่าตัวอย่างต้องถูกแทนที่ สามารถรับข้อมูลได้สูงสุด 32 รายการที่ต่างกัน รายการที่ ได้รับการยืนยันจะแสดงชื่อ/โฮสต์/พอร์ต โดยไม่ใช้ข้อมูลลับร่วมกัน; การเลือกหนึ่งรายการ จะบันทึกข้อมูลรับรองเข้าสู่คลังข้อมูลในพื้นที่ทำงาน ความพร้อมใช้งานยังไม่ได้รับการทดสอบจนกว่าจะ มีการทดสอบการส่งข้อมูลอย่างชัดเจน หากแคตตาล็อกมีรูปแบบไม่ถูกต้อง จะสามารถกำหนดค่าด้วยตนเองได้

การติดตั้งบนระบบท้องถิ่น: ตั้งค่า `TGWITNESS_PROXY_CATALOG` เป็นเส้นทาง JSON ในเครื่อง Docker:

```
docker compose -f compose.yaml -f deploy/compose/compose.proxies.yaml up -d --build
```

โอเวอร์เลย์ติดตั้ง `proxy-config` ในโหมดอ่านอย่างเดียว; ไฟล์ต้องสามารถอ่านได้โดย UID 10001 ของคอนเทนเนอร์ ไดเรกทอรีนี้ถูกยกเว้นจาก Git, บริบทการสร้าง Docker และไฟล์อาร์ไคฟ์ต้นฉบับ ไฟล์ แคตตาล็อกนี้กำหนดค่าบัญชีที่ใช้ในการเก็บข้อมูล; [บอทพยานใช้](https://phishdestroy.github.io/TgWitness/th/docs/reference/witness/) เส้นทาง HTTP/SOCKS5 ของตัวเอง ไม่ใช่ MTProxy

การเปลี่ยนเส้นทางสำรองโดยตรงถูกควบคุมโดยโหมด IP ข้างต้น ให้หยุดการสังเกตการณ์ก่อน ที่จะเปลี่ยนเส้นทาง การบันทึกจะตัดการเชื่อมต่อกับไคลเอนต์เก่าและยกเลิกการเข้าสู่ระบบที่ยังไม่เสร็จสิ้น; ไคลเอนต์ ใหม่จะใช้เส้นทางที่บันทึกไว้ การผูกมัดระหว่างบันทึก/เซสชันของบัญชีจะยังคงอยู่ การตั้งค่าจะแทนที่เส้นทางเดิม: ให้ป้อนข้อมูลรับรองพร็อกซีใหม่เมื่อแก้ไขเส้นทาง

ข้อมูลรับรองการเข้าสู่ระบบถูกเข้ารหัสด้วย`network.enc` API ไม่ส่งคืนชื่อผู้ใช้ รหัสผ่าน หรือข้อมูลลับ บันทึกที่ลงนามแล้วจะระบุประเภทเส้นทางและระบุว่าข้อมูลรับรองการเข้าสู่ระบบ มีอยู่หรือไม่ โดยไม่รวมจุดปลายทางและข้อมูลลับ ผู้ใช้งานสามารถดูจุดปลายทาง ได้ในแผงควบคุม สนามข้อมูลลับจะถูกล้างหลังจากบันทึก ล็อก หรือเปลี่ยนพื้นที่ทำงาน

**การทดสอบการเชื่อมต่อ Telegram** (สามารถใช้งานได้ก่อนการเข้าสู่ระบบ) จะเปิดและปิดการเชื่อมต่อ Telegram ชั่วคราว ที่ไม่ได้รับอนุญาตผ่านเส้นทางดังกล่าว โดยไม่ติดต่อกับเว็บไซต์ตรวจสอบ IP การทดสอบที่สำเร็จจะยืนยันการเชื่อมต่อด้านการส่งข้อมูลเท่านั้น ไม่รวมถึงการเข้าถึงกลุ่ม การส่งข้อความที่สมบูรณ์ หรือความเป็นนิรนาม

พร็อกซีนี้ใช้กับการเชื่อมต่อของไคลเอนต์ Telegram รวมถึงการดาวน์โหลดสื่อจาก Telegram DC เครื่องมือ TSA ที่เรียกใช้ผ่านเบราว์เซอร์ pip SSH หรือแบบแมนนวล มีเส้นทางแยกต่างหาก ชื่อโฮสต์ของพร็อกซีอาจถูกแปลงชื่อในระบบท้องถิ่นได้ `rdns` มีผลต่อชื่อโฮสต์ปลายทาง; Telegram มักให้ที่อยู่ IP แบบตัวเลขของ DC

SOCKS5 และ HTTP CONNECT แบบธรรมดาไม่เข้ารหัสข้อมูลรับรองพร็อกซีหรือ ช่องอุโมงค์ระหว่างไคลเอนต์กับพร็อกซี MTProto ปกป้องการรับส่งข้อมูล Telegram แยกต่างหาก ใช้ ช่องทางการสื่อสารที่ปลอดภัยและเหมาะสมเพื่อเชื่อมต่อกับพร็อกซีบนเครือข่ายที่ไม่น่าเชื่อถือ กลุ่มส่วนตัว เป็นการสนทนาบนคลาวด์; MTProto ไม่เปลี่ยนกลุ่มเหล่านี้ให้เป็นการสนทนาลับ (Secret Chats) ที่เข้ารหัสแบบปลายทางถึงปลายทาง

## การเข้ารหัสและลายเซ็น

| ชั้น | ได้ดำเนินการแล้ว | ความรับผิดชอบของผู้ดำเนินการ |
| --- | --- | --- |
| การสื่อสารใน Telegram | Telethon MTProto | ความน่าเชื่อถือของแพลตฟอร์ม, เส้นทาง และความพร้อมใช้งาน |
| แผงควบคุมบนเว็บ | Bearer token, loopback default, request limits | HTTPS หรืออุโมงค์ SSH สำหรับการเข้าถึงจากระยะไกล |
| ความลับ | Fernet สำหรับข้อมูลรับรอง API, เซสชัน, ข้อมูลรับรองพร็อกซี และกุญแจส่วนตัวสำหรับการลงนาม | รักษาความปลอดภัยของกุญแจถอดรหัสและเซิร์ฟเวอร์ที่ทำงานอยู่ |
| กุญแจ Vault | กุญแจท้องถิ่น หรือกุญแจหลักภายนอก สำหรับการติดตั้งใหม่ | พื้นที่จัดเก็บข้อมูลที่แยกต่างหากและได้รับการป้องกัน พร้อมการสำรองข้อมูลกุญแจ |
| ข้อความและไฟล์แนบ | การเก็บข้อมูลแอปพลิเคชันในรูปแบบข้อความธรรมดา | ดิสก์/โวลุ่มที่เข้ารหัส |
| ZIP/JSONL/CSV/HTML | การตรวจสอบความถูกต้อง ไม่มีการเข้ารหัสเนื้อหา | ปกป้องสำเนาที่ส่งออกและการถ่ายโอน |
| ที่มาและเวลา | บันทึกที่ลงนาม, ใบรับกระบวนการ, เครื่องมือตาม RFC 3161 | กุญแจที่เชื่อถือได้, จุดตรวจสอบอิสระ/TSA และขั้นตอนการเก็บรักษา |

**การป้องกันข้อมูล**ในส่วน Account แสดงสถานะเหล่านี้ โทเค็นของแผงควบคุมเป็น รหัสลับการเข้าถึง ไม่ใช่รหัสผ่านสำหรับการเข้ารหัส มันให้สิทธิ์การเข้าถึงระดับผู้ดูแลระบบ; [โทเค็นที่ออก](https://phishdestroy.github.io/TgWitness/th/docs/reference/access/)สามารถกำหนดขอบเขตให้ใช้ได้กับบัญชีและแชทได้ พื้นที่ทำงาน (Workspaces) ใช้ กระบวนการโฮสต์ร่วมกัน และไม่ใช่เทนท์ที่แยกกัน

BitLocker, LUKS, FileVault หรือ volume ที่เข้ารหัสแบบจัดการได้ สามารถปกป้องพื้นที่จัดเก็บข้อมูลได้ภายใต้ โมเดลภัยคุกคามของแต่ละระบบ ผู้ดูแลระบบของเครื่องที่เปิดล็อกและกำลังทำงาน ยังสามารถอ่านข้อมูลได้ ให้รวม SQLite WAL/SHM, ไฟล์สื่อ, ไฟล์ส่งออกชั่วคราว, swap, สำรองข้อมูล และไฟล์ที่ดาวน์โหลดจากเบราว์เซอร์ในการวางแผนพื้นที่จัดเก็บข้อมูล Docker volume ไม่ได้รับการเข้ารหัสเพียงเพราะ มันเป็น volume TgWitness ไม่ใช้ SQLCipher หรือการเข้ารหัสแบบอ็อบเจ็กต์

## กุญแจหลักภายนอก

สำหรับการติดตั้ง**ใหม่** ให้วางกุญแจหลัก (master key) ไว้นอกไดเรกทอรีข้อมูล ขั้นตอนนี้จะไม่ย้ายคลังกุญแจท้องถิ่น (local-key vault) ที่มีอยู่โดยอัตโนมัติ ให้เตรียมไดเรกทอรีกุญแจ ที่เข้าถึงได้เฉพาะโดยตัวตนของบริการ (service identity) แล้วรันคำสั่งต่อไปนี้:

```
python -m tgwitness.security create-master-key /private/keys/tgwitness-master.key
export TGWITNESS_VAULT_KEY_FILE=/private/keys/tgwitness-master.key
python -m tgwitness --data-dir /private/observations/new-case
```

PowerShell, โดยใช้สภาพแวดล้อมโครงการที่ติดตั้งไว้:

```
python -m tgwitness.security create-master-key E:\PrivateKeys\tgwitness-master.key
$env:TGWITNESS_VAULT_KEY_FILE = 'E:\PrivateKeys\tgwitness-master.key'
python -m tgwitness --data-dir E:\PrivateData\new-case
```

ใน Docker ให้ mount ไฟล์แบบอ่านอย่างเดียว (read-only) นอก `/data` เช่น ที่ `/run/secrets/tgwitness-master.key` และตั้งค่าตัวแปรสภาพแวดล้อม (environment variable) ให้ชี้ไปยังเส้นทางนั้น UID ของบริการต้องสามารถอ่านไฟล์นั้นได้ ให้ส่งเส้นทาง (path) ไม่ใช่ไบต์ของกุญแจ (key bytes) ผ่าน ไฟล์สภาพแวดล้อม/ไฟล์การตั้งค่า

แต่ละพื้นที่ทำงานจะได้รับ salt สาธารณะแบบสุ่มและกุญแจ Fernet ของตัวเองที่สร้างขึ้นผ่าน HKDF-SHA256. `vault.external.json` เก็บข้อมูลเมตาดาต้าการสร้างกุญแจ ไม่ใช่กุญแจหลัก หากกุญแจขาดหายหรือผิดพลาด ระบบจะไม่สามารถเริ่มต้นได้โดยไม่แทนที่กุญแจนั้นโดยเงียบๆ ให้เก็บรักษาทั้ง ข้อมูลเมตาดาต้า salt และกุญแจหลักไว้เพื่อการกู้คืน

ทุกพื้นที่ทำงานล้วนมีต้นกำเนิดจากกุญแจหลักเดียวกัน; การถูกบุกรุกของกุญแจหลักจะส่งผลกระทบต่อ ระบบติดตั้งทั้งหมด กระบวนการที่กำลังทำงานอยู่สามารถถอดรหัสความลับได้ นี่ไม่ใช่ HSM หรือ KDF ของรหัสผ่าน รหัสผ่านที่ผู้ใช้กำหนดเองจะไม่ได้รับการยอมรับแทนกุญแจสุ่ม

เก็บกุญแจเดิมไว้สำหรับการติดตั้งที่มีอยู่จนกว่าการย้ายระบบอย่างตั้งใจจะ ถูกดำเนินการและตรวจสอบแล้ว การลบ`vault.key` หรือการเปลี่ยนกุญแจหลักอาจทำให้ การเข้าถึงเซสชัน/กุญแจลงนามถูกทำลาย เก็บสำเนาสำรองที่เข้ารหัสและกุญแจไว้แยกกัน และ ทดสอบการกู้คืนในอินสแตนซ์ที่แยกออกมา
