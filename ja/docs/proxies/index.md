# Telegram · プロキシを選択してください

Canonical page: https://phishdestroy.github.io/TgWitness/ja/docs/proxies/

アカウントをオンラインに保ち、サーバーの IP を見せてよいかどうかは自分で決めます。

## まずIPモードを選択してください

01**アドレスを非表示にする**

プロキシのみ。使えるものがなければ待機します。

02**最終手段としてのダイレクトメッセージ**

一定時間後に直接接続し、使えるプロキシが見つかれば戻ります。

03**トンネルまたはVPNを経由したサーバー**

直接接続で構いません。VPN の設定や確認は行いません。

ルートによって接続方法が決定されます。IPモードによって、直接接続が許可されるかどうかが決まります。

## ルートはプールに任せておきましょう

1. **アカウント → 設定 → 接続設定**。
2. IP モードと**自動 MTProxy**、または固定ルートを選びます。
3. 保存し、**Telegram 接続テスト**を行います（ログイン前でも使えます）。
4. 収集を開始し、自分宛てにテストメッセージを送ります。

新しいワークスペースは自動 MTProxy と**アドレスを非表示**で始まります。プールは 4 つの公開リストを取得し、サーバーを確認して、良いものを残し、使えなくなったものを入れ替えます。

## ご自身のプロキシをご利用ください

SOCKS5、HTTP CONNECT、Telegram のプロキシリンク、または運営者のカタログ。切り替える前に観察を一時停止してください。Fake TLS のシークレット（`ee`…）は使えません。

**ローテーション、共有、再試行の設定**

**パラメータ → 自動 MTProxy**：失敗のしきい値、クールダウン、ローテーション、プロキシあたりのアカウント数。上限 1 は、共有せずに待機するという意味です。異なるプロキシでも出口 IP が同じことはあります。

## Telegramと外部からのリクエストを分離する

MTProxy が運ぶのは Telegram だけです。タイムスタンプ、通知、コピー、コードチェックは、別の SOCKS5/HTTP プロキシ、アカウントの SOCKS5/HTTP ルート、またはモードが許せば直接接続を通ります。オフにすることもできます。

`TGWITNESS_PROXY_FEED_PROXY` はリストのダウンロードに使うルートを設定します。[証人](https://phishdestroy.github.io/TgWitness/ja/docs/witness/)には独自の設定があります。どれもブラウザーやシステムのネットワークには影響しません。

詳しくは：[モードと既定値](https://phishdestroy.github.io/TgWitness/ja/docs/reference/connection/#ip-modes)、[ルートを変更できる人](https://phishdestroy.github.io/TgWitness/ja/docs/access/)。
