# המשך להפעיל את האתר

Canonical page: https://phishdestroy.github.io/TgWitness/he/docs/server/

יש להקפיד שהאספן יהיה זמין ושהנתונים שבו יישמרו ללא שינוי גם לאחר הפעלה מחדש.

## בחר שיטת השקה

להתקנה מקומית, השתמשו במ[פעיל](https://phishdestroy.github.io/TgWitness/he/docs/start/) ובדוגמאות השירות הנמצאות בתיקיית [deploy/.](https://github.com/phishdestroy/TgWitness/blob/main/deploy/README.md) עבור Docker, התקינו את Docker עם Compose והפעילו מהספרייה של הפרויקט:

```
docker compose up -d --build --wait
docker compose exec tgwitness cat /data/panel-token.txt
```

לוח הבקרה המוגדר כברירת מחדל מאזין לכתובת הלופבק של המארח, יציאה 8787. פתחו אותו באופן מקומי או דרך מנהרת SSH. השתמשו באסימון מהפקודה השנייה כדי לפתוח את נעילת לוח הבקרה.

## יש לשמור את ספריית הנתונים במלואה

התקנות מקומיות משתמשות ב-`data/live`. Docker משתמש בנפח הקבוע `tgwitness-data`. שמרו יחד את היומנים, הפעלות החשבון, המפתחות ומצב התפעול. ייצוא חתום מהווה ראיה שימושית, אך אינו גיבוי מלא של ההתקנה.

1. יש להפסיק את האיסוף לפני ביצוע גיבוי קבוע.
2. העתיקו את ספריית הנתונים הפרטיים במלואה לאחסון מוגן מחוץ לשרת המארח.
3. בדקו את השחזור בסביבה מבודדת לפני שתסתמכו על הגיבוי.

## יש לבדוק לאחר הפעלה מחדש

יש לאשר את סביבת העבודה והמפתח הצפויים, את החיבור ל-Telegram, את המקורות הנבחרים ואת לכידת ההודעות החדשות. מצב MTProto שנשמר ותכונת ההשלמה מסייעים לשחזר עדכונים ש-Telegram עדיין שומר. לא ניתן לשחזר כל עדכון שפג תוקפו או עריכה שנמחקה לפני הלכידה.

"תקינות הקונטיינר" פירושה שהשרת האינטרנטי מגיב. יש להשתמש בהודעה מבוקרת ובבדיקת עדים כדי להעריך את האיסוף והפרסום החיצוני.

## פרסם רק את מה שאתה מתכוון לפרסם

מדריך הפריסה כולל דוגמאות ל-HTTPS, פקודות לניהול נפח קבוע, עדכונים ושלבי שחזור. פקודות Docker מסופקות לצורך הפריסה; [תיעוד האימות](https://phishdestroy.github.io/TgWitness/he/docs/reference/verification/) הנוכחי מפרט את הסביבות שנבדקו בפועל.
