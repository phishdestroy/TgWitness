# รูปแบบบัญชีและเซสชัน

Canonical page: https://phishdestroy.github.io/TgWitness/th/docs/reference/accounts/

ลงชื่อเข้าใช้ผ่านโทรศัพท์มือถือ รหัส QR หรือกุญแจการยืนยันตัวตน นำเข้าเซสชันจาก Telethon Pyrogram หรือ Telegram Desktop และจัดการหลายบัญชีได้

[TgWitness](https://github.com/phishdestroy/TgWitness/blob/main/README.md) / [เอกสารประกอบ](https://github.com/phishdestroy/TgWitness/blob/main/docs/README.md) · [เริ่มต้นใช้งาน](https://phishdestroy.github.io/TgWitness/th/docs/reference/quickstart/)

![เริ่มต้นใช้งาน](https://phishdestroy.github.io/TgWitness/assets/chapter-start.svg)

TgWitness ลงชื่อเข้าใช้ในฐานะบัญชี**ผู้ใช้ Telegram** (ไม่ใช่บอต) ผ่าน MTProto โดยใช้ Telethon แต่ละบัญชีจะอยู่ในพื้นที่ทำงานของตัวเอง (เรียกว่า *workspace* ใน API และเครื่องมือบรรทัดคำสั่ง) พร้อมด้วยเซสชัน แหล่งข้อมูล บันทึก และกุญแจลงนามของตัวเอง

ไฟล์เซสชัน, สตริงเซสชัน และ Auth Keys เป็น**ข้อมูลการอนุญาตของบัญชี**: ผู้ใดก็ตาม ที่ถือข้อมูลเหล่านี้สามารถดำเนินการในนามบัญชีนั้นได้ แต่ข้อมูลเหล่านี้ไม่รวมประวัติข้อความ

> [!WARNING] **อย่าใช้ข้อมูลใดที่คุณไม่สามารถรับความสูญเสียได้** เราขอแนะนำอย่างแรงว่าอย่าเชื่อมต่อ บัญชีส่วนตัวหรือบัญชีที่มีค่าอื่นใด และอย่าสร้าง API ID / API hash บน บัญชีที่คุณให้ความสำคัญ นี่ไม่ใช่เรื่องที่ TgWitness ยังไม่ผ่านการทดสอบ: Telegram จำกัดและ ห้ามบัญชีอย่างถาวรแบบคาดเดาไม่ได้ — สำหรับปริมาณคำขอที่ Telegram ถือว่า เกินขีดจำกัด โดยไม่คำนึงถึงผู้ใช้หรือวัตถุประสงค์ และไม่มีเอกสารประกอบที่เพียงพอ การห้ามบัญชี หลายกรณีไม่สามารถย้อนกลับได้ ใช้บัญชีที่จัดไว้เฉพาะสำหรับการทดสอบ การทดสอบที่ราบรื่นขึ้นอยู่กับ Telegram ไม่ใช่ ซอฟต์แวร์ และไม่รับประกันอะไรสำหรับอนาคต

## สรุปโดยย่อ

| สิ่งที่คุณมี | แท็บในส่วน "**เพิ่มบัญชี"** | คุณยังจำเป็นต้อง |
| --- | --- | --- |
| หมายเลขโทรศัพท์และสิทธิ์การเข้าถึงรหัสเข้าสู่ระบบ | **โทรศัพท์** | รหัสผ่าน 2FA หากเปิดใช้งาน |
| Telegram เปิดอยู่บนอุปกรณ์อื่น | **QR code** | รหัสผ่าน 2FA หากเปิดใช้งาน |
| ไฟล์`.session` (Telethon หรือ Pyrogram) | **ไฟล์** | ไฟล์ JSON เสริม (ไม่บังคับ) สำหรับการตั้งค่าแอปพลิเคชัน |
| `.session` + `.json` ที่มีชื่อเดียวกัน | **ไฟล์** (เลือกทั้งสอง) | โดยทั่วไปไม่มีเนื้อหาอื่นใด |
| โฟลเดอร์`tdata` บน Telegram Desktop | **ไฟล์** (ในรูปแบบ ZIP) | รหัสผ่านท้องถิ่นบนเดสก์ท็อป หากมีการตั้งไว้ |
| Telethon StringSession (text, `.txt`, `.tgwitness-session`) | **ไฟล์** | ไม่จำเป็นต้องใช้คู่ API แยกต่างหาก |
| `.json` พร้อมด้วยเซสชันหรือกุญแจการยืนยันตัวตน (Auth Key) | **ไฟล์** | ไม่จำเป็นต้องใช้คู่ API แยกต่างหาก |
| กุญแจการยืนยันตัวตน (512 ตัวอักษรเฮกซ์) และหมายเลข DC ของมัน | **กุญแจการรับรอง** | ID ผู้ใช้ (ไม่บังคับ) |

TgWitness ระบุไฟล์จาก**เนื้อหา** ไม่ใช่จากชื่อไฟล์ การเปลี่ยนชื่อไฟล์ จะไม่ทำให้ไฟล์นั้นถูกแปลงรูปแบบ

## ก่อนเริ่ม: API ID และ API hash

คุณสามารถเข้าสู่ระบบได้โดยไม่ต้องสร้างแอปพลิเคชัน Telegram API เมื่อไม่มีการป้อนคู่ใด หรือนำเข้า หรือคู่ที่บันทึกไว้แล้วในพื้นที่ทำงาน TgWitness จะเลือกคู่จากกลุ่มคู่ API สาธารณะ 50 (`tgwitness/api_pool.py`) ที่ติดตั้งมาพร้อมระบบ โดยจะให้優先 Telegram Desktop สำหรับการเข้าสู่ระบบใหม่ และเก็บคู่ที่บันทึกไว้ก่อน; คู่ที่เหลือจะถูกจัดเรียงแบบสุ่ม หาก Telegram ปฏิเสธคู่ (`API_ID_INVALID`, `API_ID_PUBLISHED_FLOOD`, `UPDATE_APP_TO_LOGIN`), จะลองคู่ถัดไป, สูงสุดแปดคู่ต่อการลงชื่อเข้าใช้; คู่ที่ถูกปฏิเสธจะถูกข้ามไปจนกว่าจะรีสตาร์ท คู่ที่ลงชื่อเข้าใช้ได้ ถูกบันทึกไว้กับบัญชีและใช้ซ้ำสำหรับบัญชีนั้น ID **API** และแฮช **API**

สำหรับช่องข้อมูลการเชื่อมต่อที่ขาดหายไป ให้ใช้คู่เครื่อง/ระบบปฏิบัติการแบบกำหนดค่าแน่นอนจาก [แคตตาล็อก opentele2 2.0.0](https://github.com/DedInc/opentele2/tree/7e973bc71cd7a714ad13ac703c0895a90d36a735) ที่มาพร้อมกับแพ็กเกจ: Desktop `2040`, Android `6`, Android X `21724`, iOS `10840`, macOS `2834`, และ Web `2496`. ID การสร้างจากแหล่งต้นของ Android `4` ก็ใช้แคตตาล็อก Android เช่นกัน ตามที่ระบุใน [BuildVars ของ Telegram Android](https://github.com/DrKLO/Telegram/blob/master/TMessagesProj/src/main/java/org/telegram/messenger/BuildVars.java). Web ตั้งค่าเริ่มต้นเป็น A; หากมีคำต่อท้ายเวอร์ชันแอป `K` ที่นำเข้ามา หรือแพ็กเกจภาษา `macos` จะเลือก K และเวอร์ชัน `0.7.0` จะเลือก Webogram ID แอปพลิเคชันที่ไม่รู้จักจะคงค่าเริ่มต้นของโฮสต์ Telethon ไว้เสมอ ฟิลด์ที่นำเข้ามาจะมีผลเหนือกว่าเสมอ รวมถึงเวอร์ชันแอปที่เก่ากว่าและแพ็กเกจภาษาที่ว่าง แคตตาล็อกจะไม่เปลี่ยนแปลง API ID/hash เลย ภาพรวมเวอร์ชันของมันจะ ได้รับการตรวจสอบอย่างชัดเจน ไม่ใช่การดึงข้อมูลระหว่างการเข้าสู่ระบบ โปรไฟล์ที่บันทึกไว้จะคงความเสถียรหลังการอัปเดต

`account.getAuthorizations` รายงานข้อมูลเมตาดาต้าการอนุญาตที่ Telegram เก็บไว้; มัน ไม่ใช่การสะท้อนของ `initConnection` ใหม่แต่ละครั้ง ให้เปรียบเทียบกับโปรไฟล์ที่ส่งไปจริง การเชื่อมต่อกับการอนุญาตที่มีอยู่จะไม่ตรวจสอบความถูกต้องของแฮช API ที่เกี่ยวข้อง: `initConnection` ส่ง API ID ในขณะที่แฮชถูกใช้ในคำขอเข้าสู่ระบบ

หลังจากยืนยันตัวตนด้วยโทรศัพท์ใหม่หรือ QR Code, TgWitness จะขอข้อมูลการตั้งค่า, ศูนย์ข้อมูล (DC) ที่ใกล้ที่สุด, สถานะออนไลน์, ภาษา (เมื่อแพ็กเกจภาษาไม่ว่างเปล่า), การอัปเดตแอป และ การอัปเดตเงื่อนไขการให้บริการ โดยเว้นระยะ 0.3–1.5 วินาทีระหว่างการขอข้อมูล การอัปเดตสถานะ จะทำให้บัญชีถูกทำเครื่องหมายว่าออนไลน์ชั่วคราว ลำดับขั้นตอนนี้ทำงานเพียงครั้งเดียวเมื่อการเข้าสู่ระบบเสร็จสิ้น, ไม่ใช่เมื่อนำเข้าข้อมูล, เชื่อมต่อใหม่ หรือรีสตาร์ท ระบบ การยืนยันสิทธิ์จะถูกบันทึกไว้ก่อน; หากคำขอ ล้มเหลว ลำดับขั้นตอนนี้จะหยุดลงโดยไม่ลองใหม่หรือยกเลิกการเข้าสู่ระบบ ผลลัพธ์จะถูก บันทึกเป็น`account.initialized` พร้อมชื่อข้อผิดพลาดแทนเนื้อหาการตอบกลับ ลำดับขั้นตอนนี้ไม่รับประกันว่าจะไม่เกิดข้อจำกัดของบัญชี

สำหรับ `tdesktop` , หาก `tz_offset` ขาดหายไป จะใช้ค่า UTC offset ท้องถิ่นของเซิร์ฟเวอร์ ซึ่งถูกปัดเศษ เป็น 900 วินาที โดยใช้อัลกอริทึม [opentele2](https://github.com/DedInc/opentele2/blob/7e973bc71cd7a714ad13ac703c0895a90d36a735/crates/opentele2-core/src/fingerprint.rs) (MIT; ใบอนุญาตใน `tgwitness/client_profiles.LICENSE` ) ค่านี้จะถูกอัปเดตทุกครั้ง ที่มีการเชื่อมต่อ เพื่อให้การเปลี่ยนแปลงเวลาออมแสงถูกสะท้อนอย่างถูกต้อง `tz_offset` ที่นำเข้ามามีความสำคัญเหนือกว่าบนทุกแพลตฟอร์มและถูกรักษาไว้อย่างแม่นยำ รวมถึงค่าศูนย์ด้วย ส่วนรายการ `initConnection.params` อื่น ๆ จะถูกรักษาไว้ แบบฟอร์มการลงชื่อเข้าใช้ HTTP รับค่าเขตเวลาแบบตัวเลขที่ส่งคืนจากการนำเข้าไฟล์; ค่าบูลีน ค่าเศษส่วน และค่าออฟเซ็ตที่อยู่นอกช่วงที่รองรับจะถูกปฏิเสธ

เส้นทาง Direct, SOCKS5 และ HTTP CONNECT ใช้ Telethon's `ConnectionTcpObfuscated` (MTProto ที่ถูกทำให้ซับซ้อนและย่อ) HTTPS CONNECT ยังคงใช้ TLS ไปยังพร็อกซี และใช้ การขนส่งที่ถูกทำให้ซับซ้อนแบบเดียวกันภายในอุโมงค์ MTProxy ยังคงรักษา การขนส่งขั้นกลางแบบสุ่มที่จำเป็นและการจัดการข้อมูลลับไว้ การเปลี่ยนเส้นทางใช้ ตัวเลือกเดียวกัน การทำให้ซับซ้อนจะเปลี่ยนการจัดกรอบแพ็กเก็ต แต่ไม่ซ่อนบัญชี หรือข้อมูลเมตาของไคลเอนต์จาก Telegram และไม่หมายความว่ามีความคุ้มกันต่อข้อจำกัด

หลังจากเชื่อมต่อกับไคลเอนต์ที่ได้รับอนุญาตแล้วTgWitnessจะตรวจสอบการตั้งค่าศูนย์ข้อมูล (DC) ที่ใกล้ที่สุด การอนุญาตปัจจุบัน ฐานข้อมูลชั้นที่ได้รับการตรวจสอบแล้ว ภาษา การอัปเดตแอป และการอัปเดตเงื่อนไขการให้บริการ การวินิจฉัยเหล่านี้จะทำงานครั้งเดียวต่ออินสแตนซ์ของไคลเอนต์ ก่อนการเก็บข้อมูล และจะแสดงอยู่ภายใต้รายละเอียดการเชื่อมต่อพร้อมเวลา `account.connection_checked` บันทึกผลลัพธ์โดยไม่รวมแฮชเซสชัน, IP, โทเค็น หรือแฮช API มันไม่รับเงื่อนไขหรือติดตั้งการอัปเดตเลย การร้องขอ ที่ล้มเหลวหรือ FloodWait จะหยุดการร้องขอถัดไป; ผลลัพธ์ที่ขาดหายไปจะยังคงเป็นข้อมูลที่ไม่ทราบ การตรวจสอบในเครื่องท้องถิ่นยังสามารถรายงานผลลัพธ์ได้ ในขณะที่การตรวจสอบเครือข่ายจะถูกข้ามไป

การวินิจฉัย FloodWait เก็บรักษาวิธีการ TL ที่ล้มเหลว, ตัวห่อ Takeout/range ใดๆ, การรอที่เซิร์ฟเวอร์ร้องขอ และเส้นตายที่มีผลใน`telegram.backoff` รายละเอียดการเชื่อมต่อแสดงวิธีการและเส้นตายในขณะที่คำขอถูกหยุดชั่วคราว การวินิจฉัยนี้รวมถึงตัวนับการเรียกจากฝั่งลูกค้าต่อแต่ละวิธีตั้งแต่ลูกค้าดังกล่าว ถูกสร้างขึ้น; ตัวนับเหล่านี้จะนับการแก้ไขที่อยู่ของ peer ที่ซ้อนกันแยกต่างหาก แต่ไม่นับแพ็กเก็ต หรือการลองใหม่ภายในของ Telethon ตัวนับปัจจุบันยังมีให้ใช้ได้ในฐานะ `collector.rpc_activity` ใน API สถานะ ไม่รวมอาร์กิวเมนต์ของคำขอ ชื่อผู้ใช้ แฮชการเข้าถึง หรือข้อความข้อยกเว้น การวินิจฉัยครั้งสุดท้ายและกำหนดเวลาเต็ม จะคงอยู่หลังการรีสตาร์ท การรอที่ผ่านมาก่อนหน้าโดยไม่มีบันทึกวิธีการไม่สามารถระบุ ย้อนหลังได้ ดูข้อจำกัดการส่งออก  สำหรับการตรวจสอบแหล่งที่มาและ ความแตกต่างระหว่างการค้นพบและการเก็บข้อมูลประวัติ

`official_app=True` หรือ `False` เป็นตัวบ่งชี้การอนุญาตปัจจุบันของ Telegram ทั้งสอง ค่านี้ไม่ได้กำหนดว่าบัญชีนั้นถูกจำกัด ถูกเชื่อถือ หรืออยู่ภายใต้การสังเกต ภาพถ่ายโหมดหลักฐาน `account.devices` ที่มีอยู่ยังคงเป็นประวัติของทุก อุปกรณ์ที่ลงชื่อเข้าใช้; ส่วนการวินิจฉัยการเชื่อมต่อเก็บไว้เพียงคำอธิบายของอุปกรณ์ปัจจุบันเท่านั้น

ก่อนการเชื่อมต่อ การตรวจสอบเชิงแนะนำจะเปรียบเทียบรูปแบบของแพลตฟอร์ม API แพ็กเกจภาษา รูปแบบของอุปกรณ์/ระบบปฏิบัติการและเวอร์ชันแอป ภาษาท้องถิ่นของระบบมือถือ และชั้นสคีมาจริง ของ Telethon กับฐานข้อมูลแคตตาล็อกที่ได้รับการตรวจสอบแล้ว คำเตือนจะปรากฏใน บันทึกเซิร์ฟเวอร์และข้อมูลเมตาดาต้าสถานะบัญชี; คำเตือนเหล่านี้จะไม่แทนที่ค่าที่นำเข้าหรือเปลี่ยนแปลง ชั้นสคีมา ชั้นข้อมูลที่ต่างกันเป็นสัญญาณการตรวจสอบความเข้ากันได้ ไม่ใช่หลักฐานว่า บัญชีนั้นถูกระงับหรือถูกจำกัด การตรวจสอบเหล่านี้และรหัส`official_app` ไม่รับรองว่า Telegram ถือว่าบัญชีนั้นปลอดภัยจากข้อจำกัด สถานะบัญชีที่ตัดการเชื่อมต่อ จะใช้โปรไฟล์ที่บันทึกไว้แทนที่จะสร้างคำอธิบายอุปกรณ์ใหม่

หากต้องการใช้แอปพลิเคชันของคุณเองแทน (บัญชีที่ลงทะเบียนแอปพลิเคชันนั้นคือบัญชีที่เสี่ยง; ดู [Why a built-in API pool?](https://github.com/phishdestroy/TgWitness/blob/main/docs/PROJECT-GUIDE.md#connect-a-telegram-account)):

1. เปิด [my.telegram.org](https://my.telegram.org) และลงชื่อเข้าใช้ด้วยหมายเลขโทรศัพท์ใดก็ได้ ที่คุณเป็นเจ้าของ รหัสยืนยันจะส่งมาในแอป Telegram ไม่ใช่ผ่าน SMS.
2. เลือก**เครื่องมือพัฒนา API**
3. สร้างแอปพลิเคชัน: ชื่อและชื่อสั้น (5–32 ตัวอักษร) ตามต้องการ, แพลตฟอร์ม **Desktop**. URL และคำอธิบายสามารถทิ้งว่างไว้ได้
4. คัดลอก **App api_id** (ตัวเลข) และ **App api_hash** (32 ตัวอักษรฐานสิบหก)

ในส่วนแผงควบคุม ให้ใส่ Open **API ID + Hash** ใต้แบบฟอร์มลงชื่อเข้าใช้ คุณสามารถวางคู่ `api_id:api_hash` เดียวลงในช่อง **API ID** และทั้งสองช่องจะถูกกรอกอัตโนมัติ คู่หนึ่งสามารถ ใช้ได้กับบัญชีทั้งหมดของคุณ หลังจากลงชื่อเข้าใช้สำเร็จ ข้อมูลจะถูกบันทึกและเข้ารหัสไว้ ในพื้นที่ทำงานนั้นเท่านั้น และจะไม่ถูกส่งกลับไปยังเบราว์เซอร์เลย

มีข้อมูลรับรองสามประเภทที่เกี่ยวข้อง:

| ลับ | เปิด | ที่อยู่ |
| --- | --- | --- |
| โทเค็นของแผง | แผงควบคุมเว็บของ TgWitness | `panel-token.txt` ในไดเรกทอรีข้อมูล หรือ `TGWITNESS_TOKEN` |
| API ID + hash | ไม่มีเนื้อหาอื่นใดเพิ่มเติม; ใช้เพื่อระบุชื่อแอป | ใช้คู่เครื่องมือที่ติดตั้งมาพร้อมระบบ ตั้งค่าที่นำเข้า หรือสร้างแอปของคุณเองได้ที่ my.telegram.org |
| การอนุญาตบัญชี | บัญชี Telegram | สร้างขึ้นผ่านการเข้าสู่ระบบด้วยโทรศัพท์/QR หรือนำเข้ามาเป็นเซสชัน |

หากต้องเข้าถึง Telegram ผ่านพร็อกซี ให้ตั้งค่าก่อนที่ **บัญชี → การตั้งค่า → การตั้งค่าการเชื่อมต่อ → เปลี่ยนเส้นทางเชื่อมต่อ**

## หมายเลขโทรศัพท์

1. เปิด**บัญชี**, คลิกแท็บ "**โทรศัพท์**" และป้อนหมายเลขในรูปแบบสากล, เช่น `+44 7700 900123`. ช่องว่างและเครื่องหมายขีดจะถูกตัดออกโดยอัตโนมัติ.
2. กด "**Continue**" (ต่อ). API ID + Hash สามารถทิ้งว่างไว้ได้
3. ป้อนรหัสที่ Telegram ส่งมา (โดยทั่วไปจะส่งไปยังแอป Telegram; ไม่รับประกันว่าจะส่งผ่าน SMS)
4. หากบัญชีมีการยืนยันสองขั้นตอน ให้ป้อนรหัสผ่านนั้น ไม่ใช่ โทเค็นของแผงควบคุม และไม่ใช่รหัสผ่านของอุปกรณ์
5. ตรวจสอบ ID บัญชีที่แสดงขึ้นหลังการเข้าสู่ระบบ แล้วเลือกแหล่งข้อมูล

รหัสเข้าสู่ระบบและรหัสผ่าน 2FA ไม่ถูกบันทึกลงบนดิสก์เลย

## รหัส QR

ใช้ตัวเลือกนี้เมื่อบัญชีได้เข้าสู่ระบบแล้วบนโทรศัพท์หรือคอมพิวเตอร์เครื่องอื่น

1. คลิกที่ **QR code** → **แสดง QR code**. API ID + Hash สามารถทิ้งว่างไว้ได้
2. บนอุปกรณ์ที่ลงชื่อเข้าใช้แล้ว: **การตั้งค่า → อุปกรณ์ → เชื่อมต่ออุปกรณ์เดสก์ท็อป**, สแกนรหัส และยืนยัน
3. กรุณาป้อนรหัสผ่าน 2FA ใน TgWitness หาก Telegram ขอให้ป้อน

ภาพ QR ถูกสร้างขึ้นในเครื่องท้องถิ่น รหัสมีอายุการใช้งานจำกัด; คลิก "**สร้างรหัส QR อีกครั้ง"** เพื่อลองใหม่ การล็อกหน้าต่าง การเปลี่ยนพื้นที่ทำงาน หรือการเข้าสู่ระบบด้วยบัญชีอื่น จะทำให้ รหัสที่ยังไม่ถูกใช้ถูกยกเลิก

## Auth Key + DC ID

Auth Key คือรหัสอนุญาตดิบขนาด 256 ไบต์ที่อยู่เบื้องหลังทุกเซสชัน Telegram ซึ่งเขียน เป็น**ตัวเลขฐานสิบหก 512 ตัว** พร้อมด้วยหมายเลขศูนย์ข้อมูล **DC 1–5**

1. แท็บ "**Auth key**" (กุญแจการยืนยันตัวตน). วางกุญแจทั้งหมดลงไป; กุญแจที่ถูกตัดสั้นลงซึ่งมีตัวอักษร `…` จะไม่สามารถใช้งานได้
2. เลือก DC ID ที่มาพร้อมกับกุญแจ
3. สามารถป้อน **ID ผู้**ใช้ได้ (ไม่บังคับ) TgWitness จะปฏิเสธการเชื่อมต่อหาก Telegram รายงาน บัญชีที่ต่างออกไป
4. **บัญชี** Press **Connect**.

Auth Key (512 ตัวอักษร) ไม่ใช่ API hash (32 ตัวอักษร) กุญแจเดียวกันนี้ยังสามารถ นำเข้าในรูปแบบ JSON ได้ ดู [Account JSON](https://phishdestroy.github.io/TgWitness/th/docs/reference/accounts/#account-json)

## ไฟล์บัญชี

คลิก **“เพิ่มบัญชี” → “ไฟล์”** และเลือกไฟล์สูงสุด **4 ไฟล์จากบัญชีเดียว** (รวมทั้งหมด **8 MiB**) แล้วคลิก **“เชื่อมต่อบัญชี**”

The **ไฟล์**, **กุญแจการรับรอง** และแบบฟอร์มการนำเข้าแบบกลุ่มจะแสดงคำเตือนเกี่ยวกับเซสชันคู่ขนาน ก่อนการเชื่อมต่อ โดยค่าเริ่มต้น การอนุญาตที่นำเข้าจะถูกใช้ซ้ำ ให้ปิด ไคลเอนต์ต้นฉบับไว้ขณะที่คีย์ของมันกำลังถูกใช้ที่นี่ **ไฟล์** และ **กุญแจการรับรอง** ยังเสนอ **สร้างการอนุญาตแบบอิสระ**, ซึ่งอธิบายไว้ด้านล่าง การนำเข้าแบบกลุ่มยังคงใช้ โหมดโดยตรง การเข้าสู่ระบบผ่านโทรศัพท์และ QR แบบโต้ตอบจะสร้างการอนุญาตแยกต่างหาก หัวข้อคำเตือนจะยังคงแสดงอยู่ในแบบฟอร์มการนำเข้า; คำอธิบายเต็มจะเปิด อัตโนมัติเมื่อมีการส่งไฟล์หรือคีย์/สตริงเซสชัน สามารถพับได้ หลังจากอ่านแล้ว เพื่อให้ตัวเลือกไฟล์และตัวควบคุมการเชื่อมต่อยังคงใช้งานได้บนโทรศัพท์

- ไฟล์จะถูกแปลง**ใน**หน่วยความจำบนเซิร์ฟเวอร์ TgWitness ของคุณ การอัปโหลดจะไม่ถูกเก็บไว้ ไฟล์ ZIP จะไม่ถูกแตกออกสู่ดิสก์ และไม่มีการติดต่อกับบริการภายนอกใดๆ
- เซสชันที่ได้มาจะถูกตรวจสอบกับ Telegram หากไฟล์ระบุ ID ผู้ใช้ มันต้องตรงกับบัญชีที่ Telegram รายงาน
- ไฟล์ที่อธิบายบัญชีต่าง ๆ หรือข้อมูลรับรอง API ต่าง ๆ จะถูกปฏิเสธ แทนที่จะเลือกเพียงหนึ่งรายการ
- **ช่องรหัสผ่านหรือข้อความเซสชัน (Passcode or session text)** เป็นช่องสำหรับกรอกรหัสผ่านท้องถิ่น TData ซึ่งเป็นช่องสำหรับวาง StringSession และ**ไฟล์ Read โดยไม่ต้องลงชื่อเข้าใช้** (กรอกแบบฟอร์มโดยไม่ต้อง ติดต่อกับ Telegram)

### สร้างระบบการอนุญาตที่อิสระ

เลือก **สร้างการอนุญาตอิสระ** ก่อนเชื่อมต่อไฟล์ที่นำเข้า หรือ กุญแจการอนุญาต (Auth Key)TgWitness จะเชื่อมต่อกับผู้บริจาคที่นำเข้าอย่างชั่วคราว ใช้ผู้บริจาคดังกล่าวเพื่ออนุมัติ โทเค็นการเข้าสู่ระบบ QR ของลูกค้าใหม่ และตัดการเชื่อมต่อกับผู้บริจาคทันทีหลังการอนุมัติ ลูกค้าใหม่จะมีกุญแจการอนุญาตของตัวเองและโปรไฟล์ Desktop ที่เลือกแยกต่างหาก ข้อมูลรับรอง API และโปรไฟล์อุปกรณ์ที่ผู้บริจาคให้มาจะถูกใช้เฉพาะ สำหรับการเชื่อมต่อกับผู้บริจาคเท่านั้น การอนุญาตที่มีอยู่จะไม่ถูกออกจากระบบหรือถูกเพิกถอน

**ให้ปิดแอปพลิเคชันต้นฉบับของผู้บริจาคอย่างสมบูรณ์ในขั้นตอนนี้** การเชื่อมต่อ ครั้งแรกยังคงใช้กุญแจที่คัดลอกมา ดังนั้นโหมดนี้จึงไม่สามารถขจัดความเสี่ยง จากการใช้งานคู่ขนานในขั้นต้นได้ เมื่อการอนุญาตใหม่เชื่อมต่อสำเร็จแล้ว เจ้าของสามารถเปิด แอปพลิเคชันต้นฉบับอีกครั้งและใช้งานทั้งสองอย่างได้อย่างอิสระ การเข้าสู่ระบบด้วย **QR code** แบบโต้ตอบช่วยให้ แอปพลิเคชันต้นฉบับสามารถอนุมัติการเข้าสู่ระบบได้โดยไม่ต้องคัดลอกหรือเชื่อมต่อกุญแจของมันที่นี่

หาก Telegram ขอให้ใช้การยืนยันตัวตนสองขั้นตอน (2FA) โหมดนี้จะใช้ `twoFA` จากไฟล์ JSON ที่เลือกไว้หากมี หรือขอรหัสผ่าน รหัสผ่านที่นำเข้าแล้วถูกปฏิเสธจะกลับไปยังแบบฟอร์มรหัสผ่าน รหัสผ่านไม่ถูกบันทึกไว้ คีย์ผู้สมัครจะถูกบันทึกไว้ในรูปแบบเข้ารหัสใน `independent_login.enc` รวมถึงการเปลี่ยนแปลงระหว่างการย้ายศูนย์ข้อมูล หลังจาก เกิดการขัดจังหวะ ให้เลือกผู้บริจาคเดิมและตัวเลือกนี้เพื่อต่อคีย์ผู้สมัครที่บันทึกไว้ พื้นที่ทำงานจะยังคงถูกจองไว้สำหรับบัญชีนั้น; การดำเนินการที่ล้มเหลวจะไม่ลบ พื้นที่ทำงานใหม่ ให้เก็บไดเรกทอรีข้อมูลและกุญแจ vault ของมันไว้ ข้อมูลรับรองขั้นสุดท้ายและบันทึกในวารสาร `account.authorized` จะรวมถึงวิธีการนำเข้า รูปแบบข้อมูลที่ป้อน และ ID API ของผู้บริจาค โดยไม่รวมกุญแจหรือรหัสผ่านของผู้บริจาค

เมื่อวันที่5 พฤศจิกายน2026 บัญชีเฉพาะได้ผ่านการตรวจสอบแบบเรียลไทม์กับผู้บริจาค Telethon, Pyrogram และ TData: การเสร็จสิ้นการยืนยันตัวตนสองขั้นตอน (2FA), กุญแจการอนุญาตใหม่ที่ไม่ซ้ำกัน, การเข้าถึงพร้อมกัน โดยผู้บริจาคและลูกค้าใหม่, และการอ่านช่องสาธารณะ กรณี Telethon ยัง ได้ดำเนินการต่อจากผู้สมัครที่บันทึกไว้หลังจากเกิดการขัดจังหวะในขั้นตอนการป้อนรหัสผ่าน การอนุญาตใหม่แต่ละครั้ง ได้เสร็จสิ้นคำขอการเริ่มต้นระบบหกขั้นตอนหลังการเข้าสู่ระบบ และบันทึก ที่ลงนามแล้วได้รับการตรวจสอบแล้ว เซสชันเดิมยังคงใช้งานได้ในทั้งสี่รูปแบบที่จัดเตรียมไว้

[ฐานข้อมูลข้อผิดพลาด RPC](https://core.telegram.org/api/errors.json) ของ Telegram เชื่อมโยง `FRESH_CHANGE_ADMINS_FORBIDDEN` กับการเปลี่ยนผู้ดูแลระบบ, `FRESH_CHANGE_PHONE_FORBIDDEN` กับการเปลี่ยนหมายเลขโทรศัพท์, และ `FRESH_RESET_AUTHORISATION_FORBIDDEN` กับ การเพิกถอนเซสชันอื่น ๆ, การเปลี่ยนระยะเวลาการใช้งาน หรือการลงทะเบียนรหัสผ่าน `SESSION_TOO_FRESH_*` และ `PASSWORD_TOO_FRESH_*` เกี่ยวข้องกับการโอนสิทธิ์การเป็นเจ้าของและ การถอนเงินรายได้หรือของขวัญ นี่ไม่ใช่การดำเนินการเก็บรวบรวมข้อมูล; การเข้าสู่ระบบใหม่ ไม่ได้หมายความว่าจะมีการห้ามอ่านข้อมูลแบบครอบคลุมเป็นเวลา 24 ชั่วโมง การส่งออกข้อมูลสามารถส่งคืน `TAKEOUT_INIT_DELAY_*` แยกต่างหากได้ TgWitness เก็บข้อมูลการหยุดชั่วคราวที่เซิร์ฟเวอร์ร้องขอไว้ และไม่พยายาม รับโทเค็นใหม่โดยอัตโนมัติหรือยกเลิกเซสชันเพื่อหลีกเลี่ยงข้อจำกัด

### คู่ Session + JSON

บัญชีมักถูกแจกจ่ายเป็นสองไฟล์ที่มีชื่อเดียวกัน เช่น `447700900123.session` และ `447700900123.json` ให้เลือกทั้งสองไฟล์พร้อมกัน

- จากไฟล์ JSON TgWitness ใช้ `app_id`/`api_id` และ `app_hash`/`api_hash` ดังนั้นคุณ โดยทั่วไปไม่จำเป็นต้องป้อนข้อมูลรับรอง API
- โปรไฟล์การเชื่อมต่อใช้ `device_model` (ชื่อเรียกอีกอย่างคือ `device`), `system_version` (ชื่อเรียกอีกอย่างคือ `sdk`), `app_version`, `lang_code`, `system_lang_code` (ชื่อเรียกอีกอย่างคือ `system_lang_pack`), `lang_pack` และ `tz_offset` (ตัวเลือกเสริม) (วินาทีจาก UTC, -43200 ถึง 50400) ค่าที่ระบุไว้มีลำดับความสำคัญสูงกว่าค่าเริ่มต้นที่ระบบสร้างขึ้นและภาษาของ แผงควบคุม/เบราว์เซอร์ ชื่อเรียกที่ขัดแย้งกันจะถูกปฏิเสธ โปรไฟล์ที่แก้ไขแล้วจะถูกบันทึกไว้ใน ข้อมูลรับรองพื้นที่ทำงานที่เข้ารหัส และถูกนำกลับมาใช้ใหม่หลังการรีสตาร์ท รวมถึงเวอร์ชันของแอปด้วย
- `phone`, การตั้งค่าพร็อกซี และโทเค็นอุปกรณ์จะถูก**เพิกเฉย** `twoFA` เป็นแบบอ่านอย่างเดียว เมื่อเลือก **สร้างการอนุญาตแบบอิสระ**; การนำเข้าโดยตรงจะเพิกเฉยมัน
- JSON ที่ไม่มีสนามการอนุญาตที่ได้รับการสนับสนุนจะเป็นเพียงข้อมูลเมตาเท่านั้น ให้เพิ่มไฟล์เซสชัน หรือดำเนินการต่อด้วยการเข้าสู่ระบบผ่านโทรศัพท์หรือ QR Code JSON ที่มีเซสชันที่ได้รับการสนับสนุนหรือ Auth Key สามารถทำการอนุญาตได้ด้วยตัวเอง; ดู [Account JSON](https://phishdestroy.github.io/TgWitness/th/docs/reference/accounts/#account-json).

### Telegram Desktop (TData)

TData คือโฟลเดอร์`tdata` ของแอปพลิเคชัน Telegram Desktop (แอปข้ามแพลตฟอร์ม จาก desktop.telegram.org)

| ระบบ | ตำแหน่ง`tdata` ตามค่าเริ่มต้น |
| --- | --- |
| Windows | `%APPDATA%\Telegram Desktop\tdata` (Telegram แบบพกพา: อยู่ข้าง `Telegram.exe`) |
| Linux | `~/.local/share/TelegramDesktop/tdata` |
| macOS | `~/Library/Application Support/Telegram Desktop/tdata` |

เพื่อนำเข้า:

> **คำเตือนเกี่ยวกับเซสชันคู่ขนาน** การนำเข้า TData โดยตรงจะใช้กุญแจการอนุญาตของ Telegram Desktop ซ้ำกัน อย่าใช้กุญแจนั้นใน Desktop และ TgWitness พร้อมกัน Telegram อาจทำให้การอนุญาตเป็นโมฆะด้วย `AUTH_KEY_DUPLICATED` ทำให้ทั้งสองสำเนาไม่สามารถใช้งานได้จนกว่าจะเข้าสู่ระบบใหม่
>
>
>
> ปิด Desktop อย่างสมบูรณ์ รวมถึงกระบวนการในถาดระบบ และรักษาสำเนาดังกล่าวให้ปิดอยู่ระหว่างที่ TgWitness ใช้เซสชันที่นำเข้า **ปิดโปรแกรมเท่านั้น อย่าออกจากระบบหรือยกเลิกเซสชัน:** การยกเลิกจะทำให้สำเนาที่นำเข้าเป็นโมฆะด้วย หากจำเป็นต้องให้ทั้งสองไคลเอนต์ทำงานพร้อมกัน ให้เลือก **สร้างการอนุญาตแบบอิสระ** และรักษา Desktop ให้ปิดอยู่จนกว่า การเข้าสู่ระบบใหม่จะสำเร็จ หรือเข้าสู่ระบบTgWitness ผ่านโทรศัพท์หรือ QR แนะนำให้ใช้ บัญชีเฉพาะ แต่สิ่งนี้ไม่ทำให้การใช้กุญแจที่ถูกโคลนพร้อมกันเป็นปลอดภัย
>
>
>
> สิ่งนี้ยังใช้กับไฟล์`.session` ที่นำเข้า ข้อความ StringSession และ Auth Key HEX ลูกค้าอื่น ๆ ที่มีระบบการอนุญาตที่สร้างขึ้นอย่างอิสระสามารถยังคงลงชื่อเข้าใช้ได้ ดู[เอกสาร AUTH_KEY_DUPLICATED ของ Telegram](https://core.telegram.org/api/errors#406-not-acceptable)

1. ปิด Telegram Desktop อย่างสมบูรณ์
2. สร้างไฟล์ ZIP ที่ประกอบด้วย**เพียง**สองรายการต่อไปนี้จาก `tdata`:

   - `key_datas`
   - ไฟล์ 16 ตัวอักษรที่ลงท้ายด้วย `s` ที่อยู่ข้างๆ โดยทั่วไปคือ `D877F783D5D3EF8Cs`

   การบีบอัดทั้งโฟลเดอร์พร้อมแคชสื่อมักเกินขีดจำกัด (512 รายการ, 32 MiB เมื่อคลายการบีบอัด). 3. เลือกไฟล์ ZIP ในส่วน **Files** หาก Telegram Desktop มี**รหัสผ่านท้องถิ่น** ให้ป้อนรหัสผ่านนั้น ในส่วน **Passcode หรือข้อความเซสชัน**ก่อน นี่ไม่ใช่รหัสผ่าน 2FA

รองรับ: บัญชีเดียวต่อไฟล์เก็บถาวร, ระบบจัดเก็บข้อมูลสมัยใหม่แบบ `key_datas`/`key_data0`/`key_data1`, รหัสผ่านท้องถิ่น ไม่รองรับ: โฟลเดอร์ที่มีหลายบัญชีที่เข้าสู่ระบบ, รูปแบบเดสก์ท็อป รุ่นเก่า, ไฟล์ ZIP ที่ป้องกันด้วยรหัสผ่าน และแอป macOS ดั้งเดิมที่แยกต่างหาก "Telegram for macOS"

### Telethon StringSession

ข้อความหนึ่งบรรทัด โดยทั่วไปเริ่มต้นด้วย `1` และมีความยาวประมาณ 350 ตัวอักษร โหลด มันเป็นไฟล์ `.txt` หรือ `.tgwitness-session` (สูงสุด 4 KiB) หรือวางมันลงใน ส่วน **Passcode หรือ session text** รับเฉพาะสตริง Telethon เท่านั้น; สตริง Pyrogram และ TDLib ใช้รูปแบบที่ต่างกัน

### JSON ของบัญชี

วัตถุ JSON หนึ่งชิ้น ขนาดสูงสุด **64 KiB** ในไฟล์ที่มีส่วนท้ายเป็น **`.json`**

| Field (ชื่อเรียกอื่น) | ความหมาย |
| --- | --- |
| `api_id` (`app_id`) | ID แอปพลิเคชัน, เป็นจำนวนบวก |
| `api_hash` (`app_hash`) | แฮชของแอปพลิเคชัน, 32 ตัวอักษรฐานสิบหก |
| `string_session` (`session_string`, `session_str`; `session` แบบเก่า) | ข้อความ Telethon StringSession ไม่ใช่ชื่อไฟล์ |
| `auth_key` (`auth_key_hex`) + `dc_id` | กรอก Auth Key ครบ 512 ตัวอักษร และ DC 1–5 |
| `user_id` (`id`) | เป็นตัวเลือก; ตรวจสอบกับ Telegram ก่อนที่จะบันทึกการอนุญาต |
| `device_model` (`device`) | คำอธิบายอุปกรณ์เชื่อมต่อ |
| `system_version` (`sdk`) | เวอร์ชันระบบปฏิบัติการของอุปกรณ์ที่เชื่อมต่อ |
| `app_version` | เวอร์ชันแอปพลิเคชันที่ส่งไปยัง Telegram |
| `lang_code`, `system_lang_code` (`system_lang_pack`), `lang_pack` | ภาษาของไคลเอนต์, ภาษาของระบบ และแพ็กเกจภาษาของไคลเอนต์; `lang_pack` ที่ว่างเปล่าได้รับอนุญาต |
| `tz_offset` | ค่า UTC offset (เป็นตัวเลือก) ในหน่วยวินาที ซึ่งส่งมาใน`initConnection.params`; เป็นสตริงแบบจำนวนเต็มหรือสตริงแบบจำนวนเต็มทศนิยม |

หากมีทั้งชื่อแฝงและชื่อหลัก ทั้งสองต้องตรงกัน สนามเซสชัน Telethon ที่ระบุอย่างชัดเจนจะมีลำดับความสำคัญสูงกว่า blob `session` แบบทั่วไปในรูปแบบอื่น หาก ทั้งสองมีเซสชัน Telethon ที่สามารถระบุได้ ทั้งสองต้องอธิบายการอนุญาตเดียวกัน หากไม่มีสนามที่ระบุอย่างชัดเจน `session` ต้องเป็น Telethon StringSession ที่ถูกต้อง ตัวอย่าง:

```
{ "app_id": 1234567, "app_hash": "0123456789abcdef0123456789abcdef" }
```

```
{
  "api_id": 1234567,
  "api_hash": "0123456789abcdef0123456789abcdef",
  "auth_key": "REPLACE_WITH_ALL_512_HEXADECIMAL_CHARACTERS",
  "dc_id": 2,
  "user_id": 123456789
}
```

ตัวอย่างแรกใช้เพียงข้อมูลรับรอง API เท่านั้น; ลงชื่อเข้าใช้ผ่านโทรศัพท์หรือ QR หรือเพิ่มไฟล์เซสชัน ไม่รับรายการจำนวนมาก (อาร์เรย์ JSON ของบัญชี)

## ระบุสิ่งที่คุณมี

| คุณจะเห็น | นี่คือ | การใช้งาน |
| --- | --- | --- |
| `*.session`; เมื่อเปิดในโปรแกรมแก้ไขข้อความ จะเห็น `SQLite format 3` ปรากฏอยู่ด้านบน | Telethon หรือ Pyrogram SQLite | **ไฟล์** (ถูกตรวจพบอัตโนมัติ) |
| โฟลเดอร์`tdata` ที่มี`key_datas` | Telegram Desktop TData | ZIP ไฟล์สองไฟล์ แล้วคลิก "**ไฟล์"** |
| บรรทัดข้อความหนึ่งเริ่มต้นด้วย `1`, ~350 ตัวอักษร | Telethon StringSession | **ไฟล์** |
| `*.json` กับ `app_id`/`app_hash` | ข้อมูลเมตาดาต้าที่เกี่ยวข้อง | **ไฟล์** พร้อมทั้งเซสชัน |
| `*.json` กับ `auth_key` หรือ `string_session` | JSON ของบัญชี | **ไฟล์** |
| 512 ตัวอักษร `0-9a-f` | กุญแจการยืนยันตัวตน | **กุญแจการรับรอง** |
| 32 ตัวอักษร `0-9a-f` | API hash | **API ID + Hash** |
| `td.binlog` หรือ `db.sqlite` จากแอป TDLib | พื้นที่จัดเก็บ TDLib | ไม่รองรับ |
| `123456789:AA…` | โทเค็นบอท | ไม่รองรับ |

## หลายบัญชี

กด **+** ข้างตัวเลือกรายชื่อบัญชี หรือเปิด **บัญชี → การตั้งค่า → การตั้งค่าการเชื่อมต่อ → พื้นที่ทำงาน**, ป้อนชื่อและ ลงชื่อเข้าใช้

- สามารถสร้างพื้นที่ทำงานได้ไม่จำกัด รวมถึงพื้นที่ทำงานหลัก แต่ละพื้นที่ทำงานมีเซสชัน โปรกซี เส้นทาง แหล่งข้อมูล นโยบายการบันทึก บันทึกหลักฐาน กุญแจลงนาม จุดตรวจสอบ และการส่งออกเป็นของตัวเอง
- การเปลี่ยนพื้นที่ทำงานที่แสดงอยู่จะไม่ทำให้พื้นที่ทำงานอื่น ๆ หยุดทำงาน
- บันทึกจะผูกติดกับบัญชีที่สร้างมันขึ้น การลงชื่อเข้าใช้ด้วย บัญชีอื่นจำเป็นต้องใช้พื้นที่ทำงาน (workspace) อีกหนึ่ง และบัญชีหนึ่งไม่สามารถถูกกำหนดให้ใช้กับ พื้นที่ทำงานสองแห่งได้
- โทเคนบนแผงหลักควบคุมพื้นที่ทำงานทั้งหมด [สิทธิ์การเข้าถึงที่มอบให้](https://phishdestroy.github.io/TgWitness/th/docs/reference/access/)สามารถจำกัดการเข้าถึงของผู้ใช้อื่นให้เฉพาะบัญชีและแชทที่เลือกไว้ พร้อมด้วยสิทธิ์การเข้าถึงและขีดจำกัดเซสชันที่แยกกัน
- **บัญชี**จะเปลี่ยนชื่อพื้นที่ทำงานและลบพื้นที่ทำงานที่เพิ่มเข้ามา พร้อมทั้งเซสชัน บันทึก แหล่งข้อมูล และกุญแจลงนาม พื้นที่ทำงานหลักไม่สามารถลบได้จากแผงควบคุม

### การนำเข้าแบบกลุ่มและกลุ่มบัญชี

ใช้ **Accounts → Import accounts** เพื่อเพิ่มบัญชีหลายบัญชี จับคู่ไฟล์ตามชื่อไฟล์ และดูผลการเข้าสู่ระบบของแต่ละบัญชี บัญชีแต่ละบัญชีจะมีพื้นที่ทำงานของตัวเอง

กลุ่มจะรวมบัญชีที่เกี่ยวข้องไว้ด้วยกันโดยไม่รวมเซสชัน กุญแจ หรือ หลักฐานของบัญชีเหล่านั้น **เปิดกลุ่ม** บน **บัญชี** จะนำคุณไปยังหน้าของมันที่ `/groups/<id>`:

- **บัญชี:** เส้นทางการเชื่อมต่อ การสังเกตการณ์ และข้อความล่าสุดของสมาชิกแต่ละคน พร้อมด้วย **เริ่มทั้งหมด** และ **หยุดทั้งหมด**
- **ต้องตรวจสอบ:** บัญชีที่ออกจากระบบแล้ว, ไม่สามารถใช้งานได้ หรือมี ปัญหาด้านการเชื่อมต่อ, การรับข้อมูล, แหล่งข้อมูล หรือสื่อ; ชื่อแต่ละชื่อจะนำไปยังบัตรข้อมูลของบัญชีนั้น
- **การสนทนาที่หลายบัญชีสามารถดูได้:** แหล่งข้อมูลที่แชร์, บัญชีที่ติดตามการสนทนาเหล่านั้น และ การขัดจังหวะในช่วงเวลาการติดตามในพื้นที่ทำงานที่มีอยู่ (สูงสุด 7 วัน) **การส่งออกด้วย N บัญชี** จะแบ่งการส่งออกช่องหรือกลุ่มใหญ่ระหว่างบัญชีเหล่านั้น และลงนามในไฟล์เก็บถาวรหนึ่งไฟล์
- **ส่งออกกลุ่ม:**ZIP หนึ่งอัน พร้อมกับการส่งออกที่ลงนามของแต่ละบัญชีภายใต้ `accounts/` และ `manifest.json` แสดงรายการSHA-256 และลายนิ้วมือกุญแจ ซึ่งได้รับการลงนามโดยพื้นที่ทำงานหลัก ใน `manifest.signature.json`. ตรวจสอบไฟล์เก็บถาวรของแต่ละบัญชีแยกกันด้วย `python -m tgwitness.verify` และลายนิ้วมือที่เชื่อถือได้ของบัญชีนั้น

สมาชิกจะแบ่งปันการตั้งค่าของกลุ่ม; แต่บัญชีแต่ละบัญชีสามารถเก็บค่าการตั้งค่าของตัวเองได้ [ดูการตั้งค่าที่แบ่งปัน](https://phishdestroy.github.io/TgWitness/th/docs/reference/settings/#account-groups) [คู่มือการนำเข้าและกลุ่ม](https://github.com/phishdestroy/TgWitness/blob/main/docs/wiki/Accounts.md#import-accounts-and-share-settings) [และแดชบอร์ดกลุ่มMTProxy](https://github.com/phishdestroy/TgWitness/blob/main/docs/wiki/Proxies.md#pool-dashboard-and-custom-sources)

## ออกจากระบบ

**บัญชี → ออกจาก Telegram** (พร้อมการหยุดการสังเกต) จะขอให้ Telegram ยุติ เซสชัน ดังนั้นเซสชันดังกล่าวจะหายไปจากเมนู **ตั้งค่า → อุปกรณ์** ของบัญชี และลบ เซสชันออกจากคลังพื้นที่ทำงาน ส่วนบันทึก แหล่งข้อมูล การตั้งค่า และกุญแจลงนามจะยังคงอยู่ และ บันทึกจะบันทึกการออกจากระบบ พื้นที่ทำงานยังคงเป็นของบัญชีนั้น: มีเพียง บัญชีนั้นเท่านั้นที่สามารถเชื่อมต่อกับมันได้อีกครั้ง หาก Telegram ไม่ตอบสนอง เซสชันจะยังคงถูกลบ ที่นี่ และแผงควบคุมจะแจ้งให้ทราบ; ให้สิ้นสุดเซสชันใน Telegram ที่ **การตั้งค่า → อุปกรณ์**

## การรักษาความปลอดภัยของไฟล์บัญชี

- ให้ปฏิบัติกับทุก`.session`, TData ZIP, StringSession, Auth Key และ JSON ของบัญชีเหมือน รหัสผ่าน TgWitness เก็บข้อมูลการอนุญาตที่นำเข้าไว้ในคลังข้อมูลที่เข้ารหัส; คุณสามารถ ลบไฟล์ต้นฉบับได้หลังจากนั้น
- อย่าใช้การอนุญาตเดียวกันในสองโปรแกรมพร้อมกัน Telegram อาจเพิกถอนการอนุญาตนั้น (`AUTH_KEY_DUPLICATED`) และทั้งสองโปรแกรมจะหยุดทำงาน
- เซสชันที่หมดอายุหรือถูกยกเลิกไม่สามารถฟื้นคืนได้ด้วยการแปลงข้อมูล โปรดเข้าสู่ระบบใหม่
