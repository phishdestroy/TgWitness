# Описания доказательств

Команда `python -m tgwitness.narrative` генерирует отчёт с ссылками на исходные данные на основе **проверенного полного ZIP**-архива **с доказательствами**. Сначала выполняется аутентификация архива, затем создаются файлы в форматах PDF, HTML, JSON и четыре диаграммы в формате SVG. Предоставленный JSON-файл с вердиктом никогда не принимается в качестве доказательства. Неудачная проверка подписи, несоответствие манифеста или противоречивые свидетельские данные приостанавливают генерацию отчёта.

```sh
python -m tgwitness.narrative evidence.zip --lang de --jurisdiction DE --out narrative-de/
python -m tgwitness.narrative evidence.zip --lang ru --fingerprint COLLECTOR_FP --witness witness.zip --witness-fingerprint WITNESS_FP --check-drand --check-bitcoin --out narrative-ru/
```

Получайте отпечатки независимо. Можно описать пакет без привязки, и в отчёте будет указано, что его привязка отсутствует. В инструкциях отчёта используются `TRUSTED_COLLECTOR_FP` и `TRUSTED_WITNESS_FP`; они никогда не превращают встроенный ключ в независимое решение о доверии. Параметр `--tsa-ca ROOT.pem` включает существующую проверку корневого сертификата по RFC 3161. Внешние проверки используют существующую модель доверия верификатора; см. файл [FOR-THE-RECORD.md](FOR-THE-RECORD.md).

Целевой каталог должен быть пустым. Процесс генерации предварительно выводит все результаты в этот каталог перед их публикацией. Он не перезаписывает существующий отчёт, не связывается с Telegram, не отправляет временные метки, не рассылает электронную почту и не публикует ничего. Сетевые проверки выполняются только по запросу. Входной ZIP-файл остаётся неизменённым. Результатом является производный отчёт, а не новый пакет доказательств с независимым свидетельством.

<a id="saved-configuration-profiles"></a>
## Сохраненные профили конфигурации

Используйте явный локальный файл JSON для сохранения настроек представления и требований к проверке. См. [пример конфигурации](../examples/narrative.json) и [инструкции на русском языке](NARRATIVE.md).

```sh
python -m tgwitness.narrative --write-config narrative-config.json
python -m tgwitness.narrative --config narrative-config.json --profile ru-html --print-config
python -m tgwitness.narrative evidence.zip --config narrative-config.json --profile ru-html --out narrative-ru/
python -m tgwitness.narrative evidence.zip --config narrative-config.json --profile de-proof --fingerprint COLLECTOR_FP --witness witness.zip --witness-fingerprint WITNESS_FP --out narrative-de/
```

Приоритет установлен в следующем порядке: встроенные настройки по умолчанию → настройки из файла `defaults` → запись в именованных `profiles` → явные параметры командной строки. Загружается только файл, указанный с помощью параметра ``--config``; конфигурация, содержащаяся в архиве доказательств, никогда не выполняется и не применяется. Относительные пути к свидетелям и сертификационному центру TSA в файле определяются относительно каталога, в котором находится этот файл; пути в командной строке определяются относительно каталога вызова. Параметр ``--write-config`` отказывается заменять существующий файл. Параметр ``--print-config`` отображает действующие настройки без открытия пакета доказательств или отправки сетевых запросов.

| Параметр | CLI | Значение по умолчанию / значение |
|---|---|---|
| `lang`, `jurisdiction` | `--lang`, `--jurisdiction` | `en`, без юрисдикции; параметр `--jurisdiction none` сбрасывает юрисдикцию профиля |
| `outputs` | `--outputs html json svg` | `pdf html json svg`; требуется указать как минимум один из форматов: PDF, HTML или JSON |
| `diagrams` | `--diagrams timeline flow ladder files` | Все четыре; параметр `--diagrams none` исключает чертежи, если не выбран формат вывода SVG |
| `max_records` | `--max-records` | 100 000 на журнал, допустимо 1–1 000 000; при превышении этого значения процесс останавливается без усечения отчёта |
| `scene_max_records` | `--scene-max-records` | 2000, допустимо 1–10 000; ограничивает количество сгруппированных записей перед добавлением перекрестных ссылок при перезапуске |
| `fingerprint`, `witness`, `witness_fingerprint`, `tsa_ca` | Существующие флаги с названиями, содержащими дефис | Независимо указанные входные данные доверия; отпечатки должны быть представлены в шестнадцатеричном формате SHA-256 строчными буквами |
| `check_drand`, `check_bitcoin` | `--check-drand`, `--check-bitcoin` | `false`; соответствующий параметр `--no-check-…` переопределяет значение `true` в профиле |
| `require_tier` | `--require-tier` | `self_attested`; требования не создают доказательств и не инициируют сетевые запросы неявно |
| `require_pinned_signer` | `--require-pinned-signer` / `--no-require-pinned-signer` | `false`; при необходимости должен быть предоставлен независимо закреплённый сборщик или проверенный соответствующий закреплённый свидетель |
| `expert`, `procedure` | `--expert` / `--no-expert`, `--procedure criminal\|civil` | `false`, `criminal`; добавляет [протокол экспертизы](#expert-examination-protocol) для выбранной юрисдикции и процедуры |

Пример `de-proof` запрашивает внешние проверки и требует наличия параметра `witness_anchored` плюс доверенного фиксатора. Он отклонит архив, в котором отсутствуют эти доказательства. Простое указание отпечатка свидетеля без соответствующего архива свидетеля не удовлетворяет требованию о фиксаторе. Вывод исключительно в формате JSON позволяет избежать требований к шрифтам в PDF. Выбор диаграмм не устраняет текстовую лестницу гарантий, ограничения или ссылки на события. Форматы и языки не изменяют модель машинной сцены; изменение размера сцены влияет только на группировку. Сцена с пробелом также указывает на следующий зафиксированный перезапуск, даже если эта дополнительная перекрестная ссылка превышает предел группировки.

Каждый успешный запуск также записывает файл `**`narrative-run.json`**`: действующие настройки представления/проверки, их SHA-256, хеши входного пакета, опциональный хеш TSA CA, статус PIN-кода и достигнутый уровень. Пути к локальному свидетелю и центру сертификации опускаются. Это неподписанная квитанция о запуске, а не внешнее подтверждение. Она прилагается даже к выводу, состоящему исключительно из PDF или HTML. Хеш настроек описывает объект общедоступных настроек; хеши входных файлов представляют собой отдельные поля.

Коды завершения: 0 — успешно сгенерировано; 1 — сбой при проверке пакета, превышение лимита записей или сбой рендеринга; 2 — неверная конфигурация или несоблюдение требований к PIN-коду/уровню. Неизвестные поля, дубликаты ключей JSON, недопустимые типы данных и конфигурации объёмом более 64 КиБ отклоняются. Не существует настроек, позволяющих пропустить проверку подписи, отключить ограничения, вынести вердикт или пометить переводы как проверенные. Сохраненные профили и настройки CLI не изменяют подписанный входной архив.

Тесты конфигурации охватывают приоритеты и пути, выборочный вывод, целостность примечаний/ссылок без диаграмм, ограниченную группировку, переполнение записей, недопустимые настройки, подделку архива и коды завершения работы CLI. Подписанные тестовые наборы «сборщик» и «свидетель» проверяют требуемый профиль `witness_anchored` с подтверждёнными, отсутствующими и несоответствующими обязательствами; ответы внешней сети в этих тестах являются синтетическими.

<a id="reading-the-report"></a>
## Ознакомление с отчётом

Ознакомьтесь с введением, хронологией, проверками достоверности, примечаниями к записанным данным и командами проверки в указанном порядке. Условия юрисдикции являются необязательными. В приложении указаны все цитируемые записи с указанием журнала, порядкового номера и полного SHA-256. SHA-256 исходного пакета указан в начале документа. Порядковые номера сборщика и свидетеля имеют отдельные пространства имён.

Зарегистрированное заявление описывается как «зарегистрированное заявление». Событие документа, содержащее `signature_claimed: qualified` и `signature_objects: 0`, **не** является основанием для вывода о том, что PDF-файл не подписан, подделан или юридически недействителен. Программа визуализации не проводит самостоятельной проверки подписей PDF-файлов, не подтверждает достоверность QES или DKIM и не восстанавливает более раннюю дату квитанции. Внешние файлы-якоря считаются достоверными только в том случае, если верификатор фактически их проверил. Ожидающая отправка OTS остаётся неподтверждённой.

Подсчёты описывают типы событий. Новые сообщения, правки, уведомления об удалении и отсутствие при повторной проверке остаются отдельными, а записи о покрытии описывают непрерывность. Неизвестные события сохраняют ссылки на источники и примечание с интерпретацией. Даты в сценах берутся из метаданных подписанных событий; проверенные временные метки связывают их внешне. Даты в сети Биткойн — это даты заголовков блоков.

Временная шкала в формате HTML содержит ссылки на события, на которые можно навести курсор мыши или перейти с помощью клавиатуры. Каждый файл SVG имеет заголовок и описание. В PDF используется выделяемый текст и та же геометрия рисунка; он не зависит от браузера или службы преобразования SVG. При генерации японского PDF используется существующая в проекте система обнаружения шрифтов CJK; требуется установка подходящего шрифта. Новых зависимостей от пакетов добавлено не было.

В HTML и PDF проверки достоверности отображаются в виде таблицы состояний с текстовой меткой для каждого состояния; рисунок лестницы представлен только в файле `diagrams/ladder.svg`. Примечания, относящиеся ко всем сценам, отображаются один раз в начале хронологии. Время сцены указывается в формате `YYYY-MM-DD HH:MM:SS.mmm UTC`, а ссылки на последовательные записи сокращаются до диапазонов, например `collector #2–9`; в приложении по-прежнему перечислены все записи с указанием их SHA-256.

<a id="expert-examination-protocol"></a>
## Протокол экспертизы

`--expert` добавляет к описанию черновой вариант отчёта эксперта. Эксперт запускает программу на своём собственном компьютере, используя собственную копию пакета и собственную установку: верификатор сначала проверяет пакет, а в протоколе фиксируются только результаты данного запуска. Протокол, составленный сборщиком, представляет собой описание собственного материала со стороны сборщика; значимым является именно запуск, выполненный экспертом.

```sh
python -m tgwitness.narrative evidence.zip --lang pl --jurisdiction PL --expert --procedure criminal --fingerprint COLLECTOR_FP --out protocol-pl/
python -m tgwitness.narrative evidence.zip --lang ja --jurisdiction JP --expert --procedure civil --fingerprint COLLECTOR_FP --tsa-ca tsa-root.pem --out protocol-ja/
```

В результате запуска рядом с описанием, после параметра `--outputs`, создаются файлы `expert-protocol.html`, `expert-protocol.pdf` и `expert-protocol.json`. Протокол содержит:

| Часть | Содержание |
| --- | --- |
| Вводная часть | Пустые поля для указания дела, назначающего органа, фамилии эксперта, его образования, специальности, опыта работы и срока проведения экспертизы; правовые основания для назначения, вопросы, содержание отчёта и обязанности эксперта; перечень содержания отчёта, требуемого юрисдикцией, в виде контрольного списка; предупреждение об ответственности, составленное в судебном стиле, с строкой для подписи; заявление, если это предусмотрено правилами; хеш-код SHA-256 пакета, рассчитанный в ходе экспертизы |
| Методы и стандарты | Версия TgWitness и SHA-256 исходного кода используемого верификатора; SHA-256 (FIPS 180-4), Ed25519 (RFC 8032), токены временных меток (RFC 3161) и пути сертификатов (RFC 5280), OpenTimestamps в сопоставлении с заголовками блоков сети Биткойн; стандарты в области цифровых доказательств, изданные или принятые в данной юрисдикции. Эксперт указывает, в соответствии с какими стандартами проводилась экспертиза |
| Ход экспертизы | Команды, повторяющие каждую проверку на другой копии. Вводятся отпечатки пальцев, предоставленные экспертом; в противном случае команды сохраняют значения `TRUSTED_COLLECTOR_FP` и `TRUSTED_WITNESS_FP`, поскольку отпечаток, взятый из пакета, лишь повторил бы собственное заявление пакета |
| Результаты | Две группы. **Установленные в результате вычислений**: целостность и время, подтверждённые третьей стороной. **Установленные при соблюдении указанного условия**: ключ сборщика (отпечаток, полученный заранее по другому каналу), сохраненная контрольная точка, независимый свидетель и заверенный цикл сбора данных, каждый со своими условиями |
| Подпись | Пустое поле для имени, даты и подписи. Эксперт может добавить подпись со своим собственным сертификатом; ключ сборщика подписывает журнал, но никогда не подписывает отчёт эксперта |
| Приложение А | Вопросы, содержащиеся в постановлении о назначении экспертизы: вопросы, на которые даёт ответ данный пакет, причём каждый из них сопровождается отметкой, подтверждающей полученный ответ |
| Приложение B | Хеш SHA-256 файла `narrative-run.json` для данного прогона |

В заголовке указаны юрисдикция, процедура, языки суда по названию, язык документа, дата проверки правовых ссылок и SHA-256 пакета. Содержится заявление о том, что каталожные обозначения для гражданского судопроизводства не включаются в уголовный протокол.

Для суда необходимо подать оригинал на английском языке вместе с заверенным или присяжным переводом на язык суда. Присяжный переводчик владеет местной терминологией и знает формальные требования к судебным документам. В протоколе и описательной части приведена данная рекомендация; их версии на других языках представляют собой машинные переводы, предназначенные для ориентации.

Файлы HTML и JSON не содержат информации о времени генерации. Одна и та же версия TgWitness, пакет и исходные данные генерируют байт-идентичные файлы HTML и JSON, что позволяет второму эксперту повторить экспертизу и сравнить файлы. Файл PDF содержит дату создания в своих метаданных.

<a id="examination-catalog"></a>
### Каталог экспертиз

В каталоге [`tgwitness/narrative/examination/`](../../tgwitness/narrative/examination/README.md) хранится по одному файлу на каждую юрисдикцию: назначение эксперта, вопросы, обязательное содержание отчёта, обязанности эксперта, законодательство о деятельности экспертов, ответственность за заведомо ложное заключение с предупреждением, которое подписывает эксперт, любые необходимые заявления, стандарты в отношении цифровых доказательств, а также законодательство об электронной подписи и временных метках. В каждой записи указывается официальный источник и дата проверки, а в разделе `open_questions` перечисляются моменты, которые не удалось подтвердить на основании официального текста. В протоколе эксперту предлагается сверить каждую ссылку с действующим официальным текстом.

Каталог охватывает 61 юрисдикцию: AE, AT, AU, BD, BE, BG, BR, CA, CH, CN, CY, CZ, DE, DK, EE, ES, ET, FI, FR, GE, GR, HK, HR, HU, ID, IE, IL, IN, IR, IT, JP, KR, KZ, LT, LU, LV, MD, MT, MX, MY, NL, NO, PH, PK, PL, PT, RO, RU, SA, SE, SG, SI, SK, TH, TR, TW, UA, UK, US-federal, UZ, VN. `UK` — это Англия и Уэльс; `US-federal` охватывает федеральные суды. Записи различаются по тому, какая часть информации удалось подтвердить на основании официальных текстов: в каждой из них перечислены неподтвержденные моменты в поле `open_questions` (от 3 до 12 на каждую запись), и протокол выводит их для проверки экспертом.

Параметр `--jurisdiction` принимает коды обоих каталогов. Раздел терминов описания и протокол эксперта используют запись из каталога экспертизы для выбранной процедуры `--procedure`. Для 14 юрисдикций, перечисленных ниже, в описании добавляется ссылка на доступ в соответствии с GDPR из более старого каталога терминологии. Без параметра `--jurisdiction` протокол оставляет правовое основание, предупреждение и местные стандарты для добавления экспертом.

<a id="templates-and-jurisdictions"></a>
## Шаблоны и юрисдикции

Имеется 39 полных каталогов фраз и соответствующих глоссариев. Поддерживаемые языки: en, de, fr, es, it, pt, nl, pl, cs, sk, uk, ru, ro, bg, hu, el, sv, da, fi, no, lt, lv, et, tr, ja, zh, zh-Hant, ko, ar, he, fa, hi, ur, bn, id, ms, vi, th, uz. Отчёты на арабском, иврите, персидском и урду оформляются справа налево. Для PDF-файлов на китайском и корейском языках, как и для японского, требуется установленный шрифт CJK; для HTML и JSON он не требуется. В 14 языках, добавленных для использования в судах, количество сцен указывается как «записи в журнале: N», что не требует форм множественного числа. В `no` используется формулировка на языке букмол. В `pt` используется общее правило CLDR для португальского языка. Шаблоны поддерживают ограниченное **подмножество форм множественного числа** ICU, используемое в этих каталогах, включая вложенные заполнители и ветви с точным числом; это не является общей реализацией всех форматоров ICU.
