# เลือกพร็อกซี

Canonical page: https://phishdestroy.github.io/TgWitness/th/docs/proxies/

รักษาการเชื่อมต่อบัญชีไว้ และกำหนดอย่างชัดเจนว่าเมื่อใดเส้นทางของบัญชีนั้นสามารถใช้ที่อยู่ของเซิร์ฟเวอร์ได้

## เลือกโหมด IP ก่อน

01**ซ่อน IP**

ใช้พร็อกซี เมื่อไม่มีพร็อกซีใดทำงานได้ ให้รอโดยไม่เชื่อมต่อ Telegram โดยตรง

02**อนุญาตให้ใช้ตัวเลือกสำรอง**

อนุญาตให้เชื่อมต่อโดยตรงหลังจากช่วงเวลาหน่วงที่กำหนดไว้; กลับไปยังพร็อกซีที่ใช้งานได้เมื่อมีพร็อกซีตอบรับ

03**Tunnel / VPN**

อนุญาตให้ใช้เส้นทางตรงผ่านเครือข่ายของผู้โฮสต์ ตัวเลือกนี้ไม่ติดตั้งหรือตรวจสอบ VPN

เส้นทางจะกำหนดการเชื่อมต่อ โหมด IP จะกำหนดว่าอนุญาตให้มีการเชื่อมต่อโดยตรงหรือไม่

## ให้ pool เป็นผู้ดูแลเส้นทาง

1. เปิด**บัญชี → การตั้งค่า → การตั้งค่าการเชื่อมต่อ**.
2. เลือกโหมด IP และ **MTProxy อัตโนมัติ** หรือป้อนเส้นทางคงที่
3. บันทึกและเรียกใช้**การทดสอบการเชื่อมต่อ Telegram** ได้ด้วย ซึ่งสามารถใช้งานได้แม้ก่อนการเข้าสู่ระบบ
4. หลังจากเริ่มการเก็บข้อมูลแล้ว ให้ตรวจสอบว่าข้อความที่ได้รับการควบคุมได้ส่งถึงบันทึกหลักฐานแล้วหรือไม่

พื้นที่ทำงานใหม่ใช้ MTProxy อัตโนมัติพร้อมฟังก์ชัน Hide IP กลุ่มนี้รวมแหล่งข้อมูลสาธารณะสี่แห่ง ตรวจสอบรายการ รักษาเส้นทางที่ทำงานได้ และแทนที่พร็อกซีที่ล้มเหลว การดาวน์โหลดที่ล้มเหลวจะเก็บรักษาภาพถ่ายหน้าจอ (snapshot) ก่อนหน้าไว้

## ใช้พร็อกซีของคุณเอง

ป้อนรายละเอียด SOCKS5 หรือ HTTP CONNECT, วางลิงก์พร็อกซี Telegram ที่รองรับ หรือระบุแคตตาล็อกผู้ให้บริการ ให้หยุดการสังเกตการณ์ก่อนที่จะเปลี่ยนเส้นทางที่กำลังใช้งานอยู่ รหัสลับ TLS MTProxy ปลอมที่เริ่มต้นด้วย `ee` ยังไม่ได้รับการสนับสนุน

**การตั้งค่าการหมุนเวียน การแชร์ และการลองใหม่**

ในส่วน **Parameters → Automatic MTProxy** ให้ตั้งค่าขีดจำกัดความล้มเหลว (failure thresholds), ระยะเวลาพัก (cooldowns), การหมุนเวียนตามแผน (planned rotation) และจำนวนบัญชีต่อพร็อกซี (accounts per proxy) การตั้งค่าขีดจำกัดการแชร์เป็น 1 จะทำให้บัญชีต้องรอเมื่อไม่มีช่องทางเข้าแบบเอกสิทธิ์ (exclusive entry) ที่ว่างอยู่ ช่วงเวลาการรีเฟรชรายการ (list refresh) และช่วงเวลาการตรวจสอบ (probe intervals) จะตามค่าของพื้นที่ทำงานหลัก (main workspace) พร็อกซีที่แยกกันไม่รับประกันว่าจะมี IP ทางออก (exit IPs) ที่แยกกัน

## แยก Telegram ออกจากคำขอจากภายนอก

MTProxy รับส่งข้อมูลการสื่อสารของ Telegram เท่านั้น ส่วนการบันทึกเวลา การแจ้งเตือน การคัดลอก และการตรวจสอบแหล่งที่มา จะใช้พร็อกซี SOCKS5/HTTP แยกต่างหาก เส้นทาง SOCKS5/HTTP ของบัญชี หรือ Direct หากโหมด IP อนุญาต คำขอจากภายนอกเหล่านี้สามารถปิดใช้งานได้

การกำหนดค่า`TGWITNESS_PROXY_FEED_PROXY` อย่างชัดเจนจะกำหนดเส้นทางของโปรแกรมดาวน์โหลดฟีด [ผู้สังเกตการณ์อิสระ](https://phishdestroy.github.io/TgWitness/th/docs/witness/)จะเก็บการตั้งค่าของตนเองไว้ การควบคุมเหล่านี้ไม่ติดตั้ง VPN ของระบบหรือกำหนดเส้นทางของการรับส่งข้อมูลเบราว์เซอร์
