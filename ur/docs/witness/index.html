ویٹنس بوٹ قائم کریں

ایک الگ عمل کو جرنل چیک کرنے دیں اور آپ کے چینل پر دستخط شدہ چیک پوائنٹس شائع کریں۔

دو ہوسٹس، دو دستخطی کلیدیں

ایک بوٹ اور ایک چینل تیار کریں

BotFather کے ذریعے ایک بوٹ بنائیں اور اسے اپنے زیرِ کنٹرول چینل میں پوسٹ کرنے کی اجازت دیں۔ گواہ کے لیے ایک کمپیوٹر یا سرور منتخب کریں۔ ایک الگ ہوسٹ اور آپریٹر کلیکٹر کے سرور پر دوسری پراسیس کے مقابلے میں زیادہ خودمختاری فراہم کرتے ہیں۔

Extras میں تین مراحل

  1. صرف پڑھنے کی اجازت۔ اضافی آپشنز کھولیں → اپنے چینل میں ایک بوٹ شامل کریں، ایک وِٹنس ٹوکن بنائیں اور رسائی فائل محفوظ کریں۔ یہ چیک پوائنٹس اور ہیلتھ پڑھنے کی اجازت دیتا ہے، نہ کہ گفتگو یا کلیکٹر کنٹرولز۔
  2. چینل اور وقفہ۔ چینل اور ایک کلیکٹر ایڈریس درج کریں جو گواہ سے قابلِ رسائی ہو۔ سیٹنگز فائل محفوظ کریں۔
  3. لانچ۔ witness.json، witness-token.txt اور bot-token.txt کو بطورِ ویٹنس ہوسٹ ایک ساتھ بنائیں۔ انسٹال شدہ پروجیکٹ ماحول میں درج ذیل کمانڈز چلائیں۔
python -m tgwitness.witness run --config witness.json --check-config
python -m tgwitness.witness run --config witness.json

فائلز ڈاؤن لوڈ کرنے سے ویٹنس شروع نہیں ہوتا۔ اس بات کو یقینی بنائیں کہ پہلی دستخط شدہ پوسٹ چینل میں ظاہر ہو، پھر ویٹنس کی پبلک کی فنگر پرنٹ کو الگ سے محفوظ کر لیں۔

شائع کرنے کی تعدد منتخب کریں

ہر چیک کی اشاعت ایک باقاعدہ بیرونی ریکارڈ بناتی ہے۔ پانچ منٹ کے وقفوں سے، یعنی روزانہ فی ورک اسپیس تقریباً 288 پوسٹس۔ جدید ترتیبات تبدیلیوں یا مسائل کی اشاعت، ایک پروکسی اور ایک حسبِ ضرورت Bot API پتہ بھی فراہم کرتی ہیں۔

یہ بوٹ حقیقت میں کس چیز کی تصدیق کرتا ہے؟

گواہ کلیکٹر سے ایک دستخط شدہ چیک پوائنٹ طلب کرتا ہے، اسے متوقع کلید کے خلاف تصدیق کرتا ہے اور ایک الگ دستخط شدہ جرنل رکھتا ہے۔ یہ غیر موجودہ جوابات اور مسترد شدہ جوابات کے ساتھ ساتھ کامیاب چیکس کو بھی ریکارڈ کرتا ہے۔ اشاعت اب بھی اس بات پر منحصر ہے کہ گواہ چل رہا ہو اور ٹیلیگرام کے بوٹ API تک پہنچ رہا ہو۔

یہ کلیکٹر کی رپورٹ کردہ جرنل کی حالت چیک کرتا ہے۔ یہ ہر ٹیلیگرام پیغام کا آزادانہ مشاہدہ نہیں کرتا۔ اس کے لیے کنٹرولڈ ڈیلیوری ٹیسٹ شامل کریں۔

بعد میں شواہد چیک کریں
