# Экспорт аккаунта и минимизированное раскрытие

Экспорт аккаунта занимает аккаунт монопольно. Перед запуском или продолжением экспорта явно
приостановите наблюдение или другой сбор; приложение никогда не останавливает их автоматически.

Под администратором установки выберите **Главная → Выгрузить аккаунт** или **Экспорт → Аккаунт → Настроить экспорт аккаунта**. При необходимости войдите, проверьте объём и явно запустите экспорт. Постоянное наблюдение не требуется. **Сохраненные наблюдения** — отдельный экспорт существующего журнала; его ZIP включает все источники независимо от фильтров журнала. У каждого рабочего пространства свои задания, ключ подписи и хранилище. Выданный доступ к панели, включая неограниченное право на обычный экспорт, не открывает эти маршруты уровня всего аккаунта.

Фильтры по отправителю и тексту раскрываются в разделе **Фильтр по отправителю или тексту сообщения**. Раздел **Данные аккаунта и способ подключения** содержит необязательные категории данных аккаунта и выбор между Takeout и обычной сессией; его сводка показывает выбранные варианты, даже когда раздел свёрнут. Сворачивание этих разделов сохраняет их настройки. Черновики экспорта и отчёта сохраняются в текущей сессии панели при переключении разделов, но не переживают перезагрузку страницы браузера. Существующие задания доступны из любого варианта экспорта.

Этот процесс экспортирует данные, доступные подключённому аккаунту на текущий момент. По умолчанию используется [Telegram Takeout](https://core.telegram.org/api/takeout), который возвращает доступную историю в её текущем состоянии. Секретные чаты записываются в реальном времени [модулем Secret Chat](../PSEUDO-SECRET.md), а правки — наблюдением в реальном времени. Telegram может назначить период ожидания перед началом Takeout. Панель показывает это ожидание и не переключает способ получения данных незаметно для вас. Явно выбираемый вариант с обычным API имеет другой охват и отмечает неподдерживаемые категории.

Takeout — официальный API экспорта, которым пользуется и Telegram Desktop. TgWitness может
записывать JSON, совместимый с Desktop, непосредственно из собственного сбора; импортировать
чужой архив не нужно. ID чатов и сообщений доступны при обоих способах получения.
Скорость экспорта и задержка одобрения Takeout зависят от ограничений Telegram для аккаунта,
от того, публичный ли чат и разрешена ли в нём пересылка. Прежде чем сравнивать скорость,
выполняйте замеры с одинаковым объёмом и одинаковыми настройками медиа.

Для не более чем 20 явно выбранных ID чатов экспорт через обычный API сначала разрешает
эти чаты напрямую и лишь затем обращается к полному списку диалогов аккаунта. Поэтому
читаемый публичный канал можно экспортировать, не вступая в него, даже если его нет
в списке диалогов. Чаты, отсутствующие в кэше, обрабатываются через обычный список. Фильтр
архива продолжает действовать: если Telegram не вернул диалог, а архивные чаты исключены,
неизвестный статус архивации записывается как пропуск.
Takeout сохраняет свою процедуру составления списка по диапазонам. Ни один из способов
не вступает в чаты и не меняет разрешения на пересылку.
В JSON, совместимом с Desktop, каналы, которые Telegram помечает как `left`, попадают
в `left_chats`, включая читаемые публичные каналы, в которые аккаунт не вступал.

И `FLOOD_WAIT`, и `FLOOD_PREMIUM_WAIT` приостанавливают запросы на весь запрошенный сервером
срок. Срок ожидания для аккаунта сохраняется при переподключениях и перезапусках; более короткое
последующее ожидание не может его сократить. Число повторов ограничено, отмена сохраняет
запечатанные страницы, а учётные данные API не меняются ради обхода ограничения частоты.
Premium не покупается.

## Выбор собираемых данных

| Параметр | Значение |
| --- | --- |
| Цель | Укажите, зачем нужен этот сбор. Не вносите сюда лишние имена и чувствительные подробности дела. |
| Язык отчёта | Выберите язык подписей в читаемом отчёте. Исходный текст сообщений не меняется; непереведённые подписи шаблона остаются на английском. Язык фиксируется вместе с подписанными параметрами задания. |
| Типы чатов / ID чатов | Все выбранные типы или только перечисленные чаты; «Избранное» относится к личным чатам. Архивные чаты выбираются отдельно. |
| Даты | UTC. Начальная и конечная календарные даты в панели обе включаются в диапазон. API использует включительную границу `from_utc` и исключительную `to_utc`; панель передаёт начало дня, следующего за конечной датой. Пустая граница оставляет эту сторону без ограничений. |
| ID отправителей | Только сообщения перечисленных отправителей; пустой список включает всех отправителей. |
| Текст содержит | Буквальные фразы без учёта регистра, объединяемые через ИЛИ. Условия по отправителю, датам и собственным сообщениям объединяются через И. |
| Собственные сообщения | Оставить только исходящие сообщения. |
| Типы медиа | Выберите категории вложений или снимите все отметки, чтобы не скачивать файлы сообщений. |
| Лимиты на файл / на все медиа | МиБ на файл и общий объём скачанных медиа в ГиБ. Текст, квитанции, читаемые отчёты и служебные данные ZIP требуют дополнительного места на диске. |
| Категории аккаунта | Для профиля, контактов, фото профиля, историй, метаданных сессий и других данных Takeout есть отдельные переключатели. |

Предустановка **Сведите сбор данных к минимуму** отключает файлы и метаданные аккаунта. Фильтры по отправителю и содержимому применяются до сохранения страниц сообщений и скачивания медиа. Telegram всё равно передаёт страницы истории API с сообщениями, нужными для проверки этих фильтров: фильтры ограничивают то, что сохраняется и скачивается, а невыбранные сообщения с этих страниц всё равно проходят через память процесса. Другое текущее наблюдение в рабочем пространстве имеет собственные настройки охвата и хранения.

История фото профиля и истории по умолчанию не выбраны. Если по делу нужны только сообщения, отключите также профиль и контакты. Если вложения или метаданные не нужны, исключение их при сборе позволяет не хранить в этом экспорте ещё одну копию личных данных.

Для фотографий сохраняется статичный вариант изображения, указанный в их метаданных и манифестах хешей, в том числе для фото с вариантом анимированного аватара. Анимация не подставляется вместо выбранного статичного изображения. Содержимое, которое короче или длиннее наблюдавшегося размера, записывается как неудачная загрузка вложения, а изменённое представление при обновлении ссылки на файл отклоняется. После таких сбоев архив становится частичным, но записи сообщений сохраняются. Независимая проверка также отклоняет сохранённые вложения, подписанная длина которых противоречит наблюдавшемуся размеру или представлению, в том числе в старых архивах.

## Продолжение, охват и проверка

Каждое задание фиксирует свои параметры и аккаунт. Список и полученные страницы подписываются; квитанции страниц записывают хеши, курсоры, время, результаты загрузки вложений и предыдущую квитанцию. Прогресс продвигают только зафиксированные страницы. Перезапуск и продолжение проверяют эти записи, прежде чем продолжить работу. Сменившийся аккаунт, изменённая подписанная страница или несогласованная цепочка квитанций отклоняются. Параметры нельзя изменить посреди сбора: для другого объёма запустите другое задание.

Пауза освобождает аккаунт от выполняемой операции. После перезапуска приложения незавершённая работа остаётся доступной для явного продолжения. Истёкшая сессия Takeout требует явного продолжения; изменение диапазонов разбиения в Telegram может потребовать нового сбора. Продолжение сохраняет прежние наблюдения, поэтому длительный экспорт — не единый атомарный снимок. Во время сбора блокируются другие операции, меняющие аккаунт, и конфликтующие экспорты. Прежде чем удалять рабочее пространство, дождитесь окончания упаковки.

Продолжение сначала проверяет уже полученное содержимое. Для больших архивов на медленном хранилище проверка может превысить настроенный **Инструменты → Параметры → Таймаут действия панели** (по умолчанию 120 секунд). Увеличьте его перед повторной попыткой; при отмене или сбое хранилища задание остаётся приостановленным, а при неудачной проверке целостности завершается ошибкой с объяснением. Проверка должна закончиться или безопасно остановиться, прежде чем её файлы можно будет закрыть. Синтетические проверки не подтверждали никаких заявлений о пропускной способности для больших аккаунтов.

Панель отличает полностью собранный выбранный объём от частичного архива и записывает пропуски и неудачные чтения. Намеренно исключённые файлы отличаются от файлов, загрузка которых не удалась или которые недоступны. Проверяйте охват, даже если проверка целостности прошла успешно. Никакой локальный клиент не может доказать, что Telegram вернул все когда-либо существовавшие сообщения.

Готовые ZIP остаются доступны для повторного скачивания и загрузки по диапазонам HTTP. Архив аккаунта содержит `manifest.json`, `manifest.sig`, подписанный `job.json`, `inventory.json`, `receipts/`, эталонные данные `data/*.jsonl`, выбранные `media/`, читаемый HTML и верификатор. Получите отпечаток коллектора по независимому каналу, затем проверьте архив доверенной установкой:

```sh
python -m tgwitness.verify account-export.zip --fingerprint TRUSTED_SHA256
```

Для архивов, распакованное содержимое которых превышает 4 ГиБ, явно задайте достаточное значение `--max-gib`. Панель проверяет свои аутентифицированные завершённые локальные архивы по заявленному распакованному размеру и опубликованному дайджесту ZIP; внешний CLI сохраняет собственное независимое ограничение размера. Проверяйте архив до открытия читаемого HTML. Встроенный в архив верификатор удобен, но верификатор, полученный независимо, избавляет от необходимости доверять исполняемому коду, поставленному вместе с доказательствами.

Подпись Ed25519 и хеши SHA-256 выявляют изменения, внесённые после того, как коллектор зафиксировал соответствующие байты. Рассматривайте этот результат вместе с записанным объёмом сбора, интервалами получения, квитанциями внешних меток времени и проверками происхождения, доступными для выбранного развёртывания. Более поздние наблюдения записываются отдельно, а ранее полученные версии сохраняются.

## Подготовка раскрытия для юриста или другого получателя

Скачав готовый экспорт, сохраните исходный ZIP и откройте `index.html`
из распакованной копии. Отчёт описывает свой объём, доступный охват и
ограничения. Ссылки на записи в нём состоят из ссылки на архив, пути к документу
и номера записи, поэтому получатель может найти ту же запись в HTML или распечатке.
Пример — [вымышленный отчёт](https://phishdestroy.github.io/TgWitness/demo/report/).

У готового экспорта аккаунта выберите **Подготовить копию для обмена**. Будет создан отдельный подписанный производный архив. Исходный ZIP остаётся неизменным и закрытым; не отправляйте его вместе с минимизированной копией, если получатель не вправе получать его полное содержимое. Язык отчёта для копии выбирается отдельно. После смены языка или любой настройки отбора перед созданием нужен новый предварительный просмотр.

1. Укажите цель раскрытия и выберите даты, ID отправителей и буквальные текстовые условия.
2. Выберите, сохранить ли личности, раскрыть только перечисленных участников или заменить всех псевдонимами. В обоих режимах с псевдонимами также заменяются ID и названия чатов и ID сообщений. Псевдонимы постоянны в пределах одного раскрытия и различаются между независимо подготовленными раскрытиями.
3. Сохраните текст сообщений, полностью исключите его или добавьте буквальные имена и фразы для маскировки. В режимах со скрытием личностей инструмент также маскирует известные скрытые имена отправителей и дополнительные имена пользователей, ID отправителей, совпадающие с целым словом, названия личных чатов, ссылки, адреса электронной почты и строки, похожие на номера телефонов. При сопоставлении известных имён учитывается приведение регистра Unicode, включая `Straße`/`STRASSE`. Общие названия групп и каналов из текста сообщений автоматически не удаляются. Если превышен лимит маскировки известных личностей, сузьте исходный экспорт или исключите текст; инструмент отказывается продолжать, а не пропускает последующие имена молча. Это правила, применяемые по мере возможности, а не полноценная анонимизация.
4. Оставляйте файлы исключёнными, если они не нужны получателю. Включённые оригиналы сохраняют изображение, звук, текст и метаданные. Инструмент их **не** обезличивает.
5. Просмотрите счётчики, предупреждения и примеры преобразованных сообщений, затем явно подтвердите создание. Примеров не больше 12, каждый — не длиннее 2 000 символов текста. Это выборка, а не полная проверка результата. После изменения настроек нужен новый предварительный просмотр. Просмотр действует 15 минут, привязан к сессии этого администратора и к конкретному исходному ZIP; после создания его нельзя использовать повторно. Новый просмотр отменяет предыдущий для того же задания и сессии.
6. Перед передачей полностью просмотрите полученные `index.html` и `messages.jsonl` локально. Если в них раскрыты лишние сведения, создайте новое раскрытие с более строгими исключениями. Не редактируйте подписанный ZIP на месте.

### Сообщения, исключённые отбором

**Предварительный просмотр.** Неполное раскрытие не выглядит полным. В каждом чате, где осталось хотя бы одно раскрытое сообщение, сообщения, исключённые отбором, показываются маркерами `[withheld by selection — rule: sender]` (или `text`, `period`). В параметре **Сообщения, исключённые отбором** выберите один маркер на каждую серию подряд идущих скрытых сообщений (по умолчанию) или по маркеру на каждое сообщение. Маркеры содержат только правило и количество — никогда текст, отправителя, дату или файлы. Чаты, в которых ничего не раскрыто, исключаются полностью, поэтому пакет не выдаёт их существование.

Раскрытые ответы указывают, на что они отвечают: на сообщение, включённое в эту копию, на сообщение, скрытое отбором, или на сообщение, которого нет в исходном экспорте (удалено до экспорта или никогда не экспортировалось; экспорт не может определить, что именно). Скрытое сообщение, на которое отвечает раскрытый ответ, всегда получает собственный маркер, поэтому ответ указывает на запись, объясняющую, почему она пуста. Эти три состояния отличаются от удалений и пропусков сбора, которые относятся к исходному экспорту.

В `messages.jsonl` (формат `tgwitness-account-disclosure-v2`) у каждого сообщения есть `state`: `disclosed` либо `withheld` с `rules` и `count`. У раскрытого ответа есть `reply_to` с `id` целевого сообщения и `state` (`disclosed`, `withheld`, `not_in_source`). Манифест подсчитывает раскрытые сообщения, чаты, медиа и сообщения `withheld`. `verify.py` отклоняет маркер, содержащий данные, и ответ, указывающий на запись, которой нет в пакете; пакеты версии 1 проверяются как прежде.

Минимизированный формат не содержит структурированных профилей аккаунтов, контактов, аватаров, сессий, историй, исходных объектов Telegram, заголовков пересылки, цитат в ответах, контактных карточек и метаданных местоположения. В него не входят исходные файлы JSONL, закрытые настройки фильтров, ключ псевдонимов и таблица соответствия личностей. Выбранный текст, явно сохранённые личности и включённые файлы всё же могут содержать те же имена, ID или фразы, что использовались в фильтрах; их нужно проверить отдельно. Закрытая политика и ключ псевдонимов хранятся в зашифрованном виде в локальном хранилище задания; удаление задания стирает связанные с ним закрытые записи раскрытия. Публичная политика записывает количество фильтров, а не их значения. Указанная цель публична — она есть в манифесте и HTML: явные закрытые критерии и, в режимах с псевдонимами, известные скрытые личности маскируются и там, в том числе когда текст сообщений исключён. Не включайте в цель лишние персональные сведения; неизвестный идентифицирующий контекст может остаться.

Манифест копии связывает производные файлы, публичную политику и хеш исходного ZIP. Проверка может подтвердить целостность, а если исходный архив доступен локально, — и связь с исходником:

```sh
python -m tgwitness.verify minimized-disclosure.zip --fingerprint TRUSTED_SHA256
python -m tgwitness.verify minimized-disclosure.zip --fingerprint TRUSTED_SHA256 --evidence account-export.zip
```

Связь с исходником показывает, из какого архива и под каким ключом сборщика получено раскрытие. Раскрытие содержит только выбранное содержимое; отбор и удаление идентифицирующих подробностей проверяйте по исходному экспорту.

## Передача копии и облачный сбор

Выберите нужные получателю сообщения и файлы, просмотрите копию для обмена целиком и храните исходник отдельно. Запишите хеш переданного ZIP, чтобы получатель мог опознать и проверить именно эту копию. Псевдонимизация заменяет выбранные идентификаторы; включённый текст и исходные файлы по-прежнему нужно проверить.

GitHub Actions поддерживает экспорт всего аккаунта и выбранных чатов через Takeout или обычный API, а также журнал событий одного чата. [Руководство по облачному сбору](https://phishdestroy.github.io/TgWitness/docs/capture/) описывает проверку настроек и ограничение в 120 минут. Чтобы проверить копию для обмена, полученную из облачного сбора, сверьте указанный в ней хеш исходника с исходным архивом и проверьте аттестацию этого архива [проверками для соответствующего режима](../EVIDENCE.md#verification-scope).
