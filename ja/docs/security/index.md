## すべての情報が集約されている場所

コレクター、パネル、すべての記録はあなたのマシンに留まります。既定で接続するのは Telegram だけで、それ以外はすべて個別のスイッチです。

- **Telegram**常に・お客様のルートを通じて

  アカウントのMTProto接続方法：ダイレクト、SOCKS5、HTTP、またはMTProxyです。「IP非表示モード」は、正常に動作するプロキシを待機します。ダイレクトへのフォールバックには、それを明示的に許可するモードが必要です。
- **外部サイト用コピー**オプション・デフォルトではオフ

  ジャーナル、ファイル、チェックポイントは、S3互換のストレージにアップロードされる前にAES-GCMで暗号化されます。鍵はユーザーが管理します。添付ファイルの名前は、内容ハッシュではなく、鍵付きハッシュによって付けられます。
- **通知**オプション・デフォルトではオフ

  チャットタイトル付きの課題と変更点の一覧。メッセージの抜粋は、有効に設定した場合にのみ送信されます。
- **タイムスタンプの信頼性**オプション・デフォルトではオフ

  署名付きチェックポイントの SHA-256 ハッシュと、ランダムなノンスのみが含まれます。メッセージやチャット名は一切含まれません。
- **ウィットネス**オプション・デフォルトではオフ

  読み取り専用トークンを使用して、署名付きチェックポイントとキャプチャカウンターを取得します。会話の内容を読み取ったり、設定を変更したりすることはできません。

デフォルト設定：Telegramへの接続のみがこのマシンから行われます。

保存先はワークスペースごとに設定可能です。メッセージ本文およびメディアは、データディレクトリ内に暗号化されずに保存されますので、ディスク暗号化やファイル権限の設定により保護してください。

## それぞれの秘密が解き明かすもの

| シークレット | 保存場所 | このツールがもたらす可能性 | 万が一情報が漏洩した場合 |
| --- | --- | --- | --- |
| **パネルトークン** | データディレクトリの `panel-token.txt`。ブラウザーはタブごとに保持します | すべてのワークスペースのすべて | TgWitness を停止し、`panel-token.txt` を削除して、再起動します：新しいものが作られます |
| **Telegramのセッション** | Vault、暗号化済み（`credentials.enc`） | Telegramアカウント自体 | Telegramの「*設定」→「デバイス」*からセッションを終了してください。 |
| **署名鍵** | Vault、暗号化済み（`signing.enc`） | あなたのフィンガープリントで記録に署名すること | 別の場所に保管したチェックポイント、証人、タイムスタンプが、以前に存在したものを引き続き示します |
| **Vaultキー** | データの隣にある `vault.key`、または外部のマスターキー | Vault | セッションと署名鍵も漏れたと考えてください |
| **Witnessトークン** | witnessホストについて | 読み取り専用：チェックポイントと稼働状態 | 証人のページで削除し、新しく作ります |
| **外部サイト用コピー用キー** | Vault：復元のために一度ダウンロードしてください | オフサイトコピー | バケットも手に入れた人は復号できます：コピーは漏えいしたものとして扱ってください |

## 保護の対象となる範囲

### 掲載済み

- 記録の変更、削除、並べ替え：ハッシュチェーンか署名が壊れます。
- 別の場所にチェックポイントを保管した後で、ジャーナルが切り詰められたり作り直されたりした場合：チェックポイントが一致しなくなります。
- トークンの推測：256 ビットの乱数、定数時間の比較、1 分間に 15 回失敗するとそのアドレスはブロックされます。
- 悪意のあるチャット内容：本文は常にテキストのままで HTML にはなりません。添付ファイルはファイルとしてダウンロードされ、パネルは他のサイトから何も読み込みません。
- 外部の Vault キーを使っている状態でデータディレクトリが盗まれた場合：セッションと鍵は暗号化されたままです。

### ご判断にお任せいたします

- メインのトークンは何でもできます。他の人には範囲を限ったアクセスを渡し、メインのトークンは自分だけで持ってください。
- マシンの管理者は誰でも、すべてを読み、ジャーナルに署名し直せます。フィンガープリントとチェックポイントは別の場所に保管してください。
- TgWitness はメッセージとメディアを暗号化しません。ディスクを暗号化し、権限を絞ってください。
- localhost 以外での平文の HTTP はトークンを漏らします。HTTPS か SSH トンネルを使ってください。
- 署名は何を見逃したかを教えてくれません。自分のアカウントとソースでカバレッジを確認し、配信をテストしてください。

権限、有効期限、セッション制限を付けて[ケースへのアクセスを共有](https://phishdestroy.github.io/TgWitness/ja/docs/access/)します。

## インストールのセキュリティ強化

8件中0件完了

1. **専用の Telegram アカウントを使ってください**。メインのアカウントは使わないでください。
2. **パネルは 127.0.0.1 に固定してください。**リモートアクセスは HTTPS（同梱の Caddy）か SSH トンネルだけにします。
3. **データディレクトリのあるディスクを暗号化してください**。メッセージとメディアはそのまま保存されます。
4. **データディレクトリへのアクセスを**サービスアカウントに限定してください（Unix では 0700、Windows ではフォルダーの権限）。
5. **サーバーでは Vault キーを別の場所に置いてください**：初回起動前に `TGWITNESS_VAULT_KEY_FILE` を設定します。
6. **フィンガープリントとチェックポイントを保存してください**。保存先は別のシステムにし、証人は別のホストで動かします。
7. `data/`、セッション、`panel-token.txt`、またはVaultキーをGitHubやチャットに**アップロードしないでください**。
8. リバースプロキシでは、`Authorization`ヘッダーやリクエスト本文を**ログに記録しないでください**。

**データを失うことなく、パネルトークンを変更することはできますか？**

はい、トークンで開けるのはパネルだけです。TgWitness を停止し、`panel-token.txt` を削除して、再起動します。ジャーナル、セッション、鍵は残ります。`TGWITNESS_TOKEN` が設定されている場合は、ファイルよりその値が優先されます。

**なぜメッセージは保存時に暗号化されないのですか？**

コレクターは検索、比較、エクスポートのためにそれらを読む必要があります。同じマシンにある鍵では、そのマシンをもともと読める人は止められません。ディスク暗号化は盗まれたディスクを、権限は動作中のシステムを守ります。

## 脆弱性を報告する

GitHub の **Security → Report a vulnerability** を使ってください。バージョン、影響、架空のデータでの最小の再現手順を添えます。認証情報、アカウントのフォルダー、本物の証拠は絶対に送らないでください。非公開の報告が無効なら、エクスプロイトの詳細は書かずに、非公開の連絡手段を求める issue を開いてください。
