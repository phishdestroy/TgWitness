# Выберите способ получения данных

Начните с нужного вам результата. Эти рабочие процессы сохраняют разные наборы данных;
выбор одного из них не приводит к автоматическому запуску другого и не изменяет настройки подключения учетной записи.

| Цель | Где | Результат | Использование учетной записи |
| --- | --- | --- | --- |
| Поделиться уже сохраненными материалами | Экспорт → Сохраненные наблюдения | Архив подписанных журналов, читаемый отчет или сокращенная передача дел | Сообщений в Telegram не поступает; наблюдение можно продолжать |
| Сохранить будущие изменения | «Чаты» → Выберите, затем «Начать наблюдение» | Доставленные сообщения, версии и уведомления об удалении в рабочей области | Является владельцем учетной записи во время работы |
| Добавить историю в рабочую область | Дополнительные инструменты → Источники → Чаты в области поиска → Полная история | Текущие отображаемые сообщения, результаты работы с мультимедиа и доступные «Недавние действия» в журнале, к которому вы вошли | Продолжайте наблюдение; выберите «Стандартный API» или «На вынос» |
| Создать отдельный снимок учетной записи | Экспорт → Аккаунт в Telegram | Избранные чаты, файлы и (по желанию) данные учетной записи в отдельном подписанном архиве | Происходит параллельно с наблюдением; источники наблюдений не определяют этот отбор |
| Экспорт одного чата | Чаты → Экспорт чата | Подписанная выбранная история и контекст, при необходимости разбитые по соответствующим аккаунтам | Каждая выбранная учетная запись должна находиться в неактивном состоянии и уже иметь доступ |
| Защитите важную учетную запись | [Trusted Live](../TRUSTED-LIVE.md) локально или [official Web](../OFFICIAL-WITNESS.md) в GitHub Actions | Видео и подписанные комментарии о том, что отображает официальный клиент Telegram | TgWitness самостоятельно не выполняет запросы к API Telegram и не импортирует сессию; запросы выполняет официальный клиент; предварительный просмотр |
| Сохранить сеанс взаимодействия между официальным представителем и клиентом | Дополнительные инструменты → Дополнительные функции → Независимый захват → Trusted Live | Защищенное видео, сохраненный исходный JSON и артефакты непрерывности | Отдельный модуль записи и ручной вход в систему для сотрудников и клиентов; предварительный просмотр |
| Захват с указанием истории рабочего процесса GitHub | Экспорт → Другие форматы и инструменты для сбора данных → Сбор данных с помощью GitHub Actions | Зашифрованная передача и подтверждение рабочего процесса | Отдельный поток и явно авторизованная сессия; предварительный просмотр |

<a id="existing-observations-and-fresh-reads"></a>
## Существующие наблюдения и новые материалы

Архив ZIP с доказательствами экспортирует сохраненный журнал в пределах фиксированного диапазона. Он не
обращается к Telegram повторно и может быть подготовлен, пока сбор данных продолжается. В читаемом
отчете или сокращенной версии можно выбрать подмножество данных; полный архив ZIP с доказательствами сохраняет
задокументированный объем полного журнала.

Функции «История» и «Экспорт аккаунта/чата» в Telegram теперь работают по-новому. Они отображают то, к чему выбранный
аккаунт имеет доступ во время данного запуска, а не полную реконструкцию прошлого.
Изменения и удаления, которые никогда не фиксировались, могут быть недоступны.

<a id="one-acquisition-per-account"></a>
## Одно приобретение на один аккаунт

Один цикл просмотра полной истории или экспорт данных учетной записи/чата использует слот сбора данных данной учетной записи.
Наблюдение в режиме реального времени продолжается параллельно. Элементы управления паузой работают независимо друг от друга; запуск
сбора данных не приводит к автоматической паузе наблюдения.
Отдельные рабочие пространства аккаунтов могут работать одновременно, имея отдельные идентификаторы
и права доступа.

Во время полной загрузки истории обработчики в режиме реального времени сохраняют внесенные изменения. Последующее
доработка или чтение истории возвращает текущее состояние каждого сообщения. При сравнении сохраненных
версий сравниваются наблюдения, зафиксированные при каждом проходе.

Правила приостановки, возобновления и идентификации учетной записи описаны в разделах [История](../HISTORY.md),
[Экспорт учетной записи](../ACCOUNT-EXPORT.md) и [Распределенный экспорт](../DISTRIBUTED-EXPORT.md).

<a id="official-client-capture"></a>
## Снимок экрана официального клиента

[Trusted Live](../TRUSTED-LIVE.md) использует явно выбранный разъем своего записывающего устройства.
Настройки захвата API не превращают задачу MTProto в захват официальным клиентом.
Нативный экспорт осуществляется вручную; в этом предварительном просмотре сохраняется JSON без связанного с ним
дерева вложений. При захвате только видео отсутствуют идентификаторы структурированных сообщений. Для гибридного сравнения
требуются аннотации оператора, привязанные к сохраненным кадрам.

Аннотации о непрерывности отображаются в отдельном окне чата. Отсутствующие идентификаторы или ответы являются
фактами, требующими расследования; об удалении сообщается в уведомлениях Telegram об удалении.
WARP и регулирование темпа снижают нагрузку на серверы, а решение об ограничениях для аккаунтов принимает Telegram.

<a id="read-the-result-before-handing-it-over"></a>
## Проверьте результат, прежде чем передать его

Проверьте выбранную область источника, зафиксированные версии, время источника и наблюдения,
результаты присоединения и интервалы восстановления. Сверьте архив с достоверными
исходными данными для его режима: ключ сборщика или свидетеля, сохраненная контрольная точка, внешние
хронологические подтверждения и соответствующие доказательства получения данных из GitHub или Intel TDX. В результате должно
быть определено, какие проверки сбора, целостности, непрерывности и времени прошли успешно.

См. раздел «Текущие возможности и квалификация» ](../STATUS.md), чтобы узнать, что уже прошло испытания.
