# Экспорт аккаунта

Canonical page: https://phishdestroy.github.io/TgWitness/ru/docs/reference/account-export/

Экспорт того, что аккаунт может прочитать в данный момент: область действия, возобновляемые задания, подписанный архив и сжатые копии для обмена.

[TgWitness](https://github.com/phishdestroy/TgWitness/blob/main/README.md) / [Документация](https://github.com/phishdestroy/TgWitness/blob/main/docs/README.md) · [Evidence and verification](https://phishdestroy.github.io/TgWitness/ru/docs/reference/evidence/)

![Evidence & verification](https://phishdestroy.github.io/TgWitness/assets/chapter-evidence.svg)

Экспорт аккаунта резервирует его исключительно для своей задачи. Перед запуском или возобновлением явно приостановите мониторинг или другой сбор данных: приложение никогда не останавливает их автоматически.

Как администратор установки выберите **«Начать здесь» → «Экспортировать мою учётную запись**» или **«Экспорт» → «Учётная запись Telegram» → «Настроить экспорт учётной записи**». При необходимости войдите в систему, проверьте объем данных и явно запустите экспорт. Непрерывное наблюдение не требуется. **«Сохраненные наблюдения»** — это отдельный экспорт существующего журнала; его ZIP включает все источники, независимо от фильтров журнала. Каждая рабочая область имеет свои собственные задания, идентификатор подписи и хранилище. Предоставленный доступ к панели, включая неограниченное право на обычный экспорт, не позволяет открывать эти маршруты, относящиеся ко всей учетной записи.

Фильтры по отправителю и тексту раскрываются в разделе **«Фильтр по отправителю или тексту сообщения**». **Раздел «Данные аккаунта и способ подключения**» содержит дополнительные категории аккаунтов и выбор между Takeout и обычной сессией; в его сводке отображаются активные настройки даже в закрытом состоянии. При закрытии этих разделов их настройки сохраняются. Черновики экспорта и отчетов остаются в текущей сессии панели при смене представлений; они не сохраняются при перезагрузке браузера. Доступ к существующим заданиям сохраняется при выборе любого из вариантов экспорта.

Этот рабочий процесс экспортирует данные, доступные в данный момент для подключённой учётной записи. По умолчанию используется [Telegram Takeout](https://core.telegram.org/api/takeout); это не является резервной копией недоступных или удалённых данных Telegram. Секретные чаты, недоступная история и более ранние правки не восстанавливаются. Telegram может установить период ожидания перед запуском Takeout. Панель отображает это ожидание; она не переключает транспортный протокол незаметно. Явная опция regular-API имеет другой охват и записывает неподдерживаемые категории.

Takeout is the official export API also used by Telegram Desktop. TgWitness can write Desktop-compatible JSON directly from its own acquisition; importing someone else's archive is not required. Chat and message IDs are available through both transports. A public chat or permission to forward does not guarantee a faster export or remove Takeout's approval delay. Measure the same scope and media settings before comparing speed.

For up to 20 explicitly selected chat IDs, regular-API export resolves those peers directly before considering the account's complete dialog inventory. A readable public channel can therefore be exported without joining it, even when it is absent from the dialog list. Uncached peers fall back to the ordinary inventory. The archive filter remains enforced: if Telegram does not return a dialog and archived chats are excluded, the unknown archive status is recorded as an omission. Takeout keeps its split-range inventory procedure. Neither path joins chats or changes forwarding permissions. In Desktop-compatible JSON, channels that Telegram marks `left` appear under `left_chats`, including readable public channels the account has not joined.

Both `FLOOD_WAIT` and `FLOOD_PREMIUM_WAIT` pause requests for the full server-requested period. The account's deadline is persisted across reconnects and restarts; a shorter later wait cannot shorten it. Retries are bounded, cancellation preserves sealed pages, and API credentials are not rotated to bypass a rate limit. No Premium purchase is made.

## Выберите, что собирать

| Настройки | Значение |
| --- | --- |
| Цель | Опишите, почему необходимо данное приобретение. Не указывайте здесь ненужные имена или конфиденциальные детали дела. |
| Язык отчёта | Выберите язык меток в отчёте для чтения. Текст исходного сообщения остаётся неизменным; непереведённые метки шаблона используют английский язык. Язык фиксируется с помощью параметров подписанного задания. |
| Типы чатов / идентификаторы чатов | Все выбранные типы или только перечисленные чаты; «Сохраненные сообщения» относятся к личным чатам. Архивированные чаты можно выбирать отдельно. |
| Даты | UTC. В панели указаны даты «С» и «По» по календарю, включая оба дня. API использует включительные `from_utc` и исключительные `to_utc`; панель отправляет начало дня, следующего за датой «До». Пустой предел оставляет эту сторону неограниченной. |
| Идентификаторы отправителей | Только сообщения от указанных отправителей; пустой список включает всех отправителей. |
| Текст содержит | Литеральные фразы, нечувствительные к регистру, сопоставляются с помощью оператора OR. Условия «отправитель/дата/собственное сообщение» комбинируются с помощью оператора AND. |
| Собственные сообщения | Сохраняйте только исходящие сообщения. |
| Типы медиафайлов | Выберите категории вложений или сбросьте все, чтобы избежать загрузки файлов из сообщений. |
| Ограничения на файлы / общее количество медиафайлов | Объём в MiB для каждого файла и общий объём загруженных медиафайлов в GiB. Текст, квитанции, читаемые отчёты и накладные расходы, связанные с ZIP, требуют дополнительного дискового пространства. |
| Категории аккаунтов | Для профиля, контактов, фотографий профиля, историй, метаданных сеансов и других данных Takeout предусмотрены отдельные элементы управления. |

Предустановка **«Minimize»** отключает файлы и метаданные аккаунтов. Фильтры отправителей и контента применяются до сохранения страниц сообщений и загрузки медиафайлов. Telegram по-прежнему передаёт страницы истории API, содержащие сообщения, необходимые для оценки этих фильтров: фильтрация не гарантирует, что неотборные сообщения никогда не поступят в оперативную память. Другие текущие наблюдения в рабочей области имеют собственные настройки области действия и срока хранения.

История фотографий профиля и истории по умолчанию не выбираются. Отключите также профиль и контакты, если для дела требуются только сообщения. Если вложения или метаданные не нужны, их исключение при сборе данных позволит избежать сохранения ещё одной частной копии в этом экспорте.

Photo payloads use the still-image variant identified in their metadata and hash manifests, including photos with an animated avatar variant. That animation is not substituted for the selected still image. A shorter or longer payload than the observed size is recorded as a failed attachment, and a changed representation during file-reference renewal is rejected. These failures leave the archive partial while retaining the message records. Independent verification also rejects saved attachments whose signed length contradicts their observed size or representation, including in older archives.

## Отчёт, охват и проверка

Каждое задание фиксирует свои настройки и идентификатор аккаунта. Инвентарь и захваченные страницы подписываются; в квитанциях страниц фиксируются хеши, курсоры, время, результаты работы с вложениями и предшествующие квитанции. Только зафиксированные страницы учитываются при подсчете прогресса. При перезапуске или возобновлении задания эти записи проверяются перед продолжением работы. Измененный аккаунт, измененная подписанная страница или несогласованная цепочка квитанций отклоняются. Настройки нельзя редактировать в середине процесса сбора данных: для другого объема данных запустите новое задание.

Команда «Pause» приостанавливает текущую операцию с аккаунтом. При перезапуске приложения незавершённая работа остаётся доступной для явного возобновления. Сессия Takeout, срок действия которой истек, требует явного возобновления; изменение диапазонов фрагментов Telegram может потребовать нового сбора данных. При возобновлении сохраняются предыдущие наблюдения, поэтому длительный экспорт не представляет собой единый атомарный снимок. Другие операции по смене аккаунта и конфликтующие экспорты блокируются во время сбора данных. Перед удалением рабочего пространства дождитесь завершения упаковки.

Функция «Возобновить» проверяет уже записанный контент перед продолжением. Объемные архивы на медленном хранилище могут превысить настроенное **в разделе «Параметры» → «Таймаут действия панели»** значение (по умолчанию — 120 секунд). Увеличьте это значение перед повторной попыткой; отмена или прерывание работы хранилища приводит к приостановке задания, а неудачные проверки целостности — к сбою задания с пояснением причины. Проверка должна завершиться или безопасно остановиться, прежде чем файлы можно будет закрыть. Заявления о пропускной способности для крупных аккаунтов не подтверждены синтетическими тестами.

Панель позволяет отличить завершённый выбранный диапазон от частичного архива, а также фиксирует пропуски и неудачные попытки чтения. Намеренно исключённые файлы отличаются от файлов, чтение которых завершилось сбоем или которые недоступны. Проверяйте охват даже в случае успешной проверки целостности. Ни один локальный считыватель не может доказать, что Telegram вернул все сообщения, которые когда-либо существовали.

Готовые ZIP остаются доступными для повторной загрузки и загрузки по HTTP-диапазону. Архив аккаунта содержит `manifest.json`, `manifest.sig`, подписанные `job.json`, `inventory.json`, `receipts/`, авторитетные `data/*.jsonl`, выделенным `media/`, читаемый HTML и верификатор. Закрепите отпечаток коллектора через независимый канал, а затем проверьте с помощью доверенной установки:

```
python -m tgwitness.verify account-export.zip --fingerprint TRUSTED_SHA256
```

Для архивов, расширенный объём которых превышает 4 ГиБ, необходимо явно задать соответствующий `--max-gib`. Панель проверяет свои аутентифицированные, завершенные локальные архивы, используя их заявленный размер в развернутом виде и опубликованный дайджест ZIP; внешний CLI сохраняет свой независимый лимит размера. Проверьте перед открытием читаемого HTML. Встроенный в архив верификатор удобен, но верификатор, полученный независимо, позволяет избежать доверия к исполняемому коду, поставляемому вместе с доказательством.

Подпись Ed25519 и хэши SHA-256 позволяют обнаруживать изменения после того, как сборщик зафиксировал соответствующие байты. Они **не** доказывают, что Telegram подписал эти сообщения, что оператор сборщика действовал добросовестно, что история аккаунта полна или что суд примет эти материалы. Время записи определяется по часам сборщика. Независимые временные метки и независимое происхождение данных должны оцениваться отдельно.

## Подготовьте раскрытие информации для юриста или другого получателя

После загрузки готового экспорта сохраните исходный файл ZIP и откройте `index.html` из извлечённой копии. В отчёте объясняются его объем, доступный охват и ограничения. Ссылки на записи в отчёте объединяют ссылку на архив, путь к документу и номер записи, чтобы получатель мог найти ту же запись в HTML-файле или на распечатке. Пример с решением см. по ссылке [открыть вымышленный отчёт](https://phishdestroy.github.io/TgWitness/demo/report/).

После завершения экспорта аккаунта выберите **«Подготовить копию для обмена**». Это создаст отдельный подписанный производный файл. Исходный файл ZIP остаётся неизменённым и конфиденциальным; не отправляйте его вместе с минимизированным производным файлом, если получатель не уполномочен получать его полное содержимое. Выберите язык отчёта отдельно. Изменение языка или любых настроек выбора требует повторного предварительного просмотра перед созданием.

1. Укажите цель раскрытия информации и выберите даты, идентификаторы отправителей и критерии по тексту.
2. Выберите, сохранять ли идентификационные данные, раскрывать только указанных участников или использовать псевдонимы для всех. В любом режиме с использованием псевдонимов также заменяются идентификаторы/названия чатов и идентификаторы сообщений. Псевдонимы остаются неизменными в пределах одного раскрытия информации и меняются между независимо подготовленными раскрытиями.
3. Можно сохранить текст сообщения, полностью его опустить или добавить конкретные имена/фразы для маскировки. В приватных режимах инструмент также маскирует известные скрытые имена отправителей и альтернативные имена пользователей, идентификаторы отправителей в виде целых токенов, имена в прямых чатах, ссылки, адреса электронной почты и строки, похожие на номера телефонов. Сопоставление по известным именам учитывает преобразование регистра символов в Unicode, включая `Straße`/`STRASSE`. Общие названия групп/каналов не удаляются автоматически из текста сообщения. Если превышен лимит маскировки известных идентификаторов, сузьте исходный экспорт или опустите текст; инструмент не будет молча пропускать последующие имена. Это правила, действующие в рамках разумных возможностей, а не общая анонимизация.
4. Не включайте файлы, если они не нужны получателю. Включенные исходные файлы сохраняют свои пиксели, аудио, текст и метаданные. Инструмент **не** анонимизирует их.
5. Просмотрите предварительный просмотр с подсчётом, предупреждениями и образцами преобразованных сообщений, а затем явно подтвердите создание. Образцы ограничены 12 сообщениями и 2 000 текстовых символов в каждом. Это пример, а не полный обзор результата. Изменение настроек требует повторного предварительного просмотра. Срок действия предварительного просмотра истекает через 15 минут и привязан к данной сессии администратора и точному исходному ZIP; его нельзя повторно использовать после создания. Новый предварительный просмотр аннулирует предыдущий для той же задачи и сессии.
6. Ознакомьтесь с полным результатом `index.html` и `messages.jsonl` локально перед передачей. Если в нём обнаружится ненужная информация, создайте новое раскрытие с более строгими исключениями. Не редактируйте подписанный ZIP на месте.

### Сообщения, не включённые в выборку

**Предварительный просмотр.** Раскрытие информации не выглядит полным, если оно таковым не является. Внутри каждого чата, в котором сохранено хотя бы одно раскрытое сообщение, сообщения, не вошедшие в выделенный фрагмент, отображаются в виде маркеров, `[withheld by selection — rule: sender]` (или `text`, `period`). Выберите **«Сообщения, не включённые в выделение**»: по одному маркеру для каждой серии последовательных нераскрытых сообщений (по умолчанию) или по одному для каждого сообщения. Маркеры содержат только правило и счётчик, но никогда не содержат текст, отправителя, дату или файлы. Чаты, в которых нет раскрытых сообщений, полностью исключаются, поэтому пакет не показывает их существование.

Раскрытые ответы указывают, на что они отвечают: на сообщение, включённое в эту копию, на сообщение, исключённое при отборе, или на сообщение, которого нет в исходном экспорте (удалённое до экспорта или никогда не экспортированное; экспорт не может определить, что именно). Удержанное сообщение, на которое отвечает раскрытый ответ, всегда получает собственный маркер, поэтому ответ указывает на запись, объясняющую, почему оно пустое. Эти три состояния отличаются от удалений и пробелов в наборе данных, которые относятся к исходному экспорту.

В `messages.jsonl` (формат `tgwitness-account-disclosure-v2`) каждое сообщение имеет `state`: `disclosed`, либо `withheld` с `rules` и `count`. Открытый ответ содержит `reply_to` с целью `id` и `state` (`disclosed`, `withheld`, `not_in_source`). Манифест учитывает раскрытые сообщения, чаты, мультимедиа и `withheld` сообщения. `verify.py` Отклоняет маркер, несущий содержимое, и ответ, указывающий на запись, отсутствующую в пакете; пакеты версии 1 проверяются как и ранее.

В сокращённом формате не отображаются структурированные профили аккаунтов, контакты, аватары, сеансы, истории, исходные объекты Telegram, заголовки пересылок, цитаты из ответов, карточки контактов и метаданные о местоположении. Из него исключены исходные файлы JSONL, настройки частных фильтров, ключ псевдонима и карта идентичностей. Выделенный текст, явно сохраненные идентичности и включённые файлы могут по-прежнему содержать те же имена, идентификаторы или фразы, что и в этих фильтрах; они требуют отдельной проверки. Политика конфиденциальности и ключ псевдонима хранятся в зашифрованном виде в локальном хранилище для данного задания; удаление задания приводит к очистке связанных с ним записей о раскрытии конфиденциальной информации. Записи публичной политики фильтруют количество, а не значения фильтров. Заявленная цель указывается публично в манифесте и HTML: явные критерии конфиденциальности, а в режимах псевдонимизации — известные скрытые идентичности также маскируются там, в том числе когда текст сообщения опущен. Не включайте в цель ненужные личные данные; неизвестный идентифицирующий контекст может оставаться.

Его манифест связывает производные файлы, публичную политику и хэш исходного ZIP. Проверка позволяет установить целостность и, если исходный файл предоставлен локально, подтвердить соответствие исходной ссылки:

```
python -m tgwitness.verify minimized-disclosure.zip --fingerprint TRUSTED_SHA256
python -m tgwitness.verify minimized-disclosure.zip --fingerprint TRUSTED_SHA256 --evidence account-export.zip
```

Ссылки на исходные материалы сами по себе не доказывают, что при преобразовании были выбраны все необходимые элементы или удалены все идентифицирующие детали. Исходный открытый текст не встроен в качестве доказательства. Для вынесения такого заключения требуется новая экспертиза.

## Передача копии и облачный сбор

Select the messages and files the recipient needs, review the complete sharing copy, and retain the source separately. Record the delivered ZIP's hash so the recipient can identify and verify that exact copy. Pseudonymization replaces the selected identifiers; included text and original files remain part of the review.

GitHub Actions supports full-account and selected-chat exports through Takeout or the regular API, plus a one-chat event journal. The [hosted capture guide](https://phishdestroy.github.io/TgWitness/docs/capture/) explains settings verification and the 120-minute limit. To verify a sharing copy derived from hosted capture, check its source hash against the original archive and verify that archive's attestation with the [mode-specific checks](https://phishdestroy.github.io/TgWitness/ru/docs/reference/evidence/#verification-scope).
