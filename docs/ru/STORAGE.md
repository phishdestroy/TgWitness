# Хранение и восстановление

Панель разделяет три задачи:

| Задача | Для чего это нужно |
| --- | --- |
| Сохраните резервную копию | Скопируйте подписанный журнал, контрольные точки, сохраненные файлы и экспортные задания в очереди в настроенное хранилище S3. |
| Свободное пространство на диске | Скопируйте выбранные старые вложения в S3 или на удалённый облачный сервер rclone, полностью загрузите их обратно, проверьте зашифрованные байты, а затем удалите проверенную локальную копию. |
| Сохраните копию документа | Настройте функцию S3 Object Lock и проверьте возвращенный статус хранения. Сервис должен подтвердить запрашиваемый режим и дату. |

При освобождении места подписанный журнал никогда не удаляется и не перезаписывается. Каждое вложение сохраняет
свой исходный SHA-256 и квитанцию восстановления. Дополнительное сжатие gzip происходит
до шифрования с аутентификацией. Имена файлов в облаке не содержат имен Telegram,
идентификаторов чатов или исходных имен вложений. Размер одного вложения может составлять до 32 GiB.

Сам по себе ответ на отправку не является разрешением на удаление файла. TgWitness загружает
весь зашифрованный объект, проверяет его размер и SHA-256, сохраняет подтверждение,
а затем непосредственно перед удалением повторно проверяет локальные данные. В случае сбоя при отправке,
несовпадения при обратном считывании или отмены передачи локальный файл остаётся на месте. Если
включенная резервная копия доказательств ещё не скопировала этот файл, удаление также откладывается до её завершения.

<a id="when-the-disk-is-filling-up"></a>
## Когда диск заполняется

Загрузка вложений приостанавливается при достижении значения, указанного в разделе **Дополнительные инструменты → Параметры → Фотографии и файлы →
Приостанавливать загрузку при достижении этого значения свободного места на диске** (по умолчанию — 1 ГиБ), при этом очередь загрузки сохраняется. Текстовые уведомления продолжают поступать. Это
не зависит от настроек уведомлений. Отключение уведомлений не отключает
резерв для загрузки или меры защиты хранилища.

Для более раннего вмешательства включите параметр **Запускать автоматически**, выберите **Удалить локальный
файл для освобождения места** и включите параметр **Запускать дополнительный цикл переноса данных при
недостатке места на диске**. Дополнительное правило запускается при наличии менее 5120 MiB свободного места и продолжается пакетно до тех пор, пока
по умолчанию будет освобождено 10240 MiB. Оба пороговых значения настраиваются. Оно использует те же
условия: место назначения, минимальный возраст файла, ограничение на пакет, полную проверку при обратном чтении и резервное копирование доказательств,
что и при ручном проходе. Оно никогда не включает место назначения самостоятельно.
Проверки выполняются каждые 30 секунд; ошибка или отсутствие прогресса задерживают следующий цикл с давлением
на пять минут. Состояние давления и время повторной попытки сохраняются после перезапуска. Запланированные
циклы по-прежнему используют свой обычный интервал, когда правило давления неактивно.

На панели отображаются свободное пространство, резерв для сжатия, информация о том, включено ли правило давления,
а также файлы, пропущенные из-за нехватки временного пространства. Процессы сжатия и восстановления
перед запуском проверяют максимальный объем требуемого временного пространства и отслеживают доступное
пространство во время записи. Этот резерв представляет собой настроенный резерв для загрузки, минимальный размер которого
составляет 64 МБ для операций хранения. Эти проверки не являются квотой файловой системы;
другой процесс по-прежнему может занимать место между проверками.

Сжатие Gzip является сжатием без потерь и применяется к удаленным объектам; оно не уменьшает размер
активного журнала и не создает локальных архивов. Размер файлов JPEG, видео и ZIP может практически не измениться или
незначительно увеличиться. При включенном сжатии текущему конвейеру упаковки может временно потребоваться примерно
двойной размер вложения плюс резерв. Выберите
начальный порог, достаточно ранний для ваших самых больших файлов. Файл, размер которого слишком велик для подготовки,
сохраняется и фиксируется в отчёте; более мелкие файлы и ранее проверенные удалённые копии могут
по-прежнему освобождать место. Проверенная копия может быть перенесена без создания дополнительного локального файла упаковки.
Для восстановления также требуется временное пространство, и оно может быть отклонено до тех пор, пока не
появится свободное место.

Если нет подходящих данных, которые можно переместить, или не настроен пункт назначения, TgWitness
не может автоматически освободить место. Подписанный журнал никогда не удаляется и не
перезаписывается системой управления хранением. Ему по-прежнему требуется место для новых текстовых наблюдений.

Рабочие пространства на одном сервере используют одни и те же вложения. Сохраненный файл получает имя, соответствующее его
SHA-256; если в другой рабочей области на этом же сервере уже имеется такой же файл в папке
`cas/` каталога данных, новая копия заменяется жесткой ссылкой на него после того, как
оба файла вновь проходят хеширование, так что три рабочие области, сохраняющие один и тот же канал, используют
дисковое пространство только одной копии. Каждая рабочая область по-прежнему имеет свой собственный файл в
каталоге `media/` и читает, экспортирует и выгружает его, как и раньше. Файл, на который невозможно создать ссылку,
например, в файловой системе без жестких ссылок, остаётся отдельной копией. При каждом запуске
TgWitness удаляет из `cas/` только те файлы, на которые больше не ссылается ни одна рабочая область; файл рабочей области
никогда не удаляется на этом этапе.

<a id="connect-a-destination"></a>
## Подключить пункт назначения

В разделе **«Дополнительные инструменты» → «Дополнения» → «Хранение и место на диске» → «Управление хранением»** выберите задачу и место назначения,
сохраните настройки, а затем выберите **Проверить загрузку и скачивание**. В ходе теста загружается небольшой случайный тестовый файл, а затем он
считывается обратно. При этом не используется контент Telegram.

Для S3 используйте фактический конечный пункт, регион и корзину поставщика. Wasabi, Backblaze,
Cloudflare R2 и другие совместимые сервисы используют те же настройки S3. Само по себе наличие совместимого
API не означает поддержку Object Lock. В режиме «Управление» уполномоченный
администратор может обойти ограничения на хранение; в режиме «Соответствие» действуют другие
ограничения. Перед тем как полагаться на ограничения по хранению, ознакомьтесь с возвращаемым статусом Object Lock.

Для места назначения rclone создайте один удаленный сервер с помощью настройки провайдера rclone и
вставьте в панель раздел `[name]` этого удаленного сервера. Установленный помощник поддерживает
MEGA, Google Drive, OneDrive, Dropbox, Box, pCloud и других провайдеров, указанных в
списке выбора. Учетные данные сохраняются в зашифрованном хранилище данного рабочего пространства. Данные обновления OAuth
также сохраняются в хранилище. Учетные данные не добавляются в журнал
событий и не включаются в загрузки при восстановлении.

Помощник устанавливается в рабочей области с закреплённой версией и SHA-256.
Он не добавляется в системную переменную PATH. Файлы конфигурации и рабочие файлы являются
временными файлами в пределах этой рабочей области. Удалённые серверы, основанные на командах и локальных файлах,
не допускаются. В настоящее время rclone требует явно выбранного маршрута **Напрямую** для
внешних запросов. Используйте собственное хранилище S3 для маршрута SOCKS5 или HTTP рабочей области;
rclone не обходит недоступный маршрут без предупреждения.

<a id="keep-the-recovery-file"></a>
## Сохраните файл восстановления

После копирования файлов выберите **«Сохранить файл восстановления»** и сохраните его в месте,
отдельном от установки. Он содержит ключ дешифрования и подписанные
квитанции об объектах, поэтому относитесь к нему как к резервной копии закрытого ключа. Также храните исходную удаленную конфигурацию
и учетные данные для доступа к целевому серверу отдельно. Файл восстановления, созданный до
более поздней копии, не содержит квитанцию этой более поздней копии.

Запишите отпечаток ключа подписи отдельно: сверка подписи с
этим отпечатком позволит определить, кому принадлежит файл восстановления.

Чтобы восстановить отсутствующие квитанции хранения в существующей рабочей области, откройте пункт **Восстановить файлы
из сохраненного файла восстановления** и выберите файл. Панель проверяет подпись и требует использования того же ключа подписи рабочей области
. Она отказывается заменять другой ключ хранилища. Затем выберите **Восстановить
все файлы**. Восстановление приостанавливает действие автоматического правила хранения, чтобы следующий запланированный
цикл не смог сразу же снова удалить восстановленные файлы. Снова включите правило, когда
закончите работу с локальными копиями.

Функция восстановления проверяет шифротекст, подтверждает подлинность расшифровки, распаковывает файл, если
это необходимо, и проверяет SHA-256 исходного открытого текста перед помещением файла в `media/`.
Повреждённый удалённый объект никогда не заменяет локальный файл. При импорте файла восстановления
локальный файл считается присутствующим только в том случае, если его размер и SHA-256 совпадают с квитанцией, поэтому функция **«Восстановить
все файлы»** также восстанавливает локальный файл, байты которого отличаются. Эти байты не
перезаписываются: как только проверенная копия готова, они перемещаются без изменений в
`storage-conflicts/EXPECTED_SHA256.LOCAL_SHA256`, в журнале фиксируются
`storage.local_conflict`, а в результатах восстановления перечисляются все конфликты. Панель «Хранение»
показывает, сколько файлов содержит `storage-conflicts/`, и перечисляет первые 20 с
указанием их размера; команда `recover` выводит каждый конфликт с обоими хешами и его
путем. Пока такой файл не будет восстановлен, при полном экспорте доказательств вам будет предложено сначала восстановить все
файлы.

<a id="recover-after-losing-the-installation"></a>
## Восстановление после потери установки

Установите TgWitness на другом компьютере. Используйте личный файл восстановления, отдельно
записанный отпечаток и исходные учетные данные для входа:

```sh
python -m tgwitness.storage recover \
  --recovery storage-recovery.json \
  --fingerprint TRUSTED_WORKSPACE_SHA256 \
  --credentials original-rclone.conf \
  --output recovered-attachments
```

Для S3 элемент `--credentials` указывает на частный файл JSON, содержащий `access_key` и
`secret_key`; подписанный файл восстановления предоставляет настройки места назначения.
Команда использует прямое внешнее соединение и загружает закреплённый вспомогательный файл,
когда это требуется удалённому серверу rclone. Она отклоняет существующий каталог вывода, если
в этом каталоге находится прерванный процесс восстановления из того же подписанного файла восстановления;
повторный запуск команды сохраняет проверенные файлы и продолжает работу с остальными.

Восстановленные исходные байты записываются в `recovered-attachments/media/`, именованный по
их SHA-256. `recovery-log.jsonl` представляет собой запись операций восстановления без подписи.
Команда не восстанавливает утраченный подписанный журнал или его ключ подписи. Для этого следует сохранять
полную резервную копию рабочей области. Файл восстановления хранилища не является полной резервной копией
рабочей области.

<a id="operator-bot-and-completion-notices"></a>
## Бот-оператор и уведомления об окончании работы

Бот в Telegram принадлежит оператору. Создайте его с помощью BotFather и настройте в панели управления его
токен, целевой чат и явный список разрешенных ID пользователей Telegram. И
отправитель, и чат должны совпадать. Пересланные сообщения и команды от других
ботов игнорируются.

`/status` и `/stats` доступны в режиме «только статус» по умолчанию. В дополнительном
режиме управления добавляются `/pause`, `/resume` и `/copy`. `/copy` запрашивает настроенную
задачу хранения; это не означает, что удалённая загрузка уже завершилась. Команды
не могут передавать произвольные URL-адреса, файлы или программы оболочки.

Используйте отдельные настройки уведомлений для оповещений и завершения задач. Уведомления
о завершении позволяют отличить экспорт учетной записи с пробелами от полного экспорта, а также отображают
историю и количество записей в хранилище. Выдержки из сообщений не включаются, если это не
включено отдельно в настройках уведомлений. Список доступных сервисов формируется на основе фактически
установленного каталога Apprise, а не фиксированного набора примеров поставщиков.
