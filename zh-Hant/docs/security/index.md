## 每個秘密所揭示的真相

| 機密 | 儲存位置 | 它能帶來什麼 | 若發生洩漏 |
| --- | --- | --- | --- |
| **面板代幣** | 資料目錄中的 `panel-token.txt`；瀏覽器依分頁保存 | 每個工作區中的一切 | 停止 TgWitness，刪除 `panel-token.txt`，重新啟動：會產生新的權杖 |
| **Telegram 會話** | Vault，加密版（`credentials.enc`） | Telegram 帳號本身 | 請在 Telegram 的*「設定」→「裝置」*中結束該會話 |
| **簽名金鑰** | Vault，加密版（`signing.enc`） | 以您的指紋簽署紀錄 | 存放在別處的檢查點、見證人和時間戳記仍能顯示先前存在的內容 |
| **金庫金鑰** | 資料旁的 `vault.key`，或外部主金鑰 | 金庫 | 請假定工作階段和簽名金鑰也已外洩 |
| **Witness 代幣** | 關於 Witness 主機 | 唯讀：檢查點和健康狀態 | 在見證人頁面刪除它，再建立新的 |
| **站外文案關鍵詞** | Vault；只需下載一次即可進行資料恢復 | 異地副本 | 同時取得 bucket 的人可以解密它：請將副本視為已外洩 |

## 保護範圍涵蓋哪些內容

### 已涵蓋

- 紀錄被修改、刪除或重新排序：雜湊鏈或簽名會斷裂。
- 在您將檢查點存到別處之後，日誌被截短或重建：檢查點就不再相符。
- 猜測權杖：256 位元隨機值，固定時間比較，每分鐘失敗 15 次即封鎖該位址。
- 惡意聊天內容：文字一律是文字，絕不當作 HTML；附件以檔案形式下載；面板不從其他網站載入任何內容。
- 資料目錄被竊但金庫金鑰在外部：工作階段和金鑰仍維持加密。

### 交由您決定

- 主權杖可以做任何事。請給他人限定範圍的存取權，主權杖留給自己。
- 電腦上的管理員可以讀取一切並重新簽署日誌。請將指紋和檢查點存放在別處。
- TgWitness 不會加密訊息和媒體。請加密磁碟，收緊權限。
- 在 localhost 以外使用一般 HTTP 會洩漏權杖。請使用 HTTPS 或 SSH 通道。
- 簽名不會告訴您遺漏了什麼。請在您自己的帳戶和來源上檢查涵蓋範圍並測試送達。

[分享案件的存取權](https://phishdestroy.github.io/TgWitness/zh-Hant/docs/access/)，可設定權限、到期時間和工作階段限制。

## 強化安裝安全性

已完成 0 / 8

1. **請使用專用的 Telegram 帳號**，絕不要用主帳號。
2. **請將控制面板維持在 127.0.0.1。**遠端存取只透過 HTTPS（內建 Caddy）或 SSH 通道。
3. **請加密存放資料目錄的磁碟**，訊息和媒體以原樣儲存。
4. **將資料目錄限制**為只有服務帳戶可存取（Unix 上為 0700，Windows 上為資料夾權限）。
5. **在伺服器上將金庫金鑰存放在別處**：首次啟動前設定 `TGWITNESS_VAULT_KEY_FILE`。
6. **將指紋和檢查點儲存**在另一個系統上，在另一台主機上執行見證人。
7. **切勿將** `data/`、會話金鑰、`panel-token.txt` 或金庫金鑰**上傳**至 GitHub 或聊天室。
8. 請勿在反向代理伺服器上記錄 `Authorization` 標頭或請求正文。

**我可以在不丟失資料的情況下變更面板代幣嗎？**

可以，它只能打開面板。停止 TgWitness，刪除 `panel-token.txt`，重新啟動。日誌、工作階段和金鑰都會保留。若設定了 `TGWITNESS_TOKEN`，則以該值為準，而非檔案。

**為何訊息在靜止狀態下未經加密？**

收集器必須讀取它們才能搜尋、比較和匯出。放在同一台電腦上的金鑰擋不住原本就能讀取這台電腦的人。磁碟加密防的是磁碟遭竊，權限防的是執行中的系統。

## 回報漏洞

在 GitHub 上使用 **Security → Report a vulnerability**。提供版本、影響以及使用虛構資料的最小重現。切勿傳送憑證、帳戶資料夾或真實證據。若私人回報已關閉，請開一個 issue 要求私人管道，不要寫漏洞利用細節。
