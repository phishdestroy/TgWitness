確保安全

了解 Telegram 的傳輸路徑、公開代理伺服器清單以及可選的外部服務。了解每項密鑰能解鎖哪些功能、防護措施涵蓋哪些範圍，以及哪些部分需要您自行處理。

所有內容的匯集之處

該收集器、其控制面板以及所有儲存的記錄，均保留在您運行該工具的電腦或伺服器上。預設情況下，Telegram 是唯一的輸出目的地；其他每個目的地皆需透過獨立開關設定。

保護範圍涵蓋哪些內容

✓ 已涵蓋

  • 若匯出紀錄中出現遭變更、刪除或重新排序的項目：雜湊鏈或簽名將無法通過驗證。
  • 若日誌在檢查點之後被刪減或重建，且該檢查點已儲存於其他位置：則保留的檢查點將不再與當前日誌內容相符。
  • 面板代幣猜測機制：256 位元隨機位元組，以恆定時間進行比對；若每分鐘失敗 15 次，該位址將被拒絕。
  • 具敵意之聊天內容：文字以純文字形式插入，絕不以 HTML 格式呈現；附件將以檔案形式下載；該面板不會從其他網站載入任何內容。
  • 一個包含外部金庫金鑰的複製資料目錄：若無主金鑰，會話與簽名金鑰將保持加密狀態。

! 交由您決定

  • 主控制面板的代幣擁有完全控制權。可授予他人有限度的存取權限，使其僅能存取所需的帳戶、聊天室及操作；請務必將主金鑰保密。
  • 該伺服器的管理員可讀取所有內容，並能重寫及重新簽署該日誌。請將指紋與檢查點儲存於另一套系統中。
  • TgWitness 不會對訊息內容及媒體檔案進行加密。請使用磁碟加密並設定嚴格的存取權限。
  • 若透過 localhost 以外的純 HTTP 連線，網路將暴露該存取憑證。請使用 HTTPS 或 SSH 隧道。
  • 簽名用以證明所記錄的內容未被篡改，而非證明每個 Telegram 事件均已被記錄。

可透過權限設定、有效期限及會話限制，分享案件存取權限。證人代幣仍為獨立的憑證。

強化安裝安全性

已完成 0 / 8
  1. 請使用專用的 Telegram 帳號——切勿使用您的主要帳號。控制面板代幣與會話可讓您完全掌控該帳號。
  2. 請將控制面板維持在 127.0.0.1。僅可透過 HTTPS（內建的 Caddy 設定）或 SSH 隧道進行遠端存取。
  3. 對存放資料目錄的磁碟進行加密：訊息內容與媒體檔案均以原始接收狀態儲存。
  4. 將資料目錄限制在服務帳戶內。在 Unix 系統上，新建立的目錄預設權限為 0700；在 Windows 系統上，請設定該資料夾的權限。
  5. 請將金庫主金鑰存放於其他伺服器上：在建立資料目錄之前，請先設定 TGWITNESS_VAULT_KEY_FILE。
  6. 請將簽名金鑰的指紋和檢查點儲存於另一套系統中，並在另一台主機上新增一名見證者。
  7. 切勿將 data/、會話金鑰、panel-token.txt 或金庫金鑰上傳至 GitHub 或聊天室。
  8. 請勿在反向代理伺服器上記錄 Authorization 標頭或請求正文。
我可以在不丟失資料的情況下變更面板代幣嗎？

是的。該代幣僅用於開啟控制面板。停止 TgWitness 運作，從資料目錄中刪除 panel-token.txt，然後重新啟動；日誌、會話及金鑰均保持不變。若設定為 TGWITNESS_TOKEN，則會使用環境變數值而非檔案內容。

為何訊息在靜止狀態下未經加密？

收集者必須讀取這些記錄，才能進行搜尋、比對版本及匯出。若僅在同一台機器上使用金鑰進行加密，對於能夠讀取該機器的人而言，幾乎起不到任何防護作用。磁碟加密能保護已停用或遭竊的磁碟；嚴格的權限設定則能保護正在運行的磁碟。

回報漏洞

請透過 GitHub 儲存庫中的「安全性」→「回報漏洞」功能進行回報。請包含版本資訊、影響範圍以及最簡化的重現步驟。切勿傳送憑證、帳戶目錄或真實證據檔案。若無法進行私下回報，請開啟一個問題，請求開設私人頻道，並避免在其中提及漏洞利用細節。
