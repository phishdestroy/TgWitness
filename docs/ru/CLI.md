# Командная строка для скриптов и агентов

[MCP только для чтения](MCP.md) · [Полнотекстовый поиск](SEARCH.md) · [Вики](../wiki/Archive-and-Integrations.md)

**Предварительный просмотр.** Команды `tgwitness search`, `context`, `messages`, `stats` и `export` считывают сохранённые наблюдения для скриптов и ИИ-агентов. Они не могут отправлять что-либо в Telegram, изменять настройки или модифицировать подписанный журнал. Команды `tgwitness index` и `tgwitness backup` (см. [ниже](#index-and-backup)) работают с локальным каталогом данных и не требуют токена.

При использовании параметра `--json` в stdout выводится ровно один документ JSON (команда `export` записывает данные в формате JSON Lines). Информация о ходе выполнения, подсказки и ошибки выводятся в stderr. Коды завершения являются стабильными:

| Код | Значение |
| --- | --- |
| `0` | Успех, включая пустой результат |
| `1` | Ошибка: недоступная панель, нечитаемые данные, прерванный экспорт |
| `2` | Ошибка использования или недопустимый запрос: неверная дата, неизвестный параметр, отключенный индекс поиска |
| `3` | В данный момент недоступно: рабочая область открыта в запущенной панели, либо панель просит повторить попытку позже (ограничение частоты запросов, превышение времени ожидания) |
| `4` | Доступ запрещён: отсутствующий, просроченный или отозванный токен; чат, выходящий за пределы его области действия; инструмент, который это не допускает |
| `130` | резервное копирование (`backup`) остановлено с помощью Ctrl+C: в место назначения ничего не было записано |

<a id="two-ways-to-read"></a>
## Два способа чтения

**Через панель (`--url`).** Команда использует тот же API архива с ограниченной областью действия, что и MCP. Установите соединение в разделе **Дополнительные инструменты → Интеграции → MCP**: выберите рабочие области и чаты, инструменты и срок действия, затем скопируйте токен один раз. Это соединение предназначено только для чтения, ограничено указанными чатами, имеет ограничение по частоте запросов (60 запросов в минуту) и может быть отозвано или обновлено в любой момент. Токены входа в панель и учетные данные Telegram здесь не работают.

```sh
export TGWITNESS_URL=https://panel.example.org      # default http://127.0.0.1:8787
export TGWITNESS_MCP_TOKEN=tgw_mcp_...              # or --token-file path
tgwitness search 'перевод карта' --json
```

Удаленная панель требует HTTPS; простой HTTP допускается только для `127.0.0.1`, `localhost` и `::1`. Переменные среды прокси игнорируются, а перенаправления отклоняются, поэтому токен попадает только на указанный вами адрес.

**Непосредственно из остановленной рабочей области (`--data-dir`).** Осуществляет чтение каталога данных с полным локальным доступом без использования токена. Используйте эту опцию на копии каталога данных или во время остановки сбора данных. Подписанные записи никогда не изменяются; как и в случае с панелью, открытие рабочей области может привести к обновлению производных индексов. Если панель имеет открытую рабочую область, команда завершается с кодом `3`; вместо этого читайте данные через панель. При отсутствии параметра `--data-dir` используется `TGWITNESS_DATA`, `./data/live` или каталог данных установки, в которой запускается команда.

Параметр `--workspace ID` позволяет выбрать рабочую область (по умолчанию — `default`). Команда `tgwitness messages --workspaces` выводит список рабочих областей, которые доступны для чтения.

<a id="commands"></a>
## Команды

| Команда | Результат |
| --- | --- |
| `tgwitness search QUERY [--chat ID] [--since] [--until] [--any] [--limit N] [--offset N]` | Наилучшие совпадения вначале, с учетом форм слов, точных фраз в кавычках, доменов и `@username` ([синтаксис](SEARCH.md#search-syntax)) |
| `tgwitness search QUERY --exact [--before SEQ]` | Точный текст, сначала самые новые, без учета индекса |
| `tgwitness context CHAT_ID MESSAGE_ID [--limit N] [--before SEQ]` | Сохраненные сообщения в пределах десяти идентификаторов сообщений в обе стороны |
| `tgwitness messages [--limit N] [--offset N]` | Чаты, которые вы можете читать |
| `tgwitness messages CHAT_ID [--since] [--until] [--limit N] [--before SEQ]` | Сохраненные сообщения чата, сначала самые новые |
| `tgwitness messages CHAT_ID --message ID` | Каждая сохраненная версия и запись об удалении одного сообщения |
| `tgwitness stats [--chat ID] [--sender ID] [--since] [--until] [--top N]` | Статистика активности, приведена ниже |
| `tgwitness export [--chat ID] [--since] [--until] [--output FILE]` | Сохраненные наблюдения в формате JSON Lines в порядке ведения журнала |

Даты указаны в формате `2026-10-01` (полночь по UTC) или в формате ISO с указанием часового пояса: `2026-10-01T09:00+03:00`. При `search`е, работе с `messages` и `export`е выбирается время наблюдения. Страницы содержат до 50 записей: для ранжированного поиска используйте `next_offset` (`--offset`), а в остальных случаях — `next_before` (`--before`).

Ранжированный поиск ограничивается 1 000 результатами. Последняя страница может быть короче, чем указано в параметре `--limit`. Если совпадающих наблюдений больше, на последней странице отображается соответствующее уведомление (`truncated: true` при использовании `--json`); сузьте запрос, выберите другой чат или период.

В простом формате вывода каждая запись начинается с её порядкового номера в журнале и времени, когда сборщик зафиксировал её (`observed`), за чем следует время, указанное Telegram, если оно имеется: `sent` для сообщения, `edited` для отредактированной версии. Уведомление об удалении содержит только время наблюдения. Параметр `--json` передаёт оба значения как `observed_at` и `source_at`.

Каждый результат по сообщению содержит значение `untrusted_content: true`, идентификаторы рабочей области, чата и сообщения, порядковый номер в журнале, хеш сохраненной записи и ссылку на панель. Редактирования, уведомления об удалении и `missing_on_recheck` представляют собой отдельные записи. Показатель «Охват» в разделе `stats` отражает периоды, к которым относятся результаты поиска.

<a id="activity-statistics"></a>
### Статистика активности

В разделе `stats` подсчитывается количество сохраненных наблюдений для одного чата, одного отправителя или всех чатов в пределах области охватывания:

- количество сообщений по часам UTC и по дням недели (начиная с понедельника), а также самые активные часы и дни;
- доля отредактированных, удалённых и `missing_on_recheck` сообщений;
- отправители с количеством сообщений, а также временем отправки первого и последнего сообщения;
- наиболее часто встречающиеся домены и `@handles`, подсчитываемые один раз на каждое сообщение по всем его сохраненным версиям;
- покрытие: записи `coverage.gap`, а также — при доступе к всему рабочему пространству — периоды отсутствия сигнала о работоспособности подключенного сборщика (`collector_liveness`).

Период определяется **временем сообщения, указанным Telegram**. Подсчёт часов и дней недели помогает оценить часовой пояс отправителя. Цифры рассчитываются по запросу из журнала и не сохраняются. Каждый результат указывает имя вершины журнала, который он охватывает, если ваш доступ распространяется на всю рабочую область. Чтение прекращается через пять секунд при работе через панель или через `--timeout` секунд локально (по умолчанию 30); после этого значение `complete` принимает значение false, а `partial` указывает первую запись, которая не была прочитана. В этом случае учитываются только самые последние записи.

<a id="export"></a>
### Экспорт

Команда `export` записывает по одному объекту JSON на каждое сохранённое наблюдение (новые сообщения, моментальные снимки, правки, восстановленные сообщения, уведомления об удалении, записи `missing_on_recheck` и сохранённые медиафайлы) в порядке журнала. Каждая строка содержит те же поля, что и другие результаты, с полным текстом. При использовании параметра `--output` файл записывается под именем `.partial` и переименовывается только после записи о завершении работы панели; прерванный экспорт не оставляет файла и завершается с кодом `1`. Параметр `--output` никогда не перезаписывает существующий файл. При использовании параметров `--output` и `--json` в stdout выводится сводка: количество записей, последний номер журнала и, при доступе ко всему рабочему пространству, вершина журнала.

Для экспорта через панель требуется соединение, допускающее **сообщения Export (только из командной строки)**; по умолчанию эта опция не выбрана. Данный файл является рабочей копией; для проверяемой передачи данных используйте подписанный экспорт в **разделе Экспорт**, который проверяется командой ``python -m tgwitness.verify``.

Панель проводит повторную проверку прав доступа перед отправкой каждой записи, включая запись о завершении. Отзыв или истечение срока действия прав доступа приводит к неполному экспорту. Отложенное чтение страниц делит лимит архивного рабочего процесса с другими запросами и имеет ограниченное время ожидания.

<a id="index-and-backup"></a>
### Индексирование и резервное копирование

Эти две команды читают данные непосредственно из каталога и не принимают ни токен, ни параметр ``--url``.

| Команда | Результат |
| --- | --- |
| `tgwitness index status [--workspace ID] [--data-dir DIR] [--json]` | Проверка состояния индекса одной рабочей области или, по умолчанию, всех рабочих областей: режим (`ready`, `building` или `not built`), индексированность и вершина журнала. Работает во время работы панели |
| `tgwitness index rebuild [--workspace ID] [--data-dir DIR] [--json]` | Перестраивает индекс, начиная с первой записи журнала. Перезаписывает только производный индекс, но никогда не затрагивает подписанный журнал. Выходит с кодом `3`, если панель имеет открытую рабочую область. Ничего не создаётся, если рабочая область хранит индекс в памяти или у неё отключен поиск |
| `tgwitness backup FOLDER [--data-dir DIR] [--json]` | Копирует весь каталог данных в новую или пустую папку за пределами каталога данных при продолжающейся работе панели и записывает файл ``backup-manifest.json``, содержащий SHA-256 каждого файла и вершины журналов. Папка появляется только после завершения копирования; в случае сбоя или прерывания копирования ничего не сохраняется |
| `tgwitness verify-backup FOLDER [--json]` | Проверяет папку резервной копии, не изменяя её: сравнивает размер и SHA-256 каждого файла, указанного в манифесте, сообщает о файлах, отсутствующих в манифесте, и сравнивает последнюю запись каждого журнала с манифестом |

Команда `index` принимает параметр `--workspace default` или идентификатор рабочей области; по умолчанию используется значение `all`. При резервном копировании пропускаются временные экспорты, файлы-сайдкар SQLite и файлы блокировки. В этой папке хранятся сеансы и ключи подписи Telegram, поэтому обеспечьте её такую же конфиденциальность, как и каталог данных. В разделе [Резервное копирование, восстановление и ёмкость](DEPLOYMENT.md#backup-restore-and-capacity) описаны процедуры восстановления и то, что фиксируется при следующем запуске.

<a id="mcp-and-the-command-line"></a>
## MCP и командная строка

Оба используют одни и те же подключения, проверки области действия и ограничения. Результаты MCP ограничены одной страницей объёмом 64 КиБ, поэтому MCP не поддерживает массовый экспорт; командная строка передаёт данные потоком. Команда ``get_activity_stats`` доступна для обоих.
