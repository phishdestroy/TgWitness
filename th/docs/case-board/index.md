# สร้าง Case Board

Canonical page: https://phishdestroy.github.io/TgWitness/th/docs/case-board/

เปลี่ยนข้อมูลการสังเกต Telegram ที่บันทึกไว้ให้เป็นคดีที่ทีมของคุณสามารถตรวจสอบร่วมกันได้

Case Board เก็บบันทึกบุ๊กมาร์ก ส่วนข้อความที่ถูกเน้นด้วยข้อความต้นฉบับแบบตรงตามตัวอักษร ส่วนที่ถูกบันทึกไว้ และบทสนทนาไว้ข้างๆ อ้างอิงแหล่งที่มา การจัดเก็บข้อมูลช่วยให้คดีมีโครงสร้างการทำงานที่ชัดเจน; ส่วนการแก้ไขที่ลงนามจะบันทึกไว้ว่าทีมได้พัฒนาคดีนี้อย่างไร

## จากข้อความสู่บัตรคดี

1. เปิด **Investigation → Case Board** ในโหมด Standard หรือ Expert สร้างคอลเลกชันสำหรับคดีและเลือกขอบเขตการสนทนา
2. ใน **Journal** หรือการสนทนาที่บันทึกไว้ ให้เลือก "**To board**" หรือเน้นที่บันทึกแล้วกด **B** บัตรจะเข้าสู่ Inbox; ตั้งชื่อที่เหมาะสมและย้ายไปยังคอลเลกชันของคุณ
3. เลือกข้อความในบทสนทนาที่บันทึกไว้ แล้วเลือก **Highlight → board** เพื่อรักษาคำอ้างอิงและเวอร์ชันข้อความไว้อย่างถูกต้อง เพิ่มหมายเหตุอธิบายว่าทำไมข้อความนี้จึงสำคัญ
4. หารือเกี่ยวกับบัตรข้อมูล กำหนดสถานะการตรวจสอบ และกลับไปยังบริบทต้นทางเมื่อใดก็ตามที่จำเป็นต้องตรวจสอบข้ออ้าง ใช้ **Presentation** เพื่อนำเพื่อนร่วมงานดูข้อมูลที่เก็บรวบรวม

### โปรดติดตามลิงก์การชำระเงินที่เปลี่ยนแปลงไปหนึ่งลิงก์

ตัวอย่างสังเคราะห์ · ภาพประกอบท้องถิ่น

1. **บันทึกข้อมูล.** เปิดบันทึกการสังเกต #142 ที่เก็บไว้และเวอร์ชันข้อความของมัน
2. **บุ๊กมาร์ก.** เก็บคำอ้างอิง, แหล่งที่มา และคำถามของคุณไว้บนบัตร
3. **ตรวจสอบ.** เพิ่มความคิดเห็นของทีมและย้ายบัตรไปยังขั้นตอน "ตรวจสอบ"
4. **แสดงผล.** นำผู้ใช้ผ่านขั้นตอนการเก็บรวบรวมข้อมูลและเปิดบริบทของแหล่งข้อมูลที่อ้างอิง

#### บันทึกการสังเกตที่เก็บไว้ #142

“ใช้ลิงก์การชำระเงินใหม่”

แชทการดำเนินงาน · ข้อความที่ 38 · เวลาที่สังเกต 09:12 UTC

#### Card: เปลี่ยนจุดหมายปลายทาง

> ใช้ลิงก์การชำระเงินใหม่

คำถาม: จุดหมายปลายทางใดปรากฏในเวอร์ชันก่อนหน้า?

#### การตรวจสอบโดยทีม

นักวิเคราะห์: เปรียบเทียบกับข้อสังเกต #101.

สถานะ: ทบทวน · เก็บฉบับแก้ไขไว้

#### บริบทของข้อความต้นฉบับ

Card → เวอร์ชันที่บันทึกไว้ → การสังเกตการณ์ก่อนหน้านี้

คำอธิบายประกอบและการสังเกต Telegram ยังคงสามารถระบุแยกกันได้

## บันทึกช่วงที่มีประโยชน์ไว้ครั้งเดียว

กด Shift พร้อมคลิกบันทึกสองรายการในแชทเดียวกันเพื่อใช้ **Slice between**, เลือก **Slice by time** หรือบันทึกตัวกรอง Journal ปัจจุบัน ตรวจสอบจำนวนก่อนบันทึก เปิด Slice อีกครั้งเพื่อใช้คำค้นหาที่บันทึกไว้; **ตัวเลือก Show records added since bookmark** จะแสดงบันทึกที่เพิ่มเข้ามาภายหลัง

ช่วงเวลากำหนดตามเวลาที่ Collector สังเกตการณ์ ช่วง ID ข้อความสามารถติดตามข้อความที่เลือกไว้ได้เมื่อมีการเปลี่ยนแปลงเกิดขึ้นในภายหลัง ขอบเขตการสร้างที่บันทึกไว้ช่วยให้ผู้รับสามารถเปรียบเทียบการเลือกเดิมกับสถานะในภายหลังได้

## กำหนดบทบาทที่เหมาะสมให้แต่ละเพื่อนร่วมงาน

**ผู้ตรวจสอบ**อ่านบอร์ด;**นักวิเคราะห์**เพิ่มการ์ดและแสดงความคิดเห็น;**ผู้ดำเนินการยัง**จัดการชุดข้อมูลและตัดสินใจเกี่ยวกับการตรวจสอบด้วย สิทธิ์การใช้งานพื้นที่ทำงานและแชทมีผลต่อการ์ด บริบทต้นฉบับ และการอภิปราย ใช้สิทธิ์การเข้าถึงที่กำหนดชื่อเพื่อระบุแหล่งที่มาอย่างชัดเจน

## นำงานไปจัดทำเป็นเอกสารส่งมอบ

ส่งออกส่วนข้อมูล (slice) ในรูปแบบ JSON ที่ลงนาม หรือใช้ CSV สำหรับสเปรดชีต การตั้งค่ารายงานสามารถรวมบุ๊กมาร์กและส่วนข้อมูล (slice) ได้ พร้อมด้วยความคิดเห็นของทีมเมื่อถูกเลือก ให้เลือกเนื้อหาเหล่านี้ใน [Report Studio](https://phishdestroy.github.io/TgWitness/th/docs/reports/); ส่วนข้อมูล (slice) ที่บันทึกไว้จะไม่กำหนดค่ารายงานโดยอัตโนมัติ สำหรับผู้รับที่มีสิทธิ์จำกัด ให้ใช้[การควบคุมการส่งต่อที่](https://phishdestroy.github.io/TgWitness/th/docs/handover/)แยกต่างหาก

โปรดอ่าน[เอกสารอ้างอิง](https://phishdestroy.github.io/TgWitness/th/docs/reference/case-board/)ของ [Case Board](https://phishdestroy.github.io/TgWitness/th/docs/reference/case-board/) เพื่อทราบเกี่ยวกับการแก้ไขที่ลงนาม การจับคู่คำพูดอย่างแม่นยำ การตรวจสอบการเลือก และสิทธิ์การเข้าถึง
