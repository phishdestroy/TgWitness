# রপ্তানি এবং যাচাই করুন

Canonical page: https://phishdestroy.github.io/TgWitness/bn/docs/exports/

প্রাপ্তকারীকে এমন ফাইল দিন যা তারা সংগ্রহস্থল ওয়ার্কস্পেস এবং এর সংরক্ষিত ইতিহাসের সাথে যাচাই করতে পারে।

একটি রেফারেন্স রাখুনস্বাক্ষরিত ZIP রপ্তানি করুনপ্রাপ্তকারী যাচাই করে

স্বাক্ষর এবং চেকপয়েন্ট সম্পর্কে নতুন? [একটি নমুনা রেকর্ড পরিবর্তন করুন](https://phishdestroy.github.io/TgWitness/bn/docs/concepts/#chain) এবং দেখুন কোন কোন চেক তা সনাক্ত করে।

কপিটি কালেক্টর থেকে দূরে রাখছেন? [S3 সেটআপ](https://phishdestroy.github.io/TgWitness/bn/docs/exports/#s3), [অবজেক্ট লক](https://phishdestroy.github.io/TgWitness/bn/docs/exports/#s3-retention) বা [যাচাইকৃত পুনরুদ্ধ](https://phishdestroy.github.io/TgWitness/bn/docs/exports/#s3-restore)ারে যান।

## একজন বিশ্বস্ত রেফারেন্স রাখুন

ওয়ার্কস্পেসের পাবলিক-কি ফিঙ্গারপ্রিন্ট কালেক্টরের বাইরে সংরক্ষণ করুন। সংগ্রহের সময় স্বাক্ষরিত চেকপয়েন্টগুলো অন্যত্র রাখুন অথবা একটি [স্বাধীন সাক্ষী](https://phishdestroy.github.io/TgWitness/bn/docs/witness/) ব্যবহার করুন। এই রেফারেন্সগুলো প্রাপককে কী এবং পূর্ববর্তী জার্নাল সীমানা যাচাই করতে সাহায্য করে।

## স্বাক্ষরিত ZIP ডাউনলোড করুন

**Exports** খুলুন এবং স্বাক্ষরিত প্রমাণ ZIP তৈরি করুন। এতে পূর্ণ ওয়ার্কস্পেস জার্নাল এবং স্বাক্ষরিত ফাইল ম্যানিফেস্ট অন্তর্ভুক্ত থাকে। [Report Studio](https://phishdestroy.github.io/TgWitness/bn/docs/reports/) ব্যবহার করে এর পাঠযোগ্য রিপোর্ট তৈরি করুন, অথবা শুধুমাত্র নির্বাচিত ও সংক্ষিপ্ত ডেটা সরবরাহ করতে [হ্যান্ডওভার এক্সট্র্যাক্ট](https://phishdestroy.github.io/TgWitness/bn/docs/handover/) ব্যবহার করুন।

HTML, PDF এবং JSON রিপোর্টগুলির নিজস্ব স্বাক্ষরিত সীল রয়েছে এবং সেগুলি পৃথকভাবে যাচাই করা যায়। CSV বিশ্লেষণের জন্য একটি সুবিধাজনক অনুলিপি; এর অখণ্ডতা যাচাই করতে যাচাইকৃত ZIP-এর ভিতরে থাকা সঠিক CSV ব্যবহার করুন। যখন প্রাপক উৎস রেকর্ড এবং সংযুক্তিও প্রয়োজন, তখন স্বাক্ষরিত ZIP সংরক্ষণ করুন।

## TgWitness-এর একটি বিশ্বস্ত অনুলিপির মাধ্যমে যাচাই করুন।

ইনস্টলকৃত প্রকল্প পরিবেশে উদাহরণস্বরূপ ফিঙ্গারপ্রিন্ট এবং ফাইল পথগুলো প্রতিস্থাপন করুন:

```
python -m tgwitness.verify evidence.zip --fingerprint TRUSTED_PUBLIC_KEY_SHA256 --checkpoint retained-checkpoint.json
```

যখন উভয় রেফারেন্স পাস হয়, ফলাফল `key_pinned: true` এবং `checkpoint_checked: true` রিপোর্ট করে। যাচাইয়ের ফলাফলটি মূল আর্কাইভের সাথে সংরক্ষণ করুন। সংরক্ষিত চেকপয়েন্টটি রপ্তানির সীমানার মধ্যে বা তার আগে হতে হবে।

## যাচাইয়ের ফলাফল ব্যবহার করুন

- **প্রদানকৃত ফাইলগুলো যাচাই করুন:** ম্যানিফেস্ট তাদের হ্যাশগুলো আবদ্ধ করে, এবং রেকর্ড স্বাক্ষরগুলো সংরক্ষিত জার্নালকে আবদ্ধ করে। কোনো পরিবর্তিত ফাইল বা ভেঙে যাওয়া রেকর্ড চেইন সনাক্ত করা হয়েছে।
- **ওয়ার্কস্পেস পরিচয় যাচাই করুন:** স্বাধীনভাবে সংরক্ষিত ফিঙ্গারপ্রিন্ট প্রত্যাশিত স্বাক্ষর কী সনাক্ত করে।
- **আগের একটি সীমা তুলনা করুন:** একটি সংরক্ষিত চেকপয়েন্ট হ্যান্ডওভারের আগে সংরক্ষিত জার্নাল প্রিফিক্সের বিপরীতে রপ্তানি যাচাই করে।
- **পর্যালোচনা সংগ্রহের পরিধি:** ফাঁক, অধিগ্রহণ ফলাফল এবং একটি নিয়ন্ত্রিত পাঠান → সম্পাদনা → মুছে ফেলা পরীক্ষা এই সেটআপটি যে ঘটনাগুলি ধারণ করেছে তা বর্ণনা করে।

এই ফলাফলগুলো প্রাপকের কপিতে সংরক্ষণ করুন। [যাচাইকরণ](https://phishdestroy.github.io/TgWitness/bn/docs/reference/evidence/#verification-scope) চেকগুলির পরিধি এবং উৎস দাবিসমূহ ও সংগ্রহের কভারেজের পৃথক মূল্যায়নের জন্য [কী প্রতিষ্ঠিত করে তা](https://phishdestroy.github.io/TgWitness/bn/docs/reference/evidence/#verification-scope) দেখুন।

## S3 অফ-সাইট কপি সেট আপ করুন

আপনার চলমান কর্মস্থলে **Exports → Off-site copy** খুলুন। এই ঐচ্ছিক বৈশিষ্ট্যটি AWS S3 এবং অন্যান্য S3-সঙ্গতিপূর্ণ সেবার সাথে কাজ করে। এটি জার্নাল সেগমেন্ট, সংরক্ষিত ফটো ও ফাইল, চেকপয়েন্ট এবং তাদের টাইমস্ট্যাম্পযুক্ত প্রতিক্রিয়া, এবং সম্পন্ন চ্যাট এক্সপোর্টগুলো অনুলিপি করে। আপলোডের আগে প্রতিটি অবজেক্ট কালেক্টরে `AES-256-GCM` দিয়ে এনক্রিপ্ট করা হয়।

অনলাইন ডেমোতে আপলোড অক্ষম করে একই নিয়ন্ত্রণগুলি দেখানো হয়েছে। স্টোরেজ ক্রেডেনশিয়াল শুধুমাত্র আপনার নিজস্ব চলমান ওয়ার্কস্পেসেই প্রবেশ করুন।

উন্নত বিকল্পসহ সম্পূর্ণ প্যানেল প্রসারিত। কোনো স্টোরেজ শংসাপত্র দেখানো নেই।

| ক্ষেত্র | কি লিখতে হবে |
| --- | --- |
| শেষবিন্দু | স্টোরেজ সার্ভিস URL, কোনো বকেট পাথ বা ক্রেডেনশিয়াল ছাড়া। কাল্পনিক উদাহরণ: `https://s3.example.invalid` |
| অঞ্চল | আপনার প্রদানকারীর প্রয়োজনীয় অঞ্চল। অ্যাপ্লিকেশনের ডিফল্ট হল `us-east-1`। |
| বালতি | একটি বিদ্যমান বাকেট যা আপনি অ্যাক্সেস করতে পারেন। কাল্পনিক উদাহরণ: `example-case-backup` |
| বাকেট-এ ফোল্ডার | অবজেক্টের প্রিফিক্স; ডিফল্ট `tgwitness`। অ্যাপ্লিকেশনটি এই ওয়ার্কস্পেসের স্বাক্ষর-কী ফিঙ্গারপ্রিন্ট থেকে প্রাপ্ত একটি প্রিফিক্স সংযুক্ত করে। |
| অ্যাক্সেস কী আইডি / গোপন অ্যাক্সেস কী | উভয় স্টোরেজ শংসাপত্র একসঙ্গে প্রবেশ করান। এগুলো ওয়ার্কস্পেস ভল্টে সংরক্ষিত হয়। পরবর্তীতে সেভ করার সময় উভয়ই খালি রাখুন যাতে সংরক্ষিত যুগল অক্ষুণ্ণ থাকে। |
| পাথ-স্টাইল ঠিকানা | প্রদানকারীর নির্দেশনা অনুযায়ী, সক্ষম থাকলে `endpoint/bucket` ব্যবহার করুন, অথবা অক্ষম থাকলে `bucket.endpoint` ব্যবহার করুন। |
| কপি ইন্টারভাল | ১ থেকে ১,৪৪০ মিনিট; ডিফল্ট ৫ মিনিট। নির্ধারিত কপিগুলির জন্য অ্যাপ্লিকেশনটি চলমান থাকতে হবে। |
| অবজেক্ট লক ধরে রাখা | অবজেক্ট লক সমর্থনকারী একটি বকেট-এর রিটেনশন দিন এবং মোড। শূন্য দিন বকেট-এর ডিফল্ট রিটেনশন কার্যকর রাখে। |

1. আপনার প্রদানকারীর সাথে বাকেট তৈরি করুন, তারপর এর গন্তব্য এবং ক্রেডেনশিয়ালগুলো প্রবেশ করান। প্রস্তুতি চলাকালীন **অফ-সাইট কপি** চেক না করে রাখুন, তারপর **'অফ-সাইট কপি সংরক্ষণ করুন'** নির্বাচন করুন।
2. টেস্ট সংযোগ নির্বাচন করুন। এটি একটি এনক্রিপ্ট করা টেস্ট অবজেক্ট আপলোড করে এবং স্টোরেজ প্রতিক্রিয়া পরীক্ষা করে।
3. **ডাউনলোড এনক্রিপশন কী** নির্বাচন করুন। সেই ফাইলটি কালেক্টরের থেকে আলাদাভাবে রাখুন; পুনরুদ্ধারের জন্য এটি প্রয়োজনীয়।
4. **'অফ-সাইটে কপি রাখুন**' চেকবক্সটি সক্রিয় করুন এবং আবার সংরক্ষণ করুন। ম্যানুয়াল পাস করার জন্য **'এখনই কপি করুন'** নির্বাচন করুন, অথবা সময়সূচি চলতে দিন।

## রিটেনশন এবং কপির অগ্রগতি পরীক্ষা করুন

**More options**-এ, retention days এবং `GOVERNANCE` বা `COMPLIANCE` নির্বাচন করুন যখন আপনার bucket Object Lock সমর্থন করে। TgWitness আপলোডকৃত object-এর retention mode এবং deadline পুনরায় পড়ে। পৃথক retention ফলাফল পর্যালোচনা করুন: নিশ্চিত, retention অনুপস্থিত বা চেক ব্যর্থ।

প্যানেলটি শেষ পাস, অবজেক্টের সংখ্যা, স্থানান্তরিত বাইট, অনুলিপি করা জার্নাল সীমানা এবং কোনো ত্রুটি রিপোর্ট করে। অনুপস্থিত বা পরিবর্তিত স্থানীয় মিডিয়া রিপোর্ট করা হয় এবং পরবর্তী পাসে পুনরায় চেষ্টা করা হয়। সেই মিডিয়ার পর ফাইল, চেকপয়েন্ট এবং সারিতে থাকা রপ্তানিগুলি এখনও অনুলিপি করা যেতে পারে।

আপলোডগুলি ওয়ার্কস্পেসের Direct, SOCKS5 বা HTTP রুট ব্যবহার করে। S3 কপি করার জন্য এই রুটগুলির একটি নির্বাচন করুন; শুধুমাত্র MTProxy রুট কপিটিকে ত্রুটির কারণে পেন্ডিং রেখে দেয়।

## রিকভারি কীটি আলাদাভাবে রাখুন।

ডাউনলোডকৃত JSON-এ ডিক্রিপশন কী, গন্তব্য সেটিংস, ওয়ার্কস্পেস অবজেক্ট প্রিফিক্স এবং স্বাক্ষর-কী ফিঙ্গারপ্রিন্ট রয়েছে। পুনরুদ্ধারের জন্য এই কী ফাইল এবং বকেট-এ পড়ার অ্যাক্সেস সহ পৃথক স্টোরেজ ক্রেডেনশিয়াল উভয়ই প্রয়োজন। এগুলো আপনার পুনরুদ্ধার পরিকল্পনায় রাখুন।

যদি আপনি এন্ডপয়েন্ট, বাকেট বা ফোল্ডার প্রিফিক্স পরিবর্তন করেন, তাহলে গন্তব্য সেটিংসের সাথে মিল রাখতে কী ফাইলটি আবার ডাউনলোড করুন। অ্যাপ্লিকেশনটি নতুন গন্তব্যে স্থানীয়ভাবে সংরক্ষিত জার্নাল, ফাইল এবং চেকপয়েন্টের একটি নতুন অনুলিপি শুরু করে। স্থানীয় আপলোড কুই থেকে ইতিমধ্যেই সরানো সম্পন্ন চ্যাট এক্সপোর্টগুলো তাদের পূর্ববর্তী গন্তব্যেই থাকে।

## অন্য একটি মেশিনে পুনরুদ্ধার করুন এবং যাচাই করুন।

TgWitness-এর একটি বিশ্বাসযোগ্য ইনস্টলেশন, ডাউনলোডকৃত কী JSON, পড়ার অ্যাক্সেসসহ স্টোরেজ ক্রেডেনশিয়াল এবং একটি খালি আউটপুট ডিরেক্টরি ব্যবহার করুন। নিচের কাল্পনিক ক্রেডেনশিয়াল প্লেসহোল্ডারগুলো প্রতিস্থাপন করুন।

### উইন্ডোজ পাওয়ারশেল

```
$env:TGWITNESS_S3_ACCESS_KEY = 'YOUR_READ_ACCESS_KEY'
$env:TGWITNESS_S3_SECRET_KEY = 'YOUR_READ_SECRET_KEY'
python -m tgwitness.replica restore --key-file tgwitness-replica-key.json --out restored-evidence
```

### লিনাক্স / ম্যাকওএস

```
export TGWITNESS_S3_ACCESS_KEY='YOUR_READ_ACCESS_KEY'
export TGWITNESS_S3_SECRET_KEY='YOUR_READ_SECRET_KEY'
python -m tgwitness.replica restore --key-file tgwitness-replica-key.json --out restored-evidence
```

ডাউনলোড এবং ডিক্রিপ্ট করা অবজেক্টগুলো ব্যক্তিগত অস্থায়ী স্টোরেজে থাকে যতক্ষণ না সম্পূর্ণ জার্নাল, সংরক্ষিত চেকপয়েন্ট এবং সংরক্ষিত মিডিয়া হ্যাশ ও আকার যাচাই করা হয়। অসুরক্ষিত পথ, দ্বন্দ্বপূর্ণ জার্নাল সেগমেন্ট এবং চেকপয়েন্টের চেয়ে ছোট জার্নাল প্রত্যাখ্যাত হয়। ব্যর্থ যাচাইকরণ কোনো পুনরুদ্ধারকৃত ফাইল প্রকাশ করে না।

সফল পুনরুদ্ধার কপিতে উপলব্ধ উপাদানের জন্য `events.jsonl`, `media/`, `checkpoints/` এবং `exports/` তৈরি করে। পুনরুদ্ধারকৃত উপাদানের সাথে কমান্ডের JSON ফলাফল রাখুন।

উদ্ধারকৃত উপাদানকে আপনার স্বতন্ত্রভাবে সংরক্ষিত চেকপয়েন্ট বা সাক্ষী রেকর্ডের সাথে তুলনা করুন, তারপর আপনার প্রয়োজনীয় সময়ের জন্য রেকর্ডকৃত সংগ্রহের কভারেজ পর্যালোচনা করুন।
