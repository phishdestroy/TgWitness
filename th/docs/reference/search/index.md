# Telegram · การค้นหาข้อความเต็ม

Canonical page: https://phishdestroy.github.io/TgWitness/th/docs/reference/search/

ค้นหาข้อความที่บันทึกไว้ตามรูปแบบคำ วลีที่ตรงกันเป๊ะ โดเมน และ @usernames โดยแสดงผลลัพธ์ที่ตรงกันมากที่สุดก่อน พร้อมทั้งดัชนีที่เชื่อมโยงกับบันทึกที่ลงนามแล้ว

**ดูตัวอย่าง** ใน **Journal** ให้เลือก "**Best match · word forms**" ข้างช่องค้นหา ผลลัพธ์จะถูกจัดอันดับด้วย BM25 และจับคู่กับรูปแบบอื่น ๆ ของคำเดียวกัน: *"перевод"* จะพบ *"переводом"* และ *"переводы"*, *"transfer"* จะพบ *"transfers"*, และวลีภาษาจีน จะถูกค้นหาโดยไม่เว้นวรรค **"Newest first · exact text"** จะคงการค้นหา ส่วนย่อยของข้อความจากครั้งก่อนไว้บนบันทึกทั้งหมด

ดัชนีเป็นข้อมูลที่สร้างขึ้นใหม่ โดยถูกสร้างขึ้นใหม่จากบันทึกที่ลงนามแล้ว ไม่เคยถูกลงนาม ด้วยตัวเอง และไม่เคยถูกส่งออกเลย บันทึกต้นฉบับไม่เปลี่ยนแปลง

## ไวยากรณ์การค้นหา

| เขียน | ผลการค้นหา |
| --- | --- |
| `перевод карта` | บันทึกที่มีคำทั้งสองคำอยู่ด้วย ในรูปแบบใดก็ตาม |
| `"переводом на карту"` | ใช้คำวลีนี้ตามลำดับที่ระบุไว้ |
| `бонус OR подарок` | คำใดก็ได้ |
| `перевод -казино` | บันทึกโดยไม่รวมคำที่ถูกยกเว้น |
| `example.com` | โดเมนและโดเมนย่อยของมัน รวมถึงในลิงก์ที่ซ่อนอยู่และ URL ของปุ่ม |
| `@username`, `t.me/username` | การกล่าวถึงและลิงก์ของบัญชี รวมถึงข้อความที่บัญชีดังกล่าวส่งไป |
| `#tag` | แฮชแท็ก |
| `+79991234567`, ที่อยู่กระเป๋าเงิน, ที่อยู่อีเมล | ค่าเดียวกันในข้อความหรือลิงก์ |
| `from:@username`, `from:123456` | ข้อความจากผู้ส่งนั้น |
| `chat:-1001234567890` | การสนทนาเดียว; สามารถจำกัดการเข้าถึงได้เฉพาะตัวคุณเท่านั้น |
| `id:42` | เวอร์ชันที่บันทึกไว้ของข้อความ 42 |
| `since:2026-01-01 until:2026-01-31` | ช่วงเวลาการสังเกตการณ์; วันที่ไม่มีเวลาจะครอบคลุมทั้งวัน |
| `kind:edited` | แก้ไขเฉพาะ (`new`, `snapshot`, `edited`, `recovered`) |
| `source:ocr`, `source:transcription`, `source:all` | ข้อความที่ระบบระบุได้ แทนที่ หรือร่วมกับ ข้อความ |

คำบุพบทและคำหน้าที่อื่น ๆ จะถูกละเว้นเมื่อมีคำอื่นอยู่ด้วย ตัวอักษรที่คล้ายกันแต่ถูกผสมอยู่ในคำ (เช่น ตัวอักษรละติน *"a"* ภายในคำซีริลลิก), ตัวอักษร Unicode ที่มีความกว้างเต็มและตัวอักษรตกแต่ง รวมถึงตัวอักษรที่มองไม่เห็น จะถูกปรับให้เป็นมาตรฐาน

## ภาษา

ภาษาจะถูกตรวจจับสำหรับแต่ละบันทึกจากสคริปต์และตัวอักษรในบันทึกนั้น:

| สคริปต์ | การจับคู่ |
| --- | --- |
| อักษรซีริลลิก | เลมมาภาษารัสเซียและยูเครนด้วย [pymorphy3](https://github.com/no-plagiarism/pymorphy3) โดยหากไม่ใช้พจนานุกรมภาษายูเครนแบบเลือกได้ จะใช้ตัวแยกคำรากภาษายูเครนแบบเบา |
| ภาษาละติน | ตัวแยกคำแบบ Snowball ภาษาอังกฤษ; เครื่องหมายเสียงถูกเพิกเฉย |
| ภาษาจีน, ภาษาญี่ปุ่น, ภาษาเกาหลี, ภาษาไทย, ภาษาลาว, ภาษาเขมร, ภาษาพม่า | คู่ตัวอักษรที่ทับซ้อนกัน: ทุกวลีจะถูกค้นหาโดยไม่เว้นช่องว่าง คำสั่งภาษาจีนจะถูกแบ่งเป็นคำด้วย jieba |
| สคริปต์อื่น ๆ | คำที่ตรงตามต้นฉบับ |

พจนานุกรมภาษายูเครน (`pymorphy3-dicts-uk`) ถูกแจกจ่ายภายใต้ใบอนุญาต GPL-3.0 ดังนั้นจึง ไม่ถูกติดตั้งโดยค่าเริ่มต้น ให้ติดตั้งด้วย `pip install "tgwitness[uk-dictionary]"`; ดัชนีจะตรวจพบตัววิเคราะห์ใหม่และสร้างตัวเองขึ้นใหม่

## ตำแหน่งของดัชนี

| โหมด | พื้นที่จัดเก็บ | การใช้งาน |
| --- | --- | --- |
| บนดิสก์ (ค่าเริ่มต้น) | `search/fulltext.sqlite3` ในไดเรกทอรี workspace | ไฟล์เก็บถาวรขนาดใหญ่; ยังคงอยู่แม้จะรีสตาร์ทระบบ |
| เก็บไว้ในหน่วยความจำเท่านั้น | ไม่มีข้อมูลใดๆ บนดิสก์; สร้างใหม่ทุกครั้งที่เริ่มต้น | ไม่มีการคัดลอกข้อความที่ดัดแปลงไว้บนดิสก์ |
| ปิด | ไม่มีดัชนี; **แสดงตามลำดับจากใหม่ที่สุด · ข้อความต้นฉบับ**ยังคงอยู่ | การติดตั้งแบบขั้นต่ำ |

ผู้ดูแลระบบหลักจะเลือกโหมดภายใต้ **Journal → Filters → Search index** สำหรับแต่ละพื้นที่ทำงาน `TGWITNESS_FULLTEXT=disk|memory|off` ตั้งค่าเริ่มต้นสำหรับ พื้นที่ทำงานที่ยังไม่ได้เลือกเอง การเปลี่ยนไปใช้โหมดในหน่วยความจำหรือปิดโหมดจะลบไฟล์ดังกล่าว ไฟล์ดัชนีมีการป้องกันเช่นเดียวกับบันทึก: ไฟล์นี้อยู่ในไดเรกทอรีข้อมูลส่วนตัว ไฟล์นี้ไม่ได้รับการเข้ารหัส และไม่ถูกรวมอยู่ในการสำรองข้อมูลหรือสำเนาที่เก็บไว้นอกสถานที่

บันทึกใหม่จะถูกจัดทำดัชนีในพื้นหลังภายในไม่กี่วินาที; การค้นหายังจัดทำดัชนี ข้อมูลค้างเก่าในปริมาณน้อยก่อน ดังนั้นบันทึกที่เพิ่งบันทึกเมื่อไม่นานมานี้จึงสามารถค้นหาได้ บันทึกที่มีอยู่ จะถูกจัดทำดัชนีหลังการอัปเดตโดยไม่ทำให้แผงควบคุมหยุดทำงาน; จนกว่าจะเสร็จสิ้น ผลลัพธ์จะครอบคลุม บันทึกที่จัดทำดัชนีแล้ว และบันทึกจะแสดงความคืบหน้า **การสร้างดัชนีใหม่จะ**เริ่มต้นใหม่ จากบันทึกแรก

```
python -m tgwitness index status --data-dir data/live
python -m tgwitness index rebuild --data-dir data/live --json
```

`rebuild` ต้องหยุดการทำงานของ panel (หากไม่หยุด จะให้รหัสออก 3) โดย `--json`, ผลออกทางมาตรฐานจะแสดงเพียงผลลัพธ์เท่านั้น; ความคืบหน้าจะถูกส่งไปยังมาตรฐานข้อผิดพลาด

## ผลลัพธ์และบันทึกที่ลงนาม

ดัชนีเก็บหมายเลขลำดับและค่าแฮชของบันทึกในสมุดบันทึกสุดท้ายที่มันครอบคลุม และตรวจสอบข้อมูลเหล่านี้กับสมุดบันทึกเมื่อเปิดขึ้น สมุดบันทึกที่ถูกแทนที่ ฟื้นฟู หรือแก้ไข จะทำให้ต้องสร้างดัชนีใหม่ ทุกการตอบกลับจะรายงานตำแหน่งนี้ และทุกการค้นหาจะถูก อ่านกลับจากสมุดบันทึกที่ลงนามตามหมายเลขลำดับ: ดัชนีจะตัดสินใจว่า บันทึกใดจะแสดงและในลำดับใด แต่ไม่เคยกำหนดเนื้อหาของบันทึกนั้น การเข้าถึงแชทถูกนำไปใช้กับ ช่องแชทของสมุดบันทึกเอง ไม่ใช่เนื้อหาของดัชนี

## ข้อความที่ตรวจพบ

OCR และข้อความถอดเสียงจะยังคงอยู่ในไฟล์ที่เข้ารหัสไว้ ดัชนีของข้อมูลเหล่านี้มีอยู่เพียงใน หน่วยความจำ และจะถูกสร้างขึ้นใหม่เมื่องานการรู้จำเสร็จสิ้น ผลลัพธ์ที่ตรงกันจะปรากฏใน `media.saved` บันทึก โดยถูกระบุว่าเป็น "การระบุโดยเครื่อง" พร้อมด้วยชื่อเครื่องยนต์ โมเดล และ ส่วนคัดลอก; มันจะไม่ถูกแสดงเป็นข้อความที่ส่งใน Telegram เลย ดัชนีเดียวกันนี้ยังใช้ **สำหรับการค้นหาข้อความที่ได้รับการระบุ** ซึ่งยังคงสามารถจับคู่กับส่วนย่อยของข้อความแบบธรรมดาได้อีกด้วย

## เข้าถึง

สิทธิ์การเข้าถึงในระดับแชทจะค้นหาบันทึกเฉพาะจากแชทนั้นเท่านั้น รวมถึงข้อความที่ระบบระบุได้จาก ไฟล์แนบของแชทนั้น `chat:` และตัวกรองอื่น ๆ สามารถจำกัดชุดข้อมูลนั้นได้เท่านั้น สถานะดัชนี ที่แสดงให้สิทธิ์การเข้าถึงแบบจำกัดจะไม่นับรวมยอดรวมของบันทึกทั้งหมด มีเพียงผู้ดูแลระบบหลักเท่านั้นที่สามารถเปลี่ยน โหมดหรือสร้างดัชนีใหม่ได้

## ติดต่อกับฝ่ายเก็บข้อมูลและ MCP

เมื่อดัชนีเสร็จสมบูรณ์ **ระบบจะ**ดึงแหล่งข้อมูลจากดัชนีนี้: ผลลัพธ์ที่ตรงกันมากที่สุดจากแชทที่เลือก โดยข้อความที่บันทึกไว้จะถูกนับเพียงครั้งเดียว ส่งแหล่งข้อมูลได้สูงสุด 24 แหล่ง; ข้อความยาวจะถูกตัดรอบจุดที่ตรงกันและทำเครื่องหมายว่าถูกตัดทอน คำถามเกี่ยวกับการเปลี่ยนแปลงล่าสุด เวอร์ชันที่บันทึกไว้ของข้อความเดียว และการค้นหาในขณะที่ ดัชนียังอยู่ในระหว่างการสร้าง ให้ใช้การดึงข้อมูลตามลำดับเวลาครั้งก่อน การแสดงตัวอย่าง จะแสดงว่าใช้วิธีการใด

ลูกค้า MCP สามารถเรียกใช้ `search_messages` ด้วย `ranked=true` และหน้าด้วย `next_offset`. การเชื่อมต่อแบบจำกัดขอบเขตจะรับเฉพาะการสนทนาของตนเองเท่านั้น

การแบ่งหน้าตามอันดับจะครอบคลุมผลลัพธ์1,000แรกเท่านั้น ไม่ว่าขนาดหน้าจะเป็นเท่าใดก็ตาม ให้จำกัดการค้นหา แชท หรือช่วงเวลา เพื่อตรวจสอบผลลัพธ์ที่ตรงกันเพิ่มเติม การค้นหาแบบ ใหม่ที่สุดก่อน จะจัดเรียงข้อความ ผลลัพธ์ OCR และผลการถอดความ ก่อนที่จะเลือกแต่ละหน้า

## Benchmark

`python tools/bench_fulltext.py --messages 1000000 --work <empty directory>`สร้างบันทึกที่ลงนามแบบกำหนดได้ ซึ่งประกอบด้วยข้อความผสมระหว่างภาษารัสเซีย ยูเครน อังกฤษ จีน และญี่ปุ่น พร้อมด้วยลิงก์และแฮนเดิลใน 200 ห้องสนทนา สร้างดัชนี และวัดเวลาการค้นหาทั่วไป (50 ผลลัพธ์, ค่ามัธยฐานจากการทดสอบ 7 ครั้ง)
