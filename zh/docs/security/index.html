所有内容的归宿

该采集器、其控制面板以及所有保存的记录均存储在您运行该工具的计算机或服务器上。默认情况下，Telegram 是唯一的输出目标；其他目标均需通过单独的开关进行设置。

保护范围

✓ 已收录

  • 导出记录中若存在被修改、删除或重新排序的条目：哈希链或签名将无法通过验证。
  • 在检查点之后被截短或重建的日志：保留的检查点已不再匹配。
  • 面板令牌猜测：256 位随机位，在常数时间内进行比对；每分钟失败 15 次后，该地址将被拒绝。
  • 恶意聊天内容：文本以纯文本形式插入，绝不以 HTML 形式呈现；附件以文件形式下载；该面板不会从其他网站加载任何内容。
  • 一个包含外部保险库密钥的复制数据目录：若无主密钥，会话和签名密钥将保持加密状态。

! 由您决定

  • 主控制面板的令牌拥有完全控制权。可向其他人授予其所需的、针对特定范围的账户、聊天和操作访问权限；请务必将主密钥保密。
  • 服务器管理员可以读取所有内容，并可重写和重新签署日志。请将指纹和检查点保存在另一台系统上。
  • TgWitness 不会对消息文本和媒体文件进行加密。请使用磁盘加密并设置严格的权限。
  • 若通过 localhost 以外的普通 HTTP 连接，网络上将暴露令牌。请使用 HTTPS 或 SSH 隧道。
  • 签名仅证明所记录的内容未被篡改，而非证明每个 Telegram 事件均已被记录。

可通过设置权限、有效期和会话限制来共享案件访问权限。Witness 令牌仍作为独立的凭证存在。

强化安装安全性

已完成 0/8
  1. 请使用专用的 Telegram 账号——切勿使用您的主账号。控制面板令牌和会话可让您对其拥有完全控制权。
  2. 请将控制面板保留在 127.0.0.1 上。仅可通过 HTTPS（随附的 Caddy 配置）或 SSH 隧道进行远程访问。
  3. 对存放数据目录的磁盘进行加密：消息正文和媒体文件均按接收时的原始状态存储。
  4. 将数据目录限制在服务账户内。在 Unix 系统中，新建目录的权限应设为 0700；在 Windows 系统中，请设置文件夹的权限。
  5. 请将保险库主密钥保存在其他服务器上：在创建数据目录之前，请设置 TGWITNESS_VAULT_KEY_FILE。
  6. 请将签名密钥指纹和检查点保存在另一台系统上，并在另一台主机上添加一个见证节点。
  7. 切勿将 data/、会话密钥、panel-token.txt 或保险库密钥上传至 GitHub 或聊天群组。
  8. 请勿在反向代理服务器上记录 Authorization 标头或请求正文。
我可以更改面板令牌而不丢失数据吗？

是的。该令牌仅用于打开控制面板。停止 TgWitness，从数据目录中删除 panel-token.txt，然后重新启动；日志、会话和密钥均保持不变。设置 TGWITNESS_TOKEN 后，将使用环境变量值代替文件。

为什么消息在静止状态下不进行加密？

采集者必须读取这些日志才能进行搜索、版本比对和导出。若仅在同一台机器上使用密钥对日志进行加密，对于能够读取该机器的人来说，这种加密措施几乎起不到什么作用。磁盘加密可保护已停止运行或被盗的磁盘；而严格的权限设置则可保护正在运行的磁盘。

报告漏洞

请在 GitHub 仓库中使用“Security”→“Report a vulnerability”（安全 → 报告漏洞）功能。请包含版本号、影响范围以及最简复现步骤。切勿发送凭据、账户目录或真实证据存档。如果无法进行私下报告，请提交一个问题，请求开通一个不包含漏洞细节的私有频道。
