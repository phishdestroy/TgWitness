# 보안을 유지하세요

Canonical page: https://phishdestroy.github.io/TgWitness/ko/docs/security/

무엇이 컴퓨터 밖으로 나가는지, 각 비밀 값이 무엇을 여는지, 보호 장치가 다루는 것과 귀하가 책임질 것.

**127.0.0.1**기본 패널 주소

**256비트**무작위 패널 토큰

**0**CDN, 분석 도구 또는 원격 폰트

**Ed25519**모든 기록에 서명 포함

## 모든 정보가 모여 있는 곳

수집기, 패널, 모든 기록은 귀하의 컴퓨터에 남습니다. 기본적으로 텔레그램에만 연결하며, 나머지는 모두 별도의 스위치입니다.

06 / 기계에서 남는 것설치 방법

사용자의 컴퓨터 또는 서버

**패널**127.0.0.1:8787 · 베어러 토큰

**수집기**워크스페이스당 텔레그램 클라이언트 1개

데이터 디렉토리

**저널**SQLite · 해시 체인 방식 · 서명됨

**미디어**SHA-256을 기준으로 이름이 지정된 파일

**Vault**Fernet · 세션, API 쌍, 서명 키, 프록시

- **텔레그램**항상 · 귀하의 경로를 통해

  계정의 MTProto 연결 방식: 직접 연결, SOCKS5, HTTP 또는 MTProxy. IP 숨기기 모드는 작동하는 프록시를 기다립니다. 직접 연결로 자동 전환하려면 이를 명시적으로 허용하는 모드가 필요합니다.
- **외부 사이트용 문구**선택 사항 · 기본값은 비활성화됨

  저널, 파일 및 체크포인트는 S3 호환 스토리지에 업로드되기 전에 AES-GCM으로 암호화됩니다. 암호화 키는 사용자가 직접 관리하며, 첨부 파일의 이름은 내용 해시가 아닌 키가 적용된 해시로 지정됩니다.
- **알림**선택 사항 · 기본값은 비활성화됨

  채팅 제목과 함께 문제점 및 변경 내역을 제공합니다. 메시지 발췌문은 사용자가 해당 기능을 활성화한 경우에만 전송됩니다.
- **타임스탬프 신뢰성**선택 사항 · 기본값은 비활성화됨

  서명된 체크포인트의 SHA-256 해시값과 무작위 논스(nonce)만 포함됩니다. 메시지나 채팅 이름은 포함되지 않습니다.
- **Witness**선택 사항 · 기본값은 비활성화됨

  읽기 전용 토큰을 사용하여 서명된 체크포인트와 캡처 카운터를 가져옵니다. 대화 내용을 읽거나 설정을 변경할 수는 없습니다.

기본 설정: 텔레그램 연결만 이 기기를 통해 이루어집니다.

선택적 저장 위치는 워크스페이스별로 구성됩니다. 메시지 본문과 미디어 파일은 데이터 디렉터리에 암호화되지 않은 상태로 저장되므로, 디스크 암호화 및 파일 권한 설정을 통해 보호해야 합니다.

## 각 비밀이 열어주는 것

| 비밀 | 보관 위치 | 이 도구가 제공하는 이점 | 유출될 경우 |
| --- | --- | --- | --- |
| **패널 토큰** | 데이터 디렉터리의 `panel-token.txt`, 브라우저는 탭마다 보관합니다 | 모든 작업 공간의 모든 것 | TgWitness를 멈추고, `panel-token.txt`를 지우고, 다시 시작: 새 토큰이 생깁니다 |
| **텔레그램 세션** | Vault, 암호화됨 (`credentials.enc`) | 텔레그램 계정 자체 | 텔레그램에서 [*설정] → [기기]*로 이동하여 세션을 종료하세요. |
| **서명 키** | Vault, 암호화됨 (`signing.enc`) | 귀하의 지문으로 기록에 서명하기 | 다른 곳에 보관한 체크포인트, 증인, 타임스탬프가 이전에 있던 것을 여전히 보여 줍니다 |
| **볼트 키** | 데이터 옆의 `vault.key` 또는 외부 마스터 키 | 볼트 | 세션과 서명 키도 유출되었다고 가정하십시오 |
| **Witness 토큰** | witness 호스트에서 | 읽기 전용: 체크포인트와 상태 | 증인 페이지에서 삭제하고 새로 만듭니다 |
| **외부 사이트용 카피 키** | Vault; 복구를 위해 한 번만 다운로드하세요 | 오프사이트 사본 | 버킷까지 가진 사람은 복호화할 수 있습니다: 사본이 노출된 것으로 취급하십시오 |

## 보호 대상 범위

### 포함

- 기록 변경, 삭제, 순서 바꾸기: 해시 체인이나 서명이 깨집니다.
- 다른 곳에 체크포인트를 저장한 뒤 저널을 잘라 내거나 다시 만든 경우: 체크포인트가 더 이상 일치하지 않습니다.
- 토큰 추측: 256비트 난수, 상수 시간 비교, 1분에 15번 실패하면 주소가 차단됩니다.
- 악의적인 채팅 내용: 텍스트는 항상 텍스트로 남고 HTML이 되지 않으며, 첨부 파일은 파일로 다운로드되고, 패널은 다른 사이트에서 아무것도 불러오지 않습니다.
- 외부 볼트 키를 쓰는 상태에서 데이터 디렉터리를 도난당한 경우: 세션과 키는 암호화된 채로 남습니다.

### , 여러분께 맡깁니다

- 메인 토큰은 무엇이든 할 수 있습니다. 다른 사람에게는 범위가 제한된 액세스를 주고, 메인 토큰은 혼자 가지십시오.
- 컴퓨터의 관리자는 누구든 모든 것을 읽고 저널에 다시 서명할 수 있습니다. 지문과 체크포인트는 다른 곳에 보관하십시오.
- TgWitness는 메시지와 미디어를 암호화하지 않습니다. 디스크를 암호화하고 권한을 좁히십시오.
- localhost 밖에서 일반 HTTP를 쓰면 토큰이 샙니다. HTTPS나 SSH 터널을 사용하십시오.
- 서명은 무엇을 놓쳤는지 알려 주지 않습니다. 귀하의 계정과 소스에서 범위를 확인하고 전달을 테스트하십시오.

권한, 만료, 세션 제한을 두고 [사건 액세스를 공유](https://phishdestroy.github.io/TgWitness/ko/docs/access/)합니다.

## 설치 환경 강화

8개 중 0개 완료

1. **전용 텔레그램 계정을 사용하십시오**. 주 계정은 절대 쓰지 마십시오.
2. **패널은 127.0.0.1에 유지하십시오.** 원격 액세스는 HTTPS(내장 Caddy)나 SSH 터널로만.
3. **디스크를 암호화하십시오**. 데이터 디렉터리가 있는 디스크이며, 메시지와 미디어는 그대로 저장됩니다.
4. **데이터 디렉터리를 제한하십시오**. 서비스 계정만 접근하도록(Unix에서는 0700, Windows에서는 폴더 권한).
5. **서버에서는 볼트 키를 다른 곳에 두십시오**: 처음 시작하기 전에 `TGWITNESS_VAULT_KEY_FILE`을 설정합니다.
6. **지문과 체크포인트를 저장하십시오**. 다른 시스템에 두고, 증인은 다른 호스트에서 실행합니다.
7. `data/`, 세션, `panel-token.txt` 또는 볼트 키를 GitHub이나 채팅방에 **절대 업로드하지 마십시오**.
8. 리버스 프록시에서는 `Authorization` 헤더나 요청 본문을 **기록하지 마십시오**.

**데이터를 잃지 않고 패널 토큰을 변경할 수 있나요?**

예, 토큰은 패널만 엽니다. TgWitness를 멈추고, `panel-token.txt`를 지우고, 다시 시작하십시오. 저널, 세션, 키는 남습니다. `TGWITNESS_TOKEN`이 설정되어 있으면 파일보다 그 값이 우선합니다.

**저장된 메시지가 왜 암호화되지 않나요?**

수집기는 검색, 비교, 내보내기를 위해 그것들을 읽어야 합니다. 같은 컴퓨터에 있는 키로는 어차피 그 컴퓨터를 읽을 수 있는 사람을 막지 못합니다. 디스크 암호화는 도난당한 디스크를, 권한은 실행 중인 시스템을 보호합니다.

## 취약점 신고

GitHub의 **Security → Report a vulnerability**. 버전, 영향, 가짜 데이터로 만든 최소 재현을 포함하십시오. 자격 증명, 계정 폴더, 실제 증거는 절대 보내지 마십시오. 비공개 신고가 꺼져 있으면 익스플로잇 세부 정보 없이 비공개 채널을 요청하는 이슈를 여십시오.
