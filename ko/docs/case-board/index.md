# 케이스 보드 구축하기

Canonical page: https://phishdestroy.github.io/TgWitness/ko/docs/case-board/

저장된 텔레그램 관찰 내용을 팀이 함께 검토할 수 있는 사건으로 전환하십시오.

Case Board는 출처 참조 정보 옆에 북마크, 정확한 텍스트 하이라이트, 저장된 슬라이스 및 토론 내용을 함께 보관합니다. 컬렉션은 사건에 작업 구조를 제공하며, 서명된 수정 내역은 팀이 이를 어떻게 발전시켜 왔는지를 보존합니다.

## 메시지에서 사건 카드로

1. **‘조사’ → ‘케이스 보드’를** 표준 모드 또는 전문가 모드로 엽니다. 해당 사건에 대한 수집 항목을 생성하고 채팅 범위를 선택합니다.
2. **저널** 이나 저장된 채팅에서 **‘보드에 추가’를** 선택하거나, 해당 기록을 선택하고 **B 키를** 누르십시오. 카드가 수신함으로 이동합니다. 적절한 제목을 지정하고 컬렉션으로 이동시키십시오.
3. 저장된 채팅 메시지에서 해당 구절을 선택하고 **‘하이라이트(Highlight)’ → ‘보드(board)’를** 선택하여 정확한 인용문과 메시지 버전을 유지하십시오. 해당 내용이 중요한 이유를 설명하는 메모를 추가하십시오.
4. 주장을 확인해야 할 때마다 해당 카드를 검토하고, 검토 상태를 지정하며, 원본 맥락으로 되돌아가십시오. **‘프레젠테이션’** 기능을 사용하여 동료들과 함께 수집 내용을 단계별로 살펴보세요.

### 변경된 결제 링크 하나를 따라가세요

합성 예시 · 현지화 예시

1. **캡처.** 저장된 관찰 기록 #142와 해당 메시지 버전을 엽니다.
2. **북마크.** 인용문, 출처 참조 및 질문을 카드에 저장해 두세요.
3. **검토.** 팀 코멘트를 추가하고 카드를 ‘검토’ 상태로 이동하십시오.
4. **현재.** 수집 과정을 단계별로 안내하고 인용된 출처의 맥락을 열어보세요.

#### 저장된 관찰 기록 #142

“새로운 결제 링크를 사용하세요.”

운영 채팅 · 메시지 38 · 확인 시간 09:12 UTC

#### 카드: 수신처 변경

> 새로운 결제 링크를 사용해 주십시오.

질문: 이전 버전에는 어떤 대상이 등장했나요?

#### 팀 검토

분석가: 관찰 사항 #101과 비교하십시오.

상태: 검토 · 수정 내용 유지

#### 원문 맥락

카드 → 저장된 버전 → 이전 관찰 내용

주석과 텔레그램 관찰 내용은 별도로 식별 가능합니다.

## 유용한 범위를 한 번에 저장하세요

한 채팅에서 두 개의 기록을 Shift 키를 누른 채 클릭하여 **‘Slice**between’을 선택하거나, **‘Slice by time’을** 선택하거나, 현재 저널 필터를 저장하십시오. 저장하기 전에 개수를 확인하십시오. 저장된 쿼리를 적용하려면 슬라이스를 다시 여십시오. **‘북마크 이후 추가된 기록 표시’를** 선택하면 나중에 추가된 기록을 확인할 수 있습니다.

타임 슬라이스는 수집기의 관찰 시간을 따릅니다. 메시지 ID 슬라이스는 이후 변경 사항이 발생함에 따라 선택된 메시지를 추적할 수 있습니다. 저장된 생성 경계 정보를 통해 수신자는 원래 선택 내용과 이후 상태를 비교할 수 있습니다.

## 각 동료에게 적절한 역할을 부여하십시오

**검토자는** 보드를 확인하고, **분석가는** 카드와 코멘트를 추가하며, **운영자는** 수집 작업과 검토 결정을 관리합니다. 작업 공간 및 채팅 권한은 카드, 원본 컨텍스트 및 토론에 적용됩니다. 명확한 출처 표기를 위해 명명된 접근 권한을 사용하십시오.

## 이 작업을 결과물로 완성해 주십시오.

슬라이스를 서명된 JSON으로 내보내거나, 스프레드시트용 CSV를 사용하십시오. 보고서 설정에는 북마크와 슬라이스를 포함할 수 있으며, 선택 시 팀 코멘트를 추가할 수 있습니다. [Report](https://phishdestroy.github.io/TgWitness/ko/docs/reports/)Studio에서 이러한 내용을 선택하십시오. 저장된 슬라이스가 자동으로 보고서를 구성하지는 않습니다. 수신자가 제한된 경우, 별도의 [인계 제어](https://phishdestroy.github.io/TgWitness/ko/docs/handover/) 기능을 사용하십시오.

서명된 수정 사항, 정확한 인용문 일치, 선택 내용 확인 및 권한에 대해서는 [Case Board 참조](https://phishdestroy.github.io/TgWitness/ko/docs/reference/case-board/) 문서를 확인하십시오.
