# Развёртывание и эксплуатация

<a id="choose-an-installation"></a>
## Выберите способ установки

Для портативного пакета распакуйте файл `TgWitness-<version>-windows-amd64-portable.zip` из релизов GitHub. Для других способов загрузите и распакуйте ZIP-архив с исходным кодом или клонируйте репозиторий, а затем выполните следующую команду из каталога проекта:

| Установка | Запуск | Работает в фоновом режиме? |
| --- | --- | --- |
| Портативный пакет для Windows | `TgWitness.cmd` | Нет; окно должно оставаться открытым. |
| Нативная версия для Windows | `Start.cmd` | Нет; для работы в фоновом режиме используйте дополнительную задачу входа в систему. |
| Нативная версия для Linux/macOS | `sh start.sh` | Нет; для работы в фоновом режиме используйте systemd/launchd. |
| Docker на любом поддерживаемом хосте | `docker compose up -d --build --wait` | Да, при условии, что работает демон Docker. |
| Вспомогательная программа Docker в Windows | `scripts\Docker.cmd` | Да; вспомогательная программа отслеживает работоспособность веб-сервера. |
| Вспомогательная программа Docker в Linux/macOS | `sh scripts/docker-start.sh` | Да; вспомогательная программа отслеживает работоспособность веб-сервера. |

В случае облачного сервера, состояние которого должна иметь возможность проверять сторонняя организация — созданного с помощью API провайдера, без использования SSH, доступ к которому осуществляется исключительно через Cloudflare Tunnel — см. [раздел Развертывание с высоким уровнем надежности](HIGH-ASSURANCE.md).

При запуске с помощью нативной программы создаётся частная среда `.venv` и устанавливаются закреплённые зависимости. Docker собирает их внутри образа, не требуя наличия Python на хосте. Для первоначальной настройки необходим доступ к Интернету. Если Python версии 3.11 или выше не обнаружен, файл ``Start.cmd`` перед установкой Python 3.12 для текущего пользователя Windows запрашивает его согласие (с помощью `winget`, в противном случае — с помощью установщика с сайта python.org после проверки подписи Python Software Foundation); при этом никогда не запрашиваются права администратора. Docker и службы ОС остаются обязательными условиями.

Нативные и переносимые установки используют папку `data/live` внутри своей директории. Docker использует именованный том `tgwitness-data` в каталоге `/data`. Эти установки являются отдельными, пока вы сознательно не перенесёте весь каталог данных. Не ожидайте, что новый контейнер Docker автоматически обнаружит нативные аккаунты.

<a id="installation-requirements"></a>
## Требования к установке

Для нативной установки требуется Python 3.11 или более поздней версии с `venv` и `ensurepip`, доступ в Интернет для установки первых зависимостей, а также каталог проекта с правами на запись для `.venv`. Входящая в комплект панель управления не требует Node.js или сборки интерфейса. Запустите программу запуска из своего обычного аккаунта ОС; TgWitness не требует прав администратора или root.

- **Windows:** файл `Start.cmd` проверяет наличие `py -3`, затем `python`, а также папки установки по умолчанию для пользователя и в каталоге «Program Files» и требует версии 3.11 или более поздней. Если ни один из вариантов не сработает, предлагается автоматическая установка для пользователя, описанная выше. Также работает команда `py -3 start.py`. Портативный пакет не требует наличия Python вообще.
- **Linux:** Скрипт `start.sh` проверяет наличие `python3.13`, `python3.12`, `python3.11`, `python3` и `python`, а если ни один из них не подходит, выводит команду установки для apt, dnf, pacman, zypper, apk или Homebrew. Для установок в Debian/Ubuntu может потребоваться пакет `python3-venv`, соответствующий выбранному интерпретатору. Устаревшую версию Python, установленную по умолчанию в дистрибутиве, необходимо заменить или дополнить версией Python 3.11+.
- **macOS:** установите актуальную версию Python 3.11+; не следует полагать, что интерпретатор, предоставляемый ОС, соответствует требованиям. Используйте команду `python3 start.py` из каталога проекта.
- **Docker:** используйте Docker Engine/Desktop с Compose версии 2.20 или более поздней. В Windows Docker Desktop должен использовать контейнеры Linux. Контейнер устанавливает собственные зависимости Python; на хост-компьютере не требуется отдельная установка Python.

<a id="local-computer"></a>
## Локальный компьютер

Используйте команду `Start.cmd` в Windows или `sh start.sh` в Linux/macOS. Команды `scripts\Setup.cmd` или `sh start.sh --setup-only` подготавливают среду. Программа запуска устанавливает зависимости при первом запуске; последующие запуски используют уже подготовленную среду. Для настройки и сбора данных из Telegram требуется доступ в Интернет, однако просмотр существующих записей и создание экспортов работают в автономном режиме.

После настройки запустите команду ``python start.py --check``, чтобы проверить локальные зависимости, Ed25519, хранилище, конфигурацию ключей и адрес прослушивания без запуска сборщика. Для получения структурированного вывода используйте опцию ``--json``. Укажите нужные значения параметров ``--data-dir``, ``--host`` и ``--port``. Эта проверка не устанавливает пакеты, не создаёт журнал и не подключается к Telegram; она не является проверкой целостности или полноты охвата. Верификатор `python start.py --help` также позволяет избежать установки.

После запуска start.py выполняйте вспомогательные команды с помощью `.venv\Scripts\python.exe` в Windows или `.venv/bin/python` в Linux/macOS, либо сначала активируйте эту среду. Приведённые ниже примеры использования команды `python -m ...` предполагают, что среда уже активна.

~~~sh
python -m tgwitness --data-dir /path/to/private/data --host 127.0.0.1 --port 8787
~~~

Переменные среды: TGWITNESS_DATA, TGWITNESS_HOST, TGWITNESS_PORT, TGWITNESS_TOKEN. Переменная TGWITNESS_VAULT_KEY_FILE выбирает режим внешнего ключа для новой установки; см. раздел [Внешний главный ключ](SECURITY-MODEL.md#external-master-key). Переменная TGWITNESS_TOKEN, если она указана, должна содержать не менее 24 символов; используйте криптографически случайное значение. В случае её отсутствия приложение генерирует 256-битный случайный токен в файле panel-token.txt. Переопределение переменных среды не приводит к перезаписи этого файла. Перезапустите систему для смены учетных данных.

Каталог данных может принадлежать ровно одному процессу. Кроссплатформенная блокировка файлов в ОС предотвращает случайные одновременные записи. Используйте один рабочий процесс Uvicorn. Панель может управлять любым количеством рабочих областей, для которых создаются дополнительные каталоги в папке profiles/<id>/. Для отдельных экземпляров службы используйте отдельные каталоги и порты. Файлы WAL базы данных SQLite должны храниться в локальном постоянном хранилище, а не в сетевой файловой системе. Не используйте один том совместно для нескольких реплик.</id>

<a id="windows-portable-package"></a>
## Портативный пакет для Windows

Каждый релиз на GitHub содержит файл `TgWitness-<version>-windows-amd64-portable.zip` и его контрольную сумму `.sha256`. Он включает официальную встраиваемую среду выполнения Python 3.12 с сайта python.org (контрольная сумма зафиксирована в файле `tools/build_portable.py`), TgWitness и его зафиксированные зависимости, а также три программы запуска:

| Файл | Назначение |
| --- | --- |
| `TgWitness.cmd` | Запуск панели; дополнительные параметры передаются, например: ``TgWitness.cmd --port 8790`` |
| `TgWitness-Demo.cmd` | Запуск синтетической демонстрации в папке `data\demo` |
| `TgWitness-Check.cmd` | Запуск проверки готовности без запуска программы |

Закреплённый словарь русской морфологии и цветовые профили в формате PDF включены в пакет для автономного использования. Система упаковки допускает только известные пути к файлам внутри каталогов зависимостей `data`; наличие неожиданных файлов в этих каталогах приводит к сбою сборки.

Распакуйте весь архив в папку с правами на запись, например, `Documents\TgWitness`; не запускайте программу из самой ZIP-архива или из папки «Program Files». Среда выполнения использует изолированный путь к модулям, поэтому другие установки Python и переменная `PYTHONPATH` не влияют на её работу. Данные хранятся в папке `data` пакета. Для обновления остановите TgWitness, распакуйте новую версию в новую папку и скопируйте туда папку `data`.

Соберите программу самостоятельно на 64-разрядной версии Windows с Python 3.12:

~~~sh
python tools/build_portable.py
~~~

<a id="container"></a>
## Контейнер

```sh
docker compose up -d --build --wait
```

При этом создаётся именованный постоянный том для /data. Веб-порт сопоставляется с адресом 127.0.0.1:8787. Процесс запускается с UID 10001 с ограниченными правами, корневой файловой системой, доступной только для чтения, а также доступными для записи каталогами /data и /tmp. Параметр `--wait` проверяет работоспособность веб-сервера перед возвратом результата; авторизация и доставка сообщений Telegram отображаются на панели. Предоставленные вспомогательные программы используют таймаут готовности продолжительностью 180 секунд после сборки. Первоначальная загрузка зависимостей может занять больше времени.

Оба базовых файла Compose используют название проекта `tgwitness`, поэтому распаковка нового релиза в другой каталог не приводит к автоматическому выбору нового тома данных. Держите активным только одно развёртывание для данного проекта. Для независимых установок используйте уникальную команду ``docker compose -p NAME ...`` и другой порт хоста, а при обновлениях сохраняйте оба развёртывания. Для более старого развёртывания, использующего другое имя проекта, продолжайте использовать его исходное имя с параметром `-p`; команда ``docker compose ls`` выводит список существующих проектов.

Скопируйте файл ``deploy/env.example`` в ``.env`` и измените переменную ``TGWITNESS_PORT``, чтобы использовать другой порт loopback. Например, значение ``TGWITNESS_PORT=8788`` делает панель доступной по адресу `http://127.0.0.1:8788`; при этом контейнер по-прежнему прослушивает порт 8787. Файл ``.env`` игнорируется системой Git.

Получите начальный токен:

~~~sh
docker compose exec tgwitness cat /data/panel-token.txt
~~~

Полезные команды:

```sh
docker compose ps
docker compose logs --tail 100 -f
docker compose stop
docker compose up -d --wait
```

`restart: unless-stopped` — перезапускает сборщик после сбоя или перезапуска демона Docker. На сервере под управлением Linux включите Docker при загрузке с помощью диспетчера служб вашего дистрибутива, как правило, с помощью команды ``sudo systemctl enable --now docker``. В Windows/macOS включите настройку «Запускать при входе в систему» в Docker Desktop. Выход из системы, переход в режим сна или остановка демона Docker могут прервать сбор данных. Явно остановленный контейнер остаётся остановленным до тех пор, пока вы не запустите его заново.

В приведённой конфигурации объём тома /tmp ограничен 512 MiB. При экспорте конструкций вместо него используется папка ``temporary-exports/`` каждой рабочей области, расположенная в постоянном хранилище /data. Зарезервируйте там место для одновременных экспортов, роста журнала/WAL, медиафайлов и резервных копий. Программа запуска использует файл `deploy/constraints.txt` для фиксации версий зависимостей среды выполнения, соответствующих требованиям. Установка Docker и серверов с высоким уровнем безопасности осуществляется на основе файлов deploy/requirements.lock и deploy/build.lock с помощью команды pip --require-heashes: каждый файл пакета должен соответствовать хешу SHA-256, зафиксированному в коммите, поэтому файл, заменённый на PyPI или в зеркале, будет отклонен. Пакеты, поставляемые только в виде исходного кода (jieba, pyaes), собираются с использованием версий setuptools, зафиксированных в файле deploy/build.lock (с параметром `--no-build-isolation`), как запускающим модулем, так и портативным сборщиком для Windows, а также Dockerfile; таким образом, pip не создаёт отдельную, незафиксированную среду сборки. Базовый образ Python и пакеты операционной системы по-прежнему требуют независимой квалификации выпуска.

Не используйте команду `docker compose down -v`, если только вы не намерены уничтожить журнал и ключи. Отчет о работоспособности контейнера отражает доступность веб-сервера, а не успешный захват данных Telegram. Проверьте состояние сборщика панели, сигнал работоспособности, ошибки и события покрытия.

<a id="independent-witness-profile"></a>
### Независимый профиль свидетеля

Дополнительная служба `witness` запускает [независимый свидетельский](WITNESS.md) узел в собственном контейнере с собственным ключом и журналом в томе `witness-data` и предоставляет сборщику только токен свидетеля, доступный только для чтения. Создайте токен в панели в разделе **Дополнительные инструменты → Дополнения → Независимый свидетель**, добавьте его вместе с токеном бота и каналом в файл ``.env``, а затем запустите профиль:

```sh
docker compose --profile witness up -d          # deploy/compose/compose.image.yaml: same flag
docker compose logs witness                     # witness key fingerprint
```

Служба обращается к сборщику внутри сети Compose по адресу `http://tgwitness:8787` (этот адрес переопределяется переменной `TGWITNESS_WITNESS_COLLECTOR`; например, `/profiles/<workspace ID>` для другой рабочей области). Для свидетеля на отдельном сервере, управляемом другим пользователем, используйте там файл `deploy/compose/compose.witness.yaml`, установив для переменной `TGWITNESS_WITNESS_COLLECTOR` HTTPS-адрес сборщика; этот файл содержит только данные свидетеля.

<a id="install-a-published-image"></a>
## Установка опубликованного образа

Скопируйте файл `deploy/env.example` в `.env`. Установите значение `TGWITNESS_IMAGE`, указав опубликованную версию с использованием пути к репозиторию **в нижнем регистре**, например:

```dotenv
TGWITNESS_IMAGE=ghcr.io/your-owner/your-repository:1.0.0
TGWITNESS_PORT=8787
```

Запустите этот файл отдельно, вместо файла ``compose.yaml``:

```sh
docker compose --project-directory . -f deploy/compose/compose.image.yaml pull
docker compose --project-directory . -f deploy/compose/compose.image.yaml up -d --wait
docker compose --project-directory . -f deploy/compose/compose.image.yaml exec tgwitness cat /data/panel-token.txt
```

На хосте не требуется сборка исходного кода, Python или компилятор. Рабочий процесс выпуска ориентирован на контейнеры Linux AMD64 и ARM64, включая виртуальную машину Linux в Docker Desktop. Используйте тег версии или `ghcr.io/owner/repository@sha256:...`, указанный в сводке рабочего процесса. Не настроено перемещение тега `latest` или автоматическое обновление приложения. Образ и варианты исходного кода используют один и тот же том данных, если их названия проектов совпадают.

<a id="automatic-https-on-a-server"></a>
## Автоматическая настройка HTTPS на сервере

Используйте сервер с Docker, домен, который находится под вашим контролем, и постоянное локальное хранилище. Направьте записи A/AAAA домена на сервер; публикуйте запись AAAA только в том случае, если к серверу осуществляется доступ по IPv6. Разрешите входящий трафик по TCP-портам 80 и 443, а также исходящий трафик DNS/HTTPS для выдачи сертификатов. Эти порты не должны быть заняты другими службами.

Скопируйте файл ``deploy/env.example`` в ``.env`` и укажите имя хоста без схемы или пути:

```dotenv
TGWITNESS_DOMAIN=watch.your-domain.org
```

Запустите сборку исходного кода с использованием оверлея HTTPS:

```sh
docker compose -f compose.yaml -f deploy/compose/compose.https.yaml up -d --build --wait
docker compose -f compose.yaml -f deploy/compose/compose.https.yaml exec tgwitness cat /data/panel-token.txt
```

```sh
docker compose --project-directory . -f deploy/compose/compose.image.yaml -f deploy/compose/compose.https.yaml up -d --wait
```

Для опубликованного образа вместо этого используйте файл ``deploy/compose/compose.image.yaml`` в качестве первого файла. Сохраните оба аргумента `-f` для последующих команд status, logs, update и stop.

Caddy получает и обновляет сертификат, перенаправляет HTTP-запросы на HTTPS и пересылает запросы сборщику в частной сети Compose. Состояние сертификата хранится в собственном постоянном томе. Порт хоста сборщика, к которому осуществляется прямое подключение, остается доступным только для локального цикла. В предоставленной конфигурации Caddy не включена регистрация доступа.

Откройте страницу `https://watch.your-domain.org` и введите токен панели. Готовность Compose распространяется на контейнеры; выдача сертификата и доступность извне зависят от DNS и брандмауэра. Если HTTPS не готов, проверьте настройки DNS, правила брандмауэра, а также:

```sh
docker compose -f compose.yaml -f deploy/compose/compose.https.yaml logs --tail 100 caddy
```

Предоставленный образ Caddy соответствует тегу `2-alpine`. При выполнении команды «pull» этот образ обновляется; зафиксируйте проверенный дайджест в своём развёртывании, если вам требуются фиксированные версии инфраструктуры.

<a id="updates-and-backups"></a>
## Обновления и резервное копирование

Сохраняйте название проекта Compose и том данных при обновлениях. Сначала остановите сборщика и создайте полную резервную копию. Для развёртывания по умолчанию на основе исходного кода:

```sh
docker compose stop
docker compose cp tgwitness:/data ../tgwitness-backup-before-update
```

Каждый раз используйте новое место назначения для резервного копирования, расположенное вне репозитория, и защищайте его как материал, требующий доступа к аккаунту. Приведённый пример пути носит иллюстративный характер; используйте своё собственное место для резервного копирования. Скопируйте весь каталог, включая скрытые файлы, все рабочие области, ключи, журналы и медиафайлы. Отдельно создайте резервную копию главного ключа внешнего хранилища, если он настроен. ZIP-архив с доказательствами не является резервной копией приложения, пригодной для восстановления. При использовании HTTPS также сохраните тома Caddy, если вам необходимо сохранить состояние его сертификата или аккаунта.

Для развертывания из исходного кода загрузите файлы новой версии и выполните:

```sh
docker compose up -d --build --wait
```

При развёртывании из образа замените `TGWITNESS_IMAGE` на нужную версию, а затем выполните:

```sh
docker compose --project-directory . -f deploy/compose/compose.image.yaml pull
docker compose --project-directory . -f deploy/compose/compose.image.yaml up -d --wait
```

Используйте файлы Compose вашей установки также для вышеуказанных команд остановки и копирования. Сохраните файл `.env`, пользовательскую конфигурацию и то же имя проекта. Команда `down` сохраняет именованные тома; команда **`down -v` удаляет их**. Не копируйте файл `.venv` между операционными системами или версиями Python. При выполнении нативных обновлений остановите TgWitness, создайте резервную копию всего каталога данных, замените исходные файлы и перед запуском выполните команду `python start.py --setup-only`.

После обновления проверьте доступ к панели управления, идентификацию аккаунта, состояние наблюдения и охват. После перезапуска TgWitness возобновляет работу с сохранённой позицией обновления Telegram и запрашивает обновления, пропущенные во время обновления. Для отката может потребоваться резервная копия, созданная до обновления, если в будущей версии изменятся форматы хранения.

<a id="remote-server"></a>
## Удалённый сервер

Обеспечьте привязку службы к loopback и используйте SSH-туннель либо завершайте HTTPS-соединение на обратном прокси-сервере. Базовый файл Compose предназначен исключительно для локального использования; дополнительный файл-наложение `deploy/compose/compose.https.yaml` предоставляет Caddy для настроенного домена. Не допускайте попадания токена bearer в URL-адреса и журналы прокси-сервера. Обратный прокси-сервер должен ограничивать размер запросов и частоту подключений. Не открывайте доступ к простому HTTP из Интернета.

Примеры для systemd, задачи входа в систему Windows, пользовательского агента macOS и Caddy приведены в [каталоге deploy/](../../deploy/README.md). Перед установкой проверьте и адаптируйте указанные в них пути. Это предоставленные шаблоны, а не локально выполняемые настройки для конкретной платформы. Обычный запускатель не регистрирует никаких фоновых служб или задач.

В Windows при запуске без оконного интерфейса с помощью `pythonw.exe` диагностические данные о запуске и работе сервера сохраняются в файле `logs/server.log` в каталоге data (5 МБ на файл, две сменяющиеся резервные копии). При запуске в консольном режиме ведётся консольная регистрация событий. Регистрация доступа по HTTP отключена в обоих режимах. Обеспечьте защиту журналов с помощью каталога data и проверьте их перед передачей.

<a id="restart-and-gaps"></a>
## Перезапуск и пропуски

Сохраняется состояние наблюдения, запрошенное в последний раз. Если наблюдение было активным, при запуске происходит попытка повторного подключения и возобновления выбранных источников. Ручная пауза сбрасывает это намерение. Неудачный перезапуск фиксируется и отображается на панели.

TgWitness сохраняет в хранилище рабочей области данные о положении обновлений Telegram для аккаунта и для каждого канала (pts, qts, seq и date) и восстанавливает их при следующем запуске. Затем клиент запрашивает обновления, пропущенные во время остановки процесса, а периодическая повторная проверка восстанавливает пропущенные сообщения и фиксирует сохраненные сообщения, которые Telegram больше не возвращает. Диалоги перезагружаются при запуске. При каждом запуске фиксируются предыдущая вершина журнала, граница автономного режима и позиция обновления, с которой возобновился процесс. Монитор проверяет подключение каждые 10 секунд и отправляет сигнал проверки работоспособности каждую минуту (**Дополнительные инструменты → Параметры → Отметка активности каждые**). Разрывы соединения и периоды без активности регистрируются как пробелы в охвате с указанием их причины. Снимки истории хранятся в виде отдельных наблюдений «текущее-история» рядом с записями в режиме реального времени.

Очередь для медиафайлов хранится в базе данных SQLite каждой рабочей области. Сообщение и соответствующее задание фиксируются атомарно. Прерванные выполняющиеся задания восстанавливаются для повторной попытки при запуске. Каждая загрузка имеет базовый таймаут в 120 секунд плюс время, рассчитанное исходя из скорости 256 КиБ/с и размера файла, а также ограничение в 1–2 000 МиБ на каждый тип вложения; настройки таймаута, скорости и повторных попыток находятся в разделе **Дополнительные инструменты → Параметры**. Сборщик пропускает файлы с неизвестным размером. При приостановке работы задачи, находящиеся в очереди, сохраняются. При повторной попытке используется исходный дескриптор файла, наблюдаемый во время наблюдения, а не последняя версия сообщения, отредактированная впоследствии. В случае временных сбоев количество повторных попыток ограничено; паузы в работе FloodWait сохраняются после перезапуска. Восстановление медиафайлов осуществляется отдельно от восстановления обновлений Telegram и не позволяет воссоздать исчезнувшие файлы.

<a id="backup-restore-and-capacity"></a>
## Резервное копирование, восстановление и емкость

Команда `tgwitness backup FOLDER` копирует каталог данных при продолжающейся работе панели: сначала контрольные точки, затем файлы SQLite через API онлайн-резервного копирования, далее ключи, медиафайлы и профили, благодаря чему ни одна скопированная контрольная точка не будет более поздней, чем скопированный журнал. Файл `backup-manifest.json` содержит SHA-256 каждого файла и вершины журналов. Для восстановления остановите TgWitness и замените весь каталог данных этой папкой. При следующем запуске будет зафиксировано, что журнал был восстановлен из более старой копии. Эта запись сравнивает журнал с вершиной журнала, хранящейся в `TGWITNESS_STATE_DIR` — папке, расположенной вне каталога данных: том `tgwitness-state` в Compose, `/var/lib/tgwitness-state` в модулях systemd, а в остальных случаях — в локальной папке состояния пользователя. При отсутствии доступной для записи папки состояния восстановление не обнаруживается, о чём один раз сообщается в журнале.

Если эта команда отсутствует, остановите процесс перед копированием **всего каталога данных**, включая файлы vault.key, signing.enc, credentials.enc, файлы базы данных SQLite и WAL, медиафайлы, токен, контрольные точки, а также все подкаталоги profiles/. Восстановите полную копию, пока целевой сервис остановлен. Отсутствие ключей хранилища или несоответствие ключей подписи приводят к сбою запуска; не генерируйте ключи заново, чтобы принудительно получить доступ.

Храните секретные резервные копии в зашифрованном виде с контролем доступа. ZIP-архивы с доказательствами являются переносимыми артефактами для проверки, а не резервными копиями приложения или сеансов Telegram. Автоматического удаления по истечении срока хранения не предусмотрено. Запланируйте дисковое пространство для всех сообщений, исходных метаданных, медиафайлов, временных экспортов и резервных копий.

Проводите проверку при запуске и экспортируйте записи потока вместо загрузки всего журнала. Экспорт фиксирует моментальный снимок для чтения, в то время как новые записи в WAL могут продолжаться; длительные экспорты могут сохранять страницы WAL, поэтому объём дискового пространства по-прежнему имеет значение. Размер ZIP-архивов ограничен 4 ГиБ в несжатом виде в соответствии с настройками по умолчанию независимого верификатора; **Дополнительные инструменты → Параметры → Максимальный размер ZIP-архива с подписью (в несжатом виде)** позволяет увеличить этот предел, и такие архивы проверяются с помощью команды `verify.py --max-gib N`. Для других форматов ограничения по количеству событий отсутствуют. Поддерживаемые браузеры передают фрагменты ответа в потоковом режиме в файл, выбранный пользователем. Другие браузеры буферизуют не более 128 MiB и направляют более объёмные передачи в авторизованный CLI:

~~~sh
python -m tgwitness.download --token-file data/live/panel-token.txt --out evidence.zip
~~~

Используйте параметр `--profile ID` из **меню Экспорт → Идентификатор рабочей области** для другой рабочей области, `--format zip|jsonl|csv|html`, `--url https://your-server` для удалённого сервера или `--max-mib` для изменения ограничения на передачу данных в 5 ГБ. Простой HTTP допускается только для loopback. Токены передаются в заголовках, перенаправления не допускаются, существующие файлы не перезаписываются, а незавершённые загрузки не публикуются как завершённые файлы. Если TGWITNESS_TOKEN переопределяет сгенерированный токен, используйте отдельно защищённый файл, содержащий это активное значение: файл panel-token.txt не перезаписывается при переопределении. SHA-256 команды является лишь контрольной суммой передачи; независимо проверьте подписанный ZIP-архив.

Панель отображает медиафайлы в очереди или с ошибками, самые старые медиафайлы в ожидании, свободное место на диске, паузы в запросах Telegram, а также источники, доступ к которым не подтверждён. Данные диагностические данные не являются полноценным монитором доставки от начала до конца. Рабочие области используют общий процесс; активный аккаунт по-прежнему может влиять на другие. Остаются нерешенными вопросы, касающиеся отдельных рабочих процессов, хранения и ротации данных, восстановления после отказов при обновлении и полной квалификации развёртывания. Доступ к панели с ограниченной областью действия описан в разделе [Доступ и разрешения](ACCESS.md); независимые контрольные точки рассматриваются в [руководстве для свидетелей](WITNESS.md).

Подробные процедуры: [подключение/безопасность](CONNECTION-SECURITY.md) и [режимы работы](OPERATIONS.md).
