# TgWitness: запуск, масштабирование и доказательства

[English](../OVERVIEW.md) · **Русский**

TgWitness — это экспортер Telegram с открытым исходным кодом и рабочая область для расследований. Установите его одной командой, подключите аккаунт, выберите чаты и экспортируйте подписанный архив. Он также поддерживает временное хранение данных в GitHub Actions и продолжение расследований с помощью сохраненных правок, наблюдений за удалениями, поиска и отчётов.

<a id="start-with-the-task-you-have"></a>
## Начните с той задачи, которая у вас есть

| Ваша задача | Кратчайший путь | Что вы получите |
| --- | --- | --- |
| Сохраните чат или аккаунт | Установите приложение, подключите аккаунт, выберите объем экспорта | Подписанный архив с выбранной историей, результатами сбора и материалами для проверки |
| Соберите данные на временном рабочем процессе | Воспользуйтесь функцией сбора данных GitHub Actions, авторизуйтесь в новом сеансе и выберите область | Зашифрованный архив с информацией о происхождении рабочего процесса GitHub |
| Отслеживайте изменения с течением времени | Обеспечьте непрерывное наблюдение за выбранными чатами | Сохраненные версии, уведомления об удалении, вложения и записи переписки |
| Анализируйте и делитесь результатами | Осуществляйте поиск в архиве, используйте Case Board и настраивайте отчет или копию для передачи | Результаты, привязанные к исходным данным, и поддающаяся проверке передача информации, адаптированная к потребностям получателя |

<a id="one-command-installation"></a>
### Установка с помощью одной команды

Установщик включает Python и зависимости. Извлечение исходного кода, Docker, поставщик ИИ и независимый свидетель являются опциональными компонентами, а не обязательными условиями установки.

Linux / macOS:

```sh
curl -fsSL https://get.destroy.tools/install.sh | bash
```

Windows, в PowerShell или командной строке:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -Command "irm https://get.destroy.tools/install.ps1 | iex"
```

Откройте панель, подключите свой аккаунт Telegram и выберите область сбора данных. Установка сама по себе не запускает сбор данных. В [руководстве по установке](INSTALLATION.md) описаны локальный доступ, серверы, обновления и проверка загруженной сборки.

Для создания временного исполнителя следуйте [инструкциям по настройке GitHub Actions](SEALED-ACTIONS.md). Для этого рабочего процесса требуется форк репозитория на GitHub, авторизация и пароль к архиву. На странице настройки описаны эти шаги, а также время, отведённое на сеанс перед запуском. Загрузите и сохраните полученный архив и материалы для его проверки.

<a id="more-settings-when-the-task-needs-them"></a>
## Дополнительные настройки, если они требуются для выполнения задачи

Для экспорта данных из одного чата требуется аккаунт и выбранная область сбора данных. Непрерывное наблюдение, использование нескольких аккаунтов, прокси-серверы, политики вложений, оформление отчётов, доступ рецензентов, внешние временные метки и хранение данных за пределами платформы отвечают различным требованиям расследований и передачи материалов. Настройте эти функции, если они актуальны.

Область действия, разрешения и минимизация количества копий для обмена данными помогают операторам выбирать, что собирать и раскрывать. Рекомендации по юрисдикции и настройки отчётов фиксируют выбранную процедуру и этапы подготовки. Ознакомьтесь с [экспортом аккаунтов](ACCOUNT-EXPORT.md), [настройками доступа](ACCESS.md) и [конфигурацией отчётов](CASE_REPORTS.md).

Приложение работает на выбранном компьютере или сервере. Для базового сбора данных не требуется графический процессор (GPU) или модель большого языка (LLM). Дополнительные функции — OCR, транскрипция и анализ с помощью искусственного интеллекта — имеют собственные требования к ресурсам. Определите масштаб развертывания с учётом интенсивности обмена сообщениями, вложений, объёма сохраняемой истории и количества одновременно обрабатываемых аккаунтов.

<a id="preserve-the-record-whoever-it-helps"></a>
## Сохраняйте записи, кому бы они ни помогли

Цель заключается в сохранении наблюдаемого материала, контекста и изменений независимо от того, чью позицию они подтверждают. Доказательства могут опровергнуть собственную версию событий, представленную сборщиком данных. Обеспечьте возможность идентификации исходных наблюдений, пропущенных фрагментов и аналитических выводов, чтобы другое лицо могло оценить тот же материал.

Логика следующая: наблюдение, видимое для аккаунта → подписанный журнал → экспорт → проверка получателем. Сохраненные правки добавляют версии. Наблюдения об удалениях сохраняют ранее зафиксированное содержание. Записи об охвате раскрывают известные перерывы. Отчеты и анализ с помощью ИИ ссылаются на сохраненные источники; интерпретация не становится наблюдением из источника лишь потому, что она фигурирует в подписанном отчете.

| Проверка достоверности | Что может установить получатель |
| --- | --- |
| Хеши файлов, подписи и цепочка журналов | Предоставленные записи и файлы соответствуют ожидаемому ключу и границам журнала |
| Отдельно сохраненная контрольная точка или свидетель | Архив соответствует ранее сохраненному состоянию журнала |
| Проверенная внешняя временная метка | Указанные байты существовали на момент установления временной метки в соответствии с заявленными допущениями о доверии |
| Свидетельство о фиксации GitHub | Архив соответствует утверждённому рабочему процессу, ревизии сборщика и записанному дайджесту |
| Аттестация Intel TDX | Цитата, статус платформы, ожидаемые показатели ОС/приложения, актуальность данных и идентификационные данные сборщика прошли настроенные проверки |

При заверенном сборе данных аутентифицированное соединение с Telegram и выходные данные утвержденного сборщика привязаны к проверенной среде выполнения. Архив сохраняет захваченное содержимое и контекст; отчеты и аналитика ссылаются на эти записи. Используйте этапы проверки, специфичные для данного режима, а также доверенные входные данные, указанные в [руководстве по доверию](TRUST.md) и [формате доказательств](EVIDENCE.md).

<a id="testing-history-and-duration"></a>
### История и продолжительность тестирования

Разработка и тестирование TgWitness продолжались около шести месяцев. Сначала были созданы сборщик, подписанный журнал и верификатор; веб-панель и дополнительные модули были построены на их основе позднее. Данный репозиторий был создан 29 октября 2026 года специально для публикации и основан на существующем коде, поэтому его возраст не соответствует возрасту проекта ([истории разработки](QUESTIONS-AND-CHECKS.md#development-history)). Совокупный объём протестированной нагрузки составляет порядка 100 миллионов, включая предыдущие запуски, сбои, исправления и повторную валидацию. Отдельные запуски, каждый со своей ревизией, методом и результатом, задокументированы в [датированных публичных измерениях](QUESTIONS-AND-CHECKS.md#dates-of-the-published-measurements).

<a id="read-capability-status-precisely"></a>
## Точно оценивайте состояние работоспособности

Оценивайте каждый рабочий процесс с учётом его реализации, опубликованной сборки и зафиксированных тестов. Исходный код в настоящее время помечен как «предварительная версия». Этот ярлык выпуска сосуществует с рабочей коллекцией, экспортами, независимой верификацией и опубликованными результатами масштабных измерений. Функция, находящаяся в предварительной версии, и проверенный рабочий процесс могут существовать в одном приложении; описывайте конкретную функцию и доказательства, лежащие в основе оценки.

Используйте [текущие возможности](STATUS.md), [функции и ограничения](PRODUCT.md), [результаты верификации](VERIFICATION.md) и [журнал изменений](../CHANGELOG.md) в совокупности. При цитировании результата указывайте проверенную версию. Снимок измерений от 6 ноября также содержит сведения о неудачных и пропущенных тестах; они не считаются успешными.

<a id="readable-by-people-and-ai-tools"></a>
## Доступно для чтения людьми и инструментами искусственного интеллекта

На веб-сайте представлен краткий файл `llms.txt`, полное руководство на английском языке в файлах `llms-full.txt` и `llms-full.md`, а также версии страниц в формате Markdown. Это форматы документации, а не требования к ИИ для запуска TgWitness.

Дополнительный [доступ](CLI.md) [через MCP](MCP.md) и [командную строку](CLI.md) позволяет авторизованным инструментам считывать выбранные сохраненные записи. Содержание сообщений остаётся недоверенными входными данными. В сводках следует указывать источники, проводить разграничение между наблюдаемыми фактами и выводами, а также отражать степень неопределённости. Полнотекстовый поиск, OCR и результаты обработки искусственного интеллекта не изменяют исходные подписанные наблюдения.
