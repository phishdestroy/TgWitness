# Руководство по юрисдикции в Report Studio

Откройте **Экспорт → Создать отчёт → Рекомендации по юрисдикции · необязательно**. Выберите юрисдикцию и процедуру соответствующего суда, проверьте исходные ссылки, а затем сохраните настройки отчёта. На вкладке «Рекомендации» отображается предварительный просмотр приложения на основе текущего черновика. Предварительный просмотр или изменение страны не приводят к сохранению данных. Существующие макеты отчётов, темы, языковые настройки, фильтры охвата и примечания к экспертизе по-прежнему остаются в силе.

В каталоге представлены полные профили рекомендаций для 31 юрисдикции: Австралия, Бразилия, Канада, материковый Китай, Хорватия, Англия и Уэльс, Франция, Грузия, Германия, Индия, Индонезия, Иран, Италия, Казахстан, Люксембург, Малайзия, Мальта, Мексика, Пакистан, Филиппины, Португалия, Россия, Саудовская Аравия, Сингапур, Словения, Испания, Турция, Украина, ОАЭ, США и Вьетнам. Для других стран, включённых в каталог экспертных исследований, представлены только рекомендации по проведению экспертизы. Примечания по сфере применения указывают на ограничения, такие как различия между федеральным и штатным уровнями; указание страны не заменяет указания конкретного суда. Данный набор представляет собой перечень охватываемых юрисдикций, а не рыночный рейтинг.

<a id="defaults-and-configuration"></a>
## Настройки по умолчанию и конфигурация

Вложенный объект ``jurisdiction_guidance`` поддерживается параметрами ``ReportOptions`` и ``report_presentation`` в настройках аккаунта и совместного доступа:

```json
{
  "jurisdiction_guidance": {
    "jurisdiction": "",
    "procedure": "civil",
    "include_in_report": true,
    "local_note": false,
    "include_methods": false
  }
}
```

| Выбор | Поведение |
| --- | --- |
| Пустое поле «jurisdiction» | Приложение отсутствует. Никогда не определяется на основе IP-адреса, языка интерфейса или местоположения провайдера. |
| Код юрисдикции, например, `BR`, `US`, `IN`, `GB-EW` | Использует данную запись каталога. Неизвестные коды отклоняются. |
| `civil` / `criminal` | Выбирает соответствующую основу, источники и локальное резюме. Задачи по подготовке гражданских дел не используются повторно в качестве уголовных формальностей. |
| `include_in_report: false` | Сохраняет выбор в настроенных параметрах, при этом опуская приложение. |
| `local_note: true` | Добавляет резюме на родном языке. Это не является заверенным переводом. Для PDF-файла требуются шрифты, соответствующие данному алфавиту; отсутствие необходимых глифов приводит к явной ошибке. |
| `include_methods: true` | Добавляет пояснения относительно подписей, временных меток, хранения данных, свидетелей, TEE, визуальной фиксации и участия человека. Речь идет о возможных мерах, а не о утверждениях, что они были применены. |

Запрос `GET /api/report-guidance` предоставляет каталог с указанием версии авторизованным пользователям, имеющим право на просмотр. Запрос `POST /api/report-options` использует существующее разрешение на экспорт. При изменении этих параметров сохраняйте полный объект report-options, как и в случае с другими настройками отчёта. Эти параметры настраивают отчёт, а не сборщик данных, учётную запись в облаке, политику хранения или службу свидетелей.

Используйте **Примечания к экспертизе** для указания конкретного суда, применимых региональных норм, порядка сертификации, вопросов и профессиональной экспертизы. В случае юрисдикции, не указанной в списке, или особой процедуры оставьте поле выбора из каталога пустым и воспользуйтесь этими примечаниями; не выбирайте соседнюю страну в качестве юридического представителя.

<a id="reports-and-isolation"></a>
## Отчёты и изоляция

| Вывод | Выбор руководств |
| --- | --- |
| Журнал и передача данных в форматах HTML, PDF, JSON и подписанные манифесты | Сохраненные настройки отчётов в рабочих областях или явные настройки для данного экспорта. |
| Отчёт по отдельному чату | Его параметры отчёта. |
| Отчет по аккаунту и отчеты по чатам | Явная настройка параметра ``report_presentation`` или сохраненная настройка рабочей области, если вызывающая сторона API не указала её. |
| Свернутая копия для совместного доступа | Отсутствие неявного наследования. Вызывающая сторона API может явно выбрать общедоступный профиль в параметре `report_presentation` производного объекта. |
| Автономный экспорт заметок из Case Board | Вне данного потока настроек отчёта. Для данного приложения используйте отчёт о доказательствах или отчёт о аккаунтах. |

Профили макетов, предназначенные для повторного использования, исключают объект юрисдикции, так же как они исключают названия дел, выводы и фильтры. Новая рабочая область создаётся без указания юрисдикции. Существующие средства защиты «unsigned-preview» и «lock/workspace» также распространяются на эти поля.

Приложение содержится в объекте `case_assessment.jurisdiction_guidance` вместе с версией каталога и SHA-256, датой исследования, объёмом, источниками и статусом исследования. Данные отчёта в форматах HTML, PDF и структурированном виде отображают тот же объект. Существующие подписи связывают приложение с предоставленной копией. Проверки криптографической оценки не обновляются и не скрываются при выборе юрисдикции или объяснения мер защиты.

Приложение начинается с раздела **Что необходимо сделать с данной копией дальше**, составленного на основе фактической оценки экспорта: наблюдаемого результата и следующего этапа проверки или документирования для каждой проверки. Например, отсутствующая временная метка, непроверенная квитанция и временная метка, охватывающая только префикс, приводят к разным инструкциям. Зафиксированные несоответствия приводят к объяснению затронутого периода, а не к утверждению о том, что настройка может исправить прошлые данные. Включённые цитаты TDX по-прежнему требуют независимой проверки. Предварительный просмотр проекта не генерирует эти выводы; они добавляются во время экспорта. Данный список задач служит руководством при подготовке пакета и фиксирует проведённые проверки.

<a id="research-status"></a>
## Статус исследования

Версия каталога `2026-11-14.2` представляет собой **рабочий проект** с ссылками на источники для каждого маршрута; маршрут по уголовному праву Ирана помечен как `needs_local_review`. В профилях Хорватии, Грузии, Казахстана, Люксембурга, Мальты и Словении приводятся ссылки на официальные порталы законодательства в редакции от 14 ноября 2026 года; более поздние поправки к цитируемым статьям были отслежены лишь частично. Для каждой подачи документов необходимо подтвердить действующее законодательство, а также фактические сведения о суде, органе, уполномоченном на получение документов, раскрытии информации, удостоверении подлинности, использовании свидетельских показаний из вторых рук (где это применимо), переводе и формальностях; кроме того, английское руководство и резюме на родном языке должны быть проверены практикующим специалистом, имеющим право на практику в данной стране.

При выборе меры безопасности добавляется объяснение её преимуществ, того, что следует сохранить, и способов её усиления. Проверка журнала осуществляется с использованием ключа доверенного сборщика данных; сохраненные контрольные точки свидетелей позволяют сравнить данные с ранее независимо проведенными наблюдениями за границами журнала. Аккаунт поставщика, принадлежащий отдельной стороне, выводит хост и гипервизор из-под контроля оператора.

Помимо перечня выбранных мер безопасности, в приложении также приводится [Руководство ENFSI по передовым методам проведения криминалистической экспертизы цифровых технологий](https://enfsi.eu/wp-content/uploads/2016/09/1._forensic_examination_of_digital_technology_0.pdf) (ENFSI-BPM-FIT-01, версия 01, ноябрь 2015 г.) — практическое руководство для криминалистических лабораторий. Данный документ не является законом и не устанавливает правил допустимости доказательств для какого-либо суда.

Необходимо обеспечить сохранность фактических версий объектов и прав доступа; одного лишь шифрования, конечной точки S3 или управления версиями недостаточно. См. [AWS Object Lock](https://docs.aws.amazon.com/AmazonS3/latest/userguide/object-lock.html). Заявления о TEE требуют проверки соответствующих связей развертывания и вывода; сфера применения данной платформы задокументирована в [dstack](https://github.com/Dstack-TEE/dstack). Просмотрите видеозапись с зафиксированным маршрутом сбора данных, интервалами наблюдения и результатами проверки записывающего устройства.

<a id="validation"></a>
## Валидация

Закрытые регрессионные тесты охватывают настройки по умолчанию, отклонение входных данных, каждую ветвь каталога по гражданским и уголовным делам, неизменные проверки доверия, границы рабочей области и прав доступа, настройки по умолчанию для совместного доступа, исключение макетов, все восемь вариантов оформления HTML/PDF, соответствие манифеста и JSON, а также сбой подписи после изменения текста руководства. При проверке в браузере используются синтетические записи, обе темы, узкие и настольные области просмотра, навигация с помощью клавиатуры, сравнение сохраненных и черновых вариантов, а также переключение между процедурами.
