Why

On a verified server the provider's log shows everything done through the API. It cannot show what someone with root on the physical host does: read the server's memory and its signing key, or change data before it is signed. Intel TDX closes that gap.

What if TDX is broken

Processor flaws are found and fixed with microcode updates; Intel then rates platforms without the fix as out of date. Suppose someone breaks TDX on the machine that runs your collector:

! They can

  • Read the memory of a machine on that host, the signing key included
  • Sign false new records from then on
  • Produce quotes that look valid for new records

✓ They cannot

  • Change checkpoints that witnesses already hold
  • Move RFC 3161 time stamps or OpenTimestamps receipts
  • Change copies already stored under S3 Object Lock
  • Change what Telegram itself still holds
  • Change the result of earlier quotes: each is rated as of the time it was recorded

A break reaches forward, not back.

Rollback of the disk by the host

dstack encrypts the disk, but the host can put back an older copy of it; dstack acknowledges this limit. Checkpoints kept outside the machine catch it.
