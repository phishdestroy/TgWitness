# ייצוא ואימות

Canonical page: https://phishdestroy.github.io/TgWitness/he/docs/exports/

יש לספק למקבל קבצים שאותם יוכל להשוות לסביבת העבודה של האיסוף ולהיסטוריה השמורה שלה.

שמור הפניהייצא ZIP חתוםהנמען מאמת

חדש בתחום החתימות ונקודות הבקרה? [שנה רשומה לדוגמה](https://phishdestroy.github.io/TgWitness/he/docs/concepts/#chain) ובדוק אילו בדיקות מזהות אותה.

רוצים לשמור עותק בנפרד מהאוסף? עברו [להגדרות S3](https://phishdestroy.github.io/TgWitness/he/docs/exports/#s3), [נעילת אובייקטים](https://phishdestroy.github.io/TgWitness/he/docs/exports/#s3-retention) או [שחזור מאומת](https://phishdestroy.github.io/TgWitness/he/docs/exports/#s3-restore).

## שמרו על מקור מידע אמין

יש לשמור את טביעת האצבע של המפתח הציבורי של סביבת העבודה מחוץ לאספן. במהלך האיסוף, יש לשמור נקודות ביקורת חתומות במקום אחר או להשתמש [בעד עצמאי](https://phishdestroy.github.io/TgWitness/he/docs/witness/). הפניות אלה מאפשרות למקבל לבדוק את המפתח ואת גבול היומן הקודם.

## הורד את קובץ ה-ZIP החתום

פתחו **את** **"ייצוא"** **(Exports)** וצרו קובץ ZIP חתום של ראיות. הקובץ כולל את יומן סביבת העבודה המלא ואת רשימת הקבצים החתומה. השתמשו ב-["Report Studio"](https://phishdestroy.github.io/TgWitness/he/docs/reports/) כדי לעצב דוח קריא, או [בתמצית](https://phishdestroy.github.io/TgWitness/he/docs/handover/) [למסירה](https://phishdestroy.github.io/TgWitness/he/docs/handover/) כדי להעביר רק נתונים נבחרים ומצומצמים.

דוחות בפורמטים HTML, PDF ו-JSON נושאים חותמות חתומות משלהם וניתן לבדוק אותם בנפרד. קובץ CSV מהווה עותק נוח לניתוח; יש להשתמש בקובץ ה-CSV המדויק הנמצא בתוך קובץ ה-ZIP המאומת כדי לבדוק את תקינותו. יש לשמור את קובץ ה-ZIP החתום כאשר הנמען זקוק גם לרישומים המקוריים ולנספחים.

## אמת באמצעות עותק מהימן של TgWitness

בסביבת הפרויקט המותקנת, יש להחליף את טביעת האצבע לדוגמה ואת נתיבי הקבצים:

```
python -m tgwitness.verify evidence.zip --fingerprint TRUSTED_PUBLIC_KEY_SHA256 --checkpoint retained-checkpoint.json
```

כאשר שתי ההפניות עוברות את הבדיקה, התוצאה מדווחת על `key_pinned: true` ו-`checkpoint_checked: true`. שמור את תוצאת האימות יחד עם הארכיון המקורי. נקודת הבדיקה שנשמרה חייבת להיות בגבול הייצוא או לפניו.

## השתמש בתוצאת האימות

- **יש לבדוק את הקבצים שנמסרו:** קובץ המניפסט קושר את חתימות ה-hash שלהם, וחתימות הרשומות קושרות את היומן השמור. ניתן לזהות קובץ ששונה או שרשרת רשומות שבורה.
- **בדקו את זהות סביבת העבודה:** טביעת האצבע שנשמרה באופן עצמאי מזהה את מפתח החתימה שציפיתם לו.
- **השוו לגבול קודם:** נקודת ביקורת שנשמרה בודקת את הייצוא מול קידומת יומן שנשמרה לפני המסירה.
- **יש לבדוק את היקף האיסוף:** פערים, תוצאות הרכישה ומבחן מבוקר של "שליחה → עריכה → מחיקה" המתאר את האירועים שתועדו בהגדרה זו.

יש לשמור תוצאות אלה יחד עם העותק של הנמען. יש לבדוק [מה קובעת האימות](https://phishdestroy.github.io/TgWitness/he/docs/reference/evidence/#verification-scope) לגבי היקף הבדיקות והערכה הנפרדת של טענות המקור והיקף האיסוף.

## הגדרת העותק החיצוני ב-S3

בסביבת העבודה הפועלת שלכם, פתחו **את 'ייצוא' → 'עותק מחוץ לאתר**'. תכונה אופציונלית זו פועלת עם AWS S3 ושירותים אחרים התואמים ל-S3. היא מעתיקה קטעי יומן, תמונות וקבצים שנשמרו, נקודות ביקורת עם תגובות חותמת הזמן שלהן, וייצוא צ'אטים שהושלמו. כל אובייקט מוצפן באספן באמצעות `AES-256-GCM` לפני ההעלאה.

ההדגמה המקוונת מציגה את אותם פקדים כאשר האפשרות להעלאת קבצים מושבתת. הזן את פרטי הכניסה לאחסון רק בסביבת העבודה שלך.

[![לוח בקרות מלא מחוץ לאתר: נקודת קצה, אזור, דלי, מפתחות גישה, לוח זמנים, נעילת אובייקטים ובקרות מפתחות שחזור](https://phishdestroy.github.io/TgWitness/assets/off-site-copy.png)](https://phishdestroy.github.io/TgWitness/assets/off-site-copy.png)

לוח הבקרה המלא עם האפשרויות המתקדמות פתוח. לא מוצגים פרטי הזדהות לאחסון.

| תחום | מה להזין |
| --- | --- |
| נקודת קצה | כתובת ה-URL של שירות האחסון, ללא נתיב לתיקייה או פרטי התחברות. דוגמה בדיונית: `https://s3.example.invalid`. |
| אזור | האזור הנדרש על ידי הספק שלך. ברירת המחדל של היישום היא `us-east-1`. |
| Bucket | ארכיון קיים שאליו ניתן לגשת. דוגמה בדיונית: `example-case-backup`. |
| תיקייה בסל | קידומת האובייקט; ברירת המחדל היא `tgwitness`. היישום מוסיף קידומת הנגזרת מטביעת האצבע של מפתח החתימה של סביבת העבודה הזו. |
| מזהה מפתח גישה / מפתח גישה סודי | הזן את שני פרטי ההזדהות לאחסון יחד. הם נשמרים בכספת סביבת העבודה. השאר את שניהם ריקים בשמירות עתידיות כדי לשמור על הצמד שנשמר. |
| כתובות בסגנון Path | יש להשתמש ב-`endpoint/bucket` כאשר האפשרות מופעלת, או ב-`bucket.endpoint` כאשר האפשרות מושבתת, בהתאם להוראות הספק. |
| מרווח בין טקסטים | בין 1 ל-1,440 דקות; ברירת המחדל היא 5 דקות. על היישום לפעול כדי לבצע העתקות מתוזמנות. |
| שמירת נתוני Object Lock | ימי שמירה ואופן השמירה עבור דלי התומך ב-Object Lock. "אפס ימים" משאיר את הגדרת השמירה המוגדרת כברירת מחדל של הדלי בתוקף. |

1. צרו את ה-bucket אצל הספק שלכם, ולאחר מכן הזינו את היעד ואת פרטי ההזדהות שלו. השאירו **את האפשרות "שמור עותק מחוץ לאתר"** ללא סימון במהלך ההכנה, ולאחר מכן בחרו "**שמור עותק מחוץ לאתר"**.
2. בחר באפשרות "**בדוק חיבור**". פעולה זו מעלה אובייקט בדיקה מוצפן ובודקת את תגובת האחסון.
3. בחר באפשרות "**הורד מפתח הצפנה**". שמור קובץ זה בנפרד מהאספן; הוא נדרש לשחזור.
4. סמן את תיבת הסימון "**שמור עותק מחוץ לאתר**" ושמור שוב. בחר "**העתק עכשיו"** לביצוע ידני, או השאר את לוח הזמנים פועל.

## בדוק את משך השמירה ואת התקדמות ההעתקה

תחת **"אפשרויות נוספות**" (**More options**), בחר את ימי השמירה ואת "`GOVERNANCE`" או "`COMPLIANCE`" כאשר ה-bucket שלך תומך ב-Object Lock. TgWitness קורא בחזרה את מצב השמירה ואת מועד התפוגה של אובייקט שהועלה. בדוק את תוצאת השמירה הנפרדת: מאושר, שמירה חסרה או כישלון בבדיקה.

הפאנל מדווח על המעבר האחרון, מספר האובייקטים, כמות הבתים שהועברו, גבול היומן שהועתק וכל שגיאה. מדיה מקומית חסרה או ששונתה מדווחת, והפעולה חוזרת על עצמה במעבר הבא. קבצים, נקודות ביקורת וייצוא בתור לאחר אותה מדיה עדיין ניתנים להעתקה.

העלאות משתמשות במסלול Direct, SOCKS5 או HTTP של סביבת העבודה. יש לבחור באחד ממסלולים אלה לצורך העתקה ל-S3; מסלול המשתמש ב-MTProxy בלבד יותיר את ההעתקה במצב "ממתינה" עם שגיאה.

## יש לשמור את מפתח השחזור בנפרד

קובץ ה-JSON שהורדת מכיל את מפתח הפענוח, הגדרות היעד, קידומת האובייקט של סביבת העבודה וטביעת האצבע של מפתח החתימה. לשחזור נדרשים הן קובץ המפתח הזה והן פרטי הזדהות נפרדים לאחסון, הכוללים גישה לקריאה לדלי. יש לשמור אותם בתוכנית השחזור שלך.

אם תשנו את נקודת הקצה, את הדלי או את קידומת התיקייה, הורידו את קובץ המפתח שוב כדי שהגדרות היעד שלו יתאימו. היישום יפעיל עותק חדש של היומן, הקבצים ונקודות הבדיקה השמורים באופן מקומי, ביעד החדש. ייצוא צ'אטים שהושלמו וכבר הוסרו מתור ההעלאה המקומי יישארו ביעדם הקודם.

## שחזור ואימות במחשב אחר

השתמש בהתקנה אמינה של TgWitness, בקובץ ה-JSON של המפתח שהורדת, בפרטי הזדהות לאחסון עם גישה לקריאה, ובספריית פלט ריקה. החלף את מחליפי פרטי הזדהות הדמיוניים המופיעים להלן.

### Windows PowerShell

```
$env:TGWITNESS_S3_ACCESS_KEY = 'YOUR_READ_ACCESS_KEY'
$env:TGWITNESS_S3_SECRET_KEY = 'YOUR_READ_SECRET_KEY'
python -m tgwitness.replica restore --key-file tgwitness-replica-key.json --out restored-evidence
```

### Linux / macOS

```
export TGWITNESS_S3_ACCESS_KEY='YOUR_READ_ACCESS_KEY'
export TGWITNESS_S3_SECRET_KEY='YOUR_READ_SECRET_KEY'
python -m tgwitness.replica restore --key-file tgwitness-replica-key.json --out restored-evidence
```

הקבצים שהורדו והאובייקטים שהוצפנו נשמרים באחסון זמני פרטי בזמן שבוצעת בדיקה של היומן כולו, נקודות הבדיקה שנשמרו, וכן חתימות ה-hash והגדלים של המדיה שנשמרה. נתיבים לא בטוחים, קטעי יומן סותרים ויומן שקצר מנקודת הבדיקה שלו נדחים. אימות שנכשל אינו מפרסם קבצים משוחזרים.

שחזור מוצלח יניב את `events.jsonl`, `media/`, `checkpoints/` ו-`exports/` עבור החומר הזמין בעותק. שמרו את תוצאת ה-JSON של הפקודה יחד עם החומר ששוחזר.

השוו את החומר ששוחזר לנקודות הבקרה או לרישומי העדים ששמרתם באופן עצמאי, ולאחר מכן עיינו בהיקף האיסוף המתועד עבור התקופה הדרושה לכם.
