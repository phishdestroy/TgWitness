# Швидкий старт TgWitness

TgWitness — автономний додаток для спостереження за групами й каналами Telegram, до яких мають доступ ваші облікові записи. Він працює локально з власним каталогом даних.

**Уперше тут?** [Ознайомтеся з демоверсією](#explore-the-interface), перш ніж підключати обліковий запис. [Оберіть посібник](../README.md) про проксі, свідків, експорт або налаштування сервера. [Збір через GitHub Actions](../SEALED-ACTIONS.md) (попередня версія) виконує збір у вашому власному форку на GitHub замість локальної інсталяції.

<a name="install-and-start"></a>

## Встановлення та запуск

Покроковий інсталятор має власний Python і перед встановленням перевіряє хеші пакетів та підписи релізу. Повторний запуск оновлює наявну інсталяцію.

**Linux / macOS:**

```sh
curl -fsSL https://get.destroy.tools/install.sh | bash
```

**Windows (PowerShell або командний рядок):**

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -Command "irm https://get.destroy.tools/install.ps1 | iex"
```

На сервері Ubuntu запускайте інсталятор від імені root, щоб установити фонову службу; на настільному комп’ютері — від імені звичайного користувача. В Ubuntu інсталятор виводить адресу панелі та ключ доступу; у macOS і Windows локальна панель відкривається в браузері. Далі переходьте до розділу **Підключити Telegram** нижче. У розділі [Встановлення, перевірка та оновлення](../INSTALLATION.md) описано варіанти доступу до сервера, перевірку скрипту перед запуском, оновлення та видалення.

### Інші способи

Релізи на GitHub, вихідний код і Docker — альтернативи інсталятору. Портативні пакети стають доступні після публікації релізної збірки:

| Хост | Без попереднього встановлення | З вихідного коду: Python 3.11+ | Docker: Engine/Desktop з Compose 2.20+ |
| --- | --- | --- | --- |
| Windows | Розпакуйте `TgWitness-<version>-windows-amd64-portable.zip` з GitHub Releases і двічі клацніть `TgWitness.cmd` | Двічі клацніть `Start.cmd` | Двічі клацніть `scripts\Docker.cmd` |
| Linux / macOS | — | `sh start.sh` | `sh scripts/docker-start.sh` |

Для способів із вихідним кодом [завантажте й розпакуйте поточну гілку `main`](https://github.com/phishdestroy/TgWitness/archive/refs/heads/main.zip) або клонуйте репозиторій:

```sh
git clone https://github.com/phishdestroy/TgWitness.git
cd TgWitness
```

Якщо відповідного Python не знайдено, `Start.cmd` пропонує встановити Python 3.12 для вашого користувача Windows (через winget або підписаним інсталятором із python.org). Якщо Python відсутній, `start.sh` виводить точну команду встановлення для вашого дистрибутива Linux або для macOS. Під час першого запуску з вихідного коду автоматично створюється `.venv` і встановлюються залежності.

Docker збирає додаток і запускає його у фоновому режимі; Python на хості не потрібен. Коли контейнер успішно проходить перевірку стану, `scripts\Docker.cmd` і `scripts/docker-start.sh` виводять адресу панелі та токен. Еквівалентні команди Docker для будь-якого підтримуваного хоста:

```sh
docker compose up -d --build --wait
docker compose exec tgwitness cat /data/panel-token.txt
```

Відкрийте **http://127.0.0.1:8787**. Використайте токен, який вивів допоміжний скрипт Docker або друга команда Docker, а для портативної інсталяції чи інсталяції з вихідного коду прочитайте **data/live/panel-token.txt**. Далі переходьте до розділу **Підключити Telegram** нижче. Нативні інсталяції та інсталяції Docker використовують окремі сховища; запуск Docker не імпортує наявний журнал нативної інсталяції.

Для сервера розділ [розгортання](DEPLOYMENT.md) описує автоматичний HTTPS, перезапуск, опубліковані образи, оновлення та резервні копії.

<a name="explore-the-interface"></a>

## Ознайомлення з інтерфейсом

1. Запустіть **TgWitness-Demo.cmd** у портативному пакеті, **scripts\Demo.cmd** у папці з вихідним кодом у Windows або `sh start.sh --demo` у Linux/macOS. Запуск із вихідного коду спершу створює `.venv` і встановлює залежності.
2. Відкрийте **http://127.0.0.1:8787**.
3. Локальна демоверсія автоматично відкриває зразковий журнал. Для прямого локального доступу копіювати токен не потрібно.

Повідомлення в демоверсії вигадані. У демонстраційному режимі неможливо підключити справжній обліковий запис Telegram.

## Підключити Telegram

> [!WARNING]
> **Використовуйте спеціальні облікові записи.** Telegram може обмежити або назавжди заблокувати облікові записи за обсяг запитів, який вважає надмірним, незалежно від клієнта. Підключайте облікові записи, підготовлені для спостереження, а не особисті чи цінні, і створюйте ідентифікатор API та хеш на спеціальному обліковому записі.

1. Якщо працює нативна демоверсія, зупиніть її та запустіть **Start.cmd** або `sh start.sh`. Інакше не зупиняйте робочу інсталяцію, запущену вище.
2. Увійдіть за допомогою токена панелі. У новому робочому просторі відкривається [початкове налаштування](../SETTINGS.md). Виберіть **Просто завантажити**, **Стежити за чатами** або **Докази у справі**.
3. Перегляньте результат перевірки з’єднання. За потреби налаштуйте власний проксі; параметри з’єднання залишаються доступними й після налаштування.
4. На кроці **Підключити Telegram** відскануйте QR-код або введіть номер телефону. Імпорт файлів і повний ключ автентифікації доступні в розділі **Інші способи входу**. Коли з’явиться запит, підтвердьте вхід у Telegram, введіть код і пароль двоетапної перевірки.
5. Перевірте показаний обліковий запис, виберіть чати й перегляньте налаштування. Завершіть на останньому екрані. У режимі **Просто завантажити** кнопка **Почати експорт** запускає одноразовий експорт і відкриває розділ «Експорт», де видно його перебіг; безперервного спостереження вона не вмикає.

Після налаштування вибрані чати можна змінити в **Чати → Виберіть**. **Налаштування** керують збором і файлами; **Інші інструменти → Джерела** містить докладний список джерел на рівні «Стандартний» або «Експертний». [Посібник з панелі](../PANEL.md) описує шість основних розділів і їхні контекстні елементи керування.

Поле **Ідентифікатор API + хеш** необов’язкове: робочий простір використовує збережену або імпортовану пару чи робочу пару з вбудованого пулу. Щоб використати власний додаток, вставте одну пару `API ID:API Hash` у поле «Ідентифікатор API». Для способу **Ключ автентифікації** вставте всі 512 шістнадцяткових символів і виберіть наданий разом із ключем DC ID. Ідентифікатор користувача необов’язковий; якщо його введено, він перевіряється.

Облікові дані API ідентифікують ваш додаток; самі по собі вони не авторизують обліковий запис. Приватним групам не потрібне публічне ім’я користувача, але ваш обліковий запис повинен мати до них доступ.

Для наявних облікових записів див. [облікові записи та формати сесій](../ACCOUNTS.md): панель приймає Telethon StringSession, Telethon/Pyrogram SQLite, ZIP-архів TData з одним обліковим записом і JSON-файли облікових записів підтримуваного формату. Виберіть сесію разом із супровідним JSON і натисніть **Підключити обліковий запис**. Вхід за QR-кодом також доступний із тими самими необов’язковими параметрами API. TDLib, сесії ботів і списки облікових записів у CSV/JSON не підтримуються.

Щоб додати кілька облікових записів, скористайтеся **Облікові записи → Імпортувати облікові записи** й виберіть їхні файли сесій підтримуваного формату. Супровідні JSON-файли зіставляються за базовим ім’ям файлу; кожен імпортований обліковий запис отримує власний робочий простір. Див. [масовий імпорт і групи облікових записів](../ACCOUNTS.md#bulk-import-and-account-groups).

Щоб додати ще один обліковий запис, натисніть **+** поруч із перемикачем облікових записів або скористайтеся **Облікові записи → Додати обліковий запис**. Робочі простори мають окремі сесії, журнали, ключі, джерела й черги. Перемикання між робочими просторами в панелі не зупиняє інші колектори. Один і той самий обліковий запис Telegram не можна призначити двом робочим просторам у цій інсталяції. Фіксованої кількості робочих просторів немає; вони працюють в одному процесі, тож їхня можлива кількість залежить від комп’ютера.

Токен панелі робочої інсталяції захищає доступ до ваших авторизацій Telegram і збережених матеріалів; він не пов’язаний з обліковими даними API Telegram. Автоматичний вхід отримує лише явно запущена локальна демоверсія, до якої звертаються напряму. Віддалена демоверсія або демоверсія за проксі все одно використовує `data/demo/panel-token.txt`.

## Перегляд і експорт

- **Журнал:** пошук і фільтрація спостережень за джерелом і типом події.
- Виберіть подію, щоб переглянути її оригінальний запис, атрибуцію та збережені версії.
- Відомості про редагування показують доступний вміст до і після змін. Відомості про видалення показують останній зафіксований вміст, якщо він є; невідомий виконавець залишається невідомим.
- **Експорт:** підписаний ZIP, JSONL, CSV і офлайн-HTML.
- **Повний експорт чату** (**Чати → Експорт чату** або **Експорт → Зібрати або експортувати один чат**): завантажте всю видиму історію одного чату як підписаний пакет із `chat.json` (у стилі експорту Telegram) і читабельним `chat.html`. Приватні чати теж підтримуються, якщо обліковий запис є їх учасником. Це поточний знімок, а не відновлення видалених чи раніше відредагованих повідомлень. Перевірте копію командою `python verify.py chat-export.zip --fingerprint TRUSTED_SHA256`.
- **Зберегти контрольну точку:** зберігайте межу підписаного журналу поза колектором.
- **Завантажити підписану квитанцію про виконання:** збережіть запис про програму й версію колектора.
- **Підготувати запит на отримання часової мітки:** підготуйте офлайн-запит до центру видачі міток часу; щоб отримати й перевірити відповідь, дотримуйтеся [TIMESTAMP.md](../TIMESTAMP.md).
- **Перевірити журнал:** перевірка підписів подій і зв’язків ланцюжка. Експорт у ZIP також перевіряє медіафайли.

Підтримувані браузери зберігають великі експорти безпосередньо у вибраний файл. Інші браузери буферизують не більше 128 MiB. Поки сервер працює, потоковий CLI дає змогу завантажувати більші обсяги без буферизації всієї відповіді:

```sh
python -m tgwitness.download --token-file data/live/panel-token.txt --out evidence.zip
```

Для іншого робочого простору додайте `--profile ID`, узявши значення з **Експорт → Ідентифікатор робочого простору**. Для віддаленого сервера додайте `--url https://your-server`. Типове обмеження передавання — 5 GiB; його змінює `--max-mib`. Для вмісту підписаного ZIP за замовчуванням діє окреме обмеження перевірки — 4 GiB у розпакованому вигляді (його підвищують у **Інші інструменти → Параметри**; такі архіви перевіряйте командою `verify.py --max-gib N`). Перевіряйте архів довіреною копією верифікатора, незалежно збереженим відбитком ключа, а для мінімальних вимог щодо доказів — ще й кореневим сертифікатом центру видачі міток часу (`--tsa-ca`).

## Перевірка інсталяції

```sh
python start.py --setup-only
python start.py --check
python start.py --check --json
```

Параметр `--check` перевіряє локальні залежності, підтримку підпису, сховище, конфігурацію ключів і адресу прослуховування. Він нічого не встановлює й не підключається до Telegram. Зайнятий порт може означати, що вже працює інший екземпляр. Укажіть інший `--port` або спершу зупиніть той екземпляр.

Програма запуску встановлює все в `.venv`. Допоміжні команди `python -m tgwitness...` слід запускати через `.venv\Scripts\python.exe` у Windows або `.venv/bin/python` у Linux/macOS, якщо це середовище ще не активовано.

## Сесії, захист і робота

Закритий і цілісний файл SQLite-сесії Telethon `.session` можна локально перетворити командою `python -m tgwitness.sessions account.session --out account.tgwitness-session`, а потім завантажити в **Інші інструменти → Обліковий запис → Файли**. Також доступні прямий імпорт файлу та вхід за QR-кодом. Формати входу, SOCKS5, HTTP CONNECT, MTProxy і зовнішні головні ключі описано в [CONNECTION-SECURITY.md](../CONNECTION-SECURITY.md).

**Призупинити спостереження** зупиняє збір. **Блокування** лише закриває доступ із браузера. Закриття вкладки не зупиняє процес колектора. Зупинка процесу перериває збір; знімок історії не може відтворити всі пропущені редагування чи видалення. Політики подій, черги вкладень, ізоляцію облікових записів і поведінку під час перезапуску описано в розділі [як працює збір](../COLLECTION.md).

Сесії та секрети зашифровано. Для вмісту повідомлень, медіафайлів і експортів потрібен зашифрований диск або том. Перевіряйте підписи журналу за довіреним ключем і зберігайте контрольні точки окремо. Переглядайте записи про збір, зовнішні квитанції часу та атестації середовища для вибраного режиму збору.

Про резервне копіювання й відновлення читайте в [OPERATIONS.md](../OPERATIONS.md), про хостинг — у [DEPLOYMENT.md](DEPLOYMENT.md), приклади служб наведено в [deploy/](../../deploy/README.md). Встановлена панель також містить офлайн-посібник із налаштування за адресою `/guide.html`.

Фактично виконані перевірки та обмеження, що залишаються, зафіксовано у [VERIFICATION.md](../VERIFICATION.md) і [READINESS.md](../internal/READINESS.md).
