# TgWitness त्वरित आरंभ

TgWitness एक स्वतंत्र एप्लिकेशन है जो आपके खातों द्वारा पहुँच योग्य टेलीग्राम समूहों और चैनलों का अवलोकन करने के लिए है। यह अपने स्वयं के डेटा निर्देशिका के साथ स्थानीय रूप से चलता है।

**पहली बार आ रहे हैं?** खाता कनेक्ट करने से पहले [डेमो देखें](#इटरफस-क-अनवषण-कर)। प्रॉक्सी, विटनेस, एक्सपोर्ट या सर्वर सेटअप के लिए [एक गाइड चुनें](../README.md)।

## इंस्टॉल करें और शुरू करें

एक विधि चुनें। पोर्टेबल डाउनलोड तब उपलब्ध होते हैं जब एक रिलीज़ बिल्ड प्रकाशित हो जाता है:

| होस्ट | कुछ भी स्थापित नहीं | स्रोत से: पाइथन 3.11+ | Docker: Engine/Desktop Compose 2.20+ के साथ |
| --- | --- | --- | --- |
| विंडोज | GitHub रिलीज़ से `TgWitness-<version>-windows-amd64-portable.zip` निकालें, `TgWitness.cmd` पर डबल-क्लिक करें | `Start.cmd` पर डबल-क्लिक करें | `scripts\Docker.cmd` पर डबल-क्लिक करें |
| लिनक्स / मैकओएस | — | `sh start.sh` | `sh scripts/docker-start.sh` |

सोर्स मेथड्स के लिए, GitHub रिलीज़ से सोर्स ZIP डाउनलोड और एक्सट्रेक्ट करें या रिपॉजिटरी क्लोन करें। `Start.cmd` आपके Windows यूज़र के लिए Python 3.12 इंस्टॉल करने का विकल्प देता है यदि कोई उपयुक्त Python नहीं मिलता (winget, या signed python.org इंस्टॉलर)। `start.sh` आपके Linux डिस्ट्रीब्यूशन या macOS के लिए सटीक इंस्टॉल कमांड प्रिंट करता है यदि Python मौजूद नहीं है। पहला स्रोत लॉन्च `.venv` बनाता है और निर्भरताएँ स्वचालित रूप से इंस्टॉल करता है।

Docker एप्लिकेशन का निर्माण करता है और इसे पृष्ठभूमि में शुरू करता है; होस्ट Python अनावश्यक है। `scripts\Docker.cmd` और `scripts/docker-start.sh` कंटेनर स्वस्थ होने पर पैनल का पता और टोकन प्रिंट करते हैं। प्रत्येक समर्थित होस्ट पर समकक्ष Docker कमांड हैं:

```sh
docker compose up -d --build --wait
docker compose exec tgwitness cat /data/panel-token.txt
```

**http://127.0.0.1:8787** खोलें। Docker हेल्पर या दूसरी Docker कमांड द्वारा प्रिंट किए गए टोकन का उपयोग करें, या पोर्टेबल या सोर्स इंस्टॉलेशन के लिए **data/live/panel-token.txt** पढ़ें। नीचे **'Connect Telegram**' पर जारी रखें। नेटिव और Docker इंस्टॉलेशन अलग-अलग स्टोरेज का उपयोग करते हैं; Docker शुरू करने से मौजूदा नेटिव जर्नल आयात नहीं होता।

सर्वर के लिए, [डिप्लॉयमेंट](DEPLOYMENT.md) में स्वचालित HTTPS, पुनरारंभ, प्रकाशित छवियाँ, अपडेट और बैकअप शामिल हैं।

## इंटरफ़ेस का अन्वेषण करें

1. पोर्टेबल पैकेज में **TgWitness-Demo.cmd** चलाएँ, Windows स्रोत फ़ोल्डर में **scripts\Demo.cmd** चलाएँ, या Linux/macOS पर `sh start.sh --demo` चलाएँ। एक स्रोत लॉन्च पहले `.venv` बनाता है और निर्भरताएँ स्थापित करता है।
2. **http://127.0.0.1:8787** खोलें।
3. स्थानीय डेमो स्वचालित रूप से नमूना जर्नल खोलता है। सीधे स्थानीय पहुँच के लिए टोकन कॉपी की आवश्यकता नहीं है।

डेमो संदेश काल्पनिक हैं। डेमो मोड वास्तविक टेलीग्राम खाते से कनेक्ट नहीं कर सकता।

## टेलीग्राम कनेक्ट करें

> [!WARNING]
> **ऐसी कोई भी चीज़ न उपयोग करें जिसे आप खोने का जोखिम नहीं उठा सकते।** हम व्यक्तिगत या मूल्यवान खातों को जोड़ने और उस खाते पर API ID/हैश बनाने के खिलाफ दृढ़ता से सलाह देते हैं जिसे आप महत्व देते हैं। टेलीग्राम अनिश्चित रूप से और अक्सर स्थायी रूप से खातों पर प्रतिबंध लगाता है, चाहे क्लाइंट कोई भी हो। एक सुचारू परीक्षण रन टेलीग्राम पर निर्भर करता है, TgWitness पर नहीं, और भविष्य के लिए कोई गारंटी नहीं देता।

1. यदि नेटिव डेमो चल रहा है, तो उसे रोकें और **Start.cmd** या `sh start.sh` चलाएँ। अन्यथा, ऊपर चल रही लाइव इंस्टॉलेशन को चालू रखें।
2. पैनल खोलने के लिए अपने इंस्टॉलेशन तरीके के लिए पैनल टोकन का उपयोग करें।
3. यदि आपको प्रॉक्सी की आवश्यकता है, तो इसे **Account → Settings → Connection settings → Change connection route** में सहेजें।
4. **खाते** में अपना फ़ोन नंबर दर्ज करें और **जारी रखें** दबाएँ, **QR कोड → QR कोड दिखाएँ** चुनें, या फ़ाइलें चुनें और **खाता कनेक्ट करें** दबाएँ। **API ID + हैश** वैकल्पिक है: कार्यक्षेत्र अपनी सहेजी या आयात की गई जोड़ी, या अंतर्निहित पूल से एक कार्यशील जोड़ी का उपयोग करता है। अपना ऐप उपयोग करने के लिए, API ID में एक `API ID:API Hash` पेयर पेस्ट करें। एक पूर्ण ऑथराइज़ेशन कुंजी के लिए, **Auth key** चुनें, सभी 512 हेक्साडेसिमल अक्षर पेस्ट करें, और दिए गए DC ID का चयन करें। यूज़र आईडी वैकल्पिक है और दर्ज करने पर जाँची जाती है।
5. अपनी चुनी हुई साइन-इन विधि पूरी करें: फोन/कोड/2FA, QR के लिए साइन-इन किए गए Telegram ऐप से पुष्टि, या समर्थित अधिकृत सत्र आयात।
6. प्रदर्शित खाता आईडी की जाँच करें। ओपन **सोर्सेस**: आपकी चैट्स स्वचालित रूप से लोड होती हैं; अपने समूह जोड़ें।
7. **'किस परिवर्तन को संरक्षित किया जाए**' के अंतर्गत, इवेंट श्रेणियाँ या **'संदेश, संपादन और हटाने'** प्रीसेट चुनें, फिर मॉनिटरिंग सेटिंग्स सहेजें।
8. संलग्नक सेटिंग्स को अलग से चुनें, फिर **अवलोकन शुरू करें पर** क्लिक करें।

API क्रेडेंशियल आपके एप्लिकेशन की पहचान करते हैं; वे स्वयं किसी खाते को अधिकृत नहीं करते। निजी समूहों को सार्वजनिक उपयोगकर्ता नाम की आवश्यकता नहीं होती, लेकिन आपके खाते को पहुँच होनी चाहिए।

मौजूदा खातों के लिए, [खातों और सत्र प्रारूपों को](../ACCOUNTS.md) देखें: पैनल Telethon StringSession, Telethon/Pyrogram SQLite, एकल-खाता TData ZIP, और समर्थित खाता JSON स्वीकार करता है। एक सत्र और उसके साथी JSON को एक साथ चुनें, फिर **'खाता कनेक्ट करें**' दबाएँ। समान वैकल्पिक API सेटिंग्स के साथ QR लॉगिन भी उपलब्ध है। TDLib, बॉट्स, और थोक खाता सूचियाँ समर्थित नहीं हैं।

एक और खाता जोड़ने के लिए, खाता चयनकर्ता के बगल में **+** दबाएँ या **Account → Settings → Connection settings → Workspaces** खोलें, या **Accounts** का उपयोग करें। वर्कस्पेस के अलग-अलग सत्र, जर्नल, कुंजी, स्रोत और कतारें होती हैं। दृश्य बदलने पर अन्य कलेक्टर चलते रहते हैं। इस इंस्टॉलेशन में एक ही टेलीग्राम खाते को दो वर्कस्पेस में असाइन नहीं किया जा सकता। वर्कस्पेस की कोई निश्चित संख्या नहीं है; वे एक ही प्रक्रिया साझा करते हैं, इसलिए क्षमता मशीन पर निर्भर करती है।

लाइव पैनल टोकन आपके टेलीग्राम अधिकृत अनुमतियों और सहेजे गए सामग्री तक पहुंच की सुरक्षा करता है; यह टेलीग्राम API क्रेडेंशियल्स से अलग है। केवल स्पष्ट रूप से शुरू किया गया, सीधे एक्सेस किया गया स्थानीय डेमो ही स्वचालित रूप से प्रवेश पाता है। एक रिमोट/प्रॉक्सी डेमो अभी भी `data/demo/panel-token.txt` का उपयोग करता है।

## समीक्षा और निर्यात

- **जर्नल:** स्रोत और घटना प्रकार के अनुसार अवलोकनों को खोजें और फ़िल्टर करें।
- किसी घटना का चयन करें ताकि आप उसके मूल रिकॉर्ड, श्रेय और सहेजे गए संस्करणों की जाँच कर सकें।
- संपादन विवरण उपलब्ध पहले/बाद की सामग्री दिखाते हैं। हटाने के विवरण, यदि कोई हो, अंतिम कैप्चर की गई सामग्री दिखाते हैं; एक अज्ञात कर्ता अज्ञात बना रहता है।
- **निर्यात:** हस्ताक्षरित ZIP, JSONL, CSV और ऑफ़लाइन HTML।
- **पूर्ण चैट एक्सपोर्ट** (Sources → Full chat export): किसी एक चैट का पूरा दृश्यमान इतिहास एक हस्ताक्षरित बंडल के रूप में डाउनलोड करें, जिसमें `chat.json` (Telegram-export शैली) और एक पठनीय `chat.html` शामिल है। निजी चैट तब काम करती हैं जब खाता सदस्य हो। यह एक वर्तमान स्नैपशॉट है, न कि हटाए गए या पहले संपादित संदेशों का पुनर्निर्माण। `python verify.py chat-export.zip --fingerprint TRUSTED_SHA256` के साथ एक प्रति की पुष्टि करें।
- **चेकपॉइंट सहेजें:** हस्ताक्षरित जर्नल सीमा को कलेक्टर के बाहर रखें।
- **हस्ताक्षरित रन रसीद डाउनलोड करें:** कलेक्टर के प्रोग्राम/संस्करण रिकॉर्ड को संरक्षित करें।
- **टाइमस्टैम्प अनुरोध तैयार करें:** टाइमस्टैम्प प्राधिकरण के लिए एक ऑफ़लाइन अनुरोध तैयार करें; प्रतिक्रिया प्राप्त करने और सत्यापित करने के लिए [TIMESTAMP.md का](../TIMESTAMP.md) पालन करें।
- **जर्नल सत्यापित करें:** इवेंट सिग्नेचर और चेन लिंक जांचें। ZIP एक्सपोर्ट मीडिया भी जांचता है।

समर्थित ब्राउज़र बड़े एक्सपोर्ट्स को सीधे चुनी गई फ़ाइल में सहेजते हैं। अन्य ब्राउज़र अधिकतम 128 MiB तक बफ़र करते हैं। जब सर्वर चल रहा हो, तो स्ट्रीमिंग CLI पूरे रिस्पॉन्स को बफ़र किए बिना बड़े डाउनलोड्स का समर्थन करता है:

```sh
python -m tgwitness.download --token-file data/live/panel-token.txt --out evidence.zip
```

दूसरे वर्कस्पेस के लिए, **एक्सपोर्ट्स → वर्कस्पेस आईडी** का उपयोग करके `--profile ID` जोड़ें। रिमोट सर्वर के लिए, `--url https://your-server` जोड़ें। डिफ़ॉल्ट ट्रांसफर सीमा 5 जीबी है; `--max-mib` इसे बदलता है। हस्ताक्षरित ZIP सामग्री की डिफ़ॉल्ट रूप से एक अलग 4 GiB की बिना-संपीड़ित सत्यापन सीमा होती है (**Parameters** इसे बढ़ाता है; ऐसे आर्काइव्स को `verify.py --max-gib N` से सत्यापित करें)। आर्काइव को सत्यापनकर्ता की एक विश्वसनीय प्रति और स्वतंत्र रूप से संरक्षित कुंजी फिंगरप्रिंट/चेकपॉइंट का उपयोग करके सत्यापित करें।

## स्थापना की जाँच करें

```sh
python start.py --setup-only
python start.py --check
python start.py --check --json
```

`--check` स्थानीय निर्भरताओं, हस्ताक्षर समर्थन, भंडारण, कुंजी कॉन्फ़िगरेशन और लिसनिंग एड्रेस की जांच करता है। यह कुछ भी इंस्टॉल नहीं करता और टेलीग्राम से कनेक्ट नहीं होता। व्यस्त पोर्ट का मतलब हो सकता है कि कोई अन्य इंस्टेंस चल रहा है। एक अलग `--port` का उपयोग करें या पहले इसे बंद कर दें।

लॉन्चर `.venv` में इंस्टॉल होता है। सहायक `python -m tgwitness...` कमांड्स को Windows पर `.venv\Scripts\python.exe` और Linux/macOS पर `.venv/bin/python` का उपयोग करना चाहिए, जब तक कि वह वातावरण पहले से सक्रिय न हो।

## सत्र, सुरक्षा और संचालन

एक बंद, सुसंगत Telethon SQLite `.session` को स्थानीय रूप से `python -m tgwitness.sessions account.session --out account.tgwitness-session` के साथ परिवर्तित किया जा सकता है, फिर Account में लोड किया जा सकता है। डायरेक्ट फ़ाइल इम्पोर्ट और QR लॉगिन भी उपलब्ध हैं। लॉगिन प्रारूपों, SOCKS5, HTTP CONNECT, MTProxy और बाहरी मास्टर कुंजियों के लिए [CONNECTION-SECURITY.md](../CONNECTION-SECURITY.md) देखें।

**पॉज़ ऑब्ज़र्वेशन** संग्रह को रोकता है। **लॉक** केवल ब्राउज़र एक्सेस को बंद करता है। टैब बंद करने पर कलेक्टर प्रक्रिया चलती रहती है। प्रक्रिया को रोकने से संग्रह बाधित होता है; एक इतिहास स्नैपशॉट सभी छूटी हुई संपादनों या हटाई गई वस्तुओं को पुनर्स्थापित नहीं कर सकता। इवेंट नीतियों, अटैचमेंट क्यूज़, खाता पृथक्करण, और पुनरारंभ व्यवहार के लिए [संग्रह कैसे काम करता है](../COLLECTION.md), देखें।

सत्र और रहस्य एन्क्रिप्ट किए गए हैं। संदेश सामग्री, मीडिया और एक्सपोर्ट्स के लिए एक एन्क्रिप्टेड डिस्क या वॉल्यूम की आवश्यकता होती है। हस्ताक्षर एक विश्वसनीय कुंजी के सापेक्ष अखंडता स्थापित करते हैं; वे टेलीग्राम उत्पत्ति की पुष्टि नहीं करते और न ही कलेक्टर और उसकी कुंजी को नियंत्रित करने वाले ऑपरेटर द्वारा जालसाजी को रोकते हैं।
