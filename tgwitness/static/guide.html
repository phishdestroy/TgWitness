API ID and API hash are optional

Your own API ID and API hash are optional. When no pair is entered, imported or saved in the workspace, TgWitness picks one from a built-in pool of public pairs and tries the next if Telegram refuses it. API settings identify the application; they do not replace account authorization. The TgWitness panel token opens the panel and is separate from Telegram login.

Open Account and select Phone, QR code, Files, or Auth key. To use your own application, open API ID + Hash in the form and enter its credentials. You can paste one app_id:app_hash pair into API ID. This workspace reuses its saved pair or falls back to the built-in pool.

Supported formats

Phone number, code, and optional two-step verification
Sign in directly in Account. Telegram chooses how the code is delivered; SMS is not guaranteed.
QR login
Select QR code, press Show QR code and confirm in an already-authorized Telegram app under Settings → Devices → Link Desktop Device. Enter two-step verification if requested. Expired codes can be regenerated.
Telethon StringSession
Paste an authorized session string or load a plain-text .tgwitness-session or .txt file, up to 4 KiB.
Telethon SQLite .session
Load a closed, consistent schema 7/8 file directly. The optional Telethon-only CLI converter also accepts files up to 64 MiB.
Pyrogram SQLite .session
Load a schema 2/3 production user session. The panel detects its contents; renaming a file is not conversion.
Telegram Desktop TData ZIP
Quit Telegram Desktop, then ZIP only key_datas and the 16-character file ending in s beside it (usually D877F783D5D3EF8Cs) from the tdata folder; the whole folder with its cache is usually too large. Supply the Desktop local passcode if one is set. One account per archive; legacy layouts, multi-account folders, and encrypted ZIP containers are unsupported.
Session + JSON pair
Accounts are often supplied as name.session plus name.json. Select both together: the JSON supplies app_id/app_hash; other fields such as phone, device or a stored 2FA password are ignored, and TgWitness asks for 2FA when Telegram requires it.
Account JSON
Supported fields include api_id/app_id, api_hash/app_hash, Telethon StringSession, or complete 512-character Auth Key HEX with dc_id. A companion JSON may contain only API metadata; load it with a session or use phone/QR login.
Other formats
TDLib, Pyrogram StringSession, CSV/JSON bulk account lists, and bots are unsupported. Add each account in its own workspace.

Files: what to select and how they are checked

In Files, choose one session format: Telethon/Pyrogram .session, TData ZIP, or Telethon StringSession text. Add its companion JSON if supplied; you do not need every session format. Select up to four matching files, totaling at most 8 MiB, then press Connect account. Use Passcode or session text for a protected TData archive or a session string. Conversion runs in memory on your own TgWitness server without saving uploads, extracting ZIPs, or contacting a conversion service. The Connect button then checks the account with Telegram. To read files without authorization, use Passcode or session text → Read files without signing in. Conflicting files are rejected; imported user IDs are checked online.

JSON is limited to one object of 64 KiB. TData ZIPs are limited to 512 entries and 32 MiB expanded size, with 64 KiB authorization files. Close the original SQLite client and create a consistent copy; do not discard an unfinished WAL to bypass validation.

I only have an API ID and API Hash

Enter them under API ID + Hash, then sign in with your phone number and login code, scan a QR code with an already-signed-in Telegram app, or import a session. API credentials identify your application; they do not provide access to an account by themselves.

I have an Auth Key (HEX) and DC ID

Select Auth key, paste the complete key, and choose the supplied DC ID (1–5). Optionally enter User ID to check the account identity. Your own API ID and Hash are optional. Press Connect account. An Auth Key contains 512 hexadecimal characters; an API Hash contains 32. Shortened keys containing ... cannot work.

You can also save an account JSON with the fields below and select it in Files, replacing the example values with your own:

{
  "auth_key": "REPLACE_WITH_ALL_512_HEXADECIMAL_CHARACTERS",
  "dc_id": 2
}

Replace the example DC ID with the supplied value, from 1 to 5. An optional numeric user_id is checked during authorization. Keep this JSON private; it grants account access. A JSON containing only app_id and app_hash supplies app settings and still needs a session or phone/QR login.

A session grants account access. Keep original and converted files private. Conversion transfers authorization, not message history, and cannot restore a revoked login.

I have a .session file or TData ZIP

Load supported Telethon/Pyrogram SQLite or TData ZIP directly with its optional JSON companion. A separate API pair is optional; imported or saved settings take precedence over the built-in pool. For an offline Telethon-only conversion, close its original client and use a consistent copy:

python -m tgwitness.sessions account.session --out account.tgwitness-session

The result grants account access. Do not run concurrent clients using cloned authorizations. QR attempts are cancelled by lock, workspace switch, route change, or a new login; a closed/reloaded tab may leave an attempt pending until expiry.

  1. Choose the workspace and scope. Each workspace belongs to one Telegram account and has its own sources, settings, journal, queue, and signing key. Add as many workspaces as you need.

  2. Save the collection policy. Select new messages, edits, deletions, reactions, and membership events as needed. Settings apply to the workspace's selected sources. Re-enabling a category does not recover missed events.

  3. Start observation. Updates from the active account client become separate signed records. An edit adds a version; a deletion notice does not erase text already captured. Unknown editors and deletion actors stay unknown.

  4. Review outcomes and gaps. Attachments download separately when enabled. A queued attachment is not yet preserved. An explicit history snapshot saves current visible messages and cannot reconstruct missed changes.

Service events, pausing and the panel token

Operational records and other group service events remain separate from the event switches. Captured messages can retain embedded reaction or membership metadata. Some deletion notices do not identify a chat; they are saved as unscoped account-level notices without guessing a source.

Pause observation stops that collector. Lock and closing a tab do not stop collection; switching workspaces only changes the view. Stopping the Python process stops all workspaces. After a restart, observation resumes and asks Telegram for the updates missed while it was off.

One panel token controls every workspace. Account separation is not a separate-user permission system. An existing journal cannot be reassigned to another Telegram account.

Proxy formats, public lists and testing

Each workspace supports Direct, SOCKS5, HTTP CONNECT and experimental MTProxy. MTProxy accepts a 16-byte hex key or dd + key. Fake TLS ee secrets are unsupported. Stored proxy passwords/secrets are never returned to the panel.

Public MTProxy lists are included. Open Account → Settings → Connection settings → Change connection route, choose a server and save it. Update public lists downloads fresh addresses while keeping your selected route.

Open Where the list comes from for providers, saved dates and the download route. Unavailable sources keep their previous entries. You can also enter your own proxy or use an operator catalog.

A failed proxy does not trigger a direct fallback. Pause observation before changing routes; saving cancels unfinished login. Test Telegram connection can run before sign-in; it checks transport, not complete update delivery.

This configures the Telegram client, not a system VPN. Remote access to the web panel needs HTTPS or an SSH tunnel.

  1. Download

    Exports provides ZIP, JSONL, CSV, HTML, a checkpoint and a signed run receipt. Exports cover a full journal prefix for the selected workspace, regardless of search filters.

    Browsers with file-streaming support ask you to choose a destination first and write data as it arrives. Other browsers buffer at most 128 MiB. For larger files, use the streaming CLI while the server is running:

    python -m tgwitness.download --token-file data/live/panel-token.txt --out evidence.zip
    Other workspaces, remote servers and limits

    For another workspace, add --profile PROFILE_ID. The ID appears at the top of Exports → Workspace ID. See all command options with:

    python -m tgwitness.download --help

    The token is sent in an HTTP header, not in the URL or command arguments. For a remote server, add --url https://your-server. The default transfer limit is 5 GiB, configurable with --max-mib. Signed ZIP content has a separate 4 GiB uncompressed limit. Existing output files are not overwritten.

  2. Verify

    Verify using a trusted copy of the program:

    python -m tgwitness.verify evidence.zip --fingerprint TRUSTED_SHA256 --checkpoint checkpoint.json

  3. Keep the fingerprint

    A signature establishes integrity relative to the trusted key, not Telegram origin. Retain the fingerprint and checkpoint independently. An RFC 3161 request alone is not a trusted timestamp; obtain and verify the authority's reply.

Never delete or replace vault.key: you would lose access to sessions and signing keys.

  • Vault mode

    Storage protection shows the vault mode. Sessions and secrets are encrypted. Messages, attachments and exports require protected storage such as an encrypted disk/volume. An evidence ZIP is not an encrypted application backup.

  • External master key

    New installations may use an external master key through TGWITNESS_VAULT_KEY_FILE. Do not delete vault.key or replace an existing installation's key: doing so can destroy access to sessions and signing keys.

  • Backups

    For backup, stop the process cleanly and preserve the whole data directory, all workspaces and required keys. Temporary exports use each workspace's temporary-exports/; interrupted export files are cleaned on the next startup.

Troubleshoot startup

Three commands answer most startup questions.

From the project directory, run:

$ python start.py --setup-only
$ python start.py --check
[PASS] python · fastapi · telethon · cryptography
[PASS] signing_backend: Ed25519 sign/verify available
[PASS] storage: Write probe passed
[PASS] listen_address: Address and port available at check time
Ready to attempt startup.
$ python start.py

  • What the check tests

    The check tests dependencies, signing support, disk writes, the address/port and key configuration without Telegram login. An occupied port may mean another instance is running. Choose another --port or stop the previous process.

  • Commands need the project environment

    Auxiliary python -m tgwitness… commands need the project environment: replace python with .venv\Scripts\python.exe on Windows or .venv/bin/python on Linux/macOS, or activate .venv first.

  • Pause, lock and downtime

    Pause observation stops collection. Lock only closes browser access. Closing the tab does not stop the process. Events may be missed during downtime; a current-history snapshot cannot reconstruct every deletion or intermediate edit.

  • Server deployment

    Server examples are included under deploy/, with full instructions in docs/DEPLOYMENT.md. Platform qualification and live Telegram acceptance are documented separately; TgWitness does not guarantee universal compatibility or complete capture.

What does the bot actually prove?

A retained signed check lets you compare a later export with the journal as it was observed. It does not establish that every Telegram event was delivered. Unavailable checks and failed posts need attention; there is no guarantee of uninterrupted publication.

Launch commands and a minimal configuration

Install TgWitness on the monitor host. Create read-only access in step 1 of the bot setup and save it as account-a-token.txt next to proof.json. A bot and channel are not required for the public page.

Copy the collector address from step 2 of the bot setup and its signing-key fingerprint from Exports. For another host, use a reachable HTTPS address, keeping any /profiles/ID suffix. Replace both placeholders below.

{
  "title": "Collection pilot",
  "data_dir": "./proof-data",
  "interval": 5,
  "workspaces": [{
    "id": "account-a",
    "label": "Account A",
    "collector": "REPLACE_WITH_COLLECTOR_ADDRESS",
    "collector_fingerprint": "REPLACE_WITH_COLLECTOR_FINGERPRINT",
    "token_file": "account-a-token.txt"
  }]
}

Add one workspace entry per account, with its own token, address and fingerprint. Use the Python environment where TgWitness is installed.

python -m tgwitness.proof --config proof.json --check-config
python -m tgwitness.proof --config proof.json

The first command validates the files without connecting. The second starts the monitor on 127.0.0.1:8790. Put this read-only service behind your HTTPS reverse proxy and keep the collector's control panel private.

Source downloads include compose.proof.yaml and deploy/proof.config.example for Docker, plus the complete deployment and verification instructions in docs/PROOF.md.

For a real delivery check, send, edit and delete a unique test message from a separate account in a controlled test group, then compare the signed exports. Counters alone do not demonstrate complete capture.
