MCP тільки для читання

Підключіть клієнт MCP до вибраних робочих просторів та чатів із тимчасовим, відкличним доступом.

Поточна основна версія: використовуйте репозиторій з вихідним кодом; портативна попередня версія 0.7.0 не підтримує цю функцію.

Посібник з організації робочого процесу · Вікі

Встановіть додатковий сервер із каталогу проєкту TgWitness:

python -m pip install '.[mcp]'

У панелі відкрийте «Інтеграції» → «MCP». Назвіть з’єднання, виберіть його робочі простори та чати, а також вкажіть термін дії. Скопіюйте архівний токен один раз; його неможливо відновити пізніше. Анулюйте втрачені токени та видайте замінні. Токени панелі та облікові дані Telegram не є обліковими даними MCP.

Підключити клієнта#

Панель генерує .vscode/mcp.json для локального модуля VS Code, використовуючи його задокументовану конфігурацію. Збережіть завантажений файл у цій папці, запустіть MCP: List Servers та запустіть TgWitness. VS Code запросить токен через вікно введення пароля. Завантажений файл JSON містить посилання на запит, а не сам токен. Використовуйте виконуваний файл Python із середовища, де встановлено додаток MCP.

Для інших клієнтів stdio виконайте:

python -m tgwitness.mcp_server --api-url http://127.0.0.1:8787

Встановіть TGWITNESS_ARCHIVE_TOKEN у захищеному середовищі клієнта. Не вказуйте його у аргументах команд або URL-адресах. Міст зчитує дані через авторизований API архіву панелі; він не має прямого доступу до бази даних. Stdout передає лише повідомлення MCP.

Для віддалених клієнтів запустіть службу поруч із панеллю:

python -m tgwitness.mcp_server --transport streamable-http \
  --api-url http://127.0.0.1:8787 --port 8766 \
  --public-url https://archive.example.org/mcp

Перенаправте /mcp через зворотний проксі HTTPS на 127.0.0.1:8766/mcp, зберігаючи заголовок Authorization: Bearer …. Вимкніть реєстрацію заголовків авторизації та тіл запитів/відповідей. Здійснюйте підключення за межі loopback лише за потреби, використовуючи --host та --public-url. Кінцева точка використовує Streamable HTTP з офіційного MCP Python SDK. Він підтримує явно налаштовані облікові дані носія, а не виявлення OAuth; клієнти, які потребують виключно OAuth, не підтримуються.

Перевірка протоколу та доступ ініціалізують справжній клієнт MCP та відображають список інструментів. Ця процедура не завантажує повідомлення. Для віддаленої перевірки обраний сервер MCP отримує токен архіву. Налаштовуйте лише той сервер, яким ви керуєте або якому довіряєте в цьому контексті.

Сфера застосування та результати#

Доступні інструменти: list_workspaces, list_chats, search_messages, get_message_versions, get_message_context, get_journal_event та get_capture_status. Немає інструментів для виконання дій у Telegram, зміни конфігурації або масового експорту. При кожному прочитанні відбувається повторна перевірка доступу до робочого простору/чату; облікові дані, термін дії яких закінчився або які було скасовано, перестають діяти. Обмеження становлять 60 запитів до API на хвилину на один обліковий запис, 50 записів на сторінку, відповідь розміром 64 Кбайт та восьмисекундний ліміт часу на відповідь API.

Результати пошуку повідомлень містять робочу область, ідентифікатори чату/повідомлення, послідовність подій, збережений хеш, а також посилання на панель. Користувач, який відкриває посилання, повинен мати власну авторизовану сесію панелі. Необроблені об’єкти Telegram, хеші доступу, посилання на файли, матеріали сесії та ключі не відображаються. Пошук здійснюється за текстом повідомлення, а не за необробленими полями. Текст є обмеженим, а урізання позначається. Редагування, повідомлення Telegram про видалення та missing_on_recheck залишаються окремими спостереженнями. Доступ у межах чату не дозволяє бачити операційні події в масштабі робочого простору; статус запису явно позначає це обмеження.

Текст архіву є ненадійним вхідним даними. Інструкції всередині повідомлень не надають додаткових повноважень і не повинні розглядатися як інструкції клієнта. Зовнішня модель штучного інтелекту може отримувати будь-який вміст, який запитує її клієнт MCP. Доступ лише для читання запобігає змінам в архіві; він не заважає клієнту зберігати дані, які він зчитує.

Хеші ідентифікують збережені записи та забезпечують перевірку цілісності. Вони не доказують самостійно авторство у Telegram або те, що кожне повідомлення було зафіксовано.
