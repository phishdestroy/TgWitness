الحسابات وتنسيقات الجلسات

قم بتسجيل الدخول عبر الهاتف أو رمز الاستجابة السريعة (QR) أو مفتاح المصادقة، واستورد جلسات Telethon أو Pyrogram أو Telegram Desktop، وقم بتشغيل عدة حسابات.

TgWitness / التوثيق · Getting started

تقوم TgWitness بتسجيل الدخول كحساب مستخدم Telegram (وليس كروبوت) عبر بروتوكول MTProto، باستخدام Telethon. ويوجد كل حساب في مساحة عمل خاصة به (تُسمى «مساحة العمل» في واجهة برمجة التطبيقات وأدوات سطر الأوامر) مع جلسة عمل ومصادر وسجل ومفتاح توقيع خاص به.

ملفات الجلسة وسلاسل الجلسة ومفاتيح المصادقة هي تفويضات للحساب: فمن يمتلك أيًا منها يمكنه التصرف بصفته صاحب ذلك الحساب. ولا تحتوي هذه العناصر على سجل الرسائل.

[!تحذير] لا تستخدم أي شيء لا يمكنك تحمل خسارته. ننصح بشدة بعدم ربط حسابات شخصية أو حسابات قيّمة بأي شكل آخر، وكذلك بعدم إنشاء معرّف API / تجزئة API على حساب تقدّره. لا يتعلق الأمر هنا بعدم اختبار TgWitness: فـ Telegram يقيد و يحظر الحسابات بشكل دائم وبطريقة غير متوقعة — وذلك بسبب حجم الطلبات الذي يعتبره مفرطًا، بغض النظر عن العميل أو الغرض، ودون توثيق كافٍ. العديد من حالات الحظر لا رجعة فيها. استخدم حسابات مخصصة. تعتمد سلاسة عمليات الاختبار على Telegram، وليس على البرنامج، ولا تضمن أي شيء في المستقبل.

قبل البدء: معرّف واجهة برمجة التطبيقات (API ID) وتجزئة واجهة برمجة التطبيقات (API hash)#

You can sign in without creating a Telegram API application. When no pair is entered, imported or already saved in the workspace, TgWitness picks a pair from its built-in pool of 50 public API pairs (tgwitness/api_pool.py), preferring Telegram Desktop for a fresh login and retaining a saved pair first; remaining candidates are shuffled. If Telegram refuses a pair (API_ID_INVALID, API_ID_PUBLISHED_FLOOD, UPDATE_APP_TO_LOGIN), the next one is tried, up to eight per sign-in; refused pairs are skipped until restart. The pair that signed in is saved with the account and reused for it. An API ID and API hash identify the application to Telegram; they do not authorize an account by themselves.

Missing connection fields use a deterministic device/OS pair from the bundled opentele2 2.0.0 catalogs: Desktop 2040, Android 6, Android X 21724, iOS 10840, macOS 2834, and Web 2496. Android's source-build ID 4 also uses the Android catalog, as identified in Telegram Android's BuildVars. Web defaults to A; an imported K app-version suffix or macos language pack selects K, and version 0.7.0 selects Webogram. Unknown application IDs keep Telethon's host defaults. Imported fields always win, including an older app version and an empty language pack. The catalog never changes the API ID/hash. Its version snapshot is reviewed explicitly, not fetched during login. A saved profile stays stable after updates.

account.getAuthorizations reports Telegram's saved authorization metadata; it is not an echo of each new initConnection. Compare it with the actual sent profile. Connecting an existing authorization does not validate its companion API hash: initConnection sends the API ID, while the hash is used by login requests.

After a new phone or QR authorization, TgWitness requests config, nearest DC, online status, languages (when the language pack is nonempty), app updates and terms-of-service updates, with 0.3–1.5 seconds between requests. Updating status briefly marks the account online. This sequence runs once at login completion, not on imports, reconnects or restarts. The authorization is saved first; a failed request stops the sequence without retrying or discarding the login. Results are recorded as account.initialized, with error names rather than response bodies. The sequence is not a guarantee against account restrictions.

For tdesktop, a missing tz_offset uses the server's local UTC offset, rounded to 900 seconds using the opentele2 algorithm (MIT; license in tgwitness/client_profiles.LICENSE). It is refreshed on each connection so daylight-saving changes are reflected. An imported tz_offset takes precedence on every platform and is kept exactly, including zero. Other initConnection.params entries are retained. The HTTP sign-in form accepts the numeric timezone returned by file import; booleans, fractions and offsets outside the supported range are rejected.

Direct, SOCKS5 and HTTP CONNECT routes use Telethon's ConnectionTcpObfuscated (obfuscated abridged MTProto). HTTPS CONNECT retains TLS to the proxy and uses the same obfuscated transport inside the tunnel. MTProxy retains its required randomized intermediate transport and secret handling. Route switches apply the same choices. Obfuscation changes packet framing; it does not hide the account or its client metadata from Telegram or imply immunity to restrictions.

After connecting an authorized client, TgWitness checks config, nearest DC, the current authorization, the reviewed layer baseline, languages, app updates and terms-of-service updates. These diagnostics run once per client instance, before collection, and are shown under the connection details with their time. account.connection_checked records the result without session hashes, IPs, tokens or API hashes. They never accept terms or install updates. A request failure or FloodWait stops subsequent requests; a missing result stays unknown. Local checks can still report their results while network checks are skipped.

FloodWait diagnostics retain the failed TL method, any Takeout/range wrappers, the server-requested wait and the effective deadline in telegram.backoff. Connection details show the method and deadline while requests are paused. The diagnostic includes per-method client-call counters since that client was created; they count nested peer resolution separately, but do not count packets or Telethon's internal retry attempts. Current counters are also available as collector.rpc_activity in the status API. No request arguments, usernames, access hashes or exception text are included. The last diagnostic and full deadline survive restart. Earlier waits without a method record cannot be attributed retrospectively. See export limits for the source review and the distinction between discovery and history acquisition.

official_app=True or False is Telegram's current-authorization flag. Neither value establishes whether the account is restricted, trusted or under observation. The existing evidence-mode account.devices snapshots remain the history of all signed-in devices; connection diagnostics retain only the current device description.

Before connection, advisory checks compare the API platform, language pack, device/OS and app-version formats, mobile system locale, and Telethon's actual schema layer against the reviewed catalog baseline. Warnings appear in the server log and account status metadata; they never replace imported values or change the schema layer. A different layer is a compatibility review signal, not proof of a broken or restricted account. These checks and official_app do not certify that Telegram considers the account safe from restrictions. Disconnected account status uses the saved profile instead of generating another device description.

لاستخدام تطبيقك الخاص بدلاً من ذلك (الحساب الذي يسجله هو الذي يتعرض للخطر؛ انظر: لماذا توجد مجموعة واجهات برمجة تطبيقات (API) مدمجة؟):

  1. افتح my.telegram.org وقم بتسجيل الدخول باستخدام أي رقم هاتف تمتلكه. سيصل الرمز إلى تطبيق Telegram، وليس عبر رسالة SMS.
  2. اختر أدوات تطوير واجهة برمجة التطبيقات (API).
  3. إنشاء تطبيق: أي عنوان واسم مختصر (5–32 حرفًا)، منصة سطح المكتب. يمكن ترك حقل عنوان URL والوصف فارغين.
  4. انسخ معرّف التطبيق (api_id) (رقم) وتجزئة التطبيق (api_hash) (32 حرفًا سداسي عشري).

في اللوحة، يوجد «معرف API المفتوح + التجزئة» أسفل نموذج تسجيل الدخول. يمكنك لصق زوج واحد من api_id:api_hash في حقل «معرف API» ليتم ملء كلا الحقلين تلقائيًا. يمكن استخدام زوج واحد لجميع حساباتك. بعد تسجيل الدخول بنجاح، يتم حفظ البيانات مشفرة في مساحة العمل تلك فقط ولا يتم إرسالها أبدًا إلى المتصفح.

رقم الهاتف#

  1. افتح حسابًا، ثم انتقل إلى علامة التبويب «الهاتف»، وأدخل الرقم بالصيغة الدولية، على سبيل المثال +44 7700 900123. تتم إزالة المسافات والشرطات تلقائيًا.
  2. اضغط على «متابعة». يمكن ترك حقل «معرف API» و«التجزئة» فارغين.
  3. أدخل الرمز الذي يرسله Telegram (عادةً إلى تطبيق Telegram؛ ولا يُضمن وصوله عبر الرسائل القصيرة).
  4. إذا كان الحساب مزودًا بالتحقق بخطوتين، فأدخل كلمة المرور تلك. فهي ليست رمز اللوحة ولا رمز مرور الجهاز.
  5. تحقق من معرّف الحساب الذي يظهر بعد تسجيل الدخول، ثم اختر المصادر.

لا يتم أبدًا تسجيل رموز تسجيل الدخول وكلمة مرور المصادقة الثنائية (2FA) على القرص.

رمز الاستجابة السريعة (QR)#

استخدم هذه الميزة عندما يكون الحساب مسجلاً بالفعل على هاتف أو جهاز كمبيوتر آخر.

  1. انقر على رمز QR → اعرض رمز QR. يمكن ترك حقل معرّف API + التجزئة فارغًا.
  2. على الجهاز الذي قمت بتسجيل الدخول إليه: الإعدادات → الأجهزة → ربط جهاز سطح المكتب، امسح الرمز ضوئيًّا ثم قم بالتأكيد.
  3. أدخل كلمة مرور المصادقة الثنائية (2FA) في TgWitness إذا طلبها Telegram.

يتم إنشاء صورة رمز الاستجابة السريعة (QR) محليًّا. تنتهي صلاحية الرموز؛ اضغط على «إنشاء رمز QR آخر » لإعادة المحاولة. يؤدي قفل اللوحة أو التبديل بين مساحات العمل أو بدء عملية تسجيل دخول أخرى إلى إلغاء الرمز المعلق.

مفتاح المصادقة + معرّف DC#

مفتاح المصادقة (Auth Key) هو مفتاح المصادقة الخام المكون من 256 بايت الذي يقف وراء كل جلسة Telegram، ويُكتب على شكل 512 حرفًا سداسي عشريًّا، إلى جانب رقم مركز البيانات DC 1–5.

  1. مفتاح المصادقة في علامة التبويب. الصق المفتاح كاملاً؛ فالمفتاح المختصر الذي يحتوي على … لا يعمل.
  2. اختر معرّف DC المرفق مع المفتاح.
  3. يمكنك إدخال معرّف المستخدم اختياريًّا. عندئذٍ يرفض TgWitness الاتصال إذا أبلغ Telegram عن حساب مختلف.
  4. حساب Press Connect.

مفتاح المصادقة (512 حرفًا) ليس تجزئة واجهة برمجة التطبيقات (API) (32 حرفًا). يمكن أيضًا استيراد المفتاح نفسه بتنسيق JSON، انظر JSON الحساب.

ملفات الحسابات#

افتح «إضافة حساب» → «الملفات» واختر ما يصل إلى أربعة ملفات تابعة لحساب واحد، بحد أقصى 8 ميغابايت، ثم اضغط على «ربط الحساب».

The Files, Auth key and bulk-import forms show the parallel-session warning before connecting. By default imported authorizations are reused. Keep the original client closed while its key is in use here. Files and Auth key also offer Create an independent authorization, described below. Bulk import still uses the direct mode. Phone and interactive QR login create separate authorizations. The warning heading stays visible in the import form; its full explanation opens automatically when files or a key/session string are supplied. It can be collapsed after reading, so the file picker and connection controls remain usable on a phone.

  • يتم تحويل الملفات في الذاكرة على خادم TgWitness الخاص بك. لا يتم تخزين الملفات التي يتم تحميلها، ولا يتم استخراج ملفات ZIP إلى القرص، ولا يتم الاتصال بأي خدمة خارجية.
  • ثم يتم التحقق من الجلسة الناتجة مع Telegram. إذا كان الملف يحتوي على معرّف مستخدم، فيجب أن يتطابق مع الحساب الذي يبلغ عنه Telegram.
  • يتم رفض الملفات التي تصف حسابات مختلفة أو بيانات اعتماد API مختلفة بدلاً من اختيار واحدة منها.
  • يحتوي حقل «رمز المرور» أو «نص الجلسة» على حقل «TData local passcode»، وهو مربع مخصص للصق ملفات StringSession وRead دون تسجيل الدخول (يملأ النموذج دون الاتصال بـ Telegram).

Create an independent authorization#

Select Create an independent authorization before connecting imported files or an Auth Key. TgWitness connects the imported donor briefly, uses it to approve the new client's QR login token, and disconnects the donor immediately after approval. The new client has its own authorization key and a separately selected Desktop profile. The donor's supplied API credentials and device profile are used only for the donor connection. No existing authorization is logged out or revoked.

Keep the donor's original client fully closed during this step. The initial connection still uses its copied key, so this mode cannot remove that initial parallel-use risk. Once the new authorization is connected, the owner can reopen the original client and use both independently. Interactive QR code login lets the original client approve the login without copying or connecting its key here.

If Telegram requests 2FA, this mode uses twoFA from the selected JSON when present, or asks for the password. A rejected imported password returns to the password form. Passwords are not saved. The candidate key is saved encrypted in independent_login.enc, including changes during data-centre migration. After an interruption, select the same donor and this option to resume the saved candidate. The workspace remains reserved for that account; failed completion does not delete the new workspace. Keep its data directory and vault key. The final credentials and account.authorized journal record include the import method, input formats and donor API ID, without the donor key or password.

On 5 November 2026, a dedicated account passed live checks with Telethon, Pyrogram and TData donors: 2FA completion, distinct new authorization keys, concurrent access by the donor and new client, and reading a public channel. The Telethon case also resumed a saved candidate after an interruption at the password step. Each new authorization completed the six post-login initialization requests, and its signed journal verified. The original session remained usable in all four supplied formats.

Telegram's RPC error database associates FRESH_CHANGE_ADMINS_FORBIDDEN with changing admins, FRESH_CHANGE_PHONE_FORBIDDEN with changing the phone number, and FRESH_RESET_AUTHORISATION_FORBIDDEN with revoking other sessions, changing their lifetime or registering a passkey. SESSION_TOO_FRESH_* and PASSWORD_TOO_FRESH_* concern ownership transfers and revenue or gift withdrawals. These are not collection operations; a new login does not imply a blanket 24-hour reading ban. Export can separately return TAKEOUT_INIT_DELAY_*. TgWitness retains server-requested pauses and does not retry token acceptance automatically or revoke sessions to work around restrictions.

Telethon .session#
ما هي هذه الأداة؟ قاعدة بيانات SQLite التي تنشئها الأدوات القائمة على Telethon، على سبيل المثال my_account.session
معترف بها من قبل الجداول sessions (مع dc_id، server_address، port، auth_key) وversion = 7 أو 8
المتطلبات صف واحد فقط من الجلسات المصرح بها؛ قاعدة بيانات مغلقة وكاملة

أغلق أولاً البرنامج الذي أنشأ الملف. إذا كان my_account.session-journal أو my_account.session-wal موجودًا بجانبه، فهذا يعني أن قاعدة البيانات لم تكتمل بعد: افتح العميل الأصلي وأغلقه بشكل صحيح. قد يؤدي حذف ملفات «sidecar» هذه إلى ترك نسخة تالفة.

Pyrogram .session#
ما هي هذه الأداة؟ قاعدة بيانات SQLite التي تنشئها الأدوات القائمة على Pyrogram
معترف بها من قبل الجدول sessions مع dc_id، auth_key، test_mode، user_id، is_bot؛ version = 2 أو 3
المتطلبات جلسة مستخدم واحدة مصرح بها على شبكة الإنتاج. يتم رفض جلسات الروبوتات وجلسات مراكز البيانات التجريبية

يتم التحقق من معرّف المستخدم المخزّن مقابل Telegram أثناء تسجيل الدخول.

زوج من الجلسة وملف JSON#

غالبًا ما يتم توزيع الحسابات على شكل ملفين يحملان الاسم نفسه، على سبيل المثال 447700900123.session و447700900123.json. حدد كلا الملفين في آن واحد.

  • من ملف JSON، تستخدم TgWitness app_id/api_id وapp_hash/api_hash، لذا لا يتعين عليك عادةً إدخال بيانات اعتماد واجهة برمجة التطبيقات (API).
  • The connection profile uses device_model (alias device), system_version (alias sdk), app_version, lang_code, system_lang_code (alias system_lang_pack), lang_pack and optional tz_offset (seconds from UTC, -43200 to 50400). Supplied fields take priority over generated defaults and the panel/browser language. Conflicting aliases are rejected. The resolved profile is saved in the encrypted workspace credentials and reused after restart, including its app version.
  • phone, proxy settings and device tokens are ignored. twoFA is read only when Create an independent authorization is selected; direct import ignores it.
  • A JSON without a supported authorization field is only metadata. Add its session file or continue with phone or QR login. A JSON containing a supported session or Auth Key can authorize on its own; see Account JSON.

Telegram Desktop (TData)#

TData هو المجلد tdata الخاص بتطبيق Telegram Desktop (التطبيق متعدد المنصات المتوفر على desktop.telegram.org).

النظام الموقع الافتراضي لـ tdata
Windows %APPDATA%\Telegram Desktop\tdata (Telegram المحمول: بجوار Telegram.exe)
Linux ~/.local/share/TelegramDesktop/tdata
macOS ~/Library/Application Support/Telegram Desktop/tdata

لاستيرادها:

Parallel session warning. Direct TData import reuses Telegram Desktop's authorization key. Do not use that key in Desktop and TgWitness simultaneously. Telegram can invalidate the authorization with AUTH_KEY_DUPLICATED, leaving both copies unusable until a new login.

Fully quit Desktop, including its tray process, and keep that copy closed while TgWitness uses the imported session. Quit, do not log out or revoke the session: revocation also invalidates the imported copy. If you need both clients running, select Create an independent authorization and keep Desktop closed until the new login succeeds, or sign in to TgWitness by phone or QR. A dedicated account is recommended, but does not make cloned keys safe to use in parallel.

وينطبق هذا أيضًا على الملفات المستوردة .session والنصوص في StringSession ومفتاح المصادقة HEX. يمكن للعملاء الآخرين الذين لديهم تصاريح تم إنشاؤها بشكل مستقل أن يظلوا مسجلين الدخول. انظر وثائق Telegram الخاصة بـ AUTH_KEY_DUPLICATED.

  1. أغلق تطبيق Telegram Desktop تمامًا.

  2. قم بإنشاء ملف ZIP يحتوي فقط على هذين العنصرين من tdata:

    • key_datas
    • الملف المكون من 16 حرفًا الذي ينتهي بـ «s» بجانبه، وعادةً ما يكون «D877F783D5D3EF8Cs»

    عادةً ما يتجاوز ضغط المجلد بأكمله مع ذاكرة التخزين المؤقتة للوسائط الحدود المسموح بها (512 إدخالًا، 32 ميغابايت بعد فك الضغط). 3. حدد ملف ZIP في قسم «الملفات». إذا كان لدى Telegram Desktop رمز مرور محلي، فأدخله أولاً في حقل «رمز المرور» أو نص الجلسة. هذه ليست كلمة مرور المصادقة الثنائية (2FA).

ميزات مدعومة: حساب واحد لكل أرشيف، تخزين حديث بنظام key_datas/key_data0/key_data1، ورمز مرور محلي. ميزات غير مدعومة: المجلدات التي تحتوي على عدة حسابات مسجلة الدخول، وتصميمات سطح المكتب القديمة، وملفات ZIP المحمية بكلمة مرور، والتطبيق الأصلي المنفصل لنظام macOS «Telegram for macOS».

Telethon StringSession#

سطر واحد من النص، يبدأ عادةً بـ 1 ويبلغ طوله حوالي 350 حرفًا. قم بتحميله كملف .txt أو .tgwitness-session (بحد أقصى 4 كيلوبايت)، أو الصقه تحت «رمز المرور» أو «نص الجلسة». لا تُقبل سوى سلاسل Telethon؛ أما سلاسل Pyrogram وTDLib فتستخدم تنسيقات مختلفة.

حساب JSON#

كائن JSON واحد، بحجم 64 كيلوبايت كحد أقصى، في ملف ينتهي بـ .json.

الحقل (الأسماء المستعارة) المعنى
api_id (app_id) معرّف التطبيق، وهو عدد موجب
api_hash (app_hash) هاش التطبيق، 32 حرفًا سداسي عشريًّا
string_session (session_string, session_str; legacy session) نص Telethon StringSession، وليس اسم ملف
auth_key (auth_key_hex) + dc_id مفتاح المصادقة الكامل المكون من 512 حرفًا وDC 1–5
user_id (id) اختياري؛ تتم المقارنة مع Telegram قبل حفظ التفويض
device_model (device) Connection device description
system_version (sdk) Connection OS version
app_version Application version sent to Telegram
lang_code, system_lang_code (system_lang_pack), lang_pack Client language, system language and client language pack; an empty lang_pack is allowed
tz_offset Optional UTC offset in seconds, sent in initConnection.params; integer or decimal integer string

If both an alias and the main name are present, they must agree. Explicit Telethon session fields take priority over a generic session blob in another format. If both contain recognizable Telethon sessions, they must describe the same authorization. Without an explicit field, session must be a valid Telethon StringSession. Examples:

{ "app_id": 1234567, "app_hash": "0123456789abcdef0123456789abcdef" }
{
  "api_id": 1234567,
  "api_hash": "0123456789abcdef0123456789abcdef",
  "auth_key": "REPLACE_WITH_ALL_512_HEXADECIMAL_CHARACTERS",
  "dc_id": 2,
  "user_id": 123456789
}

المثال الأول يملأ بيانات اعتماد واجهة برمجة التطبيقات (API) فقط؛ قم بتسجيل الدخول عبر الهاتف أو رمز الاستجابة السريعة (QR)، أو أضف ملف جلسة. لا تُقبل القوائم المجمعة (مصفوفة JSON للحسابات).

حسابات متعددة#

اضغط على + بجانب أداة اختيار الحساب، أو افتح الحساب → الإعدادات → إعدادات الاتصال → مساحات العمل، وأدخل تسمية ثم سجّل الدخول.

  • عدد غير محدود من مساحات العمل، بما في ذلك المساحة الرئيسية. لكل منها جلستها الخاصة، ومسار الوكيل ، ومصادرها، وسياسة التسجيل، والسجل، ومفتاح التوقيع، ونقاط التحقق، وعمليات التصدير.
  • لا يؤدي تبديل مساحة العمل المعروضة إلى إيقاف المساحات الأخرى مؤقتًا.
  • يظل السجل مرتبطًا بالحساب الذي أنشأه. ويتطلب تسجيل الدخول بحساب مختلف مساحة عمل أخرى، ولا يمكن تخصيص حساب واحد لمساحتين من مساحات العمل.
  • يتحكم رمز اللوحة الرئيسية في جميع مساحات العمل. ويمكن أن يقصر حق الوصول الممنوح وصول الآخرين على حسابات ومحادثات محددة، مع أذونات منفصلة وحدود للجلسات.
  • تقوم الحسابات بإعادة تسمية مساحة العمل وحذف مساحة العمل المضافة، مع جلستها وسجلها ومصادرها ومفتاح التوقيع الخاص بها. لا يمكن حذف مساحة العمل الرئيسية من اللوحة.

الاستيراد الجماعي ومجموعات الحسابات#

استخدم «الحسابات» → «استيراد الحسابات» لإضافة عدة حسابات، وإقران الملفات حسب الاسم الأساسي والاطلاع على نتيجة كل عملية تسجيل دخول. يحصل كل حساب على مساحة عمل خاصة به.

تجمع المجموعة الحسابات ذات الصلة معًا دون دمج جلساتها أو مفاتيحها أو أدلتها. يؤدي فتح المجموعة في قسم «الحسابات» إلى صفحتها على /groups/<id>:

  • الحسابات: مسار اتصال كل عضو، وملاحظاته، وآخر رسالة له، مع بدء الكل وإيقاف كل شيء مؤقتًا.
  • يحتاج إلى انتباه: الحسابات التي تم تسجيل الخروج منها، أو غير المتاحة، أو التي تعاني من مشكلة في الاتصال أو الاستقبال أو المصدر أو الوسائط؛ كل اسم يؤدي إلى بطاقته.
  • ترى المحادثات عبر عدة حسابات: المصادر المشتركة، والحسابات التي تراقبها، و الانقطاعات في فترة المراقبة المتاحة لمساحة العمل (حتى سبعة أيام). يؤدي التصدير باستخدام N حسابات إلى تقسيم تصدير القناة أو المجموعة الفائقة بينها وتوقيع أرشيف واحد.
  • تصدير المجموعة: صورة واحدة ZIP مع التصدير الموقّع لكل حساب تحت accounts/ و manifest.json مع إدراج بصمات SHA-256 وبصمات المفاتيح الخاصة بها، موقعة من قبل مساحة العمل الرئيسية في manifest.signature.json. تحقق من أرشيف كل حساب على حدة باستخدام python -m tgwitness.verify وبصمة الإصبع الموثوقة لذلك الحساب.

يتشارك الأعضاء إعدادات المجموعة؛ ويمكن للحساب الاحتفاظ بقيمه الخاصة. انظر الإعدادات المشتركة، ودليل الاستيراد والمجموعات ولوحة معلومات المجمع MTProxy.

تسجيل الخروج#

الحساب → تسجيل الخروج من Telegram (مع إيقاف المراقبة مؤقتًا) يطلب من Telegram إنهاء الجلسة، وبالتالي تختفي أيضًا من «الإعدادات» → «الأجهزة» في الحساب، وتُزال الجلسة من خزينة مساحة العمل. ويبقى السجل والمصادر والإعدادات ومفتاح التوقيع، و يسجل السجل عملية تسجيل الخروج. لا تزال مساحة العمل مملوكة لحسابها: ولا يمكن إلا لهذا الحساب الاتصال بها مرة أخرى. إذا لم يستجب Telegram، تُزال الجلسة مع ذلك هنا وتشير اللوحة إلى ذلك؛ قم بإنهائها في Telegram ضمن الإعدادات → الأجهزة.

الحفاظ على أمان ملفات الحسابات#

  • تعامل مع كل .session وملف TData ZIP وStringSession ومفتاح المصادقة وملف JSON الخاص بالحساب كما لو كان كلمة مرور. تحتفظ TgWitness بتفويضات الدخول المستوردة في خزينة مشفرة؛ ويمكنك إزالة الملفات الأصلية بعد ذلك.
  • لا تقم بتشغيل نفس التفويض في برنامجين في آن واحد. فقد يقوم Telegram بإلغائه (AUTH_KEY_DUPLICATED)، وستتوقف النسختان عن العمل.
  • لا يمكن إعادة تنشيط جلسة منتهية الصلاحية أو تم إلغاؤها عن طريق التحويل. يرجى تسجيل الدخول مرة أخرى.

حل المشكلات#

رسالة أم أعراض ما يجب فعله
يتعذر قراءة هذه الجلسة. أغلق العميل الأصلي... ملف SQLite مفتوح أو غير مكتمل (ملف -journal/-wal المرافق). أغلق البرنامج الأصلي بشكل صحيح وانسخ الملف مرة أخرى.
مخططات Telethon SQLite المدعومة: 7 و8 / Pyrogram … 2 و 3 تم إنشاء الملف باستخدام إصدار قديم جدًّا أو غير معروف من المكتبة. قم بتسجيل الدخول عبر الهاتف/رمز الاستجابة السريعة (QR) بدلاً من ذلك.
لا يتم دعم سوى جلسات المستخدمين المصرح لهم بالإنتاج ينتمي ملف Pyrogram إلى روبوت أو إلى شبكة الاختبار.
يتجاوز حجم أرشيف TData 512 إدخالًا أو 32 ميغابايت ملف ZIP يحتوي فقط على key_datas وD877F783D5D3EF8Cs، وليس المجلد بأكمله.
يتعذر فك تشفير TData. تحقق من رمز المرور المحلي لسطح المكتب أدخل رمز المرور المحلي لـ Telegram Desktop في حقل «رمز المرور» أو نص الجلسة.
استيراد حساب TData واحد في كل مرة كان لدى Telegram Desktop عدة حسابات؛ انظر «التنسيقات غير المدعومة».
تصف الملفات المختارة حسابات مختلفة أو بيانات اعتماد واجهة برمجة التطبيقات (API) اختر ملفات حساب واحد فقط.
لا يحتوي ملف JSON على أي بيانات اعتماد أو تفويضات مدعومة لواجهة برمجة التطبيقات (API) تحقق من أسماء الحقول في ملف JSON الخاص بالحساب.
بيانات تعريف واجهة برمجة التطبيقات (API) فقط لا يحتوي ملف JSON على جلسة عمل. أضف الملف .session أو استخدم الهاتف/رمز الاستجابة السريعة (QR).
يجب أن يحتوي مفتاح المصادقة HEX على جميع الأحرف الـ512 السداسية العشرية المفتاح مقطوع أو يحتوي على ….
معرف الحساب لا يتطابق مع الحساب المستورد يختلف معرّف المستخدم الخاص بالملف عما أوردته Telegram؛ فالملف يخص حسابًا آخر.
الحساب مملوك بالفعل لمساحة عمل أخرى افتح مساحة العمل تلك بدلاً من إضافة الحساب مرتين.
متصل، لكن هناك مجموعة خاصة مفقودة من قائمة الدردشات في «المصادر» تحقق من العضوية. يقوم أداة الاختيار بفحص أول 1,000 محادثة؛ قم برفع الحد الأقصى ضمن «المعلمات».
فشل الاتصال عبر الوكيل تحقق من المسار ووضع IP. يحاول الوضع التلقائي MTProxy إدخالًا آخر فعالًا. يظل وضع «إخفاء العنوان» في حالة انتظار؛ أما الوضع «مباشر» (كملاذ أخير) فيمكنه الاتصال مباشرةً بعد انقضاء فترة التأخير المحددة. انظر أوضاع التوجيه.

انظر أيضًا: الاتصال والأمان للوكلاء والتشفير، وكيفية عمل عملية التجميع لما يتم التقاطه بعد تسجيل الدخول.
