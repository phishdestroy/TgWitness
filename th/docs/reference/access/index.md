# การเข้าถึงและสิทธิ์

Canonical page: https://phishdestroy.github.io/TgWitness/th/docs/reference/access/

ให้สิทธิ์ผู้ตรวจสอบเข้าถึงการสนทนาหนึ่งครั้ง ให้สิทธิ์นักวิเคราะห์ส่งออกกรณี หรือ ให้ผู้ดำเนินการควบคุมบัญชีที่เลือกไว้ แต่ละคนจะได้รับโทเค็นของตัวเอง โทเค็นของ แผงควบคุมหลักจะอยู่กับผู้ดูแลระบบ

## สองขอบเขตงาน สองหน้าที่ที่แตกต่างกัน

**ขอบเขตการเก็บ**ข้อมูลกำหนดว่าบัญชีจะบันทึกอะไร: การสนทนาที่เลือกไว้, โฟลเดอร์ Telegram หรือบัญชีทั้งหมด **ขอบเขตการ**เข้าถึงกำหนดว่าบัญชีและ การสนทนาที่บันทึกไว้เหล่านั้น คนอื่นสามารถดูและใช้ได้หรือไม่ การให้สิทธิ์การเข้าถึงไม่ทำให้เข้าร่วม การสนทนา Telegram, ไม่เริ่มการเก็บข้อมูล หรือให้สิทธิ์การเข้าถึงบัญชี Telegram

สิทธิ์การเข้าถึงสามารถเปิดพื้นที่ทำงานที่เลือกไว้, การสนทนาที่เลือกไว้ภายในพื้นที่ทำงานนั้น, ทุก พื้นที่ทำงาน หรือทุก [บัญชีในกลุ่มบัญชีได้](https://phishdestroy.github.io/TgWitness/th/docs/reference/accounts/#bulk-import-and-account-groups) **สิทธิ์การเข้าถึงทุกพื้นที่ทำงาน รวมถึงพื้นที่ทำงานที่เพิ่มเข้ามาภายหลัง** ยังครอบคลุมบัญชีที่จะเพิ่มเข้ามาในอนาคตด้วย สิทธิ์การเข้าถึงกลุ่มยัง ครอบคลุมบัญชีที่เพิ่มเข้ามาในกลุ่มนั้นในภายหลังด้วย ให้เลือกพื้นที่ทำงานอย่างชัดเจนเมื่อ กรณีนั้นควรจำกัดอยู่เฉพาะในพื้นที่ทำงานเหล่านั้นเท่านั้น

## ให้สิทธิ์การเข้าถึงแก่ผู้ใช้

1. ลงชื่อเข้าใช้ในฐานะผู้ดูแลระบบหลัก และเปิดส่วน **Access**
2. ในส่วน **“ให้สิทธิ์เข้าถึงแก่บุคคลใด**บุคคลหนึ่ง” ให้ป้อนชื่อที่คุณจะสามารถระบุได้ในบันทึก
3. เลือกพื้นที่ทำงาน และหากจำเป็น ให้เลือกการสนทนาแต่ละครั้ง
4. เลือกสิ่งที่บุคคลนี้อาจทำได้ โดยตัวเลือก “ดู” จะถูกรวมไว้เสมอ
5. ตั้งระยะเวลาหมดอายุ, ข้อจำกัดการลงชื่อเข้าใช้/เซสชัน และที่อยู่ที่ได้รับอนุญาตตามความต้องการ
6. คลิก "**Create access**" (สร้างสิทธิ์เข้าถึง) คัดลอกโทเค็นทันที: โทเค็นนี้จะแสดงขึ้นเพียงครั้งเดียวเท่านั้น
7. ส่งที่อยู่แผงควบคุมและโทเค็นแบบส่วนตัว ผู้รับจะป้อนโทเค็นนั้น บนหน้าเข้าสู่ระบบปกติ; พวกเขาไม่จำเป็นต้องใช้โทเค็นแผงควบคุมหลักของคุณหรือเซสชัน Telegram ของคุณ

เปิดแผงควบคุมด้วยโทเค็นที่ออกให้ในเซสชันเบราว์เซอร์ที่แยกต่างหาก และตรวจสอบ การสนทนาที่แสดงอยู่และกิจกรรมที่ได้รับอนุญาตก่อนที่จะส่งมอบให้

## เลือกสิทธิ์การเข้าถึง

สำหรับการสาธิตสาธารณะแบบข้อความเท่านั้น ให้ใช้ **Public showcase** แทนการเข้าถึงแบบ reviewer ปกติ มันจะแสดงช่องสาธารณะที่เลือกไว้อย่างชัดเจน การแก้ไขและ การลบที่เก็บไว้ รวมถึงสถิติที่ลงนาม โดยสนามผู้เขียนจะถูกปิดบังและไฟล์จะถูกปิดที่ ขอบเขต API [สร้างและตรวจสอบ showcase](https://phishdestroy.github.io/TgWitness/th/docs/reference/showcase/)

| สิทธิ์ | สิ่งที่เครื่องมือนี้สามารถทำได้ |
| --- | --- |
| `view` | อ่านการสนทนาที่ได้รับอนุญาต ข้อความที่ถูกบันทึก โปรไฟล์ ไฟล์ และบันทึกในสมุดบันทึกที่ผ่านการกรอง ซึ่งถูกรวมไว้เสมอ |
| `export` | สามารถส่งออกประวัติการสนทนาและแฟ้มข้อมูลที่ได้รับอนุญาตได้ การส่งออกหลักฐานของพื้นที่ทำงานทั้งหมดจำเป็นต้องมีสิทธิ์เข้าถึงพื้นที่ทำงานทั้งหมด |
| `sources` | จัดการแหล่งข้อมูล ภาพถ่ายหน้าจอ และการจับภาพโปรไฟล์ การเข้าถึงแบบจำกัดตามแชทสามารถดำเนินการได้เฉพาะในแชทที่ได้รับอนุญาตเท่านั้น ส่วนการค้นพบแหล่งข้อมูลและการตั้งค่าขอบเขตในระดับบัญชีทั้งหมดจะยังคงถูกปิดไว้ |
| `collect` | เริ่มหรือหยุดการทำงานของตัวเก็บข้อมูล ต้องมีสิทธิ์เข้าถึงพื้นที่ทำงานทั้งหมด เนื่องจากการเก็บข้อมูลจะส่งผลต่อบัญชี |
| `interact` | ดำเนินการโต้ตอบ Telegram ที่ได้รับการสนับสนุนภายในขอบเขตการเข้าถึง การเข้าถึงแบบจำกัดการสนทนาไม่สามารถใช้การดูตัวอย่างลิงก์สำหรับบัญชีทั้งหมดได้ |
| `settings` | ปรับการตั้งค่าการเก็บข้อมูล, เวลาบันทึก, การแจ้งเตือน, สำเนาที่เก็บไว้นอกระบบ และพารามิเตอร์ต่างๆ ต้องมีสิทธิ์เข้าถึงพื้นที่ทำงานทั้งหมด |
| `account` | ลงชื่อเข้าหรือออกจาก Telegram และจัดการเส้นทางเชื่อมต่อ ต้องมีสิทธิ์เข้าถึงพื้นที่ทำงานทั้งหมด |
| `board.read` | อ่านบันทึกบน Case Board ได้เฉพาะภายในพื้นที่ทำงานและบทสนทนาที่ได้รับอนุญาตเท่านั้น |
| `board.write` | เพิ่มบุ๊กมาร์ก, การเน้นข้อความ, การตัดส่วนข้อความ, ความคิดเห็น และสถานะการเปิด/ตรวจสอบ นอกจากนี้ยังจำเป็นต้องใช้ `board.read` |
| `board.manage` | จัดการชุดข้อมูล สถานะทีมสุดท้าย และบัตรของผู้เข้าร่วมอื่น ๆ นอกจากนี้ยังต้องการสิทธิ์อ่าน/เขียนบนบอร์ด |

สิทธิ์และขอบเขตจะถูกตรวจสอบร่วมกัน การเลือกสิทธิ์หนึ่งจะไม่เปิด แชทอื่น ๆ หรือปลดล็อกการดำเนินการระดับพื้นที่ทำงาน สำหรับสิทธิ์ที่จำกัดเฉพาะแชท สำหรับการส่งออกแบบขนาน สิทธิ์การเข้าถึงต้องครอบคลุมการสนทนาที่ส่งออกในทุกบัญชี ที่เลือกไว้ สิทธิ์การเข้าถึงที่ออกแล้วไม่สามารถสร้างสิทธิ์การเข้าถึงใหม่ จัดการเซสชัน ของผู้อื่น หรือเปิดคอนโซลผู้ดูแลระบบได้

### สามวิธีตั้งค่าที่มีประโยชน์

| บุคคล | ขอบเขต | สิทธิ์ |
| --- | --- | --- |
| ผู้ตรวจสอบ | การบันทึกการสนทนาในหนึ่งกรณี | `view` |
| นักวิเคราะห์กำลังเตรียมการส่งต่องาน | การสนทนาที่จำเป็นต้องตรวจสอบและส่งออก | `view`, `export`; เพิ่ม `interact` เฉพาะเมื่อจำเป็นต้องดำเนินการผ่าน Telegram |
| ผู้ดำเนินการการเก็บรวบรวมข้อมูล | พื้นที่ทำงานที่เลือกไว้ทั้งหมด | `view`, `sources`, `collect`; เพิ่ม `settings` หรือ `account` เฉพาะเมื่อจำเป็นเท่านั้น |

การตั้งค่าเริ่มต้นของแบบฟอร์ม Access ยังรวมถึง Case Board: ผู้ตรวจสอบสามารถอ่านได้, ผู้วิเคราะห์สามารถอ่าน และเขียนได้, และผู้ดำเนินการสามารถจัดการได้ การตั้งค่าเริ่มต้นยังคงสามารถแก้ไขได้ และสิทธิ์ที่มีอยู่จะไม่ ถูกขยายอัตโนมัติ ดู [Case Board](https://phishdestroy.github.io/TgWitness/th/docs/reference/case-board/) เพื่อทราบขอบเขตการสนทนาที่สืบทอดมาและนโยบายความเป็นส่วนตัวในการส่งออก

## ข้อจำกัดและเซสชัน

| บริบท | วิธีการทำงาน |
| --- | --- |
| เซสชันคู่ขนาน | จำกัดจำนวนเซสชันที่เปิดพร้อมกันไว้ที่ 1–100 เมื่อถึงขีดจำกัด ให้ปฏิเสธการเข้าสู่ระบบครั้งต่อไป หรือปิดเซสชันที่เปิดมานานที่สุด |
| อนุญาตให้เข้าสู่ระบบ | จำกัดจำนวนครั้งการใช้โทเค็นที่สำเร็จเพื่อเริ่มเซสชัน เซสชันที่มีอยู่จะไม่ถูกปิดเพียงเพราะได้ใช้สิทธิ์การเข้าสู่ระบบครั้งสุดท้ายที่ได้รับอนุญาตแล้ว |
| มีผลจนถึง | การเข้าถึงมีวันหมดอายุที่แน่นอน การเข้าถึงที่หมดอายุแล้วไม่สามารถเข้าสู่ระบบหรือส่งคำขอได้อีก |
| ไม่มีกิจกรรมเป็นเวลาหลายนาที | เวลาหมดอายุความไม่ใช้งานของเซสชัน ตั้งแต่อินเทอร์วัล 5 นาที ถึง 30 วัน คำขอที่สำเร็จจะขยายเวลาดังกล่าว; แผงที่เปิดอยู่สามารถรักษาสถานะใช้งานได้โดยการส่งคำขอตรวจสอบเป็นระยะ |
| ที่อยู่อีเมลที่ได้รับอนุญาต | รับที่อยู่ IP หรือซับเน็ต CIDR ที่กำหนดไว้ หากไม่กรอกค่าใด ๆ จะอนุญาตให้ใช้ที่อยู่ใดก็ได้ เว้นแต่มีการเปิดใช้งานการผูกมัดการเข้าสู่ระบบครั้งแรก |
| เชื่อมโยงกับการเข้าสู่ระบบครั้งแรก | การลงชื่อเข้าใช้ที่สำเร็จครั้งแรกจะกำหนดที่อยู่ที่ได้รับอนุญาตสำหรับการเข้าถึงนั้น |

IP คือที่อยู่ของลูกค้าที่แอปพลิเคชันเห็นได้ หากอยู่เบื้องหลัง reverse proxy หรือ tunnel ให้ตรวจสอบที่อยู่แสดงใน "**Open sessions**" ก่อนที่จะใช้กฎ IP: มิฉะนั้น ผู้ใช้หลายคนอาจดูเหมือนใช้ที่อยู่ของ proxy ร่วมกัน

## เปลี่ยนหรือยกเลิกสิทธิ์การเข้าถึง

แก้ไขรายการภายใต้ "**การเข้าถึงที่ได้รับอนุญาต"** เพื่อเปลี่ยนขอบเขต สิทธิ์ หรือข้อจำกัด การเปลี่ยนแปลงขอบเขตและสิทธิ์จะถูกตรวจสอบในคำขอถัดไป รวมถึง คำขอจากเซสชันที่เปิดอยู่แล้ว การเพิกถอนการเข้าถึงจะยุติเซสชันนั้น และทำให้โทเค็นที่ออกไว้ไม่สามารถใช้งานได้ **เซสชันที่เปิดอยู่**ยังช่วยให้ผู้ดูแลระบบ สามารถยุติเซสชันเฉพาะได้โดยไม่ต้องเพิกถอนการเข้าถึงทั้งหมด

สำเนาที่ส่งออกและเก็บรักษาจะยังคงข้อมูลผู้สร้าง พื้นที่ทำงาน ขอบเขตการสนทนา และสิทธิ์ที่จำเป็น สิทธิ์การเข้าถึงที่ได้รับการอนุมัติสามารถแสดงรายการหรือดาวน์โหลดสำเนาของตนเองได้เฉพาะเมื่อสิทธิ์ดังกล่าวยังมีผลอยู่เท่านั้น; สำเนาที่มี Case Board ยังต้องการสิทธิ์ `board.read` ด้วย ผู้ดูแลระบบสามารถเรียกคืนสำเนาทั้งหมดได้ สำเนาเก่าที่ไม่มีข้อมูลเมตาดาต้าและกลุ่มไฟล์นี้สามารถเข้าถึงได้เฉพาะผู้ดูแลระบบเท่านั้น ตั๋วดาวน์โหลด และไฟล์ตอบกลับที่เตรียมไว้จะตรวจสอบสิทธิ์การเข้าถึงอีกครั้งหลังจากเตรียมไฟล์แล้ว ก่อนส่งข้อมูลไบต์ของไฟล์

การเพิกถอนสิทธิ์ไม่สามารถเรียกคืนไฟล์ที่ผู้ใช้อื่นได้ดาวน์โหลดไปแล้วได้ การออกจากระบบ, การล็อกหน้าจอ หรือการปิดเซสชัน จะไม่หยุดการทำงานของตัวเก็บข้อมูลที่กำลังทำงานอยู่

## สิ่งที่ผู้ดูแลระบบสามารถเห็นได้

ผู้ตรวจสอบและนักวิเคราะห์จะได้รับข้อมูลความคืบหน้าของการเก็บข้อมูลโดยไม่รวมจุดปลายทางพร็อกซี, ข้อมูลวินิจฉัยของพูล, เส้นทางเซิร์ฟเวอร์ หรือข้อผิดพลาดการเชื่อมต่อแบบดิบ การวินิจฉัยการเชื่อมต่อ ต้องการสิทธิ์ `account` สำหรับพื้นที่ทำงานทั้งหมด การอ่านการแจ้งเตือน, การคัดลอกนอกไซต์ และการตั้งค่าพารามิเตอร์ ต้องการสิทธิ์ `settings`

สตริงUser-Agent แบบเต็มในเบราว์เซอร์จะไม่ถูกเก็บรักษาในเซสชันการเข้าถึง การอัปเกรด ยังจะลบสตริงเหล่านี้ออกจากแคชเซสชันที่สามารถเปลี่ยนแปลงได้อีกด้วย บันทึกกระบวนการของแผงควบคุมจะปิดบัง ที่อยู่ IP แบบตัวอักษร URL ข้อมูลรับรอง และข้อมูลลับที่มีป้ายกำกับ บันทึกบริการท้องถิ่นและ บันทึกวารสารที่ลงนามไว้ก่อนหน้านี้จะไม่ถูกเขียนทับ กฎการเข้าถึงและ บันทึกการลงชื่อเข้าใช้ที่ลงนามแล้วยังคงใช้ที่อยู่ของไคลเอนต์

### เปลี่ยนกุญแจหลัก

ใช้ **Access → My limits → Reissue administrator key** หรือเรียกใช้ `tgwitness token rotate` จากระบบที่ได้รับการจัดการในขณะที่แผงควบคุมกำลังทำงาน เซสชันเบราว์เซอร์ที่มีอยู่ทั้งหมดจะสิ้นสุดลง รวมถึงเซสชันที่เปิดด้วยโทเค็นของเพื่อนร่วมงาน เบราว์เซอร์ที่ส่งคำขอจะได้รับเซสชันใหม่; บันทึกกุญแจผู้ดูแลระบบใหม่ ก่อนที่จะซ่อนมัน โทเค็นของเพื่อนร่วมงานที่ออกไว้จะยังคงมีผลจนกว่าจะถูกเพิกถอนอย่างแยกต่างหาก การติดตั้งที่ใช้`TGWITNESS_TOKEN` ต้องปรับเปลี่ยนการตั้งค่าสภาพแวดล้อมดังกล่าวและเริ่มต้นใหม่

### ขอบเขตการร้องขอและพร็อกซี

API อนุญาตให้มีคำขอสูงสุด 600 ครั้งต่อนาทีต่อ IP ของลูกค้า หากมีการปฏิเสธ การยืนยันตัวตน 10 ครั้งภายใน 1 นาที จะเริ่มกระบวนการรอคอยแบบทวีคูณ ตั้งแต่ 1 วินาที จนถึง 5 นาที การพยายามที่ล้มเหลวหลังจากช่วงเวลาการรอคอยจะเพิ่มระยะเวลาการรอคอย; หากไม่มีการพยายามที่ล้มเหลวเป็นเวลา 10 นาที กระบวนการเพิ่มระยะเวลาการรอคอยจะถูกรีเซ็ต การปฏิเสธจะส่งคืนรหัสข้อผิดพลาด HTTP 429 และ `Retry-After` ข้อจำกัดถูกเก็บไว้ในหน่วยความจำ และใช้ร่วมกันระหว่างพื้นที่ทำงานในกระบวนการ panel เดียวกัน; การรีสตาร์ทจะล้างข้อจำกัดเหล่านี้ สตรีมสดถูกจำกัดไว้ที่ 4 สตรีมต่อโทเค็น bearer และ 32 สำหรับกระบวนการ panel การเปิดสตรีมยังใช้โควตาคำขอ API ด้วย

ตัวเนื้อหาคำขอมีเวลาจำกัดในการรับ 60 วินาที (8 วินาทีสำหรับ MCP) แต่ละแอปพลิเคชันจะจำกัด ตัวเนื้อหาคำขอที่ยังไม่เสร็จสมบูรณ์ไว้ที่ 32 คำขอ และ 64 MiB ของโควตาเส้นทางที่สำรองไว้ ตัวเนื้อหาคำขอที่เกินขนาดจะส่งคืน รหัส 413 ตัวเนื้อหาคำขอที่หมดเวลาจะส่งคืนรหัส 408 และตัวเนื้อหาคำขอที่เกินความจุจะส่งคืนรหัส 503 พร้อมด้วย`Retry-After`

ส่วนหัว IP ที่ถูกส่งต่อจะถูกเพิกเฉย เว้นแต่คู่ TCP ที่แท้จริงจะอยู่ในกลุ่ม `TGWITNESS_TRUSTED_PROXIES` (IP ที่คั่นด้วยเครื่องหมายจุลภาคหรือ CIDR) ตั้งค่า `TGWITNESS_PROXY_HEADER` เป็น `x-forwarded-for` หรือ `cf-connecting-ip` XFF จะถูกตรวจสอบ จากพร็อกซีที่ใกล้ที่สุดไปยังคู่ที่ยังไม่เชื่อถือได้ตัวแรก ข้อมูลเมตาดาต้าของที่อยู่ที่น่าเชื่อถือ ที่มีรูปแบบผิดหรือซ้ำกันจะถูกปฏิเสธ ดังนั้นจึงไม่สามารถรับช่วงต่อที่อยู่พร็อกซี ที่อยู่ในรายการอนุญาตได้ อุโมงค์ด่วนที่ได้รับการจัดการ เชื่อถือตัวเชื่อมต่อ Cloudflare ท้องถิ่น; การตั้งค่าโดเมนของตัวเองเชื่อถือ Caddy ท้องถิ่น การติดตั้งแบบ Direct ไม่เชื่อถือพร็อกซีโดยค่าเริ่มต้น หากเปิด Uvicorn ด้วยตัวเอง ให้ปิดการประมวลผล proxy-header ของมัน เพื่อให้ขอบเขตนี้รับ peer ที่แท้จริง

`TGWITNESS_PANEL_ALLOWED_IPS` จำกัดการเข้าถึงแผงควบคุมทั้งหมด รวมถึงผู้ดูแลระบบ ให้เฉพาะ IP หรือ CIDR ที่ระบุไว้เท่านั้น การตรวจสอบ routing-identity ของตัวติดตั้งจะยังคงเป็นสาธารณะและ ไม่ส่งข้อมูลบัญชีใดๆ กลับคืนมา ให้รวมเส้นทางบริหารจัดการท้องถิ่นที่จำเป็นก่อน ที่จะเปิดใช้งานรายการอนุญาต (allowlist) คู่มือ **START-HERE** สำหรับการติดตั้งแบบจัดการรวมถึง การตั้งค่าบริการและคำแนะนำในการกู้คืนระบบ

ตัวเลือกรายการค้นหา API `ws` ต้องระบุพื้นที่ทำงาน (workspace) ในเส้นทางคำขอ; ตัวเลือกรายการค้นหาที่ไม่รู้จัก ไม่ตรงกัน หรือซ้ำกัน จะถูกปฏิเสธด้วยรหัส 404.

สคริปต์และสไตล์ของแผงควบคุมมีเมตาข้อมูลความสมบูรณ์ SHA-384 แผนที่การนำเข้ายัง ครอบคลุมโมดูล JS ที่นำเข้าในเครื่องท้องถิ่น สำหรับเบราว์เซอร์ที่สนับสนุนความสมบูรณ์ของ import-map การตอบสนองภาษาที่สร้างขึ้นแบบไดนามิกเป็นสิ่งที่แยกต่างหาก การตรวจสอบเหล่านี้ตรวจจับ การแทนที่สินทรัพย์เมื่อเทียบกับหน้าเว็บที่ส่งมา; แต่ไม่สร้างความเชื่อถือ ในเซิร์ฟเวอร์ที่ถูกบุกรุก ซึ่งสามารถแทนที่ทั้งหน้าเว็บและแฮชของมันได้

**บันทึกตั้งแต่เริ่มต้นนี้**รวมบันทึกกระบวนการกับกิจกรรมในสมุดบันทึกจากทุก พื้นที่ทำงาน: การเข้าสู่ระบบ, การปฏิเสธ, การเปลี่ยนเส้นทาง และการดำเนินการของผู้ใช้ เป็น คอนโซลในหน่วยความจำสำหรับกระบวนการปัจจุบัน ไม่ใช่สำเนาถาวรของทุกข้อความ เหตุการณ์ข้อความที่เกิดขึ้นบ่อยครั้งจะเก็บไว้ในสมุดบันทึกแทนที่จะไปเติมเต็มคอนโซล

การออก เปลี่ยนแปลง และเพิกถอนสิทธิ์การเข้าถึง รวมถึงการเริ่มหรือสิ้นสุดเซสชัน จะสร้าง บันทึกสมุดบันทึก`access.*` ที่ลงนามด้วยเช่นกัน โทเค็นไม่ถูกรวมอยู่ในบันทึกเหล่านั้น โทเค็นที่ออกและข้อมูลรับรองเซสชันจะถูกเก็บรักษาไว้ในรูปแบบแฮชภายในคลังข้อมูลที่เข้ารหัส

****ผู้ดูแลระบบหลักและขอบเขตความเชื่อถือ****

The main panel token remains unrestricted. Browser sign-ins with it create sessions subject to the administrator's configured session limits. Scripts sending the main token directly retain full access and are not counted as browser sessions.

This is application-level access control in one installation. All workspaces share the server process; this is not isolation from the host administrator. Keep the main token, Telegram sessions, signing keys and data directory private. A witness token is a separate checkpoint/health credential, not a panel access token.
