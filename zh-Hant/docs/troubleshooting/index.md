# 找出問題所在

Canonical page: https://phishdestroy.github.io/TgWitness/zh-Hant/docs/troubleshooting/

從症狀著手。逐層檢查。

## 控制面板要求輸入代幣

請使用啟動器顯示的本地檔案中的面板代幣。若使用 Docker，請執行 `docker compose exec tgwitness cat /data/panel-token.txt`。Telegram 登入代碼、BotFather 代幣及唯讀見證代幣各有其用途。

## Telegram 無法連線

開啟連線設定並執行連線檢查。若使用公共代理伺服器，請嘗試其他條目並明確儲存路徑。檢查代理伺服器類型及支援的密鑰格式。刷新公共清單並不會切換帳戶的路徑。

## 已連線，但無新訊息

1. 請確認「觀察」功能正在正確的工作區中執行。
2. 請確認已選取該來源，且該帳戶可查看該來源。
3. 在受控群組中發送一則內容獨特的新訊息，並搜尋該確切文字。
4. 請檢視運作日誌，以確認是否存在中斷、作業延遲或 Telegram 錯誤。

歷史快照與新訊息事件有所不同。靜態來源可在不產生新訊息的情況下進行連線。當完整性至關重要時，請使用受控傳送測試。

## 重啟後出現 FloodWait 或間隔

「FloodWait」表示 Telegram 需要暫停。請等待指定時間並檢視資料收集工作量；重複重新連線並不會解除此限制。儲存的更新狀態有助於在重新啟動後補上進度，但過期的更新及某些中斷時段仍會造成限制。請記錄資料缺口，而非將日誌視為完整。

## 該機器人已設定完成，但尚未發布任何內容

請確認 Witness 程序確實正在運行，該機器人能夠在頻道中發文，且 Witness 能連接到收集器與機器人 API。檢查其日誌以確認是否有發佈失敗的情況。僅僅成功查詢收集器並不能確認頻道發文是否成功。

## GitHub 憑證整合功能在哪裡？

**規劃中。**「額外資訊」部分說明了擬議的分叉與建置驗證工作流程。目前尚無 GitHub 憑證表單，亦無自動驗證機制可確認運行中的安裝環境是否與儲存庫相符。請參閱[當前功能狀態](https://phishdestroy.github.io/TgWitness/zh-Hant/docs/reference/features/)。

回報問題時，請提供版本、作業系統、操作步驟及經遮蔽處理的錯誤訊息。請勿在公開問題中透露會話、憑證、私人訊息及資料目錄等資訊。
