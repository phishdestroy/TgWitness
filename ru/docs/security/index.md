# Безопасность установки

Canonical page: https://phishdestroy.github.io/TgWitness/ru/docs/security/

Что уходит с вашей машины, что открывает каждый секрет и что защищено, а что остаётся на вас.

**127.0.0.1**Адрес панели по умолчанию

**256-битный**случайный токен панели

**0**CDN, аналитика или удалённые шрифты

**Ed25519**подпись на каждой записи

## Где всё хранится

Сборщик, панель и все записи остаются на вашей машине. По умолчанию связь есть только с Telegram, всё остальное включается отдельно.

ВАШ КОМПЬЮТЕР ИЛИ СЕРВЕР

**Панель**127.0.0.1:8787 · токен bearer

**Коллектор**один клиент Telegram на каждое рабочее пространство

КАТАЛОГ ДАННЫХ

**Журнал**SQLite · с цепочкой хешей · подписанный

**СМИ**Файлы, имена которых сформированы на основе SHA-256

**Хранилище**Fernet · сессия, пара API, ключ подписи, прокси

- **Telegram**Всегда · по вашему маршруту

  Тип подключения аккаунта по протоколу MTProto: прямое, SOCKS5, HTTP или MTProxy. Режим «Скрытие IP» ожидает подключения к рабочему прокси-серверу. Для перехода на прямое подключение в качестве резервного варианта требуется режим, явно разрешающий такую возможность.
- **Текст для внешних ресурсов**Необязательно · по умолчанию отключено

  Журнал, файлы и контрольные точки шифруются с помощью алгоритма AES-GCM перед загрузкой в хранилище, совместимое с S3. Ключ хранится у вас; вложения именуются по хэшам с ключом, а не по хэшам их содержимого.
- **Уведомления**Необязательно · по умолчанию отключено

  Указание проблем и количества изменений с указанием названий чатов. Выдержки из сообщений отправляются только в том случае, если вы включите эту функцию.
- **Авторитетный источник временных меток**Необязательно · по умолчанию отключено

  Только хеш SHA-256 подписанной контрольной точки и случайный нонс. Никаких сообщений, никаких имен участников чата.
- **Свидетель**Необязательно · по умолчанию отключено

  С помощью токена, предназначенного только для чтения, извлекает подписанные контрольные точки и счетчики захватов. Инструмент не может читать переписки или изменять настройки.

По умолчанию: с данного компьютера выходит только соединение с Telegram.

Дополнительные места назначения настраиваются для каждого рабочего пространства. Текст сообщений и мультимедийные файлы хранятся в незашифрованном виде в каталоге данных: обеспечьте их защиту с помощью шифрования диска и прав доступа к файлам.

## Что открывает каждая тайна

| Секретно | Где хранится | Какие возможности это открывает | В случае утечки |
| --- | --- | --- | --- |
| **Токен панели** | `panel-token.txt` в папке данных; браузер хранит его для вкладки | Всё во всех пространствах | Остановите TgWitness, удалите `panel-token.txt`, запустите снова — будет новый |
| **Сессия Telegram** | Хранилище, зашифрованное (`credentials.enc`) | Сам аккаунт в Telegram | Завершите сессию в Telegram в разделе *«Настройки» → «Устройства»* |
| **Ключ подписи** | Хранилище, зашифрованное (`signing.enc`) | Подпись записей вашим отпечатком | Контрольные точки в другом месте, свидетель и метки времени по-прежнему показывают, что было раньше |
| **Ключ хранилища** | `vault.key` рядом с данными или внешний мастер-ключ | Хранилище секретов | Считайте, что сессия и ключ подписи тоже утекли |
| **Токен Witness** | На хостинге Witness | Только чтение: контрольные точки и состояние | Удалите его на странице свидетеля и создайте новый |
| **Ключевые фразы для текстов на внешних ресурсах** | Vault; загрузите его один раз для восстановления данных | Внешнюю копию | Тот, у кого есть ещё и бакет, может её расшифровать: считайте копию раскрытой |

## Что охватывают меры защиты

### : освещено

- Изменённая, удалённая или переставленная запись: ломается цепочка хешей или подпись.
- Журнал обрезан или пересобран после того, как вы сохранили контрольную точку в другом месте: точка перестаёт совпадать.
- Подбор токена: 256 случайных бит, сравнение за постоянное время, 15 ошибок в минуту — и адрес блокируется.
- Враждебное содержимое чатов: текст остаётся текстом, не HTML; вложения скачиваются как файлы; панель ничего не грузит с чужих сайтов.
- Украденная папка данных при внешнем ключе хранилища: сессии и ключи остаются зашифрованными.

### Решать вам

- Главный токен может всё. Давайте другим ограниченный доступ, а главный держите при себе.
- Администратор машины может прочитать всё и переподписать журнал. Храните отпечаток и контрольные точки в другом месте.
- Сообщения и медиа TgWitness не шифрует. Шифруйте диск и ограничивайте права.
- Обычный HTTP вне localhost раскрывает токен. Используйте HTTPS или SSH-туннель.
- Подписи не скажут, что было пропущено. Проверяйте охват и доставку на своих аккаунтах и источниках.

[Дайте доступ к делу](https://phishdestroy.github.io/TgWitness/ru/docs/access/) с правами, сроком действия и лимитом сессий.

## Усиление безопасности установки

Выполнено 0 из 8

1. **Используйте отдельный аккаунт Telegram**, никогда не основной.
2. **Держите панель на 127.0.0.1.** Удалённо — только через HTTPS (встроенный Caddy) или SSH-туннель.
3. **Зашифруйте диск** с папкой данных: сообщения и медиа хранятся как есть.
4. **Ограничьте папку данных** служебной учётной записью (0700 в Unix, права папки в Windows).
5. **Храните ключ хранилища отдельно** на серверах: задайте `TGWITNESS_VAULT_KEY_FILE` до первого запуска.
6. **Сохраняйте отпечаток и контрольные точки** на другой системе, запустите свидетеля на другом хосте.
7. **Ни в коем случае не загружайте** ключи `data/`, сеансовые ключи, `panel-token.txt` или ключи хранилища на GitHub или в чат.
8. **Не регистрируйте** заголовки `Authorization` или тела запросов на обратном прокси-сервере.

**Можно ли изменить токен панели без потери данных?**

Да, он только открывает панель. Остановите TgWitness, удалите `panel-token.txt`, запустите снова. Журнал, сессии и ключи останутся. Если задан `TGWITNESS_TOKEN`, используется он, а не файл.

**Почему сообщения не шифруются при хранении?**

Сборщику нужно читать их для поиска, сравнения и экспорта. Ключ на той же машине не остановит того, кто и так может читать эту машину. Шифрование диска защищает украденный диск, права — работающий.

## Сообщить об уязвимости

**Security → Report a vulnerability** на GitHub. Версия, последствия и минимальный пример на вымышленных данных. Никогда не присылайте учётные данные, папки аккаунтов или настоящие доказательства. Если приватные отчёты выключены, откройте issue с просьбой о закрытом канале, без деталей эксплойта.
