# TgWitness: запуск, масштабирование и доказательства

TgWitness — это экспортер данных из Telegram с открытым исходным кодом и рабочая среда для расследований. Установите
его одной командой, подключите аккаунт, выберите чаты и экспортируйте подписанный
архив. Программа также поддерживает временное сбора данных через GitHub Actions и продолжение
расследований с помощью сохраненных правок, отслеживания удалений, поиска и отчетов.

## Начните с той задачи, которая у вас есть

| --- | --- | --- |

| Соберите на временном бегуне | Используйте функцию «Capture» в GitHub Actions, авторизуйтесь в новой сессии и выберите область доступа | Зашифрованный архив с информацией о происхождении рабочего процесса GitHub |

<a id="one-command-installation"></a>
### Установка с помощью одной команды

Установщик включает Python и необходимые зависимости. Загрузка исходного кода, Docker, провайдер ИИ
и независимый свидетель являются дополнительными опциями, а не обязательными условиями для установки.

Linux / macOS:

```sh
curl -fsSL https://get.destroy.tools/install.sh | bash
```

В Windows, в PowerShell или в командной строке:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -Command "irm https://get.destroy.tools/install.ps1 | iex"
```

Откройте панель, подключите свой аккаунт Telegram и выберите область сбора данных.
Установка сама по себе не запускает сбор данных. В [руководстве по установке](INSTALLATION.md)
описаны вопросы локального доступа, серверов, обновлений и проверки загруженной сборки.

Для запуска временного рабочего процесса следуйте инструкциям на странице [GitHub Actions: capture](SEALED-ACTIONS.md). Для этого
рабочего процесса потребуется форк на GitHub, авторизация и пароль к архиву. На странице capture
описаны эти шаги, а также указан допустимое время сеанса до начала запуска. Скачайте
и сохраните полученный архив и файлы для его проверки.

<a id="more-settings-when-the-task-needs-them"></a>
## Дополнительные настройки, если они требуются для выполнения задачи

Для экспорта данных из одного чата требуется учетная запись и выбранная область действия. Длительное наблюдение,
использование нескольких аккаунтов, прокси-серверы, политики вложений, оформление отчетов, доступ рецензентов,
внешние временные метки и хранение данных за пределами системы отвечают различным требованиям к расследованию и
передаче материалов. Настройте эти функции, если они актуальны.

Объем, разрешения и сведение к минимуму количества копий для совместного доступа помогают операторам выбирать, какие данные
собирать и раскрывать. Рекомендации по юрисдикции и настройки отчетов фиксируют
выбранную процедуру и этапы подготовки. См. [экспорт учетной записи](ACCOUNT-EXPORT.md), [доступ](ACCESS.md) и
[настройка отчета](CASE_REPORTS.md).

Приложение работает на выбранном компьютере или сервере. Для базового сбора данных не
требуется ни графический процессор (GPU), ни большой языковой модель (LLM). Для дополнительных функций — OCR, транскрипции и анализа с помощью ИИ — предусмотрены
собственные требования к ресурсам. Размер развертывания следует рассчитывать с учетом частоты обмена сообщениями, вложений,
объема хранимой истории и количества одновременно работающих аккаунтов.

<a id="preserve-the-record-whoever-it-helps"></a>
## Сохраните запись, кому бы она ни помогла

Цель заключается в том, чтобы сохранить наблюдаемые данные, контекст и изменения, независимо от того,
чью точку зрения они подтверждают. Факты могут опровергать собственную версию событий, изложенную
собирателем. Необходимо обеспечить идентифицируемость исходных наблюдений, пропусков в освещении и аналитических выводов,
чтобы другой человек мог оценить тот же материал.

Логика такова: наблюдение, видимое для учетной записи → подписанный журнал → экспорт → проверка
получателем. Сохраненные правки добавляют версии. Наблюдения об удалении сохраняют ранее
зафиксированное содержание. Записи об охвате выявляют известные перерывы. Отчеты и анализ с помощью ИИ
ссылаются на сохраненные источники; интерпретация не становится источником
наблюдения только потому, что она фигурирует в подписанном отчете.

| Проверка достоверности | Что может установить получатель |
| --- | --- |
| Хэши файлов, подписи и цепочка журналов | Предоставленные записи и файлы соответствуют ожидаемому ключу и границе журнала |
| Отдельно сохраненная контрольная точка или свидетель | Архив соответствует ранее сохраненному состоянию журнала |
| Проверенная внешняя метка времени | Указанные байты существовали на момент, соответствующий временной метке, при соблюдении указанных допущений о доверии |
| Подтверждение захвата GitHub | Архив соответствует утвержденному рабочему процессу, версии сборщика и записанному дайджесту |
| Аттестация Intel TDX | Цитата, статус платформы, ожидаемые показатели ОС/приложений, актуальность данных и идентификатор сборщика прошли настроенные проверки |

При подтверждённом сборе данных заверенное коллекционером аутентифицированное соединение Telegram
и его выходные данные привязаны к проверенной среде выполнения. В архиве сохраняются
зафиксированное содержимое и контекст; отчёты и аналитические материалы ссылаются на эти записи.
Используйте этапы проверки, специфичные для данного режима, и доверенные входные данные, приведённые в
[руководстве по доверию](TRUST.md) и [формате доказательств](EVIDENCE.md).

<a id="testing-history-and-duration"></a>
### История тестирования и его продолжительность

Разработка и тестирование TgWitness продолжались около шести месяцев. Сначала были созданы коллектор,
подписанный журнал и верификатор; веб-панель и дополнительные модули
были построены на их основе позже. Этот репозиторий был создан 29 октября 2026 года для
публикации и начался с существующего кода, поэтому его возраст не совпадает с возрастом проекта
([история разработки](QUESTIONS-AND-CHECKS.md#development-history)).
Совокупный объём проведённых тестов составляет порядка 100 миллионов, включая ранние
запуски, сбои, исправления и повторную валидацию. Отдельные запуски, каждый со своей ревизией,
методом и результатом, задокументированы в
[датированных публичных измерениях](QUESTIONS-AND-CHECKS.md#dates-of-the-published-measurements).

<a id="read-capability-status-precisely"></a>
## Точное определение состояния функции чтения

Оцените каждый рабочий процесс с учетом его реализации, опубликованной сборки и записанных
тестов. В настоящее время исходный код имеет метку «preview». Эта метка выпуска сосуществует
с рабочей коллекцией, экспортами, результатами независимой верификации и опубликованными
показателями масштабируемости. Функция в стадии предварительного просмотра и проверенный рабочий процесс могут существовать в одном
приложении; опишите конкретную функцию и приведите доказательства, лежащие в основе оценки.

Используйте вместе [текущие возможности](STATUS.md), [функции и ограничения](PRODUCT.md),
[проверку](VERIFICATION.md) и [журнал изменений](../CHANGELOG.md).
При указании результата указывайте проверенную версию. В снимке измерений от 6 ноября
также сохранены неудачные и пропущенные тесты; они не считаются пройденными.

<a id="readable-by-people-and-ai-tools"></a>
## Удобно для чтения как людьми, так и инструментами искусственного интеллекта

На сайте представлены краткое руководство `llms.txt`, полное руководство на английском языке
`llms-full.txt` и `llms-full.md`, а также версии страниц в формате Markdown. Это
форматы документации, а не требования к ИИ для запуска TgWitness.

Дополнительные функции [MCP](MCP.md) и [доступ из командной строки](CLI.md) позволяют авторизованным инструментам считывать
выбранные сохраненные записи. Содержание сообщений по-прежнему считается недоверенными данными. В сводках следует
указывать источники, проводить разграничение между наблюдаемыми фактами и выводами, а также отражать степень неопределенности.
Полнотекстовый поиск, OCR и результаты работы ИИ не изменяют исходные подписанные наблюдения.
