# 存档分析

Canonical page: https://phishdestroy.github.io/TgWitness/zh/docs/reference/analysis/

搜索已保存的消息、审查 AI 输入内容，并保存附有来源参考信息的分析报告。

[工作流指南](https://phishdestroy.github.io/TgWitness/docs/archive/) · [维基](https://github.com/phishdestroy/TgWitness/blob/main/docs/wiki/Archive-and-Integrations.md)

使用**“日志**”进行不依赖 AI 的本地搜索；[全文搜索](https://phishdestroy.github.io/TgWitness/zh/docs/reference/search/)（预览） 可匹配词形、短语、域名和 @用户名。若要**使用“查询存档”**功能，请先在**“集成**”中 启用并配置提供商。工作区选择器用于选择 账户；表单用于选择聊天记录和观察时间段。 检索在 本地运行。精确短语或域名可缩小检索范围；输入消息 ID 可查询已保存的 版本。查看摘录并打开其日志记录或上下文。 本工具不包含向量数据库，也不支持自动执行 Telegram 操作。

## 服务提供商与同意条款

AI 功能在每个工作区中默认处于禁用状态。仅主管理员可配置 模型、端点、加密 API 密钥、上下文/输出限制、超时及每日 请求配额。密钥绝不会返回至浏览器。若要保留当前密钥，请将密钥字段 留空；如需移除，请明确将其删除。

Ollama 使用其文档中记载的 [`/api/chat` 端点](https://docs.ollama.com/api/chat)， 该端点输出非流式 JSON 数据。其默认地址为 TgWitness 服务器上的 `http://127.0.0.1:11434`。操作员可通过 `TGWITNESS_AI_LOCAL_ENDPOINT` 更改该地址；此地址不受模型控制。请自行安装 所选模型。TgWitness 不会自动下载该模型。

兼容的服务提供商应具备以 `/v1` 结尾的基础 URL，并支持 [聊天内容补全协议](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)： `messages`、JSON 响应模式、`max_completion_tokens` 以及 `choices[0].message.content`。缺少这些字段的服务不予支持。 连接测试会发送合成文本，并计入请求配额。

每次请求均使用工作区配置的外部路由。被封锁的路由或 仅限Telegram的MTProxy将导致错误；系统不会直接重试。若刻意 配置了本地Ollama地址，则允许访问私有目的地。 环回 AI 端点需要工作区配置的“Direct”外部路由；代理路由将在 传输前被拒绝。对于其他私有服务，适用现有的服务器级私有 目标选择加入机制。预览中会显示端点和外部路由， 包括适用的代理主机。更改该路由需要生成新的预览。

生成前，**发送至模型的数据**包含以下请求信息：问题、 已选中的摘录、事件类型、观察时间及覆盖标记。Telegram 会话、原始字段、提供商密钥、附件字节以及完整的日志 均不属于该上下文范围。请取消勾选不需要的来源，然后明确批准 处理。 外部提供商可能会根据其自身的 政策保留提交的内容。本地执行意味着端点位于本地；这并不保证 独立配置的服务会遵循特定行为。

全球范围内最多同时存在两个服务提供商请求，每个 工作区限一个。预览有效期为十分钟，且仅可生成一个响应。 页面会显示提供商报告的令牌数量；只有 在输入和输出费率均已配置的情况下，才会显示成本估算。失败的尝试也会 消耗每日请求配额。自动重试不会消耗额外配额。

## 来源与局限性

检索功能在[全文索引](https://phishdestroy.github.io/TgWitness/zh/docs/reference/search/#ask-the-archive-and-mcp) 构建完成后启用：根据选定聊天记录中包含词形变体的最佳匹配结果进行检索。关于 近期更改或单条消息版本的查询，以及在索引 构建期间的搜索，均采用针对最新记录的有限词汇检索。预览功能会标注 所采用的方法。检索结果最多返回 24 个来源；长文本会在匹配位置处截断。 截断的摘录和不完整的结果集均会标注。该 时间段指**观察时间**，并不意味着 Telegram 历史记录 是完整的。工作区范围内的事件不会在聊天范围的访问中显示。 缺失的数据将被描述为“在可用存档中未找到”。

该模型不接收任何工具。其源 ID 需与所选 记录进行比对验证，哈希值需重新核查，且引用的字符串必须出现在这些记录中。 未知 ID、被修改的引文以及未被引用的主张将导致答案被拒绝。该应用程序 会生成链接；模型生成的 URL 不能用作引用来源。这些检查 旨在验证来源的存在性和引文的准确性，而非推论的真实性。 在依赖推论结果之前，请对照记录进行核查。

## 报告

将经过审核的回答保存为一份独立的分析报告。该报告包含模型 摘要、观察到的时间线、提取的链接和标识符、编辑/删除记录、 覆盖范围限制以及源事件哈希值。同时附有提供商、模型、端点、时间以及 提示词模板版本信息。不会自动合并任何身份信息。

分析师的修订和注释与模型摘要分开存储。报告 保存在加密的衍生文件中，索引位于签名事件流之外； 原始事件和媒体内容不会发生改变。只有所有者或管理员才能 打开报告，且会再次验证源访问权限。 下载同样需要导出 权限。第 1 版不会对报告进行签名，也不暗示模型结论是 经过验证的证据。限制：每个工作区 100 份报告，每份报告 100 次分析师修订 。

有关手动 OCR 和文字转录，请参阅[“媒体处理”](https://phishdestroy.github.io/TgWitness/zh/docs/reference/media-analysis/)。 有关客户端访问，请参阅 [MCP](https://phishdestroy.github.io/TgWitness/zh/docs/reference/mcp/)。
