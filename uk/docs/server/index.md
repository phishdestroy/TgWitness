# Забезпечте його безперебійну роботу

Canonical page: https://phishdestroy.github.io/TgWitness/uk/docs/server/

Тримайте збирач у роботі, а дані — в безпеці під час перезапусків.

## Оберіть спосіб запуску

Нативно: [лаунчер](https://phishdestroy.github.io/TgWitness/uk/docs/start/) плюс шаблони служб у [deploy/](https://github.com/phishdestroy/TgWitness/blob/main/deploy/README.md). Docker, з папки проєкту:

```
docker compose up -d --build --wait
docker compose exec tgwitness cat /data/panel-token.txt
```

Панель слухає localhost:8787. Відкривайте локально або через SSH-тунель, з токеном із другої команди.

## Збережіть весь каталог даних

Нативно: `data/live`. Docker: том `tgwitness-data`. Журнали, сесії й ключі мають зберігатися разом. Підписаний експорт — це доказ, а не резервна копія.

1. Спершу зупиніть збір.
2. Скопіюйте всю папку даних у надійне місце поза хостом.
3. Спробуйте відновити її на окремому встановленні, перш ніж їй довіряти.

## Перевірте після перезапуску

Перевірте простір і ключ, підключення, джерела й те, що нові повідомлення надходять. TgWitness наздоганяє те, що ще зберігає Telegram, а не все, що сталося, поки він був вимкнений.

«Здоровий» контейнер означає, що вебсервер відповідає. Чи працює збір, покажуть тестове повідомлення й свідок.

## Публікуйте лише те, що ви маєте намір опублікувати

HTTPS, томи, оновлення й відновлення — у довіднику з розгортання. Що реально перевірено: [журнал перевірок](https://phishdestroy.github.io/TgWitness/uk/docs/reference/verification/).
