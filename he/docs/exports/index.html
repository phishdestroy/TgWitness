ייצוא ואימות

שתפו תיעוד חתום שמישהו אחר יוכל לאמת.

שמור הפניהייצא ZIP חתוםהנמען מאמת

חדש בתחום החתימות ונקודות הבקרה? שנה רשומה לדוגמה ובדוק אילו בדיקות מזהות אותה.

רוצים לשמור עותק בנפרד מהאוסף? עברו להגדרות S3, נעילת אובייקטים או שחזור מאומת.

שמרו על מקור מידע אמין

יש לשמור את טביעת האצבע של המפתח הציבורי של סביבת העבודה מחוץ לאספן. במהלך האיסוף, יש לשמור נקודות ביקורת חתומות במקום אחר או להשתמש בעד עצמאי. הפניות אלה מאפשרות למקבל לבדוק את המפתח ואת גבול היומן הקודם.

הורד את קובץ ה-ZIP החתום

פתחו את 'ייצוא' וצרו קובץ ZIP של ראיות חתום. הקובץ כולל את יומן סביבת העבודה ואת רשימת הקבצים החתומה. מסנני הלוח אינם מגבילים ייצוא מלא זה של היומן: עיינו בחומר לפני שתשתפו אותו.

הורדות נפרדות בפורמטים HTML ו-CSV שימושיות לקריאה ולניתוח. שמרו את קובץ ה-ZIP החתום כמקור הניתן לאימות; לקובץ ה-HTML או ה-CSV הנפרד אין חתימה עצמאית.

אמת באמצעות עותק מהימן של TgWitness

בסביבת הפרויקט המותקנת, יש להחליף את טביעת האצבע לדוגמה ואת נתיבי הקבצים:

python -m tgwitness.verify evidence.zip --fingerprint TRUSTED_PUBLIC_KEY_SHA256 --checkpoint retained-checkpoint.json

כאשר שתי ההפניות עוברות את הבדיקה, התוצאה מדווחת על key_pinned: true ו-checkpoint_checked: true. שמור את תוצאת האימות יחד עם הארכיון המקורי. נקודת הבדיקה שנשמרה חייבת להיות בגבול הייצוא או לפניו.

הבנת התוצאה

  • אמינות: ההיסטוריה המתועדת והקבצים המיוצאים תואמים לחתימותיהם.
  • הערה קודמת: נקודת ביקורת חיצונית מאפשרת להשוות את הייצוא לקידומת יומן שנשמרה בעבר.
  • ביצוע: בדיקה מבוקרת של שלח → ערוך → מחק, המשווה אירועים ספציפיים לרישום שנאסף.

חתימה תקפה אינה מוכיחה שכל אירוע ב-Telegram אכן התרחש, שהמקור אמר את האמת או שהשעון של האוסף היה מדויק.

הגדרת העותק החיצוני ב-S3

בסביבת העבודה הפועלת שלכם, פתחו את 'ייצוא' → 'עותק מחוץ לאתר'. תכונה אופציונלית זו פועלת עם AWS S3 ושירותים אחרים התואמים ל-S3. היא מעתיקה קטעי יומן, תמונות וקבצים שנשמרו, נקודות ביקורת עם תגובות חותמת הזמן שלהן, וייצוא צ'אטים שהושלמו. כל אובייקט מוצפן באספן באמצעות AES-256-GCM לפני ההעלאה.

ההדגמה המקוונת מציגה את אותם פקדים כאשר האפשרות להעלאת קבצים מושבתת. הזן את פרטי הכניסה לאחסון רק בסביבת העבודה שלך.

הגדרות אחסון ב-Exports → עותק מחוץ לאתר
תחוםמה להזין
נקודת קצהכתובת ה-URL של שירות האחסון, ללא נתיב לתיקייה או פרטי התחברות. דוגמה בדיונית: https://s3.example.invalid.
אזורהאזור הנדרש על ידי הספק שלך. ברירת המחדל של היישום היא us-east-1.
Bucketארכיון קיים שאליו ניתן לגשת. דוגמה בדיונית: example-case-backup.
תיקייה בסלקידומת האובייקט; ברירת המחדל היא tgwitness. היישום מוסיף קידומת הנגזרת מטביעת האצבע של מפתח החתימה של סביבת העבודה הזו.
מזהה מפתח גישה / מפתח גישה סודיהזן את שני פרטי ההזדהות לאחסון יחד. הם נשמרים בכספת סביבת העבודה. השאר את שניהם ריקים בשמירות עתידיות כדי לשמור על הצמד שנשמר.
כתובות בסגנון Pathיש להשתמש ב-endpoint/bucket כאשר האפשרות מופעלת, או ב-bucket.endpoint כאשר האפשרות מושבתת, בהתאם להוראות הספק.
מרווח בין טקסטיםבין 1 ל-1,440 דקות; ברירת המחדל היא 5 דקות. על היישום לפעול כדי לבצע העתקות מתוזמנות.
שמירת נתוני Object Lockימי שמירה ואופן השמירה עבור דלי התומך ב-Object Lock. "אפס ימים" משאיר את הגדרת השמירה המוגדרת כברירת מחדל של הדלי בתוקף.
  1. הזן את היעד ואת פרטי ההזדהות. השאר את האפשרות "שמור עותק מחוץ לאתר" ללא סימון בזמן ההכנה, ולאחר מכן בחר "שמור עותק מחוץ לאתר".
  2. בחר באפשרות "בדוק חיבור". פעולה זו מעלה אובייקט בדיקה מוצפן ובודקת את תגובת האחסון.
  3. בחר באפשרות "הורד מפתח הצפנה". שמור קובץ זה בנפרד מהאספן; הוא נדרש לשחזור.
  4. סמן את תיבת הסימון "שמור עותק מחוץ לאתר" ושמור שוב. בחר "העתק עכשיו" לביצוע ידני, או השאר את לוח הזמנים פועל.

אינו יוצר דלי אחסון. העלאות מתוזמנות נפסקות כאשר היישום נעצר.

בדוק את משך השמירה ואת התקדמות ההעתקה

תחת "אפשרויות נוספות", בחר את מספר ימי השמירה ואת GOVERNANCE או COMPLIANCE כאשר הדלי שלך תומך ב-Object Lock. TgWitness קורא בחזרה את מצב השמירה ואת מועד התפוגה של אובייקט שהועלה. הסטטוס מדווח על אישור, על שמירה חסרה או על כישלון בבדיקה; העלאה מוצלחת כשלעצמה אינה מהווה אישור לשמירה.

הפאנל מדווח על המעבר האחרון, מספר האובייקטים, כמות הבתים שהועברו, גבול היומן שהועתק וכל שגיאה. מדיה מקומית חסרה או ששונתה מדווחת, והפעולה חוזרת על עצמה במעבר הבא. קבצים, נקודות ביקורת וייצוא בתור לאחר אותה מדיה עדיין ניתנים להעתקה.

ההעלאות מתבצעות באמצעות נתיב ה-Direct, SOCKS5 או HTTP של סביבת העבודה. העתקה ל-S3 אינה זמינה דרך MTProxy; היישום אינו עובר לחיבור ישיר כחלופה.

אינו מחייב את הספק לאכוף את "נעילת האובייקט" (Object Lock) אך ורק משום שההעלאה התקבלה.

יש לשמור את מפתח השחזור בנפרד

קובץ ה-JSON שהורדת מכיל את מפתח הפענוח, הגדרות היעד, קידומת אובייקט סביבת העבודה וטביעת האצבע של מפתח החתימה. הוא אינו מכיל את פרטי הגישה ל-S3: לשחזור נדרשים פרטי גישה נפרדים עם הרשאת קריאה לדלי.

אם תשנו את נקודת הקצה, את הדלי או את קידומת התיקייה, הורידו את קובץ המפתח שוב כדי שהגדרות היעד שלו יתאימו. היישום יפעיל עותק חדש של היומן, הקבצים ונקודות הבדיקה השמורים באופן מקומי, ביעד החדש. ייצוא צ'אטים שהושלמו וכבר הוסרו מתור ההעלאה המקומי יישארו ביעדם הקודם.

אינו מבצע: הכלי אינו מפענח את העותק ללא המפתח שיוצא. פרטי הכניסה לאחסון אינם יכולים להחליף מפתח זה.

שחזור ואימות במחשב אחר

השתמש בהתקנה אמינה של TgWitness, בקובץ ה-JSON של המפתח שהורדת, בפרטי הזדהות לאחסון עם גישה לקריאה, ובספריית פלט ריקה. החלף את מחליפי פרטי הזדהות הדמיוניים המופיעים להלן.

Windows PowerShell

$env:TGWITNESS_S3_ACCESS_KEY = 'YOUR_READ_ACCESS_KEY'
$env:TGWITNESS_S3_SECRET_KEY = 'YOUR_READ_SECRET_KEY'
python -m tgwitness.replica restore --key-file tgwitness-replica-key.json --out restored-evidence

Linux / macOS

export TGWITNESS_S3_ACCESS_KEY='YOUR_READ_ACCESS_KEY'
export TGWITNESS_S3_SECRET_KEY='YOUR_READ_SECRET_KEY'
python -m tgwitness.replica restore --key-file tgwitness-replica-key.json --out restored-evidence

הקבצים שהורדו והאובייקטים שהוצפנו נשמרים באחסון זמני פרטי בזמן שבוצעת בדיקה של היומן כולו, נקודות הבדיקה שנשמרו, וכן חתימות ה-hash והגדלים של המדיה שנשמרה. נתיבים לא בטוחים, קטעי יומן סותרים ויומן שקצר מנקודת הבדיקה שלו נדחים. אימות שנכשל אינו מפרסם קבצים משוחזרים.

שחזור מוצלח יניב את events.jsonl, media/, checkpoints/ ו-exports/ עבור החומר הזמין בעותק. שמרו את תוצאת ה-JSON של הפקודה יחד עם החומר ששוחזר.

הכלי אינו משחזר תצפיות שמעולם לא נכללו ביומן, ואינו מחליף נקודת ביקורת או עד שנשמרו באופן עצמאי.
