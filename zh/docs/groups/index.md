# 管理一组账户

Canonical page: https://phishdestroy.github.io/TgWitness/zh/docs/groups/

可同时管理多个采集账户，同时确保每个账户的记录和签名身份保持独立。

账户组将连接状态、监控控制、共享设置和导出功能整合到一个工作视图中。当多个账户涉及同一项调查或需要保持一致的操作设置时，此功能非常有用。

## 打开群组概览

在**“账户**”中，打开群组。每个账户会显示其监控状态、连接路径、最近一次检查成功时测得的路径延迟，以及最后保存的消息。**需关注**链接指向需要处理的账户；**点击“修复**”可打开相关工作区和控制界面。

**“全部开始**”和**“全部暂停**”操作将在确认后对符合条件的账户生效。**“组设置**”可共享选定的设置；具有独立设置值的账户将保留其原有设置，直至您选择替换。

### 审查群组内的路线变更

合成示例 · 说明性检查及结果

1. **选择。**选择群组并查看哪些账户将发生变更。
2. **准备工作。**当需要保持独立时，请保留账户自身的路径。
3. **检查。**测试建议的连接并检查测量结果。
4. **提交。**保存前请重新检查，并审查每个账户的处理结果。

## 在流程中增加一个审核步骤

1. 选择**“更改群组路由**”，然后选择连接类型和设置。
2. 选择**“审查”选项**。审查列出的账户及其各自的路由覆盖设置。
3. 选择**“准备”并执行检查**。该检查使用全新的 Telegram 传输通道；受支持的 HTTP 路由也会报告其 HTTPS 出口检查结果。
4. 选择**“应用已选中的连接**”，并检查每个账户的结果。先前正在运行的监控将在应用成功处继续；处于空闲状态的账户仍保持空闲。

延迟描述了测得的 Telegram 连接建立情况。出口 IP 检查描述了在记录的检查时间点该路由的状态。账户授权和监控状态各有相应的指标；群组变更可能导致不同账户产生不同的结果。

## 使用重叠访问权限

**“多个账户可见的聊天”**功能显示共享来源及可用工作区观察范围。符合条件的频道和超级群组可使用**“与…账户导出”功能，**将单个聊天的历史记录采集任务分配给多个账户。私人聊天和普通群组仍保留在起始账户下，因为其消息编号属于该账户的历史记录。

## 将群组导出为包

**导出组**会生成一个 ZIP 文件，其中包含每个账户的已签名导出文件以及这些文件的已签名列表。原始工作区的身份信息和指纹仍可供验证。利用这些参考信息构建跨账户的叙事；单一的合并时间线仍需单独组装。
