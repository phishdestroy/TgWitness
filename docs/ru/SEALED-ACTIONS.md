# Выгрузка из своего форка через GitHub Actions

**Предварительная версия в ветке `main`.** Пользователь делает форк,
запускает задачу，входит в Telegram во временной панели и выбирает режим，состав
данных и настройки．Можно выгрузить весь доступный аккаунт，выбранные чаты или
журнал одного чата，GitHub создаёт аттестацию ZIP либо манифеста частей，после
чего результат передаётся в зашифрованном виде．

Для просмотра через официальный Telegram Web с видеозаписью выберите `client=official_web` и укажите свой HTTP или SOCKS5 прокси в `official_proxy`．В панели доступны пассивное наблюдение и последовательная прокрутка，вход по QR，выбор чата，ограничения темпа и времени．Этот режим сохраняет отображаемое в одном чате，а полная выгрузка аккаунта остаётся в `client=api`．Подробности и пределы описаны в [руководстве официального клиента](../OFFICIAL-WITNESS.md)．

Верификатор сверяет архив с аттестацией GitHub, разрешёнными версиями workflow
и сборщика, затем проверяет журнал и вложения. Получатель может изучить код
сбора и проверить, что полученный файл соответствует зафиксированному запуску.

## Расчёт времени сеанса

Перед сбором нажмите **«Рассчитать время и размер»**．Панель покажет оценку истории
и вложений，оставшееся время с учётом входа и резерв на упаковку．Начальная оценка
файлов использует скорость 1 МиБ/с с двукратным запасом，во время сбора она уточняется
по фактическому темпу．Если объём не помещается，можно оставить только сообщения
или выбрать меньше чатов．Ожидание Takeout учитывается после ответа Telegram．

Сбор заканчивается，когда оставшееся время требуется для подготовки архива．Уже
полученные данные сохраняются，а частичный результат отмечается в пакете．Для
неполной выборки панель отдельно показывает，что весь объём ещё не оценён．

## Запуск по шагам

Схема показывает пять этапов и подмену сообщения или сборщика на примере.
Кнопка «Перейти к выгрузке» открывает мастер.

1. Нажмите **«Выгрузка через GitHub Actions»** на главной странице проекта,
   экране входа в панель или откройте **«Экспорт → Открыть помощник выгрузки»**.
   [Прямая ссылка на помощник](https://phishdestroy.github.io/TgWitness/sealed.html?lang=ru).
   Можно также открыть `tgwitness/static/capture.html` из доверенной копии репозитория
   локально в современном браузере.
2. Нажмите **«Создать и сохранить ключ»**. Сохраните `sealed-key.json` у себя.
   В GitHub копируется только отдельно показанное значение **recipient**.
   Закрытый файл ключа нельзя публиковать. Без него результат не восстановить.
   Отметьте, что сохранили файл, и перейдите на следующий шаг. Если архив уже
   получен, загрузите свой ключ и нажмите **«У меня уже есть архив»**.
3. Нажмите **«Создать форк TgWitness»**, затем в своём форке откройте **Actions**
   и включите выполнение workflow. Выберите **Sealed chat capture → Run
   workflow**. Вставьте только recipient и выберите 30, 60 или 120 минут.
   Телефон, коды, пароль Telegram и закрытый ключ в поля GitHub не вводятся.
4. Не дожидаясь конца задачи, скачайте артефакт **sealed-connection**.
   Распакуйте ZIP и откройте `connection.tgwsealed` в помощнике. Если страница
   перезагружалась, сначала загрузите сохранённый `sealed-key.json`.
5. Откройте ссылку для подключения. Войдите с помощью QR-кода или указав свой номер
   телефона и код доступа. Введите пароль двухэтапной аутентификации, если Telegram его
   запросит. По умолчанию используется встроенный пул учетных данных API, как и в
   обычном рабочем пространстве. Вы можете развернуть дополнительный раздел
   «Пользовательские учетные данные» и ввести `api_id` и `api_hash` с сайта
   [my.telegram.org/apps](https://my.telegram.org/apps). Оставьте оба поля пустыми,
   чтобы использовать встроенный пул; неполная или некорректно сформированная пара будет
   отклонена．Импорт сеансов не допускается，выберите режим и состав выгрузки．
   Ссылка для подключения содержит секретный ключ доступа: не разглашайте его.
6. Выберите **Telegram Takeout**，**Обычный Telegram API** или **Журнал одного чата**．
   Для выгрузки аккаунта доступны все чаты либо несколько выбранных，период，типы
   чатов，категории аккаунта и правила вложений．Проверьте настройки，при необходимости
   сохраните их для проверяющего，затем начните сбор．Пропуски，ошибки вложений и
   остановка по времени останутся в подписанном результате．
7. Скачайте **sealed-result**, распакуйте и откройте `delivery.tgwsealed`
   своим ключом в помощнике. Полученный `delivery.zip` содержит `evidence.zip`
   и `attestation.jsonl`. Для файлов больше 256 МиБ используйте локальную команду:

```sh
python -m tgwitness.sealed_crypto decrypt delivery.tgwsealed --key sealed-key.json --out delivery.zip
```

## Проверка результата

Распакуйте `delivery.zip` и проверьте `evidence.zip` доверенной установкой TgWitness:

```sh
python -m tgwitness.sealed_verify evidence.zip --bundle attestation.jsonl --repo OWNER/TgWitness
```

Нужны зависимости TgWitness и актуальный GitHub CLI. Проверка требует
одобренную версию **нашего общего workflow**, даже если запуск принадлежит
пользовательскому форку. Подпись произвольного изменённого форка не подходит.
После окончания завершите временную сессию в **Telegram → Настройки →
Устройства**, если её отзыв не подтверждён или задача была принудительно убита.

Проверяющему передают `evidence.zip` и `attestation.jsonl`. Закрытый ключ
`sealed-key.json` передавать не нужно: он используется только для расшифровки
доставленного пакета. Расшифровка без последующей проверки аттестации не
подтверждает, каким кодом получен архив.

Чтобы заранее согласовать состав，после проверки настроек нажмите **«Сохранить
настройки для проверки»** и передайте `sealed-export-settings.json` проверяющему
до сбора．Сборщик фиксирует действующие настройки и их SHA-256 в подписанном
журнале，квитанции экспорта аккаунта связывают с результатом тот же набор параметров．

```sh
python -m tgwitness.sealed_verify evidence.zip --bundle attestation.jsonl --repo OWNER/TgWitness --expected-selection sealed-export-settings.json --require-complete
```

`--expected-selection` отклоняет другой режим，набор чатов，фильтры или правила
вложений．`--require-complete` отклоняет неполную выгрузку аккаунта и журнал чата，
для которого общая полнота не установлена．Без этих параметров проверка всё равно
сверяет подписи и аттестацию，показывая фактические настройки и пропуски．Файл，
полученный только вместе с готовым архивом，не доказывает предварительного согласования．

Большие результаты содержат `delivery-NNNNNN.tgwsealed`，а основной пакет
`delivery.tgwsealed` содержит `evidence.parts.json` и аттестацию．Скачайте все
части，расшифруйте основной пакет и положите его манифест рядом с частями：

```sh
python -m tgwitness.sealed_parts evidence.parts.json --key sealed-key.json --out evidence.zip
python -m tgwitness.sealed_verify evidence.parts.json --assembled evidence.zip --bundle attestation.jsonl --repo OWNER/TgWitness
```

Аттестация относится к манифесту，он связывает части с собранным ZIP．Для большого
архива задайте подходящий предел распакованного объёма через `--max-gib`，по умолчанию
проверка ограничена 4 ГиБ．Проверка согласованных настроек работает и для частей．

## Какой режим выбрать

| Режим | Что настраивается | Отличия |
| --- | --- | --- |
| Telegram Takeout，выбран по умолчанию | Весь доступный аккаунт или выбранные чаты，период，категории данных，вложения，JSON и HTML | Официальный механизм экспорта Telegram，может потребовать подтверждения и ожидания．Позволяет получать доступные покинутые группы и каналы，дополнительные данные аккаунта． |
| Обычный Telegram API | Тот же выбор состава и представлений，в пределах доступных методов API | Не запускает Takeout，не перечисляет покинутые группы и каналы，контакты включают пользователей Telegram，но не весь сохранённый телефонный список．Лимиты запросов сохраняются． |
| Журнал одного чата | Один чат，правила вложений，аватары | История и изменения，наблюдаемые во время запуска．Категории аккаунта，фильтр дат и представления Desktop не применяются． |

У всех трёх режимов одинаковая аттестация GitHub и шифрование доставки，Takeout
определяет способ получения данных．Автоматической замены Takeout обычным API нет．
Совместимые JSON и HTML создаёт TgWitness，это не файлы с подписью Telegram и не
обещание побайтового совпадения с экспортом Desktop．Описание механизма есть в
[документации Telegram](https://core.telegram.org/api/takeout)．

По умолчанию выбраны Takeout，все доступные типы чатов с архивными，весь период，
профиль и контакты，JSON и HTML，скачивание вложений．Начальный бюджет файлов
составляет 4 ГиБ，пределы каждого типа видны в настройках，при превышении размера
или бюджета сохраняются доступные серверные хеши．Хеш не восстанавливает файл．
Фото профиля，истории，сведения о сессиях и дополнительные данные выбираются отдельно．

Secret Chats и недоступные данные не выгружаются，личные облачные чаты входят в
состав，если выбраны．Подпись обнаруживает подмену готового результата，но не
доказывает，что владелец не изменил или не удалил сообщения до сбора．

Takeout может потребовать подтверждения в уже действующей сессии，срок ожидания
задаёт Telegram．Запуск работает максимум 120 минут с учётом входа и подтверждения，
поэтому крупный аккаунт или долгое ожидание могут оставить результат неполным．
Новый запуск создаёт новую сессию，локальная выгрузка может продолжать ту же сессию，
но её подпись не получает аттестацию GitHub．

В разделе **«Экспорт → Открыть помощник выгрузки»** мастер работает прямо внутри
панели. Отдельная страница использует тот же мастер, оформление и темы. Четыре
шага показывают, где вы находитесь: ключ → GitHub → сбор → готовый архив.
GitHub и временная панель Telegram открываются в новых вкладках; после сбора
нужно вернуться в мастер. При блокировке рабочей панели ключ удаляется из её
памяти. Сохранённый файл ключа остаётся на вашем устройстве.

| Задача | Вариант |
| --- | --- |
| Доступные данные аккаунта или выбранные чаты，ограниченное время сбора，архив с аттестацией запуска | Выгрузка через GitHub Actions |
| Несколько чатов, постоянное наблюдение, поиск, чтение и управление аккаунтами | Локальная установка или Docker |
| Восстановить удалённое до сбора или получить абсолютное доказательство истинности сообщений | Ни один из этих вариантов этого не обеспечивает |

Это отдельный сбор: существующий журнал и сессия из вашей локальной панели
никуда не загружаются．В облаке нужно войти заново，после старта состав и настройки
изменить нельзя．При остановке по времени после начала сбора
сохраняется частичный результат с указанием пропусков. До начала сбора или при
отмене архив не создаётся. После уничтожения раннера продолжить тот же сбор
нельзя，следующий запуск создаст новый журнал．

## Форк, ключи и приватность

**Форк публикует копию кода, а не вашу переписку.** Данные Telegram не нужно
коммитить в репозиторий. В параметры workflow передаются открытый ключ
шифрования recipient и время работы. Закрытый `sealed-key.json` остаётся у вас.
Не помещайте в репозиторий, Issues или логи API-ключи Telegram, коды входа,
пароль 2FA, файлы сессий, закрытый ключ и расшифрованную ссылку подключения.

В Artifacts загружаются только зашифрованные `connection.tgwsealed` и
`delivery*.tgwsealed`．Срок хранения составляет **один день**，скачайте их вовремя．
`sealed-key.json` нужно хранить отдельно: без него ни мы, ни GitHub не смогут
восстановить зашифрованный результат.

Во время работы Telegram-сессия и открытые данные находятся на временной
машине GitHub. GitHub и HTTPS-туннель входят в модель доверия. Аттестация может
публично раскрывать хеш архива и сведения о workflow, но не содержит саму
переписку. Её время относится к фиксации архива, а не подтверждает даты сообщений.

Два разных ключа решают разные задачи: ваш закрытый ключ расшифровывает доставку,
а ключ журнала внутри сборщика подписывает наблюдения. Внешняя аттестация
GitHub связывает готовый архив с разрешённой версией workflow. Проверка требует
именно её: обычной подписи произвольного изменённого форка недостаточно.

## Если что-то не получается

| Проблема | Что проверить |
| --- | --- |
| Нет кнопки Run workflow | Открыт ли ваш форк, включён ли Actions и синхронизирован ли форк с `main` исходного репозитория. Не меняйте закреплённые версии сборщика ради обхода ошибки. |
| Не появился sealed-connection | Задача должна стартовать и пройти создание панели и загрузку артефакта. Очередь, правила репозитория, ошибка загрузки образа или туннеля могут остановить запуск. |
| Ссылка не открывается | Раннер ещё работает; артефакт распакован; загружен ключ именно этого запуска. |
| История приостановлена | Посмотрите статус в панели. Пока задача активна, можно продолжить чтение или завершить с уже собранными данными. Telegram может ограничить запросы. |
| Нет sealed-result | После отмены и истечения времени до начала сбора архива нет．Ошибка сбора，аттестации или упаковки тоже предотвращает выдачу результата．Посмотрите упавший шаг，не публикуя секреты． |
| Большой файл не открывается в браузере | Для пакетов больше 256 МиБ используйте команду расшифровки выше. Ошибочный или потерянный ключ не заменяется новым. |
| Проверка отклоняет подпись | Укажите точное `OWNER/REPOSITORY` своего форка и используйте доверенную актуальную версию TgWitness. Не принимайте файл политики, предложенный вместе с неизвестным архивом. |
| Сессия осталась в Telegram | Завершите её в «Настройки → Устройства». Автоматический выход может не сработать при сетевой ошибке или принудительном завершении задачи. |

## Проверка перед первой выгрузкой

Перед важной выгрузкой проверьте небольшой чат под своим контролем: сообщение
и вложение должны попасть в архив, расшифровка и проверка должны завершиться
успешно, а временная сессия — исчезнуть из Telegram либо требовать ручного отзыва.
Автоматические тесты проверяют синтетический чат и отдельно настоящую
аттестацию GitHub; они не заменяют сквозной тест с реальным аккаунтом.

GitHub и HTTPS-туннель входят в доверенную инфраструктуру. Временный раннер
обрабатывает сессию Telegram и сообщения, а готовый архив шифруется для получателя.
В архиве указаны выбранные данные，настройки，результаты загрузки истории и вложений，
а также статус завершения сбора. Режим сохраняет доступную историю;
удалённые до сбора сообщения и пропущенные версии остаются за её пределами.

Форк не отменяет правил использования Actions. Эта версия предназначена для
проверки функции; обещать на её основе неограниченный бесплатный сервис нельзя.
Подробности, ограничения, криптографический формат, проверка без сети и порядок
публикации закреплённых версий: [Sealed Actions](../SEALED-ACTIONS.md).
