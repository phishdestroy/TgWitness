# 문제가 발생한 원인을 파악하세요

Canonical page: https://phishdestroy.github.io/TgWitness/ko/docs/troubleshooting/

증상부터 파악하십시오. 한 단계씩 차례로 확인하십시오.

## 패널에서 토큰을 요청합니다

런처에 표시된 로컬 파일의 패널 토큰을 사용하십시오. Docker의 경우 `docker compose exec tgwitness cat /data/panel-token.txt`를 실행하십시오. 텔레그램 로그인 코드, BotFather 토큰 및 읽기 전용 위트니스 토큰은 각각 다른 용도로 사용됩니다.

## 텔레그램은 연결되지 않습니다

연결 설정을 열고 연결 확인을 실행하십시오. 공용 프록시를 사용하는 경우 다른 항목을 시도하고 경로를 명시적으로 저장하십시오. 프록시 유형과 지원되는 비밀 형식을 확인하십시오. 공용 목록을 새로 고침해도 계정의 경로는 변경되지 않습니다.

## 연결 상태이지만 새 메시지는 없음

1. 관찰 기능이 올바른 작업 공간에서 실행되고 있는지 확인하십시오.
2. 해당 계정이 소스를 선택했으며 이를 볼 수 있는지 확인하십시오.
3. 통제된 그룹에서 고유한 새 메시지를 보내고, 그 정확한 텍스트를 찾아보세요.
4. 운영 일지를 검토하여 중단, 작업 지연 또는 텔레그램 오류 여부를 확인하십시오.

과거 스냅샷과 새 메시지 이벤트는 서로 다릅니다. '조용한' 소스는 새 메시지를 생성하지 않고도 연결할 수 있습니다. 데이터의 완전성이 중요한 경우에는 제어된 전송 테스트를 사용하십시오.

## 재시작 후 FloodWait 또는 간격 발생

FloodWait는 텔레그램에서 일시 중지가 필요함을 의미합니다. 표시된 기간 동안 기다린 후 수집 작업량을 검토하십시오. 재연결을 반복해도 제한이 해제되지는 않습니다. 저장된 업데이트 상태는 재시작 후 작업을 따라잡는 데 도움이 되지만, 만료된 업데이트와 일부 중단 기간은 여전히 제한 사항으로 남아 있습니다. 저널을 완료된 것으로 간주하기보다는 중단된 부분을 기록하십시오.

## 봇은 설정되어 있으나 아무것도 게시하지 않습니다.

위트니스 프로세스가 실제로 실행 중인지, 봇이 채널에 게시물을 올릴 수 있는지, 위트니스가 수집기 및 봇 API에 연결될 수 있는지 확인하십시오. 저널을 검토하여 게시 실패 내역이 있는지 확인하십시오. 수집기 폴링이 성공했다고 해서 채널 게시물이 확인된 것은 아닙니다.

## GitHub 토큰 연동 기능은 어디에 있나요?

**계획 중.** ‘추가 정보’ 섹션에서는 제안된 포크 및 빌드 검증 워크플로를 설명합니다. 현재 실행 중인 설치 환경이 리포지토리와 일치함을 확인하는 GitHub 토큰 양식이나 자동 인증 기능은 없습니다. [현재 기능 현황](https://phishdestroy.github.io/TgWitness/ko/docs/reference/features/)을 참조하십시오.

문제를 보고할 때는 버전, 운영 체제, 재현 단계 및 편집된 오류 내용을 포함해 주십시오. 세션, 토큰, 비공개 메시지 및 데이터 디렉터리는 공개 이슈에 포함하지 마십시오.
