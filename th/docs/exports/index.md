# ส่งออกและตรวจสอบ

Canonical page: https://phishdestroy.github.io/TgWitness/th/docs/exports/

ส่งไฟล์ให้ผู้รับเพื่อตรวจสอบเทียบกับพื้นที่ทำงานการเก็บรวบรวมข้อมูลและประวัติที่บันทึกไว้

เก็บไว้เป็นข้อมูลอ้างอิงส่งออก ZIP ที่มีลายเซ็นผู้รับยืนยัน

ยังไม่คุ้นเคยกับลายเซ็นและจุดตรวจสอบ? [ลองแก้ไขบันทึกตัวอย่าง](https://phishdestroy.github.io/TgWitness/th/docs/concepts/#chain)และดูว่าการตรวจสอบใดจะตรวจพบการเปลี่ยนแปลงนั้น

ต้องการเก็บสำเนาไว้แยกจากผู้เก็บข้อมูล? ไปที่[การตั้งค่า S3](https://phishdestroy.github.io/TgWitness/th/docs/exports/#s3), [Object Lock](https://phishdestroy.github.io/TgWitness/th/docs/exports/#s3-retention) หรือ[การกู้คืนที่ได้รับการยืนยัน](https://phishdestroy.github.io/TgWitness/th/docs/exports/#s3-restore)

## เก็บรักษาแหล่งอ้างอิงที่น่าเชื่อถือ

บันทึกลายนิ้วมือของกุญแจสาธารณะของพื้นที่ทำงานไว้ภายนอกตัวเก็บข้อมูล ระหว่างการเก็บข้อมูล ให้เก็บจุดตรวจสอบที่ลงนามไว้ที่อื่น หรือใช้[พยานอิสระ](https://phishdestroy.github.io/TgWitness/th/docs/witness/) การอ้างอิงเหล่านี้ช่วยให้ผู้รับสามารถตรวจสอบกุญแจและขอบเขตของบันทึกก่อนหน้านี้

## ดาวน์โหลดไฟล์ ZIP ที่ลงนามแล้ว

**เปิดการส่งออก** **(**Open **Exports)** และสร้างไฟล์ ZIP ของหลักฐานที่ลงนามแล้ว ซึ่งรวมถึงบันทึกพื้นที่ทำงานทั้งหมดและรายการไฟล์ที่ลงนามแล้ว ใช้ [Report Studio](https://phishdestroy.github.io/TgWitness/th/docs/reports/) เพื่อจัดรูปแบบรายงานให้อ่านได้ง่าย หรือใช้การ[สกัดข้อมูลสำหรับการส่งต่อ](https://phishdestroy.github.io/TgWitness/th/docs/handover/) [(handover extract](https://phishdestroy.github.io/TgWitness/th/docs/handover/)) เพื่อส่งข้อมูลที่เลือกไว้และถูกลดขนาดลงเท่านั้น

รายงานในรูปแบบ HTML, PDF และ JSON มีตราประทับที่ลงนามไว้และสามารถตรวจสอบได้แยกกัน CSV เป็นสำเนาที่สะดวกสำหรับการวิเคราะห์; ใช้ไฟล์ CSV ที่อยู่ใน ZIP ที่ได้รับการตรวจสอบแล้วเพื่อตรวจสอบความสมบูรณ์ของข้อมูล เก็บ ZIP ที่ลงนามไว้เมื่อผู้รับต้องการบันทึกต้นฉบับและไฟล์แนบด้วย

## ตรวจสอบด้วยสำเนา TgWitness ที่เชื่อถือได้

ในสภาพแวดล้อมโครงการที่ติดตั้งแล้ว ให้เปลี่ยนลายนิ้วมือตัวอย่างและเส้นทางไฟล์:

```
python -m tgwitness.verify evidence.zip --fingerprint TRUSTED_PUBLIC_KEY_SHA256 --checkpoint retained-checkpoint.json
```

เมื่อการอ้างอิงทั้งสองผ่านแล้ว ผลลัพธ์จะรายงาน `key_pinned: true` และ `checkpoint_checked: true` ให้เก็บผลการตรวจสอบไว้พร้อมกับไฟล์เก็บถาวรต้นฉบับ จุดตรวจสอบที่เก็บไว้ต้องอยู่ ณ หรือก่อนขอบเขตของการส่งออก

## ใช้ผลการตรวจสอบ

- **ตรวจสอบไฟล์ที่ส่งมา:** ไฟล์ manifest เชื่อมโยงค่าแฮชของไฟล์เหล่านั้น และลายเซ็นของบันทึกเชื่อมโยงกับบันทึกที่เก็บไว้ ระบบจะตรวจพบหากมีไฟล์ที่ถูกแก้ไขหรือห่วงโซ่บันทึกที่ขาด
- **ตรวจสอบความถูกต้องของพื้นที่ทำงาน:** ลายนิ้วมือที่เก็บรักษาไว้อย่างอิสระจะระบุกุญแจการลงนามที่คุณคาดหวัง
- **เปรียบเทียบกับจุดแบ่งเขตก่อนหน้านี้:** จุดตรวจสอบที่เก็บรักษาไว้จะตรวจสอบการส่งออกกับคำนำหน้าของบันทึกที่เก็บไว้ก่อนการส่งต่อ
- **ตรวจสอบขอบเขตการเก็บรวบรวมข้อมูล:** ช่องว่าง, ผลลัพธ์การเก็บรวบรวมข้อมูล และการทดสอบแบบควบคุม (ส่ง → แก้ไข → ลบ) เพื่ออธิบายเหตุการณ์ที่การตั้งค่านี้บันทึกไว้

เก็บผลลัพธ์เหล่านี้ไว้ในสำเนาของผู้รับ ดู[ว่าการตรวจสอบยืนยันกำหนด](https://phishdestroy.github.io/TgWitness/th/docs/reference/evidence/#verification-scope)ขอบเขตการตรวจสอบอย่างไร รวมถึงการประเมินแยกต่างหากเกี่ยวกับข้ออ้างของแหล่งข้อมูลและขอบเขตการเก็บรวบรวมข้อมูล

## ตั้งค่าสำเนาสำรอง S3 นอกสถานที่

ในพื้นที่ทำงานของคุณ ให้เปิด **Exports → Off-site copy** (ส่งออก → สำเนาภายนอกระบบ) คุณสมบัตินี้เป็นตัวเลือกเสริมที่ทำงานร่วมกับ AWS S3 และบริการอื่น ๆ ที่รองรับ S3 มันจะคัดลอกส่วนต่าง ๆ ของบันทึก รูปภาพและไฟล์ที่เก็บรักษาไว้ จุดตรวจสอบพร้อมข้อมูลเวลาตอบสนอง และไฟล์ส่งออกการสนทนาที่เสร็จสมบูรณ์ ทุกวัตถุจะถูกเข้ารหัสบนเครื่องเก็บข้อมูลด้วย`AES-256-GCM` ก่อนการอัปโหลด

การสาธิตออนไลน์แสดงปุ่มควบคุมเดียวกัน แต่ปิดฟังก์ชันการอัปโหลดไว้ โปรดป้อนข้อมูลรับรองการเข้าถึงพื้นที่จัดเก็บข้อมูลเฉพาะในพื้นที่ทำงานของคุณเองเท่านั้น

[![แผงคัดลอกข้อมูลนอกไซต์แบบครบถ้วน: จุดปลายทาง (endpoint), ภูมิภาค (region), บักเก็ต (bucket), กุญแจเข้าถึง (access keys), ตารางเวลา (schedule), การล็อกวัตถุ (Object Lock) และการควบคุมกุญแจกู้คืน (recovery key controls)](https://phishdestroy.github.io/TgWitness/assets/off-site-copy.png)](https://phishdestroy.github.io/TgWitness/assets/off-site-copy.png)

แผงควบคุมแบบเต็มที่มีตัวเลือกขั้นสูงถูกขยายออกแล้ว ไม่แสดงข้อมูลรับรองการเข้าถึงพื้นที่จัดเก็บข้อมูล

| Field | สิ่งที่ต้องกรอก |
| --- | --- |
| Endpoint | URL ของบริการจัดเก็บข้อมูล โดยไม่รวมเส้นทาง bucket หรือข้อมูลรับรอง ตัวอย่างสมมติ: `https://s3.example.invalid`. |
| ภูมิภาค | ภูมิภาคที่ผู้ให้บริการของคุณกำหนด ค่าเริ่มต้นของแอปพลิเคชันคือ `us-east-1` |
| Bucket | บัคเก็ตที่มีอยู่แล้วที่คุณสามารถเข้าถึงได้ ตัวอย่างสมมติ: `example-case-backup`. |
| โฟลเดอร์ใน bucket | คำนำหน้าของวัตถุ; ค่าเริ่มต้นคือ`tgwitness` แอปพลิเคชันจะเพิ่มคำนำหน้าที่สร้างขึ้นจากลายนิ้วมือของกุญแจลงนามของพื้นที่ทำงานนี้ |
| ID กุญแจการเข้าถึง / กุญแจการเข้าถึงลับ | ป้อนข้อมูลรับรองการเข้าถึงพื้นที่จัดเก็บทั้งสองรายการพร้อมกัน ข้อมูลเหล่านี้จะถูกเก็บไว้ใน vault ของพื้นที่ทำงาน เมื่อบันทึกข้อมูลในครั้งต่อไป ให้ปล่อยทั้งสองช่องว่างไว้เพื่อรักษาคู่ข้อมูลที่บันทึกไว้ |
| ที่อยู่แบบ Path | ใช้ `endpoint/bucket` เมื่อเปิดใช้งาน หรือ `bucket.endpoint` เมื่อปิดใช้งาน ตามที่ผู้ให้บริการกำหนด |
| ช่วงเวลาการคัดลอก | ตั้งแต่ 1 ถึง 1,440 นาที; ค่าเริ่มต้นคือ 5 นาที แอปพลิเคชันต้องกำลังทำงานอยู่เพื่อดำเนินการคัดลอกตามกำหนดเวลา |
| การเก็บรักษาข้อมูลตามหลัก Object Lock | จำนวนวันและวิธีการเก็บรักษาข้อมูลสำหรับ bucket ที่สนับสนุน Object Lock หากตั้งค่าเป็น Zero days จะทำให้การเก็บรักษาข้อมูลตามค่าเริ่มต้นของ bucket ยังคงมีผล |

1. สร้าง bucket กับผู้ให้บริการของคุณ แล้วป้อนปลายทางและข้อมูลรับรอง ปล่อยให้ตัวเลือก **“เก็บสำเนาไว้นอกไซต์”** ไม่ถูกเลือกขณะเตรียมการ แล้วเลือก **“เก็บสำเนาไว้นอกไซต์**”
2. เลือก "**Test connection**" (ทดสอบการเชื่อมต่อ) เพื่ออัปโหลดวัตถุทดสอบที่เข้ารหัสและตรวจสอบการตอบสนองจากระบบจัดเก็บข้อมูล
3. เลือก **"ดาวน์โหลดกุญแจการเข้ารหัส" (Download encryption key**) เก็บไฟล์นั้นแยกจากโปรแกรมเก็บข้อมูล (collector) เพราะจำเป็นต้องใช้สำหรับการกู้คืนข้อมูล
4. ทำเครื่องหมายในช่อง **“เก็บสำเนาไว้นอกเว็บไซต์**” และบันทึกอีกครั้ง เลือก **“คัดลอกทันที**” เพื่อดำเนินการด้วยตนเอง หรือปล่อยให้กำหนดเวลาทำงานต่อไป

## ตรวจสอบระยะเวลาการเก็บรักษาข้อมูลและสถานะการคัดลอก

ในส่วน **“More options**” (ตัวเลือกเพิ่มเติม) ให้เลือกจำนวนวันเก็บรักษา และเลือก “`GOVERNANCE`” หรือ “`COMPLIANCE`” เมื่อ bucket ของคุณสนับสนุน Object Lock TgWitness จะอ่านกลับโหมดการเก็บรักษาและวันหมดอายุของวัตถุที่อัปโหลดมา ตรวจสอบผลการเก็บรักษาที่แยกต่างหาก: ยืนยันแล้ว, การเก็บรักษาไม่ครบถ้วน หรือการตรวจสอบล้มเหลว

แผงควบคุมจะรายงานรอบการประมวลผลครั้งล่าสุด จำนวนวัตถุ ไบต์ที่ถ่ายโอน ขอบเขตของบันทึกที่คัดลอก และข้อผิดพลาดใดๆ สื่อท้องถิ่นที่ขาดหายไปหรือถูกเปลี่ยนแปลงจะถูกรายงานและระบบจะลองใหม่ในรอบการประมวลผลครั้งถัดไป ไฟล์ จุดตรวจสอบ และการส่งออกที่อยู่ในคิวหลังจากสื่อดังกล่าวนั้นยังสามารถคัดลอกได้

การอัปโหลดใช้เส้นทาง Direct, SOCKS5 หรือ HTTP ของพื้นที่ทำงาน ให้เลือกหนึ่งในเส้นทางเหล่านี้สำหรับการคัดลอกไปยัง S3; หากใช้เส้นทาง MTProxy เท่านั้น การคัดลอกจะอยู่ในสถานะรอการดำเนินการพร้อมข้อผิดพลาด

## เก็บกุญแจกู้คืนไว้แยกต่างหาก

ไฟล์ JSON ที่ดาวน์โหลดมาประกอบด้วยกุญแจถอดรหัส การตั้งค่าจุดหมายปลายทาง คำนำหน้าของวัตถุในพื้นที่ทำงาน และลายนิ้วมือของกุญแจลงนาม การกู้คืนข้อมูลจำเป็นต้องใช้ทั้งไฟล์กุญแจนี้และข้อมูลรับรองการเก็บข้อมูลแยกต่างหากที่มีสิทธิ์อ่านใน bucket ให้เก็บข้อมูลเหล่านี้ไว้ในแผนการกู้คืนของคุณ

หากเปลี่ยนจุดปลายทาง (endpoint), บักเก็ต (bucket) หรือคำนำหน้าโฟลเดอร์ (folder prefix) ให้ดาวน์โหลดไฟล์กุญแจใหม่เพื่อให้การตั้งค่าจุดหมายปลายทางตรงกัน แอปพลิเคชันจะสร้างสำเนาใหม่ของบันทึก ไฟล์ และจุดตรวจสอบ (checkpoints) ที่เก็บไว้ท้องถิ่นไปยังจุดหมายปลายทางใหม่ ส่วนการส่งออกการสนทนาที่เสร็จสิ้นแล้วและถูกลบออกจากคิวอัปโหลดท้องถิ่นจะยังคงอยู่ที่จุดหมายปลายทางเดิม

## กู้คืนและตรวจสอบบนเครื่องอื่น

ใช้การติดตั้ง TgWitness ที่เชื่อถือได้, ไฟล์ JSON ของกุญแจที่ดาวน์โหลดมา, ข้อมูลการเข้าสู่ระบบของพื้นที่จัดเก็บที่มีสิทธิ์อ่าน, และไดเรกทอรีผลลัพธ์ที่ว่างเปล่า ให้แทนที่ข้อมูลการเข้าสู่ระบบตัวอย่างที่สมมติไว้ด้านล่าง

### Windows PowerShell

```
$env:TGWITNESS_S3_ACCESS_KEY = 'YOUR_READ_ACCESS_KEY'
$env:TGWITNESS_S3_SECRET_KEY = 'YOUR_READ_SECRET_KEY'
python -m tgwitness.replica restore --key-file tgwitness-replica-key.json --out restored-evidence
```

### Linux / macOS

```
export TGWITNESS_S3_ACCESS_KEY='YOUR_READ_ACCESS_KEY'
export TGWITNESS_S3_SECRET_KEY='YOUR_READ_SECRET_KEY'
python -m tgwitness.replica restore --key-file tgwitness-replica-key.json --out restored-evidence
```

ไฟล์ที่ดาวน์โหลดและไฟล์ที่ถอดรหัสแล้วจะถูกเก็บไว้ในพื้นที่จัดเก็บชั่วคราวส่วนตัว ในขณะที่บันทึกทั้งหมด จุดตรวจสอบที่เก็บไว้ รวมถึงค่าแฮชและขนาดของสื่อที่เก็บรักษาไว้จะถูกตรวจสอบ เส้นทางที่ไม่ปลอดภัย ส่วนบันทึกที่ขัดแย้งกัน และบันทึกที่มีขนาดสั้นกว่าจุดตรวจสอบจะถูกปฏิเสธ หากการตรวจสอบล้มเหลว ไฟล์ที่กู้คืนมาจะไม่ถูกเผยแพร่

การกู้ข้อมูลที่สำเร็จจะให้ผลลัพธ์เป็น `events.jsonl`, `media/`, `checkpoints/` และ `exports/` สำหรับข้อมูลที่มีอยู่ในสำเนา เก็บผลลัพธ์ JSON ของคำสั่งไว้พร้อมกับข้อมูลที่กู้คืนได้

เปรียบเทียบข้อมูลที่กู้คืนได้กับจุดตรวจสอบหรือบันทึกพยานที่คุณเก็บรักษาไว้อย่างอิสระ จากนั้นตรวจสอบขอบเขตการเก็บรวบรวมที่บันทึกไว้สำหรับช่วงเวลาที่คุณต้องการ
