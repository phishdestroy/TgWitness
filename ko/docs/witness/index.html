Witness 봇 설정하기

별도의 프로세스가 이 저널을 확인하고 서명된 체크포인트를 채널에 게시하도록 하세요.

호스트 2개, 서명 키 2개

봇과 채널 준비하기

BotFather를 사용하여 봇을 생성하고, 관리하는 채널에 게시할 수 있도록 설정하십시오. 위트니스(Witness)를 호스팅할 컴퓨터나 서버를 선택하십시오. 별도의 호스트와 운영자를 활용하면 수집자 서버에서 두 번째 프로세스를 실행하는 것보다 더 강력한 독립성을 확보할 수 있습니다.

'추가 기능'의 세 단계

  1. 읽기 전용 액세스. ‘Extras’를 열어 채널에 봇을 추가하고, 위트니스 토큰을 생성한 후 액세스 파일을 저장하세요. 이를 통해 대화 내용이나 수집기 제어 기능은 이용할 수 없으며, 체크포인트 및 상태 정보만 확인할 수 있습니다.
  2. 채널 및 간격. 채널과 위트니스에서 접근 가능한 수집기 주소를 입력하십시오. 설정 파일을 저장하십시오.
  3. 시작하기. witness.json, witness-token.txt 및 위트니스 호스트에서 생성된 bot-token.txt를 함께 배치합니다. 설치된 프로젝트 환경에서 아래 명령어를 실행하십시오.
python -m tgwitness.witness run --config witness.json --check-config
python -m tgwitness.witness run --config witness.json

파일을 다운로드한다고 해서 위트니스가 자동으로 실행되지는 않습니다. 채널에 첫 번째 서명된 게시물이 표시되는지 확인한 후, 위트니스의 공개 키 지문을 별도로 보관하십시오.

게시 빈도 선택

모든 확인 내역을 게시하면 정기적인 외부 기록이 생성됩니다. 5분 간격으로 게시할 경우, 워크스페이스당 하루 약 288개의 게시물이 생성됩니다. 고급 설정에서는 변경 사항이나 문제 발생 시 게시, 프록시, 사용자 지정 봇 API 주소 설정도 제공합니다.

이 봇은 실제로 무엇을 증명합니까?

증인은 수집자에게 서명된 체크포인트를 요청하고, 예상된 키와 대조하여 이를 검증한 후 별도의 서명된 일지를 보관합니다. 이 도구는 성공적인 확인 결과뿐만 아니라 누락된 응답과 거부된 답변도 기록합니다. 게시 여부는 여전히 증인이 실행 중이고 텔레그램의 봇 API에 접속할 수 있는지에 달려 있습니다.

이 도구는 수집기가 보고한 기록부 상태를 확인합니다. 모든 텔레그램 메시지를 독립적으로 관찰하지는 않습니다. 이를 위해서는 ‘제어된 전달 테스트’를 추가해야 합니다.

나중에 증거를 확인하세요

증거 일지, 채널 게시물 및 별도로 저장된 지문을 보관하십시오. 전체 검증 절차에서는 이를 수집자가 서명한 내보내기 파일과 비교합니다.
