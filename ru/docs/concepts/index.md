# Как устроены доказательства

Canonical page: https://phishdestroy.github.io/TgWitness/ru/docs/concepts/

Сообщения меняются. Ваша запись того, что вы видели, — нет, и проверить это может кто угодно.

Ниже два небольших эксперимента. Вымышленные сообщения, всё работает в браузере, в Telegram ничего не уходит.

## От экспорта чата до проверяемой записи

[Экспорт Telegram Desktop](https://telegram.org/blog/export-and-more) сохраняет видимую сейчас историю в HTML или JSON. TgWitness добавляет непрерывный журнал изменений, подписи на каждой записи и контрольные точки, с которыми могут сверяться другие.

| Задача | Экспорт из Telegram Desktop | TgWitness |
| --- | --- | --- |
| Просмотр сохраненных переписок | HTML или JSON с выбранными медиафайлами | Сохраненные чаты, журнал с возможностью поиска и отчеты в автономном режиме |
| Отслеживайте изменения во времени | История, доступная при экспорте | Старые версии, поздние правки и удаления — всё сохранено |
| Проверьте файлы после передачи | Стандартные файлы экспорта в формате HTML/JSON не подписаны | Подписанный манифест, подписанные записи и запечатанные отчёты, проверяемые по доверенному ключу |
| Сравните с предыдущим сохраненным состоянием | Сохраните отдельную справочную копию или хеш | Подписанные контрольные точки, отдельный свидетель и опциональные внешние временные метки |

Сравнение основано на [коде экспорта Telegram Desktop](https://github.com/telegramdesktop/tdesktop/tree/768d47cda6c7f447c10a25d1f363279493a90ed7/Telegram/SourceFiles/export/output) по состоянию на 2 ноября 2026 года.

## Одно сообщение, три замечания

Новое сообщение, правка и удаление становятся тремя отдельными записями. Правка не перезаписывает первую, удаление её не стирает.

01 / ПУТЬ СООБЩЕНИЯИллюстративная последовательность

Telegram delivers an update to the collector, which appends a journal record. · Telegram · Коллектор · Журнал · обновление → · добавить →

ПРОСМОТР ТЕКУЩЕГО ЧАТА Сообщение № 42

Сообщение удалено

Сообщение исчезло из окна чата.

ЖУРНАЛ НАБЛЮДЕНИЙ 3 записи

1. 01

   `message.new`

   Встреча в 10:00

   ✓
2. 02

   `message.edited`

   Встреча в 11:00

   ✓
3. 03

   `message.deleted`

   Уведомление об удалении № 42

   ✓

Все три зафиксированных события сохраняются в журнале.

Упрощённый путь для одного уже выбранного источника. Оперативные записи также используют тот же журнал. Захват данных зависит от того, что доступно для просмотра в учётной записи и что предоставляет Telegram.

Telegram не сообщает, кто удалил сообщение и когда именно. TgWitness оставляет эти поля пустыми, а не угадывает.

## Измените запись. Проследите хеш.

Каждая запись содержит хеш предыдущей. Контрольная точка, сохранённая в другом месте, фиксирует длину журнала и последний хеш.

02 / ПЕСЧАНКА HASH-CHAINНастоящий SHA-256 · примеры записей

ЗАПИСЬ 01**Сообщение получено**`h₁ = SHA-256(e₁)`Ссылки на 64 нуля

ЗАПИСЬ 02**Встреча в 11:00**`h₂ = SHA-256(e₂)`Включает h₁

ЗАПИСЬ 03**Зафиксировано удаление**`h₃ = SHA-256(e₃)`Включает h₂

ХРАНИТСЯ В ДРУГИХ ИСТОЧНИКАХ**3 записи · заголовок `h₃`**Сравните эту фиксированную границу с предоставленным журналом.

Изменение события приводит к изменению его хеша. Восстановление цепочки приводит к изменению её начала. Удаление конца делает цепочку короче, чем сохраненная контрольная точка.

Данная тестовая среда вычисляет хэши, а не подписи. Реальный верификатор также проверяет подпись Ed25519, последовательность и ссылку каждого события. Простое восстановление хэшей не позволяет создать действительные подписи с использованием доверенного ключа.

## Фактические правила в нескольких строках

ХЭШ + ПОДПИСЬ

h0 = 064
hi = hex(SHA-256(C(ei)))
σi = Ed25519.Sign(sk, unhex(hi))

**C** — это девять полей события в виде UTF-8 JSON: ключи по порядку, без лишних пробелов, без ASCII-экранирования, без NaN/бесконечности. `previous_hash` — это hi−1, h0 — 64 нуля, подписи покрывают 32 сырых байта дайджеста.

Поля: `seq`, `observed_at`, `source_at`, `kind`, `chat_id`, `message_id`, `actor_id`, `payload`, `previous_hash`. Полная спецификация: [кодирование событий](https://phishdestroy.github.io/TgWitness/ru/docs/reference/evidence/#event-canonicalization).

СОХРАНЕННАЯ КОНТРОЛЬНАЯ ТОЧКА

Nexport ≥ Ncheckpoint
hexport[Ncheckpoint] = Hcheckpoint

Проверьте подпись контрольной точки по закреплённому ключу, затем сравните её с журналом. Поздний экспорт может быть длиннее, но в точке должен совпадать.
