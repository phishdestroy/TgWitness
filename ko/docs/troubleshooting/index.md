# Telegram · 문제가 발생한 원인을 파악하세요

Canonical page: https://phishdestroy.github.io/TgWitness/ko/docs/troubleshooting/

증상에서 출발해 한 번에 하나씩 확인하십시오.

## 패널에서 토큰을 요청합니다

런처가 출력한 파일의 패널 토큰을 원합니다. Docker: `docker compose exec tgwitness cat /data/panel-token.txt`. 텔레그램 코드도, 봇 토큰도, 증인 토큰도 아닙니다.

## 텔레그램은 연결되지 않습니다

연결 확인을 실행합니다. 공개 프록시라면 다른 것을 골라 저장합니다. 프록시 유형과 비밀 값 형식을 확인합니다. 목록을 새로 고쳐도 경로가 저절로 바뀌지는 않습니다.

## 연결 상태이지만 새 메시지는 없음

1. 올바른 작업 공간에서 관찰이 실행 중입니까?
2. 소스가 선택되어 있고 그 계정에 보입니까?
3. 테스트 그룹에 고유한 메시지를 보내고 검색합니다.
4. 저널에서 중단이나 텔레그램 오류를 찾습니다.

조용한 채팅은 그냥 새것이 없을 뿐입니다. 완전성이 중요하면 통제된 전달 테스트를 실행하십시오.

## 재시작 후 FloodWait 또는 간격 발생

FloodWait는 텔레그램이 "천천히"라고 말하는 것입니다. 지나갈 때까지 기다리고 부하를 줄이십시오. 다시 연결해도 소용없습니다. 재시작 후 TgWitness는 텔레그램에 아직 남은 것을 따라잡으며, 나머지는 공백이므로 적어 두십시오.

## 봇은 설정되어 있으나 아무것도 게시하지 않습니다.

증인이 실행 중인지, 봇이 채널에 게시할 수 있는지, 수집기와 Bot API에 닿는지 확인하십시오. 증인 저널에서 실패한 게시물을 찾으십시오. 수집기 쪽에 폴링이 있다고 해서 게시물이 나간 것은 아닙니다.

## GitHub 토큰 연동 기능은 어디에 있나요?

**계획 중.** ‘추가 정보’ 섹션에서는 제안된 포크 및 빌드 검증 워크플로를 설명합니다. 현재 실행 중인 설치 환경이 리포지토리와 일치함을 확인하는 GitHub 토큰 양식이나 자동 인증 기능은 없습니다. [현재 기능 현황](https://phishdestroy.github.io/TgWitness/ko/docs/reference/features/)을 참조하십시오.

버그를 신고하나요? 버전, OS, 단계, 개인 정보를 가린 오류를 알려 주십시오. 세션, 토큰, 개인 메시지, 데이터 디렉터리는 절대 공개 이슈에 올리지 마십시오.
