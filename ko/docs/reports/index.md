# 보고서 설계

Canonical page: https://phishdestroy.github.io/TgWitness/ko/docs/reports/

독자가 사건 관련 질문에서 저장된 기록에 이르기까지 명확한 경로를 파악할 수 있도록 하십시오.

Report Studio는 데이터 선택, 가독성 높은 변경 내역, 차트 및 작성한 조사 결과를 통합합니다. 8가지 통합 디자인이 지원되는 HTML 및 네이티브 PDF 출력에 적용됩니다. HTML, PDF 및 JSON 보고서에는 각각 서명된 인장이 포함되며, ZIP 매니페스트는 패키지 내 파일을 묶어줍니다. HTML 및 PDF는 최종 레이아웃이 완료된 후 인장이 찍힙니다.

## 3단계로 보고서 작성하기

1. **‘내보내기’ → ‘구성 및 미리 보기’ → ‘데이터’를** 엽니다. 전체 작업 공간을 사용하거나, 채팅, 작성자, UTC 기준 관찰 날짜 및 기록 유형을 선택하십시오. 날짜는 TgWitness가 해당 기록을 관찰한 시점을 나타냅니다.
2. **‘디자인 및**내용’에서 디자인 및 내용 사전 설정을 선택하십시오. 활동 차트, 참가자 라벨, 대화록, 저장된 변경 사항 및 선택 사항인 케이스 보드 자료를 선택하십시오. 사건 세부 정보와 조사 메모를 추가하십시오.
3. **'미리 보기'를** 열어 건수, 활동 내역, 참여자, 표본 추출된 기록 및 누락된 ID 범위를 확인하십시오. 설정을 저장한 후 필요한 형식으로 다운로드하십시오.

### 독자가 이해하기 쉽도록 저장된 자료를 체계적으로 정리하십시오.

합성 예시 · 개략적인 레이아웃이며, 실제 생성된 보고서가 아님

1. **선택.** 해당 사건에 대한 두 개의 채팅과 관찰 기간을 선택하십시오.
2. **작성해 주십시오.** 레이아웃을 선택하고 질문에 답하는 섹션을 골라주세요.
3. **미리 보기.** 선택된 개수와 저장된 변경 전후 텍스트를 검토하십시오.
4. **검증하십시오.** 최종 파일을 생성하고, 신뢰할 수 있는 작업 공간 지문과 대조하여 서명을 확인하십시오.

#### 주요 사항

채팅 2건 · 관찰일 1일

메시지, 수정 내역 및 삭제 알림

#### 보고서 구조

##### 결제 수취처 변경

사건 질문 → 범위 → 조사 결과 → 기록 참조

**메시지 맥락**

관찰 사항 #142: “새로운 결제 링크를 사용하세요.”

**저장된 변경 사항**

변경 전: old.example.invalid → 변경 후: new.example.invalid

#### 선택 사항 검토

18건의 검토 의견 · 2건의 저장된 수정 사항

전송, 편집 및 확인 시간에는 각각 별도의 라벨이 지정되어 있습니다.

#### 최종 결과물

서명된 PDF + 서명된 JSON, 또는 읽기 가능한 보고서가 포함된 서명된 ZIP 파일

수신자는 파일과 신뢰할 수 있는 지문을 확인합니다.

## 읽기 스타일 선택

**Classic, Editorial, Briefing, Analytics, Technical, Overview, Reading 시리즈 및 Ledger & margin은** 동일한 기본 기록을 서로 다른 구성으로 제시합니다. 디자인을 변경하더라도 데이터 선택 사항과 작성된 메모는 유지됩니다. 보고서 언어는 지원되는 25개 언어 중에서 선택할 수 있습니다.

‘Reading’ 시리즈는 섹션 레일을 중심으로 사건, 범위, 조사 결과 및 변경 사항을 그룹화합니다. ‘Ledger & margin’은 번호가 매겨진 챕터와 넓은 여백을 사용합니다. 두 시리즈 모두 계정 HTML 개요 및 사본 공유를 지원합니다. 네이티브 PDF는 번들된 글꼴을 사용하여 생성되며, PDF 생성을 위해 사용자의 컴퓨터에 브라우저나 Node를 설치할 필요가 없습니다. 중국어, 일본어 및 한국어 PDF의 경우, Noto Sans CJK와 같은 적절한 글꼴이 서버에 시스템 전체에 설치되어 있거나 `TGWITNESS_FONT_DIR`에 배치되어 있어야 합니다. 해당 글꼴이 없는 경우, ZIP 파일에는 HTML 및 JSON 보고서만 포함됩니다.

## 변경 사항을 맥락과 함께 파악하십시오

저장된 수정 내역은 변경 전후를 모두 표시합니다. 삭제 알림에는 마지막으로 캡처된 버전이 함께 표시될 수 있습니다. 답글, 인용, 전달, 반응, 버튼 및 첨부 파일 메타데이터는 해당 참조 정보를 그대로 유지합니다. 파일 SHA-256 및 저널 기록 해시는 별도로 표기됩니다.

디자인 미리보기에는 처음 50,000개의 원본 기록 중 일치하는 기록을 사용한 표지, 검토 및 차트 구성 요소가 표시됩니다. 별도의 데이터 미리보기는 정확한 선택 개수를 확인하기 위해 전체 안정화된 저널 스냅샷을 스캔하며, 표시된 샘플 제한 수에 라벨이 붙어 있습니다. PDF를 생성하여 최종 페이지 배열을 확인하십시오. 전체 계정 내보내기에는 HTML 개요가 포함되며, 개별 채팅 PDF 파일은 선택한 디자인을 적용합니다.

## 수신자용 사본을 신중하게 선택하십시오.

보고서 필터를 통해 가독성 높은 보고서를 생성할 수 있습니다. 전체 증거 ZIP 파일에는 원본 저널과 첨부 파일이 그대로 포함됩니다. 수신자가 선택된 데이터만 받아야 하는 경우, [최소한의 인계](https://phishdestroy.github.io/TgWitness/ko/docs/handover/) 절차를 사용하십시오. [보고서 내용 및 검증](https://phishdestroy.github.io/TgWitness/ko/docs/reference/case-reports/) 정보를 확인하거나, [완성된 내보내기 파일을 검증하십시오](https://phishdestroy.github.io/TgWitness/ko/docs/exports/).
