# חבר חשבון

Canonical page: https://phishdestroy.github.io/TgWitness/he/docs/accounts/

כל סביבת עבודה מכילה חשבון אחד, היומן שלו ומפתח החתימה שלו.

## בחר כיצד להתחבר

פתחו **חשבונות**, הוסיפו סביבת עבודה ופתחו את הגדרות החיבור שלה. השתמשו בחשבון ייעודי לצורך תצפית.

- **קוד QR:** סרקו אותו מהגדרות המכשיר ב-Telegram ואשרו את הכניסה החדשה.
- **מספר טלפון:** הזן את המספר, את הקוד ש-Telegram שולח ואת סיסמת האימות הדו-שלבי שלך, אם האפשרות מופעלת.
- **ייבוא סשן:** ייבא סשן נתמך או נתוני Telegram Desktop השייכים לך.

בחר פרופיל API מובנה או הזן מזהה API והאש משלך. פרופיל API מזהה את הלקוח; הוא אינו מתחבר לחשבון ואינו הופך את החיבור לאנונימי.

**צריך פרוקסי קודם?**

ניתן [לבחור ולבדוק את מסלול החיבור](https://phishdestroy.github.io/TgWitness/he/docs/proxies/) לפני הכניסה. לכל חשבון יש מסלול משלו.

## בחרו מה לעקוב אחריו

1. פתח את רשימת המקורות ובחר את הצ'אטים, הקבוצות או הערוצים הדרושים לך.
2. יש לבדוק את הגדרות האיסוף, כולל קבצי מדיה, לפני תחילת המעקב.
3. הפעל את האספן ובדוק את החיבור שלו ואת הפעילות האחרונה.

על החשבון להיות בעל גישה למקור. תפקידים שונים יכולים לראות אירועים שונים; היומן משקף את מה שהחשבון הספציפי קיבל.

למקרה המשתרע על כל החשבון, השתמש ב**-Sources → Observation scope → Investigation mode**, בדוק את ההגדרות ולחץ על **Save scope**. [המדריך המלא לחקירה](https://phishdestroy.github.io/TgWitness/he/docs/cases/) מכסה את כל סוגי הצ'אטים הגלויים, היסטוריה ישנה, פרופילים של אנשים, הפניות בין צ'אטים והעברת ראיות.

## בדוק את הנתיב המלא

בקבוצת בדיקה שבשליטתכם, שלחו הודעה ייחודית מחשבון אחר, ערכו אותה ומחקו אותה. אמתו את שלושת האירועים ביומן, ולאחר מכן [ייצאו את הרישום ואמתו](https://phishdestroy.github.io/TgWitness/he/docs/exports/) אותו.

סטטוס "מחובר" מאשר את החיבור. הודעת בדיקה שנלכדה מאשרת שאירוע מסוים הגיע לסביבת העבודה הזו.

## הוסף חשבון נוסף

צרו סביבת עבודה נוספת תחת **"חשבונות**" וחזרו על תהליך ההגדרה. שמרו את טביעת האצבע של מפתח החתימה של כל חשבון, כדי שתוכלו לזהות את הייצוא שלו בהמשך.
