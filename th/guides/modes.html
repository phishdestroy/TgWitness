01

เลือกขอบเขตการสังเกต

สามขอบเขตและตั้งค่าล่วงหน้าสำหรับการสืบสวน การยกเว้นและประเภทแหล่งที่มาที่เปิดใช้งานยังคงมีผลบังคับใช้

บันทึก
ใช้เฉพาะแหล่งข้อมูลที่คัดสรรด้วยมือเท่านั้น
การสนทนาใหม่
ไม่ถูกเพิ่มอัตโนมัติ
เลือกใช้
ชุดช่องหรือกลุ่มที่ทราบกันดี ยังไม่มีการกำหนดความจุการสนทนาที่คงที่

ไม่ทำ มันไม่ค้นพบการสนทนาอื่น ๆ หรือเติมข้อมูลประวัติการสนทนาในอดีต

บันทึก
การรวมโฟลเดอร์และหมวดหมู่ โดยไม่รวมการยกเว้นและการสนทนาที่ถูกเก็บเข้าคลังเมื่อมีการกำหนดค่า
การสนทนาใหม่
การจับคู่แชทที่ใช้งานอยู่; การเปลี่ยนแปลงในโฟลเดอร์ภายในหนึ่งชั่วโมง
เลือกใช้
นักวิเคราะห์ได้จัดเก็บโฟลเดอร์คดีไว้แล้ว ยืนยันการเก็บรวบรวมข้อมูลในบัญชีที่จัดไว้เฉพาะ

ไม่ทำ มันไม่ใช้เงื่อนไขการเปลี่ยนแปลงของโฟลเดอร์ muted/read ของโฟลเดอร์

บันทึก
การสนทนาที่บัญชีสามารถเห็นได้ รวมถึงการสนทนาส่วนตัวและบอต ในประเภทที่เลือกไว้
การสนทนาใหม่
จะเพิ่มเมื่อมีการอัปเดตครั้งแรก
เลือกใช้
บัญชีการสังเกตการณ์เฉพาะทาง รวมถึงบัญชีที่เข้าร่วมในคดี

ไม่ทำ มันไม่เข้าร่วมการสนทนาอัตโนมัติหรือข้ามการเข้าถึงแหล่งข้อมูล

บันทึก
ทุกประเภทแหล่งข้อมูล, การดำเนินการของตัวเอง, โปรไฟล์แหล่งข้อมูล และข้อความ 200 ข้อความล่าสุดที่มองเห็นได้จากแหล่งข้อมูลที่เพิ่งค้นพบ
การสนทนาใหม่
การสนทนาหรือบอทใหม่จะได้รับโปรไฟล์และภาพถ่ายประวัติ
เลือกใช้
เข้าร่วมทีมหรือโต้ตอบกับบอทผ่านแผงควบคุม ตรวจสอบและบันทึกการตั้งค่าล่วงหน้า

ไม่ทำ มันไม่สร้างภาพถ่ายทุกการสนทนาที่มีอยู่ หรือติดตามการเรียกกลับที่ถูกกดในไคลเอนต์อื่น

บัตรเหล่านี้เป็นการเปรียบเทียบในระบบท้องถิ่น ไม่ใช่เครื่องมือควบคุมผู้รวบรวมข้อมูลแบบเรียลไทม์ และไม่ส่งผลต่อการเปลี่ยนแปลงบัญชี

ไม่ทำ ไม่มีโหมดใดที่อ่านการสนทนาลับ บันทึกข้อมูลขณะที่กระบวนการถูกหยุดลง เข้าร่วมแหล่งข้อมูลด้วยตนเอง หรือดึงประวัติเก่ากว่าที่ร้องขอ snapshot/export.

02

สิ่งที่ถูกบันทึก

เพียงการสังเกตการณ์ที่ส่งถึงหรือได้รับการร้องขออย่างชัดเจนเท่านั้นที่จะถูกบันทึกไว้ แหล่งที่มาที่ไม่ทราบจะยังคงไม่ทราบ

สวิตช์การจับภาพ · ภาพประกอบท้องถิ่น

แผงควบคุมจะปรับใช้สวิตช์เหล่านี้ตามแต่ละพื้นที่ทำงาน (workspace) การปิดสวิตช์หนึ่งจะรักษาบันทึกที่มีอยู่ไว้; การเปิดสวิตช์นั้นกลับจะไม่สร้างเหตุการณ์ที่พลาดไปขึ้นมาใหม่

แมทริกซ์เหตุการณ์: ข้อมูลที่บันทึกไว้และสิ่งที่ยังไม่ทราบ
หมวดหมู่บันทึกแล้วยังไม่ทราบ
ข้อความข้อความ, ID, ข้อมูลเมตาของผู้ส่ง, บริบทการตอบกลับ และซองอัปเดตต้นฉบับไม่มีลายเซ็น Telegram ที่สามารถตรวจสอบได้โดยฝ่ายที่สาม
แก้ไขทุกเวอร์ชันที่ได้รับการสังเกต โดยไม่เขียนทับเวอร์ชันก่อนหน้าการแก้ไขระหว่างทางอาจถูกมองข้าม; ผู้ส่งไม่จำเป็นต้องเป็นผู้แก้ไข
การลบข้อความแจ้งเตือน พร้อมข้อความที่บันทึกไว้ก่อนหน้านี้ (หากมี)ไม่มีการระบุผู้ลบ (deleter) และเวลาดำเนินการที่แม่นยำ
การลบที่ไม่มีขอบเขตคำเตือนระดับบัญชี; คู่ที่ไม่รู้จักยังคงถูกระบุอย่างชัดเจนไม่มีการคาดเดาการสนทนา การเชื่อมโยงข้อมูลจะใช้ ID ที่บันทึกไว้ก่อนหน้านี้ในระดับบัญชี เมื่อเป็นไปได้
ปฏิกิริยาตัวนับที่ส่งมาและตัวตนล่าสุดที่มองเห็นได้ไม่ใช่ทุกตัวรีแอคเตอร์ที่มองเห็นได้; รายชื่อทั้งหมดที่มีอยู่จำเป็นต้องใช้การค้นหาแยกต่างหาก
สมาชิกข้อความบริการที่ส่งไปแล้วและการอัปเดตของผู้เข้าร่วมบทบาทและประเภทการสนทนาจำกัดการมองเห็น; การไม่แสดงตัวไม่ได้หมายความว่าไม่ปรากฏตัว
ไฟล์แนบตัวอธิบายเวอร์ชันต้นฉบับ, ไบต์ที่บันทึกไว้, SHA-256 และผลลัพธ์ของการลองไฟล์ที่ถูกลบอาจไม่สามารถเข้าถึงได้; เวอร์ชันใหม่กว่าจะไม่แทนที่ไฟล์เดิม
ภาพถ่ายประวัติข้อความที่แสดงอยู่ปัจจุบัน ถูกทำเครื่องหมายเป็นการสังเกตประวัติการแก้ไขก่อนหน้านี้และเนื้อหาที่ถูกลบจะไม่ถูกสร้างขึ้นใหม่
การกระทำของตนเองส่งออกไป messages/edits และคีย์บอร์ดตอบกลับที่ตรงกัน button_press เมตาดาต้าการเรียกกลับ (callbacks) ที่ถูกกดในไคลเอนต์ Telegram อื่นจะไม่ปรากฏให้เห็น
ปุ่มบอทข้อมูลเมตาดาต้าของ callback, URL, web-app และคำขอจะถูกเก็บรักษาไว้พร้อมกับข้อความURL และ phone/location คำขอ เป็นข้อความ ไม่ใช่ถูกเปิดหรือดำเนินการโดยอัตโนมัติ

ดำเนินการจากแผงควบคุม

ส่งหรือตอบกลับ กดปุ่มบอตที่มีอยู่ บันทึกตัวอย่างลิงก์ แล้วเข้าร่วมแชทอย่างชัดเจน หรือเริ่มบอตด้วยพารามิเตอร์ start ของมัน

interaction.preview→interaction.requested→interaction.result

ใบยืนยันการดูตัวอย่าง การขอ และผลลัพธ์ได้รับการลงนาม ก่อนที่จะกดปุ่ม เซิร์ฟเวอร์จะดึงข้อความมาอีกครั้งและปฏิเสธการเปลี่ยนข้อมูลจากคีย์บอร์ด ข้อความ callback และ URL ที่ส่งกลับมาจะยังคงถูกบันทึกไว้ในบริบท

ไม่ทำ ไม่มีแอปเว็บ การชำระเงิน, phone/location การแชร์ หรือการสอบถามแบบอินไลน์ การแสดง URL ไม่ทำให้มันเปิดขึ้น

ช่องว่างจะถูกแสดงให้เห็น ไม่ใช่ถูกซ่อนไว้

กลับสู่ตำแหน่งที่บันทึกไว้

หลังจากรีสตาร์ท Telegram จะถูกถามถึงการอัปเดตที่พลาดไป การเก็บรักษาข้อมูลในระยะเวลาจำกัดและความแตกต่างที่หมดอายุอาจก่อให้เกิดช่องว่าง

ตรวจสอบข้อความที่แสดงอีกครั้ง

ค่าเริ่มต้น: แหล่งข้อมูลลำดับความสำคัญทุก 15 นาที ส่วนอื่นๆ ทุก 6 ชั่วโมง ผลลัพธ์รวมถึง message.recovered และ message.missing_on_recheck.

อ่าน coverage.json

ไม่ทำ ภาพถ่ายประวัติในภายหลังจะไม่ลบการหยุดทำงานหรือกู้คืนทุกเวอร์ชันที่หายไป คอร์เซอร์ที่บันทึกไว้ไม่ใช่การยืนยันการรับบันทึกแบบไม่สูญเสียข้อมูล

06

เจ็ดระดับ คำถามที่แตกต่างกัน

กลไกแต่ละกลไกตอบคำถามที่มีขอบเขตจำกัด กำหนดค่าบริการภายนอกแยกกัน และเก็บรักษาจุดยึดความเชื่อถือของบริการเหล่านั้นไว้ภายนอกตัวเก็บข้อมูล

  1. 01

    บันทึก

    SHA-256 chain + Ed25519 ต่อเหตุการณ์; ตัวแรก previous_hash คือ 64 ตัวศูนย์.

    การตรวจสอบจากฝ่ายที่สาม การจัดลำดับและลายเซ็นภายใต้กุญแจผู้รวบรวมที่ถูกตรึงไว้

    ไม่ทำ มันไม่พิสูจน์แหล่งที่มาของ Telegram หรือความครบถ้วน

    คำสั่งการตรวจสอบ
    python -m tgwitness.verify evidence.zip --fingerprint TRUSTED_SHA256
  2. 02

    Container

    manifest.json แสดงรายการแฮชของไฟล์; manifest.sig ลงนามในไฟล์นั้น. media.saved ผูกข้อมูลไบต์ของไฟล์แนบกับเหตุการณ์

    การตรวจสอบจากฝ่ายที่สาม ไฟล์ที่จัดเตรียมมาตรงกับไฟล์ manifest ที่ลงนามและใบเสร็จรับเงินสื่อ

    ไม่ทำ มันไม่ลงนามใน CSV, HTML หรือภาพหน้าจอที่ดาวน์โหลดมาแยกต่างหาก

    คำสั่งการตรวจสอบ
    python -m tgwitness.verify evidence.zip --fingerprint TRUSTED_SHA256
  3. 03

    ขอบเขตที่รักษาไว้

    จุดตรวจสอบเมื่อเริ่มต้นระบบ (checkpoint) ทุก 5 นาทีตามค่าเริ่มต้น และหยุดระบบอย่างเป็นระเบียบ เก็บสำเนาไว้ที่อื่น

    การตรวจสอบจากฝ่ายที่สาม การส่งออกในภายหลังสอดคล้องกับความยาวและส่วนหัวที่เก็บไว้ก่อนหน้านี้; สามารถตรวจพบการย้อนกลับได้

    ไม่ทำ ระบบนี้ไม่ตรวจจับการแทนที่ทั้งบันทึกและจุดตรวจสอบทั้งหมดที่เก็บไว้

    คำสั่งการตรวจสอบ
    python -m tgwitness.verify evidence.zip --fingerprint TRUSTED_SHA256 --checkpoint checkpoint.json
  4. 04

    เวลาภายนอก

    โหมดหลักฐานส่งจุดตรวจสอบ SHA-256 ไปยัง RFC 3161 หน่วยงานที่มีอำนาจ (FreeTSA, DigiCert) และ OpenTimestamps ปฏิทิน

    การตรวจสอบจากฝ่ายที่สาม การตอบกลับ TSA ที่ได้รับการยืนยันจะกำหนดวันที่ให้กับไบต์เหล่านั้น; ส่วน OpenTimestamps จะยึดตรึงไบต์เหล่านั้นกับ Bitcoin

    ไม่ทำ มันไม่ถือว่าคำขอที่เตรียมไว้หรือใบรับปฏิทินที่รอการยืนยันเป็นเวลาประทับที่ยืนยันแล้ว

    คำสั่งการตรวจสอบ
    python -m tgwitness.verify evidence.zip --fingerprint TRUSTED_SHA256 --tsa-ca trusted-ca.pem
ots upgrade checkpoint.ots
ots verify checkpoint.ots
  5. 05

    พยานอิสระ

    แยก host, จุดปลายทางอ่านอย่างเดียวที่มีขอบเขต, ความท้าทายใหม่, และ key/journal และ TGW1 โพสต์ในช่อง

    การตรวจสอบจากฝ่ายที่สาม หัวข้อที่ได้รับการยอมรับก่อนหน้านี้; สถานะ ok, key_changed, rollback, fork, invalid และ no_response.

    ไม่ทำ มันไม่เปลี่ยนพื้นที่ทำงานสองแห่งบนโฮสต์ผู้รวบรวมเดียวกันให้เป็นผู้สังเกตการณ์อิสระ

    คำสั่งการตรวจสอบ
    python -m tgwitness.verify evidence.zip --fingerprint TRUSTED_SHA256 --witness witness.zip --witness-fingerprint WITNESS_SHA256 --channel result.json
  6. 06

    สำเนาสำรองนอกเว็บไซต์

    S3- สำเนาที่เข้ากันได้ ซึ่งถูกเข้ารหัสด้วย AES-256-GCM; Object Lock เมื่อ bucket รองรับ

    การตรวจสอบจากฝ่ายที่สาม Restore จะเผยแพร่ไฟล์ก็ต่อเมื่อการตรวจสอบบันทึก จุดตรวจสอบ และสื่อที่เก็บรักษาไว้สำเร็จแล้วเท่านั้น

    ไม่ทำ ระบบจะไม่ทำการกู้คืนข้อมูลหากไม่มีกุญแจที่ส่งออก หรือสมมติว่าข้อมูลถูกเก็บรักษาไว้โดยไม่ตรวจสอบคำตอบจากระบบจัดเก็บข้อมูล

    คำสั่งการตรวจสอบ
    python -m tgwitness.replica restore --key-file KEY.json --out EMPTY_DIR
  7. 07

    ตรวจสอบที่มา

    ใบรับการรันที่ลงนาม: ค่าแฮชของแหล่งที่มา, เวอร์ชันของส่วนที่พึ่งพา และบริบทของกระบวนการ รายงานโดยตัวมันเอง

    การตรวจสอบจากฝ่ายที่สาม ข้อมูลที่ผู้รวบรวมลายเซ็นรายงานเกี่ยวกับการทำงานของตัวเอง

    ไม่ทำ มันไม่ให้การรับรองกระบวนการอย่างอิสระ หรือไม่ยกเว้นการถูกบุกรุกก่อนการบันทึก

    คำสั่งการตรวจสอบ
    python -m tgwitness.verify evidence.zip --fingerprint TRUSTED_SHA256

สิ่งที่ไม่มีระดับใดสามารถพิสูจน์ได้

การส่งมอบทุกการอัปเดตของ Telegram; ความจริงของข้อความ; ว่า ID ผู้ส่งระบุตัวบุคคลจริง; การไม่มีการละเมิดความปลอดภัยของผู้รวบรวมข้อมูลก่อนการบันทึก; ความสามารถในการรับฟังเป็นหลักฐานในศาล

เลือกเส้นทางผ่านหลักฐาน

สถานการณ์สมมติ เริ่มการเก็บข้อมูลก่อนเหตุการณ์ที่เกี่ยวข้อง; รักษาขอบเขตและช่องว่างไว้พร้อมกับเนื้อหา

01

ช่อง (channel) เปลี่ยนแปลงรายละเอียดการชำระเงิน

โหมด → เหตุการณ์
การสนทนาที่เลือก → ข้อความ, การแก้ไข, การลบ
ผลลัพธ์

ไม่ทำ มันไม่สามารถกู้คืนต้นฉบับที่ไม่เคยถูกบันทึกไว้ได้

ข้อความจะหายไปหลังจากเกิดเหตุการณ์

โหมด → เหตุการณ์
โฟลเดอร์หรือบัญชีทั้งหมด → ทุกหมวดหมู่เหตุการณ์
ผลลัพธ์

ไม่ทำ มันไม่ระบุผู้ลบจากคำแจ้งเตือนที่ไม่ได้ระบุผู้ดำเนินการ

ตรวจสอบบอทร้านค้า

โหมด → เหตุการณ์

ไม่ทำ มันไม่เปิดแอปเว็บของบอต ไม่ทำการชำระเงิน และไม่บันทึก callback ของไคลเอนต์อื่น

  • CSV

เก็บข้อจำกัดไว้พร้อมกับหลักฐาน

การตรวจสอบมีประโยชน์เมื่อขอบเขตของมันยังคงชัดเจน

  • การสนทนาลับไม่สามารถใช้งานได้
  • ไม่มีการบันทึกข้อมูลใดๆ เมื่อกระบวนการถูกหยุด; การกู้คืนมีข้อจำกัด
  • บันทึกที่ได้รับการยืนยันไม่ใช่หลักฐานว่าเนื้อหาของมันเป็นความจริง
  • ผู้ดำเนินการที่มีกุญแจสามารถลงนามเนื้อหาใดก็ได้ ผู้สังเกตการณ์อิสระและเวลาประทับช่วยจำกัดการแทนที่ในภายหลัง ไม่ใช่การบันทึกข้อมูลเริ่มต้นที่ไม่ซื่อสัตย์
  • ใช้บัญชีเฉพาะ ไม่ใช่บัญชีหลักของคุณ
  • Telegram อาจจำกัดบัญชีเนื่องจากปริมาณคำขอ

ไม่ทำ ไม่มีโหมดหรือระดับหลักฐานใดที่กำหนดความยอมรับได้ทางกฎหมาย การส่งข้อความ Telegram ที่สมบูรณ์ หรือตัวตนในโลกจริง
