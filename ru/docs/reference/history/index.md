# Загрузить историю источников

Canonical page: https://phishdestroy.github.io/TgWitness/ru/docs/reference/history/

Загрузка прошлых сообщений из включенных источников, приостановка и возобновление, а также проверка подписанного отчета о ходе работы.

[TgWitness](https://github.com/phishdestroy/TgWitness/blob/main/README.md) / [Документация](https://github.com/phishdestroy/TgWitness/blob/main/docs/README.md) · [Коллекция](https://github.com/phishdestroy/TgWitness/blob/main/docs/COLLECTION-MODES.md)

![Сборник](https://phishdestroy.github.io/TgWitness/assets/chapter-collect.svg)

В **Sources** просмотрите включенные чаты, приостановите наблюдение, выберите Стандартный API или экспорт Takeout, затем выберите **Загрузить полную историю**. Запуск фиксирует этот список источников и считывает доступные прошлые сообщения в Чаты и подписанный журнал наблюдений. Медиафайлы используют существующие настройки вложений и постоянную очередь загрузки. Это отдельно от подписанного экспорта в формате JSON/HTML для каждого чата.

Для сбора данных по всей учётной записи выберите **Вся учётная запись**, запустите наблюдение, чтобы загрузить её исходный список, и проверьте этот список перед запуском истории. Ограничение на количество диалогов в списке по-прежнему действует (по умолчанию 1,000, настраивается в Параметрах). Успешный запуск не гарантирует, что все диалоги учётной записи были включены в список. Для чатов, обнаруженных или включённых позже, требуется повторный запуск. Приостановите наблюдение перед запуском истории; одновременно сбором данных по одной учётной записи занимается только один процесс.

Выберите от одного до пяти обработчиков вложений и укажите, следует ли сохранять доступные Недавние действия и сравнивать ранее сохраненные версии. Вынос данных может потребовать утверждения в Telegram и определённого сервером времени ожидания. Эти настройки остаются неизменными при возобновлении работы. См. раздел [Поведение Backfill и Контракт доказательств](https://github.com/phishdestroy/TgWitness/blob/main/docs/BACKFILL.md) для получения подробностей о транспортировке, повторных попытках и доверии.

## Приостановка, возобновление и частичные результаты

- **Приостановить историю** останавливает чтение. **Продолжить историю** возобновляет с последнего зафиксированного сообщения в каждом источнике; при перезапуске приложения выполнение также остается приостановленным до возобновления. Для возобновления требуется тот же неактивный аккаунт Telegram.
- Наблюдение за сообщением, обработка вложений и фиксация положения курсора выполняются в одной транзакции. При возобновлении выполнения уже зафиксированные наблюдения не повторяются. В режиме реального времени или в рамках отдельного, явно запущенного цикла могут независимо наблюдаться одни и те же сообщения.
- Каждый источник (каждый разделённый диапазон Telegram в Takeout) фиксирует верхний ID сообщения при первом чтении. Более новые сообщения относятся к текущему наблюдению, а не к оставшимся историческим страницам этого источника.
- Недоступные источники и источники, отключенные во время сбора данных, остаются видимыми как «неудачные» или «пропущенные». Работа с остальными источниками продолжается; общий результат является неполным.
- Задержки FloodWait учитывают настроенный для аккаунта интервал повторных попыток. При временных сбоях повторные попытки выполняются до пяти раз; при исчерпании квоты или нехватке места на диске происходит пауза с сохранением положения курсора.
- **Завершение данного цикла истории** сохраняет сохраненные наблюдения. Оно не удаляет их и не отменяет задания по прикреплению файлов через стандартный API. Завершение Takeout помечает оставшиеся файлы Takeout как пропущенные; приостановка позволяет возобновить их обработку. Новый цикл заново считывает включенные источники.

Завершение истории описывает только чтение истории. Вложения могут оставаться в ожидании, завершиться сбоем или быть исключены в соответствии с настроенной политикой. Проверяйте подтверждения получения медиафайлов в журнале и в очереди вложений; только завершенное подтверждение с сохраненными байтами считается сохраненным вложением. Операция с историей представляет собой явный запрос на создание моментального снимка и не связана с параметрами, выбирающими категории будущих событий в режиме реального времени.

## Передача и проверка

Сохраните **подписанный отчёт о ходе работы**, а затем воспользуйтесь **функцией «Экспорт доказательств»**, чтобы загрузить журнал и сохраненные вложения. Более поздний экспорт доказательств может включать дополнительные записи; отчёт привязывает свои счетчики к префиксу журнала на момент его создания. Запустите верификатор из надёжной копии этой версии:

```
python tgwitness/verify.py tgwitness-history-report.json --evidence evidence.zip --fingerprint TRUSTED_FINGERPRINT
```

Сохраните ожидаемый отпечаток ключа подписи отдельно. Верификатор проверяет подпись отчёта, архив доказательств, контрольную точку отчёта, исходный план, учётную запись и количество сохраненных/недоступных сообщений. Новые прогоны также привязывают ход выполнения исходного плана и параметры к подписанным событиям курсора. Без параметра `--evidence` проверяется только подписанный отчёт и его внутренняя согласованность. Устаревшие поля прогресса и сводки вложений остаются подписанными заявлениями сборщика. Верификатор доказательств проверяет байты заархивированных медиафайлов.

Ни подписание, ни завершение доступной истории не доказывают происхождение из Telegram, наличие атомарного моментального снимка или историческую полноту. Сообщения могут изменяться во время чтения; удалённые сообщения и промежуточные правки, не входящие в доступные Недавние действия, а также секретные чаты, не восстанавливаются. Оператор, контролирующий ключ подписи, может сфабриковать журнал до появления внешних обязательств. Используйте отдельно сохраняемые контрольные точки или независимого свидетеля для подтверждения свойств обнаружения несанкционированного вмешательства.

Курсор сбора данных отражает состояние локальной рабочей области. Восстановление только ZIP-архива с доказательствами не приводит к восстановлению ожидающего выполнения задания на сбор данных или сеанса Telegram. Сохраните резервную копию рабочей области, если требуется продолжение выполнения исходного задания.
