# Быстрый старт TgWitness

TgWitness — самостоятельное приложение для наблюдения за группами и каналами Telegram,
к которым есть доступ у ваших аккаунтов. Оно работает локально и хранит данные в собственном каталоге.

**Впервые здесь?** [Изучите демо](#ознакомьтесь-с-интерфейсом), прежде чем подключать аккаунт.
[Выберите руководство](../README.md) по прокси, свидетелям, экспорту или настройке сервера.
[Сбор через GitHub Actions](SEALED-ACTIONS.md) (предварительная версия) выполняет сбор в вашем
собственном форке на GitHub вместо локальной установки.

## Установка и запуск

Пошаговый установщик содержит собственный Python и перед установкой проверяет хеши пакетов
и подписи выпуска. Повторный запуск обновляет существующую установку.

**Linux / macOS:**

```sh
curl -fsSL https://get.destroy.tools/install.sh | bash
```

**Windows (PowerShell или командная строка):**

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -Command "irm https://get.destroy.tools/install.ps1 | iex"
```

На сервере Ubuntu запускайте установщик от root, чтобы установить фоновую службу; на рабочем
компьютере — от обычного пользователя. В Ubuntu установщик выводит адрес панели и ключ доступа;
в macOS и Windows локальная панель открывается в браузере. Продолжайте с раздела
[«Подключитесь к Telegram»](#подключитесь-к-telegram) ниже. В руководстве
[«Установка, проверка и обновление»](../INSTALLATION.md) описаны варианты доступа к серверу,
проверка скрипта перед запуском, обновление и удаление.

### Другие способы

Альтернативы установщику — релизы GitHub, исходный код и Docker. Портативный пакет становится
доступен для загрузки после публикации сборки выпуска:

| Система | Без установленных компонентов | Из исходного кода: Python 3.11+ | Docker: Engine/Desktop с Compose 2.20+ |
| --- | --- | --- | --- |
| Windows | Распакуйте `TgWitness-<version>-windows-amd64-portable.zip` из GitHub Releases и дважды щёлкните `TgWitness.cmd` | Дважды щёлкните `Start.cmd` | Дважды щёлкните `scripts\Docker.cmd` |
| Linux / macOS | — | `sh start.sh` | `sh scripts/docker-start.sh` |

Для запуска из исходного кода [скачайте и распакуйте текущую ветку `main`](https://github.com/phishdestroy/TgWitness/archive/refs/heads/main.zip)
или клонируйте репозиторий:

```sh
git clone https://github.com/phishdestroy/TgWitness.git
cd TgWitness
```

Если подходящий Python не найден, `Start.cmd` предлагает установить Python 3.12 для вашего
пользователя Windows (через winget или подписанный установщик с python.org). Если Python
отсутствует, `start.sh` выводит точную команду установки для вашего дистрибутива Linux или macOS.
При первом запуске из исходного кода автоматически создаётся `.venv` и устанавливаются зависимости.

Docker собирает приложение и запускает его в фоне; Python на хосте не нужен. Когда контейнер
становится работоспособным, `scripts\Docker.cmd` и `scripts/docker-start.sh` выводят адрес панели
и токен. Равнозначные команды Docker для любой поддерживаемой системы:

```sh
docker compose up -d --build --wait
docker compose exec tgwitness cat /data/panel-token.txt
```

Откройте **http://127.0.0.1:8787**. Используйте токен, выведенный вспомогательным скриптом Docker
или второй командой Docker; для портативного пакета или установки из исходного кода прочитайте его
из **data/live/panel-token.txt**. Продолжайте с раздела [«Подключитесь к Telegram»](#подключитесь-к-telegram)
ниже. Установки без Docker и с Docker используют раздельные хранилища: запуск Docker не импортирует
существующий журнал установки без Docker.

Для сервера в разделе [«Развёртывание»](DEPLOYMENT.md) описаны автоматический HTTPS, перезапуск,
опубликованные образы, обновления и резервные копии.

## Ознакомьтесь с интерфейсом

1. Запустите **TgWitness-Demo.cmd** в портативном пакете, **scripts\Demo.cmd** в папке с исходным
   кодом в Windows или `sh start.sh --demo` в Linux/macOS. При запуске из исходного кода сначала
   создаётся `.venv` и устанавливаются зависимости.
2. Откройте **http://127.0.0.1:8787**.
3. Локальное демо автоматически открывает образец журнала. При прямом локальном доступе копировать
   токен не нужно.

Сообщения в демо вымышлены. В демо-режиме нельзя подключить настоящий аккаунт Telegram.

## Подключитесь к Telegram

> [!WARNING]
> **Используйте выделенные аккаунты.** Telegram может ограничить или навсегда заблокировать
> аккаунт за объём запросов, который сочтёт чрезмерным, независимо от клиента. Подключайте аккаунты,
> подготовленные для наблюдения, а не личные или ценные, и создавайте API ID / hash на выделенном
> аккаунте.

1. Если запущено демо без Docker, остановите его и запустите **Start.cmd** или `sh start.sh`.
   В остальных случаях оставьте работать рабочую установку, запущенную выше.
2. Войдите с токеном панели. В новом рабочем пространстве открывается [первая настройка](SETTINGS.md).
   Выберите **Просто скачать**, **Следить за чатами** или **Доказательства по делу**.
3. Просмотрите результат проверки подключения. При необходимости настройте собственный прокси;
   настройки подключения остаются доступны и после завершения настройки.
4. На этапе **«Подключить Telegram»** выберите номер телефона, QR-код, файлы учетной записи
   (TData, `.session`, StringSession, JSON учетной записи) или полный ключ авторизации. При
   появлении запроса пройдите подтверждение в Telegram, введите код и пароль двухэтапной
   аутентификации.
5. Проверьте показанный аккаунт, выберите чаты и просмотрите настройки. Завершите настройку
   на последнем экране. В режиме **Просто скачать** кнопка **Начать экспорт** запускает разовый
   экспорт и открывает раздел «Экспорт» с его ходом; постоянное наблюдение при этом не включается.

После настройки выбранные чаты меняются в **Чаты → Выбрать**. **Настройки** управляют сбором
и файлами; подробный список источников находится в **Инструменты → Источники** на уровне
«Обычный» или «Эксперт». [Руководство по панели](../PANEL.md) описывает шесть основных
разделов и их контекстные элементы управления.

Поле **Идентификатор API + хеш** заполнять не обязательно: рабочее пространство использует
сохранённую или импортированную пару либо рабочую пару из встроенного пула. Чтобы использовать
собственное приложение, вставьте одну пару `API ID:API Hash` в поле «Идентификатор API». Для способа
**Ключ аутентификации** вставьте все 512 шестнадцатеричных символов и выберите DC ID, полученный
вместе с ключом. Поле «Идентификатор пользователя» необязательно; если оно заполнено, значение проверяется.

Учётные данные API идентифицируют ваше приложение; сами по себе они не авторизуют аккаунт.
Закрытым группам не нужно публичное имя пользователя, но у вашего аккаунта должен быть к ним доступ.

Для существующих аккаунтов см. [аккаунты и форматы сессий](../ACCOUNTS.md): панель принимает
Telethon StringSession, SQLite-сессии Telethon/Pyrogram, ZIP с TData одного аккаунта
и поддерживаемый JSON аккаунта. Выберите сессию вместе с сопутствующим JSON и нажмите
**Подключить аккаунт**. Вход по QR-коду также
доступен с теми же необязательными настройками API. TDLib, сессии ботов и списки аккаунтов
в CSV/JSON не поддерживаются.

Для нескольких аккаунтов откройте **Аккаунты → Импорт аккаунтов** и выберите их поддерживаемые
файлы сессий. Сопутствующие JSON-файлы сопоставляются по имени без расширения; каждый
импортированный аккаунт получает собственное рабочее пространство. См.
[пакетный импорт и группы аккаунтов](../ACCOUNTS.md#bulk-import-and-account-groups).

Чтобы добавить ещё один аккаунт, нажмите **+** рядом с переключателем аккаунтов или откройте
**Аккаунты → Добавить аккаунт**. У рабочих пространств раздельные сессии,
журналы, ключи, источники и очереди. Переключение просмотра не останавливает другие коллекторы.
Один и тот же аккаунт Telegram нельзя назначить двум рабочим пространствам в одной установке.
Фиксированного предела числа рабочих пространств нет; они работают в одном процессе, поэтому
их количество ограничено возможностями компьютера.

Токен панели рабочей установки защищает доступ к вашим авторизациям Telegram и сохранённым
материалам; он не связан с учётными данными Telegram API. Автоматический вход есть только
у явно запущенного локального демо при прямом доступе. Удалённое демо или демо за прокси
по-прежнему использует `data/demo/panel-token.txt`.

## Просмотр и экспорт

- **Журнал:** поиск и фильтрация наблюдений по источнику и типу события.
- Выберите событие, чтобы посмотреть исходную запись, атрибуцию и сохранённые версии.
- Сведения о правке показывают доступное содержимое до и после изменения. Сведения об удалении
  показывают последнее захваченное содержимое, если оно есть; неизвестный исполнитель остаётся неизвестным.
- **Экспорт:** подписанный ZIP, JSONL, CSV и автономный HTML.
- **Полный экспорт чата** (**Чаты → Экспорт чата** или **Экспорт → Сбор или экспорт одного
  чата**): скачивание всей видимой
  истории одного чата в виде подписанного пакета с `chat.json` (в стиле экспорта Telegram) и читаемым
  `chat.html`. Закрытые чаты доступны, если аккаунт в них состоит. Это текущий
  снимок, а не восстановление удалённых или ранее отредактированных сообщений. Проверьте
  копию командой `python verify.py chat-export.zip --fingerprint TRUSTED_SHA256`.
- **Сохраните контрольную точку:** хранить подписанную границу журнала вне коллектора.
- **Скачайте подписанную квитанцию о выполнении:** сохранить запись о программе и версии коллектора.
- **Подготовьте запрос на установку временной метки:** подготовить автономный запрос к службе
  меток времени; чтобы получить и проверить ответ, следуйте [TIMESTAMP.md](../TIMESTAMP.md).
- **Проверьте журнал:** проверить подписи событий и связи цепочки. При экспорте в ZIP проверяются
  и медиафайлы.

Поддерживаемые браузеры сохраняют большие экспорты сразу в выбранный файл. Другие браузеры
буферизуют не более 128 МиБ. Пока сервер работает, потоковый CLI позволяет скачивать файлы
большего размера без буферизации всего ответа:

```sh
python -m tgwitness.download --token-file data/live/panel-token.txt --out evidence.zip
```

Для другого рабочего пространства добавьте `--profile ID`, взяв ID из **Экспорт → Идентификатор рабочей области**.
Для удалённого сервера добавьте `--url https://your-server`. Лимит передачи по умолчанию —
5 ГиБ; его меняет `--max-mib`. Для содержимого подписанного ZIP по умолчанию действует отдельный
лимит проверки — 4 ГиБ в распакованном виде (его повышают в **Инструменты → Параметры**; такие
архивы проверяйте с `verify.py --max-gib N`). Проверяйте архив доверенной копией верификатора,
с независимо сохранённым отпечатком ключа и — для выполнения минимальных требований к доказательствам —
с корневым сертификатом службы меток времени (`--tsa-ca`).

## Проверьте установку

```sh
python start.py --setup-only
python start.py --check
python start.py --check --json
```

Проверка `--check` оценивает локальные зависимости, поддержку подписи, хранилище, конфигурацию
ключей и адрес прослушивания. Она ничего не устанавливает и не подключается к Telegram. Занятый
порт может означать, что уже работает другой экземпляр. Укажите другой `--port` или сначала
остановите его.

Скрипт запуска устанавливает всё в `.venv`. Вспомогательные команды `python -m tgwitness...`
нужно выполнять через `.venv\Scripts\python.exe` в Windows или `.venv/bin/python` в Linux/macOS,
если это окружение ещё не активировано.

## Сессии, защита и эксплуатация

Закрытый файл Telethon SQLite `.session` в согласованном состоянии можно локально преобразовать
командой `python -m tgwitness.sessions account.session --out account.tgwitness-session`, а затем
загрузить в **Инструменты → Аккаунт → Файлы**. Также доступны прямой импорт файла и вход по QR-коду.
Форматы входа, SOCKS5, HTTP CONNECT, MTProxy и внешние мастер-ключи описаны
в [CONNECTION-SECURITY.md](../CONNECTION-SECURITY.md).

Кнопка **Приостановите наблюдение** останавливает сбор. **Блокировка** только закрывает доступ
из браузера. Закрытие вкладки не останавливает процесс коллектора. Остановка процесса прерывает
сбор; снимок истории не может восстановить все пропущенные правки и удаления.
Политики событий, очереди вложений, изоляция аккаунтов и поведение при перезапуске описаны
в разделе [«Как работает сбор»](../COLLECTION.md).

Сессии и секреты хранятся в зашифрованном виде. Для содержимого сообщений, медиафайлов
и экспортов нужен зашифрованный диск или том. Проверяйте подписи журнала по доверенному ключу
и храните контрольные точки отдельно. Изучайте записи о сборе, квитанции внешнего времени
и аттестации среды для выбранного режима сбора.

Резервное копирование и восстановление описаны в [OPERATIONS.md](../OPERATIONS.md), размещение
на сервере — в [DEPLOYMENT.md](DEPLOYMENT.md), примеры служб — в [deploy/](../../deploy/README.md).
Установленная панель также содержит автономное руководство по настройке по адресу `/guide.html`.

Фактически выполненные проверки и оставшиеся ограничения записаны
в [VERIFICATION.md](../VERIFICATION.md) и [READINESS.md](../internal/READINESS.md).
