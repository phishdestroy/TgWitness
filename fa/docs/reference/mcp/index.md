# MCP فقط-خواندنی

Canonical page: https://phishdestroy.github.io/TgWitness/fa/docs/reference/mcp/

یک کلاینت MCP را به فضاهای کاری و چت‌های منتخب با دسترسی منقضی‌شونده و قابل فسخ متصل کنید.

**نسخهٔ اصلی کنونی:** از نسخهٔ سورس استفاده کنید؛ پیش‌نمایش قابل‌حمل نسخهٔ ۰.۷.۰ پیش از این قابلیت عرضه شده است.

[راهنمای گردش کار](https://phishdestroy.github.io/TgWitness/docs/archive/) · [ویکی](https://github.com/phishdestroy/TgWitness/blob/main/docs/wiki/Archive-and-Integrations.md)

سرور اختیاری را از دایرکتوری پروژه TgWitness نصب کنید:

```
python -m pip install '.[mcp]'
```

در پنل، **«ادغام‌ها» → «MCP»**را باز کنید. برای اتصال یک نام انتخاب کنید، فضای کاری‌ها و چت‌های آن را مشخص کرده و یک تاریخ انقضا تعیین کنید. توکن آرشیو را یک‌بار کپی کنید؛ زیرا بعداً قابل بازیابی نخواهد بود. توکن‌های گم‌شده را لغو کرده و جایگزین‌های جدیدی صادر کنید. توکن‌های پنل و اطلاعات ورود به تلگرام، اطلاعات ورود به MCP محسوب نمی‌شوند.

## اتصال یک کلاینت

پنل با استفاده از [پیکربندی مستندشده](https://code.visualstudio.com/docs/agents/reference/mcp-configuration) خود، توکن `.vscode/mcp.json` را برای **محیط Local VS Code** تولید می‌کند. فایل دانلود شده را در آن مکان ذخیره کنید، **دستور MCP: List Servers را** اجرا کرده و TgWitness را راه‌اندازی کنید. VS Code از طریق ورودی رمز عبور، توکن را درخواست می‌کند. فایل JSON دانلود شده حاوی یک شناسه درخواست است، نه خود توکن. از فایل اجرایی پایتون موجود در محیطی که MCP extra در آن نصب شده است، استفاده کنید.

برای سایر مشتریان stdio، اجرا کنید:

```
python -m tgwitness.mcp_server --api-url http://127.0.0.1:8787
```

`TGWITNESS_ARCHIVE_TOKEN` را در محیط محافظت‌شده کلاینت تنظیم کنید. آن را در آرگومان‌های فرمان یا URLها قرار ندهید. پل از طریق API آرشیو مجاز پنل می‌خواند؛ دسترسی مستقیمی به پایگاه داده ندارد. خروجی استاندارد (Stdout) فقط پیام‌های MCP را منتقل می‌کند.

برای مشتریان راه دور، سرویس را در کنار پنل اجرا کنید:

```
python -m tgwitness.mcp_server --transport streamable-http \
  --api-url http://127.0.0.1:8787 --port 8766 \
  --public-url https://archive.example.org/mcp
```

ترافیک `/mcp` را از طریق یک پروکسی معکوس HTTPS به `127.0.0.1:8766/mcp` فوروارد کنید و هدر `Authorization: Bearer …` را حفظ نمایید. ثبت‌گذاری (لگینگ) هدرهای احراز هویت و بدنه درخواست/پاسخ را غیرفعال کنید. اتصال به خارج از لوپ‌بک (loopback) را تنها در صورت لزوم با استفاده از `--host` و `--public-url` برقرار کنید. این نقطه پایانی از Streamable HTTP در [SDK پایتون رسمی MCP](https://github.com/modelcontextprotocol/python-sdk) استفاده می‌کند. این قابلیت، اعتبارنامه‌های حمل‌کننده‌ی پیکربندی‌شده به صورت صریح را پشتیبانی می‌کند، نه کشف OAuth؛ کلاینت‌هایی که تنها به OAuth نیاز دارند، پشتیبانی نمی‌شوند.

**پروتکل بررسی و دسترسی،** یک کلاینت واقعی MCP را راه‌اندازی کرده و ابزارها را فهرست می‌کند. این کار پیام‌ها را دریافت نمی‌کند. برای بررسی از راه دور، سرور MCP انتخاب‌شده توکن آرشیو را دریافت می‌کند. تنها سروری را پیکربندی کنید که خودتان اداره می‌کنید یا در آن با این دامنه اعتماد دارید.

## دامنه و نتایج

ابزارهای موجود: `list_workspaces`، `list_chats`، `search_messages`، `get_message_versions`، `get_message_context`، `get_journal_event` و `get_capture_status`. هیچ اقدام تلگرامی، تغییر پیکربندی، یا ابزار خروجی‌گیری انبوهی وجود ندارد. هر بار خواندن، دسترسی به فضای کاری/چت را مجدداً بررسی می‌کند؛ اعتبارنامه‌های منقضی شده و لغو شده از کار می‌افتند. محدودیت‌ها عبارتند از ۶۰ درخواست API در دقیقه برای هر اعتبارنامه، ۵۰ رکورد در هر صفحه، یک پاسخ ۶۴ کیلوبایتی، و مهلت هشت ثانیه‌ای برای API.

نتایج پیام شامل فضای کاری، شناسه‌های چت/پیام، توالی رویدادها، هش ذخیره شده و یک لینک پنل است. کاربری که لینک را باز می‌کند باید جلسه پنل مجاز خود را داشته باشد. اشیاء خام تلگرام، هش‌های دسترسی، ارجاعات فایل، محتوای جلسه و کلیدها حذف شده‌اند. جستجو متن پیام را بررسی می‌کند، نه فیلدهای خام را. متن محدود است و قطع شدن مشخص می‌شود. ویرایش‌ها، اعلان‌های حذف تلگرام و `missing_on_recheck` به عنوان مشاهدات جداگانه باقی می‌مانند. دسترسی در محدوده چت نمی‌تواند رویدادهای عملیاتی در سراسر فضای کاری را مشاهده کند؛ وضعیت ضبط به صراحت این محدودیت را مشخص می‌کند.

متن بایگانی ورودی غیرقابل اعتمادی است. دستورالعمل‌های داخل پیام‌ها هیچ دامنه اضافی را فراهم نمی‌کنند و نباید به‌عنوان دستورالعمل‌های کلاینت در نظر گرفته شوند. یک مدل هوش مصنوعی خارجی ممکن است هر محتوایی را که کلاینت MCP آن درخواست می‌کند، دریافت کند. دسترسی فقط-خواندن از تغییرات بایگانی جلوگیری می‌کند؛ اما مانع از نگهداری داده‌هایی که کلاینت می‌خواند توسط آن نمی‌شود.

هش‌ها، سوابق ذخیره‌شده را شناسایی کرده و از بررسی‌های یکپارچگی پشتیبانی می‌کنند. آن‌ها به طور مستقل، اصالت فرستنده تلگرام یا ثبت شدن تمام پیام‌ها را اثبات نمی‌کنند.
