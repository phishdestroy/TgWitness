# จัดการกับคลังข้อมูล

Canonical page: https://phishdestroy.github.io/TgWitness/th/docs/archive/

ค้นหาข้อความ ตรวจสอบแหล่งที่มา สร้างคดี

เครื่องมือเหล่านี้มีพร้อมใช้งานในสาขาหลักปัจจุบัน (main branch) เวอร์ชัน 0.7.0 portable preview ออกมาก่อนเวอร์ชันปัจจุบัน ดังนั้น ให้ใช้การเช็คเอาต์จากซอร์สโค้ด (source checkout) สำหรับกระบวนการทำงานนี้

01**นำประวัติมา**

โหลดข้อความที่ผ่านมาจากแหล่งข้อมูลที่เปิดใช้งานแล้วเข้าสู่พื้นที่ทำงาน

02**ติดตามแหล่งข้อมูล**

ค้นหาในคลังข้อมูลและเปิดข้อความที่บันทึกไว้ที่อยู่เบื้องหลังแต่ละผลลัพธ์

03**ให้กระบวนการส่งต่องานชัดเจน**

บันทึกการวิเคราะห์ของคุณไว้อย่างแยกต่างหาก และส่งออกหลักฐานที่ลงนามไว้พร้อมกับมัน

ข้อมูลที่บันทึกไว้ ข้อความที่ได้รับการระบุ และข้อสรุปของนักวิเคราะห์ จะถูกแยกไว้อย่างชัดเจน

## โหลดข้อความที่ผ่านมา

1. **แหล่งข้อมูล**เปิด (Open **Sources)**, ตรวจสอบการสนทนาที่เปิดใช้งานแล้ว และเริ่มการสังเกตการณ์
2. เลือก **“โหลดประวัติทั้งหมด**” (**Load full history**) การดำเนินการครั้งนี้จะใช้รายชื่อแหล่งที่มาที่เลือกไว้ในขณะนั้น
3. ใช้ "**หยุดประวัติ"** และ "**ต่อประวัติ**" ตามความจำเป็น หลังจากรีสตาร์ท ให้ดำเนินการต่ออย่างชัดเจน
4. ตรวจสอบผลลัพธ์ตามแหล่งข้อมูลและคิวไฟล์แนบ บันทึกรายงานความคืบหน้าที่ลงนามไว้พร้อมกับการส่งออกหลักฐาน

การนี้จะแสดงข้อความที่มีอยู่ทั้งหมดในพื้นที่ทำงาน การส่งออก HTML/JSON ตามแต่ละแชทเป็นกระบวนการที่แยกต่างหาก [รายละเอียดเกี่ยวกับประวัติและการกู้คืน](https://phishdestroy.github.io/TgWitness/th/docs/reference/history/)

## ค้นหาข้อมูลก่อน แล้วจึงตัดสินใจเกี่ยวกับ AI

1. เปิด **Ask the archive**. เลือกพื้นที่ทำงาน, การสนทนา และช่วงเวลาการสังเกตการณ์
2. ค้นหาวลี โดเมน หรือ ID ข้อความ เปิดบันทึกที่ตรงกับคำค้นหาและเวอร์ชันที่บันทึกไว้
3. สำหรับการวิเคราะห์ด้วย AI ผู้ดูแลระบบต้องตั้งค่าผู้ให้บริการก่อน จากนั้นตรวจสอบ**ข้อมูลที่ส่งไปยังโมเดล** และยกเลิกการเลือกส่วนที่ไม่ต้องการก่อนที่จะอนุมัติคำขอ
4. ตรวจสอบการอ้างอิงที่ระบบส่งกลับมา บันทึกคำตอบเป็นรายงาน และเพิ่มการแก้ไขหรือหมายเหตุของคุณเอง

การค้นหาดำเนินการในระบบท้องถิ่นโดยไม่ใช้ AI รายงานวิเคราะห์เก็บรักษาข้อมูลอ้างอิงแหล่งที่มาและประวัติการแก้ไข; รายงานเหล่านี้แยกต่างหากจากบันทึกที่ลงนามแล้ว [การตั้งค่าผู้ให้บริการและรายงาน](https://phishdestroy.github.io/TgWitness/th/docs/reference/analysis/)

## เลือกการเชื่อมต่อที่คุณต้องการ

| งาน | เปิด | การตั้งค่า |
| --- | --- | --- |
| อ่านบทสนทนาที่เลือกจากไคลเอนต์ AI | **การบูรณาการ → MCP** | [ติดตั้ง MCP extra, สร้างโทเค็นที่มีขอบเขตการใช้งาน และเชื่อมต่อไคลเอนต์](https://phishdestroy.github.io/TgWitness/th/docs/reference/mcp/) |
| ระบุข้อความในสื่อที่บันทึกไว้ | บันทึก`media.saved` → **ระบุไฟล์แนบ** | [ตั้งค่า Docker worker ท้องถิ่นและไฟล์ภาษา/โมเดลที่จำเป็น](https://phishdestroy.github.io/TgWitness/th/docs/reference/media-analysis/) |
| ส่งเหตุการณ์ไปยัง n8n หรือ SIEM | **การบูรณาการ → Webhooks ส่งออก** | [เพิ่มผู้รับ, ตรวจสอบ HMAC และลบข้อมูลซ้ำของ ID เหตุการณ์](https://phishdestroy.github.io/TgWitness/th/docs/reference/webhooks/) |

**โทเค็นการเข้าถึงใดใช้สำหรับส่วนใด?**

การเข้าถึงแผงควบคุม (Panel) เป็นสำหรับผู้ตรวจสอบคดี ผู้ใช้ MCP จะได้รับโทเค็นเก็บถาวรแบบอ่านอย่างเดียว (read-only) แยกต่างหาก ตัวรับเว็บฮุค (webhook receiver) ใช้ HMAC secret ของตัวเอง ไม่มีใครจำเป็นต้องใช้ไฟล์เซสชัน Telegram

[แชร์สิทธิ์การเข้าถึงแผง](https://phishdestroy.github.io/TgWitness/th/docs/access/)ควบคุมหรือ[กำหนดค่าไคลเอนต์ MCP](https://phishdestroy.github.io/TgWitness/th/docs/reference/mcp/)

## ส่งต่อแหล่งข้อมูลและข้อสรุป

เก็บรายงานวิเคราะห์ที่ได้รับการตรวจสอบไว้พร้อมกับไฟล์ ZIP ของหลักฐานที่ลงนามแล้ว รายงานนี้อธิบายการตีความของคุณต่อแหล่งข้อมูล ส่วนไฟล์ ZIP ช่วยให้ผู้รับสามารถตรวจสอบบันทึกที่เก็บไว้กับลายนิ้วมือและจุดตรวจสอบที่ได้รับการเชื่อถืออย่างอิสระ
