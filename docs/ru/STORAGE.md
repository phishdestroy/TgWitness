# Хранение и восстановление

Панель выделяет три задачи:

| Задача | Что она делает |
| --- | --- |
| Создание резервной копии | Копирование подписанного журнала, контрольных точек, сохраненных файлов и экспортов в очереди в настроенное хранилище S3. |
| Освобождение места на локальном диске | Скопируйте выбранные старые вложения в S3 или на удалённый облачный сервер rclone, полностью загрузите их обратно, проверьте зашифрованные байты, а затем удалите проверенную локальную копию. |
| Сохранение копии для доказательств | Настройте функцию S3 Object Lock и проверьте возвращённый статус хранения. Сервис должен подтвердить запрошенный режим и дату. |

Освобождение места никогда не приводит к удалению или перезаписи подписанного журнала. Каждое вложение сохраняет свой исходный SHA-256 и квитанцию восстановления. До аутентифицированного шифрования может производиться сжатие gzip (по желанию). Имена файлов в облаке не содержат имен Telegram, идентификаторов чатов или исходных имен вложений. Размер одного вложения может составлять до 32 ГиБ.

Сам по себе ответ на загрузку не является разрешением на удаление файла. TgWitness загружает полный зашифрованный объект, проверяет его размер и SHA-256, сохраняет квитанцию, а затем непосредственно перед удалением ещё раз проверяет локальные байты. Сбой загрузки, несовпадение при повторном чтении или отмена передачи приводят к тому, что локальный файл остаётся на месте. Если включённая резервная копия доказательств ещё не скопировала данный файл, удаление также откладывается до её завершения.

<a id="when-the-disk-is-filling-up"></a>
## Когда диск заполняется

Загрузка вложений уже приостанавливается при достижении значения**,** указанного в **разделе Дополнительные инструменты → Параметры → Фотографии и файлы → Приостанавливать загрузку при достижении этого значения свободного места на диске** (по умолчанию — 1 ГБ), при этом очередь загрузок сохраняется. Наблюдение текста продолжается. Это не зависит от настроек уведомлений. Отключение уведомлений не отключает резерв загрузки или меры защиты хранилища.

Для более раннего вмешательства включите параметр **Запускать автоматически**, выберите **Удалять локальный файл для освобождения места** и включите **Запускать дополнительный цикл переноса данных при нехватке места на диске**. По умолчанию это дополнительное правило запускается при уровне свободного места ниже 5120 MiB и продолжается партиями до тех пор, пока не будет освобождено 10240 MiB. Оба пороговых значения настраиваются. Оно использует те же условия, что и ручной цикл: место назначения, минимальный возраст файла, ограничение на партию, полную проверку обратного считывания и резервное копирование доказательств. Оно никогда не активирует место назначения самостоятельно. Проверки выполняются каждые 30 секунд; ошибка или отсутствие прогресса приостанавливают следующий цикл сжатия на пять минут. Состояние сжатия и время повторной попытки сохраняются после перезапуска. Запланированные циклы по-прежнему используют свой обычный интервал, когда правило сжатия неактивно.

На панели отображаются свободное пространство, резерв для упаковки, информация о том, включено ли правило «под давлением», а также файлы, пропущенные из-за нехватки временного пространства. Процессы упаковки и восстановления проверяют пиковые требования к временному пространству перед запуском и отслеживают доступное пространство во время записи. Этот резерв соответствует настроенному резерву для загрузки, минимальный размер которого для операций хранения составляет 64 МБ. Данные проверки не являются квотой файловой системы; другой процесс по-прежнему может занимать место между проверками.

Сжатие Gzip является сжатием без потерь и применяется к удалённым объектам; оно не уменьшает размер активного журнала и не создаёт локальных архивов. Размер файлов в форматах JPEG, видео и ZIP может практически не измениться или незначительно увеличиться. При включённом сжатии текущему конвейеру упаковки может временно потребоваться пространство, равное примерно удвоенному размеру вложения плюс резерв. Выберите начальный порог достаточно рано с учётом ваших самых больших файлов. Файл, размер которого превышает допустимый для подготовки, сохраняется и фиксируется в отчёте; меньшие по размеру файлы и ранее проверенные удалённые копии по-прежнему могут освободить место. Проверенную копию можно перенести без создания дополнительного локального файла упаковки. Для восстановления также требуется временное пространство, и в восстановлении может быть отказано до тех пор, пока не появится свободное место.

Если нет подходящих для перемещения файлов или не настроено место назначения, TgWitness не может автоматически освободить место. Подписанный журнал никогда не подвергается очистке или перезаписи системой управления хранением. Ему по-прежнему требуется место для новых текстовых наблюдений.

Рабочие области на одном сервере используют одинаковые вложения. Сохраненный файл получает имя по своему SHA-256; если в другой рабочей области на этом же сервере уже имеется такой же файл в каталоге `cas/` каталога данных, новая копия заменяется жесткой ссылкой на него после повторного вычисления хешей обоих файлов, благодаря чему три рабочие области, сохраняющие один и тот же канал, используют дисковое пространство, занимаемое одной копией. Каждая рабочая область по-прежнему имеет собственный файл в каталоге `media/` и читает, экспортирует и выгружает его, как и раньше. Файл, на который невозможно создать ссылку (например, в файловой системе без жестких ссылок), остаётся отдельной копией. При каждом запуске TgWitness удаляет из каталога `cas/` только те файлы, на которые больше не ссылается ни одна рабочая область; файлы рабочих областей никогда не удаляются в ходе этого шага.

<a id="connect-a-destination"></a>
## Подключение места назначения

В разделе **Дополнительные инструменты → Дополнительные функции → Хранение и дисковое пространство → Управление хранением** выберите задачу и место назначения, сохраните настройки, а затем выберите **Тестовая загрузка и скачивание**. В ходе теста загружается небольшой случайный тестовый файл, который затем считывается обратно. При этом не используется контент Telegram.

Для S3 используйте фактический конечный пункт, регион и корзину поставщика. Wasabi, Backblaze, Cloudflare R2 и другие совместимые сервисы используют те же настройки S3. Наличие совместимого API само по себе не означает поддержку Object Lock. Режим «Управление» может позволять авторизованному администратору обойти требования к хранению; режим «Соответствие» имеет иные ограничения. Перед тем как полагаться на сроки хранения, ознакомьтесь с возвращённым статусом Object Lock.

Для назначения rclone создайте один удалённый ресурс с помощью настройки провайдера в rclone и вставьте раздел `[name]` этого удалённого ресурса в панель. Установленный помощник поддерживает MEGA, Google Drive, OneDrive, Dropbox, Box, pCloud и других провайдеров, отображаемых в списке выбора. Учетные данные сохраняются в зашифрованном хранилище данной рабочей области. Данные обновления OAuth сохраняются обратно в хранилище. Учетные данные не добавляются в события журнала и не включаются в загрузки при восстановлении.

Вспомогательная программа устанавливается внутри рабочей области с закреплённой версией и контрольной суммой SHA-256. Она не добавляется в системную переменную PATH. Файлы конфигурации и рабочие файлы являются временными файлами внутри данной рабочей области. Удалённые серверы, основанные на командах или локальных файлах, не допускаются. В настоящее время rclone требует явно выбранного маршрута **Direct** для внешних запросов. Используйте собственное хранилище S3 для маршрута SOCKS5 или HTTP рабочей области; rclone не обходит недоступный маршрут в фоновом режиме.

<a id="keep-the-recovery-file"></a>
## Сохраните файл восстановления

Выберите **Сохранить файл восстановления** после копирования файлов и храните его отдельно от установки. Он содержит ключ дешифрования и подписанные квитанции объектов, поэтому относитесь к нему как к резервной копии секретного ключа. Также храните исходную конфигурацию удалённого сервера и учетные данные назначения отдельно. Файл восстановления, созданный до последующей копии, не содержит квитанцию этой последующей копии.

Запишите отпечаток ключа подписи отдельно: сверка подписи с этим отпечатком позволяет определить, кому принадлежит данный файл восстановления.

Чтобы восстановить отсутствующие квитанции хранения в существующей рабочей области, откройте **пункт Восстановить файлы из сохраненного файла восстановления** и выберите нужный файл. Панель проверит подпись и потребует ввода того же ключа подписи рабочей области. Система не допустит замены другого ключа хранения. Затем выберите **Восстановить все файлы**. Восстановление приостанавливает действие автоматического правила хранения, чтобы следующий запланированный цикл не смог сразу же снова удалить восстановленные файлы. Включите правило заново после завершения работы с локальными копиями.

В процессе восстановления проверяется зашифрованный текст, осуществляется аутентификация дешифрования, при необходимости выполняется распаковка, а также проверяется исходный открытый текст по SHA-256 перед размещением файла в папке `media/`. Повреждённый удалённый объект никогда не заменяет локальный файл. При импорте файла восстановления локальный файл считается присутствующим только в том случае, если его размер и хеш SHA-256 совпадают с данными квитанции; поэтому **команда Восстановить все файлы** восстанавливает даже локальный файл, байты которого отличаются. Эти байты не перезаписываются: как только проверенная копия будет готова, они перемещаются без изменений в папку `storage-conflicts/EXPECTED_SHA256.LOCAL_SHA256`, в журнале регистрируется событие `storage.local_conflict`, а в результатах восстановления перечисляются все конфликты. На панели «Хранение» отображается количество файлов, хранящихся в папке `storage-conflicts/`, а также перечисляются первые 20 из них с указанием их размера; команда `recover` выводит информацию о каждом конфликте с указанием обоих хешей и соответствующего пути. До тех пор, пока такой файл не будет восстановлен, при полном экспорте доказательств вам будет предложено сначала восстановить все файлы.

<a id="recover-after-losing-the-installation"></a>
## Восстановление после потери установки

Установите TgWitness на другом компьютере. Используйте частный файл восстановления, отдельно записанный отпечаток и исходные учетные данные места назначения:

```sh
python -m tgwitness.storage recover \
  --recovery storage-recovery.json \
  --fingerprint TRUSTED_WORKSPACE_SHA256 \
  --credentials original-rclone.conf \
  --output recovered-attachments
```

Для S3 параметр ``--credentials`` указывает на частный JSON-файл с ключами ``access_key`` и ``secret_key``; подписанный файл восстановления предоставляет настройки места назначения. Команда использует прямое внешнее соединение и загружает закреплённый вспомогательный модуль, когда это требуется удалённому серверу rclone. Она отклоняет существующий каталог вывода, если в этом каталоге находится прерванный процесс восстановления из того же подписанного файла восстановления; повторный запуск команды сохраняет проверенные файлы и продолжает работу с остальными.

Восстановленные исходные байты записываются в каталог `recovered-attachments/media/` с именами, соответствующими их SHA-256. Файл `recovery-log.jsonl` представляет собой неподписанную запись операций восстановления. Команда не восстанавливает утраченный подписанный журнал или его ключ подписи. Для этих целей следует хранить полную резервную копию рабочей области. Файл восстановления хранилища не является полной резервной копией рабочей области.

<a id="operator-bot-and-completion-notices"></a>
## Бот-оператор и уведомления о завершении

Бот в Telegram принадлежит оператору. Создайте его с помощью BotFather и настройте в панели его токен, целевой чат и явный список разрешённых идентификаторов пользователей Telegram. Отправитель и чат должны совпадать. Пересланные сообщения и команды от других ботов игнорируются.

Команды `/status` и `/stats` доступны в режиме «только статус» по умолчанию. Дополнительный режим управления добавляет команды `/pause`, `/resume` и `/copy`. Команда `/copy` запрашивает настроенную задачу хранения; это не означает, что удалённая загрузка уже завершилась. Команды не могут содержать произвольные URL-адреса, файлы или программы оболочки.

Используйте отдельные настройки уведомлений для оповещений и завершения задач. Уведомления о завершении различают экспорт аккаунтов с пробелами и полный экспорт, а также отображают историю и количество записей в хранилище. Выдержки из сообщений не включаются, если это не включено отдельно в настройках уведомлений. Список сервисов формируется на основе фактически установленного каталога Apprise, а не фиксированного набора примеров провайдеров.
