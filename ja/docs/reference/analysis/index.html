アーカイブ分析

保存されたメッセージを検索し、AIの入力内容を検証し、出典情報を記載した分析レポートを管理できます。

現在のメインバージョン：ソースコードをチェックアウトして使用してください。0.7.0のポータブルプレビュー版には、この機能が実装されていません。

ワークフローガイド · Wiki

AIを使用しないローカル検索にはジャーナルを使用します。アーカイブに問い合わせるを使用するには、まず連携機能でプロバイダーを有効化して設定してください。ワークスペースセレクターでアカウントを選択し、 フォームでチャットと監視期間を選択します。取得処理はローカルで実行されます。 完全一致のフレーズやドメインで取得対象を絞り込み、メッセージIDを指定すると保存された バージョンを取得します。抜粋を確認し、そのジャーナル記録や文脈を開いてください。 ベクトルデータベースやTelegramに対する自動操作はありません。

プロバイダーおよび同意#

AI機能は、すべてのワークスペースで初期状態では無効になっています。モデル、エンドポイント、暗号化されたAPIキー、コンテキスト／出力の制限、タイムアウト、および1日あたりの リクエスト上限の設定は、メイン管理者のみが変更可能です。キーはブラウザに返されることはありません。現在のキーを維持するには、キーフィールドを空白のままにしておくか、 明示的に削除してください。

Ollamaは、ドキュメントに記載された/api/chatエンドポイントを使用し、 ストリーミング形式ではないJSON出力を生成します。デフォルトのアドレスは、 TgWitnessサーバー上のhttp://127.0.0.1:11434です。オペレーターは TGWITNESS_AI_LOCAL_ENDPOINTを使用してこれを変更できます。これはモデルによって制御されるアドレスではありません。選択したモデルは ご自身でインストールしてください。TgWitnessは自動的にダウンロードしません。

互換性のあるプロバイダーは、/v1 で終わるベース URL および Chat Completions プロトコル（ messages、JSON レスポンスモード、max_completion_tokens、 choices[0].message.content）に対応している必要があります。これらのフィールドがないサービスはサポートされません。 接続テストでは合成テキストが送信され、リクエスト予算にカウントされます。

すべてのリクエストは、ワークスペースで設定された外部ルートを使用します。 ルートがブロックされている場合や、 Telegram専用のMTProxyが使用されている場合はエラーとなり、直接的な再試行は行われません。意図的に 設定されたローカルOllamaアドレスを使用することで、選択したルートを利用しつつ、 プライベートな宛先への送信が可能になります。その他のプライベートサービスについては、既存のサーバーレベルのプライベート 宛先オプトインが適用されます。パネルには、実際に設定されたエンドポイントが表示されます。

生成前に、モデルに送信されるデータには、リクエスト（質問、 チェックされた抜粋、イベントの種類、観測時刻、およびカバレッジマーカー）が含まれます。Telegram セッション、生データフィールド、プロバイダーキー、添付ファイルのバイトデータ、および完全なジャーナルは、 そのコンテキストには含まれません。不要なソースのチェックを外し、処理を明示的に承認してください。 外部プロバイダーは、自社の ポリシーに基づき、送信されたコンテンツを保持する場合があります。「ローカル実行」とは、エンドポイントがローカルにあることを意味しますが、 個別に構成されたサービスの動作を保証するものではありません。

プロバイダーへの同時リクエストは、グローバルで最大2件、ワークスペースごとに 1件までです。プレビューは10分後に失効し、1回の回答を生成できます。 プロバイダーから報告されたトークン数が表示されます。コストの見積もりは、 入力と出力の両方の料金体系が設定されている場合にのみ表示されます。失敗したリクエストも 1日のリクエスト予算を消費します。自動再試行による追加の予算消費はありません。

出典と制限事項#

検索機能は、保存されたメッセージテキストを限定された語彙検索で調査します。最大 24件の情報源を返し、切り詰められた抜粋や不完全な結果セットにはマークを付けます。この 期間は観測期間を指すものであり、Telegramの履歴が 完全であることを主張するものではありません。ワークスペース全体を対象とするイベントは、チャット範囲のアクセスからは除外されます。 欠落しているデータについては、利用可能なアーカイブ内に見つからなかったものとして記述されます。

モデルにはツールは提供されません。そのソースIDは選択された レコードに対して照合され、ハッシュ値は再確認され、引用された文字列はそれらのレコード内に存在しなければなりません。 不明なID、変更された引用、出典のない主張がある場合は、回答は却下されます。本アプリケーションは リンクを生成しますが、モデルが生成したURLは引用元として使用されません。これらのチェックは 出典の存在と引用の正確性を確認するものであり、推論の真偽を保証するものではありません。 推論を信頼する前に、記録と照らし合わせて確認してください。

レポート#

レビュー済みの回答を、独立した分析レポートとして保存します。これには、モデルの 要約、観測された時系列、抽出されたリンクとハンドル、編集・削除記録、 カバレッジの制限、およびソースイベントのハッシュが含まれます。プロバイダー、モデル、エンドポイント、時刻、 およびプロンプトテンプレートのバージョンも併記されます。身元情報は自動的に統合されません。

アナリストによる修正や注記は、モデルの要約とは別に保存されます。レポートは 暗号化された派生ファイル内に格納され、インデックスは署名付きイベントストリームの外部に配置されます。 元のイベントやメディアは変更されません。レポートを開くことができるのは所有者または管理者のみであり、 ソースへのアクセスは再度確認されます。 ダウンロードにもエクスポート 権限が必要です。バージョン1では、レポートへの署名や、モデルの結論が 検証済みの証拠であることを示唆するものではありません。制限：ワークスペースあたり100件のレポート、およびレポート1件あたり100件のアナリストによる修正 。

手動によるOCRおよび文字起こしについては、「メディア処理」を参照してください。 クライアントへのアクセスについては、MCPを参照してください。
