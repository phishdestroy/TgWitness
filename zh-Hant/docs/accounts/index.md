# 連結帳戶

Canonical page: https://phishdestroy.github.io/TgWitness/zh-Hant/docs/accounts/

每個工作區僅包含一個帳戶、其日誌及簽署金鑰。

## 選擇登入方式

開啟**帳戶**、新增工作區，並開啟其連線設定。請使用專用的帳戶進行監測。

- **QR 碼：**請透過 Telegram 的裝置設定掃描此 QR 碼，並確認新登入帳戶。
- **電話號碼：**請輸入號碼、Telegram 發送的驗證碼，以及您的兩步驟驗證密碼（若已啟用）。
- **會話匯入：**匯入您擁有的受支援會話或 Telegram Desktop 資料。

請選擇內建的 API 設定檔，或輸入您自己的 API ID 和雜湊值。API 設定檔用於識別客戶端；它不會用於登入帳戶，也不會使連線變得匿名。

**需要先設定代理伺服器嗎？**

您可以在登入前[選擇並測試連線路徑](https://phishdestroy.github.io/TgWitness/zh-Hant/docs/proxies/)。每個帳戶皆有其專屬的路徑。

## 選擇監測對象

1. 開啟來源清單，並選取您所需的聊天室、群組或頻道。
2. 在開始監測前，請檢視資料蒐集設定，包括媒體檔案。
3. 啟動收集器，並檢查其連線狀態及近期活動。

該帳戶必須能夠存取來源。不同角色可查看不同的事件；日誌反映該帳戶所接收的內容。

若要針對整個帳戶進行調查，請使用**「來源」→「觀察範圍」→「調查模式**」，檢視設定後按下「**儲存範圍**」。[完整的調查指南](https://phishdestroy.github.io/TgWitness/zh-Hant/docs/cases/)涵蓋所有可見的聊天類型、歷史紀錄、使用者個人資料、跨聊天室參考資訊以及證據移交流程。

## 檢查完整路徑

在您所控制的測試群組中，從另一個帳號發送一條獨特的訊息，對其進行編輯並刪除。確認日誌中記錄了這三項事件後，即可[匯出並驗證](https://phishdestroy.github.io/TgWitness/zh-Hant/docs/exports/)該紀錄。

「已連線」狀態表示連線成功。「已擷取的測試訊息」則確認特定事件已傳送至此工作區。

## 新增另一個帳戶

請在**「帳戶」**中建立另一個工作區，並重複上述設定步驟。請保留每個帳戶的簽名金鑰指紋，以便日後辨識其匯出檔案。
