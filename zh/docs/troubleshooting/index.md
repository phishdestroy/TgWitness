# 查找问题所在

Canonical page: https://phishdestroy.github.io/TgWitness/zh/docs/troubleshooting/

从症状入手。逐层排查。

## 面板要求输入令牌

请使用启动器显示的本地文件中的面板令牌。对于 Docker，请运行 `docker compose exec tgwitness cat /data/panel-token.txt`。Telegram 登录码、BotFather 令牌和只读见证令牌各自具有不同的用途。

## Telegram 无法连接

打开连接设置并运行连接检测。如果使用公共代理，请尝试其他条目并显式保存路由。检查代理类型和支持的密钥格式。刷新公共列表不会切换该账户的路由。

## 已连接，但无新消息

1. 请确认观察任务正在正确的作业空间中运行。
2. 请确认该来源已被选中且对该账户可见。
3. 在受控群组中发送一条唯一的新消息，并查找该消息中完全相同的文本内容。
4. 请查阅操作日志，以确认是否存在中断、工作延迟或 Telegram 错误。

历史快照与新消息事件有所不同。静默源可在不产生新消息的情况下连接。当完整性至关重要时，请使用受控交付测试。

## 重启后出现 FloodWait 或间隔

“FloodWait” 表示 Telegram 需要暂停。请等待指定时间并检查数据采集工作量；反复重新连接不会解除该限制。保存的更新状态有助于在重启后补上进度，但过期的更新和某些中断时段仍会造成限制。请记录数据缺口，而非将日志视为完整。

## 该机器人已配置完毕，但尚未发布任何内容

请确保见证进程正在运行，机器人能够向频道发布消息，且见证服务能够连接到收集器和机器人 API。检查其日志中是否存在发布失败的情况。仅成功轮询收集器并不能证明已成功向频道发布消息。

## GitHub 令牌集成功能在哪里？

**计划中。**“扩展功能”部分描述了拟议的分叉和构建验证工作流。目前尚无 GitHub 令牌表单，也无法自动验证运行中的安装是否与代码库匹配。请参阅[当前功能状态](https://phishdestroy.github.io/TgWitness/zh/docs/reference/features/)。

报告问题时，请提供版本号、操作系统、操作步骤以及经过遮蔽处理的错误信息。请勿在公开问题中透露会话信息、令牌、私信及数据目录。
