# Демонстрация выбранных публичных каналов в режиме реального времени

**Дополнительные инструменты → Доступ → Публичная демонстрация** создаёт отдельную страницу, доступную только для чтения, с использованием существующей системы токенов доступа. Она считывает сохранённые наблюдения данной установки. Она не запускает сборщик данных, не входит в Telegram и не получает доступ к каналу для посетителя.

<a id="publish-a-page"></a>
## Публикация страницы

1. Сохраните профиль источника для каждого общедоступного канала, который вы хотите показать. Канал должен иметь общедоступное имя пользователя в своём последнем сохранённом профиле; группы и личные чаты не подходят.
2. Откройте **Дополнительные инструменты → Доступ → Публичная витрина** (или `/showcase-manage.html`) в качестве администратора.
3. Выберите каналы из не более чем 16 рабочих областей, введите название публичной страницы и выберите срок действия ссылки: 1, 7 или 30 дней. Внутренние метки рабочих областей не публикуются. Можно включить до 64 каналов.
4. Проверьте текст выбранных каналов перед публикацией, затем нажмите **Предварительный просмотр выбранных записей**. В предварительном просмотре используется та же серверная проекция, что и на странице посетителя.
5. Нажмите **Создать ссылку на витрину**. Скопируйте ссылку, пока она отображается. Откройте её в отдельном окне браузера, чтобы проверить, как страница будет выглядеть у получателя, прежде чем рассылать её.

Ссылка содержит токен доступа в фрагменте URL-адреса. Перед отправкой запросов к API страница удаляет этот фрагмент и заменяет его сеансом браузера. Любой, у кого есть эта ссылка, может открыть выбранный материал до истечения срока действия или отзыва ссылки. Новые ссылки допускают 100 одновременных сеансов, каждый из которых длится не более одного часа. Существующие средства контроля доступа также могут налагать ограничения по адресам и количеству входов в систему с помощью API предоставления прав. Обычный доступ рецензента представляет собой отдельный режим и по-прежнему включает исходные разрешённые сообщения и файлы.

<a id="what-visitors-see"></a>
## Что видят посетители

| Видимое | Остаётся конфиденциальным |
| --- | --- |
| Выбранные названия общедоступных каналов, имена пользователей и даты наблюдения за профилями | Идентификаторы аккаунтов, внутренние метки рабочих областей и невыбранные источники |
| Захваченный текст и каждое сохраненное изменение | Структурированные идентификаторы отправителей, имена, имена пользователей, номера телефонов и значения профилей |
| Наблюдения об удалении с ранее сохраненным текстом, если таковые имеются | Вложения, аватары, миниатюры, имена файлов и исходные данные |
| Маркеры, указывающие, что автор/профиль или вложение были зафиксированы | Метаданные о пересылке и ответах, сетевые маршруты, IP-адреса и учетные данные |
| Количество событий по выбранным каналам, текущие переключатели сбора данных, интервалы проверки работоспособности и контрольных точек | Средства управления сбором данных и стандартные API для экспорта доказательств |
| Отпечаток подписи, контрольная точка журнала и доказательство согласованности | Ключи подписи и сеансы Telegram |

**Текст публичных сообщений не анонимизируется автоматически.** Имя, упоминание, номер телефона или ссылка, указанные в сообщении, остаются частью этого текста. Редактирование (`Redacted`) применяется к структурированным полям автора/профиля. Перед публикацией проверьте фактическое выбранное содержимое, включая сохраненные правки и удаления.

Соответствие критериям отражает **последний сохраненный исходный профиль**, а не результаты текущего запроса в Telegram. Если в последующем профиле больше отсутствует имя пользователя публичного канала, новый запрос исключает этот канал. Обновляйте исходные профили при изменении настроек общедоступности. У читателей уже может быть сохранен материал, полученный ими ранее.

Исходные подписанные записи остаются неизменными. Отображаемая проекция подписывается отдельно и содержит хеши, ссылающиеся на исходные записи. Подпись проекции подтверждает подлинность отображаемого заявления, а исходные записи, на которые даются ссылки, сохраняют свои собственные подписи.

<a id="check-signatures-and-continuity"></a>
## Проверка подписей и непрерывности

Разверните раздел **Отпечаток и подписанная контрольная точка** и загрузите моментальный снимок. После обновления страницы загрузка включает предыдущий моментальный снимок браузера и доказательство согласованности по алгоритму Меркла между границами их журналов. Автоматическое обновление происходит раз в минуту, пока страница доступна и отображает первую страницу наблюдений.

Если у вас установлен TgWitness, проверьте загруженный файл в автономном режиме с помощью верификатора:

```sh
python -m tgwitness.showcase_verify showcase.json --fingerprint TRUSTED_COLLECTOR_SHA256
```

Отпечаток должен поступать из отдельного доверенного источника. Для сравнения со снимком, который вы сохранили самостоятельно, используйте параметр `--previous earlier.json`; это переопределяет предыдущий снимок, содержащийся в загруженном файле. Текущее доказательство должно начинаться с этой сохраненной границы. Аутентифицированные клиенты могут запросить это доказательство с помощью запроса `GET /api/showcase/{workspace_id}?challenge=<32-hex-random>&from_count=<retained-count>`. Если журнал короче, возвращается код состояния HTTP 409 вместо того, чтобы без предупреждения сбросить границу.

Подписанная контрольная точка фиксирует **весь журнал сборщика**, включая количество записей и непрозрачный хеш вершины журнала. Отображаемое количество сообщений относится только к выбранным общедоступным каналам. На странице никогда не отображается содержимое других журналов. Речь идёт о количестве событий, а не о количестве уникальных сообщений. Настройки описывают текущую конфигурацию, а не каждый предыдущий интервал записи.

Проверка подписи и согласованности позволяет обнаружить изменения относительно сохраненной границы. Пересчитайте указанные события из соответствующего архива и совместно проанализируйте интервалы сбора данных и сохраненные контрольные точки-свидетели. Используйте [верификатор доказательств](TRUST.md), [независимого свидетеля](WITNESS.md) и [запись, протестированную в масштабе](VERIFICATION.md). Синтетические установки явно помечены как «синтетические».

<a id="revoke-or-host-the-page"></a>
## Отмените действие или разместите страницу

Воспользуйтесь **функцией Отменить** в диспетчере витрины или в существующем разделе **Доступ**, чтобы закрыть ссылку и завершить все связанные с ней сеансы. Посетитель очищает отображаемые записи, когда запрос обнаруживает, что доступ завершился. Срок действия и разрешения проверяются при каждом запросе. Права доступа к витрине нельзя преобразовать в обычный доступ к панели на месте; для смены режима создайте новое разрешение.

Обеспечьте доступ к странице через существующий HTTPS-адрес установки. Публикация ссылки не приводит к открытию нового порта, созданию туннеля или изменению настроек DNS. HTML-код и API остаются на установке пользователя. Посетитель витрины не может использовать стандартные API для работы с сообщениями, профилями, медиафайлами, экспортом или управлением при таком доступе.
