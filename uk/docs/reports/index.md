# Створіть звіт

Canonical page: https://phishdestroy.github.io/TgWitness/uk/docs/reports/

Надайте читачеві чіткий шлях від питання щодо справи до збережених записів.

«Report Studio» поєднує вибір даних, зручний для читання журнал змін, діаграми та ваші письмові висновки. Вісім вбудованих шаблонів застосовуються до підтримуваних форматів HTML та нативного PDF. Звіти у форматах HTML, PDF та JSON мають власні підписані печатки; маніфест ZIP-архіву також об’єднує файли в пакет. Файли HTML та PDF запечатуються після завершення їхнього остаточного верстання.

## Створіть звіт у три етапи

1. Відкрийте **«Експорт» → «Налаштування та попередній перегляд» → «Дані**». Використовуйте весь робочий простір або виберіть чати, авторів, дати спостереження за UTC та типи записів. Дати вказують, коли TgWitness зафіксував запис.
2. У розділі **«Дизайн та вміст**» оберіть попередньо встановлений шаблон дизайну та вмісту. Виберіть діаграми активності, мітки учасників, стенограму, збережені зміни та додаткові матеріали Case Board. Додайте деталі справи та нотатки щодо розслідування.
3. Відкрийте **«Попередній перегляд»**, щоб переглянути кількість записів, активність, учасників, вибірку записів та діапазони відсутніх ідентифікаторів. Збережіть налаштування, а потім завантажте потрібний формат.

### Упорядкуйте збережений матеріал так, щоб він був зрозумілим для читача

Синтетичний приклад · схематичне оформлення, а не згенерований звіт

1. **Виберіть.** Оберіть два чати та період спостереження для справи.
2. **Складіть текст.** Оберіть макет та розділи, які дають відповідь на питання.
3. **Попередній перегляд.** Перегляньте кількість перекладів та збережений текст «до» і «після».
4. **Перевірте.** Створіть остаточний файл і порівняйте його підпис із відбитком надійного робочого простору.

#### Вибрані зауваження

2 чати · 1 день спостереження

Повідомлення, редагування та повідомлення про видалення

#### Структура звіту

##### Змінено реквізити для оплати

Питання щодо справи → обсяг → висновки → посилання на записи

**Контекст повідомлення**

Зауваження № 142: «Скористайтеся новим посиланням для оплати».

**Збережено зміни**

До: old.example.invalid → Після: new.example.invalid

#### Переглянути вибір

18 коментарів · 2 збережених редагувань

Час відправлення, редагування та перегляду має окремі позначки.

#### Кінцевий результат

Підписаний PDF + підписаний JSON або підписаний ZIP-архів із читабельним звітом

Одержувач перевіряє файл та надійний цифровий відбиток.

## Оберіть стиль викладу

**Секції «Classic», «Editorial», «Briefing», «Analytics», «Technical», «Overview», «Reading series», а також «Ledger & margin»** представляють одні й ті самі базові записи у різних комбінаціях. Зміна оформлення не впливає на вибір даних та написані примітки. Мову звіту можна вибрати з-поміж 25 підтримуваних мов.

У розділі «Reading series» справа, сфера застосування, висновки та зміни згруповані навколо бічної панелі. У розділі «Ledger & margin» використовуються пронумеровані розділи та широкі поля. Обидва розділи також підтримують огляди облікових записів у форматі HTML та обмін копіями. Нативні PDF-файли генеруються з використанням вбудованих шрифтів; для створення PDF-файлів на комп’ютері користувача не потрібно встановлювати браузер або Node. Для PDF-файлів китайською, японською та корейською мовами додатково потрібен відповідний шрифт на сервері, наприклад Noto Sans CJK, встановлений у всій системі або розміщений у каталозі `TGWITNESS_FONT_DIR`. Без нього ZIP-архів зберігає звіти у форматах HTML та JSON.

## Ознайомтеся зі змінами в контексті

Збережені редагування відображаються «до» та «після». Повідомлення про видалення може супроводжуватися останньою зафіксованою версією. Відповіді, цитати, пересилання, реакції, кнопки та метадані вкладень зберігають доступні посилання. Хеші файлів SHA-256 та записів журналу позначаються окремо.

У попередньому перегляді дизайну показано компоненти обкладинки, аналізу та діаграм, створені на основі відповідних записів із перших 50 000 вихідних записів. Окремий попередній перегляд даних сканує повний стабільний знімок журналу для визначення точної кількості вибраних елементів, при цьому межі зразка позначені відповідними мітками. Створіть PDF-файл, щоб перевірити остаточну нумерацію сторінок. Повний експорт облікового запису містить огляд у форматі HTML; окремі PDF-файли чатів використовують обраний дизайн.

## Ретельно підбирайте варіант тексту для конкретного одержувача

Фільтри звітів формують зручний для читання звіт. Повний архів доказів у форматі ZIP зберігає оригінальний журнал та вкладення. Використовуйте [мінімізовану передачу,](https://phishdestroy.github.io/TgWitness/uk/docs/handover/) коли одержувач повинен отримати лише вибрані дані. Перегляньте [вміст звіту та перевірте його](https://phishdestroy.github.io/TgWitness/uk/docs/reference/case-reports/) або [перевірте готовий експорт](https://phishdestroy.github.io/TgWitness/uk/docs/exports/).
