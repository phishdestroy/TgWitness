# 何が問題だったのかを確認する

Canonical page: https://phishdestroy.github.io/TgWitness/ja/docs/troubleshooting/

まず症状から確認しましょう。1層ずつ順に確認してください。

## パネルからトークンの入力が求められます

ランチャーに表示されるローカルファイル内のパネルトークンをご利用ください。Dockerの場合は、`docker compose exec tgwitness cat /data/panel-token.txt`を実行してください。Telegramのログインコード、BotFatherトークン、および読み取り専用のウィットネストークンは、それぞれ異なる目的で使用されます。

## Telegramは接続されません

接続設定を開き、接続チェックを実行してください。パブリックプロキシを使用している場合は、別のエントリを試して、ルートを明示的に保存してください。プロキシの種類とサポートされているシークレット形式を確認してください。パブリックリストを更新しても、アカウントのルートは切り替わりません。

## 接続されていますが、新しいメッセージはありません

1. オブザベーションが正しいワークスペースで実行されていることをご確認ください。
2. そのアカウントでソースが選択され、表示されていることを確認してください。
3. 管理されたグループ内で一意の新しいメッセージを送信し、その正確なテキストを探してください。
4. 運用ログを確認し、中断、作業の遅延、またはTelegramのエラーがないかご確認ください。

過去のスナップショットと新規メッセージのイベントは異なります。「静かな」ソースは、新規メッセージを生成することなく接続できます。完全性が重要な場合は、制御された配信テストをご利用ください。

## 再起動後のFloodWaitまたは間隔

「FloodWait」とは、Telegramが一時停止を必要とする状態を指します。指定された時間待ってから、収集の負荷状況を確認してください。再接続を繰り返しても制限は解除されません。保存された更新状態は再起動後の遅れを取り戻すのに役立ちますが、期限切れの更新や一部の中断期間については制限が残ります。ジャーナルを完全なものとして扱うのではなく、その空白期間を記録するようにしてください。

## ボットは設定済みですが、何も投稿していません

witnessプロセスが実際に実行されていること、ボットがチャンネルに投稿できること、およびwitnessがコレクターとBot APIに接続できることを確認してください。ジャーナルを点検し、公開に失敗した記録がないか確認してください。コレクターへのポーリングが成功しただけでは、チャンネルへの投稿が確認されたことにはなりません。

## GitHubトークンの連携機能はどこにありますか？

**計画中。**「Extras」セクションでは、提案されているフォークおよびビルド検証のワークフローについて説明しています。現在、GitHubトークン入力フォームや、稼働中のインストール環境がリポジトリと一致していることを自動的に確認する機能はありません。[現在の機能状況](https://phishdestroy.github.io/TgWitness/ja/docs/reference/features/)については、こちらをご覧ください。

問題を報告する際は、バージョン、オペレーティングシステム、再現手順、および一部を伏せたエラー内容を記載してください。セッション、トークン、プライベートメッセージ、およびデータディレクトリについては、公開のイシューには記載しないでください。
