## Live server journal inventory · 1 November 2026

At approximately 19:15 UTC, sequential read-only SQLite `query_only` queries counted events in ten workspace databases on a running server. Collection continued during the queries, so this is not an atomic snapshot across workspaces.

| Observed across the ten workspace databases | ספירה |
| --- | --- |
| Workspaces with at least one `message.new` event | 8 |
| Journal records, including operational events | 1,610,818 |
| `message.new` events | 900,232 |
| `message.edited` events | 80,683 |
| `message.deleted` events | 400,536 |
| `message.recovered` events | 53,403 |
| `message.snapshot` events | 2,183 |
| `media.saved` events | 50,418 |
| `media.failed` events | 5,575 |
| `coverage.gap` events | 11 |
| Database bytes, excluding WAL files and media | 7,909,003,264 |

These are **event counts**, not unique messages, people or media files. The same message can appear in more than one workspace, and an edit or deletion can produce another journal event. `media.failed` counts historical failure events, not the current media queue. The queries did **not** newly verify signatures and the full hash chain of all 1,610,818 records, measure delivery or throughput, or establish that every Telegram event was captured. No message content, account or chat IDs, workspace labels, credentials or private files are published here.

At this review, the separately configured public monitor covered three sources: one capture response was OK and two reported `no_response`. That monitor is not a ten-workspace health summary. `no_response` means the observer could not obtain a response at that check; it does not establish message loss. The smaller 29 October test below has its own explicit signature and hash-chain verification.

## Recent offline and fault-injection checks · 1 November 2026

These checks use fictional data and local files; they add regression evidence for the current source, not another live Telegram delivery measurement:

Exact archived bytes and file hashes matched; private test files stayed out. A simulated write failure left the previous archive and checksum intact. |
| [Account export recovery](https://github.com/phishdestroy/TgWitness/blob/main/tools/check_account_export_recovery.py) | A simulated disk error on the second ZIP member left no published or partial ZIP. Scale assertions guard against repeated task and receipt scans as histories grow. |
| [Minimized disclosure privacy](https://github.com/phishdestroy/TgWitness/blob/main/tools/check_disclosure_privacy.py) | Synthetic Unicode names and aliases, nested metadata, unknown senders and media fields were checked in all three identity modes and with text omission. A masking-limit failure did not silently weaken redaction; the original signed account export stayed unchanged. |
| [Linux media decoder and OCR](https://github.com/phishdestroy/TgWitness/blob/main/tools/check_media_worker.py) | A [Linux Docker CI check](https://github.com/phishdestroy/TgWitness/actions/runs/41341200341/job/124951395192) at commit `5a9e0814` passed generated Ogg/Opus, MP3, M4A, MP4 with video, WAV and FLAC inputs; forged-duration and secondary-file-reference controls; and 48 mutated parser fixtures (34 rejected, 14 decoded within bounds). Real Tesseract OCR ran with original bytes unchanged. The decoder and OCR ran in network-isolated containers without a Whisper model. |

The checks run in the [pull-request](https://github.com/phishdestroy/TgWitness/blob/main/.github/workflows/pr-check.yml) and [full Checks](https://github.com/phishdestroy/TgWitness/blob/main/.github/workflows/checks.yml) workflows. They test these failure boundaries, not every possible storage failure or whether a disclosure is automatically safe to publish. The media check does not measure speech recognition accuracy or Telegram delivery. Review each derivative before sharing.

## ייצוא מוגן בסיסמה שנפתח באמצעות libarchive · 29 באוקטובר 2026

ארכיון שנכתב באמצעות קוד הצפנה לייצוא (WinZip AES-256, הפורמט ש-7-Zip ו-WinRAR קוראים) נפתח באמצעות Windows `tar` (bsdtar 3.6.2, libarchive). עם הסיסמה הנכונה, הקובץ שחולץ תאם את ה-SHA-256 המקורי; סיסמה שגויה נדחתה עם ההודעה "סיסמה שגויה". תוכנות 7-Zip ו-WinRAR עצמן לא הופעלו.

## רשימות MTProxy ציבוריות מובנות · 29 באוקטובר 2026

זהו תיעוד הבדיקות ההיסטורי של הגרסה המקורית עם בחירה ידנית. עבור מצבי המאגר האוטומטי ו-IP הנוכחיים, ראו [הגדרות חיבור](https://phishdestroy.github.io/TgWitness/he/docs/reference/connection/#ip-modes). הנתונים והתכונות שאינן נתמכות המופיעים להלן שייכים לאותה גרסה שנבדקה.

נוספו תמונת מצב ציבורית מאוגדת ורענון HTTPS מפורש מ-SoliSpirit/mtproto ו- zakky8/mtproto-proxy-pro. בשרת זה, תוכנת ההורדה של היישום השיגה את שני העדכונים בהצלחה ב-29 באוקטובר 2026 בשעה 12:58 UTC: **118 נקודות קצה ייחודיות ותואמות** לאחר סינון, הסרת כפילויות והגבלת 64 רשומות לכל מקור. פעולה זו מאמתת את אחזור הרשימה, ולא את הקישוריות או את מסירת ההודעות דרך נקודות קצה אלה. לא היה חשבון אמיתי שחובר לפרוקסי המופיע ברשימה במהלך עבודה זו. [מדריך למפעיל ולמשתמש](https://github.com/phishdestroy/TgWitness/blob/main/docs/ru/PROXIES.md).

תגובות מקור כושלות/ריקות/לא תואמות שומרות על הערכים והתאריכים הקודמים. עדכונים אינם משנים את המסלול הנבחר. כתובות ציבוריות מאומתות וכתובות IP שזוהו מוצמדות בעת הבחירה; מסלולי מפעיל/ידניים נשארים נפרדים. בדיקת החיבור זמינה כעת בלוח הבקרה לפני כניסת החשבון. TLS מזויף ובחירת פרוקסי אוטומטית אינן נתמכות עדיין. קטלוג המפעיל גובר לחלוטין על המנויים.

- סוויטת בדיקות מלאה: **366 עברו, 3 הושמטו**, 287.94 שניות. אזהרות התלות הקיימות וההשמטות בפלטפורמה נותרו. רגרסיה סופית של רשימת הציבור/לוקליזציה: **36 עברו**, כולל דחיית יציאות פרוקסי הורדה לא חוקיות; זה חופף לסוויטת הבדיקות המלאה.
- האתר עבר את בדיקת תאימות הדפדפנים באנגלית/רוסית, במצב בהיר/כהה ברזולוציה של 390/1440 פיקסלים: אפשרויות מובנות, ללא טעינה חיצונית בעת פתיחת ההגדרות, רענון מפורש, שמירת נתיבים ו מטמון במהלך תקלות, בדיקה לפני כניסה, בידוד סביבת העבודה במקרה של תגובה מאוחרת, פרטי המקור ופריסה/ניגודיות. ללא שגיאות JavaScript או בקשות חיצוניות לדפדפן.
- הכיסוי הסופי של התרגום הסטטי אושר עבור כל 13 השפות; הטקסט החדש תורגם לרוסית, עם חלופות מפורשות באנגלית במקומות אחרים. המדריך המובנה המעודכן עבר את בדיקות הפריסה והניגודיות בשני העיצובים.

## ביקורת על הגדרת הבוט והפרוקסי של Witness · 29 באוקטובר 2026

הגדרת ה-witness (כעת תחת **'Extras' → 'A bot in your channel**') מכינה witness המותקן באופן עצמאי: מפתח אספן מוצמד, הורדת אסימון מוגבל, ערוץ משלו, מדיניות פרסום, נתיב HTTP/SOCKS5 ו- Bot API מותאם אישית. אסימון הבוט נשאר במארח ה-Witness. ה-`--check-config` החדש שלו מאמת את התצורה והקבצים מבלי לפתוח חיבור רשת או ליצור מפתח. נתיבי קבצי JSON מתורגמים לצד התצורה. כל גרסאות ה-Witness של Compose מעבירות כעת את הגדרות פרוקסי ה-HTTP ו-Bot API.

הגדרות החשבון תומכות בקטלוג MTProxy ציבורי המנוהל על ידי המפעיל, בתצוגה מקדימה מותאמת אישית של קישורי פרוקסי ב-Telegram ובשדות הידניים הקיימים. תגובות הקטלוג משמיטות סודות; הבחירה מאחסנת את המסלול בכספת סביבת העבודה. קטלוגים חסרים או פגומים משאירים את המסלולים הידניים זמינים. כתובות פרוקסי של פרויקטים או שירות עדים מאוחסן אינם מומצאים או מופעלים כברירת מחדל. דוגמה של Caddy חושפת רק את נקודת הקצה הראשית המוגבלת כאשר עד חיצוני חייב להגיע לאספן שהלוח שלו נשאר פרטי.

תרגילים חדשים לכיסוי רגרסיה דחו StringSession, שינויים בקוד ובחשבון 2FA, ביטול חיפוש זהות, ביטול כניסה בהמתנה, ועדכונים באמצעות מטפלים רשומים בלקוחות פעילים, נדחים, שהוחלפו ולקוחות בדיקה. רק האספן הפעיל תורם אירועים; פרטי הזדהות שמורים והיסטוריית חתימות נשארים שלמים. בדיקות חדשות נוספות מכסות חיפוש Unicode לאחר פתיחה מחודשת של מסד נתונים, הכללה של גבולות מדיניות הניטור ב-Coverage, והחרגות באריזה ממקורות ציבוריים.

הפרויקט בפועל, `pythonw.exe`, השיק לוח סינתטי מבודד, החזיר HTTP 200 ושמר את אבחון ההפעלה ב-`logs/server.log`. היומן לא הכיל את אסימון הלוח שנוצר או את רשומות הגישה ב-HTTP. הבדיקה סיימה רק את התהליך הסינתטי שלה עצמה. לא נרשמה משימה ב-Task Scheduler; כניסה/יציאה, מצב שינה ושחזור שירות נותרים תנאים נפרדים.

הבדיקה ב-Chromium עברה בהצלחה **45 תרחישים**, ללא שגיאות JavaScript בדף וללא בקשות חיצוניות שנצפו. בדיקות חדשות מכסות תאריכים ושעות בציר הזמן ברזולוציה של 601/768/850 פיקסלים, טיוטות של קבצים מצורפים במהלך רענון הסטטוס, עריכות חדשות שבוצעו במהלך השמירה, תוצאות אימות שנמחקו בעת מעבר בין חשבונות, תגובות אימות מאוחרות לאחר מעבר לחלון אחר וחזרה, וגבולות אימות מפורשים עם הגעת אירועים חדשים. כמו כן, תוקן הריווח בין סמל החיפוש לטקסט, וחבילת הדפדפנים הושקה מחדש.

הריצה בדפדפן השתמשה בסביבת הריצה המוצמדת ב-`.venv` וב-Playwright 1.62.0/Chromium הקיים המסופק על ידי המערכת, שנוסף לאחר סביבת הפרויקט בנתיב הייבוא. התקנת תלות פיתוח אופציונלית הופסקה במהלך הורדה איטית של Playwright; לא אושרה גרסה חדשה של כלי הדפדפן. `python start.py --setup-only` רגיל השלים את שדרוג היישום. המקור, המטא-נתונים המותקנים ודוח הסמן של המשגר 0.5.1; `pip check` עבר בהצלחה. בדיקות המוכנות עברו בהצלחה בנתיב חדש שלא היה בשימוש, תוך שמירה על האזהרה הצפויה בנוגע למפתח הכספת המקומי.

ה-wheel בגרסה 0.5.1 הותקן בנפרד ועבר בדיקת תפקוד בסיסית: כל נכסי הפאנלים/המדריכים הוצגו, גישה ל-API ללא אימות נדחתה, וקבצי ZIP של ראיות המכילים 32 אירועים, הן ישירים והן מוזרמים, עברו אימות עצמאי. קובצי היישום ב חבילה המותקנת הושוו לקוד המקור. ארכיון הקוד הפתוח הציבורי משתמש ברשימת היתרים מפורשת לסוגי קבצים ודוחה קבצי מקור מקושרים; חומר ריצה המונח בתוך ספריות המקור אינו נכלל בבדיקות הרגרסיה.

במהלך ריצת תיקון הקוד, מבחר הקוד הפתוח ומערכת המועמדים ב-Git כללו 86 קבצים, ללא ספריות נתוני ריצה. סריקה לאיתור תבניות מזוהות של מפתח פרטי, אסימון GitHub, אסימון בוט טלגרם ו-StringSession לא מצאה התאמות. זוהי בדיקת תבניות מוגבלת, ולא ביקורת סודית מקיפה. בדיקות "כללי התעלמות" מכסות 12 אובייקטים נפוצים של חשבונות/נתונים/ייצוא. קבצי YAML של Workflow/issue/Compose וסקריפט המשימות של Windows נפרשו בהצלחה. קישורי התיעוד המקומיים פועלים כראוי.

כל שבעת הממצאים מהסקירה שנערכה ב-27 באוקטובר נדונו. ביצוע זרימת העבודה ב-GitHub, סביבת הריצה ב-Linux/macOS/Docker, Telegram אמיתי, תאימות עם פרוקסי חיצוני/TSA והסמכה לעומס מתמשך נותרו מחוץ להפעלה המקומית הזו. לא בוצעו פרסום מאגר, רישום שירות או איסוף חשבונות אמיתיים. .

התיעוד הציבורי והמדריך המקומי הם באנגלית; קישורים לתיעוד המקומי פועלים. PowerShell ניתח את תבנית המשימות של Windows ו-Python ניתח את קובץ ה-plist של macOS. מדובר בבדיקות תחביר, לא בהפעלת שירות. לא נרשמה אף משימה/שירות. תצורת ה-CI כוללת כעת בדיקות מוכנות, אך ה-CI המרוחק לא הופעל כאן.

בהרצת הדפדפן 0.4 נצפה שוב הזרקת AdGuard על ידי המארח ו-OSError 10022 של Windows asyncio socket-cleanup. בדיקות הדפדפן עברו בהצלחה; תצפיות סביבתיות אלו נשמרות במקום להיחשב כהתנהגות קבועה של היישום. ניסיונות ראשוניים בסביבת הארגז החולי של OpenSSL/דפדפן/pip נכשלו; הריצות המוצלחות השימוש בהרצה מאושרת מחוץ לסביבת הארגז החולי.

## גרסה 0.3.0

חבילת ה-runtime המלאה והמוצמדת עברה: **61 בדיקות**, עם אזהרת השבתה אחת של Starlette TestClient במעלה הזרם. מטא-נתוני ה-runtime מדווחים על TgWitness 0.3.0 ו- python-socks 2.8.2; בדיקת pip עברה בהצלחה. בדיקת התאימות לדפדפן עברה ללא שגיאות JavaScript בדף.

ה-wheel בגרסה 0.3.0 נבנה והותקן בספריית חבילות נפרדת. הוא סיפק את לוח הבקרה והנכסים, דחה בקשת API לא מאומתת, וייצא יומן סינתטי בן 32 אירועים שעבר אימות עצמאי. קישורי התיעוד המקומי פועלים כראוי. לאחר תיקון הנורמליזציה של מפתח גלויה ב-MTProxy, כל תשעת מבחני החיבור/אבטחה הוצאו מחדש בהצלחה.

הכיסוי החדש כולל:

- שם משתמש/סיסמה של SOCKS5 ו-HTTP CONNECT דרך שרתים אמיתיים לבדיקת לולבק; פרוקסי שהוגדר כלא פעיל נכשל במקום לעבור ליעד חלופי.
- אימות פרוקסי, בחירת שיטת העברה ב-MTProxy, דחיית סודות TLS מזויפים, התמדה, בידוד סביבת העבודה, דחיית שינויים בזמן התצפית, והחרגת סודות מסטטוס ה-API ומאירועים חתומים.
- המרה לקריאה בלבד של סכמות SQLite סינתטיות 7 ו-8 של Telethon; ה-hash של המקור נותר ללא שינוי; דחיית פורמטים אחרים, תצוגות SQL וקובץ WAL פתוח.
- מפתח ראשי חיצוני לכספת: מפתחות סביבת עבודה נגזרים שונים, פתיחה חוזרת מוצלחת, דחיית מפתח שגוי או חסר, והיעדר העברה מרומזת של כספות מקומיות קיימות.
- הגדרות פרוקסי בדפדפן, מחיקת אישורים, גילוי הגנה על אחסון, דף חיבור למכשירים ניידים, אישור קבצי הפעלה שהומרו, נתיבים נפרדים, וכל תרחישי האיסוף/הייצוא שנדונו בעבר באמצעות לקוח Telegram מזויף.

במהלך הפיתוח, בדיקת לופבק חיכתה ללא הגבלת זמן לכיבוי הצד הנגדי; בריצה אחרת נצפתה איפוס חיבור ב-Windows לאחר לחיצת היד. כעת, המתקן מגביל את כל חילופי הנתונים ומתייחס ל-EOF/איפוס לאחר לחיצת יד שהושלמה כסגירת החיבור. אימותי לחיצת היד/האימות נותרים הכרחיים. הדבר אינו פוסל ספקי פרוקסי אמיתיים ואינו מרמז על פגם קבוע בהעברת הנתונים של טלגרם.

ההערה בנוגע לבקשת AdGuard המתוארת להלן עדיין תקפה. לא נעשה שימוש בחשבון Telegram אמיתי, בפרוקסי SOCKS/HTTP חיצוני או בשרת MTProxy פעיל. MTProxy הוא כלי ניסיוני, והאפשרויות שנבחרו בו ואימות הסוד נבדקו, אך לא נבדקה תאימותו בפועל. פקודות חדשות להמרת מפתחות חיצוניים והמרת הפעלה נבדקו רק עם סודות סינתטיים. לינוקס/macOS/Docker נותרים ללא אישור בהקשר זה.

מדידת התפוקה של גרסה 0.2 המופיעה להלן לא חוזרה ואין להציגה כמדד ביצועים חדש עבור ריבוי חשבונות/פרוקסי בגרסה 0.3.

## תצפיות סביבתיות

הגבלות סביבת הבדיקה (sandbox) של Windows חסמו את הספריות הזמניות המוגדרות כברירת מחדל של pytest/pip ואת תת-התהליך של Playwright. Pytest השתמש בספרייה זמנית חדשה בתוך הפרויקט; תהליכי ההתקנה והדפדפן דרשו ביצוע מאושר מחוץ לסביבת הבדיקה.

תוכנת AdGuard המותקנת במחשב הזריקה בקשות ל-local.adguard.org לדפדפן. רישום הדפדפן שומר את הבקשות הללו. ריצה זו **אינה** מהווה הוכחה לכך שאין בקשות יוצאות בסביבת דפדפן שלא עברה שינויים; קוד המקור של האפליקציה עצמו אינו מכיל בקשות לנכסים חיצוניים, CDN או ניתוח נתונים. הגדרות AdGuard לא שונו.

בהפעלה הסופית של הדפדפן תועד גם שגיאת OSError 10022 של Windows asyncio socket-cleanup. כל בדיקות הדפדפן עברו בהצלחה ולא התרחשו שגיאות JavaScript בדף. הסיבה לכך לא הובררה, והפעלה זו אינה מעידה על היעדר בעיות בתקשורת המארח.

בדיקת ה-HTTP הראשונה של החבילה המותקנת, שהשתמשה בבקשות לסגירת חיבור של urllib, נתקלה באיפוסים של החיבור, הן בתוך הסנדבוקס והן מחוצה לו, ובשתי קבוצות התלות. הבדיקה הסופית השתמשה בחיבורים מתמשכים סטנדרטיים של HTTP/1.1 באמצעות http.client ועברה בהצלחה. גם בקשות הדפדפן עברו בהצלחה. המקור המדויק של איפוס החיבורים לא הובהר; הם לא סווגו כפגם קבוע ביישום.

## הסתייגות נוספת

המצגת הנפרדת של `website/` והגרסה ב-Pages נוספו לאחר הבדיקות של הפאנל המפורטות לעיל. לא בוצעו שינויים בהגדרות החשבון החי או בלוגיקת האיסוף.

- חבילת היישומים הקיימת עברה את הבדיקות: 138 עברו, דילוג אחד המיועד ל-POSIX בלבד, ואזהרה אחת על הפסקת תמיכה ב-Starlette/httpx במעלה הזרם. 11 בדיקות הבנייה הנוספות לאתר עברו באופן עצמאי, כולל דחיית פלט בלתי צפוי ודחיית קלט מקושר.
- שני סקריפטי הדפדפן של היישום עברו בהצלחה באמצעות project-venv Playwright ו-Chromium headless shell 156. לא נרשמו שגיאות JavaScript בדף או בקשות חיצוניות. כל תרחישי החשבונות השתמשו בתעבורה מזויפת ובנתונים פיקטיביים.
- `tools/check_site.py` עבר בהצלחה ברוחבים 320, 390, 768, 1024 ו-1440, עם נתיב משנה של כתובת האתר, מעבר בין כרטיסיות באמצעות המקלדת, גישה מוצלחת/נדחית ללוח, תנועה מצומצמת, ו-JavaScript מושבת. לא התרחשו בקשות נכשל לנכסים או בקשות חיצוניות.
- `tools/build_site.py` יצר 10 קבצים ציבוריים המופיעים ברשימת ההיתרים, בהיקף כולל של כ-460 KB. צילומי מסך של הדפדפן וקבלה נמצאים ב-`test-results/site/`, אשר מתעלם מהם.
- ה-wheel נבנה בהצלחה לאחר התקנת כלי ה-setuptools/wheel המיועדים לבנייה בלבד בסביבת הפרויקט. התקנתו ביעד מבודד ו הרצת ה-`tools/check_install.py` עברו בהצלחה: נכסים סטטיים, בקרת גישה, ייצוא סינתטי חתום של 32 אירועים, והורדת סטרימינג שאומתה באופן עצמאי.
- `pip check` עבר. סריקת תבניות של מועמדים ציבוריים שנבחרו ב-Git לא מצאה בלוקים מזוהים של מפתחות פרטיים, אסימוני GitHub/bot/AWS, הקצאות סודיות ארוכות כטקסט, או סמנים של קונפליקטים במיזוג. אין זו הוכחה לכך שכל פורמט סודי אפשרי נעדר. בדיקות נתוני ריצה/הפעלה/מפתח הושמטו על ידי Git.
- אימות ה-CLI של GitHub לא היה תקף; לא הוגדר שרת מרוחק ולא היה קיים קומיט ראשוני. לא בוצעו פעולות דחיפה (push), זרימת עבודה מאוחסנת, פריסת Pages או שחרור גרסה. Docker והאימות החי של Telegram/הפלטפורמה נותרים מחוץ לבדיקה זו.

בשרת זה, נעילת ההורדה של Playwright נכשלה במערכת הקבצים של סביבת העבודה E:. התקנת Chromium תחת `%LOCALAPPDATA%/tgwitness-playwright` והשימוש באותו `PLAYWRIGHT_BROWSERS_PATH` לצורך הבדיקות הצליחו. זוהי פתרון עוקף לסביבה, ולא שינוי בתלותי הריצה של היישום.

## תיעוד אינטראקטיבי ומטא-נתונים של האתר · 29 באוקטובר 2026

האתר הציבורי מורכב מ-12 דפי HTML באנגלית: דף בית, אינדקס מדריכים ועשרה מדריכים. הארכיון מכיל 28 קבצי מצגת המפורטים במפורש, בנפח של כ-1.85 MB, וללא נתוני איסוף. האתר הציבורי הוא באנגלית; תרגומי היישום ומדריכי המאגר המתורגמים הם נפרדים.

- בדיקות אתר, פרסום מקור וגבולות שחרור: **18 עברו, 2 הושמטו**. הבדיקות שהוחמצו נוגעות ליצירת קישורים סימליים במערכת הקבצים של Windows זו. הבדיקות בודקות מטא-נתונים ייחודיים של דפים, דפים ציבוריים באנגלית בלבד, כתובות URL קנוניות, כל הערכים במפת האתר , נכסים/נקודות עוגן מקומיות, ניווט מובנה והחרגת קבצים פרטיים.
- ה-`tools/check_site.py` וה-`tools/check_docs_site.py` עברו את הבדיקות ב-Chromium ברזולוציות של 320, 390, 768, 1024 ו-1440 פיקסלים תחת נתיב משנה של כתובת ה-URL של הפרויקט. הבדיקות במדריך מכסות את כל 11 דפי התיעוד, חיפוש וניווט באמצעות המקלדת, הצלחה/כישלון של הלוח ותוכן קריא ללא JavaScript.
- חמש דוגמאות אינטראקטיביות שעברו את הבדיקה: השמעת הודעות/התקדמות צעד אחר צעד/השהיה/איפוס עם תנועה מצומצמת והשעיה מחוץ למסך; שרשראות האש המקוריות/המשונות/המשוחזרות/המקוצצות; החלטות העד בנוגע לקבלה/חזרה לאחור/פיצול/אי-תגובה; וכן תרחישי מסירה מלאים/מעוכבים/חסרים; ומפת חקירה המקשרת תצפיות צ'אט צולבות פיקטיביות לפי מזהה השולח, היעד וה-hash של הקובץ המצורף. בקרות החקירה עברו בהצלחה בדיקות ניווט במקלדת ובדיקות גיבוי ללא JavaScript . תוצאות ה-SHA-256 בדפדפן הושוו באופן עצמאי ל-`hashlib` של Python ול-JSON הקנוני. דוגמת ה-hash שמרה גם על הגיבוי הקריא שלה כאשר Web Crypto לא היה זמין.
- יחסי התצוגה וסימוני התרשימים תואמים לטבלה הנגישה. תוויות הציר במובייל הוגדלו לאחר בדיקה ויזואלית. כל דוגמה מסומנת כ ממחישה או סינתטית, ואף דוגמה בדפדפן אינה יוצרת קשר עם טלגרם.
- לא נרשמו בקשות חיצוניות, בקשות HTTP שנכשלו או שגיאות JavaScript. צילומי מסך וקבלות ממחשב שולחני/מובייל נמצאים תחת `test-results/site/` ו-`test-results/docs-site/`. אינדקס התיעוד, דוגמאות להודעות/האשים, פריסת Witness, תרשים המסירה ומפת החקירה נבדקו בגדלים של מחשב שולחני/מובייל.
- הסריקה של הפרסום עברה בהצלחה עבור 282 קבצי מקור ציבוריים ו-1,426 קישורים מקומיים לתיעוד. Ruff עבר בהצלחה את הכלים והבדיקות של האתר ב-Python שעברו שינויים.
- `docs/HOW-IT-WORKS.md` מספק תוספת ל-GitHub Markdown הכוללת תרשימי Mermaid ונוסחאות. `docs/INVESTIGATION.md` מכסה את היקף החשבון כולו, איסוף היסטוריית צ'אטים בודדים, פרופילים של משתמשים, הפניות בין צ'אטים, ציר זמן והעברת תיקים מאומתים. השלבים והמגבלות שלו נבדקו מול ההיקף הנוכחי, האיסוף, התיק, הייצוא, המאמת וקוד הפאנל. העיבוד המארח ב-GitHub לא נבדק.

זוהי בדיקה מקומית של אתר/תיעוד. היא אינה מוסיפה הסמכת Telegram בזמן אמת, ואינה קובעת פריסת Pages מאוחסנת, הצלחת CI מרחוק או אינדוקס במנועי חיפוש. ראו [את נוהל הפרסום](https://github.com/phishdestroy/TgWitness/blob/main/docs/internal/PUBLISHING.md) ואת [הערות המטא-נתונים של האתר](https://github.com/phishdestroy/TgWitness/blob/main/docs/internal/SEO.md).
