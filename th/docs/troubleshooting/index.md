# ค้นหาว่าเกิดข้อผิดพลาดอะไร

Canonical page: https://phishdestroy.github.io/TgWitness/th/docs/troubleshooting/

เริ่มจากอาการก่อน ตรวจสอบทีละชั้น

## คณะกรรมการขอโทเค็น

ใช้โทเค็นของ panel จากไฟล์ท้องถิ่นที่แสดงโดยตัวเปิดใช้งาน สำหรับ Docker ให้รัน `docker compose exec tgwitness cat /data/panel-token.txt` รหัสเข้าสู่ระบบ Telegram โทเค็น BotFather และโทเค็น witness แบบอ่านอย่างเดียว มีวัตถุประสงค์การใช้งานที่แตกต่างกัน

## Telegram ไม่เชื่อมต่อ

เปิดการตั้งค่าการเชื่อมต่อและดำเนินการตรวจสอบการเชื่อมต่อ หากใช้พร็อกซีสาธารณะ ให้ลองใช้รายการอื่นและบันทึกเส้นทางอย่างชัดเจน ตรวจสอบประเภทพร็อกซีและรูปแบบข้อมูลลับที่รองรับ การรีเฟรชรายชื่อสาธารณะจะไม่เปลี่ยนเส้นทางของบัญชี

## มีการเชื่อมต่อ แต่ไม่มีข้อความใหม่

1. ตรวจสอบว่าการสังเกตการณ์กำลังทำงานในพื้นที่ทำงานที่ถูกต้องหรือไม่
2. ตรวจสอบให้แน่ใจว่าแหล่งข้อมูลได้ถูกเลือกและแสดงให้บัญชีนั้นเห็น
3. ส่งข้อความใหม่ที่ไม่ซ้ำใครในกลุ่มที่ได้รับการควบคุม และค้นหาข้อความที่มีเนื้อหาตรงกันนั้น
4. ตรวจสอบบันทึกการดำเนินงานเพื่อหาข้อขัดข้อง การทำงานล่าช้า หรือข้อผิดพลาดของ Telegram

ภาพถ่ายประวัติและเหตุการณ์ข้อความใหม่เป็นสองสิ่งที่ต่างกัน แหล่งข้อมูลแบบเงียบสามารถเชื่อมต่อได้โดยไม่สร้างข้อความใหม่ ให้ใช้การทดสอบการส่งแบบควบคุมเมื่อความครบถ้วนเป็นสิ่งสำคัญ

## FloodWait หรือช่องว่างหลังการรีสตาร์ท

FloodWait หมายความว่า Telegram ต้องการให้หยุดชั่วคราว รอเป็นระยะเวลาที่ระบุและตรวจสอบปริมาณงานการเก็บข้อมูล; การเชื่อมต่อใหม่ซ้ำๆ จะไม่ยกเลิกข้อจำกัดนี้ สถานะการอัปเดตที่บันทึกไว้ช่วยติดตามงานที่ค้างอยู่หลังการรีสตาร์ท แต่การอัปเดตที่หมดอายุและช่วงเวลาการหยุดชะงักบางส่วนยังคงเป็นข้อจำกัด ควรบันทึกช่วงเวลาที่ขาดหายไปแทนที่จะถือว่าบันทึกหลักฐานนั้นสมบูรณ์

## บอทได้ถูกตั้งค่าแล้ว แต่ยังไม่โพสต์อะไรเลย

ตรวจสอบให้แน่ใจว่ากระบวนการ Witness กำลังทำงานอยู่จริง บอทสามารถโพสต์ในช่องได้ และ Witness สามารถเชื่อมต่อกับ Collector และ Bot API ได้ ตรวจสอบบันทึกเพื่อหาการโพสต์ที่ล้มเหลว การสำรวจ Collector ที่สำเร็จเพียงอย่างเดียวไม่ยืนยันว่าการโพสต์ในช่องได้สำเร็จ

## การบูรณาการโทเค็น GitHub อยู่ที่ไหน?

**อยู่ในขั้นตอนการวางแผน ส่วน** Extras อธิบายถึงกระบวนการ fork และขั้นตอนการตรวจสอบการสร้างระบบที่เสนอไว้ ปัจจุบันยังไม่มีแบบฟอร์มโทเค็น GitHub หรือระบบยืนยันอัตโนมัติว่าระบบที่ทำงานอยู่ตรงกับรีโพสิตอรี ดู[สถานะคุณสมบัติปัจจุบัน](https://phishdestroy.github.io/TgWitness/th/docs/reference/features/)

เมื่อรายงานปัญหา โปรดระบุเวอร์ชัน ระบบปฏิบัติการ ขั้นตอนการดำเนินการ และข้อความข้อผิดพลาดที่ได้รับการปกปิดข้อมูล ให้หลีกเลี่ยงการเปิดเผยข้อมูลเกี่ยวกับเซสชัน โทเค็น ข้อความส่วนตัว และไดเรกทอรีข้อมูลในปัญหาที่เปิดเผยต่อสาธารณะ
