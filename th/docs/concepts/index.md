# ดูวิธีการทำงานของหลักฐาน

Canonical page: https://phishdestroy.github.io/TgWitness/th/docs/concepts/

ข้อความเปลี่ยนได้ บันทึกของสิ่งที่คุณเห็นไม่ควรเปลี่ยน และใครก็ควรตรวจสอบได้

ด้านล่างเป็นการทดลองเล็กๆ สองอย่าง ข้อความสมมติ ทุกอย่างทำงานในเบราว์เซอร์ของคุณ ไม่มีอะไรส่งไปยัง Telegram

## จากการส่งออกบทสนทนาสู่บันทึกที่สามารถตรวจสอบได้

[การส่งออกของ Telegram Desktop](https://telegram.org/blog/export-and-more) บันทึกประวัติที่คุณเห็นอยู่ตอนนี้เป็น HTML หรือ JSON TgWitness เพิ่มบันทึกการเปลี่ยนแปลงต่อเนื่อง ลายเซ็นบนทุกรายการ และ checkpoint ที่ผู้อื่นใช้เทียบได้

| งาน | การส่งออกข้อมูลจาก Telegram Desktop | TgWitness |
| --- | --- | --- |
| อ่านการสนทนาที่บันทึกไว้ | HTML หรือ JSON พร้อมสื่อที่เลือกไว้ | การสนทนาที่บันทึกไว้, บันทึกที่สามารถค้นหาได้ และรายงานแบบออฟไลน์ |
| ติดตามการเปลี่ยนแปลงตามเวลา | ประวัติข้อมูลที่มีอยู่เมื่อส่งออก | เวอร์ชันเก่า การแก้ไขภายหลัง และการลบ เก็บไว้ทั้งหมด |
| ตรวจสอบไฟล์หลังการส่งต่อ | ไฟล์ส่งออก HTML/JSON มาตรฐานไม่มีการลงนาม | แมนิเฟสต์ที่ลงนาม รายการที่ลงนาม และรายงานที่ผนึก ตรวจกับคีย์ที่เชื่อถือได้ |
| เปรียบเทียบกับสถานะที่เก็บไว้ก่อนหน้านี้ | เก็บสำเนาอ้างอิงหรือค่าแฮชไว้แยกต่างหาก | จุดตรวจสอบที่ลงนาม, พยานแยกต่างหาก และตราเวลาภายนอกตามตัวเลือก |

การเปรียบเทียบนี้อิงจาก [โค้ดการส่งออกของ Telegram Desktop](https://github.com/telegramdesktop/tdesktop/tree/768d47cda6c7f447c10a25d1f363279493a90ed7/Telegram/SourceFiles/export/output) ณ วันที่ 2 พฤศจิกายน 2026

## แก้ไขบันทึก ติดตามแฮช

ทุกรายการมีค่าแฮชของรายการก่อนหน้า checkpoint ที่เก็บไว้ที่อื่นตรึงความยาวบันทึกและค่าแฮชสุดท้าย

02 / HASH-CHAIN SANDBOXSHA-256 ที่แท้จริง · ตัวอย่างบันทึก

บันทึก 01**รับข้อความแล้ว**`h₁ = SHA-256(e₁)`ลิงก์ไปยัง 64 zeroes

RECORD 02**พบกันเวลา 11:00**`h₂ = SHA-256(e₂)`รวมถึง h₁

RECORD 03**สังเกตเห็นการลบ**`h₃ = SHA-256(e₃)`รวมถึง h₂

เก็บไว้ที่อื่น**3 รายการ · หัวข้อ`h₃`**เปรียบเทียบขอบเขตที่กำหนดนี้กับบันทึกที่ให้มา

การแก้ไขเหตุการณ์จะเปลี่ยนค่าแฮชของมัน การสร้างใหม่ของโซ่จะเปลี่ยนหัวของมัน การลบส่วนท้ายจะทำให้มันสั้นกว่าจุดตรวจสอบที่เก็บไว้

**ตรวจสอบบันทึกที่ 2 และค่าแฮชทั้งหมด**

นี่คือ JSON UTF-8 ที่ถูกแฮชในตัวอย่างนี้อย่างแม่นยำ ค่าต่างๆ เป็นค่าสมมติ; สนามทั้งเก้าและกระบวนการซีเรียลไลเซชันสอดคล้องกับรูปแบบของบันทึก


``

คำนวณใหม่ค่าแฮชของบันทึกที่ 2

``

แซนด์บ็อกซ์นี้คำนวณค่าแฮชเท่านั้น ไม่ใช่ลายเซ็น ผู้ตรวจสอบจริงยังตรวจสอบลายเซ็น Ed25519 ลำดับ และลิงก์ของทุกเหตุการณ์ด้วย การสร้างค่าแฮชใหม่เพียงอย่างเดียวไม่สามารถสร้างลายเซ็นที่ถูกต้องภายใต้กุญแจที่เชื่อถือได้

## กฎระเบียบจริง ๆ ในไม่กี่บรรทัด

HASH + SIGNATURE

h0 = 064
hi = hex(SHA-256(C(ei)))
σi = Ed25519.Sign(sk, unhex(hi))

**C** คือฟิลด์เหตุการณ์เก้าฟิลด์ในรูป JSON แบบ UTF-8: เรียงคีย์ ไม่มีช่องว่างเกิน ไม่ escape ASCII ไม่มี NaN/อนันต์ `previous_hash` คือ hi−1, h0 คือศูนย์ 64 ตัว ลายเซ็นครอบคลุมไบต์ดิบ 32 ไบต์ของไดเจสต์

ฟิลด์: `seq`, `observed_at`, `source_at`, `kind`, `chat_id`, `message_id`, `actor_id`, `payload`, `previous_hash` ข้อกำหนดฉบับเต็ม: [การเข้ารหัสเหตุการณ์](https://phishdestroy.github.io/TgWitness/th/docs/reference/evidence/#event-canonicalization)

จุดตรวจสอบที่เก็บไว้

Nexport ≥ Ncheckpoint
hexport[Ncheckpoint] = Hcheckpoint

ตรวจลายเซ็นของ checkpoint กับคีย์ที่ปักหมุดไว้ แล้วเทียบกับบันทึก การส่งออกภายหลังยาวกว่าได้ แต่ต้องตรงกันที่ checkpoint
