# Форматы аккаунтов и сеансов

TgWitness входит в систему как **аккаунт пользователя Telegram** (а не как бот) через MTProto с использованием Telethon. Каждый аккаунт находится в собственной **рабочей области** (называемой *рабочая область* в API и инструментах командной строки) со своим сеансом, источниками, журналом и ключом подписи.

Файлы сеансов, строки сеансов и ключи авторизации служат **для авторизации аккаунтов**: любой, кто ими располагает, может действовать от имени данного аккаунта. Они не содержат истории сообщений.

> [!ПРЕДУПРЕЖДЕНИЕ] **Используйте специальные аккаунты.** Telegram ограничивает и может навсегда заблокировать аккаунты за объемы запросов, которые он считает чрезмерными, независимо от клиента или цели, и документирует эти ограничения лишь частично. Подключайте аккаунты, предназначенные для наблюдения, а не личные или иные ценные аккаунты, и создавайте API-ID / API-хеш на специальном аккаунте.

## Краткий обзор

| Что у вас есть | Вкладка **Добавить аккаунт** | Вам также понадобится |
| --- | --- | --- |
| Номер телефона и доступ к кодам входа | **Номер телефона** | Пароль двухфакторной аутентификации (2FA), если она включена |
| Приложение Telegram, запущенное на другом устройстве | **QR-код** | Пароль двухфакторной аутентификации (2FA), если она включена |
| Файл `.session` (Telethon или Pyrogram) | **Файлы** | Дополнительный файл JSON с настройками приложения |
| Файлы `.session` и `.json` с одинаковым именем | **Файлы** (выберите оба) | Обычно больше ничего |
| Папка `tdata` приложения Telegram Desktop | **Файлы** (в формате ZIP) | Локальный пароль Desktop, если он установлен |
| StringSession приложения Telethon (текст, `.txt`, `.tgwitness-session`) | **Файлы** | Отдельная пара API не требуется |
| Ключ аутентификации и DC в одной строке, `<512 hex>:<1–5>` | **Файлы** (вставленный текст или текстовый файл) | Отдельная пара API не требуется |
| Файл в формате `.json`, содержащий сеансы или ключи авторизации | **Файлы** | Отдельная пара API не требуется |
| Ключ аутентификации (512 шестнадцатеричных символов) и его номер DC | **Ключ аутентификации** | Необязательный идентификатор пользователя |

TgWitness распознает файлы по их **содержимому**, а не по именам. Переименование файла никогда не приводит к его преобразованию.

<a id="before-you-start-api-id-and-api-hash"></a>
## Перед началом работы: идентификатор API и хеш API

Вы можете войти в систему без создания приложения Telegram API. Если пара не введена, не импортирована или уже не сохранена в рабочей области, TgWitness выбирает пару из встроенного пула из 50 общедоступных пар API (`tgwitness/api_pool.py`), отдавая предпочтение Telegram Desktop при новом входе в систему и в первую очередь используя сохраненную пару; остальные варианты перемешиваются. Если Telegram отклоняет пару (`API_ID_INVALID`, `API_ID_PUBLISHED_FLOOD`, `UPDATE_APP_TO_LOGIN`), пробуется следующая — до восьми попыток на один вход в систему; отклоненные пары пропускаются до перезапуска. Пара, с помощью которой был осуществлен вход, сохраняется вместе с аккаунтом и повторно используется для него.

Встроенные пары являются общедоступными: они публикуются в открытом исходном коде клиентов и библиотек Telegram. **Идентификатор API** и **хеш API** идентифицируют приложение для Telegram и не предоставляют доступа к данным аккаунтов. При входе используется собственная авторизация аккаунта: код входа и пароль двухфакторной аутентификации (2FA) либо сеанс, в котором аккаунт уже авторизован. В каждой записи `observation.started` указывается использованная пара, поэтому встроенная пара документируется для судебных целей так же, как и ваша собственная. Вместо этого вы можете ввести собственную пару с сайта my.telegram.org. По опыту проекта новая личная пара приводит к выходу из системы большинства аккаунтов, поэтому используйте её только в тех случаях, когда для решения задачи требуется ваше собственное приложение: создайте её с помощью специальной учетной записи и введите до начала сбора данных (шаги приведены ниже).

В полях, где отсутствует информация о подключении, используйте детерминированную пару «устройство/ОС» из [каталогов,](https://github.com/DedInc/opentele2/tree/7e973bc71cd7a714ad13ac703c0895a90d36a735) входящих в состав [opentele2 версии 2.0.0](https://github.com/DedInc/opentele2/tree/7e973bc71cd7a714ad13ac703c0895a90d36a735): Desktop `2040`, Android `6`, Android X `21724`, iOS `10840`, macOS `2834` и Web `2496`. Идентификатор исходной сборки Android `4` также использует каталог Android, как указано в [параметрах BuildVars Telegram для Android](https://github.com/DrKLO/Telegram/blob/master/TMessagesProj/src/main/java/org/telegram/messenger/BuildVars.java). Для Web по умолчанию используется значение «A»; при импорте суффикса версии приложения `K` или языкового пакета `macos` выбирается значение «K», а при версии `0.7.0` — «Webogram». Для неизвестных идентификаторов приложений сохраняются значения по умолчанию хоста Telethon. Импортированные поля всегда имеют приоритет, включая более старую версию приложения и пустой языковой пакет. Каталог никогда не изменяет идентификатор API или хеш. Снимок его версии проверяется явно, а не извлекается во время входа в систему. Сохраненный профиль остаётся неизменным после обновлений.

`account.getAuthorizations` возвращает сохраненные метаданные авторизации Telegram; это не повторение каждого нового вызова `initConnection`. Сравните их с фактически отправленным профилем. Подключение существующей авторизации не проверяет соответствующий хеш API: `initConnection` отправляет идентификатор API, тогда как хеш используется в запросах на вход в систему.

После новой авторизации с помощью телефона или QR-кода TgWitness запрашивает конфигурацию, ближайший дата-центр, статус онлайн, языки (если языковой пакет не пуст), обновления приложения и обновления условий предоставления услуг с интервалом 0,3–1,5 секунды между запросами. Обновление статуса на короткое время помечает аккаунт как находящийся в сети. Эта последовательность выполняется один раз по завершении входа в систему, а не при импорте данных, повторном подключении или перезапуске. Авторизация сохраняется в первую очередь; неудачный запрос останавливает последовательность без повторных попыток или отмены входа. Результаты записываются в поле ``account.initialized`` с указанием названий ошибок, а не телами ответов. Ограничения для аккаунта определяются собственными политиками Telegram.

В случае `tdesktop` при отсутствии параметра `tz_offset` используется локальное смещение по UTC сервера, округлённое до 900 секунд с помощью [алгоритма opentele2](https://github.com/DedInc/opentele2/blob/7e973bc71cd7a714ad13ac703c0895a90d36a735/crates/opentele2-core/src/fingerprint.rs) (MIT; лицензия в `tgwitness/client_profiles.LICENSE`). Это значение обновляется при каждом подключении, чтобы учитывать изменения, связанные с переходом на летнее время. Импортированное значение `tz_offset` имеет приоритет на любой платформе и сохраняется в точности, включая нулевое значение. Остальные записи `initConnection.params` сохраняются. Форма входа по HTTP принимает числовое значение часового пояса, возвращаемое при импорте файла; булевы значения, дробные значения и смещения, выходящие за пределы поддерживаемого диапазона, отклоняются.

Прямые, SOCKS5 и HTTP CONNECT-маршруты используют протокол Telethon `ConnectionTcpObfuscated` (зашифрованный сокращённый MTProto). HTTPS CONNECT сохраняет TLS до прокси и использует тот же зашифрованный транспорт внутри туннеля. MTProxy сохраняет требуемый рандомизированный промежуточный транспорт и обработку секретных данных. При переключении маршрутов применяются те же настройки. Обфускация изменяет структуру пакетов; она не скрывает аккаунт или метаданные клиента от Telegram и не означает иммунитета к ограничениям.

После подключения авторизованного клиента TgWitness проверяет конфигурацию, ближайший дата-центр, текущую авторизацию, базовые параметры проверенного уровня, языки, обновления приложения и обновления условий предоставления услуг. Эти диагностические проверки выполняются один раз для каждого экземпляра клиента перед началом сбора данных и отображаются в деталях соединения с указанием времени. В поле ``account.connection_checked`` фиксируется результат без хешей сеансов, IP-адресов, токенов или хешей API. Они никогда не принимают условия использования и не устанавливают обновления. Сбой запроса или состояние `FloodWait` приостанавливают последующие запросы; отсутствующий результат остаётся неизвестным. Локальные проверки по-прежнему могут сообщать о своих результатах, в то время как сетевые проверки пропускаются. При включенном режиме[Выбранные чаты](COLLECTION.md#strict-chosen-chats) текущая авторизация не запрашивается, и эта проверка отображается как пропущенная.

После входа в систему и при каждом новом подключении TgWitness считывает настройку конфиденциального контента аккаунта. Если она отключена, а Telegram разрешает её изменение, TgWitness включает её, чтобы контент, помеченный Telegram как конфиденциальный (18+), сохранялся, и фиксирует значение `account.content_settings`. Данная настройка относится к аккаунту и применяется во всех приложениях Telegram. Функция «Только выбранные чаты» не влияет на этот параметр; включите её перед входом в систему.

Одновременные запросы на восстановление соединения одной рабочей области используют один и тот же клиент и ожидают завершения установки соединения. Неудачная или отмененная попытка освобождает следующий запрос для повторной попытки. Если во время установки соединения сохраненные учетные данные, клиент или состояние авторизации изменяются, более старая попытка останавливается, а не сообщает о готовности соединения.

Диагностика FloodWait сохраняет неудавшийся метод TL, любые обертки Takeout/range, время ожидания, запрошенное сервером, и фактический крайний срок в `telegram.backoff`. Детали соединения отображают метод и крайний срок, пока запросы приостановлены. Диагностика включает счетчики вызовов клиента по каждому методу с момента создания данного клиента; они отдельно учитывают вложенное разрешение узлов, но не учитывают пакеты или внутренние попытки повтора Telethon. Текущие счетчики также доступны как ``collector.rpc_activity`` в API состояния. Аргументы запросов, имена пользователей, хеши доступа и тексты исключений не включаются. Последний диагностический отчёт и полный срок действия сохраняются после перезапуска. Более ранние периоды ожидания без записи о методе не могут быть отнесены к конкретному запросу задним числом. Ознакомьтесь с [ограничениями на экспорт данных](EXPORT-LIMITS.md) для проверки исходного кода, а также с различиями между обнаружением и сбором исторических данных.

`official_app=True` или `False` — это флаг текущей авторизации Telegram. Ни одно из этих значений не определяет, является ли аккаунт ограниченным, доверенным или находящимся под наблюдением. Существующие моментальные снимки `account.devices`, созданные в режиме «Доказательства», остаются историей всех устройств, на которых осуществлялся вход; диагностика подключений сохраняет только описание текущего устройства.

Перед установлением соединения в рамках предупредительных проверок сравниваются форматы API-платформы, языкового пакета, устройства/ОС и версии приложения, локаль мобильной системы, а также фактический уровень схемы Telegram с базовыми данными проверенного каталога. Предупреждения отображаются в журнале сервера и метаданных статуса аккаунта; они никогда не заменяют импортированные значения и не изменяют уровень схемы. Наличие другого уровня служит сигналом для проверки совместимости; о работоспособности свидетельствует собственный статус подключения аккаунта. Telegram самостоятельно определяет ограничения, независимо от того, какой профиль клиента используется. Статус отключенного аккаунта использует сохраненный профиль вместо генерации нового описания устройства.

Чтобы вместо этого использовать собственное приложение:

1. Откройте сайт [my.telegram.org](https://my.telegram.org) и войдите в систему, указав любой принадлежащий вам номер телефона. Код приходит в приложение Telegram, а не в виде SMS.
2. Выберите **Инструменты разработки API**.
3. Создайте приложение: укажите любое название и краткое имя (5–32 буквы), платформу **Настольный компьютер**. Поля «URL» и «Описание» можно оставить пустыми.
4. Скопируйте **App api_id** (число) и **App api_hash** (32 шестнадцатеричных символа).

В панели откройте раздел **API ID + хеш** под формой входа. Вы можете вставить одну пару `api_id:api_hash` в **поле API ID**, и оба поля будут заполнены. Одну пару можно использовать для всех ваших аккаунтов. После успешного входа данные сохраняются в зашифрованном виде исключительно в данной рабочей области и никогда не отправляются обратно в браузер.

Используются три различных набора учетных данных:

| Секретный ключ | Открывает | Место хранения |
| --- | --- | --- |
| Токен панели | Веб-панель TgWitness | Файл `panel-token.txt` в каталоге данных или `TGWITNESS_TOKEN` |
| Идентификатор API + хеш | Сам по себе ничего не означает; служит для идентификации приложения | Встроенная пара, импортированные настройки или ваше собственное приложение на сайте my.telegram.org |
| Авторизация аккаунта | Аккаунт Telegram | Создана при входе по номеру телефона/QR-коду или импортирована в качестве сеанса |

Если для доступа к Telegram требуется прокси-сервер, сначала настройте его в разделе **Дополнительные инструменты → Аккаунт → Настройки → Настройки подключения → Изменить маршрут подключения**.

<a id="phone-number"></a>
## Номер телефона

1. Откройте **Дополнительные инструменты → Аккаунт**, перейдите на вкладку **Телефон** и введите номер в международном формате, например, `+44 7700 900123`. Пробелы и дефисы удаляются автоматически.
2. Нажмите **Продолжить**. Поля «API ID» и «Хеш» можно оставить пустыми.
3. Введите код, отправленный Telegram, как правило, в приложение Telegram; решение о том, отправлять ли SMS, принимает Telegram.
4. Если для аккаунта включена двухэтапная аутентификация, введите соответствующий пароль. Это не токен панели и не код доступа к устройству.
5. Проверьте идентификатор аккаунта, отображаемый после входа, затем выберите источники.

Коды входа и пароль двухфакторной аутентификации никогда не записываются на диск.

<a id="qr-code"></a>
## QR-код

Используйте эту опцию, если аккаунт уже авторизован на телефоне или другом компьютере.

1. Вкладка **QR-код** → **Показать QR-код**. Поля «Идентификатор API» и «Хеш» можно оставить пустыми.
2. На устройстве, на котором выполнен вход: **Настройки → Устройства → Связать настольное устройство**, отсканируйте код и подтвердите.
3. Введите пароль двухфакторной аутентификации в TgWitness, если Telegram запрашивает его.

Изображение QR-кода генерируется локально. Срок действия кодов ограничен; нажмите **Сгенерировать другой QR-код,** чтобы повторить попытку. Блокировка панели, переключение рабочей области или начало нового входа в систему аннулирует код, ожидающий обработки.

<a id="auth-key--dc-id"></a>
## Ключ аутентификации + ID ЦО

Ключ аутентификации — это исходный 256-байтовый ключ авторизации, лежащий в основе каждого сеанса Telegram, записанный в виде **512 шестнадцатеричных символов** вместе с номером центра обработки данных **DC 1–5**.

1. Перейдите на вкладку **Ключ авторизации**. Вставьте полный ключ; сокращённый ключ, содержащий символ `…`, не будет работать.
2. Выберите идентификатор DC, указанный в ключе.
3. По желанию введите **идентификатор пользователя**. В этом случае TgWitness откажется подключаться, если Telegram сообщит о другом аккаунте.
4. Нажмите **Подключить аккаунт**.

Ключ авторизации (512 символов) не является хешем API (32 символа). Тот же ключ можно также импортировать в формате JSON; см. раздел [JSON-файл аккаунта](#account-json).

<a id="account-files"></a>
## Файлы аккаунта

Откройте **Добавить аккаунт → Файлы** и выберите до **четырёх файлов**, **относящихся к одному аккаунту** (общим объёмом до **8 MiB**), нажмите **Проверить файлы**, а затем **Подключить аккаунт**. При выборе файлов или вставке текста сеанса данные никуда не отправляются; **команда Проверить файлы** отправляет их на ваш сервер TgWitness, который считывает их без входа в систему и отображает найденный сеанс.

Формы **Файлы**, **Ключ авторизации** и «Массовый импорт» отображают предупреждение о параллельных сеансах перед подключением. По умолчанию импортированные авторизации используются повторно. Держите исходный клиент закрытым, пока его ключ используется здесь. Формы **Файлы** и **Ключ авторизации** также предлагают **функцию Создать независимую авторизацию**, описанную ниже. Массовый импорт по-прежнему использует прямой режим. Вход с помощью телефона и интерактивного QR-кода создаёт отдельные авторизации. Заголовок предупреждения остаётся видимым в форме импорта; его полное объяснение открывается автоматически при предоставлении файлов или ключа/строки сеанса. Его можно свернуть после прочтения, чтобы на телефоне оставались доступными элементы управления выбором файлов и подключением.

В случае [сертифицированного развёртывания](PHALA.md) (Phala Cloud, Intel TDX) сбор данных по импортированному ключу не производится. В этом случае **файлы** и **ключ авторизации** связываются только при выбранной **опции Создать независимую авторизацию**; массовый импорт не допускается. Вход по телефону и QR-коду работает в обычном режиме.

- Файлы конвертируются **в памяти** на вашем сервере TgWitness. Загруженные файлы не сохраняются, ZIP-архивы не распаковываются на диск, и не происходит обращения к каким-либо внешним сервисам.
- Затем полученный сеанс проверяется с помощью Telegram. Если в файле указан идентификатор пользователя, он должен совпадать с идентификатором аккаунта, указанным в Telegram.
- Файлы, описывающие разные аккаунты или разные учетные данные API, отклоняются, а не выбираются в приоритетном порядке.
- Поле **Пароль или Текст сеанса** содержит локальное поле пароля TData, поле для вставки StringSession и функцию **Чтение файлов без входа в систему** (заполняет форму без обращения к Telegram). Вставка StringSession очищает выбранные файлы, а выбор файлов — вставленный текст, поэтому при проверке и подключении используется последний выбор. После смены пароля нажмите **Проверить файлы** ещё раз.

<a id="create-an-independent-authorization"></a>
### Создание независимой авторизации

Выберите **Создать независимую авторизацию** перед подключением импортированных файлов или ключа авторизации. TgWitness кратковременно подключается к импортированному «донору», использует его для утверждения токена входа по QR-коду нового клиента и отключается от «донора» сразу после утверждения. Новый клиент имеет собственный ключ авторизации и отдельно выбранный профиль Desktop. Предоставленные донором учетные данные API и профиль устройства используются исключительно для подключения к донору. Ни одна из существующих авторизаций не отменяется и не аннулируется.

**На этом этапе держите исходный клиент донора полностью закрытым.** При первоначальном подключении по-прежнему используется скопированный ключ, поэтому данный режим не может устранить риск параллельного использования. После подключения новой авторизации владелец может вновь открыть исходный клиент и использовать оба одновременно. Интерактивный вход **с помощью QR-кода** позволяет исходному клиенту утвердить вход без копирования или подключения своего ключа на данном этапе.

**Не выходите из системы и не завершайте сеанс донора.** Когда сеанс, утвердивший вход по QR-коду, заканчивается, Telegram также завершает сеанс, которую она утвердила; в ходе тестирования в режиме реального времени новая авторизация прекратилась в течение секунды после выхода донора из системы. При импорте фиксируется сеанс донора (`session_origin.approved_by`: устройство, ID API и время создания). Список сеансов помечает его; команда **Завершить сеанс** отклоняет его, а команды **Завершить все остальные сеансы** и **Сделать этот сеанс единственным** оставляют пользователя авторизованным.

Если Telegram запрашивает двухфакторную аутентификацию (2FA), данный режим использует ключ `twoFA` из выбранного JSON-файла (при его наличии) или запрашивает пароль. В случае отклонения импортированного пароля происходит возврат к форме ввода пароля. Пароли не сохраняются. Ключ-кандидат сохраняется в зашифрованном виде в файле `independent_login.enc`, включая изменения, произошедшие во время миграции между центрами обработки данных. После прерывания выберите того же донора и данную опцию, чтобы возобновить работу с сохраненным ключом-кандидатом. Перед утверждением донор проверяется с помощью `help.getAppConfig`; при замороженном аккаунте процесс останавливается на этом этапе. Если Telegram отклоняет донора до утверждения входа, неутверждённый кандидатский ключ отбрасывается, и импорт можно начать заново. Другой донор заменяет сохраненного кандидата только в том случае, если Telegram сообщает, что этот кандидат не авторизован; кандидат, который авторизован или ожидает ввода пароля двухфакторной аутентификации, сохраняется. Рабочая область остаётся зарезервированной для данного аккаунта; неудачное завершение не приводит к удалению новой рабочей области. Сохраните её каталог данных и ключ хранилища. Окончательные учетные данные и запись в журнале `account.authorized` содержат метод импорта, форматы ввода и API-идентификатор донора, без указания ключа или пароля донора.

5 ноября 2026 года специальный аккаунт прошел проверки в режиме реального времени с донорами Telethon, Pyrogram и TData: завершение двухфакторной аутентификации, уникальные новые ключи авторизации, одновременный доступ донора и нового клиента, а также чтение общедоступного канала. В случае с Telethon также был возобновлен сохраненный кандидат после прерывания на этапе ввода пароля. Каждая новая авторизация завершила шесть запросов инициализации после входа в систему, а её подписанный журнал был проверен. Исходный сеанс оставался пригодным к использованию во всех четырёх предоставленных форматах.

[База](https://core.telegram.org/api/errors.json) данных [ошибок RPC](https://core.telegram.org/api/errors.json) Telegram связывает код `FRESH_CHANGE_ADMINS_FORBIDDEN` со сменой администраторов, `FRESH_CHANGE_PHONE_FORBIDDEN` — со сменой номера телефона, а `FRESH_RESET_AUTHORISATION_FORBIDDEN` — с отзывом других сеансов, изменением их срока действия или регистрацией пароля-ключа. Коды `SESSION_TOO_FRESH_*` и `PASSWORD_TOO_FRESH_*` касаются передачи прав владения, а также снятия средств или пожертвований. Данные операции не относятся к процедурам взыскания задолженности; новый вход в систему не влечёт за собой полный 24-часовой запрет на чтение данных. При экспорте могут отдельно возвращаться значения `TAKEOUT_INIT_DELAY_*`. TgWitness сохраняет паузы, запрошенные сервером, и не предпринимает автоматических повторных попыток принятия токена, а также не аннулирует сеансы с целью обхода ограничений.

**Дополнительные инструменты → Аккаунт → Безопасность аккаунта → Сеансы этого аккаунта → Завершить все остальные сеансы** вызывает функцию ``auth.resetAuthorizations`` по запросу оператора и записывает значение ``account.all_other_sessions_terminated`` с указанием количества сеансов до и после. Telegram принимает это из сеанса, в котором вы находитесь в течение 24 часов. Когда в данной рабочей области выполняется вход с помощью QR-кода из импортированного сеанса, сеанс, который это одобрил, остаётся активным: TgWitness поочерёдно завершает остальные сеансы с помощью `account.resetAuthorization` и фиксирует значение `kept_approving_session`. **Сделав этот сеанс единственным**, программа останавливается с указанием данной причины и не изменяет пароль.

**Если этот сеанс становится единственным,** выполняются те же действия для ключа, созданного при входе из данной рабочей области, после чего включается облачный пароль, если у аккаунта его ещё нет. Панель отображает этот пароль один раз; TgWitness хранит его в хранилище рабочей области только до этого момента. В журнале фиксируется событие `session.exclusive_from`. Если Telegram впоследствии укажет другой сеанс, в журнале фиксируется событие `session.exclusive_ended`, и панель выдает оповещение. Верификатор выводит на экран оба события.

**Установите этот сеанс в качестве единственного, когда Telegram разрешает выполнять** то же действие по таймеру. Эта опция появляется в **разделе Сеансы этой учетной записи** для ключа, созданного в данной рабочей области, и фиксируется как `session.exclusive_automatic`. Во время наблюдения сборщик каждые пять минут проверяет, прошло ли 24 часа с момента записи `account.authorized` для данного ключа — до этого Telegram отвечает кодом `FRESH_RESET_AUTHORISATION_FORBIDDEN` — и затем один раз выполняет ту же операцию. Успех фиксируется как `session.exclusive_from`, аналогично нажатию кнопки вручную. Отказ фиксируется однократно как `session.exclusive_postponed` с указанием причины, предоставленной Telegram, после чего сборщик повторяет попытку с увеличением задержки до шести часов. Режим «Только чтение» здесь не действует: завершение сеансов является действием, связанным с безопасностью аккаунта, а не с чатом.

Облачный пароль, сгенерированный в ходе автоматического выполнения, сохраняется в хранилище рабочей области, зашифрованный ключом рабочей области, до того как Telegram его установит. Панель извлекает его один раз с помощью запроса `POST /api/account/sessions/only/password`, который удаляет его, и отображает в том же диалоговом окне, что и при ручном выполнении, когда вы открываете **раздел Сеансы данного аккаунта**. На странице подключений отображается уведомление о том, что пароль ожидает подтверждения. Он никогда не попадает в журнал и сохраняется после перезапуска до тех пор, пока не будет отображён.

О новых сеансах также сообщается в режиме наблюдения: когда в списке сеансов Telegram появляется новая запись, запись `account.sessions` помещает её в раздел `added`, а панель выдает оповещение с указанием устройства, приложения и страны из данного моментального снимка.

<a id="witness-probe"></a>
### Проверка «Свидетель Probe»

**Дополнительные инструменты → Аккаунт → Безопасность аккаунта → Проверка свидетеля** позволяет проверить, получает ли другой клиент обновления данного аккаунта. Добавьте вторую рабочую область, авторизованную с помощью другого аккаунта Telegram и собственного сеансового ключа, создайте закрытую группу с участием обеих аккаунтов, затем выберите эту группу в качестве **Чата-пробы**, а вторую рабочую область — в качестве **Рабочей области-свидетеля** и включите проверку. Для обеих аккаунтов необходимо отключить **режим Только чтение**, а рабочая область-свидетель должна находиться в режиме наблюдения.

Во время наблюдения данная рабочая область каждые 60–120 секунд отправляет в группу сообщение `probe:<n>:<token>` и регистрирует событие `probe.sent`. Свидетель отвечает сообщением `ack:<n>:<token>` и регистрирует события `probe.seen` и `probe.ack_sent`. Подтверждение (ack), поступающее в данную сессию в режиме реального времени в течение 20 секунд, регистрируется как `probe.acked`. В противном случае рабочая область считывает недавнюю историю группы. Подтверждение (ack), обнаруженное там, но не доставленное в режиме реального времени, регистрируется как `coverage.gap` с причиной `probe_ack_missed_live`: панель генерирует оповещение и помечает приём событий как неудавшийся до тех пор, пока более позднее подтверждение не поступит в режиме реального времени (`connection.restored`, причина `probe_ack_live`). Отсутствие подтверждения регистрируется как `probe.unanswered`; прерывание соединения во время ожидания или нечитаемая история — как `probe.inconclusive`. Режим «только для чтения», ограничения Telegram и паузы FloodWait регистрируются однократно как `probe.skipped`.

### Telethon`.session`

|  |  |
| --- | --- |
| Что это такое | База данных SQLite, создаваемая инструментами на базе Telethon, например, `my_account.session` |

Удаление этих вспомогательных файлов может привести к появлению повреждённой копии.

<a id="session--json-pair"></a>
### Пара «сеанс + JSON»

Аккаунты часто распространяются в виде двух файлов с одинаковым именем, например `447700900123.session` и `447700900123.json`. Выберите **оба файла** одновременно.

- Из JSON TgWitness использует `app_id`/`api_id` и `app_hash`/`api_hash`, поэтому вам, как правило, не нужно вводить учетные данные API.
- В профиле подключения используются `device_model` (псевдоним `device`), `system_version` (псевдоним `sdk`), `app_version`, `lang_code`, `system_lang_code` (псевдоним `system_lang_pack`), `lang_pack` и опциональный параметр `tz_offset` (в секундах от UTC, от -43200 до 50400). Указанные поля имеют приоритет над сгенерированными значениями по умолчанию и языком панели/браузера. Конфликтующие псевдонимы отклоняются. Сформированный профиль сохраняется в зашифрованных учетных данных рабочей области и повторно используется после перезапуска, включая версию приложения.
- Параметры `phone`, настройки прокси и токены устройства **игнорируются**. Параметр `twoFA` считывается только в том случае, если выбран вариант **Создать независимую авторизацию**; при прямом импорте он игнорируется.
- JSON-файл без поддерживаемого поля авторизации является лишь метаданными. Добавьте соответствующий файл сеанса или продолжите вход с помощью телефона или QR-кода. JSON-файл, содержащий поддерживаемый сеанс или ключ авторизации, может самостоятельно выполнить авторизацию; см. раздел [JSON-файл аккаунта](#account-json).

<a id="telegram-desktop-tdata"></a>
### Telegram Desktop (TData)

TData — это папка `tdata` приложения Telegram Desktop (кроссплатформенного приложения с сайта desktop.telegram.org).

| Система | По умолчанию — папка `tdata` |
| --- | --- |
| Windows | `%APPDATA%\Telegram Desktop\tdata` (портативная версия Telegram: рядом с файлом `Telegram.exe`) |
| Linux | `~/.local/share/TelegramDesktop/tdata` |
| macOS | `~/Library/Application Support/Telegram Desktop/tdata` |

Чтобы импортировать данные:

> **Предупреждение о параллельных сеансах.** При прямом импорте TData повторно используется ключ авторизации Telegram Desktop. Не используйте этот ключ одновременно в Desktop и TgWitness. Telegram может аннулировать авторизацию с ошибкой `AUTH_KEY_DUPLICATED`, в результате чего обе копии станут непригодными для использования до нового входа в систему. Полностью закройте Desktop, включая его процесс в системном трее, и держите эту копию закрытой, пока TgWitness использует импортированный сеанс. **Закройте программу, не выходите из сеанса и не отзывайте сеанс:** отзыв также приведёт к аннулированию импортированной копии. Если вам необходимо, чтобы оба клиента работали, выберите **Создать независимую авторизацию** и держите Telegram Desktop закрытым до успешного нового входа в систему, либо войдите в TgWitness с помощью телефона или QR-кода. Рекомендуется использовать выделенный аккаунт, однако и с ним параллельное использование клонированных ключей небезопасно. Это также относится к импортированным файлам `.session`, тексту StringSession и шестнадцатеричному коду ключа авторизации (Auth Key HEX). Другие клиенты с собственными, независимо созданными авторизациями могут оставаться авторизованными. Ознакомьтесь [с документацией Telegram по ошибке AUTH_KEY_DUPLICATED](https://core.telegram.org/api/errors#406-not-acceptable).

1. Полностью закройте Telegram Desktop.
2. Создайте ZIP-архив, содержащий **только** следующие два элемента из папки `tdata`:
   - `key_datas`
   - файл из 16 символов с расширением `s`, расположенный рядом с ним, обычно `D877F783D5D3EF8Cs`

Сжатие всей папки вместе с кэшем медиафайлов, как правило, превышает ограничения (512 записей, 32 MiB в распакованном виде).
3. Выберите ZIP-архив в приложении **Файлы**. Если у Telegram Desktop установлен **локальный пароль**, сначала введите его в поле **Пароль или Текст сеанса**. Это не пароль двухфакторной аутентификации.

Поддерживается: один аккаунт на архив, современное хранилище `key_datas`/`key_data0`/`key_data1`, локальный пароль. Не поддерживается: папки с несколькими авторизованными аккаунтами, устаревшие версии Telegram Desktop, ZIP-архивы, защищённые паролем, а также отдельное нативное приложение для macOS «Telegram for macOS».

<a id="telethon-stringsession"></a>
### Telethon StringSession

Одна строка текста, обычно начинающаяся с цифры `1` и содержащая около 350 символов. Загрузите её в виде файла с расширением `.txt` или `.tgwitness-session` (размером не более 4 КиБ) либо вставьте в поле **Пароль или Текст сеанса**. Принимаются только строки формата Telethon; строки Pyrogram и TDLib используют другие форматы.

<a id="auth-key-and-dc-in-one-line"></a>
### Ключ аутентификации и DC в одной строке

Списки аккаунтов часто содержат исходные данные авторизации в формате `<512 hexadecimal characters>:<DC id>`, например, `a1b2…ef:5`. Вставьте эту строку в **поле Passcode или текст сеанса**, загрузите её как текстовый файл или поместите в поле `session` JSON-файла [аккаунта](#account-json). TgWitness сопоставляет DC 1–5 тем же производственным адресам, что и при импорте JSON-файла с параметрами `auth_key` + `dc_id`, и отображает формат как **Auth key HEX и DC**. Любой другой номер DC или длина ключа отклоняются.

<a id="account-json"></a>
### JSON-файл аккаунта

Один объект JSON размером не более **64 КиБ** в файле с расширением **`.json`**.

| Поле (псевдонимы) | Значение |
| --- | --- |
| `api_id` (`app_id`) | Идентификатор приложения — положительное число |
| `api_hash` (`app_hash`) | Хеш приложения, 32 шестнадцатеричных символа |
| `string_session` (`session_string`, `session_str`; устаревшая версия `session`) | Текст StringSession Telethon или `<512 hexadecimal characters>:<DC id>`; не является именем файла |
| `auth_key` (`auth_key_hex`) + `dc_id` | Полный 512-символьный ключ аутентификации и DC 1–5 |
| `user_id` (`id`) | Необязательно; проверяется в Telegram перед сохранением авторизации |
| `device_model` (`device`) | Описание устройства подключения |
| `system_version` (`sdk`) | Версия ОС устройства, с которого осуществляется подключение |
| `app_version` | Версия приложения, отправляемая в Telegram |
| `lang_code`, `system_lang_code` (`system_lang_pack`), `lang_pack` | Язык клиента, язык системы и языковой пакет клиента; допускается пустое значение параметра `lang_pack` |
| `tz_offset` | Необязательный сдвиг по отношению к UTC в секундах, отправляемый в параметрах ``initConnection.params``; целое число или строка, представляющая десятичное целое число |

Если присутствуют как псевдоним, так и основное имя, они должны совпадать. Явные поля сеанса Telethon имеют приоритет над общим блоком `session` в другом формате. Если оба содержат распознаваемые сеансы Telethon, они должны описывать одну и ту же авторизацию. При отсутствии явного поля `session` должно представлять собой действительную StringSession Telethon либо ключ авторизации и DC в формате `<512 hexadecimal characters>:<DC id>`. Примеры:

```json
{ "app_id": 1234567, "app_hash": "0123456789abcdef0123456789abcdef" }
```

```json
{
  "api_id": 1234567,
  "api_hash": "0123456789abcdef0123456789abcdef",
  "auth_key": "REPLACE_WITH_ALL_512_HEXADECIMAL_CHARACTERS",
  "dc_id": 2,
  "user_id": 123456789
}
```

В первом примере заполняются только учетные данные API; войдите в систему с помощью телефона или QR-кода либо добавьте файл сеанса. Массовые списки (массив аккаунтов в формате JSON) не принимаются.

## Определите, что у вас есть

| Вы видите | Это | Используйте |
| --- | --- | --- |
| `*.session`; при открытии этого файла в текстовом редакторе в верхней части отображается `SQLite format 3` | Telethon или Pyrogram SQLite | **Файлы** (определяются автоматически) |
| Папка `tdata`, содержащая файлы `key_datas` | TData Telegram Desktop | Скомпрессируйте два файла в ZIP, затем **Файлы** |
| Одна текстовая строка, начинающаяся с цифры `1`, длиной около 350 символов | Telethon StringSession | **Файлы** |
| Одна текстовая строка длиной `512 characters 0-9a-f`, затем символ `:` и цифра от 1 до 5 | Ключ аутентификации и DC | **Файлы**, поле **Пароль доступа или текст сеанса** |
| `*.json` с `app_id`/`app_hash` | Сопутствующие метаданные | **Файлы** вместе с соответствующим сеансом |

| 512 символов `0-9a-f` | Ключ аутентификации | **Ключ аутентификации** |

<a id="unsupported-formats"></a>
## Неподдерживаемые форматы

| Формат | Альтернатива |
| --- | --- |
| Хранилище TDLib (файл `td.binlog`) и экспортные данные TDLib | Вход с помощью телефона или QR-кода |
| **Строки** сеанса Pyrogram | Используйте файл Pyrogram`.session`, либо номер телефона/QR-код |
| TData с несколькими авторизованными аккаунтами | Выйдите из других аккаунтов в Telegram Desktop или используйте отдельный файл сеанса для каждого аккаунта |
| Токены ботов | Не поддерживается: TgWitness проводит наблюдение за аккаунтом пользователя |
| Списки аккаунтов в формате CSV/JSON | Импортируйте поддерживаемые файлы сеансов через **меню Учётные записи → Импорт аккаунтов** или входите с помощью номера телефона/QR-кода в отдельных рабочих областях |
| Сеансы Test-DC или ботов | Используйте производственный аккаунт пользователя |

<a id="multiple-accounts"></a>
## Несколько аккаунтов

Нажмите **кнопку +** рядом с выбором аккаунта или откройте **Дополнительные инструменты → Аккаунт → Настройки → Настройки подключения → Рабочие области**, введите название и войдите в систему.

- Любое количество рабочих областей, включая основную. Каждая из них имеет собственный сеанс, маршрут прокси, источники, политику захвата, журнал, ключ подписи, контрольные точки и экспортные данные.
- Переключение отображаемой рабочей области не приводит к приостановке работы остальных.
- Журнал остается привязанным к аккаунту, с которым он был создан. Для входа под другим аккаунтом требуется отдельная рабочая область, при этом один аккаунт не может быть привязан к двум рабочим областям.
- Токен главной панели управляет всеми рабочими областями. [Предоставленный доступ](ACCESS.md) может ограничивать других пользователей выбранными аккаунтами и чатами с отдельными разрешениями и ограничениями по сеансам.
- **Аккаунты** позволяют переименовывать рабочую область и удалять добавленную рабочую область вместе с ее сеансами, журналом, источниками и ключом подписи. Главное рабочее пространство нельзя удалить из панели.

<a id="bulk-import-and-account-groups"></a>
### Массовый импорт и группы аккаунтов

Воспользуйтесь **меню Аккаунты → Импорт аккаунтов**, чтобы добавить несколько аккаунтов, сопоставить файлы по базовому имени и просмотреть результаты каждого входа в систему. Каждый аккаунт получает собственную рабочую область.

Группа объединяет связанные аккаунты, не объединяя при этом их сеансы, ключи или доказательства. **Открытие группы** в **разде**ле **Аккаунты** приводит к её странице по адресу `/groups/<id>`:

- **Аккаунты:** маршрут подключения каждого участника, наблюдение и последнее сообщение, а также кнопки **Запустить всё** и **Приостановить всё**.
- **Требует внимания:** аккаунты, из которых был выполнен выход, которые недоступны или у которых возникли проблемы с подключением, приемом данных, источником или медиафайлами; каждое имя ведёт на соответствующую карточку.
- **Чаты, доступные нескольким аккаунтам:** общие источники, аккаунты, наблюдающие за ними, а также перерывы в периоде доступного наблюдения за рабочей областью (до семи дней). **Экспорт с N аккаунтами** распределяет экспорт канала или супергруппы между ними и подписывает один архив.
- **Экспорт группы:** один ZIP-файл, содержащий подписанный экспорт каждого аккаунта в папке `accounts/` и файл `manifest.json` со списком их SHA-256 и отпечатков ключей, подписанный главной рабочей областью в файле `manifest.signature.json`. Проверьте каждый архив аккаунта отдельно с помощью команды ``python -m tgwitness.verify`` и доверенного отпечатка данного аккаунта.

Участники используют общие настройки группы; аккаунт может сохранять собственные значения. См. [раздел Общие настройки](SETTINGS.md#account-groups), [руководство по импорту и группам](../wiki/Accounts.md#import-accounts-and-share-settings), а также [панель управления пулом MTProxy](../wiki/Proxies.md#pool-dashboard-and-custom-sources).

<a id="sign-out"></a>
## Выход из системы

**Дополнительные инструменты → Аккаунт → Выйти из Telegram** (с приостановкой наблюдения) отправляет запрос в Telegram на завершение сеанса, в результате чего он также исчезает из раздела **Настройки → Устройства** данного аккаунта и удаляется из хранилища рабочей области. Журнал, источники, настройки и ключ подписи остаются, а в журнале фиксируется факт выхода. Рабочая область по-прежнему принадлежит соответствующему аккаунту: только этот аккаунт может подключиться к ней повторно. Если Telegram не отвечает, сеанс всё равно удаляется здесь, и на панели отображается соответствующее сообщение; завершите его в Telegram в разделе **Настройки → Устройства**.

<a id="when-telegram-ends-the-session"></a>
## Когда Telegram завершает сеанс

Если Telegram заблокирует, заморозит или выйдет из аккаунта, либо завершит сеанс с другого устройства, журнал фиксирует причину, ошибку Telegram, маршрут и центр обработки данных. Состояние аккаунта отображается в разделе **Скачать отчёт о потере аккаунта**: это подписанный файл JSON, содержащий записи журнала за 24 часа до потери, а именно: подключения, маршруты, сеансы, уведомления об аккаунте и пробелы в покрытии, каждая из которых имеет свой хеш журнала и подпись. Проверьте его с помощью команды ``python verify.py tgwitness-account-loss.json --fingerprint COLLECTOR_FP``; экспорт доказательств содержит полную цепочку хешей. Заблокированный аккаунт также обнаруживается при подключении и в процессе наблюдения, при этом его действия по отправке сообщений и присоединению к чатам отключаются.

<a id="keeping-account-files-safe"></a>
## Обеспечение безопасности файлов аккаунта

- Относитесь к каждому файлу `.session`, ZIP-архиву TData, StringSession, ключу авторизации и JSON-файлу аккаунта как к паролю. TgWitness хранит импортированные данные авторизации в зашифрованном хранилище; после этого вы можете удалить исходные файлы.
- Не запускайте одну и ту же авторизацию одновременно в двух программах. Telegram может аннулировать её (ошибка `AUTH_KEY_DUPLICATED`), и обе копии перестанут работать.
- Сеанс с истекшим сроком действия или аннулированный сеанс невозможно восстановить путём конвертации. Войдите в систему заново.

<a id="troubleshooting"></a>
## Устранение неполадок

| Сообщение или симптом | Что делать |
| --- | --- |
| *Не удаётся прочитать данный сеанс. Закройте исходный клиент…* | Файл SQLite открыт или не завершен (дополнительный файл `-journal`/`-wal`). Корректно завершите работу исходной программы и скопируйте файл заново. |
| *Поддерживаемые схемы SQLite для Telethon: 7 и 8* / *Pyrogram… 2 и 3* | Файл был создан с использованием очень старой или неизвестной версии библиотеки. Войдите в систему с помощью телефона или QR-кода. |
| *Поддерживаются только авторизованные сеансы пользователей производственной среды* | Файл Pyrogram принадлежит боту или тестовой сети. |
| *Архив TData превышает 512 записей или 32 MiB* | В ZIP-архив следует включить только файлы `key_datas` и `D877F783D5D3EF8Cs`, а не всю папку. |
| *Не удаётся расшифровать TData. Проверьте локальный пароль Telegram Desktop* | Введите локальный пароль Telegram Desktop в **поле Пароль или** в **текстовом поле сеанса**. |
| *Импортируйте по одному аккаунту TData за раз* | В Telegram Desktop было несколько аккаунтов; см. раздел [Неподдерживаемые форматы](#unsupported-formats). |
| *Выбранные файлы относятся к разным аккаунтам или учетным данным API* | Выберите файлы только одного аккаунта. |
| *Файл JSON не содержит поддерживаемых учетных данных API или авторизации* | Проверьте названия полей в [JSON-файле аккаунта](#account-json). |
| *Только метаданные API* | В файле JSON отсутствует сеанс. Добавьте файл `.session` или воспользуйтесь телефоном/QR-кодом. |
| *HEX-код ключа авторизации должен содержать все 512 шестнадцатеричных символов* | Ключ усечён или содержит символы `…`. |
| Идентификатор аккаунта не совпадает с импортированным аккаунтом | Идентификатор пользователя в файле отличается от того, что указывает Telegram; файл относится к другому аккаунту. |
| Аккаунт уже принадлежит другой рабочей области | Откройте эту рабочую область вместо того, чтобы добавлять аккаунт дважды. |
| Учётная запись подключена, но в списке чатов в разделе **Дополнительные инструменты → Источники** отсутствует закрытая группа личных чатов | Проверьте членство в группе. Программа проверяет первые 1 000 диалогов; увеличьте этот лимит в разделе **Дополнительные инструменты → Параметры**. |
| Сбой подключения через прокси | Проверьте маршрут и режим IP. Автоматический MTProxy пробует использовать другую рабочую запись. Режим «Скрыть адрес» ожидает; режим «Прямой» в крайнем случае может установить соединение напрямую после заданной задержки. См. [режимы маршрутизации](CONNECTION-SECURITY.md#ip-modes). |

См. также: [подключение и безопасность](CONNECTION-SECURITY.md) для прокси и шифрования, а также [принцип работы сбора данных](COLLECTION.md) о том, что фиксируется после входа в систему.
