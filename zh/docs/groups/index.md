# Telegram · 管理一组账户

Canonical page: https://phishdestroy.github.io/TgWitness/zh/docs/groups/

同时运行多个账户，每个账户仍有自己的记录和密钥。

账户组将连接状态、启动/暂停、共享设置和导出放在同一个界面上。多个账户处理同一案件时很方便。

## 打开群组概览

在**账户**中打开账户组。每个账户显示其状态、路由、延迟和最后保存的消息。**需关注**列出出问题的账户，**修复**直接带您过去。

**全部开始** / **全部暂停**会先询问再执行。**组设置**是共享的，但账户自己的值会一直保留，直到您替换它们。

### 审查群组内的路线变更

合成示例 · 说明性检查及结果

1. **选择。**选择群组并查看哪些账户将发生变更。
2. **准备工作。**当需要保持独立时，请保留账户自身的路径。
3. **检查。**测试建议的连接并检查测量结果。
4. **提交。**保存前请重新检查，并审查每个账户的处理结果。

#### 案件团队

频道采集器 · 群组采集器 · 参考账户

3 个独立的工作区

#### 已审核内容

2 个账户采用建议的流程。

参考账户保持其独立路径。

#### 准备工作检查

频道采集器：Telegram传输时延 84 毫秒

群组采集器：Telegram传输时长 91 毫秒

这些数字是示例中的虚构数据。

#### 应用结果

频道采集器：已保存，观察已恢复。

群组收集器：重新检查失败，已恢复先前设置。

参考账户：保留原有路径。

## 在流程中增加一个审核步骤

1. **更改群组路由**，选择类型和设置。
2. **审查选择**：查看哪些账户会变更，哪些有自己的路由。
3. **准备并检查**会测试新的 Telegram 连接，并在可能时测试出口 IP。
4. **应用已检查的连接**，并查看每个结果。正在运行的账户继续运行，空闲的保持空闲。

延迟是建立 Telegram 连接的时间，出口 IP 是检查时路由显示的地址。结果可能因账户而异。

## 使用重叠访问权限

**多个账户可见的聊天**列出共享来源及其覆盖范围。频道和超级群组可以通过**用 … 个账户导出**由多个账户同时导出。私聊和普通群组不行，它们的消息编号按账户计算。

## 将群组导出为包

**导出组**会生成一个 ZIP，包含每个账户的签名导出及其签名列表。每份导出都保留自己的指纹用于验证。合并的时间线仍需您自己整理。
