## قم بإعداد بوت وقناة

أنشئ بوتًا عبر BotFather واسمح له بالنشر في قناتك. شغّل الشاهد في مكان آخر: مضيف آخر، ويُفضَّل أن يديره شخص آخر، أثمن بكثير من عملية ثانية بجوار المُجمِّع.

## ثلاث خطوات في قسم «Extras»

1. **وصول للقراءة فقط.** **الإضافات ← الشاهد المستقل**، أنشئ رمزًا واحفظ الملف. يقرأ نقاط التحقق والحالة، لا أكثر.
2. **القناة والفاصل الزمني.** قناة Telegram أو webhook في Discord، إضافة إلى عنوان مُجمِّع يستطيع الشاهد الوصول إليه. احفظ ملف الإعدادات.
3. **التشغيل.** ضع `witness.json` و`witness-token.txt` و`bot-token.txt` معًا على مضيف الشاهد وشغّل:

```
python -m tgwitness.witness run --config witness.json --check-config
python -m tgwitness.witness run --config witness.json
```

انتظر أول منشور موقّع في القناة، ثم احفظ بصمة الشاهد في مكان آمن.

تفضّل Discord؟ احفظ عنوان webhook باسم `discord-webhook.txt`. ينشر الشاهد الواحد في مكان واحد، والفحوص الطويلة تصل كملف على Discord.

## اختر وتيرة النشر

نشر كل فحص يعطي سجلاً خارجيًا منتظمًا: كل خمس دقائق تعني نحو 288 منشورًا يوميًا لكل مساحة عمل. الإعدادات المتقدمة تتيح النشر عند التغييرات أو المشكلات فقط، أو استخدام وكيل أو Bot API مخصص.

**ما الذي يشهد به هذا البوت فعليًّا؟**

يطلب من المُجمِّع نقطة تحقق موقّعة، ويفحصها مقابل المفتاح المتوقع، ويحتفظ بسجله الموقّع الخاص، بما في ذلك الردود الفائتة والمرفوضة.

يفحص حالة السجل، ولا يراقب Telegram بنفسه. لذلك، أجرِ اختبار تسليم مضبوطًا.

## تحقق من الأدلة لاحقًا

احتفظ بسجل الشاهد ومنشوراته وبصماته. [كيف تتحقق منها](https://phishdestroy.github.io/TgWitness/ar/docs/reference/witness/#verify) مقابل تصدير المُجمِّع.
