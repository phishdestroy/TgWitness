# Управление группой учетных записей

Canonical page: https://phishdestroy.github.io/TgWitness/ru/docs/groups/

Управляйте несколькими учетными записями для сбора данных одновременно, сохраняя при этом отдельность записей и идентификаторов подписи для каждой учетной записи.

Группа учетных записей объединяет статус подключения, элементы управления наблюдением, общие настройки и экспорт в единое рабочее окно. Это удобно, когда несколько учетных записей относятся к одному расследованию или требуют единой конфигурации работы.

## Открыть обзор группы

В разделе **«Учётные записи**» откройте группу. Для каждой учётной записи отображается статус наблюдения, маршрут соединения, последнее измеренное время задержки маршрута при успешной текущей проверке и последнее сохраненное сообщение. Ссылки **«Требует внимания»** указывают на учётные записи, требующие обработки; **кнопка «Исправить»** открывает соответствующую рабочую область и панель управления.

**Функции «Запустить всё»** и **«Приостановить всё»** действуют на соответствующие аккаунты после подтверждения. **Групповые настройки** позволяют совместно использовать выбранные параметры; аккаунты с собственными значениями сохраняют их до тех пор, пока вы не решите их заменить.

### Проверьте изменение маршрута в группе

Синтетический пример · иллюстративные проверки и результаты

1. **Выберите.** Выберите группу и проверьте, какие аккаунты будут изменены.
2. **Подготовка.** Сохраняйте отдельный маршрут для каждого аккаунта, когда это необходимо.
3. **Проверьте.** Протестируйте предложенное соединение и проанализируйте результаты измерений.
4. **Приступить к работе.** Перед сохранением проверьте текст ещё раз и проанализируйте результат для каждой учётной записи.

#### Команда по делу

Коллектор каналов · Коллектор групп · Справочная учетная запись

3 отдельных рабочих пространства

#### Проверенный текст

2 аккаунта следуют предложенному маршруту.

Справочный аккаунт следует собственному маршруту.

#### Проверки перед началом работы

Коллектор каналов: время передачи данных в Telegram — 84 мс

Групповой сборщик: время передачи данных Telegram — 91 мс

Эти цифры являются вымышленными показателями, приведенными в качестве примера.

#### Результаты применения

Коллектор каналов: маршрут сохранен, наблюдение возобновлено.

Групповой сборщик: повторная проверка завершилась неудачно, восстановлены предыдущие настройки.

Справочный аккаунт: собственный маршрут сохранен.

## Измените маршрут, добавив этап проверки

1. Выберите **«Изменить маршрут группы**», затем выберите тип подключения и настройки.
2. Выберите **«Просмотр выбора**». Просмотрите перечисленные учетные записи и их индивидуальные настройки маршрутизации.
3. Выберите **«Подготовить и проверить**». При проверке используется новый транспорт Telegram; поддерживаемые HTTP-маршруты также сообщают о результатах проверки выхода через HTTPS.
4. Выберите **«Применить отмеченные подключения»** и проверьте результаты по каждому аккаунту. Ранее запущенное наблюдение возобновляется там, где приложение работает успешно; неактивные аккаунты остаются неактивными.

Задержка описывает измеренное время установления соединения с Telegram. Проверка IP-адреса выхода описывает этот маршрут на момент записи проверки. Авторизация учетной записи и состояние наблюдения имеют свои собственные показатели; смена группы может привести к разным результатам для каждой учетной записи.

## Используйте перекрывающийся доступ

**В разделе «Чаты нескольких аккаунтов»** отображаются общие источники и доступный охват наблюдения за рабочей областью. Для соответствующих каналов и супергрупп можно использовать **функцию** **«Экспорт с … аккаунтами»,** чтобы разделить сбор истории одного чата. Личные чаты и обычные группы остаются привязанными к исходному аккаунту, поскольку номера их сообщений относятся к истории этого аккаунта.

## Экспорт группы в виде пакета

**Функция «Экспорт группы»** создает один ZIP-файл, содержащий подписанный экспорт каждого аккаунта и подписанный список этих файлов. Идентификаторы и отпечатки исходной рабочей среды остаются доступными для проверки. Составьте межаккаунтную хронологию, используя эти ссылки; единая объединенная временная шкала по-прежнему формируется отдельно.

Продолжить работу с [оформлением отчёта](https://phishdestroy.github.io/TgWitness/ru/docs/reports/), [панелью «Case Board» в рабочей области](https://phishdestroy.github.io/TgWitness/ru/docs/case-board/) или [проверкой экспорта](https://phishdestroy.github.io/TgWitness/ru/docs/exports/).
