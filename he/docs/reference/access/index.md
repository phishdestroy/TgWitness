הענק למבקר גישה לצ'אט אחד, לאנליסט הרשאה לייצא תיק, או למפעיל שליטה על חשבונות נבחרים. כל אדם מקבל אסימון משלו. האסימון של לוח הבקרה הראשי נשאר בידי המנהל.

## שני תחומי פעילות, שתי משימות שונות

**היקף האיסוף** קובע מה יוקלט בחשבון: צ'אטים נבחרים, תיקיית טלגרם או החשבון כולו. **היקף הגישה** קובע אילו מבין החשבונות והצ'אטים המוקלטים אדם אחר יכול לראות ולהשתמש בהם. מתן גישה אינו מצרף את המשתמש לצ'אט בטלגרם, אינו מתחיל איסוף ואינו מעניק הרשאות לחשבון טלגרם.

גישה יכולה לפתוח סביבות עבודה נבחרות, צ'אטים נבחרים בתוכן, את כל סביבות העבודה, או כל חשבון בקבוצת [חשבונות](https://phishdestroy.github.io/TgWitness/he/docs/reference/accounts/#bulk-import-and-account-groups). **כל סביבות העבודה, כולל אלה שנוספו מאוחר יותר**, מכסות גם חשבונות עתידיים. גישה לקבוצה מכסה גם חשבונות שנוספו לאותה קבוצה מאוחר יותר. יש לבחור סביבות עבודה במפורש כאשר יש להגביל את התיק אליהן בלבד.

## הענק גישה למישהו

1. התחבר כמנהל הראשי ופתח **את "Access"**.
2. תחת "**הענק גישה למישהו**", הזן שם שתוכל לזהות ביומן.
3. בחרו את סביבות העבודה, ובמידת הצורך, את הצ'אטים הבודדים.
4. בחר מה האדם הזה עשוי לעשות. האפשרות "**הצג"** כלולה תמיד.
5. הגדר את תוקף ההרשאה, מגבלות הכניסה/הפעילות והכתובות המותרות לפי הצורך.
6. לחץ על "**צור גישה**". העתק את האסימון כעת: הוא מוצג רק פעם אחת.
7. שלחו את כתובת הפאנל ואת האסימון באופן פרטי. הנמען מזין את האסימון הזה בדף הכניסה הרגיל; הוא אינו זקוק לאסימון הפאנל הראשי שלכם או למפגש טלגרם.

פתח את החלונית עם האסימון שהונפק במושב דפדפן נפרד ובדוק את הצ'אטים הגלויים ואת הפעולות המותרות לפני שתמסור אותו.

## בחר את ההרשאות

להדגמה ציבורית בטקסט בלבד, השתמשו ב**"תצוגה ציבורית"** במקום בגישה רגילה לבוחן. היא מציגה ערוצים ציבוריים שנבחרו במפורש, עריכות שנשמרו ו מחיקות, וכן סטטיסטיקות חתומות, כאשר שדות המחבר מושחרים והקבצים נסגרים בגבול ה-API. [צרו ואימתו תצוגה](https://phishdestroy.github.io/TgWitness/he/docs/reference/showcase/).

| הרשאה | מה הוא מאפשר |
| --- | --- |
| `view` | קראו צ'אטים מורשים, הודעות שנלכדו, פרופילים, קבצים ורשומות יומן מסוננות. כל אלה כלולים תמיד. |
| `export` | ניתן לייצא היסטוריית צ'אט ותיקים. ייצוא ראיות מכל סביבת העבודה מחייב גישה לכל סביבת העבודה. |
| `sources` | ניהול מקורות, צילומי מסך ולכידת פרופילים. גישה מוגבלת לצ'אטים יכולה לפעול רק בצ'אטים המותרים; גילוי מקורות והגדרות היקף ברמת החשבון נשארים סגורים. |
| `collect` | הפעל או הפסק את פעולת האספן. נדרשת גישה לכל סביבת העבודה, מכיוון שהאיסוף משפיע על החשבון. |
| `interact` | בצע אינטראקציות נתמכות ב-Telegram במסגרת היקף הגישה. גישה מוגבלת לצ'אט אינה מאפשרת שימוש בתצוגה מקדימה של קישורים ברמת החשבון. |
| `settings` | שינוי הגדרות האיסוף, חותמות זמן, התראות, עותקים מחוץ לאתר ופרמטרים. דורש גישה לכל סביבת העבודה. |
| `account` | התחבר או התנתק מ-Telegram ונהל את נתיבי החיבור. דורש גישה לכל סביבת העבודה. |
| `board.read` | קרא את ההערות בלוח המקרים רק בתוך סביבת העבודה והצ'אטים המותרים. |
| `board.write` | הוספת סימניות, הדגשות, קטעים, הערות ומצבי פתיחה/סקירה. נדרש גם ``board.read``. |
| `board.manage` | נהל אוספים, סטטוסים סופיים של הצוות וכרטיסי משתתפים אחרים. נדרשת גם גישה לקריאה/כתיבה ללוח. |

ההרשאות וההיקף נבדקים יחד. סימון הרשאה אינה פותחת צ'אטים אחרים ואינה מבטלת את ההגבלה על גישה לצ'אט מסוים לכל מרחב העבודה. לייצוא מקביל, הגישה חייבת לכסות את הצ'אט המיוצא בכל חשבון שנבחר. גישה שהונפקה אינה יכולה ליצור גישות חדשות, לנהל את הפעילויות של משתמשים אחרים או לפתוח את קונסולת המנהל.

### שלוש הגדרות שימושיות

| אדם | היקף | הרשאות |
| --- | --- | --- |
| מבקר | צ'אטים מוקלטים ממקרה אחד | `view` |
| אנליסט המכין מסמך העברה | הצ'אטים שיש לחקור ולייצא | `view`, `export`; הוסף את `interact` רק אם עליהם לפעול דרך טלגרם |
| מפעיל איסוף | סביבות עבודה שלמות נבחרות | `view`, `sources`, `collect`; הוסיפו `settings` או `account` רק במידת הצורך |

הגדרות ברירת המחדל של טופס הגישה כוללות גם את לוח התיקים: הבודק יכול לקרוא, האנליסט יכול לקרוא ולכתוב, והמפעיל יכול לנהל אותו. ניתן לערוך את הגדרות ברירת המחדל, וההרשאות הקיימות אינן מורחבות באופן אוטומטי. ראו [לוח התיקים](https://phishdestroy.github.io/TgWitness/he/docs/reference/case-board/) לקבלת טווחי צ'אט שעברו בירושה והגדרות פרטיות בייצוא.

## מגבלות ומפגשים

| הגדרה | איך זה עובד |
| --- | --- |
| מושבים מקבילים | הגבל את מספר הפעילויות המקבילות ל-1–100. כאשר מגיעים למגבלה, דחה את הכניסה הבאה או סיים את הפעילות הוותיקה ביותר. |
| כניסה מותרת | הגבל את מספר השימושים המוצלחים באסימון לפתיחת הפעלות. הפעלות קיימות אינן מסתיימות רק משום שנעשה שימוש בכניסה המותרת האחרונה. |
| תקף עד | תוקף הגישה פג לחלוטין. גישה שפג תוקפה אינה יכולה להתחבר או להמשיך לבצע בקשות. |
| דקות ללא פעילות | זמן ההשהיה של חוסר פעילות בפגישה, מ-5 דקות עד 30 ימים. בקשות מוצלחות מאריכות אותו; חלון פתוח עשוי לשמור על פעילותו באמצעות סקירה. |
| כתובות מותרות | קבל כתובות IP ספציפיות או תת-רשתות CIDR. השאר ריק כדי לאפשר כל כתובת, אלא אם כן מופעלת קישוריות לכניסה ראשונה. |
| התקשר לכניסה הראשונה | הכניסה המוצלחת הראשונה קובעת את הכתובת המותרת עבור גישה זו. |

כתובת ה-IP היא כתובת הלקוח הנראית על ידי היישום. מאחורי פרוקסי הפוך או מנהרה, יש לבדוק את הכתובת המוצגת תחת "**הפעלות פתוחות"** לפני הסתמכות על כללי IP: אחרת, ייתכן שייראה כי מספר משתמשים חולקים את כתובת הפרוקסי.

## שינוי או ביטול הגישה

ערוך ערך תחת **"גישה שהוענקה"** כדי לשנות את היקפה, ההרשאות או המגבלות שלה. שינויים בהיקף ובהרשאות נבדקים בבקשות עוקבות, כולל בקשות ממפגשים שכבר פתוחים. ביטול גישה מסיים את המפגשים שלה והופך את האסימון שהונפק לבלתי שמיש. "**מפגשים פתוחים"** מאפשר גם למנהל לסיים מפגש בודד מבלי לבטל את הגישה כולה.

עותקי הייצוא השמורים שומרים על זהות היוצר, סביבת העבודה, היקף הצ'אט וההרשאות הנדרשות. בעל גישה שהונפקה יכול להציג או להוריד עותקים משלו רק כל עוד ההרשאות הללו עדיין בתוקף; עותקים המכילים את "לוח התיקים" (Case Board) דורשים גם הרשאת ``board.read``. המנהל יכול לאחזר את כל העותקים. עותקים ישנים יותר ללא מטא-נתונים אלה וחבילות קבוצתיות מיועדים למנהל בלבד. כרטיסי הורדה ותגובות קבצים מוכנות בודקות מחדש את הגישה לאחר הכנת הקובץ, לפני שליחת הבייטים שלו.

ביטול ההרשאה אינו מאפשר לשחזר קבצים שכבר הורדו על ידי מישהו. יציאה מהמערכת, נעילת המסך או סיום הפעלה אינם עוצרים את פעולת האספן.

## מה המנהל יכול לראות

הבוחנים והאנליסטים מקבלים דיווח על התקדמות האיסוף ללא נקודות קצה של פרוקסי, אבחון מאגרים, נתיבי שרתים או שגיאות חיבור גולמיות. אבחון החיבור מחייב הרשאת `account` על כל סביבת העבודה. קריאת התראות, העתקה מחוץ לאתר והגדרות פרמטרים מחייבות הרשאת `settings`.

מחרוזות User-Agent המלאות בדפדפן אינן נשמרות במפגשי הגישה. שדרוג מסיר אותן גם ממטמון המפגשים הניתן לשינוי. יומן תהליכי הפאנל מסתיר כתובות IP, פרטי הזדהות URL וסודות מתויגים. יומני שירות מקומיים ו רשומות יומן שנחתמו בעבר אינם נכתבים מחדש. כללי הגישה ורשומות הכניסה החתומות עדיין משתמשות בכתובת הלקוח.

### החלף את המפתח הראשי

השתמש ב-**Access → המגבלות שלי → הנפק מחדש את מפתח המנהל**, או הפעל את `tgwitness token rotate` מהתקנה מנוהלת בזמן שהלוח פועל. כל הפעלות הדפדפן הקיימות מסתיימות, כולל הפעלות שנפתחו באמצעות אסימוני עמיתים. הדפדפן המבקש מקבל הפעלה חדשה; שמור את מפתח המנהל החדש לפני שתסתיר אותו. אסימוני עמיתים שהונפקו נשארים בתוקף עד לביטולם בנפרד. התקנה המשתמשת ב-`TGWITNESS_TOKEN` חייבת לשנות את הגדרת הסביבה הזו ולהפעיל מחדש.

### גבולות בקשות ופרוקסי

ה-API מאפשר עד 600 בקשות בדקה לכל כתובת IP של לקוח. עשר אימותים שנדחו בתוך דקה מפעילים תקופת המתנה אקספוננציאלית, הנעה בין שנייה אחת עד חמש דקות. ניסיון כושל לאחר תקופת ההמתנה מאריך אותה; עשר דקות ללא ניסיון כושל מאפסות את ההסלמה. דחיות מחזירות את הקודים HTTP 429 ו- `Retry-After`. המגבלות נמצאות בזיכרון, משותפות בין סביבות העבודה בתהליך לוח אחד; הפעלה מחדש מוחקת אותן. שידורים חיים מוגבלים לארבעה לכל אסימון נושא ו-32 לתהליך הלוח. פתיחת שידור צורכת גם היא מתקציב בקשות ה-API.

לגופי הבקשות יש מועד אחרון לקבלה של 60 שניות (8 שניות עבור MCP). כל יישום מגביל גופים לא גמורים ל-32 בקשות ו-64 MiB של מכסת נתיבים שמורה. גופים גדולים מדי מחזירים 413, גופים שחלף זמן ההמתנה שלהם מחזירים 408, וקיבולת גופים שנוצלה במלואה מחזירה 503 עם `Retry-After`.

כותרות IP מועברות מתעלמות, אלא אם כן העמית ה-TCP בפועל שייך ל- `TGWITNESS_TRUSTED_PROXIES` (כתובות IP מופרדות בפסיקים או CIDRs). הגדר `TGWITNESS_PROXY_HEADER` ל-`x-forwarded-for` או `cf-connecting-ip`. XFF עובר מהפרוקסי הקרוב ביותר לעבר העמית הלא-מהימן הראשון. מטא-נתונים של כתובות מהימנות שאינם תקינים או כפולים נדחים, ולכן אינם יכולים לרשת כתובת פרוקסי המופיעה ברשימת ההיתרים. המנהרה המהירה המנוהלת סומכת על המחבר המקומי של Cloudflare; ההגדרה של הדומיין הפרטי סומכת על Caddy המקומי. פריסות ישירות אינן סומכות על אף פרוקסי כברירת מחדל. אם אתה מפעיל את Uvicorn בעצמך, השבת את עיבוד כותרות הפרוקסי שלו, כך שגבולות אלה יקבלו את העמית בפועל.

`TGWITNESS_PANEL_ALLOWED_IPS` מגביל את כל הגישה ללוח הבקרה, כולל זו של המנהל, לכתובות IP או CIDR המפורטות ברשימה. בדיקת זהות הניתוב של תוכנית ההתקנה נשארת ציבורית ואינה מחזירה נתוני חשבון. יש לכלול את נתיב הניהול המקומי הנדרש לפני הפעלת רשימת ההיתרים. המדריך **START-HERE** להתקנה מנוהלת כולל את הוראות תצורת השירות והשחזור.

בוחר שאילתות API מסוג `ws` חייב לזהות את סביבת העבודה בנתיב הבקשה; בוחרים לא ידועים, שאינם תואמים או כפולים נדחים עם שגיאה 404.

סקריפטים וסגנונות של לוחות הבקרה נושאים מטא-נתוני תקינות SHA-384. מפת ייבוא מכסה גם מודולי JS המיובאים באופן מקומי בדפדפנים התומכים בתקינות מפת הייבוא. התגובה השפתית שנוצרת באופן דינמי היא נפרדת. בדיקות אלו מאתרות החלפת נכסים ביחס לדף שנמסר; הן אינן קובעות אמון בשרת שנפרץ, שיכול להחליף הן את הדף והן את ההאשים שלו.

**היומן מאז תחילתו** משלב יומני תהליכים עם פעילות היומן מכל סביבת עבודה: כניסות, סירובים, שינויי מסלול ופעולות המפעיל. זוהי קונסולה בזיכרון עבור התהליך הנוכחי, ולא עותק קבוע של כל הודעה. אירועי הודעות תכופים נשמרים ביומן במקום למלא את הקונסולה.

הענקת גישה, שינויה וביטולה, וכן פתיחת או סיום הפעלות, יוצרים גם הם רשומות חתומות ביומן ה-`access.*`. אסימונים אינם כלולים ברשומות אלה. אסימונים שהונפקו ופרטי הזדהות של הפעלה נשמרים כ-hashים בכספת המוצפנת.

****מנהל ראשי וגבולות האמון****

The main panel token remains unrestricted. Browser sign-ins with it create sessions subject to the administrator's configured session limits. Scripts sending the main token directly retain full access and are not counted as browser sessions.

This is application-level access control in one installation. All workspaces share the server process; this is not isolation from the host administrator. Keep the main token, Telegram sessions, signing keys and data directory private. A witness token is a separate checkpoint/health credential, not a panel access token.
