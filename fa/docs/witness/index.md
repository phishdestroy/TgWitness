تمام مثال‌های پاسخ‌دهی فرض می‌کنند که امضای معتبر و کلید سنجاق‌شده وجود دارد. هش‌های اینجا نمونه‌های مختصر هستند. تنها تعداد بیشتر به‌تنهایی نمی‌تواند ثابت کند که کل پیش‌وند قدیمی بدون تغییر باقی مانده است؛ خروجی را با نقاط کنترل حفظ‌شده مقایسه کنید.

## یک ربات و یک کانال آماده کنید

با BotFather یک ربات بسازید و اجازه دهید در کانالتان پست بگذارد. شاهد را جای دیگری اجرا کنید: میزبانی دیگر، ترجیحاً با مدیریت کسی دیگر، بسیار ارزشمندتر از فرایند دومی کنار جمع‌کننده است.

## سه مرحله در بخش اضافی

1. **دسترسی فقط‌خواندنی.** **افزونه‌ها ← شاهد مستقل**، توکن بسازید، فایل را ذخیره کنید. فقط نقاط بازرسی و سلامت را می‌خواند، نه چیز دیگری.
2. **کانال و فاصله زمانی.** کانال Telegram یا webhook دیسکورد، به‌علاوه آدرس جمع‌کننده‌ای که شاهد به آن دسترسی دارد. فایل تنظیمات را ذخیره کنید.
3. **اجرا.** `witness.json`، `witness-token.txt` و `bot-token.txt` را با هم روی میزبان شاهد بگذارید و اجرا کنید:

```
python -m tgwitness.witness run --config witness.json --check-config
python -m tgwitness.witness run --config witness.json
```

منتظر اولین پست امضاشده در کانال بمانید، سپس اثر انگشت شاهد را جای امنی ذخیره کنید.

به‌جای آن Discord؟ URL وب‌هوک را با نام `discord-webhook.txt` ذخیره کنید. هر شاهد در یک جا منتشر می‌کند؛ بررسی‌های طولانی به‌صورت فایل در Discord می‌رسند.

## انتخاب کنید هر چند وقت یک‌بار منتشر شود

انتشار هر بررسی یک سابقه بیرونی منظم می‌دهد: هر پنج دقیقه یعنی حدود 288 پست در روز برای هر فضای کاری. تنظیمات پیشرفته می‌توانند فقط هنگام تغییر یا مشکل منتشر کنند، یا از پروکسی یا Bot API سفارشی استفاده کنند.

**این بات در واقع چه چیزی را تصدیق می‌کند؟**

از جمع‌کننده یک نقطه بازرسی امضاشده می‌خواهد، آن را با کلید مورد انتظار بررسی می‌کند و ژورنال امضاشده خودش را نگه می‌دارد، از جمله پاسخ‌های ازدست‌رفته و ردشده.

وضعیت ژورنال را بررسی می‌کند، خودش Telegram را زیر نظر ندارد. برای آن، یک آزمون تحویل کنترل‌شده اجرا کنید.

## بعداً شواهد را بررسی کنید

ژورنال شاهد، پست‌ها و اثر انگشت‌ها را نگه دارید. [چطور آن‌ها را بررسی کنید](https://phishdestroy.github.io/TgWitness/fa/docs/reference/witness/#verify) در برابر خروجی جمع‌کننده.
