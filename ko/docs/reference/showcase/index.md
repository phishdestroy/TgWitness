# 공개 쇼케이스

Canonical page: https://phishdestroy.github.io/TgWitness/ko/docs/reference/showcase/

선택한 공개 채널의 저장된 메시지와 서명된 스냅샷을 유효 기간이 정해져 있고 취소 가능한 링크를 통해 게시합니다.

**'Access → Public showcase'는** 기존의 액세스 토큰 시스템을 사용하여 별도의 읽기 전용 페이지를 생성합니다. 이 페이지는 설치 환경에 저장된 관측 데이터를 읽어옵니다. 이 기능은 방문자를 위해 수집기를 시작하거나, 텔레그램에 로그인하거나, 채널을 확보하지는 않습니다.

## 페이지 게시하기

1. 표시하고자 하는 각 공개 채널에 대해 소스 프로필을 저장하세요. 채널은 가장 최근에 저장된 프로필에 공개 사용자 이름이 포함되어 있어야 하며, 그룹 및 비공개 채팅은 대상이 아닙니다.
2. 오픈 **액세스 → 공개 쇼케이스** (또는 `/showcase-manage.html`) 관리자 권한으로.
3. 최대 16개의 워크스페이스에 걸쳐 채널을 선택하고, 공개 페이지 제목을 입력한 다음, 링크 유효 기간을 1일, 7일 또는 30일 중 하나로 선택합니다. 워크스페이스 내부의 레이블은 공개되지 않습니다. 최대 64개의 채널을 포함할 수 있습니다.
4. 게시할 선택된 채널의 텍스트를 검토한 후, **‘선택한 기록 미리 보기’를** 클릭하세요. 미리 보기는 방문자 페이지와 동일한 서버 측 투영 방식을 사용합니다.
5. **'쇼케이스 생성' 링크를** 클릭하세요. 링크가 표시되어 있는 동안 복사하세요. 별도의 브라우저에서 링크를 열어 수신자에게 배포하기 전에 페이지를 미리 확인하세요.

링크의 URL 프래그먼트에는 액세스 토큰이 포함되어 있습니다. 이 페이지는 API 요청을 수행하기 전에 프래그먼트를 제거하고 이를 브라우저 세션으로 대체합니다. 링크를 보유한 사람은 누구나 만료되거나 취소될 때까지 선택된 자료를 열 수 있습니다. 새 링크는 최대 100개의 동시 세션을 허용하며, 각 세션의 지속 시간은 최대 1시간입니다. 기존 액세스 제어 기능은 grant API를 통해 주소 제한 및 로그인 횟수 제한을 적용할 수도 있습니다. 일반 검토자 액세스는 별도의 모드이며, 여전히 원래 허용된 메시지와 파일을 포함합니다.

## 방문자가 보는 화면

| 표시됨 | 비공개로 유지됨 |
| --- | --- |
| 선별된 공개 채널 제목, 사용자 이름 및 프로필 확인 날짜 | 계정 식별자, 내부 워크스페이스 레이블 및 선택되지 않은 소스 |
| 캡처된 텍스트 및 저장된 각 편집 내용 | 구조화된 발신자 ID, 이름, 사용자 이름, 전화번호 및 프로필 정보 |
| 가능한 경우, 이전에 저장된 텍스트와 함께 삭제 내역 확인 | 첨부 파일, 아바타, 썸네일, 파일 이름 및 원본 페이로드 |
| 작성자/프로필 또는 첨부 파일이 기록되었음을 나타내는 마커 | 전달 및 답장 메타데이터, 네트워크 경로, IP 주소 및 인증 정보 |
| 선택된 채널의 이벤트 수, 현재 수집 스위치, 하트비트 및 체크포인트 간격 | 컬렉션 제어 기능 및 일반 증거 내보내기 API |
| 서명 지문, 저널 체크포인트 및 일관성 증명 | 서명 키 및 텔레그램 세션 |

**공개 메시지 본문은 자동으로 익명화되지 않습니다.** 메시지에 포함된 이름, 멘션, 전화 번호 또는 링크는 해당 본문의 일부로 남아 있습니다. `Redacted`이는 구조화된 작성자/프로필 필드에 적용됩니다. 게시하기 전에 실제 선택된 내용을 검토하십시오. 여기에는 유지된 수정 및 삭제 내용도 포함됩니다.

적격성 여부는 실시간 텔레그램 조회 결과가 아닌, **가장 최근에 저장된 소스 프로필을** 반영합니다. 후속 프로필에 더 이상 공개 채널 사용자 이름이 없는 경우, 새로운 요청에서는 해당 채널이 제외됩니다. 공개 가시성이 변경되면 소스 프로필을 새로 고침하십시오. 독자들은 이전에 수신한 자료를 이미 저장해 두었을 수 있습니다.

원본 서명된 기록은 변경되지 않습니다. 표시되는 투영본은 별도로 서명되며, 원본 기록을 참조하는 해시 값을 포함합니다. 투영본 서명은 표시된 내용을 인증하는 역할을 하며, 편집된 바이트에 대한 원본 이벤트의 서명이 아닙니다.

## 서명 및 연속성 확인

**'지문 및 서명된 체크포인트**'를 확장하여 스냅샷을 다운로드하세요. 페이지가 새로 고침된 후, 다운로드 파일에는 이전 브라우저 스냅샷과 해당 저널 경계 간의 머클 일관성 증명이 포함됩니다. 자동 새로 고침은 페이지가 표시되고 첫 번째 관찰 페이지가 표시되는 동안 1분마다 한 번씩 수행됩니다.

TgWitness가 설치된 상태에서, 다운로드한 파일을 오프라인에서 확인하십시오:

```
python -m tgwitness.showcase_verify showcase.json --fingerprint TRUSTED_COLLECTOR_SHA256
```

지문은 별도로 신뢰할 수 있는 참조 출처에서 가져와야 합니다. 직접 보관한 스냅샷과 비교하려면 다음을 사용하십시오 `--previous earlier.json`; 이 명령은 다운로드 파일에 포함된 이전 스냅샷을 덮어씁니다. 현재 증명서는 보관된 경계 지점에서 시작해야 합니다. 인증된 클라이언트는 `GET /api/showcase/{workspace_id}?challenge=<32-hex-random>&from_count=<retained-count>`를 사용하여 해당 증명을 요청할 수 있습니다. 저널 길이가 더 짧을 경우, 경계를 무음으로 재설정하는 대신 HTTP 409를 반환합니다.

서명된 체크포인트는 기록 수와 불투명한 헤드 해시를 포함하여 **전체 수집기**저널에 커밋됩니다. 표시된 메시지 수는 선택된 공개 채널에만 적용됩니다. 이 페이지에는 다른 저널의 내용이 절대 나열되지 않습니다. 이는 이벤트 수이며, 고유 메시지 수가 아닙니다. 설정은 현재 구성을 설명하는 것이지, 이전의 모든 기록 간격을 설명하는 것은 아닙니다.

서명 및 일관성 검증은 보존된 경계에 대한 변경 사항을 감지할 수 있습니다. 이 기능은 서명된 카운터를 독립적으로 재계산하거나, 텔레그램 출처를 인증하거나, 중단 없는 캡처를 입증하거나, 독립적인 증인을 대체하지는 않습니다. 이러한 검토를 위해서는 [증거 검증기](https://github.com/phishdestroy/TgWitness/blob/main/docs/TRUST.md), [독립적인 증인](https://phishdestroy.github.io/TgWitness/ko/docs/reference/witness/) 및 [테스트를 거친 대규모 기록을](https://phishdestroy.github.io/TgWitness/ko/docs/reference/verification/) 사용하십시오. 합성 설치 환경은 ‘합성’으로 명확하게 표시됩니다.

## 페이지 권한 취소 또는 호스팅

쇼케이스 관리자나 기존 **접근** 섹션에서 **취소**를 사용하여 링크를 닫고 모든 세션을 종료할 수 있습니다. 요청을 통해 액세스가 종료된 것으로 감지되면 방문자의 표시된 기록이 삭제됩니다. 만료 및 권한은 모든 요청 시마다 확인됩니다. 쇼케이스 권한은 해당 위치에서 일반 패널 액세스 권한으로 변환할 수 없으며, 모드를 변경하려면 새로운 권한을 생성해야 합니다.

설치된 시스템의 기존 HTTPS 주소를 통해 페이지를 제공합니다. 링크를 게시해도 새로운 포트가 열리거나 터널이 생성되거나 DNS가 변경되지 않습니다. HTML 및 API는 사용자의 설치 환경에 그대로 남아 있습니다. 쇼케이스 방문자는 이 액세스 권한으로는 일반적인 메시지, 프로필, 미디어, 내보내기 또는 관리 API를 사용할 수 없습니다.
