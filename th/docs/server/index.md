# Telegram · ให้ระบบทำงานต่อไป

Canonical page: https://phishdestroy.github.io/TgWitness/th/docs/server/

ให้เครื่องเก็บข้อมูลทำงานต่อเนื่องและข้อมูลปลอดภัยผ่านการรีสตาร์ต

## เลือกวิธีการเปิดตัว

แบบเนทีฟ: [ตัวเปิดโปรแกรม](https://phishdestroy.github.io/TgWitness/th/docs/start/) พร้อมเทมเพลตบริการใน [deploy/](https://github.com/phishdestroy/TgWitness/blob/main/deploy/README.md) Docker จากโฟลเดอร์โปรเจกต์:

```
docker compose up -d --build --wait
docker compose exec tgwitness cat /data/panel-token.txt
```

แผงควบคุมรับฟังที่ localhost:8787 เปิดในเครื่องหรือผ่าน SSH tunnel ด้วยโทเค็นจากคำสั่งที่สอง

## เก็บไดเรกทอรีข้อมูลทั้งหมดไว้

แบบเนทีฟ: `data/live` Docker: volume `tgwitness-data` บันทึก เซสชัน และคีย์ต้องอยู่ด้วยกัน การส่งออกที่ลงนามคือหลักฐาน ไม่ใช่ข้อมูลสำรอง

1. หยุดการเก็บข้อมูลก่อน
2. คัดลอกไดเรกทอรีข้อมูลทั้งหมดไปยังที่ปลอดภัยนอกโฮสต์
3. ลองกู้คืนบนการติดตั้งแยกก่อนจะเชื่อถือ

## ตรวจสอบอีกครั้งหลังจากรีสตาร์ท

ตรวจพื้นที่ทำงานและคีย์ การเชื่อมต่อ แหล่งข้อมูล และดูว่าข้อความใหม่เข้ามาหรือไม่ TgWitness ตามเก็บสิ่งที่ Telegram ยังมีอยู่ ไม่ใช่ทุกอย่างที่เกิดขึ้นระหว่างที่มันหยุดทำงาน

คอนเทนเนอร์ "healthy" หมายถึงเว็บเซิร์ฟเวอร์ตอบสนอง การเก็บข้อมูลทำงานหรือไม่ ข้อความทดสอบและพยานจะบอกได้

## เผยแพร่เฉพาะสิ่งที่คุณตั้งใจเท่านั้น

HTTPS, volume การอัปเดต และการกู้คืนอยู่ในข้อมูลอ้างอิงการติดตั้งใช้งาน สิ่งที่ทดสอบจริงแล้ว: [บันทึกการตรวจสอบความถูกต้อง](https://phishdestroy.github.io/TgWitness/th/docs/reference/verification/)
