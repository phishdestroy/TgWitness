Постоянная работа на сервере

Обеспечьте доступность средства сбора данных и сохранность его данных при перезапусках.

Выберите способ запуска

Для локальной установки воспользуйтесь программой запуска и примерами сервисов, расположенными в папке `deploy/`. Для Docker установите Docker с Compose и запустите из каталога проекта:

docker compose up -d --build --wait
docker compose exec tgwitness cat /data/panel-token.txt

Панель по умолчанию прослушивает адрес лупбэка хоста на порту 8787. Откройте её локально или через SSH-туннель. Для разблокировки панели используйте токен из второй команды.

Сохраните весь каталог данных

При локальной установке используется data/live. В Docker используется постоянный том tgwitness-data. Храните журналы, сеансы учетных записей, ключи и операционное состояние в одном месте. Подписанный экспорт является полезным доказательством, но не является полной резервной копией установки.

  1. Прекратите сбор данных до того, как создадите полную резервную копию.
  2. Скопируйте весь каталог с конфиденциальными данными в защищённое хранилище за пределами хоста.
  3. Перед тем как полагаться на резервную копию, протестируйте восстановление данных в изолированной установке.

Проверьте после перезапуска

Подтвердите ожидаемую рабочую среду и ключ, подключение к Telegram, выбранные источники и захват новых сообщений. Сохраненное состояние MTProto и функция «догнать» помогают восстановить обновления, которые Telegram все ещё хранит. Система не может восстановить все обновления, срок действия которых истек, или правки, удалённые до момента захвата.

«Работоспособность контейнера» означает, что веб-сервер отвечает на запросы. Для оценки процесса сбора данных и их публикации во внешних источниках используйте контрольное сообщение и проверку с помощью контрольного сообщения.

Публикуйте только то, что намереваетесь

Справочник по развертыванию содержит примеры использования HTTPS, команды для работы с постоянными томами, а также инструкции по обновлению и восстановлению. Для развертывания предоставляются команды Docker; в текущей записи о валидации указаны среды, в которых фактически проводилось тестирование.
