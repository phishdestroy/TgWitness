# ออกแบบรายงาน

Canonical page: https://phishdestroy.github.io/TgWitness/th/docs/reports/

ให้ผู้อ่านเห็นเส้นทางที่ชัดเจนจากคำถามของคดีไปยังบันทึกที่เก็บไว้

Report Studio รวมการเลือกข้อมูล ประวัติการเปลี่ยนแปลงที่อ่านได้ แผนภูมิ และผลการวิเคราะห์ที่เขียนไว้ การออกแบบแปดแบบที่ผสานรวมไว้ใช้ได้กับผลลัพธ์ HTML และ PDF แบบเนทีฟที่รองรับ รายงาน HTML, PDF และ JSON มีตราประทับลายเซ็นของตัวเอง; รายการ ZIP ยังผูกไฟล์ในแพ็กเกจไว้ด้วย HTML และ PDF จะถูกประทับตราหลังจากจัดรูปแบบสุดท้ายเสร็จสิ้น

## สร้างรายงานในสามขั้นตอน

1. เปิด **Exports → Configure and preview → Data**. ใช้พื้นที่ทำงานทั้งหมดหรือเลือกการสนทนา ผู้เขียน วันที่สังเกตการณ์ UTC ที่รวมอยู่ และประเภทบันทึก วันที่ดังกล่าวอธิบายถึงช่วงเวลาที่ TgWitness สังเกตการณ์บันทึกนั้น
2. ในส่วน "**การออกแบบและเนื้อหา**" ให้เลือกการตั้งค่าล่วงหน้าสำหรับการออกแบบและเนื้อหา เลือกแผนภูมิกิจกรรม ป้ายชื่อผู้เข้าร่วม บันทึกการสนทนา การเปลี่ยนแปลงที่บันทึกไว้ และเนื้อหา Case Board (ตามความต้องการ) เพิ่มรายละเอียดคดีและบันทึกการตรวจสอบของคุณ
3. เปิด "Open **Preview"** เพื่อตรวจสอบจำนวนข้อมูล กิจกรรม ผู้เข้าร่วม บันทึกตัวอย่าง และช่วง ID ที่ขาดหายไป บันทึกการตั้งค่า แล้วดาวน์โหลดรูปแบบที่คุณต้องการ

### จัดเรียงเนื้อหาที่บันทึกไว้ให้สอดคล้องกับผู้อ่าน

ตัวอย่างสังเคราะห์ · แบบร่างแผนผัง ไม่ใช่รายงานที่สร้างขึ้น

1. **เลือก.** เลือกการสนทนาสองครั้งและช่วงเวลาการสังเกตการณ์สำหรับคดีนี้
2. **เขียนเนื้อหา** เลือกแบบจัดวางและส่วนที่ตอบคำถาม
3. **ดูตัวอย่าง.** ตรวจสอบจำนวนที่เลือกและข้อความก่อนและหลังที่บันทึกไว้
4. **ตรวจสอบความถูกต้อง** สร้างไฟล์สุดท้ายและตรวจสอบลายเซ็นของไฟล์นั้นกับลายนิ้วมือของพื้นที่ทำงานที่เชื่อถือได้

#### ข้อสังเกตที่เลือกมา

2 การสนทนา · 1 วันสังเกตการณ์

ข้อความ การแก้ไข และแจ้งเตือนการลบ

#### โครงสร้างรายงาน

##### เปลี่ยนปลายทางการชำระเงิน

คำถามของคดี → ขอบเขต → ผลการตรวจสอบ → อ้างอิงบันทึก

**บริบทของข้อความ**

ข้อสังเกต #142: “ใช้ลิงก์การชำระเงินใหม่”

**การเปลี่ยนแปลงที่บันทึกไว้**

ก่อน: old.example.invalid → หลัง: new.example.invalid

#### ตรวจสอบการเลือก

18 ข้อสังเกต · 2 การแก้ไขที่บันทึกไว้

เวลาส่ง เวลาแก้ไข และเวลาตรวจสอบ มีป้ายกำกับแยกกัน

#### ผลลัพธ์สุดท้าย

PDF ที่ลงนาม + JSON ที่ลงนาม หรือ ZIP ที่ลงนามพร้อมรายงานที่อ่านได้

ผู้รับจะตรวจสอบไฟล์และลายนิ้วมือดิจิทัลที่เชื่อถือได้

## เลือกสไตล์การอ่าน

**Classic, Editorial, Briefing, Analytics, Technical, Overview, Reading series และ Ledger & margin** แสดงข้อมูลพื้นฐานเดียวกันในรูปแบบการจัดเรียงที่แตกต่างกัน การเปลี่ยนแปลงการออกแบบจะรักษาการเลือกข้อมูลและบันทึกที่เขียนไว้ ภาษาของรายงานสามารถเลือกได้จาก 25 ภาษาที่รองรับ

Reading series จัดกลุ่มกรณี ขอบเขต ผลการค้นพบ และการเปลี่ยนแปลงรอบส่วนหลัก Ledger & margin ใช้บทที่มีหมายเลขและขอบกระดาษที่กว้าง ทั้งสองยังสนับสนุนการดูภาพรวม HTML ของบัญชีและการแชร์สำเนา ไฟล์ PDF ดั้งเดิมถูกสร้างขึ้นพร้อมฟอนต์ที่รวมอยู่ในแพ็กเกจ; เครื่องของผู้ใช้ไม่จำเป็นต้องติดตั้งเบราว์เซอร์หรือ Node เพื่อสร้าง PDF ไฟล์ PDF ภาษาจีน ญี่ปุ่น และเกาหลี ยังต้องการฟอนต์ที่เหมาะสมบนเซิร์ฟเวอร์ เช่น Noto Sans CJK ซึ่งต้องติดตั้งทั่วระบบหรือวางไว้ในโฟลเดอร์ `TGWITNESS_FONT_DIR` หากไม่มีฟอนต์ดังกล่าว ไฟล์ ZIP จะเก็บรายงาน HTML และ JSON ไว้แทน

## อ่านการเปลี่ยนแปลงพร้อมบริบท

การแก้ไขที่บันทึกไว้จะแสดงทั้งก่อนและหลัง การแจ้งเตือนการลบสามารถมาพร้อมกับเวอร์ชันล่าสุดที่บันทึกไว้ได้ การตอบกลับ การอ้างอิง การส่งต่อ การแสดงปฏิกิริยา ปุ่ม และข้อมูลเมตาของไฟล์แนบจะรักษาการอ้างอิงที่มีอยู่ไว้ ค่าแฮช SHA-256 ของไฟล์และค่าแฮชของบันทึกในสมุดบันทึกจะถูกระบุแยกกัน

ตัวอย่างการออกแบบแสดงส่วนหน้าปก ส่วนการตรวจสอบ และส่วนแผนภูมิ โดยใช้ข้อมูลที่ตรงกันจาก 50,000 รายการต้นฉบับแรก ตัวอย่างข้อมูลที่แยกต่างหากจะสแกนภาพถ่ายบันทึกที่เสถียรทั้งหมดเพื่อนับจำนวนการเลือกที่แม่นยำ พร้อมทั้งแสดงขีดจำกัดของตัวอย่างที่มีป้ายกำกับ สร้างไฟล์ PDF เพื่อตรวจสอบการจัดหน้าสุดท้าย การส่งออกบัญชีแบบเต็มมีภาพรวมในรูปแบบ HTML; ส่วน PDF ของการสนทนาแต่ละรายการใช้การออกแบบที่เลือกไว้

## เลือกสำเนาสำหรับผู้รับอย่างระมัดระวัง

ตัวกรองรายงานช่วยปรับแต่งรายงานให้อ่านได้ง่ายขึ้น ไฟล์ ZIP ของหลักฐานฉบับเต็มจะเก็บรักษาบันทึกต้นฉบับและไฟล์แนบไว้ทั้งหมด ใช้ขั้นตอน[การส่งต่อที่เรียบง่าย](https://phishdestroy.github.io/TgWitness/th/docs/handover/)เมื่อผู้รับควรได้รับข้อมูลที่เลือกไว้เท่านั้น ตรวจสอบ[เนื้อหาและกระบวนการตรวจสอบรายงาน](https://phishdestroy.github.io/TgWitness/th/docs/reference/case-reports/) หรือ[ตรวจสอบไฟล์ที่ส่งออกเสร็จแล้ว](https://phishdestroy.github.io/TgWitness/th/docs/exports/)
