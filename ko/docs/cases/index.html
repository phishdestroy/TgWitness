모든 채팅을 대상으로 조사하기

채널, 그룹, 개인 채팅, 봇에 걸친 사건 하나 전체: 수집하고, 점을 잇고, 타임라인을 재구성하고, 넘겨줍니다.

지어낸 사건 하나를 처음부터 끝까지. 수집, 검색, 인물 프로필이 기록을 찾고, Case Board가 정리하고, Report studio가 보여 줍니다.

실제 사례 / 변경된 결제 수취처

한 건의 사건. 네 건의 대화. 재구성해야 할 흔적.

채널 게시물이 봇을 가리킵니다. 한 그룹은 새 결제 링크를 이야기하고 봇도 그 링크를 보여 줍니다. 게시물이 편집되고, 개인 채팅이 링크를 반복하고, 그룹 메시지 하나가 사라집니다.

각 버전을 누가 게시했나요?해당 링크는 어디에 나타났나요?어떤 파일이 보존되었나요?무엇이, 언제 변경되었나요?
1. 모든 채팅2. 연혁 및 파일3. 실시간 활동4. 연결5. 타임라인6. 기타 계정7. 사례 패키지

기록 불러오기, AI, MCP, OCR, 웹훅: 아카이브 활용하기.

1. 계정 전체에 대한 기록 범위 설정

계정 전체 범위는 전용 계정에서만. 주 계정에는 선택한 채팅이나 폴더를 씁니다.

  1. 자체 작업 공간에서 계정을 연결합니다. 사건 번호, 계정 ID, 작업 공간, 키 지문을 적어 둡니다.
  2. 소스 → 관찰 범위 → 조사 모드: 전체 계정, 네 가지 소스 유형 모두, 내 활동. 새 채팅마다 프로필과 최근 200개의 표시 가능한 메시지가 저장됩니다. 범위 저장 후 확인합니다.
  3. 채팅 불러오기 후 계정의 채팅 목록과 비교합니다. 한도는 대화 1,000개입니다(매개변수 → 계정 목록에서 읽는 채팅에서 최대 20,000). 그 이상의 채팅은 활동이 생기면 나타납니다.
  4. 기록 설정 → 표시되는 모든 활동, 첨부 파일 한도와 디스크 공간을 확인합니다. 시작한 다음 메시지, 편집, 삭제 하나씩으로 테스트합니다.
채널그룹비공개 채팅봇
계정 1개 / 서명 키 1개계정에서 확인 가능한 모든 활동 → 하나의 기록부

메시지 · 수정 내역 · 삭제 알림 · 표시된 반응 · 회원 활동 · 본인의 행동

"전체 계정"은 이 계정이 열 수 있는 모든 채팅에서 제외 항목을 뺀 것입니다. 비밀 채팅은 포함되지 않습니다. 새 채팅은 나타날 때 추가되며, 오래된 기록은 자동으로 다운로드되지 않습니다.

2. 기록 내역 확보 및 파일 보존

Case Board 컬렉션을 만들고 중요한 것을 북마크합니다. 소스 대장을 관리하십시오: 채팅 ID, 제목, 계정, 역할, 실시간 수집 시작, 기록 결과, 미디어 결과, 공백.

질문에 맞는 수집 방식을 선택하세요
필요 사항패널 내 작업제공하는 기능
활성화된 채팅의 기록출처 → 전체 기록 불러오기사용 가능한 과거 메시지는 작업 공간 일지에 기록되며, 일시 중지/재개 기능과 서명된 진행 보고서가 제공됩니다. 사용 내역 안내.
저널에 포함된 기존 채팅 내용출처 → 기록 설정 → 기록 스냅샷최근 메시지를 서명된 기록으로. 기본 500개, 매개변수 → 최대 기록 스냅샷에서 최대 10,000개.
현재 표시된 한 채팅의 전체 기록전체 채팅 내보내기 → 전체 채팅 내보내기, 또는 채팅 → 채팅 내보내기채팅마다 chat.json과 chat.html이 든 별도의 서명된 묶음.
새로운 채팅이 나타날 때의 상황관찰 범위 → 새로운 채팅이나 봇이 나타날 때프로필과 최대 1,000개의 최근 메시지(조사 모드에서는 200개). 기존 채팅에는 적용되지 않습니다.
첨부 파일 바이트 수보이는 첨부 파일 다운로드 + 유형별 제한SHA-256과 크기가 있는 media.saved를 찾으십시오. 대기 중, 건너뜀, 실패는 저장되지 않았다는 뜻입니다.

채팅 내보내기는 저널이나 인물 프로필에 들어가지 않습니다. TgWitness 안에서 오래된 기록을 검색하려면 전체 기록 불러오기나 스냅샷을 사용하십시오.

여기서는: 채널, 그룹, 봇 채팅, 개인 채팅, 그리고 청구서 파일과 그 해시. 수집 전에 삭제된 것은 사라졌습니다.

3. 변화하는 대화 내용과 본인의 행동을 기록하세요

계속 실행해 두십시오. 중요한 채팅에는 별표를 달아 우선순위를 주고, 기록 설정 → 재확인에서 재확인을 조정하며, recheck.completed, FloodWait, 미디어 결과를 지켜봅니다.

채팅 → 프로필 → 지금 프로필 저장은 채팅 설명, 봇 명령, 기타 메타데이터를 저장합니다.

사건의 일환으로 봇을 팔로우하거나 초대를 수락하는 경우
  1. 채팅 → 텔레그램 링크 열기, 먼저 미리 보기를 저장합니다. 링크와 미리 보기는 서명된 기록이 됩니다.
  2. 필요하면 참여 / 열고 관찰이 채팅에 참여하거나 시작 매개변수로 봇을 시작합니다.
  3. 행동을 기록으로 남기려면 패널에서 답장하거나 버튼 누르기를 사용합니다. 봇의 응답과 함께 interaction.requested와 interaction.result가 남습니다.

이것은 실제 행동입니다. 다른 앱에서 누른 버튼은 보이지 않고 봇의 답장만 보입니다. 웹 앱, 결제, 전화번호/위치는 지원하지 않습니다.

4. 채팅 전반에 걸쳐 사람, 링크 및 파일을 추적하기

  1. 저널, 모든 소스에서 구문, 도메인, 사용자 이름을 검색합니다. 결과를 열고 보드에 추가합니다.
  2. 채팅 → 사람 → 프로필 켜기, 사람을 고릅니다: 이름 기록, 답장, 활동, 또한…, 링크, 지갑, 전화번호. 인용된 기록을 엽니다.
  3. 같은 숫자 사용자 ID를 다른 채팅에서도 따라갑니다. 이름, 지갑, 아바타가 일치하는 것은 단서이지 증거가 아닙니다.
  4. 파일 해시를 비교합니다. SHA-256이 같으면 = 바이트가 같습니다. 누가 공유했는지는 별개의 문제입니다.
예시 기록들을 연결하는 요소
연결보조 관찰 사항유지할 결론
동일한 텔레그램 계정그룹 #146 및 비공개 채팅 #205의 사용자 ID 71001두 채팅에서 발신자 ID가 같습니다. 그가 현실에서 누구인지는 또 다른 문제입니다.
반복되는 대상#146의 pay.example.invalid/new, #173의 버튼 메타데이터, #188 및 #205의 수정된 게시물같은 링크가 네 곳에 있습니다. 누가 통제하는지는 다른 출처가 필요합니다.
동일한 파일 바이트 수완성된 미디어 수신 확인서 #151과 #209의 SHA-256 값이 동일함두 파일은 바이트 단위로 동일합니다.

프로필은 이 작업 공간에서 무언가를 쓴 사람만 다루며, 멤버 목록이 아닙니다. 사실당 인용 수: 매개변수 → 사실당 인용 기록.

5. 순서를 재구성하고 누락된 부분을 표시하세요

채팅에서 버전을 보고, 저널에서 모든 소스 + 편집, 삭제, 범위를 고릅니다. 타임라인에는 두 시각을 모두 적습니다: 텔레그램 날짜와 관찰된 시각.

  1. 09:00 · #101채널 게시물 캡처

    원본의 대상은 그대로 유지됩니다.

  2. 09:12 · #146 / #151그룹에서 다른 링크를 소개합니다

    사용자 71001이 이를 게시하고, 첨부 파일 다운로드가 완료됩니다.

  3. 09:16 · #173봇은 동일한 목적지를 표시합니다.

    저장된 키보드 메타데이터에 링크가 포함되어 있습니다.

  4. 09:20 · #188채널 공지사항 변경 사항

    원본 및 편집된 관찰 기록이 모두 유지됩니다.

  5. 09:24 · #205 / #209비공개 후속 게시물에서도 이를 반복합니다.

    저장된 첨부 파일의 전체 SHA-256 값은 #151과 동일합니다.

  6. 09:28 · #231그룹 삭제 알림이 도착했습니다

    앞서 언급한 바와 같이, 메시지를 삭제한 사용자나 정확한 삭제 시점은 제공되지 않습니다.

예시를 위한 관찰 시간 및 참조 정보. 이 항목들 사이에는 다른 기록들이 존재합니다.

저널 순서는 도착한 순서이며, 반드시 일어난 순서는 아닙니다. 실시간 기록, 스냅샷, 복구된 메시지, 삭제, "재확인 시 없음"을 구분하고, 모든 공백은 알 수 없음으로 표시하십시오.

6. 해당 사례를 다른 수집 계정으로 확대 적용

계정마다 작업 공간 하나, 같은 단계. 각자의 역할과 지문을 적어 둡니다. 메시지 번호는 계정별이므로 항상 어느 작업 공간과 채팅인지 밝히십시오.

계정 그룹은 상태를 보여 주고, 설정을 공유하고, 모두를 함께 내보내며, 각자 자체 저널과 키를 유지합니다. 계정 간 타임라인은 메모에서 직접 만듭니다.

사건이 길어지나요? 독립 증인을 추가하고, 각 계정이 실제로 무엇을 잡는지 테스트하십시오.

7. 검증 가능한 사건 자료 패키지 전달

각 작업 공간의 서명된 ZIP(항상 전체 저널, 필터는 상관없음), 그리고 인물 프로필, 채팅 내보내기, 파일.

CASE-001/                         # assembled by the analyst
  case-notes.md                   # question, findings, alternative explanations
  sources.csv                     # every chat, role, acquisition result and gap
  timeline.csv                    # account + chat + message + seq + both times
  workspace-A/
    evidence.zip                  # complete signed observation journal
    retained-checkpoint.json
    profiles-operations.json      # separately signed people profiles
    history-channel.zip           # signed current-history export
    history-group.zip
    verification.txt
  workspace-B/                    # separate journal and trusted fingerprint
  witness/                        # retained checks, journal and signed posts
  SHA256SUMS                      # hashes of the delivered files

지문은 따로 보내십시오. 모든 것을 각자의 작업 공간과 대조해 검증합니다:

python -m tgwitness.verify evidence.zip --fingerprint TRUSTED_PUBLIC_KEY_SHA256 --checkpoint retained-checkpoint.json
python -m tgwitness.verify profiles-operations.json --fingerprint TRUSTED_PUBLIC_KEY_SHA256 --evidence evidence.zip
python -m tgwitness.verify history-channel.zip --fingerprint TRUSTED_PUBLIC_KEY_SHA256

검증 도구 출력, 원본, 범위, 전달 기록을 조사 결과와 함께 보관합니다. 정리는 Report studio에서 합니다. 받는 사람에게 더 적게 필요하면 최소화된 인계를 만드십시오.
