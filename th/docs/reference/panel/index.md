## ค้นหาทางของคุณ

ส่วน Daily อยู่ที่ด้านบนของแถบข้าง **Accounts** อยู่ใต้ **Workspace** และส่วนอื่นๆ ทั้งหมดอยู่ใต้ **More tools & settings** สวิตช์**ระดับ Interface** ในแถบด้านบนกำหนดจำนวนส่วนที่จะแสดง:

| ระดับ | ส่วนต่าง ๆ ในแถบด้านข้าง |
| --- | --- |
| เรียบง่าย | หน้าหลัก, การสนทนา, การเปลี่ยนแปลง, คลังเก็บ และตั้งค่า |
| มาตรฐาน | นอกจากนี้ยังมีCase Board, Accounts และ Access |
| ผู้เชี่ยวชาญ | นอกจากนี้ยังมี Sources, Extras, Ask the archive, Parameters, Account, System log และ Integrations |

การเรียกใช้แบบง่าย ได้แก่ Start here, Journal และ Exports **Home**, **Changes** และ **Archives** ระดับ (Level) ใช้เพื่อซ่อนส่วนต่าง ๆ เท่านั้น คุณสมบัติที่ถูกซ่อนยังคงทำงานได้ และเซิร์ฟเวอร์จะตรวจสอบ สิทธิ์การใช้งานทุกข้อด้วยตัวเอง ระดับ (Level), ภาษา, ธีม และเขตเวลาจะถูกบันทึกตาม ผู้ใช้งานและพื้นที่ทำงาน; ดู[การตั้งค่า](https://phishdestroy.github.io/TgWitness/th/docs/reference/settings/)

แถบด้านบนยังมี:

- **ไปยังส่วนใดส่วนหนึ่ง** (Ctrl+K หรือ ⌘K บน Mac): ค้นหาการสนทนา พารามิเตอร์ หรือบันทึก ในวารสาร `#number`. ใช้ปุ่มลูกศรเพื่อเคลื่อนที่, กด Enter เพื่อเปิด, กด Esc เพื่อปิด.
- **การแจ้งเตือน**: ปัญหาและการเปลี่ยนแปลงในแชทจะถูกแก้ไขจากบันทึก **Mark all as read** จะรีเซ็ตตัวนับ และ **Notification rules** จะเปิดหน้ากฎการแจ้งเตือน การส่งไปยัง Telegram, Discord หรืออีเมลสามารถตั้งค่าได้ที่ [Extras → Notifications](https://phishdestroy.github.io/TgWitness/th/docs/reference/panel/#notifications).
- ตัวบ่งชี้การเชื่อมต่อสำหรับพื้นที่ทำงานนี้ **สถานะการทำงานของ Collector** ใต้แถบด้านบน แบ่งออกเป็นการเชื่อมต่อ Telegram การรับเหตุการณ์ แหล่งข้อมูล และคิวไฟล์แนบ
- **Lock**: ปิดแผงในเบราว์เซอร์นี้ Collection ยังคงทำงานบนเซิร์ฟเวอร์ต่อไป
- โหมดการป้องกันที่อยู่ข้างหมายเลขเวอร์ชัน; ดู[โหมดการป้องกัน](https://phishdestroy.github.io/TgWitness/th/docs/reference/panel/#protection-modes)

พื้นที่ทำงานในเวอร์ชันสาธิตมีข้อความสมมติและไม่เคยเชื่อมต่อกับ Telegram การดำเนินการที่อาจเปลี่ยนแปลงพื้นที่ทำงานจริงจะถูกปฏิเสธในพื้นที่นี้

## เริ่มจากที่นี่

เลือกงานหนึ่ง **“ส่งออกบัญชีของฉัน**” จะดาวน์โหลดข้อมูลที่บัญชีนั้นสามารถอ่านได้ในขณะนี้ **“ติดตามการสืบสวน**” จะบันทึกข้อความใหม่ การแก้ไขที่สังเกตได้ และแจ้งเตือนการลบ จากแชทที่คุณเลือก บัตรตั้งค่าแสดงสามขั้นตอน: เชื่อมต่อบัญชี, เลือกแหล่งข้อมูล, เริ่มการติดตาม คำถามเป้าหมายจะปรากฏบนหน้านี้จนกว่าคุณจะ ตอบหรือข้ามไป พื้นที่ทำงานใหม่จะเปิดขั้นตอน[การตั้งค่า](https://phishdestroy.github.io/TgWitness/th/docs/reference/settings/)ครั้งแรกแทน

## แชท

การสนทนาที่บันทึกไว้ สามารถอ่านได้เท่านั้นตามค่าเริ่มต้น

- ค้นหาในรายการตามชื่อหรือ ID **เลือก**เพิ่มหรือลบการติดตามการสนทนา การ**เปิดลิงก์ Telegram** จะรับชื่อผู้ใช้หรือลิงก์เชิญและบันทึกตัวอย่างไว้ที่ journal **การเข้าร่วม / เปิดและติดตาม**จะเข้าร่วมการสนทนาและเพิ่มมันเข้าไปในแหล่งข้อมูลของคุณ; การเปิดบอทจะส่งมัน `/start`.
- ส่วนหัวของแชทนับจำนวนข้อความ **ถูกลบแล้ว แต่ข้อความยังคงอยู่**, **ถูกลบก่อนการบันทึก** และ **ไม่พบเมื่อตรวจสอบใหม่**. รายการแชทและแจ้งเตือนใช้ คำนิยามเดียวกัน ข้อความที่ถูกลบจะแสดงเป็นสีแดงและเก็บข้อความที่บันทึกไว้; ข้อความที่แก้ไข จะเก็บทุกเวอร์ชันที่บันทึกไว้ การลบแต่ละครั้งจะระบุข้อมูลที่ทราบ: เวลาที่ข้อความถูกอ่าน, ว่า Telegram ไม่รายงานว่าใครเป็นผู้ลบข้อความนั้น หรือว่าเพียงแต่การแจ้งเตือนเท่านั้นที่ส่งถึง
- **ประวัติการโหลด**จะนำข้อความ 100, 250 หรือ 500 ข้อความล่าสุดมาแสดงในมุมมองนี้และ ในบันทึก เพื่อโหลดทุกแหล่งข้อมูลที่เปิดใช้งาน ให้ใช้ [Sources → Full history](https://phishdestroy.github.io/TgWitness/th/docs/reference/panel/#sources).
- **Export chat** ดาวน์โหลดประวัติการสนทนาที่มองเห็นได้ทั้งหมดในรูปแบบที่ลงนาม `chat.json` และ `chat.html`. บัญชีหลายบัญชีที่เชื่อมต่อกันสามารถแบ่งงานกันได้: แต่ละบัญชีจะดาวน์โหลด ช่วงหมายเลขข้อความของตัวเองและลงนามในส่วนที่รับผิดชอบ ส่วนบัญชีที่เริ่ม การส่งออกจะลงนามในไฟล์เก็บถาวร ดู[การส่งออกแชทหนึ่งแชท](https://github.com/phishdestroy/TgWitness/blob/main/docs/wiki/Chat-Export.md)
- **People** แสดงรายชื่อทุกคนที่มีข้อความที่บันทึกไว้ในแชทนี้ โปรไฟล์ People ถูกปิด โดยค่าเริ่มต้น เนื่องจากเป็นข้อมูลส่วนตัวของบุคคลที่สาม เมื่อเปิดใช้งานสำหรับ แชทหนึ่ง โปรไฟล์จะแสดงชื่อและประวัติชื่อผู้ใช้ สัญลักษณ์ Telegram ค่าแฮชของรูปโปรไฟล์ กิจกรรม ใครตอบกลับใคร แชทอื่นที่สังเกตเห็น และกระเป๋าเงิน โทรศัพท์ ชื่อผู้ใช้ และลิงก์ที่ถูกกล่าวถึง ทุกข้อมูลจะชี้ไปยังบันทึกที่เกี่ยวข้อง **การส่งออกโปรไฟล์**จะบันทึกไฟล์ที่ลงนามแล้ว โดยสามารถเลือกรหัสผ่านZIP ได้; การปิดโปรไฟล์จะลบไฟล์โปรไฟล์นั้น ดู [โปรไฟล์ผู้ใช้](https://phishdestroy.github.io/TgWitness/th/docs/reference/evidence/#people-profiles)
- **Save profile now** บันทึกภาพสแนปช็อตของโปรไฟล์แชทหรือบอท: คำอธิบาย, สมาชิก, ลิงก์เชิญ, คำสั่งบอท

### อ่านอย่างเดียว, การส่งข้อความ และข้อมูลลับ

สวิตช์สองตัวที่อยู่เหนือข้อความช่วยปกป้องบัญชีและผู้อ่าน:

- **โหมดอ่านอย่างเดียว**จะเปิดเมื่อเปิดแชท ปิดโหมดนี้เพื่อส่งข้อความหรือกดปุ่มบอต แต่ละการกระทำจะถามว่า **“ส่งในฐานะ @account?**” หรือ **“กดปุ่มบอตนี้ในฐานะ @account?**” ซึ่งแจ้งให้ทราบว่าสมาชิกในห้องสนทนาจะเห็นการกระทำนั้นและมันจะถูกบันทึกไว้ใน บันทึกที่ลงนามแล้ว การเลือก **“ไม่ถามอีกใน 10 นาทีในห้องสนทนานี้”** จะข้ามคำถามนี้ไป ชั่วคราว การส่งข้อความจะถูกปิดสำหรับเป้าหมาย **“หลักฐานสำหรับคดี**” ในแผงควบคุมและใน API
- **Mask secrets** จะซ่อนข้อมูลที่ดูเหมือนรหัสผ่าน รหัสเข้าสู่ระบบ กุญแจ API หรือ แฮช โทเค็นบอท สตริงเซสชัน กุญแจส่วนตัว JWT หรือหมายเลขบัตรชำระเงิน (หมายเลขบัตรจะถูกตรวจสอบด้วย Luhn sum) **Show** จะแสดงค่าหนึ่งค่า; การแสดงผลนี้ จะถูกบันทึกไว้ในบันทึก นอกจากนี้ การปิดการซ่อนข้อมูลสำหรับเบราว์เซอร์นี้ก็จะถูกบันทึกไว้ด้วย มีเพียงการแสดงผลที่เปลี่ยนแปลง: บันทึกต้นฉบับและทุกการส่งออกยังคงเก็บข้อความเต็มไว้

## บันทึก

ทุกบันทึกที่พื้นที่ทำงานได้ลงนามไว้ โดยแสดงจากที่ใหม่ที่สุดก่อน

- **ส่วน "Overview"** นับจำนวนข้อความที่สังเกตเห็น การแก้ไขที่บันทึกไว้ การแจ้งเตือนการลบ และ แหล่งข้อมูลที่เลือกไว้
- **ไทม์ไลน์เหตุการณ์** สามารถกรองตามประเภทเหตุการณ์ (ทั้งหมด, การแก้ไข, การลบ, การแสดงปฏิกิริยา, การเป็นสมาชิก, การครอบคลุม), ตามข้อความ และตามแหล่งที่มา **โหลดเหตุการณ์ก่อนหน้านี้** ย้อนกลับหนึ่งหน้า
- เปิดบันทึกเพื่อดูรายละเอียด ค่าแฮช และข้อมูลเนื้อหา **ลิงก์ไปยังบันทึกนี้**คือ ที่อยู่ที่จะเปิดบันทึกเดียวกัน ข้อมูลลับที่อาจมีจะถูกปิดบังในตัวอย่างนี้; ไฟล์ที่ส่งออกจะรักษาข้อมูลต้นฉบับไว้
- บันทึกนี้สามารถเพิ่มข้อมูลได้เท่านั้น: ไม่มีสิ่งใดในแผงควบคุมที่สามารถแก้ไขหรือลบข้อมูลได้ ตรวจสอบได้ ผ่าน **Exports → Verify journal** หรือ `python -m tgwitness.verify`; ดู [ส่วนการส่งออกและตรวจสอบ](https://phishdestroy.github.io/TgWitness/th/docs/reference/evidence/)

## แหล่งข้อมูล

การบันทึกการสนทนาใดในพื้นที่ทำงานนี้ และข้อมูลใดจากสนทนาเหล่านั้นที่ถูกเก็บไว้ การเปลี่ยนแปลง จะมีผลต่อกิจกรรมในอนาคต ส่วนบันทึกที่เก็บไว้จะยังคงอยู่

**Refresh chat list** อ่านการสนทนาและโฟลเดอร์ของบัญชี แต่ไม่ดาวน์โหลดข้อความ

### ขอบเขต

- **สิ่งที่บัญชีนี้บันทึก** : **การสนทนาที่เลือก** (เฉพาะการสนทนาที่คุณเพิ่ม), **โฟลเดอร์ Telegram** (หนึ่งในโฟลเดอร์ของบัญชี รวมถึงการสนทนาที่เพิ่มเข้าไป ในภายหลัง) หรือ **บัญชีทั้งหมด** (ทุกการสนทนา และการสนทนาใหม่ทุกครั้ง กลุ่ม การสนทนาส่วนตัว หรือ บอทเมื่อปรากฏขึ้น) **โหมดการสืบสวน** ใช้สำหรับบัญชีเฉพาะ: มันบันทึก ทุกสิ่งที่บัญชีนั้นเห็น ข้อความของตัวเอง และการกดปุ่ม และบันทึกโปรไฟล์ การสนทนาใหม่ทุกครั้งและข้อความที่มองเห็นได้ก่อนหน้านี้ทันที ส่วน [คู่มือบัญชีเฉพาะ](https://phishdestroy.github.io/TgWitness/docs/dedicated-account/) อธิบายเหตุผลว่าทำไมไม่ควรใช้บัญชีหลักของคุณเลย
- **ประเภทแหล่ง**ข้อมูลจำกัดโหมดโฟลเดอร์และโหมดบัญชีทั้งหมดให้ใช้ได้เฉพาะกับช่อง กลุ่ม การสนทนาส่วนตัว และบอต ส่วน "**การกระทำ**ของบัญชี" จะเพิ่มข้อความ การแก้ไข และ การกดปุ่มบนคีย์บอร์ดเพื่อตอบกลับของบัญชีนั้นเอง
- **เมื่อมีแชทหรือบอทใหม่ปรากฏขึ้น**: บันทึกโปรไฟล์ของมันและข้อความล่าสุดที่มองเห็นได้ ตามจำนวนที่เลือกไว้

Limits: the published cloud collector does not receive Secret Chats. The separate [Pseudo-secret interface and its demo](https://phishdestroy.github.io/TgWitness/th/docs/reference/secret-chats/) are documented with their development status and outstanding defects. Nothing is recorded while TgWitness is not running; after a restart it catches up only what Telegram still returns, and the report shows the gap. Chats beyond the chat list limit (1,000 dialogs unless changed in Parameters) are added when they next become active. Inline bot buttons pressed in another app are invisible; the bot's reply is recorded.

### การสนทนาที่อยู่ในขอบเขต

กรองตามสถานะ (**เปิดใช้งาน**, **หยุดชั่วคราว**, **ลำดับความสำคัญ**, **ยกเว้น**, **การเข้าถึง ยังไม่ยืนยัน**, **ถูกเพิกเฉย**) และประเภท จากนั้นดำเนินการกับรายการที่เลือก: เปิดใช้งาน, หยุดชั่วคราว, กำหนดหรือยกเลิก ลำดับความสำคัญ, ยกเว้นจากขอบเขต หรือ ลบ. สัญลักษณ์สถานะแสดงเพียงสถานะเท่านั้น; การดำเนินการ อยู่ในเมนูของแต่ละแถว พร้อมคำอธิบายสั้นๆ ว่าทำอะไร การหยุดชั่วคราวและการยกเว้นจะขอ การยืนยัน รวมถึงการดำเนินการแบบกลุ่มด้วย การลบแหล่งข้อมูลจะขอชื่อของแหล่งข้อมูลนั้นและลบ โปรไฟล์ผู้ใช้ที่เกี่ยวข้อง; ส่วนบันทึกที่เก็บไว้จะยังคงอยู่ในบันทึก

แหล่งที่มาที่รายการสนทนาของบัญชีไม่แสดงคือ **รับการอัปเดต แต่ไม่อยู่ในรายชื่อแชท** ในขณะที่บันทึกยังคงเข้ามาอย่างต่อเนื่อง มิฉะนั้นจะเป็น **การเข้าถึงยังไม่ได้รับการยืนยัน** **การสนทนาที่มีอยู่** จะเพิ่มการสนทนาที่มี **เพิ่มรายการที่เลือก** หรือ **เพิ่มทุกรายการที่ตรงกัน**

### ประวัติโดยละเอียด

โหลดประวัติที่มีอยู่ของทุกแหล่งข้อมูลที่เปิดใช้งานไว้ใน Chats และ journal ความคืบหน้าจะคงอยู่แม้หลังจากรีสตาร์ท; ไฟล์แนบจะปฏิบัติตามการตั้งค่าสื่อของคุณ ดู [ประวัติแหล่งข้อมูล](https://phishdestroy.github.io/TgWitness/th/docs/reference/history/)

### การบันทึก

- **เลือกการเปลี่ยนแปลงที่ต้องการเก็บไว้**: ข้อความใหม่, การแก้ไข, การแจ้งเตือนการลบ, ปฏิกิริยาที่มองเห็นได้, การเข้าร่วมและออกจากกลุ่ม การตั้งค่าล่วงหน้าจะเปลี่ยนรูปแบบ; **การบันทึกการตั้งค่า**จะนำไปใช้ การเปิดหมวดหมู่กลับขึ้นมาจะไม่กู้คืน เหตุการณ์ที่พลาดไป
- **เก็บรักษาสื่อเมื่อมีอยู่**: ดาวน์โหลดไฟล์แนบได้สูงสุดตามขนาดต่อไฟล์, ตั้งค่า ตามประเภทตั้งแต่ 1 ถึง 2,000 MiB, และจำกัดความยาววิดีโอเป็นวินาที (0 หมายความว่าไม่มีข้อจำกัด) ทุกครั้งที่พยายามดาวน์โหลดจะบันทึกผลลัพธ์ไว้
- **ตรวจสอบซ้ำ**: ตรวจสอบแชทสำคัญทุกไม่กี่นาที ส่วนแชทอื่น ๆ ตรวจสอบน้อยครั้ง เพื่อให้บัญชี ไม่ถูกจำกัดโดย FloodWait ของ Telegram ค่า 0 จะปิดกลุ่มนี้ลง ทำเครื่องหมายแชทสำคัญ ด้วยดาวในรายการ; จำนวนแชทต่อรอบและช่วงเวลาพักระหว่างแชทอยู่ใน ส่วน Parameters ดู[คอลเลกชัน](https://phishdestroy.github.io/TgWitness/th/docs/reference/collection/)

### เป้าหมายและระดับการป้องกัน

สี่คำถาม:

1. **ใช้เพื่ออะไร?** เพื่อบันทึกส่วนตัว การสืบสวน หรือหลักฐานสำหรับคดี
2. **คุณจะติดตามเท่าใด?** การสนทนาไม่กี่ครั้ง (สูงสุดประมาณ 50 ครั้ง), การสนทนาหลายครั้ง (สูงสุดประมาณ 500 ครั้ง) หรือบัญชีทั้งหมด ซึ่งจะกำหนดขีดจำกัดของรายชื่อการสนทนาเป็น 1,000, 3,000 หรือ 20,000
3. **รูปภาพและไฟล์?** เฉพาะข้อความ, รูปภาพและสื่อสั้น (รูปภาพ 20 MB, วิดีโอ 100 MB), หรือทั้งหมด (วิดีโอและเอกสารแต่ละไฟล์สูงสุด 1 GB). การเก็บข้อมูลทั้งหมดของ บัญชีทั้งบัญชีจะรักษาพื้นที่ว่างบนดิสก์ไว้ 4 GiB
4. **จะทำงานบนอุปกรณ์ใด?** คอมพิวเตอร์เครื่องนี้ หรือเซิร์ฟเวอร์ที่เปิดทำงานตลอดเวลา

รายการข้อเสนอแนะประกอบด้วย timestamps ที่ทำงานแบบอิสระ, drand และรายชื่ออุปกรณ์ของ Telegram โดยแต่ละรายการ มีบรรทัดอธิบายว่าเพิ่มข้อมูลอะไร Timestamps จะเริ่มทำงานทุก 60, 30 หรือ 10 นาที สำหรับ บันทึกส่วนตัว การสอบสวน หรือหลักฐาน; drand และรายชื่ออุปกรณ์จำเป็นต้องมี timestamps **ให้ใช้**การเปลี่ยนแปลงเฉพาะส่วนนี้ นโยบายการแนบไฟล์ และพารามิเตอร์สองตัวข้างต้นเท่านั้น แต่ละ การเปลี่ยนแปลงถือเป็นบันทึกในสมุดบันทึก พร้อมด้วย `setup.applied`. การแจ้งเตือน สำเนาที่อยู่นอกไซต์ เซิร์ฟเวอร์ เกตเวย์ DNS การตรวจสอบโค้ด และพยาน ถูกเสนอเป็นขั้นตอนต่อไปพร้อม แบบฟอร์มของตนเอง

สองสเกลถูกคำนวณจากสิ่งที่ถูกตั้งค่าไว้ ไม่ใช่จากเป้าหมาย:

| Scale | จุดสำคัญ |
| --- | --- |
| ความน่าเชื่อถือ | บันทึกที่ลงนาม 1, เวลาประทับ 3, drand 1, รายชื่ออุปกรณ์ 1, การตรวจสอบรหัสที่ตรงกัน 1, การสำรวจผู้รับรอง 1, เซิร์ฟเวอร์ที่ได้รับการรับรอง 2, บันทึก DNS ของ Gateway 1 |
| ความน่าเชื่อถือ | เซิร์ฟเวอร์ที่ทำงานตลอดเวลา 3, สำเนาสำรองนอกสถานที่ 3, Object Lock 1, การแจ้งเตือนปัญหา 1 |

ระดับการอ่าน**สูงสุด** 80% หรือมากกว่า, 50% **ระดับสูง**, 25% **ระดับปานกลาง**, ต่ำกว่านั้นเป็น**ระดับพื้นฐาน** ความน่าเชื่อถือในปัจจุบันนับจากเซิร์ฟเวอร์ที่เปิดตลอดเวลาตามคำตอบของคำถามที่ 4, ก่อนที่จะตรวจสอบเซิร์ฟเวอร์ใดก็ตาม

### การแจ้งเตือน

การแจ้งเตือนจะถูกส่งผ่าน Apprise ไปยัง Telegram, Discord, Slack, ntfy, email, Matrix และ บริการอื่น ๆ กว่า 100 บริการ เลือกบริการหนึ่งบริการ กรอกข้อมูลในช่องหนึ่งหรือสองช่อง แล้วส่งการทดสอบ หรือ วางที่อยู่ Apprise ลงโดยตรง

- **ปัญหา**: พื้นที่ดิสก์เกือบเต็ม, บัญชีถูกออกจากระบบ, ข้อผิดพลาดในการเก็บรวบรวม, การคัดลอก หรือการบันทึกเวลา บนเซิร์ฟเวอร์ที่ปิดผนึก การเปิดพอร์ต SSH หรือการเข้าสู่ระบบก็ถือเป็นปัญหาเช่นกัน
- **การเปลี่ยนแปลง**: ข้อความที่ถูกลบ แก้ไข และขาดหายไปในแชทที่ถูกติดตาม จะถูกรวมเป็น การแจ้งเตือนหนึ่งครั้งต่อการตรวจสอบ (ทุกนาที เว้นแต่จะเปลี่ยนในส่วน Parameters)
- **งานที่เสร็จสิ้นแล้ว**: ประวัติ, การส่งออก และสำเนาเก็บรักษา
- **สรุปประจำวัน**ในเวลาที่เลือก ตามเวลาเซิร์ฟเวอร์

การแจ้งเตือนจะแสดงชื่อห้องแชทและจำนวนข้อความ ส่วนข้อความตัวอย่างจะถูกปิดไว้ตามค่าเริ่มต้น; เมื่อ เปิดใช้งาน ข้อความต้นฉบับจะถูกส่งออกจากเครื่องนี้

**บอทผู้ดำเนินการของคุณ**คือบอทที่คุณสร้างขึ้นเองจาก @BotFather ซึ่งตอบ `/status` และ `/stats`, และตามตัวเลือก `/pause`, `/resume` และ `/copy`. เฉพาะการสนทนาที่ระบุและ ID ผู้ใช้ Telegram เท่านั้นที่สามารถใช้งานได้; ข้อความการสนทนาจะเก็บไว้ในพื้นที่ทำงาน ใช้ บอทแยกต่างหากหากมีแอปพลิเคชันอื่นรับคำสั่งของมันอยู่แล้ว ดู [ส่วนการแจ้งเตือน](https://github.com/phishdestroy/TgWitness/blob/main/docs/wiki/Notifications.md)และ[บอทผู้ดูแล](https://phishdestroy.github.io/TgWitness/th/docs/reference/storage/#operator-bot-and-completion-notices)

### หลักฐานและข้อมูลสำรอง

- **timestamps ที่ทำงานอย่างอิสระ**จะส่งเพียง SHA-256 ของจุดตรวจสอบที่ลงนามแต่ละจุดไปยังหน่วยงานตาม RFC 3161 และปฏิทิน OpenTimestamps ทุก 5 ถึง 1,440 นาที **Anchor ขณะนี้** กำลังดำเนินการผ่านรอบหนึ่ง ดู [timestamps](https://phishdestroy.github.io/TgWitness/th/docs/reference/timestamp/)
- **พยานเพิ่มเติม** แต่ละพยานจะอยู่ในสถานะพักจนกว่าจะถูกเลือก: รอบ drand ล่าสุด, รายการของ Telegram เกี่ยวกับอุปกรณ์ที่ลงชื่อเข้าใช้โดยไม่มีที่อยู่ IP, และบันทึกของ Cloudflare Gateway เกี่ยวกับ คำขอ DNS ของเซิร์ฟเวอร์ ดู[บันทึกเพิ่มเติม (ไม่บังคับ](https://phishdestroy.github.io/TgWitness/th/docs/reference/evidence/#optional-records-in-evidence-mode-drand-and-telegram-devices))
- **การสำรองข้อมูลที่เข้ารหัสจะ**คัดลอกบันทึก, ไฟล์, จุดตรวจสอบ และการส่งออกการสนทนาไปยัง พื้นที่จัดเก็บข้อมูลที่เข้ากันได้กับ S3 (Wasabi, Amazon S3, Backblaze B2, Cloudflare R2, MinIO). ทุกข้อมูลจะถูกเข้ารหัสบนเครื่องนี้ก่อนเป็นอันดับแรก **ดาวน์โหลดกุญแจเข้ารหัส**และเก็บไว้ แยกต่างหาก: หากไม่มีกุญแจนี้ สำเนาจะไม่สามารถอ่านได้ Object Lock ในโหมด Governance หรือ Compliance จะป้องกันไม่ให้วัตถุถูกลบเป็นระยะเวลาที่กำหนด ดู[สำเนาที่อยู่นอกสถานที่](https://github.com/phishdestroy/TgWitness/blob/main/docs/wiki/Off-site-Copy.md)

### การตรวจสอบโค้ด

ตรวจสอบว่าโปรแกรมที่ติดตั้งตรงกับเวอร์ชันที่เผยแพร่หรือไม่

1. ป้อนชื่อรีโพสิตอรี GitHub (รีโพสิตอรีอย่างเป็นทางการถูกกรอกไว้แล้ว) และแท็ก, บรานช์ หรือคอมมิต
2. **Check now** จะส่งคำขอไปยัง API ของ GitHub ผ่านเส้นทางของพื้นที่ทำงานนี้สำหรับคำขอจากภายนอก เพื่อขอรายชื่อไฟล์ของ commit ดังกล่าว มันจะเปรียบเทียบ git blob ID ของไฟล์โปรแกรมทุกไฟล์ที่วัด กับ commit นั้น การเช็คเอาต์บน Windows ที่มีการแปลงรูปแบบการสิ้นสุดบรรทัดแล้ว ยังคงตรงกัน
3. ผลลัพธ์จะแสดงรายการไฟล์ที่เปลี่ยนแปลง ไฟล์เพิ่มเติม และไฟล์ที่ขาดหายไป (สูงสุด 50 ไฟล์ต่อประเภท) และถูกบันทึกเป็น a `source.checked` บันทึกแบบวารสาร

ผลลัพธ์จะถือเป็นข้อมูลปัจจุบันเฉพาะเมื่อไฟล์โปรแกรมที่กำลังทำงานอยู่ยังไม่มีการเปลี่ยนแปลง: ตรวจสอบอีกครั้งหลังการอัปเดต ไม่จำเป็นต้องใช้โทเคน และทำงานได้เฉพาะกับรีโพสิตอรีสาธารณะเท่านั้น; การสนทนาและข้อมูลรับรองจะไม่ถูกอัปโหลด การจับคู่จะระบุรหัสบนดิสก์ นี่ไม่ใช่ การรับรองฮาร์ดแวร์; สำหรับเรื่องนั้น โปรดดู [Phala Cloud](https://phishdestroy.github.io/TgWitness/th/docs/reference/high-assurance/#confidential-vm-on-phala-cloud-intel-tdx).

## โหมดการป้องกัน

ปุ่มสลับข้างหมายเลขเวอร์ชันแสดงโหมดที่เลือกไว้และจำนวนชั้นการป้องกันที่ใช้งานอยู่จากทั้งหมด 18 ชั้น เช่น `🟠 Witnessed 9/18`. **เปลี่ยนโหมด**ใน **Extras → Protection level** เพื่อเปิดตัวเลือก โหมดแต่ละโหมดจะอธิบายเป้าหมายและแสดงรายการสิ่งที่ ยังขาดอยู่; การบันทึก การลงนาม และการตั้งค่าที่บันทึกไว้จะเหมือนกันในทุกโหมด

| โหมด | สำหรับ | เพิ่ม |
| --- | --- | --- |
| 🟢 ง่าย | ติดตามการสนทนาและเก็บสำเนา | Chats, บันทึกประจำวัน และการส่งออกการสนทนา; การลงนามดำเนินการในพื้นหลัง |
| 🟡 ลงนามแล้ว | ส่งรายงานไปยังแพลตฟอร์ม ผู้ให้บริการ หรือศูนย์รับเรื่องร้องเรียน | ไฟล์เก็บถาวรที่ลงนาม, การตรวจสอบบันทึก, จุดตรวจสอบ, ข้อมูลสรุปการส่งต่อ |
| 🟠 Witnessed | กรณีที่อาจมีผู้อ้างว่าบันทึกถูกแก้ไข | พยานอิสระที่โพสต์ส่วนหัวบันทึกที่ลงนามแล้ว |
| 🔴 พร้อมสำหรับศาล | หลักฐานสำหรับทนายความ ตำรวจ หรือศาล | Timestamps, สำเนาที่เข้ารหัสและเก็บไว้นอกระบบ, รายละเอียดคดีในรายงาน |
| 🟣 ได้รับการยืนยันจาก GitHub | บันทึกที่ซอฟต์แวร์ต้องสามารถตรวจสอบได้โดยทุกคน | การตรวจสอบโค้ดและการบันทึกผ่าน GitHub Actions |
| ⚫ Mossad | คดีที่มีความเสี่ยงสูงต่อฝ่ายตรงข้ามที่มีทุนสนับสนุนอย่างเพียงพอ | เซิร์ฟเวอร์ที่ปิดผนึกทำงานตลอด 24/7, ที่อยู่ IP ที่ซ่อนอยู่, และทั้ง 18 ชั้น |

ชั้นต่าง ๆ: ทุกบันทึกถูกลงนามและเชื่อมต่อเป็นโซ่; ใบเสร็จการรันที่ลงนาม; ไฟล์แนบที่บันทึก ด้วยSHA-256; จุดตรวจสอบที่ลงนาม; การตรวจสอบซ้ำ; การแจ้งเตือนปัญหา; การเข้าถึงพยานแบบอ่านอย่างเดียว; พยานที่ตรวจสอบตามกำหนดเวลา; ตราเวลา RFC 3161; หลักฐาน OpenTimestamps; ตราเวลาล่าสุด ที่ได้รับการยืนยัน; สำเนาที่เข้ารหัสและเก็บไว้นอกไซต์; รายละเอียดกรณีในรายงาน; การตรวจสอบ รหัสที่ตรงกัน; Telegram ไม่เคยเห็น IP ของเครื่องนี้; คำขอจากภายนอกผ่านพร็อกซี; Object Lock บนสำเนา; เซิร์ฟเวอร์ที่ปิดผนึกพร้อมบันทึกของผู้ให้บริการ ชั้นที่ปิดอยู่มีตัวเลือก " **Set up**" ซึ่งจะเปิดแบบฟอร์มขึ้นมา การเลือกโหมดที่ต่ำกว่าจะขอการยืนยันและ ไม่ลบข้อมูลใดๆ

## เครื่องมือเพิ่มเติม

**Extras → Independent capture**: connect a separate browser or AyuGram recorder, pin its signing key, select capture options, start/pause, take snapshots and download verified signed archives. Each recorder has its own manual login, route, journal and key. Both connections start disabled. See the English [Independent capture guide](https://github.com/phishdestroy/TgWitness/blob/main/docs/OPTIONAL-CAPTURE.md).

- **ถามคลังข้อมูล**: ค้นหาข้อมูลที่บันทึกไว้ ตรวจสอบแหล่งที่มา แล้วตัดสินใจ ว่าจะส่งข้อมูลเหล่านั้นไปยังโมเดล AI หรือไม่ ดู[การวิเคราะห์คลังข้อมูล](https://phishdestroy.github.io/TgWitness/th/docs/reference/analysis/)และ [OCR และถอดความแบบท้องถิ่น](https://phishdestroy.github.io/TgWitness/th/docs/reference/media-analysis/)
- **พารามิเตอร์**: ขีดจำกัดและอัตราความเร็วในการเก็บข้อมูล, การตรวจสอบซ้ำ, การดาวน์โหลด, โปรไฟล์, การแจ้งเตือน และการส่งออกข้อมูล ค้นหาตามชื่อ, แสดงเฉพาะค่า**ที่เปลี่ยนแปลง** และเตรียม ค่าเริ่มต้นเป็นร่างด้วยตัวเลือก **“Restore defaults…”** (**คืนค่าเริ่มต้น…)** การบันทึกพารามิเตอร์จะนำค่า ไปใช้ตั้งแต่การใช้งานครั้งถัดไป และการเปลี่ยนแปลงแต่ละครั้งจะถูกบันทึกเป็นรายการในบันทึก
- **การเข้าถึง**: โทเค็นแยกกันสำหรับผู้ตรวจสอบ ผู้วิเคราะห์ และผู้ดำเนินการ โดยจำกัดไว้ที่ พื้นที่ทำงาน ห้องสนทนา และสิทธิ์ที่กำหนด ดู[ส่วนการเข้าถึง](https://phishdestroy.github.io/TgWitness/th/docs/reference/access/)
- **บันทึกระบบ** : สิ่งที่กระบวนการนี้ทำมาตั้งแต่เริ่มต้น (การเชื่อมต่อ, การเปลี่ยนพร็อกซี, การลงชื่อเข้าใช้, การปฏิเสธ, การเปลี่ยนการตั้งค่า) โดยซ่อนที่อยู่ IP ไว้ ฟังก์ชัน "**ติดตามบรรทัดใหม่** " จะแสดงบรรทัดล่าสุดไว้เสมอ ข้อความจะเก็บไว้ในบันทึกเท่านั้น
- **การบูรณาการ**: ผู้ให้บริการ AI, การเชื่อมต่อ [MCP แบบอ่านอย่างเดียว](https://phishdestroy.github.io/TgWitness/th/docs/reference/mcp/) และ [webhooks ที่ลงนามแล้ว](https://phishdestroy.github.io/TgWitness/th/docs/reference/webhooks/)
- **Case Board**: บันทึกส่วนตัวของทีม, บุ๊กมาร์ก และสไลซ์ที่อยู่ข้างหลักฐาน ดู [Case Board](https://phishdestroy.github.io/TgWitness/th/docs/reference/case-board/).
- **GitHub Actions บันทึกข้อมูล**ใน Exports: การบันทึกการสนทนาหนึ่งครั้งจาก fork ของคุณ ดู [sealed capture](https://github.com/phishdestroy/TgWitness/blob/main/docs/SEALED-ACTIONS.md).
