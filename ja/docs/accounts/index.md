# アカウントを連携する

Canonical page: https://phishdestroy.github.io/TgWitness/ja/docs/accounts/

1つのワークスペースには、1つのアカウント、そのジャーナル、および署名鍵が格納されます。

## ログイン方法をお選びください

**アカウント**を開き、ワークスペースを追加して、その接続設定を開いてください。監視には専用のアカウントを使用してください。

- **QRコード：**Telegramの端末設定からスキャンし、新しいログインを確認してください。
- **電話番号：**電話番号、Telegramから送信されるコード、および有効になっている場合は2段階認証のパスワードを入力してください。
- **セッションのインポート：**対応しているセッション、またはご自身のTelegram Desktopデータをインポートします。

組み込みのAPIプロファイルを選択するか、独自のAPI IDとハッシュを入力してください。APIプロファイルはクライアントを識別するものであり、アカウントへのログインや接続の匿名化を行うものではありません。

**まずプロキシが必要ですか？**

ログインする前に、[接続経路を選択してテスト](https://phishdestroy.github.io/TgWitness/ja/docs/proxies/)することができます。各アカウントには独自の経路が割り当てられています。

## 監視対象を選択してください

1. ソースリストを開き、必要なチャット、グループ、またはチャンネルを選択してください。
2. 監視を開始する前に、メディアを含む収集設定を確認してください。
3. コレクターを起動し、接続状況と最近のアクティビティを確認してください。

アカウントはソースにアクセスできる必要があります。役割によって表示されるイベントが異なり、ジャーナルにはそのアカウントが受信した内容が反映されます。

アカウント全体にわたるケースについては、**「ソース」→「観察範囲」→「調査モード**」を選択し、設定を確認した上で**「範囲を保存」**をクリックしてください。[調査の手順の完全な解説では](https://phishdestroy.github.io/TgWitness/ja/docs/cases/)、表示可能なすべてのチャットタイプ、過去の履歴、ユーザープロフィール、チャット間の参照、および証拠の引き継ぎについて網羅しています。

## パス全体をご確認ください

ご自身が管理するテストグループ内で、別のアカウントから一意のメッセージを送信し、それを編集してから削除してください。ジャーナル内でこれら3つのイベントすべてを確認した後、記録を[エクスポートして検証してください](https://phishdestroy.github.io/TgWitness/ja/docs/exports/)。

「接続中」というステータスが表示されれば、接続が確立されていることが確認できます。キャプチャされたテストメッセージは、特定のイベントがこのワークスペースに到達したことを確認するものです。

## 別のアカウントを追加する

「**アカウント**」で別のワークスペースを作成し、設定を繰り返してください。後でエクスポート内容を識別できるよう、各アカウントの署名鍵のフィンガープリントを保管しておいてください。
