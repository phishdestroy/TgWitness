## Копии в S3. Внешние проверки.

Сохраняйте зашифрованные копии и добавляйте независимые проверки.

По умолчанию отключено

### Копирование в S3-совместимое хранилище

Журнал, файлы, контрольные точки с отметками времени и экспортированные данные чатов — зашифровываются перед загрузкой в AWS S3 или совместимое хранилище.

**Настройки хранения и восстановление**

Шифрование перед загрузкой

Объекты шифруются на этом компьютере с помощью `AES-256-GCM`. Провайдер получает зашифрованные объекты.

Копирование по расписанию или вручную

Запустите копирование сразу или задайте интервал от 1 до 1 440 минут. Ход копирования отображается в панели.

Object Lock

Если бакет поддерживает Object Lock, задайте срок хранения в днях и режим. Панель покажет, подтверждено ли удержание загруженного объекта.

Восстановление с проверкой

Скачайте ключ шифрования и храните его отдельно. Восстановить копию можно на другом компьютере; файлы появятся в целевом каталоге только после проверки.

![Полная панель настроек для внешнего хранения: конечная точка, регион, хранилище, ключи доступа, расписание, управление функцией Object Lock и ключом восстановления](https://phishdestroy.github.io/TgWitness/assets/off-site-copy.png)

### Уведомления · Apprise

Уведомления о проблемах, изменениях в чатах и ежедневные сводки через Apprise: мессенджеры, электронную почту или ваш собственный веб-хук JSON.

**Чего не делает** Не отправляет текст сообщений, пока вы не включите короткие выдержки.

 [Настроить получателей уведомлений](https://phishdestroy.github.io/TgWitness/ru/docs/reference/operations/#notifications)

### Внешние временные метки

Метки времени RFC 3161 и OpenTimestamps для хешей контрольных точек.

**Чего не делает** рассматривает ожидающее подтверждения календарное подтверждение как подтверждённую временную метку Bitcoin.

 [Проверьте доказательства с временными метками:](https://phishdestroy.github.io/TgWitness/ru/docs/reference/timestamp/)

### Независимый свидетель

Отдельный сервер хранит подписанные наблюдения и может публиковать контрольные точки `TGW1`.

**Чего не делает**: не превращает две рабочие среды на одном хосте-коллекторе в независимые источники доказательств.

 [Настройте Witness](https://phishdestroy.github.io/TgWitness/ru/docs/witness/)

### Восстановление данных и заметные пробелы

Продолжение после перезапуска. Перепроверки и `coverage.json` показывают восстановленные сообщения и разрывы.

**Чего не делает**: не восстанавливает каждое пропущенное изменение или исчезнувшее сообщение.

 [Проверьте непрерывность и наличие пробелов](https://phishdestroy.github.io/TgWitness/ru/guides/modes.html#continuity)

### Выберите способ запуска.

Дважды щелкните по файлу `Start.cmd` или запустите его в PowerShell:

```

```

Просто знакомитесь с проектом? Дважды щелкните по ссылке `scripts\Demo.cmd`, чтобы перейти к автономной демо-версии. Вход в Telegram не требуется.

```
docker compose up -d --build --wait
docker compose exec tgwitness cat /data/panel-token.txt
```

Вторая команда отображает токен вашей личной панели. Сохраните его на своём компьютере.

## Прежде чем начать.

**Связана ли эта страница с Telegram?**

Нет. Это статичная страница проекта с вымышленными примерами и скриншотами. Фактическое приложение работает на вашем компьютере или сервере; вход в систему осуществляется именно там.

**Может ли он восстанавливать сообщения, удалённые до момента их фиксации?**

Нет. TgWitness сохраняет контент, который был доступен в вашем аккаунте на момент проведения сбора данных. Более поздний снимок истории не позволяет восстановить пропущенные изменения или удалённые сообщения.

**Зашифрован ли весь мой журнал?**

Учетные данные и секретные ключи для подписи хранятся в зашифрованном хранилище. Для локальных сообщений и вложений требуется зашифрованный диск или том. При экспорте данных можно по желанию использовать ZIP-архив с шифрованием AES-256, защищённый паролем.

**Имеет ли этот проект какое-либо отношение к Telegram?**

Нет. TgWitness — это независимый проект, использующий Telethon, распространяемый по лицензии MIT. Вы авторизуете свои собственные учётные записи, используя встроенные настройки API или свою собственную пару API.
