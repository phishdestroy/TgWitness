# Командная строка для скриптов и агентов

[MCP только для чтения](MCP.md) · [Полнотекстовый поиск](SEARCH.md) · [Вики](../wiki/Archive-and-Integrations.md)

**Предварительный просмотр.** `tgwitness search`, `context`, `messages`, `stats` и `export` считывают
сохраненные наблюдения для скриптов и ИИ-агентов. Они не могут отправлять что-либо в
Telegram, изменять настройки или вносить изменения в подписанный журнал. `tgwitness index` и
`tgwitness backup` ([ниже](#index-and-backup)) работают с локальным каталогом данных и
не требуют токена.

При использовании `--json` в stdout выводится ровно один документ JSON (`export` выводит строки JSON).
Информация о ходе выполнения, подсказки и ошибки выводятся в stderr. Коды завершения являются постоянными:

| Код | Значение |
| --- | --- |
| `0` | Успех, в том числе и при отсутствии результата |
| `1` | Ошибка: недоступная панель, нечитаемые данные, прерванный экспорт |
| `2` | Ошибка использования или недопустимый запрос: неверная дата, неизвестный параметр, индекс поиска отключен |
| `3` | В данный момент недоступно: рабочая область открыта в запущенной панели, либо панель предлагает повторить попытку позже (ограничение частоты запросов, истечение времени ожидания) |
| `4` | Доступ запрещен: отсутствует токен, срок его действия истек или он был отозван; чат выходит за пределы допустимой области; используется инструмент, который не допускается |

<a id="two-ways-to-read"></a>
## Два способа чтения

**Через панель (`--url`).** Команда использует тот же API архива с ограниченной областью действия, что и
MCP. Установите соединение в разделе **«Дополнительные инструменты» → «Интеграции» → «MCP»**: выберите рабочие пространства и чаты,
инструменты и срок действия, затем скопируйте токен один раз. Подключение доступно только для чтения, ограничено
указанными чатами, имеет ограничение по скорости — 60 запросов в минуту — и может быть отозвано или
обновлено в любой момент. Токены входа в панель и учетные данные Telegram здесь не работают.

```sh
export TGWITNESS_URL=https://panel.example.org      # default http://127.0.0.1:8787
export TGWITNESS_MCP_TOKEN=tgw_mcp_...              # or --token-file path
tgwitness search 'перевод карта' --json
```

Для удалённой панели требуется HTTPS; простой HTTP допускается только для `127.0.0.1`,
`localhost` и `::1`. Переменные среды прокси игнорируются, а перенаправления
не допускаются, поэтому токен попадает только по указанному вами адресу.

**Непосредственно из остановленного рабочего пространства (`--data-dir`).** Считывает каталог данных с
полным локальным доступом, без токена. Используйте эту команду на копии каталога данных или когда
сбор данных остановлен. Записанные записи никогда не изменяются; как и в случае с панелью, открытие
рабочей области может привести к обновлению производных индексов. Если рабочая область открыта в панели, команда завершается с
кодом `3`; вместо этого следует выполнять чтение через панель. Без `--data-dir` используется `TGWITNESS_DATA`,
`./data/live` или каталог данных установки, в которой запущена команда.

`--workspace ID` позволяет выбрать рабочую область (по умолчанию — `default`). `tgwitness messages
--workspaces` отображает список тех, которые вы можете читать.

<a id="commands"></a>
## Команды

| Команда | Результат |
| --- | --- |
| `tgwitness search QUERY [--chat ID] [--since] [--until] [--any] [--limit N] [--offset N]` | Сначала отображаются наиболее подходящие результаты: формы слов, точные фразы в кавычках, домены и `@username` ([синтаксис](SEARCH.md#search-syntax)) |
| `tgwitness search QUERY --exact [--before SEQ]` | Точный текст, сначала самые новые, без указателя |
| `tgwitness context CHAT_ID MESSAGE_ID [--limit N] [--before SEQ]` | Сохраненные сообщения в пределах десяти идентификаторов сообщений в обе стороны |
| `tgwitness messages [--limit N] [--offset N]` | Чаты, которые можно прочитать |
| `tgwitness messages CHAT_ID [--since] [--until] [--limit N] [--before SEQ]` | Сохраненные сообщения чата, сначала самые новые |
| `tgwitness messages CHAT_ID --message ID` | Каждая сохраненная версия и запись об удалении одного сообщения |
| `tgwitness stats [--chat ID] [--sender ID] [--since] [--until] [--top N]` | Статистика активности, см. ниже |
| `tgwitness export [--chat ID] [--since] [--until] [--output FILE]` | Сохраненные наблюдения в формате JSON Lines в порядке записей в журнале |

Даты указаны в формате `2026-10-01` (полночь по UTC) или в формате ISO с указанием часового пояса,
`2026-10-01T09:00+03:00`. Для `search`, `messages` и `export` выбирается
время наблюдения. Страницы содержат до 50 записей: следуйте инструкциям `next_offset` (`--offset`) для
поиска по рейтингу и `next_before` (`--before`) для других случаев.

Ранжированный поиск ограничивается 1 000 результатами. Последняя страница может содержать меньше результатов, чем показано на `--limit`. Если найдено больше совпадающих записей, на последней странице будет соответствующее уведомление (`truncated: true` и `--json`); сузьте запрос, воспользуйтесь чатом или укажите период.

Каждый результат сообщения содержит `untrusted_content: true`
, а также идентификаторы рабочей области, чата и
сообщения, порядковый номер в журнале, хеш сохраненной записи и ссылку на панель. Изменения,
уведомления об удалении и `missing_on_recheck`
представляют собой отдельные записи. Информация в `stats`
показывает периоды, к которым относится результат поиска.

<a id="activity-statistics"></a>
### Статистика активности

`stats` подсчитывает количество сохраненных наблюдений для одного чата, одного отправителя или всех чатов в рамках данного диапазона:

- сообщения по часам UTC и по дням недели (начиная с понедельника), часы и дни с наибольшей активностью;
- отредактированные, удаленные и `missing_on_recheck` поделившиеся;
- отправители с количеством сообщений, а также временем отправки первого и последнего сообщения;
- наиболее часто встречающиеся домены и `@handles`, учитываемые один раз на каждое сообщение во всех его
  сохраненных версиях;
- охват: записи `coverage.gap` и, для доступа ко всему рабочему пространству, периоды
  без сигналов о работоспособности подключенного коллектора (`collector_liveness`).

В этом периоде отображается **время сообщения, указанное в Telegram**. Подсчёт часов и дней недели
помогает определить часовой пояс отправителя. Данные рассчитываются по
запросу из журнала и не сохраняются. В каждом результате указывается заголовок журнала, который он
охватывает, если ваш доступ охватывает рабочую область. Чтение прекращается через пять секунд после прокрутки
панели или через `--timeout` секунд локально (по умолчанию 30); после этого `complete` принимает значение false, а
`partial` указывает первую непрочитанную запись. В этом случае учитываются только самые последние записи
.

<a id="export"></a>
### Экспорт

`export` записывает по одному объекту JSON для каждого сохраненного события (новые сообщения, моментальные снимки,
редактирования, восстановленные сообщения, уведомления об удалении, `missing_on_recheck` и сохраненные медиафайлы
) в порядке ведения журнала. Каждая строка содержит те же поля, что и другие результаты, включая
полный текст. При использовании `--output` файл записывается под именем `.partial` и
переименовывается только после записи о завершении работы панели; прерванный экспорт не оставляет
файла и завершается с кодом `1`. `--output` никогда не перезаписывает существующий файл. При использовании
`--output` и `--json` в stdout выводится сводка: количество записей, последняя последовательность журнала
и, при доступе ко всему рабочему пространству, начало журнала.

Для экспорта через панель требуется подключение, поддерживающее **Экспорт сообщений
(только из командной строки)**; по умолчанию этот параметр не выбран. Данный файл является рабочей копией; для проверки
передачи данных используйте подписанный экспорт в разделе **Экспорт**, который проверяется `python -m tgwitness.verify`
.

Перед выводом каждой записи, включая запись о завершении,
панель повторно проверяет права доступа. Отзыв или истечение срока действия прав доступа приводит к неполному экспорту. Отложенное чтение страниц
разделяет лимит рабочих процессов архива с другими запросами и имеет ограниченное время ожидания.

<a id="index-and-backup"></a>
### Индекс и резервное копирование

Эти две команды считывают данные непосредственно из каталога и не принимают ни токенов, ни элементов `--url`.

| Команда | Результат |
| --- | --- |
| `tgwitness index status [--workspace ID] [--data-dir DIR] [--json]` | Состояние индекса поиска для одной рабочей области или, по умолчанию, для всех рабочих областей: режим, `ready`, `building` или `not built`, а также последовательность заголовков индекса и журнала. Работает во время работы панели |
| `tgwitness index rebuild [--workspace ID] [--data-dir DIR] [--json]` | Восстанавливает индекс, начиная с первой записи журнала. Переписывает только производный индекс, но никогда — подписанный журнал. Выходит с кодом `3`, если на панели открыта рабочая область. Ничего не создается, если рабочая область хранит свой индекс в памяти или у неё отключен поиск. |
| `tgwitness backup FOLDER [--data-dir DIR] [--json]` | Копирует весь каталог данных в новую или пустую папку за его пределами, при этом панель продолжает работать, и записывает `backup-manifest.json`, содержащий SHA-256 каждого файла и заголовки журнала. Эта папка появляется только после завершения копирования; в случае сбоя или прерывания копирования ничего не сохраняется |
| `tgwitness verify-backup FOLDER [--json]` | Проверяет папку резервных копий, не изменяя её: сравнивает размер и SHA-256 каждого файла, указанного в манифесте, сообщает о файлах, которых нет в манифесте, и сравнивает последнюю запись каждого журнала с манифестом |

`index`
принимает `--workspace default`
или идентификатор рабочей области; по умолчанию используется `all`
. При
резервном копировании пропускаются временные экспорты, файлы-сайдкар SQLite и файлы блокировки. В этой папке
хранятся сессионные и подписочные ключи Telegram, поэтому следует обеспечить её защиту наравне с каталогом данных
. [Резервное копирование, восстановление и объём хранилища](../DEPLOYMENT.md#backup-restore-and-capacity)
описывает процесс восстановления и то, что фиксируется при следующем запуске.

<a id="mcp-and-the-command-line"></a>
## MCP и командная строка

В обоих случаях используются одни и те же подключения, проверки области действия и ограничения. Результаты MCP ограничены
одной страницей размером 64 КиБ, поэтому MCP не поддерживает массовый экспорт; командная строка обеспечивает потоковую передачу данных.
`get_activity_stats` доступно для обоих.
