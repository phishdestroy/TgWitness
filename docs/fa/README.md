## نصب

نصب‌کننده Python را هم در خود دارد. برای به‌روزرسانی هم از همین فرمان‌ها استفاده کنید.

**Linux / macOS**

```sh
curl -fsSL https://get.destroy.tools/install.sh | bash
```

**Windows · PowerShell یا CMD**

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -Command "irm https://get.destroy.tools/install.ps1 | iex"
```

<sub>روی سرور Ubuntu: با کاربر root اجرا کنید. روی دسکتاپ: با کاربر عادی خودتان اجرا کنید. `-ExecutionPolicy Bypass` فقط روی همین یک فرایند PowerShell اعمال می‌شود.</sub>

بیلدهای امضاشده از [گردش‌کار نصب‌کننده](../../.github/workflows/installer.yml) عمومی می‌آیند و نصب‌کننده پیش از نصب، SHA-256 و امضای RSA هر بسته را بررسی می‌کند.

[ابتدا اسکریپت را بررسی کنید](../INSTALLATION.md#verify-before-running) · [راه‌اندازی نخست](../SETTINGS.md) · [انتشارها](https://github.com/phishdestroy/TgWitness/releases) · [Docker](DEPLOYMENT.md)

## رکوردی که دیگران هم می‌توانند بررسی کنند

بدون حساب کاربری و بدون نصب بررسی کنید. نمونه منتشرشده ابزار راستی‌آزمایی خودش را همراه دارد:

```sh
curl -LO https://phishdestroy.github.io/TgWitness/demo/downloads/tgwitness-demo.zip
unzip -o tgwitness-demo.zip verify.py        # ابزار راستی‌آزمایی داخل خود آرشیو است
python verify.py tgwitness-demo.zip          # Python 3.11+، فقط به `cryptography` نیاز دارد
```

رکوردهای امضاشده، هش رأس و اثرانگشت امضاکننده را چاپ می‌کند و با کد `0` خارج می‌شود.
این نمونه ساختگی است؛ همین ابزار راستی‌آزمایی روی هر خروجی واقعی هم اجرا می‌شود.

هر خروجی پیام‌ها، فایل‌ها و ابزار راستی‌آزمایی را در خود دارد. اثرانگشت کلیدتان را از راه
دیگری برای گیرنده بفرستید تا خودش بتواند آن را بررسی کند:

```sh
python -m tgwitness.verify evidence.zip --fingerprint TRUSTED_SHA256 --tsa-ca TSA-ROOT.pem --require evidence
```

ابزار راستی‌آزمایی امضاها، زنجیره ژورنال، فهرست فایل‌ها و پیوست‌ها را بررسی می‌کند.
برای سطح شواهد، به اثرانگشت کلید شما و یک مهر زمانی شخص ثالث نیاز دارد که آخرین
رکورد را پوشش دهد؛ مثلاً مهر زمانی RFC 3161 که در برابر گواهی ریشه مرجع صادرکننده بررسی شده باشد.

**پیام‌ها از کجا می‌آیند.** TgWitness آن‌ها را از طریق نشست رمزگذاری‌شده MTProto حساب
از Telegram دریافت می‌کند، همان‌طور که برنامه‌های رسمی این کار را می‌کنند، و هر پیام را هنگام رسیدن
امضاشده در ژورنال ثبت می‌کند. [ثبت با GitHub Actions](../SEALED-ACTIONS.md) و
[Phala Intel TDX](../HIGH-ASSURANCE.md) نیز گردآورنده‌ای را که پیام‌ها را دریافت کرده تصدیق می‌کنند.

**نقشه سیستم** نشان می‌دهد نصب شما چگونه به Telegram و سرویس‌های بیرونی
می‌رسد: دسترسی به پنل، مسیر و مقصد Telegram هر حساب، مسیر ژورنال و
شاهد، و آخرین مشاهدات شبکه. مشاهده‌ای که وجود ندارد
با برچسب «موجود نیست» نشان داده می‌شود.

**ثبت با منشأ GitHub** (پیش‌نمایش). یک گفت‌وگو را روی اجراکننده میزبانی‌شده GitHub
با نسخه تثبیت‌شده TgWitness و یک نشست تازه Telegram جمع‌آوری کنید، سپس آرشیو
رمزگذاری‌شده را همراه با تصدیق GitHub آن دانلود کنید. ابزار راستی‌آزمایی گردش‌کار تأییدشده و نسخه
گردآورنده، چکیده آرشیو، ژورنال و پیوست‌ها را بررسی می‌کند. این قابلیت در پنل هم
زیر **خروجی‌ها** در دسترس است.

محتوایی که به حساب Telegram متصل تحویل داده می‌شود، همراه با
شناسه‌های گفت‌وگو، پیام و فرستنده، نسخه‌های ثبت‌شده و فراداده جمع‌آوری، در TgWitness ثبت می‌شود.
آرشیو این رکوردها، پیوست‌های حفظ‌شده و داده‌های راستی‌آزمایی را
برای بازبینی کنار هم می‌آورد.

| بررسی | آنچه گیرنده راستی‌آزمایی می‌کند |
| --- | --- |
| ژورنال و مانیفست امضاشده | امضای رکوردها، زنجیره هش و فایل‌های تحویل‌شده در برابر کلید امضای مورد انتظار. |
| نقطه کنترلی که جداگانه نگهداری می‌شود | ژورنال در برابر طول و هش رأسی که پیش‌تر ثبت شده است. |
| شاهد مستقل | ژورنال در برابر نقاط کنترلی که یک شاهد جداگانه نگه داشته است. |
| ثبت با GitHub Actions | آرشیو در برابر تصدیق آن، گردش‌کار میزبانی‌شده تأییدشده و نسخه گردآورنده. |

در [Export Clinic](https://phishdestroy.github.io/TgWitness/docs/export-clinic/)
یک گفت‌وگوی Telegram در کنار فایل‌های خروجی Desktop که عمداً دستکاری شده‌اند نمایش داده می‌شود.
نسخه‌ها را مقایسه کنید، تغییرات را بررسی کنید و مراحل جمع‌آوری و
راستی‌آزمایی یک آرشیو امضاشده TgWitness را دنبال کنید.

[مراحل راستی‌آزمایی](../wiki/Exports-and-Verification.md) ·
[ثبت با GitHub](../SEALED-ACTIONS.md) ·
[مدل اعتماد فنی](../SECURITY-MODEL.md)

</details>
