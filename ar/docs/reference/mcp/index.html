MCP للقراءة فقط

قم بتوصيل عميل MCP بمساحات العمل والدردشات المحددة مع وصول قابل للانتهاء وقابل للإلغاء.

الموضوع الرئيسي الحالي: استخدم نسخة من المصدر؛ حيث إن النسخة التجريبية المحمولة 0.7.0 تسبق هذه الميزة.

دليل سير العمل · ويكي

قم بتثبيت الخادم الاختياري من دليل مشروع TgWitness:

python -m pip install '.[mcp]'

في اللوحة، افتح «التكاملات» → «MCP». قم بتسمية الاتصال، وحدد مساحات العمل والدردشات الخاصة به، واختر مدة الصلاحية. انسخ رمز الأرشيف مرة واحدة؛ حيث لا يمكن استرداده لاحقًا. قم بإلغاء الرموز المفقودة وإصدار رموز بديلة. رموز اللوحة و بيانات اعتماد Telegram ليست بيانات اعتماد MCP.

توصيل عميل#

تقوم اللوحة بإنشاء .vscode/mcp.json لنظام VS Code Local harness باستخدام تكوينها الموثق. احفظ الملف الذي تم تنزيله في ذلك الموقع، وقم بتشغيل MCP: List Servers، وابدأ تشغيل TgWitness. يطلب VS Code الرمز المميز من خلال إدخال كلمة مرور. ملف JSON الذي تم تنزيله يحتوي على مرجع للمطالبة، وليس الرمز المميز نفسه. استخدم الملف القابل للتنفيذ بلغة Python من البيئة التي تم تثبيت ملحق MCP فيها.

بالنسبة لعملاء stdio الآخرين، قم بتشغيل:

python -m tgwitness.mcp_server --api-url http://127.0.0.1:8787

اضبط TGWITNESS_ARCHIVE_TOKEN في البيئة المحمية للعميل. لا تضعه في معلمات الأوامر أو عناوين URL. يقرأ الجسر من خلال واجهة برمجة تطبيقات الأرشيف المصرح بها لللوحة؛ ولا يمتلك وصولاً مباشرًا إلى قاعدة البيانات. لا ينقل Stdout سوى رسائل MCP.

بالنسبة للعملاء عن بُعد، قم بتشغيل الخدمة بجانب لوحة التحكم:

python -m tgwitness.mcp_server --transport streamable-http \
  --api-url http://127.0.0.1:8787 --port 8766 \
  --public-url https://archive.example.org/mcp

قم بإعادة توجيه /mcp عبر وكيل عكسي HTTPS إلى 127.0.0.1:8766/mcp، مع الحفاظ على رأس Authorization: Bearer …. قم بتعطيل تسجيل رؤوس التفويض ونصوص الطلبات/الاستجابات. قم بالربط خارج نطاق loopback فقط عند الحاجة، باستخدام --host و--public-url. تستخدم نقطة النهاية Streamable HTTP من MCP Python SDK الرسمي. وهي تدعم بيانات اعتماد الحامل المُعدة بشكل صريح، وليس اكتشاف OAuth؛ ولا يتم دعم العملاء الذين يحتاجون إلى OAuth وحده.

يؤدي فحص البروتوكول والوصول إلى تهيئة عميل MCP حقيقي وعرض قائمة بالأدوات. ولا يقوم باسترداد الرسائل. لإجراء فحص عن بُعد، يتلقى خادم MCP المختار رمز الأرشيف. قم بتكوين خادم لا تشغله أنت أو تثق به في هذا النطاق فقط.

النطاق والنتائج#

الأدوات المتاحة: list_workspaces، list_chats، search_messages، get_message_versions، get_message_context، get_journal_event، و get_capture_status. لا توجد إجراءات خاصة بـ Telegram، أو تغييرات في التكوين، أو أدوات للتصدير الجماعي. يتم إعادة التحقق من الوصول إلى مساحة العمل/الدردشة عند كل قراءة؛ وتتوقف بيانات الاعتماد منتهية الصلاحية أو الملغاة عن العمل. الحدود هي 60 طلبًا لواجهة برمجة التطبيقات (API) في الدقيقة لكل بيانات اعتماد، و50 سجلًا في كل صفحة، واستجابة بحجم 64 كيلوبايت، ومهلة 8 ثوانٍ لواجهة برمجة التطبيقات (API).

تتضمن نتائج الرسائل مساحة العمل، ومعرّفات الدردشة/الرسائل، وتسلسل الأحداث، والتجزئة المحفوظة، ورابط اللوحة. يجب أن يكون لدى المشاهد الذي يفتح الرابط جلسة لوحة مصرح بها خاصة به. يتم حذف كائنات Telegram الأولية، وتجزئات الوصول، ومراجع الملفات، ومواد الجلسة، والمفاتيح. يبحث البحث في نص الرسالة، وليس في الحقول الأولية. يكون النص محدودًا ويتم تمييز الأجزاء المقطوعة. تظل عمليات التعديل وإشعارات الحذف في Telegram و missing_on_recheck ملاحظات منفصلة. لا يمكن للوصول المقتصر على الدردشة رؤية الأحداث التشغيلية على نطاق مساحة العمل؛ وتشير حالة الالتقاط صراحةً إلى هذا القيد.

يُعتبر نص الأرشيف مدخلات غير موثوقة. لا تمنح التعليمات الموجودة داخل الرسائل أي نطاق إضافي ويجب ألا تُعامل على أنها تعليمات من العميل. قد يتلقى نموذج الذكاء الاصطناعي الخارجي أي محتوى يطلبه عميل MCP الخاص به. يمنع الوصول للقراءة فقط إجراء تغييرات على الأرشيف؛ لكنه لا يمنع العميل من الاحتفاظ بالبيانات التي يقرأها.

تُحدد التجزئات السجلات المحفوظة وتدعم عمليات التحقق من سلامة البيانات. وهي لا تثبت بشكل مستقل هوية كاتب الرسالة على Telegram أو أن كل رسالة قد تم تسجيلها.
