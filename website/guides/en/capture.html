Why this is the simplest strong option

Nothing to set up

The wizard is a web page and the collector runs on GitHub. There is no server, no local installation and no session file to hand over.

The machine was never yours

A fresh GitHub-hosted runner with clean storage signs in to Telegram with a new session. Nobody has to trust your computer.

An origin anyone can check

GitHub attests the archive. The verifier checks that attestation, the approved workflow and collector commits, and the signed journal and file hashes.

Only you can open it

The runner uploads only files encrypted for your public key. The private key is created and kept on your device.

How a capture runs

Five stages inside one session of 30, 60 or 120 minutes. The wizard at the bottom of this page walks you through each of them.

  1. Save your key

    The wizard creates sealed-key.json on your device. Only the public recipient value goes to GitHub.

  2. Run the workflow

    In your fork, enable Actions and run Sealed chat capture with the recipient and the session length.

  3. Sign in

    Open the encrypted connection with your key, then sign in to Telegram by QR code or phone. Session imports are not allowed.

  4. Choose and collect

    Pick the mode, chats, dates and attachments. Settings are fixed once collection starts.

  5. Decrypt and verify

    Download the encrypted result, open it here with the same key and run the verifier.

Choose what to collect

Default

Telegram Takeout

All accessible chats or a selection, with dates, account categories, media rules and JSON/HTML views.

Telegram's official export. Telegram may ask for approval in another session, and the wait counts against your session time.

Regular Telegram API

The same account scope without starting Takeout.

Cannot list channels you have left or fetch Takeout-only personal data. Telegram rate limits still apply.

Chat event journal

One chat: its history and the changes observed while the run is active.

Date filters, account categories and Desktop-style views do not apply.

All three modes receive the same GitHub attestation and encrypted delivery. Takeout is never silently replaced by the regular API.

What you need

  • A GitHub account and your own fork of TgWitness. The fork contains code, not chats.
  • A Telegram account you can sign in to by QR code or phone. A separate account is safer.
  • A modern browser on your computer. Keep the wizard tab open until the end.
  • Enough time: one session lasts up to 120 minutes, including sign-in and any Takeout approval.

Never put these into GitHub

Phone numbers, login codes, Telegram passwords, the private key or a session never go into workflow inputs, commits, issues or logs. The only value GitHub receives is the public recipient key.

What you receive

  • sealed-result

    The GitHub artifact with the encrypted delivery.

  • delivery.zip

    What the wizard saves after decryption.

  • evidence.zip

    The signed journal, messages and files.

  • attestation.jsonl

    GitHub provenance for the archive.

Browser decryption handles up to 256 MiB. Larger results arrive in parts and use the local command from the reference below.

GitHub keeps the encrypted artifacts for one day. Download them in time.

The attestation records when the archive was committed. It does not certify the time of each message.

Who still has to be trusted

Taken out of the circle

  • Your computer and its clock.
  • Your word about where the collection ran.
  • Anyone who edits the archive afterwards: a changed byte fails verification.

Still trusted in this setup

  • GitHub and its hosted runner.
  • The pinned, open collector code and its dependencies.
  • The HTTPS tunnel and your browser.

The temporary runner sees the Telegram session and messages in plain form while it works; everything it delivers is encrypted for you. The trust model explains each part.

Check a delivery

Unzip delivery.zip and run the verifier from a trusted TgWitness installation with GitHub CLI. Replace OWNER with the owner of the fork that ran the capture.

python -m tgwitness.sealed_verify evidence.zip --bundle attestation.jsonl --repo OWNER/TgWitness
  • Archive hash matches
  • Workflow approved
  • Collector version approved

To hold the run to settings agreed with a reviewer, save them before collection and add --expected-selection sealed-export-settings.json --require-complete.

This is a preview

  • Try a small chat you control first: collect it, decrypt it and run the verifier.
  • If Telegram still lists the temporary session, end it in Settings → Devices.
  • An unfinished capture cannot resume after its runner is gone; a new run starts a new capture.
