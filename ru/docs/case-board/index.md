# Создание Case Board

Canonical page: https://phishdestroy.github.io/TgWitness/ru/docs/case-board/

Превратите сохраненные данные Telegram в дело, которое ваша команда сможет совместно рассмотреть.

Case Board хранит закладки, выделения точного текста, сохраненные фрагменты и обсуждения рядом с ссылками на источники. Коллекция придает делу рабочую структуру; подписанные версии фиксируют процесс его разработки командой.

## От сообщения до карточки дела

1. Откройте **«Расследование» → «Доска дела»** в стандартном или экспертном режиме. Создайте коллекцию для дела и выберите область чатов.
2. В **«Журнале»** или сохраненном чате выберите **«Добавить в доску**» или выделите запись и нажмите **B**. Карточка попадает в «Входящие»; присвойте ей понятное название и переместите в свою коллекцию.
3. Выделите фрагмент в сохраненном сообщении чата и выберите **«Выделить» → «Доска»,** чтобы сохранить точную цитату и версию сообщения. Добавьте примечание с объяснением, почему это важно.
4. Обсуждайте карточку, присваивайте статус проверки и возвращайтесь к исходному контексту всякий раз, когда необходимо проверить утверждение. Используйте **функцию «Презентация»,** чтобы пройтись по сборнику данных вместе с коллегами.

### Следуйте по одной измененной ссылке для оплаты

Синтетический пример · локальная иллюстрация

1. **Захват.** Откройте сохраненное наблюдение № 142 и его версию сообщения.
2. **Добавьте в закладки.** Сохраните цитату, ссылку на источник и свой вопрос на карточке.
3. **Проверка.** Добавьте комментарий команды и переместите карточку в статус «Проверка».
4. **Представить.** Пройтись по процессу сбора данных и открыть контекст цитируемого источника.

## Сохраните полезный диапазон один раз

Нажмите Shift и щелкните по двум записям в одном чате, чтобы **выделить** **фрагмент между ними**, выберите **«Выделить по времени**» или сохраните текущие фильтры журнала. Проверьте количество записей перед сохранением. Снова откройте фрагмент, чтобы применить сохраненный запрос; функция **«Показать записи, добавленные после создания закладки»** отобразит добавленные позже записи.

Временной срез следует за временем наблюдения сборщика. Срез по ID сообщения может отслеживать выбранные сообщения по мере поступления последующих изменений. Сохраненная граница создания позволяет получателю сравнить исходный набор с его последующим состоянием.

## Назначьте каждому коллеге соответствующую роль

**Рецензент** просматривает доску; **аналитик** добавляет карточки и комментарии; **оператор** также управляет сбором данных и решениями по проверке. Права доступа к рабочему пространству и чату распространяются на карточки, контекст источников и обсуждения. Используйте именованные права доступа для четкого указания авторства.

## Подготовьте конечный результат

Экспортируйте фрагмент в виде подписанного JSON-файла или используйте формат CSV для работы в электронной таблице. Настройки отчета могут включать закладки и фрагменты, а также комментарии команды (если выбрано). Выберите эти элементы в [Report Studio](https://phishdestroy.github.io/TgWitness/ru/docs/reports/); сохраненный фрагмент не приводит к автоматической настройке отчета. Для получателей с ограниченным доступом используйте отдельные [элементы управления передачей данных](https://phishdestroy.github.io/TgWitness/ru/docs/handover/).

Ознакомьтесь со [справочником](https://phishdestroy.github.io/TgWitness/ru/docs/reference/case-board/) [по](https://phishdestroy.github.io/TgWitness/ru/docs/reference/case-board/) [Case Board](https://phishdestroy.github.io/TgWitness/ru/docs/reference/case-board/) для получения информации о подписанных редакциях, точном соответствии цитат, проверке выделенных фрагментов и разрешениях.
