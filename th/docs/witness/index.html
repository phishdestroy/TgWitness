อ่านเพิ่มเติม

จัดการกับคลังข้อมูลแบ่งปันกรณีศึกษาตั้งค่าบอทพยานให้ระบบทำงานต่อไปค้นหาว่าเกิดข้อผิดพลาดอะไร

อ้างอิง

การตั้งค่าเริ่มต้นอย่างรวดเร็วรูปแบบบัญชีและเซสชันการเข้าถึงและสิทธิ์การเชื่อมต่อ, พร็อกซี และการคุ้มครองข้อมูลการติดตั้ง
Collectวิธีการเก็บรวบรวมข้อมูลโหลดประวัติแหล่งที่มาขั้นตอนการทำงานและการดำเนินการโหมดการสืบสวนคุณสมบัติและข้อจำกัด
การเก็บรักษาข้อมูลและการบูรณาการการวิเคราะห์ข้อมูลในคลังMCP แบบอ่านเท่านั้นOCR และแปลงข้อความเป็นข้อความแบบท้องถิ่นwebhooks ส่งออก
หลักฐานวิธีการทำงานของหลักฐานรูปแบบหลักฐานพยานอิสระข้อมูลเวลา
ความปลอดภัยและโครงการความปลอดภัยและการจัดการข้อมูลสถาปัตยกรรมสิ่งที่ได้รับการทดสอบแล้วประกาศเรื่องใบอนุญาตและความไม่เข้ากันทางสถาปัตยกรรมประกาศความไม่เข้ากันได้ของผู้ดำเนินการบันทึกการเปลี่ยนแปลง

ตั้งค่าบอทพยาน

ให้กระบวนการแยกต่างหากตรวจสอบบันทึกและเผยแพร่จุดตรวจสอบที่ลงนามแล้วไปยังช่องของคุณ

สองเซิร์ฟเวอร์, สองกุญแจลงนาม

เตรียมบอทและช่อง

สร้างบอทด้วย BotFather และอนุญาตให้บอทนั้นโพสต์ในช่องที่คุณควบคุม เลือกคอมพิวเตอร์หรือเซิร์ฟเวอร์สำหรับ witness การใช้โฮสต์และผู้ดำเนินการที่แยกต่างหากจะให้ความอิสระที่มากขึ้นกว่าการใช้กระบวนการที่สองบนเซิร์ฟเวอร์ของผู้เก็บข้อมูล

สามขั้นตอนในส่วน Extras

  1. สิทธิ์การเข้าถึงแบบอ่านเท่านั้น เปิด Extras → บอทในช่องของคุณ สร้างโทเค็นพยาน และบันทึกไฟล์สิทธิ์การเข้าถึง ซึ่งอนุญาตให้อ่านจุดตรวจสอบและสถานะการทำงาน แต่ไม่รวมถึงการสนทนาหรือการควบคุมตัวเก็บข้อมูล
  2. ช่องและช่วงเวลา. ป้อนชื่อช่องและที่อยู่ของตัวเก็บข้อมูลที่สามารถเข้าถึงได้จาก witness. บันทึกไฟล์การตั้งค่า
  3. เริ่มต้นใช้งาน ใส่ witness.json, witness-token.txt และ bot-token.txt ที่สร้างขึ้นบนเครื่องโฮสต์ของ witness เข้าด้วยกัน รันคำสั่งด้านล่างในสภาพแวดล้อมโครงการที่ติดตั้งแล้ว
python -m tgwitness.witness run --config witness.json --check-config
python -m tgwitness.witness run --config witness.json

การดาวน์โหลดไฟล์จะไม่ทำให้ witness เริ่มทำงาน ตรวจสอบให้แน่ใจว่าโพสต์แรกที่มีลายเซ็นปรากฏในช่อง จากนั้นเก็บลายนิ้วมือกุญแจสาธารณะของ witness ไว้แยกต่างหาก

เลือกความถี่ในการเผยแพร่

การเผยแพร่ทุกครั้งจะสร้างบันทึกภายนอกอย่างสม่ำเสมอ โดยทุก 5 นาที จะมีการโพสต์ประมาณ 288 ครั้งต่อพื้นที่ทำงานต่อวัน นอกจากนี้ การตั้งค่าขั้นสูงยังรองรับการเผยแพร่เมื่อมีการเปลี่ยนแปลงหรือเกิดปัญหา รวมถึงการใช้พร็อกซีและที่อยู่ API ของบอทที่ปรับแต่งได้

บอทนี้ยืนยันอะไรกันแน่?

TgWitness จะขอจุดตรวจสอบที่ลงนามจากผู้เก็บข้อมูล ตรวจสอบความถูกต้องกับกุญแจที่คาดไว้ และเก็บสมุดบันทึกที่ลงนามแยกต่างหาก มันบันทึกทั้งการตอบกลับที่ขาดหายไป คำตอบที่ถูกปฏิเสธ รวมถึงการตรวจสอบที่สำเร็จ การเผยแพร่ข้อมูลยังคงขึ้นอยู่กับว่า TgWitness กำลังทำงานอยู่และสามารถเข้าถึง Bot API ของ Telegram ได้หรือไม่

เครื่องมือนี้ตรวจสอบสถานะของบันทึกที่ผู้เก็บข้อมูลรายงานมาเท่านั้น ไม่ทำการตรวจสอบข้อความ Telegram ทุกข้อความอย่างอิสระ หากต้องการตรวจสอบข้อความ Telegram ทุกข้อความอย่างอิสระ ให้เพิ่มการทดสอบการส่งข้อความแบบควบคุม (Controlled Delivery Test)

ตรวจสอบหลักฐานในภายหลัง

เก็บรักษาบันทึกพยาน โพสต์ในช่อง และลายนิ้วมือที่บันทึกไว้อย่างอิสระ ขั้นตอนการตรวจสอบอย่างครบถ้วนจะเปรียบเทียบข้อมูลเหล่านี้กับไฟล์ส่งออกที่ลงนามโดยผู้เก็บรวบรวม

อ้างอิงเต็ม →ขั้นตอนต่อไปให้ระบบทำงานต่อไป →

คู่มือเหล่านี้อธิบายการนำไปใช้ในปัจจุบัน ผลการตรวจสอบความถูกต้องและช่องว่างที่ยังเหลืออยู่ได้รับการบันทึกไว้อย่างแยกต่างหาก สิ่งที่ได้รับการทดสอบแล้ว →
