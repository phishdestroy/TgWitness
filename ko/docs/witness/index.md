# Witness 봇 설정하기

Canonical page: https://phishdestroy.github.io/TgWitness/ko/docs/witness/

별도의 프로세스가 저널을 확인하고 서명된 체크포인트를 채널에 게시합니다.

## 호스트 2개, 서명 키 2개

호스팅 / 수집기**계정 + 기록부**

텔레그램 세션 수집기 서명 키

읽기 전용 체크포인트 엔드포인트

← 서명된 답변 요청 →

HOST B / WITNESS**확인 + 보존**

고정된 수집기 지문 별도의 증인 서명 키

자체 저널 + 봇 토큰

Witness → 텔레그램 봇 API →**귀하의 채널 · 서명된 TGW1 게시물**

위트니스는 자체적으로 검증을 수행합니다. 수집기(Collector)의 접근 권한은 읽기 전용입니다. 봇 게시 기능은 위트니스의 연결 및 토큰을 사용하며, 위트니스에게는 계정 세션이 부여되지 않습니다.

03 / 체크포인트 결정 사항예시 답변

최종 승인일**120건의 기록**`head 9c7d…`

다음 답변**128건의 기록**`head a4f2…`

승인됨: 카운트가 증가하고, 서명이 검증되며, 키가 일치합니다. 위트니스는 이 새로운 경계를 유지합니다.

모든 답변 예시는 유효한 서명과 고정된 키를 전제로 합니다. 여기에 제시된 해시는 간략한 예시일 뿐입니다. 해시 값의 개수가 많다고 해서 이전 접두사 전체가 변경되지 않았음을 증명할 수는 없습니다. 체크포인트가 보존된 내보내기 파일과 비교해 보십시오.

## 봇과 채널 준비하기

BotFather로 봇을 만들고 채널에 게시할 수 있게 하십시오. 증인은 다른 곳에서 실행하십시오: 다른 호스트, 가능하면 다른 사람이 운영하는 호스트가 수집기 옆의 두 번째 프로세스보다 훨씬 가치 있습니다.

## '추가 기능'의 세 단계

1. **읽기 전용 액세스.** **추가 기능 → 독립 증인**에서 토큰을 만들고 파일을 저장합니다. 체크포인트와 상태만 읽으며 그 외에는 없습니다.
2. **채널 및 간격.** 텔레그램 채널이나 Discord 웹훅, 그리고 증인이 접근할 수 있는 수집기 주소. 설정 파일을 저장합니다.
3. **실행.** `witness.json`, `witness-token.txt`, `bot-token.txt`를 증인 호스트에 함께 두고 실행합니다:

```
python -m tgwitness.witness run --config witness.json --check-config
python -m tgwitness.witness run --config witness.json
```

채널에 첫 서명 게시물이 올라오기를 기다린 뒤, 증인 지문을 안전한 곳에 저장합니다.

Discord를 쓰나요? 웹훅 URL을 `discord-webhook.txt`로 저장하십시오. 증인 하나는 한 곳에 게시하며, 긴 확인 결과는 Discord에 파일로 도착합니다.

## 게시 빈도 선택

확인할 때마다 게시하면 꾸준한 외부 기록이 남습니다: 5분마다면 작업 공간당 하루 약 288개 게시물입니다. 고급 설정으로 변화나 문제가 있을 때만 게시하거나, 프록시나 자체 Bot API를 쓸 수 있습니다.

**이 봇은 실제로 무엇을 증명합니까?**

수집기에 서명된 체크포인트를 요청하고, 예상한 키로 확인하며, 놓친 응답과 거부된 응답까지 포함해 자체 서명 저널을 보관합니다.

저널 상태를 확인할 뿐, 텔레그램 자체를 지켜보지는 않습니다. 그러려면 통제된 전달 테스트를 실행하십시오.

## 나중에 증거를 확인하세요

증인 저널, 게시물, 지문을 보관하십시오. 수집기 내보내기와 [대조하는 방법](https://phishdestroy.github.io/TgWitness/ko/docs/reference/witness/#verify).
