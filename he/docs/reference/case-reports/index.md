# תצורת הדוח ואימותו

Canonical page: https://phishdestroy.github.io/TgWitness/he/docs/reference/case-reports/

מסנני דוחות, שמונה עיצובים, הגדרות קבועות מראש לתוכן, היסטוריית שינויים שנשמרה וההערכה הכלולה בייצואים חתומים.

[TgWitness](https://github.com/phishdestroy/TgWitness/blob/main/README.md) / [תיעוד](https://github.com/phishdestroy/TgWitness/blob/main/docs/README.md) · [חקירה](https://phishdestroy.github.io/TgWitness/he/docs/reference/investigation/)

![חקירה](https://phishdestroy.github.io/TgWitness/assets/chapter-investigate.svg)

הפכו את התצפיות שנבחרו לתיאור קריא של המקרה: השאלה, היקף החקירה, השינויים שנשמרו, התרשימים, הממצאים והפניות למקורות. כל דוח מספק למקבל דרך לבדוק את החומר שנמסר ולבחון את היקף האיסוף שלו.

הסעיף "**בסיס האמון והמגבלות"** מופיע בדוחות היומן, המסירה, הצ'אט, החשבון והשיתוף. קבצי ה-PDF של היומן והמסירה משתמשים באותה הערכה כמו קובץ ה-`report.json` החתום שלהם. קבצי ה-ZIP נושאים את ה-`case_assessment` במניפסט החתום. הערכה זו מועברת יחד עם החומר המיוצא. התצפיות המקוריות שומרות על החתימות הקיימות שלהן.

## פורמטים של מסמכים וסדר הקריאה

### סטודיו לדוחות

פתח **את** **'ייצוא' → 'הגדר' ו'תצוגה מקדימה**'. עבר על **'נתונים' → 'עיצוב ותוכן' → 'תצוגה מקדימה**':

1. השתמשו במרחב העבודה כולו או בחרו צ'אטים, מחברים, כולל תאריכי תצפית ב-UTC וסוגי אירועים. טענו את הקטלוג כדי לחפש צ'אטים ומחברים, או הזינו את מזהי ה-Telegram שלהם. מסנני המחברים מתאימים למזהי השולחים שהוקלטו; הודעת מחיקה ללא שולח אינה תואמת למסנן מחברים.
2. בחר עיצוב עמוד, ולאחר מכן בחר תרשימים, תוויות למשתתפים, תמלול ו הממצאים הכתובים שלך. שינוי העיצוב שומר על בחירות אלה.
3. הכינו את תצוגת המקדים. היא מציגה ספירות בפועל, פעילות, משתתפים, רשומות לדוגמה, שינויים שנשמרו וטווחי מספרי הודעות חסרים. שינוי בחירה מציין שתצוגת המקדים אינה מעודכנת. שמרו לפני הורדת קובץ HTML, PDF חתום, JSON חתום או קובץ ZIP של הראיות.

תצוגה מקדימה של הנתונים סופרת את קידומת היומן היציבה המלאה, ולא מדגם ראשוני. רק שורות הדוגמה המוצגות ורשימות ארוכות מוגבלות; ספירת הנתונים שהושמטו מוצגת. ייצוא מאוחר יותר לוקח תמונת מצב יציבה חדשה, ולכן איסוף מתמשך עשוי להגדיל את המספרים. ההיקף, הספירות וזהות המקור כלולים ב הדוח החתום. פתיחת הטופס או הצגתו בתצוגה מקדימה אינן שומרות אותו.

**הנחיות בנושא תחום שיפוט.** תחת פרטי המסמך, פתחו את **הנחיות בנושא תחום שיפוט · אופציונלי** כדי לבחור תחום שיפוט והליך אזרחי/מסחרי או פלילי. הנספח מכיל את הבסיס המשפטי, קישורי המקור, הערות הכנה ומצב המחקר. סיכומים והסברים בשפה המקומית על אמצעי הגנה על איסוף הנתונים הם אופציונליים. לא נבחרה שיפוט כברירת מחדל. בחירות אלה שייכות לסביבת העבודה, והן אינן נכללות בתצורות הפריסה השמורות ובברירות המחדל המרומזות לשיתוף והעתקה. ראו [ברירות מחדל, דוחות נתמכים ומגבלות מחקר](https://github.com/phishdestroy/TgWitness/blob/main/docs/JURISDICTION_GUIDANCE.md) .

**יש לבחור את הגרסה המיועדת למקבל.** התרשימים והתמליל משתמשים ברשומות שנבחרו. שלמות, שמירה וכיסוי מתארים את יומן המקור המלא. קובץ ה-ZIP של הראיות מכיל את הרשומות המקוריות והנספחים. יש להשתמש [בהעברה מצומצמת](https://phishdestroy.github.io/TgWitness/he/docs/reference/evidence/#handover-extract) כאשר על המקבל לקבל רק נתונים נבחרים ומותרים.

### קרא את העריכות, המחיקות ומזהים חסרים

עריכה מציגה את הטקסט שנשמר **לפני** **ואחרי**, ומדגישה את המילים ששונו. מחיקה מציגה את הגרסה האחרונה שנשמרה לפני ההודעה. אם לא נלכד תוכן קודם, הדוח מציין זאת. כאשר בוחרים רק עריכות או מחיקות, הגרסאות הקודמות נותרות זמינות כהקשר המסומן במפורש מחוץ למסננים. הודעות שאינן קשורות אינן מתווספות להיסטוריית פעולות אלה.

**מזהי הודעות שלא נצפו** הם פערים בין מספרים ידועים בצ'אטים שנבחרו ו טווח המזהים הנגזר מתאריכים. כל רשומת מקור ידועה נבדקת לפני הכרזה על מספר כ"לא נצפה": סינון מחבר אחר, סוג אירוע או תאריך אינו יכול ליצור פער כוזב. הודעות שמורות סמוכות מסומנות כ"הקשר". מספר חסר אינו מוכיח שהודעה הייתה קיימת או נמחקה; הודעות מחיקה ובדיקות חוזרות שלא צלחו נותרות סוגי אירועים נפרדים.

### בחרו עיצוב

קיימים שמונה עיצובים לדפים עבור דוחות HTML של יומנים וצ'אטים בודדים, וכן דוחות PDF חתומים. הם משתמשים באותם רשומות וחישובים, עם עטיפות שונות, טיפוגרפיה, כותרות פרקים, טבלאות וריווח.

| עיצוב | סגנון קריאה |
| --- | --- |
| קלאסי | תיק מסמכים מסורתי עם כריכה כהה ופרקים ממוספרים. |
| עריכה | עמוד שער ממוסגר בסגנון סריף, שוליים רחבים ופס פרקים צר. |
| תדריך | כריכה קומפקטית עם שדרה בצבע כחול כהה, כותרות קצרות וטבלאות צפופות. |
| ניתוח נתונים | עמוד שער בסגנון סקר, לוחות תרשימים מודולריים ואיורים בגופן אחיד. |
| טכני | רישום מסודר, מסגרת הפניה ממוספרת וטבלאות השוואה מדויקות. |
| סקירה כללית | כריכה פנורמית, ריווח נדיב ונתוני סיכום בולטים. |
| סדרת קריאה | תפריט צדדי ופרקים מקובצים לממצאים, היקף, שינויים ויומן התצפיות. |
| ספר חשבונות ושוליים | פרקים ממוספרים עם שוליים רחבים, טבלאות מדויקות ותמליל הודעות נפרד. |

העיצוב נשמר לכל סביבת עבודה ונרשם במניפסט הייצוא החתום. HTML פועל במצב לא מקוון, תומך בערכות נושא בהירות וכהות, ומתאים את עצמו למסכים צרים ולשפות הנכתבות מימין לשמאל. קבצי PDF מקוריים משתמשים בגופנים המצורפים; העיצוב העריכתי כולל את Noto Serif תחת רישיון SIL Open Font License המצורף. סדרות קריאה ו "Ledger & margin" חלים גם על סקירות חשבונות, צ'אטים בחשבונות ושיתוף עותקים.

קובצי PDF בסינית, יפנית וקוריאנית דורשים בנוסף גופן מתאים בשרת, כגון Noto Sans CJK, המותקן בכל המערכת או ממוקם ב-`TGWITNESS_FONT_DIR`. כאשר הגופן אינו זמין, קובץ ה-ZIP שומר את דוחות ה-HTML וה-JSON.

שני העיצובים הללו כוללים יומן קריא ללא JavaScript. עבור ייצוא בהיקף גדול, תצוגה זו מכילה עד 500 רשומות שלמות במסגרת תקציב קלט של 8 MiB; הדוח מציין את המגבלה ומכיל קישורים לצופה המלא ולרשומות המקור. ספריית החשבונות ומדד הקשרים מתארים את אותה דגימת קריאה, ולא את כל המשתתפים. תרשימי היומן המלא שומרים על היקף הציון הנפרד שלהם.

### בחרו את התוכן

| תוכן קבוע מראש | כלול כברירת מחדל |
| --- | --- |
| תיק החקירה | פעילות, זמני תצפית, משתתפים, צ'אטים ותמליל השיחה. |
| תדריך | סקירת פעילות ללא דירוג המשתתפים או תמלול. |
| סקירת פעילות | פעילות, זמני תצפית, משתתפים, צ'אטים והרכבם, עם הפניות למקורות ומספרים מדויקים. |
| דוח מותאם אישית | שילוב אישי של תרשימים, תמלילים ותצוגה מקדימה. |

שינוי הגדרה קבועה מראש שומר על העיצוב, פרטי התיק והניתוח הכתוב. בדיקות תקינות, כיסוי, מגבלות והוראות אימות נשמרות בכל עיצוב. רשומות המקור בקובץ ה-ZIP נותרות ללא שינוי כאשר תרשים או תמלול מוסתרים.

**הערות הבדיקה** האופציונליות מכילות את השאלה, השיטה, הממצאים וה מסקנה שנכתבו על ידי מחבר הדוח. יש לציין את קובץ המקור ומספרי הרשומות בממצאים. החתימה משמרת את ההצהרות שנכתבו על ידי המחבר לצד הדוח; תצפיות המקור ופרשנות המחבר נותרות ניתנות לזיהוי. בהעברות מצומצמות מושמטות הערות פרטיות אלו וטבלאות היומן המלאות. אפשרויות הטבלה והבדיקה חלות על דוחות היומן.

בחרו פעילות לאורך זמן, מפת החום של ימי השבוע/שעות לפי UTC, דירוגי משתתפים, דירוגי צ'אט והרכב הרשומות. בחרו 5–30 קבוצות מדורגות וכינויים ניטרליים של משתתפים או מזהי חשבונות. שולחים לא ידועים והמשתתפים הנותרים מופיעים בשורות נפרדות. הכינויים משפיעים על התרשימים בלבד; הרשומות המקוריות עדיין מכילות את זהותם.

תצוגה מקדימה של העיצוב מתעדכנת מהטיוטה שלא נשמרה תוך שימוש בכיסוי הסופי, ברכיבי הבדיקה וב רכיבי התרשימים, ומוגבלת לתוצאות תואמות מתוך 50,000 הרשומות הראשונות במקור. תצוגה מקדימה של הנתונים המוצגת להלן מחשבת את הבחירה המלאה. היא במפורש לא חתומה ואינה שומרת את העריכות. הכפתורים "Cover" ו-"Charts" מחליפים את החלק המוצג. זו אינה תצוגה מקדימה מלאה של קובץ PDF. **שמירת הגדרות הדוח** מחילה את הבחירות על ייצוא עתידי; קבצים חתומים קיימים אינם ניתנים לשינוי. קובץ ה-PDF משתמש בעמוד השער הנבחר, בטיפוגרפיה, בפריסת הפרקים ובאותם סיכומים שנבחרו כמו ב-HTML וב-JSON החתום.

הערכת האמינות, מגבלות הכיסוי והוראות האימות נותרות על כנן. הסתרת תרשימים או תמלול קריא אינה מסירה שורות של מקורות סמכותיים מהקובץ ZIP. סדרות תרשימים מושבתות אינן נכללות ב-JSON האנליטי; יש להשתמש בייצוא מצומצם כדי להגביל את חשיפת רשומות המקור.

מסנני בחירת נתונים חלים על דוחות יומן; ייצוא חשבונות ושיתופים שומרים על היקף הרכישה והחשיפה שלהם.

העדפות עיצוב/תרשימים משותפות נשמרות בייצוא חדש של צ'אטים/חשבונות ובתצוגה מקדימה של שיתוף חשבונות. הגדרות השפה והפרטיות של החשבון/השיתוף נותרות עצמאיות; הערות פרטיות על תיקים ובדיקות אינן מועתקות לייצוא זה. דוחות החשבון והשיתוף נשמרים ב-HTML ומוגנים על ידי מניפסט הארכיון החתום שלהם. יומן, העברת יומן ממוזערת וערכות צ'אט בודדות מספקות גם קבצי PDF חתומים.

### מה מראים התרשימים

פעילות היומן ומפות החום סופרות **תצפיות** חדשות, היסטוריות, משוחזרות, ערוכות, שנמחקו ו חסרות בבדיקה חוזרת, לפי זמן התצפית של האספן ב-UTC. פעימות לב ואישורי קבלה של קבצים מצורפים אינם נכללים. דירוג המשתתפים סופר רק תצפיות הודעות חדשות, היסטוריות ושוחזרו: שולח אינו מוגדר כעורך או כמחיק. תצפיות חוזרות יכולות לתאר את אותה הודעת טלגרם.

ניתוחי היומן שומרים על ספירות לפי סוג, הפניות לרשומות הראשונות/האחרונות וה-SHA-256 של קובץ המקור `events.jsonl`. הנתונים כוללים ערכים מדויקים ב-HTML וב-PDF. קטגוריות יומיות מתחלפות לחודשים מעבר ל-366 הימים שנרשמו; הגרפים משלבים אותן לכל היותר ל-36 אינטרוולים בעלי רוחב שווה. יותר מ-100,000 מזהים ייחודיים או 1,200 סימני חודשים גורמים לכך שהתרשים המושפע אינו זמין, בעוד שהספירות הכוללות המדויקות נותרות זמינות.

תרשימי תמונת מצב ושיתוף חשבונות סופרים רק שורות של הודעות שאינן קשורות לשירות, בהתבסס על זמן ההודעה שנרשם. נתוני השיתוף המחוברים מחושבים לאחר עריכה וסינון. תרשימים אלה משתמשים לכל היותר ב-90 מרווחי זמן שווים ברוחבם לפי UTC ושומרים עד 10,000 ערכי קיבוץ; ספירות עודפות מוצהרות במפורש ומותאמות. האינטרוול האחרון עשוי להיות קצר יותר. תאריכים לא ידועים או לא מדויקים אינם נכללים בתרשימי הזמן.

אי-מילוי טווח זמן פירושו שאין תצפיות כלולות בו; יש לבדוק את הכיסוי כדי לאתר פערים. תרשימים אלה מתארים את הפעילות שנשמרה. שולחים לא ידועים נשארים בקטגוריה נפרדת, ו כל בדיקה מדווחת בנפרד.

כאשר הוא כלול, הקובץ `analytics.json` מוגן על ידי חתימות ה-hash של הארכיון. הקובץ `report.json` משלב את אותו סיכום נבחר. אימות החתימה מזהה ביטים ששונו. כדי לבדוק את הנתונים, יש לחשב מחדש את הסיכומים של ה-journal באמצעות `report_analytics.Analytics` ו-`selected`, או את הסיכומים של ה-snapshot באמצעות `snapshot_analytics.collect` ו-`project`.

### אינדיקטורים לחריגות

**תצוגה מקדימה.**דוחות ראיות מוסיפים סעיף **אינדיקטורים לחריגות** המחושב על ידי מעבדים רשומים (`tgwitness/metrics/`, קובץ אחד לכל מדד). הדוח מציין את כל המעבדים שהפעילו את התוכנה עם גרסתם, ומציג את השיטה שלהם מתחת לטבלה, כך ש ניתן לחזור על החישוב מ-`events.jsonl` באמצעות `tgwitness.metrics.run`.

| מעבד | מה הוא מציג |
| --- | --- |
| `first_time_posters_over_time` גרסה 1 | מפרסמים חדשים והודעות ליום לפי UTC. דרישה לדגל כוללת לפחות חמישה מפרסמים חדשים ופי שלושה מהחציון שלהם, כאשר נפח ההודעות אינו עולה על פי 1.5 מהחציון. קו הבסיס משתמש בלפחות שבעה ימים שנצפו מתוך 14 הימים הקלנדריים הקודמים, לאחר שבעה ימי חימום. |
| `service_vs_message_ratio` גרסה 1 | יש להבחין בין מספרי ההודעות השמורות לכל צ'אט לבין החלק המשמש להודעות שירות. התיאור מתייחס לשיטת המספור; הוא אינו מסביר את הסיבה להיעדר מספר מסוים. |
| `join_leave_per_month` גרסה 1 | הצטרפויות, עזיבות והסרות או חסימות לפי חודש, אחת לכל אדם, צ'אט, שינוי ויום. |
| `pinned_per_month` גרסה 1 | הודעות שירות מוצמדות, הודעות על הסרת הצמדה, והודעות מוצמדות שנוספו או הוסרו בין תמונות מצב של הצ'אט, לפי חודש. |

**פרמטרים → מדדי דוח** בוחר מעבדים ואת מספר השורות המוצגות, כולל בדוחות מסוננים. טבלאות יומיות וחודשיות מציגות שורות אחרונות, טבלאות חלוקת שירות מדרגות צ'אטים לפי מספר ההודעות השמורות. הסכומים כוללים כל שורה.

מתוך גרסת המקור, צרו את כל שמונה העיצובים המפורטים לעיל מאותו כתב עת בדיוני:

```
python tools/build_report_styles.py --output test-results/report-styles
```

פתח את הקובץ `index.html` שהתקבל כדי להשוות בין דוחות HTML מלאים, קבצי PDF חתומים ו קבצי ZIP. כל עיצוב משתמש באותו יומן מקור. השתמש בספריית פלט חדשה עבור כל ריצה, כך שדוגמאות שנחתמו בעבר יישמרו.

![תיק HTML פיקטיבי](https://phishdestroy.github.io/TgWitness/assets/dossier-en.png)

קובץ ה-HTML נפתח בעמוד שער של התיק ובנתונים עיקריים. מפת הראיות הממוספרת מקשרת לכל ממצא, לעובדות התומכות בו, למגבלותיו ולבדיקה העצמאית. רשומות הניתנות לחיפוש והפניות לרשומות קבועות נותרות זמינות במציג הלא מקוון. העיצוב מותאם למסכים צרים, לערכות נושא ולדפדפנים ללא JavaScript.

קובץ ה-PDF החתום כולל עמוד שער ייעודי בגודל A4, הפניה לדוח וברקוד QR, תקציר מנהלים, מפת ראיות, ממצאים ממוספרים וסימניות למסמכים. כותרות העמוד והכותרות התחתונות מזהות את הדוח. ברקוד QR מזהה את החומר; הוא אינו תוצאת אימות עצמאית. הדפסות מדפדפן נפרדות מקובץ ה-PDF החתום קריפטוגרפית.

ציר הזמן של התצפיות מציב את תקופות התצפית שהוקלטו ואת ההפרעות על אותו ציר UTC. שטח ריק אינו מעיד על כיסוי; הטבלאות המפורטות שומרות על המרווחים המדויקים. קובץ ה-ZIP מכיל את הדוחות הניתנים לקריאה, קבצי JSON חתומים, רשומות מקור והוראות אימות.

יש ליצור תיק חדש ובדיוני באנגלית/רוסית/גרמנית עם סביבת הפיתוח המותקנת:

```
python tools/build_dossier_example.py --output test-results/my-new-dossier
```

כל ספריית שפה מכילה את הקבצים `report.html`, `report.pdf`, `report.json` ו- `dossier.zip`. ספריות הדוגמאות הקיימות לעולם אינן נמחקות. ליצירתן לא נעשה שימוש בחשבון Telegram, בשירות חותמת זמן חיצוני או בחיבור לרשת.

![שלושת העמודים הראשונים של קובץ ה-PDF הבדיוני החתום](https://phishdestroy.github.io/TgWitness/assets/dossier-pdf.png)

## קריאת מקרה ספציפי

עבור יומן המכיל 1,200 רשומות עם חותמת זמן מאומתת ברשומה ה-1,000, הדוח מזהה 200 רשומות מאוחרות יותר הנמצאות מחוץ לגבולות חותמת הזמן הזו. זהו גבול עליון לקיומו של נקודת ביקורת, ולא הוכחה לזמן השליחה של כל הודעה . אם שלושה קבצי חותמות זמן אחרים נכשלים באימות או שלא ניתן לאמתם, הם נספרים בנפרד ואינם יכולים לספק מסקנה חיובית.

חותמת זמן שמישה חייבת לעמוד בכל הבדיקות הבאות: החותמת שלה תואמת את נקודת הבדיקה, החתימה שלה מקושרת לשורש TSA מהימן בזמן החתימה, ו החתימה, המפתח, הספירה והראש של נקודת הבדיקה תואמים בדיוק לקידומת היומן. ניתוח פשוט של חותמת זמן או החזקת קבלה של OTS אינם מספיקים. הקורא חייב לבחור באופן עצמאי את שורש ה-TSA המהימן ולחזור על תהליך האימות. ל-OTS נדרשת בדיקת אישור ביטקוין משלו.

| סטטוס הדוח | משמעות |
| --- | --- |
| נבדק במהלך הייצוא | היצואן ביצע את הבדיקה המצוינת; עדיין נדרשת חזרה עצמאית על הבדיקה. |
| הוקלט; נדרשת בדיקה | התצפית הבסיסית או הצהרת המפעיל נרשמת; אין מדובר באישור עצמאי. |
| לא נכלל בטקסט זה | לטקסט אין כל תיעוד התומך בטענה זו. הוא אינו מציין כי אין תיעוד כזה במקומות אחרים. |
| לא נבדק באופן עצמאי | הדוח אינו מספק תוצאות אימות עצמאיות. |
| לא שלם או לא זמין | חומר או בדיקה נדרשת חסרים, אינם שלמים או לא הצליחו. |

יש לבדוק כל בדיקה בנפרד, לצד כיסוי האיסוף המתועד.

## מה חייבת לשמר תצורה חזקה

1. לפני שתסתמכו על האיסוף, שמרו את טביעת האצבע של מפתח האספן באמצעות ערוץ נפרד ואמין. השוו את ההתייחסות הזו למפתח החתימה של הייצוא.
2. יש לשמור על נקודות ביקורת עם חותמות זמן עצמאיות, ובמקרים שבהם נעשה בהן שימוש, על יומן עדים שנמצא מחוץ לשליטתו הניהולית של האספן. יש להשוותן מול היומן שיוצא כדי לבדוק את גבולותיו הקודמים.
3. יש לתעד את היקף איסוף הרשומות, הפערים, המסננים, המגבלות והשינויים באיסוף. יש להסביר את התקופות החסרות הרלוונטיות לתביעה בפועל, תוך הבחנה ברורה בין מזהי הודעות שלא נצפו, הודעות מחיקה ובדיקות חוזרות שלא צלחו.
4. יש לשמור על קבצי ה-ZIP המקוריים ועל חתימות ה-hash שלהם. יש לתעד כל מחזיק, העברה, תאריך ומטרה. יש לשמור יחד איתם את הצהרות המפעילים המיוחסות ואת הערות התיק.
5. במקרה של הודעות קוליות חסויות, יש לשמור ולאמת באופן עצמאי את הציטוט, האתגר, שרשרת האישורים של Intel, המדידות, המקור המדויק ותנאי הטיפול במפתחות. יש לשמור את תוצאת אימות האישור יחד עם הממצאים שנבדקו.

ראו [היקף האימות](https://phishdestroy.github.io/TgWitness/he/docs/reference/evidence/#verification-scope) לבדיקות הרכישה, שלמות הארכיון, הזמן והיקף האיסוף בכל מצב.

## בדיקה על ידי הנמען

יש להשתמש בהתקנה מהימנה של TgWitness ובטביעת אצבע שהושגה באופן עצמאי:

```
python -m tgwitness.verify evidence.zip --fingerprint TRUSTED_SHA256
python -m tgwitness.verify evidence.zip --fingerprint TRUSTED_SHA256 --tsa-ca tsa-root.pem
python -m tgwitness.verify evidence.zip --fingerprint TRUSTED_SHA256 --witness witness.zip --witness-fingerprint WITNESS_SHA256 --require-witness
python -m tgwitness.verify evidence.zip --fingerprint TRUSTED_SHA256 --check-drand
```

קובץ ה-ZIP של העד חייב להגיע ממקור מהימן ועצמאי; יש לשמור גם על המפתח והמקור שלו. יש לשמור על הפקודות, גרסת הכלי, התוצאות, ה-hash של הקלט שנבדק והשאלות שלא נפתרו. אימות ה-Beacon הוא בדיקה מקוונת נפרדת; תוכנת יצירת הדוחות לעולם אינה יוצרת קשר עם שירות כלשהו אך ורק לצורך הצגת דוח.

במקרה של מחלוקת בנוגע להודעה מסוימת, יש לצטט את הפניה לארכיון, את הפניה לקובץ ולתיעוד המוסמכים, ולאחר מכן לתאר את טווח הזמן הרלוונטי, פערי הכיסוי, הבחירה וחומר מאשש. עבור עותק לשיתוף, יש לבדוק גם את השינוי שנרשם ואת הפניותיו לארכיון המקור. מסננים פרטיים ומיפויי זהות אינם נכללים בהערכה הציבורית.

אימות קובץ ה-PDF החתום מזהה שינויים בבתים המכוסים. יש לשמור את הקובץ הדיגיטלי המקורי ואת תוצאת האימות לצד כל צילומי מסך או עותקי קריאה מודפסים.
