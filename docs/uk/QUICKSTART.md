# Швидкий старт TgWitness

TgWitness — це автономний додаток для спостереження за групами та каналами Telegram, до яких мають доступ ваші акаунти. Він працює локально з власним каталогом даних.

**Вперше на сайті?** [Ознайомтеся з демо-версією,](#ознайомтеся-з-інтерфейсом) перш ніж підключити обліковий запис. [Оберіть посібник](../README.md) щодо проксі-серверів, свідків, експорту даних або налаштування сервера.

## Встановити та запустити

Оберіть один із способів. Портативні версії для завантаження стають доступними після публікації релізної збірки:

| Хостинг | Нічого не встановлено | З вихідного коду: Python 3.11+ | Docker: Engine/Desktop із Compose 2.20+ |
| --- | --- | --- | --- |
| Windows | Витягніть `TgWitness-<version>-windows-amd64-portable.zip` з GitHub Releases, двічі клацніть `TgWitness.cmd` | Двічі клацніть на `Start.cmd` | Двічі клацніть на `Docker.cmd` |
| Linux / macOS | — | `sh start.sh` | `sh docker-start.sh` |

Щоб отримати вихідний код, завантажте та розпакуйте ZIP-архів із GitHub Releases або клонуйте репозиторій. `Start.cmd` пропонує встановити Python 3.12 для вашого користувача Windows, якщо не знайдено відповідної версії Python (winget або підписаний інсталятор з python.org). `start.sh` виводить точну команду встановлення для вашого дистрибутива Linux або macOS, якщо Python відсутній. При першому запуску вихідного коду створюється файл `.venv`, а залежності встановлюються автоматично.

Docker компілює додаток і запускає його у фоновому режимі; Python на хості не потрібен. `Docker.cmd` та `docker-start.sh` виводять адресу панелі та токен, коли контейнер працює нормально. Відповідні команди Docker для кожного підтримуваного хоста:

```sh
docker compose up -d --build --wait
docker compose exec tgwitness cat /data/panel-token.txt
```

Відкрийте файл **http://127.0.0.1:8787**. Використовуйте токен, виведений допоміжною програмою Docker або другою командою Docker, або прочитайте **файл** **data/live/panel-token.txt** для портативної або вихідної інсталяції. Продовжуйте з розділу **«Підключення Telegram»** нижче. Нативні та Docker-інсталяції використовують окремі сховища; запуск Docker не імпортує існуючий нативний журнал.

Для сервера [розгортання](DEPLOYMENT.md) охоплює автоматичне налаштування HTTPS, перезапуск, опубліковані зображення, оновлення та резервне копіювання.

## Ознайомтеся з інтерфейсом

1. Запустіть **файл TgWitness-Demo.cmd** у портативному пакеті, **Demo.cmd** у папці з вихідним кодом для Windows або `sh start.sh --demo` у Linux/macOS. Запуск з вихідного коду спочатку створює файл `.venv` та встановлює залежності.
2. Відкрити **http://127.0.0.1:8787**.
3. Локальна демо-версія автоматично відкриває зразок журналу. Для прямого локального доступу копіювання токена не потрібно.

Демонстраційні повідомлення є вигаданими. У демонстраційному режимі неможливо підключити реальний акаунт Telegram.

## Підключити Telegram

> [!WARNING]
> **Не використовуйте те, що не можете собі дозволити втратити.** Ми настійно не рекомендуємо підключати особисті або цінні акаунти, а також створювати API-ідентифікатор / хеш на акаунті, який для вас важливий. Telegram блокує акаунти непередбачувано і часто назавжди, незалежно від клієнта. Безперебійне тестування залежить від Telegram, а не від TgWitness, і не гарантує нічого на майбутнє.

1. Якщо працює вбудована демо-версія, зупиніть її та запустіть **Start.cmd** або `sh start.sh`. В іншому випадку залиште запущеною інсталяцію, яку було запущено вище.
2. Використовуйте токен панелі, що відповідає вашому способу встановлення, щоб відкрити панель.
3. Якщо вам потрібен проксі-сервер, збережіть його в меню **«Акаунт» → «Налаштування» → «Налаштування з’єднання» → «Змінити маршрут з’єднання**».
4. У розділі **«Акаунт**» введіть свій номер телефону та натисніть **«Продовжити**», виберіть **«QR-код» → «Показати QR-код**» або виберіть файли та натисніть **«Підключити акаунт**». **API ID + Hash** є необов’язковими: робоча область використовує збережену або імпортовану пару, або робочу пару з вбудованого пулу. Щоб використовувати власний додаток, вставте одну пару `API ID:API Hash` у поле «Ідентифікатор API». Для отримання повного ключа авторизації виберіть **«Ключ авторизації»**, вставте всі 512 шістнадцяткових символів та виберіть наданий DC ID. Ідентифікатор користувача є необов’язковим і перевіряється, якщо його введено.
5. Завершіть обраний спосіб входу: за номером телефону/кодом/2FA, підтвердженням із запущеного додатка Telegram для QR-коду або імпортом підтримуваної авторизованої сесії.
6. Перевірте відображений ідентифікатор облікового запису. Відкриті **джерела**: ваші чати завантажуються автоматично; додайте свої групи.
7. У розділі **«Виберіть**, **які зміни зберегти»** виберіть категорії подій або пресет **«Повідомлення, редагування та видалення**», а потім збережіть налаштування моніторингу.
8. Окремо виберіть налаштування вкладень, а потім натисніть **«Почати спостереження**».

Повноваження API ідентифікують ваш додаток; самі по собі вони не надають доступу до облікового запису. Приватні групи не потребують публічного імені користувача, але ваш обліковий запис повинен мати доступ.

Для існуючих облікових записів див. [формати облікових записів та сесій](../ACCOUNTS.md): панель підтримує Telethon StringSession, Telethon/Pyrogram SQLite, TData ZIP для одного облікового запису та JSON-файли підтримуваних облікових записів. Оберіть сесію та відповідний JSON-файл, натисніть **«Підключити обліковий запис**». Також доступний вхід за допомогою QR-коду з тими самими опціональними налаштуваннями API. TDLib, боти та масові списки облікових записів не підтримуються.

Щоб додати ще один обліковий запис, натисніть **«+»** поруч із переліком облікових записів або відкрийте **«Обліковий запис» → «Налаштування» → «Налаштування з’єднання» → «Робочі простори»**, або скористайтеся меню **«Облікові записи**». Робочі простори мають окремі сесії, журнали, ключі, джерела та черги. Перемикання між робочими просторами не зупиняє роботу інших колекторів. Один і той самий обліковий запис Telegram не можна прив’язати до двох робочих просторів у цій інсталяції. Кількість робочих просторів не обмежена; вони використовують один процес, тому їхня продуктивність залежить від потужності комп’ютера.

Токен панелі в режимі реального часу захищає доступ до ваших авторизацій у Telegram та збережених матеріалів; він не пов’язаний з обліковими даними API Telegram. Автоматичний доступ отримує лише явно запущена локальна демо-версія, до якої здійснюється прямий доступ. Віддалена або проксі-демо-версія все ще використовує `data/demo/panel-token.txt`.

## Перегляд та експорт

- **Журнал:** пошук та фільтрація спостережень за джерелом та типом події.
- Виберіть подію, щоб переглянути її оригінальний запис, атрибуцію та збережені версії.
- У деталях редагування відображається доступний вміст «до» та «після». У деталях видалення відображається останній зафіксований вміст, якщо такий є; невідомий учасник залишається невідомим.
- **Формати експорту:** підписаний ZIP, JSONL, CSV та офлайн-HTML.
- **Експорт повного чату** (Джерела → Експорт повного чату): завантажте всю видиму історію одного чату у вигляді підписаного пакету з `chat.json` (у стилі Telegram-export) та читабельного `chat.html`. Приватні чати працюють, якщо обліковий запис є учасником. Це поточний знімок, а не реконструкція видалених або раніше відредагованих повідомлень. Перевірте копію за допомогою `python verify.py chat-export.zip --fingerprint TRUSTED_SHA256`.
- **Збереження контрольної точки:** зберігайте межі підписаного журналу поза межами колектора.
- **Завантажити підписаний квитанцію про запуск:** зберегти запис про програму/версію колектора.
- **Підготовка запиту на отримання часової мітки:** підготуйте офлайн-запит до центру видачі часових міток; дотримуйтесь інструкцій у файлі [TIMESTAMP.md](../TIMESTAMP.md) для отримання та перевірки відповіді.
- **Перевірка журналу:** перевірка сигнатур подій та ланцюжків. Експорт у форматі ZIP також перевіряє медіафайли.

Підтримувані браузери зберігають великі експортні файли безпосередньо у вибраний файл. Інші браузери буферизують не більше 128 MiB. Поки сервер працює, CLI для потокової передачі даних підтримує завантаження більших обсягів без буферизації всього відповіді:

```sh
python -m tgwitness.download --token-file data/live/panel-token.txt --out evidence.zip
```

Для іншого робочого простору додайте `--profile ID`, скориставшись **меню** **«Експорт» → «Ідентифікатор робочого простору**». Для віддаленого сервера додайте `--url https://your-server`. За замовчуванням обмеження на передачу даних становить 5 ГіБ; `--max-mib` дозволяє його змінити. Підписаний вміст ZIP-архіву за замовчуванням має окремий ліміт перевірки в розмірі 4 ГіБ у розпакованому вигляді (**параметри** дозволяють його збільшити; перевіряйте такі архіви за допомогою `verify.py --max-gib N`). Перевіряйте архів за допомогою надійної копії верифікатора та незалежно збереженого відбитка ключа/контрольної точки.

## Перевірте установку

```sh
python start.py --setup-only
python start.py --check
python start.py --check --json
```

`--check` перевіряє наявність локальних залежностей, підтримку підпису, місце зберігання, конфігурацію ключів та адресу прослуховування. Він нічого не встановлює та не підключається до Telegram. Зайнятий порт може означати, що працює інший екземпляр. Використовуйте інший `--port` або спочатку зупиніть його.

Програма запуску встановлюється в `.venv`. Допоміжні команди `python -m tgwitness...` повинні використовувати `.venv\Scripts\python.exe` у Windows або `.venv/bin/python` у Linux/macOS, якщо це середовище ще не активовано.

## Сесії, захист та експлуатація

Закриту, узгоджену базу даних Telethon у форматі SQLite `.session` можна локально конвертувати за допомогою `python -m tgwitness.sessions account.session --out account.tgwitness-session`, а потім завантажити в Account. Також доступні прямий імпорт файлів та вхід за допомогою QR-коду. Формати входу, SOCKS5, HTTP CONNECT, MTProxy та зовнішні головні ключі див. у [файлі CONNECTION-SECURITY.md](../CONNECTION-SECURITY.md).

**Призупинення спостереження** зупиняє збір даних. **Блокування** лише закриває доступ через браузер. Закриття вкладки не зупиняє процес збору даних. Зупинка процесу перериває збір даних; знімок історії не дозволяє відтворити всі пропущені редагування чи видалення. Дізнайтеся, [як працює збір даних](../COLLECTION.md) щодо політик подій, черг вкладень, ізоляції облікових записів та поведінки при перезапуску.

Сесії та секретні дані шифруються. Для зберігання вмісту повідомлень, мультимедіа та експортованих даних необхідний зашифрований диск або том. Підписи підтверджують цілісність відносно довіреного ключа; вони не підтверджують походження з Telegram і не запобігають фальсифікації з боку оператора, який контролює колектор та його ключ.

Прочитайте [файл OPERATIONS.md](../OPERATIONS.md) щодо резервного копіювання та відновлення, [файл DEPLOYMENT.md](DEPLOYMENT.md) щодо хостингу, а також [папку deploy/](../../deploy/README.md) для прикладів використання сервісу. Встановлена панель також містить посібник з налаштування в автономному режимі за адресою `/guide.html`.

Фактичні результати верифікації та існуючі обмеження зафіксовані у [файлах VERIFICATION.md](../VERIFICATION.md) та [READINESS.md](../internal/READINESS.md).
