# Краткое руководство по TgWitness

TgWitness — это автономное приложение для наблюдения за группами и каналами Telegram, к которым имеют доступ ваши аккаунты. Оно работает локально с собственным каталогом данных.

**Впервые на сайте?** [Ознакомьтесь с демо-версией,](#explore-the-interface) прежде чем подключать аккаунт. [Выберите руководство](../README.md) по прокси, свидетелям, экспорту или настройке сервера. [Запуск GitHub Actions capture](SEALED-ACTIONS.md) (предварительный просмотр) выполняет сбор данных в вашем собственном форке GitHub вместо локальной установки.

<a id="install-and-start"></a>
## Установка и запуск

Установщик с пошаговыми инструкциями включает собственную версию Python и перед установкой проверяет хеши пакетов и подписи релизов. Повторный запуск обновляет существующую установку.

**Linux / macOS:**

```sh
curl -fsSL https://get.destroy.tools/install.sh | bash
```

**Windows (PowerShell или командная строка):**

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -Command "irm https://get.destroy.tools/install.ps1 | iex"
```

На сервере Ubuntu запустите программу с правами root для установки фоновой службы; на настольном компьютере — с правами обычного пользователя. В Ubuntu программа установки выводит адрес панели и ключ доступа; в macOS и Windows локальная панель открывается в вашем браузере. Продолжите на этапе **Подключить Telegram** ниже. Раздел [Установка, проверка и обновление](INSTALLATION.md) охватывает варианты доступа к серверу, проверку скрипта перед запуском, обновления и удаление.

<a id="other-methods"></a>
### Другие методы

Релизы на GitHub, исходный код и Docker являются альтернативами установщику. Портативные версии становятся доступны после публикации релизной сборки:

| Хост | Ничего не установлено | Из исходного кода: Python 3.11+ | Docker: Engine/Desktop с Compose 2.20+ |
| --- | --- | --- | --- |
| Windows | Распакуйте файл `TgWitness-<version>-windows-amd64-portable.zip` из релизов GitHub, дважды щелкните файл `TgWitness.cmd` | Дважды щелкните файл `Start.cmd` | Дважды щелкните файл `scripts\Docker.cmd` |
| Linux / macOS | — | `sh start.sh` | `sh scripts/docker-start.sh` |

Для использования исходного кода [загрузите и распакуйте текущую версию `main`](https://github.com/phishdestroy/TgWitness/archive/refs/heads/main.zip) или клонируйте репозиторий:

```sh
git clone https://github.com/phishdestroy/TgWitness.git
cd TgWitness
```

Файл `Start.cmd` предложит установить Python 3.12 для вашего пользователя Windows, если подходящая версия Python не найдена (winget или подписанный установщик с сайта python.org). Файл `start.sh` выводит точную команду установки для вашего дистрибутива Linux или macOS, если Python отсутствует. При первом запуске исходного кода автоматически создаётся файл `.venv` и устанавливаются зависимости.

Docker собирает приложение и запускает его в фоновом режиме; Python на хосте не требуется. Файлы `scripts\Docker.cmd` и `scripts/docker-start.sh` выводят адрес панели и токен, когда контейнер работает исправно. Эквивалентные команды Docker для всех поддерживаемых хостов:

```sh
docker compose up -d --build --wait
docker compose exec tgwitness cat /data/panel-token.txt
```

Откройте страницу **http://127.0.0.1:8787**. Используйте токен, выведенный утилитой Docker или второй командой Docker, либо прочитайте **файл data/live/panel-token.txt** для переносимой или исходной установки. Продолжите с раздела **Подключение к Telegram** ниже. Нативные и Docker-установки используют отдельные хранилища; запуск Docker не импортирует существующий нативный журнал.

Для сервера [развёртывание](DEPLOYMENT.md) включает автоматическую настройку HTTPS, перезапуск, публикацию образов, обновления и резервное копирование.

<a id="explore-the-interface"></a>
## Ознакомьтесь с интерфейсом

1. Запустите **файл TgWitness-Demo.cmd** в портативном пакете, **скрипт scripts\Demo.cmd** в папке с исходным кодом для Windows или команду `sh start.sh --demo` в Linux/macOS. При запуске из исходного кода сначала создаётся файл `.venv` и устанавливаются зависимости.
2. Откройте файл **http://127.0.0.1:8787**.
3. Локальная демо-версия автоматически открывает пример журнала. Для прямого локального доступа не требуется копирование токена.

Сообщения в демо-версии являются вымышленными. В демонстрационном режиме невозможно подключить реальный аккаунт Telegram.

<a id="connect-telegram"></a>
## Подключение к Telegram

> [!ПРЕДУПРЕЖДЕНИЕ] **Используйте специальные аккаунты.** Telegram может ограничить доступ или навсегда заблокировать аккаунты за объем запросов, который он считает чрезмерным, независимо от клиента. Подключайте аккаунты, предназначенные для наблюдения, а не личные или ценные, и создайте API-ID / хеш на специальном аккаунте.

1. Если запущена нативная демо-версия, остановите её и запустите **Start.cmd** или `sh start.sh`. В противном случае оставьте запущенной рабочую установку, запущенную выше.
2. Войдите в систему с помощью токена панели. [При первоначальной настройке](SETTINGS.md) откроется новая рабочая область. Выберите **Просто скачать**, **Подписаться на чаты** или **Доказательства по делу**.
3. Проверьте состояние подключения. При необходимости настройте собственный прокси; настройки подключения останутся доступными после завершения настройки.
4. В разделе **Подключить Telegram** выберите номер телефона, QR-код, файлы аккаунта (TData, `.session`, StringSession, JSON-файл аккаунта) или полный ключ авторизации. При появлении запроса пройдите подтверждение в Telegram, введите код и облачный пароль двухэтапной аутентификации.
5. Проверьте отображаемый аккаунт, выберите чаты и проверьте настройки. Завершите процесс на заключительном экране. При выборе варианта **Только скачать** **кнопка Начать экспорт** запускает однократный экспорт и открывает раздел «Экспорты» для отображения его хода; это не включает непрерывное наблюдение.

После настройки в **разделе Чаты → Выбрать** можно изменить выбранные чаты. **В разделе Настройки** управляются сбор данных и файлы; в разделе **Дополнительные инструменты → Источники** представлен подробный список источников на стандартном или экспертном уровне. В [руководстве по панели](PANEL.md) описаны шесть основных разделов и их контекстные элементы управления.

**Пара API ID:API Hash** является необязательной: рабочая область использует сохранённую или импортированную пару, либо рабочую пару из встроенного пула. Чтобы использовать собственное приложение, вставьте одну пару `API ID:API Hash` в поле «API ID». В поле **Auth key** вставьте все 512 шестнадцатеричных символов и выберите предоставленный DC ID. Поле «User ID» является необязательным и проверяется при вводе.

Учетные данные API идентифицируют ваше приложение; сами по себе они не обеспечивают авторизацию аккаунта. Для закрытых групп не требуется публичное имя пользователя, однако ваш аккаунт должен иметь соответствующий доступ.

Для существующих аккаунтов ознакомьтесь с [форматами аккаунтов и сеансов](ACCOUNTS.md): панель поддерживает Telethon StringSession, Telethon/Pyrogram SQLite, TData ZIP для одного аккаунта и поддерживаемый формат JSON для аккаунтов. Выберите сеанс и сопутствующий ему файл JSON одновременно, нажмите **Проверить файлы**, а затем **Подключить аккаунт**. Также доступен вход с помощью QR-кода с теми же опциональными настройками API. TDLib, сеансы ботов и списки аккаунтов в формате CSV/JSON не поддерживаются.

Для нескольких аккаунтов воспользуйтесь меню **Аккаунты → Импорт аккаунтов** и выберите поддерживаемые файлы сеансов. Сопутствующие файлы JSON сопоставляются по базовому имени; каждый импортированный аккаунт получает собственную рабочую область. См. раздел [Массовый импорт и Группы аккаунтов](ACCOUNTS.md#bulk-import-and-account-groups).

Чтобы добавить ещё один аккаунт, нажмите **значок +** рядом с выбором аккаунта или воспользуйтесь **меню Аккаунты → Добавить аккаунт**. Рабочие области имеют отдельные сеансы, журналы, ключи, источники и очереди. При переключении между видами остальные сборщики продолжают работать. Одну и ту же систему Telegram нельзя назначить двум рабочим областям в данной установке. Фиксированного количества рабочих областей нет; они используют один процесс, поэтому их пропускная способность зависит от мощности компьютера.

Токен панели в режиме реального времени защищает доступ к вашим авторизациям в Telegram и сохраненным материалам; он не связан с учетными данными API Telegram. Автоматический доступ получает только явно запущенная локальная демо-версия, к которой осуществляется прямой доступ. Удаленная или прокси-версия демо-версии по-прежнему использует файл `data/demo/panel-token.txt`.

<a id="review-and-export"></a>
## Просмотр и экспорт

- **Журнал:** поиск и фильтрация наблюдений по источнику и типу события.
- Выберите событие, чтобы просмотреть его исходную запись, информацию об источнике и сохраненные версии.
- В деталях редактирования отображается доступное содержимое «до» и «после». В деталях удаления отображается последнее зафиксированное содержимое, если таковое имеется; неизвестный субъект остаётся неизвестным.
- **Экспорт:** подписанный ZIP, JSONL, CSV и автономный HTML.
- **Экспорт всего чата** (**Чаты → Экспорт чата** или **Экспорт → Захват или экспорт одного чата**): загрузите всю видимую историю одного чата в виде подписанного пакета с файлом `chat.json` (в стиле экспорта Telegram) и читаемым файлом `chat.html`. Личные чаты доступны, если аккаунт является участником чата. Это текущий снимок, а не реконструкция удалённых или ранее отредактированных сообщений. Проверьте копию с помощью команды ``python verify.py chat-export.zip --fingerprint TRUSTED_SHA256``.
- **Сохраните контрольную точку:** сохраните границу подписанного журнала за пределами сборщика.
- **Загрузите подписанную квитанцию запуска:** сохраните запись о программе и версии сборщика.
- **Подготовьте запрос на временную метку:** подготовьте автономный запрос к центру выдачи временных меток; следуйте инструкциям в файле [TIMESTAMP.md](TIMESTAMP.md) для получения и проверки ответа.
- **Проверьте журнал:** проверьте подписи событий и звенья цепочки. При экспорте в формате ZIP также проверяются медиафайлы.

Поддерживаемые браузеры сохраняют объёмные экспорты непосредственно в выбранный файл. Другие браузеры буферизуют не более 128 MiB. Пока сервер работает, интерфейс командной строки для потоковой передачи поддерживает загрузку больших объёмов данных без буферизации всего ответа:

```sh
python -m tgwitness.download --token-file data/live/panel-token.txt --out evidence.zip
```

Для другой рабочей области добавьте параметр ``--profile ID``, используя **меню Экспорт → Идентификатор рабочей области**. Для удалённого сервера добавьте параметр ``--url https://your-server``. По умолчанию ограничение на передачу данных составляет 5 ГиБ; его можно изменить с помощью параметра ``--max-mib``. Для подписанного содержимого ZIP по умолчанию установлен отдельный лимит проверки в размере 4 ГиБ в несжатом виде (его можно увеличить в разделе **Дополнительные инструменты → Параметры**; проверку таких архивов выполняйте с помощью команды `verify.py --max-gib N`). Проверьте архив с помощью доверенной копии верификатора, независимо сохраненного отпечатка ключа и, как минимум для обеспечения доказательности, корневого сертификата органа, выдающего отметки времени (`--tsa-ca`).

<a id="check-the-installation"></a>
## Проверьте установку

```sh
python start.py --setup-only
python start.py --check
python start.py --check --json
```

Команда `--check` проверяет локальные зависимости, поддержку подписи, хранилище, настройки ключей и адрес прослушивания. Она ничего не устанавливает и не подключается к Telegram. Занятый порт может означать, что работает другой экземпляр. Используйте другой порт с параметром `--port` или сначала остановите его.

Программа запуска устанавливается в папку `.venv`. Вспомогательные команды `python -m tgwitness...` должны использовать `.venv\Scripts\python.exe` в Windows или `.venv/bin/python` в Linux/macOS, если данная среда ещё не активирована.

<a id="sessions-protection-and-operation"></a>
## Сеансы, защита и работа

Закрытый, согласованный файл Telethon SQLite `.session` можно преобразовать локально с помощью команды `python -m tgwitness.sessions account.session --out account.tgwitness-session`, а затем загрузить в разделе **Дополнительные инструменты → Аккаунт → Файлы**. Также доступны прямой импорт файла и вход с помощью QR-кода. См. [файл CONNECTION-SECURITY.md](CONNECTION-SECURITY.md) для ознакомления с форматами входа, SOCKS5, HTTP CONNECT, MTProxy и внешними мастер-ключами.

**Приостановка наблюдения** останавливает сбор данных. **Блокировка** закрывает только доступ через браузер. Закрытие вкладки не прекращает работу сборщика данных. Остановка процесса прерывает сбор; моментальный снимок истории не позволяет восстановить все пропущенные изменения или удаления. Ознакомьтесь [с принципами работы сборщика данных](COLLECTION.md) в отношении политик событий, очередей вложений, изоляции аккаунтов и поведения при перезапуске.

Сеансы и секретные данные зашифрованы. Для хранения содержимого сообщений, медиафайлов и экспортированных данных требуется зашифрованный диск или том. Проверяйте подписи журналов по доверенному ключу и храните контрольные точки отдельно. Ознакомьтесь с записями о сборе данных, внешними квитанциями времени и аттестациями среды для выбранного режима сбора.

Ознакомьтесь с [файлом OPERATIONS.md](OPERATIONS.md) для резервного копирования и восстановления, с [файлом DEPLOYMENT.md](DEPLOYMENT.md) для размещения на хостинге, а также с [каталогом deploy/](../../deploy/README.md) для примеров использования сервиса. Установленная панель управления также содержит руководство по автономной настройке по адресу `/guide.html`.

Результаты фактической проверки и оставшиеся ограничения зафиксированы в [файлах VERIFICATION.md](VERIFICATION.md) и [READINESS.md](../internal/READINESS.md).
