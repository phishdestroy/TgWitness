# Налаштування бота-свідка

Canonical page: https://phishdestroy.github.io/TgWitness/uk/docs/witness/

Окремий процес перевіряє ваш журнал і публікує підписані контрольні точки в канал.

## Два хости, два ключі підпису

ХОСТИНГ / КОЛЕКТОР**Акаунт + журнал**

Ключ підпису колектора сеансів Telegram

Кінцева точка контрольної точки, доступна лише для читання

← запит на підписану відповідь →

HOST B / WITNESS**Перевіряти + зберігати**

Зафіксований відбиток колектора; окремий ключ підпису свідка

Власний журнал + токен бота

Witness → API бота Telegram →**Ваш канал · підписані публікації TGW1**

Witness самостійно здійснює перевірки. Доступ колектора обмежений лише читанням. Публікація через бота використовує з’єднання та токен Witness; сесія облікового запису не надається Witness.

03 / РІШЕННЯ ЩОДО КОНТРОЛЬНИХ ПУНКТІВПриклади відповідей

ОСТАННЄ ПРИЙНЯТЕ**120 записів**`head 9c7d…`

НАСТУПНА ВІДПОВІДЬ**128 записів**`head a4f2…`

Прийнято: кількість зростає, підпис перевірено, а ключ збігається. Свідок зберігає цю нову межу.

Усі приклади відповідей базуються на припущенні про наявність дійсного підпису та закріпленого ключа. Хеші тут наведено у скороченому вигляді. Сам по собі більший лічильник не може довести, що весь старий префікс залишився незмінним; порівняйте експорт із збереженими контрольними точками.

## Підготуйте бота та канал

Створіть бота через BotFather і дозвольте йому писати у ваш канал. Запускайте свідка деінде: інший хост, в ідеалі під керуванням іншої людини, вартує значно більше, ніж другий процес поруч зі збирачем.

## Три кроки в розділі «Додаткові функції»

1. **Доступ лише для читання.** **Доповнення → Незалежний свідок**, створіть токен і збережіть файл. Він читає контрольні точки й стан, більше нічого.
2. **Канал та інтервал.** Канал Telegram або вебхук Discord, плюс адреса збирача, доступна свідку. Збережіть файл налаштувань.
3. **Запуск.** Покладіть `witness.json`, `witness-token.txt` і `bot-token.txt` разом на хост свідка й виконайте:

```
python -m tgwitness.witness run --config witness.json --check-config
python -m tgwitness.witness run --config witness.json
```

Дочекайтеся першого підписаного поста в каналі, потім збережіть відбиток свідка в надійному місці.

Натомість Discord? Збережіть URL вебхука як `discord-webhook.txt`. Один свідок публікує в одне місце; довгі перевірки приходять у Discord файлом.

## Виберіть, як часто публікувати

Публікація кожної перевірки дає регулярний зовнішній запис: кожні п'ять хвилин — це близько 288 постів на день на простір. У розширених налаштуваннях можна публікувати лише за змін чи проблем, використовувати проксі або власний Bot API.

**Що саме підтверджує цей бот?**

Він запитує в збирача підписану контрольну точку, перевіряє її за очікуваним ключем і веде власний підписаний журнал, зокрема пропущені й відхилені відповіді.

Він перевіряє стан журналу, а не стежить за Telegram сам. Для цього проведіть контрольний тест доставки.

## Перегляньте докази пізніше

Зберігайте журнал свідка, пости й відбитки. [Як звірити їх](https://phishdestroy.github.io/TgWitness/uk/docs/reference/witness/#verify) з експортом збирача.
