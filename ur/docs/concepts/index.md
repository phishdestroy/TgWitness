## ریکارڈ تبدیل کریں۔ ہیش کی پیروی کریں۔

ہر ریکارڈ میں پچھلے ریکارڈ کا ہیش ہوتا ہے۔ کہیں اور رکھا چیک پوائنٹ جرنل کی لمبائی اور آخری ہیش کو مقرر کرتا ہے۔

02 / ہیش چین سینڈباکساصلی SHA-256 · نمونہ ریکارڈز

ریکارڈ 01**پیغام موصول ہوا**`h₁ = SHA-256(e₁)`64 صفر کے روابط

ریکارڈ 02**11:00 بجے ملاقات کریں**`h₂ = SHA-256(e₂)`h₁ شامل ہے

ریکارڈ 03**مٹانے کا مشاہدہ ہوا**`h₃ = SHA-256(e₃)`h₂ شامل ہے۔

کہیں اور محفوظ شدہ**3 ریکارڈز · ہیڈ `h₃`**اس مقررہ حد کا موازنہ فراہم کردہ جرنل سے کریں۔

ایک واقعے میں تبدیلی کرنے سے اس کا ہیش بدل جاتا ہے۔ چین کو دوبارہ تعمیر کرنے سے اس کا سرب بدل جاتا ہے۔ دم کو ہٹانے سے یہ محفوظ شدہ چیک پوائنٹ سے چھوٹا ہو جاتا ہے۔

## اصلی قواعد، چند سطروں میں

ہیش + دستخط

h0 = 064
hi = hex(SHA-256(C(ei)))
σi = Ed25519.Sign(sk, unhex(hi))

**C** نو ایونٹ فیلڈز UTF-8 JSON کے طور پر ہیں: ترتیب شدہ کلیدیں، کوئی اضافی خالی جگہ نہیں، کوئی ASCII escaping نہیں، کوئی NaN/لامتناہی نہیں۔ `previous_hash` hi−1 ہے، h0 64 صفر ہے، دستخط ڈائجسٹ کے 32 خام بائٹس کا احاطہ کرتے ہیں۔

فیلڈز: `seq`، `observed_at`، `source_at`، `kind`، `chat_id`، `message_id`، `actor_id`، `payload`، `previous_hash`۔ مکمل تفصیل: [ایونٹ انکوڈنگ](https://phishdestroy.github.io/TgWitness/ur/docs/reference/evidence/#event-canonicalization)۔

محفوظ شدہ چیک پوائنٹ

Nexport ≥ Ncheckpoint
hexport[Ncheckpoint] = Hcheckpoint

چیک پوائنٹ کا دستخط پن شدہ کلید سے جانچیں، پھر جرنل سے موازنہ کریں۔ بعد کا ایکسپورٹ لمبا ہو سکتا ہے، لیکن چیک پوائنٹ پر میل کھانا چاہیے۔
