केवल-पठनीय MCP

MCP क्लाइंट को चयनित वर्कस्पेस और चैट्स से समाप्त होने वाली, रद्द की जा सकने वाली पहुँच के साथ कनेक्ट करें।

वर्तमान मुख्य: स्रोत चेकआउट का उपयोग करें; 0.7.0 पोर्टेबल पूर्वावलोकन इस सुविधा से पहले का है।

कार्यप्रवाह मार्गदर्शिका · विकी

TgWitness प्रोजेक्ट निर्देशिका से वैकल्पिक सर्वर इंस्टॉल करें:

python -m pip install '.[mcp]'

पैनल में, इंटीग्रेशन → MCP खोलें। कनेक्शन का नाम दें, इसके वर्कस्पेस और चैट चुनें, और समाप्ति चुनें। आर्काइव टोकन एक बार कॉपी करें; इसे बाद में पुनः प्राप्त नहीं किया जा सकता। खोए हुए टोकन रद्द करें और प्रतिस्थापन जारी करें। पैनल टोकन और टेलीग्राम क्रेडेंशियल MCP क्रेडेंशियल नहीं हैं।

एक क्लाइंट कनेक्ट करें#

पैनल अपनी प्रलेखित कॉन्फ़िगरेशन का उपयोग करके VS Code लोकल हार्नेस के लिए .vscode/mcp.json उत्पन्न करता है। डाउनलोड की गई फ़ाइल को उसी स्थान पर सहेजें, MCP: List Servers चलाएँ, और TgWitness शुरू करें। VS Code पासवर्ड इनपुट के माध्यम से टोकन के लिए संकेत देता है। डाउनलोड किए गए JSON में टोकन नहीं, बल्कि एक प्रॉम्प्ट संदर्भ होता है। MCP एक्स्ट्रा जिस वातावरण में इंस्टॉल है, उसी से पाइथन एक्ज़ीक्यूटेबल का उपयोग करें।

अन्य stdio क्लाइंट्स के लिए, चलाएँ:

python -m tgwitness.mcp_server --api-url http://127.0.0.1:8787

क्लाइंट के सुरक्षित वातावरण में TGWITNESS_ARCHIVE_TOKEN सेट करें। इसे कमांड आर्गुमेंट्स या URLs में न डालें। ब्रिज पैनल के अधिकृत आर्काइव API के माध्यम से पढ़ता है; इसकी सीधी डेटाबेस एक्सेस नहीं है। Stdout केवल MCP संदेशों को ले जाता है।

दूरस्थ क्लाइंट्स के लिए, पैनल के बगल में सेवा चलाएँ:

python -m tgwitness.mcp_server --transport streamable-http \
  --api-url http://127.0.0.1:8787 --port 8766 \
  --public-url https://archive.example.org/mcp

/mcp को एक HTTPS रिवर्स प्रॉक्सी के माध्यम से 127.0.0.1:8766/mcp पर फॉरवर्ड करें, Authorization: Bearer … हेडर को संरक्षित करते हुए। ऑथराइज़ेशन हेडर और रिक्वेस्ट/रिस्पॉन्स बॉडीज़ के लॉगिंग को अक्षम करें। केवल आवश्यकता पड़ने पर --host और --public-url का उपयोग करके लूपबैक से परे बाइंड करें। यह एंडपॉइंट आधिकारिक MCP पाइथन SDK से Streamable HTTP का उपयोग करता है। यह स्पष्ट रूप से कॉन्फ़िगर किए गए बेयरर क्रेडेंशियल्स का समर्थन करता है, न कि OAuth डिस्कवरी का; केवल OAuth की आवश्यकता वाले क्लाइंट्स समर्थित नहीं हैं।

चेक प्रोटोकॉल और एक्सेस प्रारंभिक सेटअप एक वास्तविक MCP क्लाइंट को इनिशियलाइज़ करता है और टूल्स की सूची दिखाता है। यह संदेश प्राप्त नहीं करता है। रिमोट चेक के लिए, चयनित MCP सर्वर को आर्काइव टोकन प्राप्त होता है। केवल उसी सर्वर को कॉन्फ़िगर करें जिसे आप संचालित करते हैं या उस दायरे में भरोसा करते हैं।

दायरा और परिणाम#

उपलब्ध उपकरण: list_workspaces, list_chats, search_messages, get_message_versions, get_message_context, get_journal_event, और get_capture_status। कोई टेलीग्राम एक्शन, कॉन्फ़िगरेशन परिवर्तन, या बल्क-एक्सपोर्ट उपकरण नहीं हैं। हर पढ़ने पर वर्कस्पेस/चैट एक्सेस की दोबारा जाँच की जाती है; समाप्त और रद्द किए गए क्रेडेंशियल काम करना बंद कर देते हैं। सीमाएँ हैं प्रति मिनट प्रति क्रेडेंशियल 60 API अनुरोध, प्रति पृष्ठ 50 रिकॉर्ड, एक 64 KiB प्रतिक्रिया, और आठ-सेकंड की API समय-सीमा।

संदेश परिणामों में वर्कस्पेस, चैट/संदेश आईडी, घटना अनुक्रम, सहेजा गया हैश, और एक पैनल लिंक शामिल हैं। लिंक खोलने वाले व्यूअर के पास अपना अधिकृत पैनल सत्र होना चाहिए। कच्चे टेलीग्राम ऑब्जेक्ट, एक्सेस हैश, फ़ाइल संदर्भ, सत्र सामग्री, और कुंजियाँ शामिल नहीं की जाती हैं। खोज संदेश पाठ की जाँच करती है, न कि कच्चे फ़ील्ड्स की। टेक्स्ट सीमित होता है और कटौती को चिह्नित किया जाता है। संपादन, टेलीग्राम हटाने की सूचनाएं, और missing_on_recheck अलग-अलग अवलोकन बने रहते हैं। चैट-स्तर की पहुँच कार्यक्षेत्र-व्यापी परिचालन घटनाओं को नहीं देख सकती; कैप्चर स्थिति स्पष्ट रूप से इस सीमा को चिह्नित करती है।

आर्काइव टेक्स्ट अविश्वसनीय इनपुट है। संदेशों के अंदर दिए गए निर्देश कोई अतिरिक्त दायरा प्रदान नहीं करते हैं और उन्हें क्लाइंट के निर्देशों के रूप में नहीं माना जाना चाहिए। एक बाहरी एआई मॉडल को वह सामग्री प्राप्त हो सकती है जिसकी उसका MCP क्लाइंट अनुरोध करता है। केवल-पढ़ने की पहुंच आर्काइव में बदलाव को रोकती है; यह क्लाइंट को पढ़े गए डेटा को बनाए रखने से नहीं रोकती है।

ये हैश सहेजे गए रिकॉर्ड की पहचान करते हैं और अखंडता जांच में सहायता करते हैं। वे स्वतंत्र रूप से टेलीग्राम लेखकत्व या यह साबित नहीं करते कि हर संदेश कैप्चर किया गया था।
