# Форматы счетов и сессий

TgWitness входит в систему как **учетная запись пользователя Telegram** (а не как бот) через MTProto с использованием
Telethon. Каждая учётная запись находится в собственном **рабочем пространстве** (называемом *workspace* в
API и инструментах командной строки) со своим сеансом, источниками, журналом и ключом подписи.

Файлы сеансов, строки сеансов и ключи аутентификации являются **авторизационными данными учетной записи**: любой, кто
их имеет, может действовать от имени этой учетной записи. Они не содержат истории сообщений.

> [!ПРЕДУПРЕЖДЕНИЕ]
> **Используйте специальные аккаунты.** Telegram ограничивает и может навсегда заблокировать аккаунты за
> объем запросов, который он считает чрезмерным, независимо от клиента или цели, и документирует
> эти ограничения лишь частично. Подключайте аккаунты, предназначенные для мониторинга, а не
> личные или иные ценные аккаунты, и создавайте API-ID / API-хэш на специальном
> аккаунте.

## Краткий обзор

| Что у вас есть | Вкладка **Добавить аккаунт** | Вам также понадобится |
| --- | --- | --- |
| Номер телефона и доступ к кодам для входа в систему | **Телефон** | Пароль для двухфакторной аутентификации (2FA), если она включена |
| Telegram открыт на другом устройстве | **QR-код** | Пароль для двухфакторной аутентификации (2FA), если она включена |
| Файл `.session` (Telethon или Pyrogram) | **Файлы** | Дополнительный файл JSON с настройками приложения (необязательно) |
| `.session` + `.json` с одинаковыми именами | **Файлы** (выберите оба) | Обычно больше ничего |
| Папка Telegram Desktop `tdata` | **Файлы** (в формате ZIP) | Локальный пароль рабочего стола, если он установлен |
| StringSession в Telethon (text, `.txt`, `.tgwitness-session`) | **Файлы** | Отдельная пара API не требуется |
| Ключ авторизации и DC в одной строке, `<512 hex>:<1–5>` | **Файлы** (вставленный текст или текстовый файл) | Отдельная пара API не требуется |
| `.json`, содержащий сессионный ключ или ключ аутентификации | **Файлы** | Отдельная пара API не требуется |
| Ключ аутентификации (512 шестнадцатеричных символов) и его номер DC | **Ключ авторизации** | Необязательный идентификатор пользователя |

TgWitness распознает файлы по их **содержанию**, а не по именам. Переименование файла
никогда не приводит к его преобразованию.

<a id="before-you-start-api-id-and-api-hash"></a>
## Перед началом работы: идентификатор API и хеш API

Вы можете войти в систему без создания приложения Telegram API. Если пара не введена,
не импортирована или не сохранена в рабочей области, TgWitness выбирает пару из встроенного пула,
состоящего из 50 общедоступных пар API (`tgwitness/api_pool.py`), отдавая предпочтение Telegram Desktop при новом
входе в систему и в первую очередь используя сохраненную пару; остальные варианты перемешиваются. Если Telegram отклоняет пару
(`API_ID_INVALID`, `API_ID_PUBLISHED_FLOOD`, `UPDATE_APP_TO_LOGIN`), пробуется следующая,
до восьми раз за один вход; отклоненные пары пропускаются до перезапуска. Пара, с помощью которой был выполнен вход,
сохраняется вместе с учётной записью и повторно используется для неё.

Встроенные пары являются общедоступными: они публикуются в открытом исходном коде клиентов и библиотек Telegram.
**Идентификатор API** и **Хеш API** идентифицируют приложение в Telegram
и не предоставляют доступа к данным учетной записи. Для входа используется собственная авторизация аккаунта: код входа
и пароль 2FA, либо сессия, в которой аккаунт уже авторизован. Каждая запись
`observation.started` указывает используемую пару, поэтому встроенная пара документируется для
суда так же, как и ваша собственная. Вместо этого вы можете ввести свою собственную пару с сайта my.telegram.org.
По опыту проекта новая личная пара приводит к выходу из системы большинства аккаунтов, поэтому используйте её
только в том случае, если дело требует использования вашего собственного приложения: создайте её с помощью специального аккаунта и
введите её до начала сбора данных (шаги приведены ниже).

В случае отсутствия полей подключения используется детерминированная пара «устройство/ОС» из входящих в комплект
[каталогов opentele2 2.0.0](https://github.com/DedInc/opentele2/tree/7e973bc71cd7a714ad13ac703c0895a90d36a735):
Desktop `2040`, Android `6`, Android X `21724`, iOS `10840`, macOS `2834` и Web `2496`.
Идентификатор сборки исходного кода Android `4` также использует каталог Android, как указано в
[BuildVars Telegram для Android](https://github.com/DrKLO/Telegram/blob/master/TMessagesProj/src/main/java/org/telegram/messenger/BuildVars.java).
По умолчанию для веб-версии используется A; импортированный суффикс версии приложения `K` или языковой пакет `macos` выбирает
K, а версия `0.7.0` выбирает Webogram. Неизвестные идентификаторы приложений сохраняют
значения по умолчанию хоста Telethon. Импортированные поля всегда имеют приоритет, включая более старую версию приложения и пустой
языковой пакет. Каталог никогда не изменяет API-идентификатор/хэш. Его моментальный снимок версии
проверяется явно, а не извлекается во время входа в систему. Сохраненный профиль остается неизменным после обновлений.

`account.getAuthorizations` содержит сохраненные метаданные авторизации Telegram; это
не повторение каждого нового `initConnection`. Сравните его с фактически отправленным профилем.
Подключение существующей авторизации не проверяет соответствующий хеш API:
`initConnection` отправляет ID API, тогда как хеш используется в запросах на вход.

После авторизации с помощью нового телефона или QR-кода TgWitness запрашивает настройки, ближайший дата-центр,
статус подключения, языки (если языковой пакет не пуст), обновления приложения и
обновления условий предоставления услуг с интервалом 0,3–1,5 секунды между запросами. Обновление статуса
на короткое время помечает учетную запись как «онлайн». Эта последовательность запускается один раз по завершении входа в систему,
а не при импорте данных, повторном подключении или перезапуске. Сначала сохраняется авторизация; неудачный
запрос останавливает последовательность без повторных попыток или отмены входа. Результаты
записываются в виде `account.initialized` с указанием названий ошибок вместо тел ответов.
Ограничения для аккаунта определяются собственными правилами Telegram.

Для `tdesktop`
в случае отсутствия `tz_offset`
используется локальное смещение UTC сервера, округленное
до 900 секунд с помощью алгоритма [opentele2](https://github.com/DedInc/opentele2/blob/7e973bc71cd7a714ad13ac703c0895a90d36a735/crates/opentele2-core/src/fingerprint.rs)

(MIT; лицензия указана в `tgwitness/client_profiles.LICENSE`
). Данные обновляются при каждом
подключении, чтобы учитывать изменения, связанные с переходом на летнее время. Импортированный `tz_offset`
имеет приоритет на всех платформах и сохраняется в точности, включая значение «ноль». Остальные записи
`initConnection.params`
сохраняются.
Форма входа по HTTP принимает числовое значение часового пояса, возвращаемое при импорте файла;
булевы значения, дроби и смещения, выходящие за пределы поддерживаемого диапазона, отклоняются.

Прямые, SOCKS5 и HTTP CONNECT маршруты используют `ConnectionTcpObfuscated`
от Telethon (зашифрованный сокращенный MTProto). HTTPS CONNECT сохраняет TLS до прокси и использует
тот же зашифрованный транспорт внутри туннеля. MTProxy сохраняет необходимый
рандомизированный промежуточный транспорт и обработку секретных данных. Переключатели маршрутов применяют
те же настройки. Зашифровка изменяет структуру пакетов; она не скрывает аккаунт
или его клиентские метаданные от Telegram и не означает иммунитета к ограничениям.

После подключения авторизованного клиента TgWitness проверяет конфигурацию, ближайший центр обработки данных,
текущую авторизацию, утвержденный базовый уровень уровня, языки, обновления приложения
и обновления условий предоставления услуг. Эти диагностические проверки выполняются один раз для каждого экземпляра клиента,
до начала сбора данных, и отображаются в деталях подключения с указанием времени.
`account.connection_checked` записывает результат без хешей сеансов, IP-адресов,
токенов или хешей API. Они никогда не принимают условия и не устанавливают обновления. Сбой запроса
или FloodWait останавливает последующие запросы; отсутствующий результат остается неизвестным.
Локальные проверки по-прежнему могут сообщать о своих результатах, в то время как сетевые проверки пропускаются.
При включенной функции [строгий выбор чатов](COLLECTION.md#strict-chosen-chats) текущая
авторизация не запрашивается, и эта проверка отображается как пропущенная.

После входа в систему и при каждом новом подключении TgWitness считывает настройку конфиденциальности
контента учетной записи. Если она отключена, а Telegram разрешает изменение, TgWitness включает её,
чтобы контент, помеченный Telegram как конфиденциальный (18+), сохранялся, и записывает
`account.content_settings`. Этот параметр относится к учётной записи и действует во всех
приложениях Telegram. В режиме «Только выбранные чаты» он остаётся неизменённым; включите его перед входом в систему.

Параллельные запросы на восстановление соединения с одной рабочей областью используют один и тот же клиент и
ожидают завершения установки соединения. В случае сбоя или отмены попытки освобождается
следующий запрос для повторной попытки. Если сохраненные учетные данные, клиент или состояние авторизации
изменяются во время установки соединения, более старая попытка прерывается, а не сообщает о готовности соединения.

Диагностика FloodWait сохраняет в `telegram.backoff` метод TL, завершившийся сбоем, любые обертки Takeout/range,
запрошенное сервером время ожидания и фактический крайний срок.
В сведениях о соединении отображаются метод и крайний срок, пока запросы приостановлены.
Диагностика включает счетчики вызовов клиента по методам с момента
создания данного клиента; они отдельно учитывают вложенное разрешение узлов, но не учитывают пакеты
или внутренние попытки повтора Telethon. Текущие счетчики также доступны в виде
`collector.rpc_activity` в API состояния. Аргументы запросов, имена пользователей,
хэши доступа или текст исключений не включаются. Последняя диагностическая информация и полный срок
сохраняются после перезапуска. Более ранние периоды ожидания без записи метода не могут быть отнесены
к конкретному методу задним числом. См. [ограничения экспорта](EXPORT-LIMITS.md) для проверки исходного кода и
разграничения между обнаружением и сбором истории.

`official_app=True` или `False` — это флаг текущей авторизации в Telegram. Ни одно из
этих значений не определяет, является ли аккаунт ограниченным, доверенным или находится под наблюдением.
Существующие снимки в режиме «доказательства» `account.devices` по-прежнему содержат историю всех
подключавшихся устройств; диагностика подключения сохраняет только описание текущего устройства.

Перед подключением в рамках профилактических проверок происходит сравнение платформы API, языкового пакета,
форматов устройства/ОС и версии приложения, языковых настроек мобильной системы, а также фактического
уровня схемы Telethon с эталонными значениями из проверенного каталога. Предупреждения отображаются в журнале сервера
и в метаданных статуса учетной записи; они никогда не заменяют импортированные значения и не изменяют
уровень схемы. Различие в уровнях является сигналом для проверки совместимости; собственный
статус подключения аккаунта показывает, работает ли он. Telegram определяет ограничения со своей
стороны, независимо от того, какой профиль клиента используется. Статус отключенного аккаунта
использует сохраненный профиль вместо генерации нового описания устройства.

Чтобы вместо этого использовать собственное приложение:

1. Откройте [my.telegram.org](https://my.telegram.org) и войдите, указав любой номер телефона,
   который принадлежит вам. Код приходит в приложении Telegram, а не в SMS.
2. Выберите **Инструменты разработки API**.
3. Создайте приложение: укажите любое название и короткое имя (5–32 буквы), платформу **Desktop**.
   Поля URL и описание можно оставить пустыми.
4. Скопируйте **App api_id** (число) и **App api_hash** (32 шестнадцатеричных символа).

В панели откройте раздел **API ID + Hash** под формой входа. Вы можете вставить одну пару
`api_id:api_hash` в поле **Идентификатор API**, и оба поля заполнятся автоматически. Одна такая пара может
использоваться для всех ваших учётных записей. После успешного входа в систему она сохраняется в зашифрованном виде
только в данной рабочей среде и никогда не отправляется обратно в браузер.

Здесь задействованы три различных типа учетных данных:

| Секрет | Открывается | Где он обитает |
| --- | --- | --- |
| Токен панели | Веб-панель TgWitness | `panel-token.txt` в каталоге «data» или `TGWITNESS_TOKEN` |
| Идентификатор API + хеш | Ничего само по себе; идентифицирует приложение | Встроенная пара, импортированные настройки или ваше собственное приложение на сайте my.telegram.org |
| Авторизация учетной записи | Аккаунт в Telegram | Создано при входе через телефон/QR-код или импортировано как сессия |

Если для доступа к Telegram требуется прокси-сервер, сначала настройте его в разделе
**Дополнительные инструменты → Аккаунт → Настройки → Настройки подключения → Изменить маршрут подключения**.

<a id="phone-number"></a>
## Номер телефона

1. Откройте **Дополнительные инструменты → Аккаунт**, вкладку **Телефон** и введите номер в международном формате,
   например, `+44 7700 900123`. Пробелы и дефисы удаляются автоматически.
2. Нажмите **Продолжить**. Поля «API ID» и «Хеш» можно оставить пустыми.
3. Введите код, отправленный Telegram, как правило, в приложение Telegram; Telegram самостоятельно решает, отправлять ли SMS.
4. Если для аккаунта включена двухэтапная аутентификация, введите соответствующий пароль. Это не токен панели
   и не код доступа к устройству.
5. Проверьте ID аккаунта, отображаемый после входа, затем выберите источники.

Коды входа и пароль для двухфакторной аутентификации никогда не записываются на диск.

<a id="qr-code"></a>
## QR-код

Используйте эту опцию, если на телефоне или другом компьютере уже выполнен вход в аккаунт.

1. Вкладка **QR-код** → **Показать QR-код**. Поля «API ID» и «Хеш» можно оставить пустыми.
2. На устройстве, на котором вы вошли в систему: **Настройки → Устройства → Подключить устройство**, отсканируйте код
   и подтвердите.
3. Введите пароль двухфакторной аутентификации в TgWitness, если Telegram запросит его.

QR-код генерируется локально. Срок действия кодов ограничен; нажмите **«Сгенерировать другой QR-код»**,
чтобы повторить попытку. Блокировка панели, переключение рабочей области или запуск другой сессии входа в систему приводит к аннулированию
кода, ожидающего обработки.

<a id="auth-key--dc-id"></a>
## Ключ аутентификации + DC ID

Ключ авторизации — это исходный 256-байтовый код авторизации, лежащий в основе каждого сеанса Telegram, записанный
в виде **512 шестнадцатеричных символов** вместе с номером дата-центра **DC 1–5**.

1. Перейдите на вкладку **Ключ авторизации**. Вставьте полный ключ; сокращённый ключ, содержащий `…`, не будет работать.
2. Выберите идентификатор DC, указанный в ключе.
3. При желании введите **Идентификатор пользователя**. В этом случае TgWitness откажется подключаться, если Telegram сообщит
   о другой учётной записи.
4. Нажмите **Подключить аккаунт**.

Ключ аутентификации (512 символов) — это не хеш API (32 символа). Этот же ключ также можно
импортировать в формате JSON, см. [JSON-файл учетной записи](#account-json).

<a id="account-files"></a>
## Файлы аккаунтов

Откройте **«Добавить аккаунт → Файлы»** и выберите до **четырёх файлов, относящихся к одному аккаунту**,
общим объёмом **8 MiB**, нажмите **«Проверить файлы»**, а затем **«Подключить аккаунт»**. Выбор файлов или
вставка текста сеанса не приводит к отправке данных; кнопка **Проверить файлы** отправляет их на ваш сервер TgWitness,
который считывает их без входа в систему и отображает найденный сеанс.

В формах **«Файлы»**, **«Ключ авторизации»** и массового импорта перед подключением отображается предупреждение о параллельных сессиях.
По умолчанию импортированные авторизации используются повторно. Не закрывайте исходный
клиент, пока его ключ используется здесь. В разделах **Файлы** и **Ключ авторизации** также доступна опция
**Создать независимую авторизацию**, описанная ниже. При массовом импорте по-прежнему используется
прямой режим. Вход с телефона и интерактивный вход с помощью QR-кода создают отдельные авторизации.
Заголовок предупреждения остаётся видимым в форме импорта; его полное объяснение открывается
автоматически при предоставлении файлов или ключа/строки сеанса. Его можно свернуть
после прочтения, чтобы на телефоне оставались доступными элементы управления выбором файлов и подключением.

[Подтвержденная конфигурация](PHALA.md) (Phala Cloud, Intel TDX) не позволяет выполнять сбор данных по
импортированному ключу. В этом случае **Файлы** и **Ключ авторизации** подключаются только при выбранном параметре **Создать независимую
авторизацию**; массовый импорт не допускается. Вход с помощью телефона и QR-кода работает в обычном режиме.

- Файлы конвертируются **в памяти** на вашем сервере TgWitness. Загруженные файлы не сохраняются,
  архивы ZIP не распаковываются на диск, и не происходит обращения к каким-либо внешним сервисам.
- Затем полученная сессия проверяется с помощью Telegram. Если в файле указан идентификатор пользователя,
  он должен совпадать с идентификатором учетной записи, указанным в Telegram.
- Файлы, описывающие разные аккаунты или разные учетные данные API, отклоняются,
  а не выбираются.
- **Пароль или текст сеанса** содержит поле локального пароля TData, поле для вставки
  StringSession и опцию **Чтение файлов без входа в систему** (заполняет форму без
  обращения к Telegram). Вставка StringSession очищает выбранные файлы, а выбор
  файлов очищает вставленный текст, поэтому при проверке и подключении используется последний выбор.
  После смены пароля нажмите **Проверить файлы** ещё раз.

<a id="create-an-independent-authorization"></a>
### Создать независимую авторизацию

Выберите **«Создать независимую авторизацию»** перед подключением импортированных файлов или
ключа авторизации. TgWitness на короткое время подключается к импортированному донору, использует его для утверждения
токена входа по QR-коду нового клиента и сразу же после утверждения отключается от донора.
Новый клиент имеет собственный ключ авторизации и отдельно выбранный профиль Desktop.
Предоставленные донором учетные данные API и профиль устройства используются только для
подключения к донору. Ни одна из существующих авторизаций не отменяется и не аннулируется.

**На этом этапе исходный клиент донора должен оставаться полностью закрытым.** Первоначальное
соединение по-прежнему использует скопированный ключ, поэтому данный режим не может устранить риск
параллельного использования. После установления нового авторизованного соединения владелец может вновь открыть
исходный клиент и использовать оба одновременно. Интерактивный вход с помощью **QR-кода** позволяет
исходному клиенту утвердить вход без копирования или подключения своего ключа в данном случае.

**Не выходите из системы и не завершайте сессию донора.** Когда заканчивается сессия, в которой был утвержден вход по QR-коду,
Telegram также завершает утвержденную им сессию; в ходе тестирования в режиме реального времени новая
авторизация прекратилась в течение секунды после выхода донора из системы. При импорте фиксируются
данные сессии донора (`session_origin.approved_by`: устройство, ID API и время создания).
Список сеансов помечает его, **«Завершить сеанс»** отменяет его, а **Завершить все другие сеансы**
и **Оставить только этот сеанс** оставляют его авторизованным.

Если Telegram запрашивает двухфакторную аутентификацию (2FA), этот режим использует `twoFA` из выбранного JSON-файла, если он присутствует,
или запрашивает пароль. В случае отклонения импортированного пароля происходит возврат к форме ввода пароля.
Пароли не сохраняются. Ключ-кандидат сохраняется в зашифрованном виде в
`independent_login.enc`, включая изменения, произошедшие во время миграции между центрами обработки данных. После
прерывания выберите того же донора и эту опцию, чтобы возобновить использование сохраненного ключа-кандидата.
Перед утверждением донор проверяется с помощью `help.getAppConfig`; если аккаунт заблокирован,
процесс останавливается на этом этапе. Если Telegram отклоняет донора до утверждения входа, неутверждённый
кандидат-ключ отбрасывается, и импорт можно начать заново. Другой донор заменяет
сохранённого кандидата только в том случае, если Telegram сообщает, что этот кандидат не вошёл в систему;
кандидат, который вошёл в систему или ожидает получения пароля 2FA, сохраняется.
Рабочая область остаётся зарезервированной для этой учётной записи; неудачное завершение не приводит к удалению
новой рабочей области. Сохраните её каталог данных и ключ хранилища. Окончательные учетные данные и
запись журнала `account.authorized` включают метод импорта, форматы ввода и
ID API донора, без ключа или пароля донора.

5 ноября 2026 года специальный аккаунт прошел проверки в режиме реального времени с донорами Telethon, Pyrogram
и TData: прохождение двухфакторной аутентификации (2FA), уникальные новые ключи авторизации, одновременный доступ
донора и нового клиента, а также чтение общедоступного канала. В случае с Telethon также
был возобновлен сохраненный кандидат после прерывания на этапе ввода пароля. Каждая новая
авторизация завершалась шестью запросами инициализации после входа в систему, а её подписанный
журнал был проверен. Исходная сессия оставалась работоспособной во всех четырёх предоставленных форматах.

База данных ошибок RPC Telegram ](https://core.telegram.org/api/errors.json) связывает
`FRESH_CHANGE_ADMINS_FORBIDDEN` со сменой администраторов, `FRESH_CHANGE_PHONE_FORBIDDEN`
со сменой номера телефона, а `FRESH_RESET_AUTHORISATION_FORBIDDEN` — с
отзывом других сеансов, изменением их срока действия или регистрацией пароля-ключа.
`SESSION_TOO_FRESH_*` и `PASSWORD_TOO_FRESH_*` касаются передачи прав владения и
вывода средств или подарков. Это не операции сбора данных; новый вход в систему
не влечет за собой полный 24-часовой запрет на чтение. Экспорт может отдельно возвращать
`TAKEOUT_INIT_DELAY_*`. TgWitness сохраняет паузы, запрошенные сервером, и не повторяет
принятие токена автоматически, а также не отменяет сессии для обхода ограничений.

**«Дополнительные инструменты» → «Аккаунт» → «Безопасность аккаунта» → «Сеансы этого аккаунта» → «Завершить все остальные сеансы»** вызывает `auth.resetAuthorizations` по
запросу оператора и записывает `account.all_other_sessions_terminated` с
количеством сеансов до и после. Telegram принимает этот запрос от сеанса, в котором пользователь находится в системе в течение 24 часов.
Когда эта рабочая среда авторизуется по QR-коду из импортированной сессии, сессия, которая это одобрила,
остаётся авторизованной: TgWitness поочерёдно завершает остальные с помощью `account.resetAuthorization` и
записывает `kept_approving_session`. **Оставить только этот сеанс** затем останавливается по этой причине
и не меняет пароль.

**Оставить только этот сеанс** выполняет те же действия для ключа, созданного при входе в систему из этой
рабочей среды, а затем включает двухэтапную аутентификацию, если для учетной записи она еще не настроена. Панель отображает этот
пароль один раз; TgWitness хранит его в хранилище рабочей среды только до этого момента. В журнале фиксируется `session.exclusive_from`. Если
позже Telegram укажет другой сеанс, в журнале фиксируется `session.exclusive_ended`, и
панель выдает предупреждение. Верификатор выводит оба значения.

**Оставить только этот сеанс, когда Telegram разрешит** — это то же самое действие, запущенное по таймеру. Эта
опция появляется в разделе **Сеансы аккаунта** для ключа, созданного в этой рабочей области, и
регистрируется как `session.exclusive_automatic`. Во время мониторинга сборщик каждые пять
минут проверяет, прошло ли 24 часа с момента записи `account.authorized` для этого ключа —
Telegram ответил `FRESH_RESET_AUTHORISATION_FORBIDDEN` до этого — и затем выполняет ту же
операцию один раз. Успех записывается как `session.exclusive_from`, как и при использовании ручной кнопки.
Отказ фиксируется один раз как `session.exclusive_postponed` с указанием причины Telegram, и
коллектор повторяет попытку с увеличивающейся задержкой до шести часов. Режим «только для чтения» здесь не влияет:
завершение сеансов является действием, связанным с безопасностью аккаунта, а не действием в чате.

Двухэтапный пароль, сгенерированный при автоматическом запуске, сохраняется в хранилище рабочей среды в зашифрованном виде
с помощью ключа рабочей среды до того, как Telegram его установит. Панель один раз извлекает его из
`POST /api/account/sessions/only/password`, после чего он удаляется, и отображает его в том же диалоговом окне,
что и при ручном запуске, когда вы открываете **Сеансы аккаунта**. На странице подключения отображается сообщение о том, что
пароль находится в ожидании. Он никогда не попадает в журнал и сохраняется после перезапуска до тех пор, пока не будет отображён.

О новых сессиях также сообщается в процессе наблюдения: когда в списке сессий Telegram появляется новая запись,
запись `account.sessions` указывает её под `added`, а панель выдает предупреждение с указанием
устройства, приложения и страны из этого моментального снимка.

<a id="witness-probe"></a>
### Расследование по делу «Свидетель»

**Дополнительные инструменты → Аккаунт → Безопасность аккаунта → Проверка свидетеля** — проверяет, получает ли другой клиент
обновления этого аккаунта. Добавьте вторую рабочую область, авторизованную с помощью другого аккаунта Telegram и собственного
сессионного ключа, создайте закрытую группу с участием обоих аккаунтов, затем выберите эту группу в качестве **Тестового
чата**, а вторую рабочую область — в качестве **Рабочей области-свидетеля** и включите проверку. На обеих аккаунтах
должен быть отключен режим **Только чтение**, а рабочая область-свидетель должна находиться в режиме наблюдения.

В процессе наблюдения данное рабочее пространство отправляет в группу `probe:<n>:<token>` каждые 60–120 секунд
и записывает `probe.sent`. Свидетель отвечает `ack:<n>:<token>` и записывает `probe.seen` и
`probe.ack_sent`. Подтверждение (ack), поступающее в эту сессию в виде оперативного обновления в течение 20 секунд,
записывается как `probe.acked`. В противном случае рабочее пространство считывает недавнюю историю группы. Подтверждение
, найденное там, но не доставленное в режиме реального времени, записывается как `coverage.gap` с причиной
`probe_ack_missed_live`: панель выдает предупреждение и помечает приём события как неудачный до тех пор, пока
позже не поступит подтверждение в режиме реального времени (`connection.restored`, причина `probe_ack_live`). Отсутствие подтверждения регистрируется как
`probe.unanswered`; обрыв соединения во время ожидания или нечитаемая история — как
`probe.inconclusive`. Режим «только для чтения», ограничения Telegram и паузы FloodWait регистрируются один раз
как `probe.skipped`.

<a id="telethon-session"></a>
### Телемарафон `.session`

|  |  |
| --- | --- |
| Что это такое | Инструменты на основе базы данных SQLite Telethon создают, например, `my_account.session` |
| Признано | Таблицы `sessions` (с `dc_id`, `server_address`, `port`, `auth_key`) и `version` = 7 или 8 |
| Требования | Ровно одна строка авторизованной сессии; закрытая, полная база данных |

Сначала закройте программу, которая создала этот файл. Если рядом с ним находится `my_account.session-journal` или
`my_account.session-wal`, это означает, что база данных не завершила работу: откройте и
корректно закройте исходный клиент. Удаление этих вспомогательных файлов может привести к появлению повреждённой копии.

<a id="pyrogram-session"></a>
### Pyrogram `.session`

|  |  |
| --- | --- |
| Что это такое | Инструменты на основе Pyrogram, создающие базы данных SQLite |
| Признано | Таблица `sessions` с `dc_id`, `auth_key`, `test_mode`, `user_id`, `is_bot`; `version` = 2 или 3 |
| Требования | Допускается один сеанс авторизованного **пользователя** в производственной сети. Сеансы ботов и тестового центра обработки данных отклоняются |

При входе в систему сохраненный идентификатор пользователя сверяется с данными Telegram.

<a id="session--json-pair"></a>
### Пара «Сессия + JSON»

Файлы с учетными данными часто предоставляются в виде двух файлов с одинаковыми именами, например
`447700900123.session` и `447700900123.json`. Выберите **оба** сразу.

- На основании данных JSON TgWitness использует `app_id`/`api_id` и `app_hash`/`api_hash`, поэтому вам
  обычно не нужно вводить учетные данные API.
- Профиль подключения использует `device_model` (псевдоним `device`), `system_version`
  (псевдоним `sdk`), `app_version`, `lang_code`, `system_lang_code` (псевдоним `system_lang_pack`),
  `lang_pack` и опциональный `tz_offset` (секунды от UTC, от -43200 до 50400).
  Указанные поля имеют приоритет над сгенерированными значениями по умолчанию и языком панели/браузера
  . Конфликтующие псевдонимы отклоняются. Окончательный профиль сохраняется в
  зашифрованных учетных данных рабочей области и используется повторно после перезапуска, включая версию приложения.
- `phone`, настройки прокси и токены устройств **игнорируются**. `twoFA` доступно только для чтения,
  если выбран параметр **«Создать независимую авторизацию»**; при прямом импорте оно игнорируется.
- JSON-файл без поддерживаемого поля авторизации является лишь метаданными. Добавьте файл сессии
  или продолжите вход с помощью телефона или QR-кода. JSON-файл, содержащий поддерживаемую сессию или
  авторизационный ключ, может авторизоваться самостоятельно; см. [JSON-файл учетной записи](#account-json).

<a id="telegram-desktop-tdata"></a>
### Telegram Desktop (TData)

TData — это папка `tdata` приложения Telegram Desktop (кроссплатформенного
приложения с сайта desktop.telegram.org).

| Система | Расположение по умолчанию `tdata` |
| --- | --- |
| Windows | `%APPDATA%\Telegram Desktop\tdata` (мобильная версия Telegram: рядом с `Telegram.exe`) |
| Linux | `~/.local/share/TelegramDesktop/tdata` |
| macOS | `~/Library/Application Support/Telegram Desktop/tdata` |

Чтобы импортировать его:

> **Предупреждение о параллельных сессиях.** При прямом импорте TData повторно используется ключ авторизации Telegram Desktop.
> Не используйте этот ключ одновременно в Desktop и
> TgWitness. Telegram может аннулировать авторизацию с помощью
> `AUTH_KEY_DUPLICATED`, в результате чего обе копии станут непригодными для использования до нового входа в систему.
>
> Полностью закройте Desktop, включая его процесс в трее, и держите эту копию закрытой, пока
> TgWitness использует импортированную сессию. **Закройте программу, не выходите из системы и не отменяйте сессию:**
> отмена также приведёт к аннулированию импортированной копии. Если вам нужно, чтобы оба клиента работали,
> выберите **«Создать независимую авторизацию»** и держите Desktop закрытым до тех пор, пока
> новый вход не пройдет успешно, либо войдите в TgWitness с помощью телефона или QR-кода. Рекомендуется использовать отдельный
> аккаунт, но это не делает клонированные ключи безопасными для параллельного использования.
>
> Это также относится к импортированным файлам `.session`, тексту StringSession и шестнадцатеричному коду Auth Key.
> Другие клиенты с собственными, независимо созданными авторизациями, могут оставаться авторизованными.
> См. [документацию Telegram по AUTH_KEY_DUPLICATED](https://core.telegram.org/api/errors#406-not-acceptable).

1. Полностью закройте Telegram Desktop.
2. Создайте ZIP-архив, содержащий **только** эти два элемента из `tdata`:
   - `key_datas`
   - файл из 16 символов, заканчивающийся на `s`, расположенный рядом с ним, обычно `D877F783D5D3EF8Cs`

   Сжатие всей папки вместе с кэшем мультимедиа, как правило, превышает установленные ограничения
   (512 записей, 32 MiB в распакованном виде).
3. Выберите ZIP-файл в разделе **Файлы**. Если у Telegram Desktop установлен **локальный пароль**, сначала введите его
   в поле **Пароль или текст сеанса**. Это не пароль двухфакторной аутентификации.

Поддерживается: одна учетная запись на архив, современное хранилище `key_datas`/`key_data0`/`key_data1`,
локальный пароль. Не поддерживается: папки с несколькими авторизованными аккаунтами, старые версии рабочего стола,
ZIP-архивы, защищенные паролем, а также отдельное нативное приложение для macOS «Telegram для macOS».

<a id="telethon-stringsession"></a>
### Телемарафон StringSession

Одна строка текста, обычно начинающаяся с `1` и содержащая около 350 символов. Загрузите
её в виде файла `.txt` или `.tgwitness-session` (размером не более 4 КиБ) или вставьте в поле
**«Пароль или текст сессии»**. Принимаются только строки формата Telethon; строки Pyrogram и TDLib
используют другие форматы.

<a id="auth-key-and-dc-in-one-line"></a>
### Ключ аутентификации и DC в одной строке

В списках аккаунтов авторизационные данные часто представлены в исходном виде как `<512 hexadecimal characters>:<DC id>`,
например, `a1b2…ef:5`. Вставьте эту строку в поле **«Пароль или текст сеанса»**, загрузите её как
текстовый файл или введите в поле `session` учетной записи [JSON-файла учетной записи](#account-json). TgWitness
сопоставляет DC 1–5 тем же производственным адресам, что и при импорте JSON-файла `auth_key` + `dc_id`, и
указывает формат как **HEX-код авторизационного ключа и DC**. Любой другой номер DC или длина ключа отклоняются.

<a id="account-json"></a>
### JSON-файл учетной записи

Один объект JSON размером не более **64 КиБ** в файле с расширением **`.json`**.

| Поле (псевдонимы) | Значение |
| --- | --- |
| `api_id` (`app_id`) | Идентификатор приложения — положительное число |
| `api_hash` (`app_hash`) | Хеш приложения, 32 шестнадцатеричных символа |
| `string_session` (`session_string`, `session_str`; устаревшее `session`) | Текст StringSession телемарафона или `<512 hexadecimal characters>:<DC id>` — это не имя файла |
| `auth_key` (`auth_key_hex`) + `dc_id` | Полный ключ аутентификации длиной 512 символов и DC 1–5 |
| `user_id` (`id`) | Необязательно; проверка в Telegram производится до сохранения авторизации |
| `device_model` (`device`) | Описание соединительного устройства |
| `system_version` (`sdk`) | Версия ОС устройства |
| `app_version` | Версия приложения, отправленная в Telegram |
| `lang_code`, `system_lang_code` (`system_lang_pack`), `lang_pack` | Язык клиента, язык системы и языковой пакет клиента; допускается использование пустого тега `lang_pack` |
| `tz_offset` | Необязательное смещение по отношению к UTC в секундах, передаваемое в `initConnection.params`; целое число или строка, содержащая десятичное целое число |

Если присутствуют как псевдоним, так и основное имя, они должны совпадать. Явные поля сессии Telethon
имеют приоритет над общим блоком `session` в другом формате. Если
оба содержат распознаваемые сессии Telethon, они должны описывать одну и ту же авторизацию.
При отсутствии явного поля `session` должно быть действительной сессией Telethon StringSession или ключом авторизации
и DC в формате `<512 hexadecimal characters>:<DC id>`. Примеры:

```json
{ "app_id": 1234567, "app_hash": "0123456789abcdef0123456789abcdef" }
```

```json
{
  "api_id": 1234567,
  "api_hash": "0123456789abcdef0123456789abcdef",
  "auth_key": "REPLACE_WITH_ALL_512_HEXADECIMAL_CHARACTERS",
  "dc_id": 2,
  "user_id": 123456789
}
```

В первом примере заполняются только учетные данные API; войдите в систему с помощью телефона или QR-кода либо добавьте файл сеанса.
Массовые списки (массив JSON с аккаунтами) не принимаются.

<a id="identify-what-you-have"></a>
## Определите, что у вас есть

| Понимаете ли | Это | Использование |
| --- | --- | --- |
| `*.session`; при открытии в текстовом редакторе вверху отображается `SQLite format 3` | Telethon или Pyrogram SQLite | **Файлы** (обнаруживаются автоматически) |
| Папка `tdata`, содержащая `key_datas` | Telegram Desktop TData | Скомпрессируйте два файла в ZIP-архив, затем **Файлы** |
| Одна строка текста, начинающаяся с `1`, ~350 символов | Телемарафон StringSession | **Файлы** |
| Одна строка текста `512 characters 0-9a-f`, затем `:` и цифра от 1 до 5 | Ключ аутентификации и DC | **Файлы**, поле **Пароль или текст сеанса** |
| `*.json` с `app_id`/`app_hash` | Сопутствующие метаданные | **Файлы** вместе с сессией |
| `*.json` вместо `auth_key` или `string_session` | JSON-файл учетной записи | **Файлы** |
| 512 символов `0-9a-f` | Ключ аутентификации | **Ключ авторизации** |
| 32 символа `0-9a-f` | Хеш API | **API ID + hash** |
| `td.binlog` или `db.sqlite` из приложения TDLib | Хранилище TDLib | Не поддерживается |
| `123456789:AA…` | Токен бота | Не поддерживается |

<a id="unsupported-formats"></a>
## Неподдерживаемые форматы

| Формат | Альтернатива |
| --- | --- |
| Хранилище TDLib (`td.binlog`) и экспортные данные TDLib | Войти с помощью телефона или QR-кода |
| Сессия Pyrogram **строки** | Используйте файл Pyrogram `.session` или телефон/QR-код |
| TData с несколькими авторизованными аккаунтами | Выйдите из других аккаунтов в Telegram Desktop или используйте отдельный файл сеанса для каждого аккаунта |
| Токены ботов | Не поддерживается: TgWitness работает под учетной записью пользователя |
| Списки с большим количеством аккаунтов в формате CSV/JSON | Импортируйте файлы сеансов, поддерживаемые системой, через **«Аккаунты» → «Импорт аккаунтов»** или войдите в систему с помощью номера телефона/QR-кода в отдельных рабочих пространствах |
| Сеансы Test-DC или ботов | Используйте рабочую учетную запись |

<a id="multiple-accounts"></a>
## Несколько аккаунтов

Нажмите **+** рядом с выбором учетной записи или откройте
**Дополнительные инструменты → Учетная запись → Настройки → Настройки подключения → Рабочие пространства**, введите название и
войдите в систему.

- Любое количество рабочих пространств, включая основное. Каждое из них имеет собственный сеанс, прокси-
  маршрут, источники, политику захвата, журнал, ключ подписи, контрольные точки и экспортные данные.
- Переключение отображаемого рабочего пространства не приводит к приостановке работы остальных.
- Журнал остается привязанным к учетной записи, которая его создала. Для входа под другой
  учетной записью требуется отдельная рабочая область, и одна учетная запись не может быть привязана к двум
  рабочим областям.
- Токен главной панели управляет всеми рабочими областями. [Предоставленный доступ](ACCESS.md) может ограничивать доступ других пользователей к выбранным аккаунтам и чатам с отдельными правами и ограничениями сеансов.
- **Аккаунты** позволяют переименовывать рабочее пространство и удалять добавленное, вместе с его сессией, журналом,
  источниками и ключом подписи. Главное рабочее пространство нельзя удалить из панели.

<a id="bulk-import-and-account-groups"></a>
### Массовый импорт и группы аккаунтов

Воспользуйтесь пунктом **«Аккаунты» → «Импорт аккаунтов»**, чтобы добавить несколько аккаунтов, сопоставить файлы по базовому имени
и просмотреть результаты входа для каждой учетной записи. Каждая учетная запись получает собственное рабочее пространство.

Группа объединяет связанные аккаунты, не объединяя при этом их сеансы, ключи или
доказательства. **Открыть группу** в разделе **Аккаунты** позволяет перейти на её страницу по адресу `/groups/<id>`:

- **Аккаунты:** маршрут подключения каждого участника, наблюдения и последнее сообщение, с
  кнопками **Запустить все** и **Приостановить все**.
- **Требует внимания:** аккаунты, из которых вышли, которые недоступны или у которых
  проблемы с подключением, приемом данных, источником или медиафайлами; каждое имя ведет к соответствующей карточке.
- **Чаты, видимые нескольким аккаунтам:** общие источники, аккаунты, наблюдающие за ними, и
  перерывы в периоде наблюдения в доступном рабочем пространстве (до семи дней). **Экспорт с N аккаунтами**
  разделяет экспорт канала или супергруппы между ними и подписывает один архив.
- **Групповой экспорт:** один ZIP-файл, содержащий подписанный экспорт каждой учетной записи под `accounts/` и
  `manifest.json` с указанием их SHA-256 и отпечатков ключей, подписанный главной
  рабочей областью в `manifest.signature.json`. Проверьте каждый архив учетной записи отдельно с помощью
  `python -m tgwitness.verify` и доверенного отпечатка этой учетной записи.

Участники используют общие настройки группы; у каждой учетной записи могут быть свои собственные настройки.
См. [общие настройки](../SETTINGS.md#account-groups)
,
[руководство по импорту и группам](../wiki/Accounts.md#import-accounts-and-share-settings)
и [панель управления пулом MTProxy](../wiki/Proxies.md#pool-dashboard-and-custom-sources)
.

<a id="sign-out"></a>
## Выйти

**Дополнительные инструменты → Аккаунт → Выйти из Telegram** (при приостановленном наблюдении) запрашивает у Telegram завершение
сеанса, в результате чего он также исчезает из раздела **Настройки → Устройства** аккаунта и удаляется из
хранилища рабочего пространства. Журнал, источники, настройки и ключ подписи остаются, и
в журнале фиксируется факт выхода. Рабочая область по-прежнему принадлежит своей учётной записи: только эта
учётная запись может подключиться к ней снова. Если Telegram не отвечает, сессия всё равно удаляется
здесь, и панель отображает соответствующее сообщение; завершите её в Telegram в разделе **Настройки → Устройства**.

<a id="when-telegram-ends-the-session"></a>
## Когда Telegram завершает сеанс

Если Telegram заблокирует, заморозит или выйдет из учетной записи, либо завершит сеанс с другого устройства, в
журнале фиксируются причина, код ошибки Telegram, маршрут и центр обработки данных. Состояние аккаунта
показывает **Скачать отчёт о потере аккаунта**: подписанный файл JSON с записями журнала
за 24 часа до потери, а именно: подключения, маршруты, сеансы, уведомления аккаунта и пробелы в охвате
, каждая из которых имеет свой хеш журнала и подпись. Проверьте это с помощью
`python verify.py tgwitness-account-loss.json --fingerprint COLLECTOR_FP`; экспорт доказательств
содержит полную цепочку хешей. Заблокированная учетная запись также обнаруживается при подключении и во время наблюдения, при этом её
возможности отправлять сообщения и присоединяться к чатам отключаются.

<a id="keeping-account-files-safe"></a>
## Обеспечение безопасности бухгалтерских документов

- Относитесь к каждому `.session`, TData ZIP, StringSession, ключу авторизации и JSON-файлу учетной записи как к
  паролю. TgWitness хранит импортированные данные авторизации в зашифрованном хранилище; после этого вы можете
  удалить исходные файлы.
- Не запускайте одну и ту же авторизацию одновременно в двух программах. Telegram может отозвать её
  (`AUTH_KEY_DUPLICATED`), и обе копии перестанут работать.
- Сессию, срок действия которой истек или которая была отозвана, невозможно восстановить путём преобразования. Войдите в систему заново.

<a id="troubleshooting"></a>
## Устранение неполадок

| Симптом или признак | Что делать |
| --- | --- |
| *Не удаётся прочитать эту сессию. Закрыть исходный клиент…* | Файл SQLite открыт или не завершен (сопутствующий файл `-journal`/`-wal`). Корректно закройте исходную программу и скопируйте файл заново. |
| *Поддерживаемые схемы Telethon SQLite: 7 и 8* / *Pyrogram … 2 и 3* | Файл был создан с помощью очень старой или неизвестной версии библиотеки. Войдите в систему с помощью телефона или QR-кода. |
| *Поддерживаются только авторизованные сеансы пользователей производственной среды* | Файл Pyrogram принадлежит боту или тестовой сети. |
| *Архив TData превышает 512 записей или 32 МиБ* | Сжатие только изображений `key_datas` и `D877F783D5D3EF8Cs`, а не всей папки. |
| *Не удается расшифровать TData. Проверьте локальный пароль рабочего стола* | Введите локальный пароль Telegram Desktop в поле **«Пароль или текст сеанса»**. |
| *Импортировать по одной учетной записи TData за раз* | В Telegram Desktop было несколько аккаунтов; см. [Неподдерживаемые форматы](#unsupported-formats). |
| *В указанных файлах содержатся данные различных аккаунтов или учетные данные для доступа к API* | Выберите файлы только из одной учетной записи. |
| *В JSON отсутствуют поддерживаемые учетные данные или авторизация API* | Проверьте названия полей в файле [Account JSON](#account-json). |
| *Только метаданные API* | В JSON-файле отсутствует сессия. Добавьте файл `.session` или воспользуйтесь телефоном/QR-кодом. |
| *HEX-код авторизационного ключа должен содержать все 512 шестнадцатеричных символов* | Ключ усечён или содержит `…`. |
| Идентификатор учетной записи не совпадает с идентификатором импортированной учетной записи | Идентификатор пользователя файла не совпадает с тем, что указывает Telegram; этот файл принадлежит другой учетной записи. |
| Учётная запись уже принадлежит другой рабочей среде | Откройте эту рабочую область, вместо того чтобы добавлять учетную запись дважды. |
| Подключено, но в списке чатов в разделе **Дополнительные инструменты → Источники** отсутствует закрытая группа | Проверьте членство. Инструмент проверяет первые 1 000 диалоговых окон; увеличьте это ограничение в разделе **Дополнительные инструменты → Параметры**. |
| Ошибка подключения через прокси | Проверьте маршрут и режим IP. Автоматический MTProxy пробует другой рабочий запись. При ожидании адреса; в крайнем случае режим «Direct» может установить соединение напрямую после заданной задержки. См. [режимы маршрутизации](CONNECTION-SECURITY.md#ip-modes). |

См. также: [подключение и безопасность](CONNECTION-SECURITY.md) — о прокси-серверах и шифровании,
а также [как работает сбор данных](COLLECTION.md) — о том, какие данные собираются после входа в систему.
