# 読み取り専用 MCP

Canonical page: https://phishdestroy.github.io/TgWitness/ja/docs/reference/mcp/

MCPクライアントを、有効期限付きかつ取り消し可能なアクセス権限で、選択したワークスペースやチャットに接続します。

**現在のメインバージョン：**ソースコードをチェックアウトして使用してください。0.7.0のポータブルプレビュー版には、この機能が実装されていません。

[ワークフローガイド](https://phishdestroy.github.io/TgWitness/docs/archive/) · [Wiki](https://github.com/phishdestroy/TgWitness/blob/main/docs/wiki/Archive-and-Integrations.md)

TgWitness プロジェクトディレクトリからオプションのサーバーをインストールします：

```
python -m pip install '.[mcp]'
```

パネルで、**「統合」→「MCP」**を開きます。接続に名前を付け、対象の ワークスペースとチャットを選択し、有効期限を設定します。アーカイブトークンは一度だけコピーしてください。 後で再取得することはできません。紛失したトークンは無効化し、代替トークンを発行してください。パネルのトークンおよび Telegramの認証情報は、MCPの認証情報とは異なります。

## クライアントを接続する

このパネルは、[ドキュメントに記載された設定](https://code.visualstudio.com/docs/agents/reference/mcp-configuration)に基づき、**VS Code Local**ハーネス用の`.vscode/mcp.json`を生成します。 ダウンロードしたファイルをその場所に保存し、MCP: List Serversを実行して、 ダウンロードしたファイルをその場所に保存し、**「MCP: List Servers**」を実行して、 TgWitnessを起動します。VS Codeは、パスワード入力画面を通じてトークンの入力を求めます。ダウンロードした JSONファイルには、トークンそのものではなく、プロンプトの参照情報が含まれています。MCPエクストラがインストールされている 環境にあるPython実行ファイルを使用してください。

stdioの他のクライアントについては、以下を実行してください：

```
python -m tgwitness.mcp_server --api-url http://127.0.0.1:8787
```

クライアントの保護された環境内で`TGWITNESS_ARCHIVE_TOKEN`を設定してください。これを コマンド引数やURLには含めないでください。ブリッジはパネルの認証済み アーカイブAPIを通じて読み込みを行います。データベースへの直接アクセスは行いません。標準出力（stdout）にはMCPメッセージのみが送信されます。

リモートクライアントの場合は、パネルの横でサービスを実行してください：

```
python -m tgwitness.mcp_server --transport streamable-http \
  --api-url http://127.0.0.1:8787 --port 8766 \
  --public-url https://archive.example.org/mcp
```

`/mcp` を HTTPS リバースプロキシ経由で `127.0.0.1:8766/mcp` に転送し、 `Authorization: Bearer …` ヘッダーを保持します。認証ヘッダーおよび リクエスト／レスポンス本文のロギングを無効にします。必要な場合にのみ、 `--host` および `--public-url` を使用してループバック以外のアドレスにバインドします。このエンドポイントは、公式の [MCP Python SDK](https://github.com/modelcontextprotocol/python-sdk) の Streamable HTTP を使用しています。 OAuthディスカバリーではなく、明示的に設定されたベアラ認証情報をサポートしており、 OAuthのみを必要とするクライアントはサポートされていません。

**プロトコルの確認とアクセスにより、**実際のMCPクライアントが初期化され、ツールの一覧が表示されます。この段階では メッセージは取得されません。リモートでの確認を行う場合、選択されたMCPサーバーが アーカイブトークンを受け取ります。この権限範囲については、自身が運用している、または信頼できるサーバーのみを設定してください。

## 範囲と成果

利用可能なツール：`list_workspaces`、`list_chats`、`search_messages`、 `get_message_versions`、`get_message_context`、`get_journal_event`、および `get_capture_status`。Telegram上の操作、設定変更、または 一括エクスポートツールは提供されていません。 読み取りのたびにワークスペース／チャットへのアクセス権が再確認され、有効期限が切れたり取り消されたりした 認証情報は機能しなくなります。制限は、認証情報1つあたり1分間に60回のAPIリクエスト、 1ページあたり50件のレコード、64 KiBのレスポンス、および8秒のAPIタイムアウトです。

メッセージの結果には、ワークスペース、チャット/メッセージID、イベントの順序、保存されたハッシュ、 およびパネルへのリンクが含まれます。リンクを開く閲覧者は、独自の認証済みパネル セッションを持っている必要があります。Telegramの生のオブジェクト、アクセスハッシュ、ファイル参照、セッション資料、 および鍵は省略されます。検索はメッセージのテキストを対象とし、生のフィールドは対象外です。 テキストは 範囲が限定され、切り捨て部分はマークされます。編集、Telegramの削除通知、および `missing_on_recheck`は、個別の観測項目として扱われます。チャット範囲のアクセス権では、 ワークスペース全体の運用イベントを閲覧することはできません。キャプチャステータスには、この制限が明示的に示されています。

アーカイブ内のテキストは信頼できない入力です。メッセージ内の指示は、追加の 権限を付与するものではなく、クライアントからの指示として扱ってはなりません。外部のAIモデルは、 そのMCPクライアントが要求するあらゆるコンテンツを受け取る可能性があります。読み取り専用アクセスは アーカイブの変更を防止しますが、クライアントが読み取ったデータを保持することを妨げるものではありません。

ハッシュ値は保存された記録を識別し、整合性チェックを可能にします。ただし、これらは Telegramでの発信元を単独で証明するものではなく、またすべてのメッセージが確実に記録されたことを証明するものでもありません。
