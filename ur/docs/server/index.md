# اسے چلتا رکھیں

Canonical page: https://phishdestroy.github.io/TgWitness/ur/docs/server/

جمع کنندہ کو دستیاب رکھیں اور اس کے ڈیٹا کو دوبارہ شروع کرنے پر بھی سالم رکھیں۔

## لانچ کا طریقہ منتخب کریں

مقامی تنصیب کے لیے [deploy/](https://github.com/phishdestroy/TgWitness/blob/main/deploy/README.md) میں موجود [لانچر](https://phishdestroy.github.io/TgWitness/ur/docs/start/) اور سروس مثالوں کا استعمال کریں۔ Docker کے لیے Compose کے ساتھ Docker انسٹال کریں اور پروجیکٹ ڈائریکٹری سے چلائیں:

```
docker compose up -d --build --wait
docker compose exec tgwitness cat /data/panel-token.txt
```

ڈیفالٹ پینل ہوسٹ کے لوپ بیک ایڈریس، پورٹ 8787 پر سن کرتا ہے۔ اسے مقامی طور پر یا SSH ٹنل کے ذریعے کھولیں۔ پینل کو انلاک کرنے کے لیے دوسری کمانڈ سے حاصل کردہ ٹوکن استعمال کریں۔

## پورے ڈیٹا ڈائریکٹری کو برقرار رکھیں

مقامی تنصیبات `data/live` استعمال کرتی ہیں۔ Docker مستقل `tgwitness-data` والیوم استعمال کرتا ہے۔ جرنلز، اکاؤنٹ سیشنز، کیز اور آپریشنل حالت کو ایک ساتھ رکھیں۔ ایک دستخط شدہ ایکسپورٹ مفید ثبوت ہے، لیکن یہ مکمل تنصیب کا بیک اپ نہیں ہے۔

1. مستقل بیک اپ لینے سے پہلے جمع کرنا بند کریں۔
2. پورے نجی ڈیٹا ڈائریکٹری کو ہوسٹ کے باہر محفوظ ذخیرہ میں نقل کریں۔
3. بیک اپ پر انحصار کرنے سے پہلے ایک الگ تنصیب میں بحالی کا ٹیسٹ کریں۔

## ری اسٹارٹ کے بعد چیک کریں

متوقع ورک اسپیس اور کلید، ٹیلیگرام کنکشن، منتخب ذرائع اور نئے پیغام کی گرفتاری کی تصدیق کریں۔ محفوظ شدہ MTProto حالت اور catch-up مدد ان اپ ڈیٹس کو بازیاب کرنے میں مدد کرتی ہے جو ٹیلیگرام اب بھی برقرار رکھتا ہے۔ یہ ہر ختم شدہ اپ ڈیٹ یا گرفتاری سے پہلے حذف شدہ ترمیم کو دوبارہ تشکیل نہیں دے سکتے۔

کنٹینر کی صحت کا مطلب ہے کہ ویب سرور جواب دے رہا ہے۔ جمع اور بیرونی اشاعت کا جائزہ لینے کے لیے ایک کنٹرول شدہ پیغام اور ایک ویٹنس چیک استعمال کریں۔

## صرف وہی شائع کریں جو آپ کا ارادہ ہو

نفاذ کے حوالے میں HTTPS کی مثالیں، مستقل حجم کے احکامات، اپ ڈیٹ اور بحالی کے مراحل شامل ہیں۔ نفاذ کے لیے Docker کے احکامات فراہم کیے گئے ہیں؛ موجودہ [توثیق ریکارڈ](https://phishdestroy.github.io/TgWitness/ur/docs/reference/verification/) ان ماحول کی نشاندہی کرتا ہے جو حقیقت میں آزمائے گئے ہیں۔
