# プロキシを選択してください

Canonical page: https://phishdestroy.github.io/TgWitness/ja/docs/proxies/

アカウントの接続を維持してください。そのルーティングでサーバーのアドレスを使用するタイミングを明確に決定してください。

## まずIPモードを選択してください

01**IPを隠す**

プロキシをご利用ください。どのプロキシも機能しない場合は、Telegramへの直接接続を行わずに待機してください。

02**フォールバックを許可する**

設定された遅延時間が経過した後に直接接続を許可し、応答があった場合は正常に動作しているプロキシに戻ります。

03**トンネル / VPN**

ホストのネットワークを経由する直接接続を許可します。このオプションでは、VPNのインストールや検証は行われません。

ルートによって接続方法が決定されます。IPモードによって、直接接続が許可されるかどうかが決まります。

## ルートはプールに任せておきましょう

1. **「アカウント」→「設定」→「接続設定」**を開いてください。
2. IPモードと**自動MTProxy**を選択するか、固定ルートを入力してください。
3. **「Telegram接続テスト」**を保存して実行してください。ログイン前でも動作します。
4. 収集を開始した後、指定したメッセージがジャーナルに正しく記録されているかご確認ください。

新しいワークスペースでは、IPアドレスを隠蔽する機能を備えた自動MTProxyが使用されます。このプロキシプールは4つの公開ソースを組み合わせ、エントリを調査し、機能しているルートを維持し、機能不全のプロキシを置き換えます。ダウンロードに失敗した場合でも、以前のスナップショットは保持されます。

## ご自身のプロキシをご利用ください

SOCKS5 または HTTP CONNECT の詳細を入力するか、対応している Telegram プロキシのリンクを貼り付けるか、オペレーターカタログを指定してください。アクティブなルートを変更する前に、監視を一時停止してください。`ee` で始まる偽の TLS MTProxy シークレットは、引き続きサポートされていません。

**ローテーション、共有、再試行の設定**

**「パラメータ」→「自動MTProxy」**で、失敗閾値、クールダウン、計画的なローテーション、およびプロキシごとのアカウント数を設定してください。共有制限を「1」に設定すると、排他的なエントリが利用できない場合、アカウントは待機状態になります。リストの更新間隔およびプローブ間隔は、メインワークスペースの設定値に従います。個別のプロキシを使用しても、個別の出口IPが保証されるわけではありません。

## Telegramと外部からのリクエストを分離する

MTProxyはTelegramのトラフィックのみを転送します。タイムスタンプ、通知、コピー、および送信元確認には、別のSOCKS5/HTTPプロキシ、アカウントのSOCKS5/HTTPルート、またはIPモードが許可している場合はDirectが使用されます。これらの外部リクエストは無効にすることができます。

明示的な`TGWITNESS_PROXY_FEED_PROXY`の設定により、フィードダウンローダーのルーティングが構成されます。[独立したウィットネス](https://phishdestroy.github.io/TgWitness/ja/docs/witness/)は独自の設定を維持します。これらの制御機能は、システムVPNをインストールしたり、ブラウザのトラフィックをルーティングしたりすることはありません。

[すべてのモード、デフォルト設定、ソースリスト](https://phishdestroy.github.io/TgWitness/ja/docs/reference/connection/#ip-modes)を確認するか、[アカウントのルーティングを変更できるユーザーを選択してください](https://phishdestroy.github.io/TgWitness/ja/docs/access/)。
