## הכינו בוט וערוץ

צרו בוט באמצעות BotFather ואפשרו לו לפרסם בערוץ שבשליטתכם. בחרו מחשב או שרת עבור ה-Witness. מארח ומפעיל נפרדים מספקים עצמאות רבה יותר מאשר תהליך משני בשרת של האספן.

## שלושה שלבים ב"תוספות"

1. **גישה לקריאה בלבד.** פתחו **את "Extras" → הוסיפו בוט לערוץ שלכם**, צרו אסימון עד (witness token) ושמרו את קובץ הגישה. הכלי מאפשר קריאת נקודות ביקורת ומצב תקינות, אך לא שיחות או הגדרות האספן.
2. **ערוץ ומרווח זמן.** הזן את הערוץ ואת כתובת האספן הנגישה מה-witness. שמור את קובץ ההגדרות.
3. **השקה.** יש למקם יחד את `witness.json`, `witness-token.txt` ו-`bot-token.txt` שנוצרו במארח ה-witness. יש להריץ את הפקודות שלהלן בסביבת הפרויקט המותקנת.

```
python -m tgwitness.witness run --config witness.json --check-config
python -m tgwitness.witness run --config witness.json
```

הורדת הקבצים אינה מפעילה את ה-Witness. יש לוודא שההודעה החתומה הראשונה מופיעה בערוץ, ולאחר מכן לשמור בנפרד את טביעת האצבע של המפתח הציבורי של ה-Witness.

## בחרו את תדירות הפרסום

פרסום כל בדיקה יוצר תיעוד חיצוני קבוע. במרווחים של חמש דקות, מדובר בכ-288 פרסומים לכל סביבת עבודה ביום. ההגדרות המתקדמות מציעות גם פרסום על שינויים או בעיות, פרוקסי וכתובת API מותאמת אישית לבוט.

**על מה בדיוק מעיד הבוט?**

ה-Witness מבקש מה-Collector נקודת ביקורת חתומה, מאמת אותה מול המפתח הצפוי ושומר יומן חתום נפרד. הוא מתעד תגובות חסרות ותשובות שנדחו, כמו גם בדיקות מוצלחות. הפרסום עדיין תלוי בכך שה-Witness פועל ומגיע ל-Bot API של Telegram.

הכלי בודק את מצב היומן המדווח על ידי האספן. הוא אינו עוקב באופן עצמאי אחר כל הודעת טלגרם. לשם כך, יש להוסיף את בדיקת המסירה המבוקרת.

## בדקו את הראיות מאוחר יותר

שמור את יומן העדים, את ההודעות בערוצים ואת טביעות האצבעות שנשמרו באופן עצמאי. [הליך האימות המלא](https://phishdestroy.github.io/TgWitness/he/docs/reference/witness/#verify) משווה אותם לייצוא החתום של האספן.
