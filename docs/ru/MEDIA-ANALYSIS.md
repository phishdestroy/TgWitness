# Локальное распознавание текста и транскрипция

[Руководство по рабочему процессу](https://phishdestroy.github.io/TgWitness/docs/archive/) · [Вики](../wiki/Archive-and-Integrations.md)

Откройте запись журнала `media.saved`, выберите **Распознать вложение**, затем выберите «OCR» или «транскрипция» в разделе **Дополнительные инструменты → Запросить у архива** (называется **Машинное распознавание,** если ИИ архива отключен). Обработка осуществляется вручную и локально. Режим облачного хранения медиафайлов и автоматическая загрузка отсутствуют. Исходные байты вложения и хеш `media_sha256` остаются неизменными; распознанный текст явно помечается как «машинное распознавание» и хранится отдельно с указанием исходного хеша, версии движка/модели, языка, параметров и времени завершения. В транскрипциях сохраняются возвращённые временные метки.

Вы можете выполнять поиск по этим результатам с помощью **функции Поиск по распознанному тексту** и фильтра OCR/транскрипции либо выбрать распознанный текст в качестве источника для поиска «Лучшее совпадение» **в журнале**. Оба метода сопоставляют формы слов с помощью [индекса в оперативной памяти](SEARCH.md#recognized-text). Это отдельный поиск по производным данным; он не преобразует автоматическое распознавание в исходный текст Telegram без уведомления и не добавляет его к подписанным событиям.

<a id="set-up-the-optional-worker"></a>
## Настройте дополнительный рабочий процесс

Версия 1 требует хоста под управлением Linux с локальным демоном Docker. В среде Windows TgWitness можно запускать внутри виртуальной машины Linux или среды WSL с собственным локальным демоном. Панель никогда не декодирует недоверенные вложения самостоятельно.

```sh
docker build -f deploy/media-worker/Dockerfile -t tgwitness-media:local .
export TGWITNESS_MEDIA_IMAGE=tgwitness-media:local
```

Задайте эти переменные в среде службы TgWitness и перезапустите её. По умолчанию сокет демона находится в `/var/run/docker.sock`; при развёртывании без прав root можно задать переменную `TGWITNESS_DOCKER_SOCKET`. Рабочий процесс явно использует этот сокет Unix, а не удалённый контекст Docker. Не предоставляйте доступ к API Docker пользователям панели и не монтируйте его сокет внутри контейнера распознавания.

Для транскрипции отдельно установите модель Whisper, совместимую с CTranslate2, а затем задайте `TGWITNESS_WHISPER_MODEL_DIR` в качестве пути к её каталогу. Рабочий процесс загружает её с параметром `local_files_only=True`; выбранная модель и входные данные монтируются в режиме «только для чтения». Ознакомьтесь с [документацией по загрузке моделей](https://github.com/SYSTRAN/faster-whisper) данного движка. Поставляемое изображение OCR содержит обучающие данные на английском и русском языках. При необходимости добавьте в свой образ другой язык; коды языков соответствуют [CLI Tesseract](https://tesseract-ocr.github.io/tessdoc/Command-Line-Usage.html).

Во время обработки модели не загружаются. При сборке или загрузке установочного пакета может использоваться сеть; в каждом контейнере фактического распознавания сетевые функции отключены. Установите образ перед его включением; в режиме выполнения используется параметр ``--pull=never``.

<a id="bounds-and-recovery"></a>
## Ограничения и восстановление

Контейнер запускается от имени пользователя без привилегий с корневым каталогом, доступным только для чтения, с ограниченными возможностями, параметром `no-new-privileges`, одним процессором, 2 ГБ памяти, ограничением на количество PID и ограниченной временной файловой системой. Монтируются только проверенная копия выбранного файла и, по желанию, каталог с моделями. База данных сборщика, хранилище и сеансы не монтируются. [Флаги среды выполнения Docker](https://docs.docker.com/reference/cli/docker/container/run/) обеспечивают соблюдение этих ограничений; это остаётся границей контейнера, а не аппаратным анклавом.

Размер файлов ограничен 50 MiB, изображений — 20 миллионами пикселей, аудиозаписей — 30 минутами при известной продолжительности, а время обработки — пятью минутами. Одновременно работает один рабочий процесс, при этом в очереди или в процессе выполнения может находиться не более 20 заданий, а в рабочей области — не более 100 сохраненных заданий. Команда «Cancel» останавливает контейнер; команда «retry» создаёт новое задание, связанное с предыдущей попыткой. Прерванные задания помечаются после перезапуска. Обработка может завершиться сбоем, если модель не укладывается в заданные ограничения; без изоляции она не выполняется в фоновом режиме.
