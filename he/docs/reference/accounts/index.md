# Telegram · חשבונות ופורמטים של הפעלות

Canonical page: https://phishdestroy.github.io/TgWitness/he/docs/reference/accounts/

התחברו באמצעות טלפון, קוד QR או מפתח אימות, ייבאו הפעלות מ-Telethon, Pyrogram או Telegram Desktop, והפעילו מספר חשבונות.

[TgWitness](https://github.com/phishdestroy/TgWitness/blob/main/README.md) / [תיעוד](https://github.com/phishdestroy/TgWitness/blob/main/docs/README.md) · [התחלת עבודה](https://phishdestroy.github.io/TgWitness/he/docs/reference/quickstart/)

![התחלת עבודה](https://phishdestroy.github.io/TgWitness/assets/chapter-start.svg)

TgWitness מתחבר כחשבון **משתמש טלגרם** (לא כבוט) באמצעות MTProto, תוך שימוש ב- Telethon. כל חשבון פועל בס**ביבת** עבודה משלו (המכונה "*סביבת עבודה*" ב- API ובכלי שורת הפקודה) עם הפעלה, מקורות, יומן ומפתח חתימה משלו.

קובצי הפעלה, מחרוזות הפעלה ומפתחות אימות (Auth Keys) הם **אישורי גישה לחשבון**: מי שמחזיק באחד מהם יכול לפעול בשם אותו חשבון. הם אינם מכילים היסטוריית הודעות.

> [!אזהרה] **אל תשתמשו בשום דבר שאינכם יכולים להרשות לעצמכם לאבד.** אנו ממליצים בחום להימנע מחיבור חשבונות אישיים או בעלי ערך אחר, וכן מיצירת מזהה API / חתימת API על חשבון שחשוב לכם. זה לא קשור לכך ש-TgWitness לא נבדק: טלגרם מגביל ו חוסם חשבונות לצמיתות באופן בלתי צפוי — כאשר נפח הבקשות נחשב בעיניו כמופרז, ללא תלות בלקוח או במטרה, וללא תיעוד הולם. חסימות רבות הן בלתי הפיכות. השתמשו בחשבונות ייעודיים. תפקוד חלק של הבדיקות תלוי ב-Telegram, ולא בתוכנה, ואינו מבטיח דבר לעתיד.

TgWitness מזהה קבצים לפי **תוכנם**, ולא לפי שמותיהם. שינוי שם של קובץ לעולם אינו מוביל להמרתו.

## לפני שתתחילו: מזהה API ו-hash של API

ניתן להתחבר ללא יצירת יישום API של Telegram. כאשר לא הוזן זוג, לא יובא או כבר נשמר בסביבת העבודה, TgWitness בוחר זוג ממאגר מובנה של זוגות API ציבוריים של 50 (`tgwitness/api_pool.py`), תוך מתן עדיפות ל-Telegram Desktop עבור כניסה חדשה ושמירת הזוג שנשמר קודם; המועמדים הנותרים מעורבבים. אם Telegram דוחה זוג (`API_ID_INVALID`, `API_ID_PUBLISHED_FLOOD`, `UPDATE_APP_TO_LOGIN`), נבדק הזוג הבא, עד שמונה זוגות לכל כניסה; זוגות שנדחו מדלגים עליהם עד להפעלה מחדש. הזוג ששימש לכניסה נשמר עם החשבון ומשמש שוב עבורו. מזהה API **(**) והאש **API (**) מזהים את היישום בפני Telegram; הם אינם מאשרים חשבון בפני עצמם.

שדות חיבור חסרים משתמשים בזוג דטרמיניסטי של מכשיר/מערכת הפעלה מתוך קטלוגים [opentele2 2.0.0](https://github.com/DedInc/opentele2/tree/7e973bc71cd7a714ad13ac703c0895a90d36a735) המצורפים: Desktop `2040`, Android `6`, Android X `21724`, iOS `10840`, macOS `2834` ו-Web `2496`. מזהה ה-source-build של Android `4` משתמש גם הוא בקטלוג Android, כפי שזוהה ב- [BuildVars של Telegram Android](https://github.com/DrKLO/Telegram/blob/master/TMessagesProj/src/main/java/org/telegram/messenger/BuildVars.java). ה-Web מוגדר כברירת מחדל ל-A; סיומת גרסת אפליקציה מיובאת `K` או חבילת שפה `macos` בוחרת K, והגרסה `0.7.0` בוחרת Webogram. מזהי יישומים לא ידועים שומרים על הגדרות ברירת המחדל של Telethon. שדות מיובאים תמיד גוברים, כולל גרסת יישום ישנה יותר וחבילת שפה ריקה. הקטלוג לעולם אינו משנה את מזהה ה-API/ה-hash. תמונת המצב של הגרסה שלו נבדקת במפורש, ולא נטענת במהלך הכניסה. פרופיל שמור נשאר יציב לאחר עדכונים.

`account.getAuthorizations` מדווח על מטא-נתוני ההרשאה השמורים של Telegram; זהו לא שיקוף של כל `initConnection` חדש. יש להשוות אותו לפרופיל שנשלח בפועל. חיבור הרשאה קיימת אינו מאמת את ה-hash של ה-API הנלווה אליה: `initConnection` שולח את מזהה ה-API, בעוד שה-hash משמש בבקשות כניסה.

לאחר אימות באמצעות טלפון חדש או QR, TgWitness מבקש תצורה, מרכז נתונים (DC) הקרוב ביותר, סטטוס מקוון, שפות (כאשר חבילת השפות אינה ריקה), עדכוני אפליקציה ו עדכוני תנאי השירות, עם מרווח של 0.3–1.5 שניות בין בקשות. עדכון הסטטוס מסמן את החשבון כמקוון לזמן קצר. רצף זה פועל פעם אחת עם השלמת הכניסה, ולא בעת ייבוא, חיבור מחדש או הפעלה מחדש. האישור נשמר תחילה; בקשה שנכשלה עוצרת את הרצף מבלי לנסות שוב או לבטל את הכניסה. התוצאות נרשמות כ-`account.initialized`, עם שמות שגיאות במקום תוכן התגובה. הרצף אינו מהווה ערובה כנגד הגבלות על החשבון.

עבור `tdesktop` , כאשר `tz_offset` חסר, נעשה שימוש בהפרש ה-UTC המקומי של השרת, המעוגל ל900 שניות באמצעות אלגוריתם [opentele2](https://github.com/DedInc/opentele2/blob/7e973bc71cd7a714ad13ac703c0895a90d36a735/crates/opentele2-core/src/fingerprint.rs) (MIT; הרישיון ב`tgwitness/client_profiles.LICENSE` ). הוא מתעדכן בכל חיבור, כך ששינויים בשעון הקיץ באים לידי ביטוי. `tz_offset` מיובא מקבל קדימות בכל פלטפורמה ונשמר במדויק, כולל אפס. ערכים אחרים ב- `initConnection.params` נשמרים. טופס הכניסה ב-HTTP מקבל את אזור הזמן המספרי המוחזר על ידי ייבוא הקובץ; ערכים בוליאניים, שברים וסטיות מחוץ לטווח הנתמך נדחים.

נתיבי Direct, SOCKS5 ו-HTTP CONNECT משתמשים ב-`ConnectionTcpObfuscated` של Telethon (MTProto מקוצר ומוסתר). HTTPS CONNECT שומר על TLS לפרוקסי ומשתמש באותו תעבורת נתונים מוסתרת בתוך המנהרה. MTProxy שומר על תעבורת הביניים האקראית הנדרשת ועל הטיפול בסודות. מעברי מסלולים מיישמים את אותן בחירות. ההסתרה משנה את מבנה החבילות; היא אינה מסתירה את החשבון או את מטא-הנתונים של הלקוח שלו מ-Telegram ואינה מרמזת על חסינות מפני הגבלות.

לאחר חיבור לקוח מורשה, ה-TgWitness בודק את התצורה, את מרכז הנתונים הקרוב ביותר, את ההרשאה הנוכחית, את קו הבסיס של השכבה שנבדקה, את השפות, את עדכוני האפליקציה ואת עדכוני תנאי השירות. אבחונים אלה מתבצעים פעם אחת לכל מופע לקוח, לפני האיסוף, ומוצגים תחת פרטי החיבור עם הזמן שבו בוצעו. `account.connection_checked` מתעד את התוצאה ללא חשישי הפעלה, כתובות IP, אסימונים או חשישי API. הוא לעולם אינו מקבל תנאים או מתקין עדכונים. כישלון בבקשה או מצב FloodWait עוצרים בקשות עוקבות; תוצאה חסרה נשארת בלתי ידועה. בדיקות מקומיות עדיין יכולות לדווח על תוצאותיהן בעוד שבדיקות רשת מדלגות.

אבחון FloodWait שומר את שיטת ה-TL שנכשלה, כל עטיפות ה-Takeout/range, ההמתנה שביקש השרת ומועד הסיום האפקטיבי ב-`telegram.backoff`. פרטי החיבור מציגים את השיטה ומועד הסיום בזמן שהבקשות מושעות. האבחון כולל מוני קריאות לקוח לכל שיטה מאז שנוצר אותו לקוח; הם סופרים בנפרד פתרון עמיתים מקונן, אך אינם סופרים מנות או ניסיונות ניסיון חוזר פנימיים של Telethon. המונים הנוכחיים זמינים גם כ- `collector.rpc_activity`ב-API הסטטוס. אין כל ארגומנטים של בקשה, שמות משתמש, חשישי גישה או טקסט חריגה. האבחון האחרון ומועד הסיום המלא נשמרים גם לאחר הפעלה מחדש. המתנות קודמות ללא רשומת שיטה אינן ניתנות לייחוס בדיעבד. ראה [מגבלות ייצוא](https://github.com/phishdestroy/TgWitness/blob/main/docs/EXPORT-LIMITS.md) לבדיקת המקור ו להבחנה בין גילוי לרכישת היסטוריה.

`official_app=True` או `False` הם דגלי ההרשאה הנוכחיים של Telegram. אף אחד מהערכים אינו קובע אם החשבון מוגבל, אמין או נמצא תחת תצפית. תמונות המצב (`account.devices`) הקיימות במצב הראיות נשארות כהיסטוריה של כל המכשירים המחוברים; אבחון החיבור שומר רק את תיאור המכשיר הנוכחי.

לפני החיבור, בדיקות ייעוץ משוות את פלטפורמת ה-API, חבילת השפה, פורמטי המכשיר/מערכת ההפעלה וגרסת האפליקציה, הגדרות השפה של מערכת המובייל, ואת שכבת הסכימה בפועל של Telethon מול קו הבסיס של הקטלוג שנבדק. אזהרות מופיעות ביומן השרת ובמטא-נתוני מצב החשבון; הן לעולם אינן מחליפות ערכים מיובאים או משנות את שכבת הסכימה. שכבה שונה מהווה אות לבדיקת תאימות, ולא הוכחה ל חשבון פגום או מוגבל. בדיקות אלו ו-`official_app` אינן מאשרות כי Telegram רואה את החשבון כבטוח מפני הגבלות. מצב חשבון מנותק משתמש בפרופיל השמור במקום ליצור תיאור מכשיר אחר.

כדי להשתמש במקום זאת ביישום משלכם (החשבון שרושם אותו הוא זה שנמצא בסיכון; ראו " [מדוע מאגר API מובנה?](https://github.com/phishdestroy/TgWitness/blob/main/docs/PROJECT-GUIDE.md#connect-a-telegram-account)"):

1. פתחו את [my.telegram.org](https://my.telegram.org) והתחברו באמצעות כל מספר טלפון שבבעלותכם. הקוד יגיע לאפליקציית טלגרם, ולא באמצעות SMS.
2. בחרו **כלי פיתוח API**.
3. יצירת יישום: כל כותרת ושם קצר (5–32 אותיות), פלטפורמה: **שולחן עבודה**. ניתן להשאיר את שדה ה-URL והתיאור ריקים.
4. העתיקו **את ה-api_id של האפליקציה** (מספר) ואת **ה-api_hash של האפליקציה** (32 תווים הקסדצימליים).

בלוח הבקרה, תחת טופס הכניסה, מופיעים **שדות "מזהה API" ו-"Hash"**. ניתן להדביק זוג `api_id:api_hash` יחיד בשדה "**מזהה API**" ושני השדות יתמלאו. ניתן להשתמש בזוג אחד לכל החשבונות שלכם. לאחר כניסה מוצלחת, הנתונים נשמרים, מוצפנים, במרחב העבודה הספציפי הזה בלבד, ואינם נשלחים חזרה לדפדפן.

מדובר בשלושה אישורים שונים:

| סודי | נפתח | היכן ניתן למצוא אותו |
| --- | --- | --- |
| אסימון פאנל | לוח הבקרה המקוון של TgWitness | `panel-token.txt` בספריית הנתונים, או `TGWITNESS_TOKEN` |
| מזהה API + hash | אין כאן מידע בפני עצמו; מזהה את האפליקציה | זוג מובנה, הגדרות מיובאות או האפליקציה שלכם ב-my.telegram.org |
| אימות חשבון | חשבון הטלגרם | נוצר באמצעות כניסה בטלפון/QR או יובא כפעילות |

אם יש צורך לגשת ל-Telegram דרך פרוקסי, יש להגדיר זאת תחילה תחת **חשבון → הגדרות → הגדרות חיבור → שינוי נתיב החיבור**.

## מספר טלפון

1. פתחו **את החשבון**, עברו לכרטיסייה **"טלפון**" והזינו את המספר בפורמט בינלאומי, לדוגמה `+44 7700 900123`. רווחים וקווים מפרידים מוסרים באופן אוטומטי.
2. לחץ על "**המשך**". שדות "מזהה API" ו-"Hash" יכולים להישאר ריקים.
3. הזן את הקוד ש-Telegram שולח (בדרך כלל לאפליקציית Telegram; אין ערובה לקבלת ה-SMS).
4. אם לחשבון יש אימות דו-שלבי, הזן את הסיסמה הזו. זו אינה אסימון הפאנל ואינה קוד הגישה למכשיר.
5. בדקו את מזהה החשבון המופיע לאחר הכניסה, ולאחר מכן בחרו מקורות.

קודי הכניסה והסיסמה ל-2FA לעולם אינם נשמרים בדיסק.

## קוד QR

יש להשתמש בכך כאשר החשבון כבר מחובר בטלפון או במחשב אחר.

1. לשונית **"קוד QR**" → **הצג קוד QR**. שדות "מזהה API" ו-"Hash" יכולים להישאר ריקים.
2. במכשיר שבו אתה מחובר: **הגדרות → מכשירים → קישור למכשיר שולחני**, סרוק את הקוד ואשר.
3. הזן את סיסמת ה-2FA ב-TgWitness אם Telegram מבקש זאת.

תמונת ה-QR נוצרת באופן מקומי. לקודים יש תוקף; לחץ על "**צור קוד QR נוסף"** כדי לנסות שוב. נעילת הלוח, מעבר לסביבת עבודה אחרת או התחלת כניסה נוספת מבטלת קוד בהמתנה.

## מפתח אימות + מזהה DC

מפתח אימות (Auth Key) הוא מפתח האימות הגולמי בן 256 בתים העומד בבסיס כל הפעלה של טלגרם, הכתוב **כ-512 תווים הקסדצימליים**, יחד עם מספר מרכז הנתונים **DC 1–5**.

1. **מפתח אימות** Tab. הדביקו את המפתח המלא; מפתח מקוצר המכיל את `…` לא יפעל.
2. בחר את מזהה ה-DC שסופק עם המפתח.
3. ניתן להזין את **מזהה המשתמש (User ID**). במקרה כזה, TgWitness יסרב להתחבר אם Telegram מדווח על חשבון שונה.
4. **חשבון** Press **Connect**.

מפתח אימות (512 תווים) אינו חתימת API (32 תווים). ניתן גם לייבא את אותו המפתח כקובץ JSON; ראו [JSON של החשבון](https://phishdestroy.github.io/TgWitness/he/docs/reference/accounts/#account-json).

## קובצי חשבונות

פתח את **"הוסף חשבון" →**"**קבצים**" ובחר עד **ארבעה קבצים השייכים לחשבון אחד**, בהיקף כולל של **8 MiB**, ולאחר מכן לחץ על "**חבר חשבון**".

הטפסים **Files**, **Auth key** ו-bulk-import מציגים את אזהרת ההפעלה המקבילה לפני ההתחברות. כברירת מחדל, אישורים מיובאים משמשים שוב. יש להשאיר את הלקוח המקורי סגור בזמן שהמפתח שלו נמצא בשימוש כאן. **Files** ו-**Auth key** מציעים גם **Create אישור עצמאי**, המתואר להלן. ייבוא המוני עדיין משתמש במצב הישיר. כניסה באמצעות טלפון ו-QR אינטראקטיבי יוצרת אישורים נפרדים. כותרת האזהרה נשארת גלויה בטופס הייבוא; ההסבר המלא שלה נפתח באופן אוטומטי כאשר מסופקים קבצים או מחרוזת מפתח/הפעלה. ניתן לקפל אותה לאחר הקריאה, כך שבוחר הקבצים ופקדי החיבור יישארו שמישים בטלפון.

- הקבצים מומרים **בזיכרון** בשרת ה-TgWitness שלכם. הקבצים המועלים אינם נשמרים, קבצי ZIP אינם נפרקים לדיסק ואין יצירת קשר עם שירות חיצוני כלשהו.
- הפעילות שהתקבלה נבדקת לאחר מכן מול טלגרם. אם קובץ מציין מזהה משתמש, עליו להתאים לחשבון שטלגרם מדווח עליו.
- קובצים המתארים חשבונות שונים או פרטי הזדהות שונים ל-API נדחים במקום לבחור באחד מהם.
- שדה **"Passcode" או "session text"** מכיל את שדה הסיסמה המקומית של TData, תיבה להדבקת StringSession **וקריאת קבצים ללא צורך בהתחברות** (ממלא את הטופס מבלי ליצור קשר עם Telegram).

### יצירת אישור עצמאי

בחר **צור אישור עצמאי** לפני חיבור קבצים מיובאים או מפתח אימות. TgWitness מחבר את התורם המיובא לזמן קצר, משתמש בו כדי לאשר את אסימון הכניסה QR של הלקוח החדש, ומנתק את התורם מיד לאחר האישור. ללקוח החדש יש מפתח אישור משלו ופרופיל שולחן עבודה שנבחר בנפרד . פרטי הזיהוי של ה-API ופרופיל המכשיר שסופקו על ידי התורם משמשים אך ורק לחיבור התורם. אף אישור קיים אינו מתנתק או מבוטל.

**יש להשאיר את הלקוח המקורי של התורם סגור לחלוטין במהלך שלב זה.** החיבור הראשוני עדיין משתמש במפתח שהועתק, ולכן מצב זה אינו יכול להסיר את הסיכון הראשוני של שימוש מקביל. ברגע שהאישור החדש מחובר, הבעלים יכול לפתוח מחדש את הלקוח המקורי ולהשתמש בשניהם באופן עצמאי. כניסה אינטראקטיבית **באמצעות קוד QR** מאפשרת ללקוח המקורי לאשר את הכניסה מבלי להעתיק או לחבר את המפתח שלו כאן.

אם Telegram מבקש 2FA, מצב זה משתמש ב-`twoFA` מה-JSON הנבחר כאשר הוא קיים, או מבקש את הסיסמה. סיסמה מיובאת שנדחתה מחזירה את המשתמש לטופס הסיסמה. סיסמאות אינן נשמרות. המפתח המועמד נשמר מוצפן ב- `independent_login.enc`, כולל שינויים במהלך העברת נתונים בין מרכזי נתונים. לאחר הפרעה, בחר באותו תורם ובאפשרות זו כדי לחדש את המפתח המועמד שנשמר. סביבת העבודה נשארת שמורה לחשבון זה; השלמה כושלת אינה מוחקת את סביבת העבודה החדשה. שמור את ספריית הנתונים ומפתח הכספת שלה. פרטי ההזדהות הסופיים ורשומת היומן ב- `account.authorized` כוללים את שיטת הייבוא, פורמטי הקלט ו- מזהה ה-API של התורם, ללא מפתח התורם או הסיסמה.

ב-5 בנובמבר 2026, חשבון ייעודי עבר בדיקות בזמן אמת עם תורמי Telethon, Pyrogram ו-TData: השלמת אימות דו-שלבי (2FA), מפתחות אישור חדשים ונפרדים, גישה בו-זמנית על ידי התורם והלקוח החדש, וקריאת ערוץ ציבורי. במקרה של Telethon גם הוחזר מועמד שנשמר לאחר הפרעה בשלב הסיסמה. כל אימות חדש השלים את שש בקשות האתחול לאחר הכניסה, והיומן החתום שלו אומת. ההפעלה המקורית נותרה שמישה בכל ארבעת הפורמטים שסופקו.

מאגר שגיאות ה-[RPC של Telegram](https://core.telegram.org/api/errors.json) מקשר את `FRESH_CHANGE_ADMINS_FORBIDDEN` לשינוי מנהלים, את `FRESH_CHANGE_PHONE_FORBIDDEN` לשינוי מספר הטלפון, ואת `FRESH_RESET_AUTHORISATION_FORBIDDEN` ל ביטול הפעלות אחרות, שינוי משך הזמן שלהן או רישום מפתח גישה. `SESSION_TOO_FRESH_*` ו-`PASSWORD_TOO_FRESH_*` נוגעים להעברות בעלות ול משיכת הכנסות או מתנות. אלה אינן פעולות גבייה; התחברות חדשה אינה מרמזת על איסור קריאה גורף למשך 24 שעות. הייצוא יכול להחזיר בנפרד את `TAKEOUT_INIT_DELAY_*`. TgWitness שומר על הפסקות שביקש השרת ואינו מנסה שוב לקבל את האסימון באופן אוטומטי או לבטל הפעלות כדי לעקוף הגבלות.

### Telethon `.session`

|  |  |
| --- | --- |
| מה זה | מסד הנתונים SQLite שהכלים המבוססים על Telethon יוצרים, לדוגמה `my_account.session` |
| מוכר על ידי | טבלאות `sessions` (יחד עם `dc_id`, `server_address`, `port`, `auth_key`) ו-`version` = 7 או 8 |

סגור תחילה את התוכנית שיצרה את הקובץ. אם `my_account.session-journal` או `my_account.session-wal` קיימים לצדו, מסד הנתונים אינו סופי: פתח ו סגור את הלקוח המקורי כהלכה. מחיקת קבצי ה-sidecar הללו עלולה להשאיר עותק פגום.

### Pyrogram `.session`

|  |  |
| --- | --- |
| מה זה | כלי מבוססי Pyrogram ליצירת מסד נתונים SQLite |

מזהה המשתמש המאוחסן נבדק מול טלגרם במהלך הכניסה.

### צמד של סשן + JSON

לעתים קרובות, החשבונות מופצים כשני קבצים בעלי אותו שם, לדוגמה `447700900123.session` ו-`447700900123.json`. יש לבחור **בשניהם** בבת אחת.

- מתוך קובץ ה-JSON, TgWitness משתמש ב-`app_id`/`api_id` וב-`app_hash`/`api_hash`, כך שבדרך כלל אין צורך להזין פרטי הזדהות ל-API.
- פרופיל החיבור משתמש ב-`device_model` (כינוי `device`), `system_version` (כינוי `sdk`), `app_version`, `lang_code`, `system_lang_code` (כינוי `system_lang_pack`), `lang_pack` ו-`tz_offset` אופציונלי (שניות מ-UTC, מ-43200 עד 50400). לשדות שסופקו יש עדיפות על פני ברירות המחדל שנוצרו ועל פני שפת הלוח/הדפדפן . כינויים סותרים נדחים. הפרופיל המוגדר נשמר ב אישורי סביבת העבודה המוצפנים ומופעל מחדש לאחר הפעלה מחדש, כולל גרסת האפליקציה שלו.
- `phone`, הגדרות פרוקסי ואסימוני מכשיר **מתעלמים מהם**. `twoFA` הוא לקריאה בלבד כאשר **יצירת אישור עצמאי** נבחר; ייבוא ישיר מתעלם ממנו.
- קובץ JSON ללא שדה אימות נתמך הוא רק מטא-נתונים. הוסף את קובץ הפעלה שלו או המשך עם כניסה באמצעות טלפון או QR. קובץ JSON המכיל הפעלה נתמכת או מפתח אימות (Auth Key) יכול לאמת את עצמו; ראה [Account JSON](https://phishdestroy.github.io/TgWitness/he/docs/reference/accounts/#account-json).

### Telegram Desktop (TData)

TData היא התיקייה `tdata` של יישום Telegram Desktop (האפליקציה הרב-פלטפורמית מ-desktop.telegram.org).

| מערכת | מיקום ברירת המחדל של `tdata` |
| --- | --- |
| Windows | `%APPDATA%\Telegram Desktop\tdata` (Telegram נייד: ליד `Telegram.exe`) |
| לינוקס | `~/.local/share/TelegramDesktop/tdata` |
| macOS | `~/Library/Application Support/Telegram Desktop/tdata` |

כדי לייבא אותו:

> **אזהרה על הפעלה מקבילה.** ייבוא ישיר של TData עושה שימוש חוזר במפתח ההרשאה של Telegram Desktop. אין להשתמש במפתח זה ב-Desktop וב- TgWitness בו-זמנית. Telegram עלולה לבטל את תוקף ההרשאה באמצעות `AUTH_KEY_DUPLICATED`, מה שיגרום לשתי הגרסאות להיות בלתי שמישות עד לכניסה מחודשת.
>
>
>
> סגור את Desktop לחלוטין, כולל תהליך מגש המערכת שלו, והשאר עותק זה סגור בזמן ש- TgWitness משתמש בהפעלה המיובאת. **סגור, אל תתנתק ואל תבטל את ההפעלה:** ביטול יגרום גם לפסילת העותק המיובא. אם אתם זקוקים לשני הלקוחות פועלים, בחרו **צור אישור עצמאי** והשאירו את Desktop סגור עד שהכניסה החדשה תצליח, או התחברו ל-TgWitness באמצעות טלפון או QR. מומלץ להשתמש בחשבון ייעודי, אך הדבר אינו הופך את המפתחות המשוכפלים לבטוחים לשימוש במקביל.
>
>
>
> זה חל גם על קבצי `.session` מיובאים, טקסט StringSession ומפתח אימות HEX. לקוחות אחרים בעלי אישורים שנוצרו באופן עצמאי יכולים להישאר מחוברים. ראו [את התיעוד של Telegram בנושא AUTH_KEY_DUPLICATED](https://core.telegram.org/api/errors#406-not-acceptable).

1. סגור את Telegram Desktop לחלוטין.
2. צרו קובץ ZIP המכיל **רק** את שני הפריטים הבאים מ-`tdata`:

   - `key_datas`
   - הקובץ בן 16 התווים המסתיים ב-`s` שלצדו, בדרך כלל `D877F783D5D3EF8Cs`

   דחיסת התיקייה כולה עם מטמון המדיה שלה חורגת בדרך כלל מהמגבלות (512 רשומות, 32 MiB לאחר הפריקה). 3. בחרו את קובץ ה-ZIP ב**"קובצים**". אם ל-Telegram Desktop יש **קוד גישה מקומי**, הזינו אותו תחילה בשדה **"קוד גישה" או "טקסט הפעלה"**. זהו לא סיסמת ה-2FA.

נתמך: חשבון אחד לכל ארכיון, אחסון מודרני מסוג `key_datas`/`key_data0`/`key_data1`, קוד גישה מקומי. לא נתמך: תיקיות עם מספר חשבונות מחוברים, פריסות שולחן עבודה ישנות יותר, קובצי ZIP המוגנים בסיסמה, והאפליקציה המקורית הנפרדת של macOS "Telegram for macOS".

### Telethon StringSession

שורת טקסט אחת, המתחילה בדרך כלל ב-`1` ואורכה כ-350 תווים. טען אותה כקובץ `.txt` או `.tgwitness-session` (בגודל של עד 4 KiB), או הדבק אותה תחת **"קוד גישה" או "טקסט הפעלה**". מתקבלות רק מחרוזות Telethon; מחרוזות Pyrogram ו-TDLib משתמשות בפורמטים שונים.

### קובץ JSON של החשבון

אובייקט JSON אחד, בגודל של עד **64 KiB**, בקובץ שמסתיים ב-**`.json`**.

| שדה (כינויים) | משמעות |
| --- | --- |
| `api_id` (`app_id`) | מזהה היישום, מספר חיובי |
| `api_hash` (`app_hash`) | ה-hash של היישום, 32 תווים הקסדצימליים |
| `string_session` (`session_string`, `session_str`; `session` הישן) | טקסט של Telethon StringSession, לא שם קובץ |
| `auth_key` (`auth_key_hex`) + `dc_id` | מפתח אימות מלא בן 512 תווים ו-DC 1–5 |
| `user_id` (`id`) | אופציונלי; נבדק מול טלגרם לפני שמירת ההרשאה |
| `device_model` (`device`) | תיאור מכשיר החיבור |
| `system_version` (`sdk`) | גרסת מערכת ההפעלה של החיבור |
| `app_version` | גרסת האפליקציה שנשלחה ל-Telegram |
| `lang_code`, `system_lang_code` (`system_lang_pack`), `lang_pack` | שפת הלקוח, שפת המערכת וחבילת השפה של הלקוח; מותר להשתמש ב-`lang_pack` ריק |
| `tz_offset` | הפרש זמן אופציונלי ביחס ל-UTC בשניות, הנשלח ב-`initConnection.params`; מספר שלם או מחרוזת של מספר שלם עשרוני |

אם קיימים הן כינוי והן שם ראשי, עליהם להיות זהים. שדות מפורשים של Telethon session מקבלים עדיפות על פני בלוק `session` כללי בפורמט אחר. אם שניהם מכילים Telethon sessions מזוהים, עליהם לתאר את אותה ההרשאה. בהיעדר שדה מפורש, `session` חייב להיות Telethon StringSession תקף. דוגמאות:

```
{ "app_id": 1234567, "app_hash": "0123456789abcdef0123456789abcdef" }
```

```
{
  "api_id": 1234567,
  "api_hash": "0123456789abcdef0123456789abcdef",
  "auth_key": "REPLACE_WITH_ALL_512_HEXADECIMAL_CHARACTERS",
  "dc_id": 2,
  "user_id": 123456789
}
```

בדוגמה הראשונה יש למלא רק את פרטי הזיהוי של ה-API; התחברו באמצעות טלפון או QR, או הוסיפו קובץ הפעלה. רשימות מרוכזות (מערך JSON של חשבונות) אינן מתקבלות.

| תיקייה בשם `tdata` המכילה את `key_datas` | Telegram Desktop TData | דחיסת שני קבצים ב-ZIP, ולאחר מכן **'קבצים'** |

## חשבונות מרובים

לחץ על **+** ליד בורר החשבונות, או פתח **חשבון → הגדרות → הגדרות חיבור → סביבות עבודה**, הזן תווית ו התחבר.

- מספר בלתי מוגבל של סביבות עבודה, כולל הסביבה הראשית. לכל אחת מהן יש הפעלה משלה, מסלול פרוקסי , מקורות, מדיניות לכידה, יומן, מפתח חתימה, נקודות ביקורת וייצוא.
- החלפת סביבת העבודה המוצגת אינה מעכבת את האחרות.
- יומן נשאר מקושר לחשבון שיצר אותו. התחברות מחשבון אחר מחייבת סביבת עבודה נפרדת, ולא ניתן להקצות חשבון אחד לשתי סביבות עבודה.
- אסימון הלוח הראשי שולט בכל סביבות העבודה. [הגישה שהוענקה](https://phishdestroy.github.io/TgWitness/he/docs/reference/access/) יכולה להגביל משתמשים אחרים לחשבונות וצ'אטים נבחרים, עם הרשאות נפרדות ומגבלות על משך ההפעלה.
- **החשבון** משנה את שם סביבת העבודה ומוחק סביבת עבודה שנוספה, יחד עם ההפעלה, היומן, המקורות ומפתח החתימה שלה. לא ניתן למחוק את סביבת העבודה הראשית מהלוח.

### ייבוא מרובה וקבוצות חשבונות

השתמשו **ב-Accounts → Import accounts** כדי להוסיף מספר חשבונות, להתאים קבצים לפי שם בסיס ולראות את תוצאות הכניסה לכל חשבון. לכל חשבון יש סביבת עבודה משלו.

קבוצה מאגדת חשבונות קשורים מבלי למזג את הפעילויות, המפתחות או הראיות שלהם. לחיצה על "**קבוצה פתוחה"** תחת "**חשבונות"** מובילה לדף שלה בכתובת `/groups/<id>`:

- **חשבונות:** מסלול החיבור של כל חבר, תצפית והודעה אחרונה, עם "**התחל הכל"** ו-**"השהה הכל**".
- **דורש תשומת לב:** חשבונות שהתחברו החוצה, אינם זמינים או שיש בהם בעיה בחיבור, בקליטה, במקור או במדיה; כל שם מוביל לכרטיס שלו.
- **בצ'אטים של מספר חשבונות ניתן לראות:** מקורות משותפים, החשבונות העוקבים אחריהם ו הפרעות בתקופת התצפית על סביבת העבודה הזמינה (עד שבעה ימים). **ייצוא עם N חשבונות** מחלק את הייצוא של ערוץ או סופר-קבוצה ביניהם וחותם על ארכיון אחד.
- **ייצוא קבוצה:** תמונה אחת ZIP עם הייצוא החתום של כל חשבון תחת `accounts/` ו `manifest.json` ורשימה של טביעות האצבעות של ה-SHA-256 והמפתח, חתומות על ידי סביבת העבודה הראשית ב `manifest.signature.json`. יש לאמת כל ארכיון חשבון בנפרד באמצעות `python -m tgwitness.verify` ובאמצעות טביעת האצבע המהימנה של אותו חשבון.

חברי הקבוצה חולקים את הגדרות הקבוצה; חשבון יכול לשמור על הערכים שלו. ראו [הגדרות משותפות](https://phishdestroy.github.io/TgWitness/he/docs/reference/settings/#account-groups), [המדריך לייבוא ולקבוצות](https://github.com/phishdestroy/TgWitness/blob/main/docs/wiki/Accounts.md#import-accounts-and-share-settings) [ולוח המחוונים של מאגר ה-MTProxy](https://github.com/phishdestroy/TgWitness/blob/main/docs/wiki/Proxies.md#pool-dashboard-and-custom-sources).

## התנתק

**חשבון → יציאה מ-Telegram** (עם השעיית המעקב) מבקש מ-Telegram לסיים את הפעילות, כך שהיא נעלמת גם מהגדרות החשבון **→ מכשירים**, ומסירה את הפעילות מכספת סביבת העבודה. היומן, המקורות, ההגדרות ומפתח החתימה נשארים, ו היומן מתעד את היציאה. סביבת העבודה עדיין שייכת לחשבון שלה: רק אותו חשבון יכול להתחבר אליה שוב. אם טלגרם לא מגיבה, ההפעלה עדיין מוסרת מכאן והלוח מציין זאת; יש לסיים אותה בטלגרם תחת **'הגדרות' → 'מכשירים**'.

## שמירה על אבטחת קבצי החשבונות

- התייחסו לכל `.session`, TData ZIP, StringSession, מפתח אימות (Auth Key) ו-JSON של חשבון כאל סיסמה. TgWitness שומר את האישור המיובא בכספת המוצפנת שלו; תוכלו להסיר את הקבצים המקוריים לאחר מכן.
- אין להפעיל את אותה הרשאה בשתי תוכנות בו-זמנית. Telegram עלולה לבטל אותה (`AUTH_KEY_DUPLICATED`), ושתי הגרסאות יפסיקו לפעול.
- לא ניתן להחיות הפעלה שפג תוקפה או שבוטלה באמצעות המרה. התחבר שוב.
