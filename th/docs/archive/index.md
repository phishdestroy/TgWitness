# Telegram · จัดการกับคลังข้อมูล

Canonical page: https://phishdestroy.github.io/TgWitness/th/docs/archive/

ค้นหาข้อความ ตรวจสอบแหล่งที่มา สร้างคดี

01**นำประวัติมา**

ดึงข้อความเก่าจากแหล่งที่เปิดใช้งานเข้าสู่พื้นที่ทำงาน

02**ติดตามแหล่งข้อมูล**

ค้นหา แล้วเปิดข้อความที่บันทึกไว้เบื้องหลังผลลัพธ์แต่ละรายการ

03**ให้กระบวนการส่งต่องานชัดเจน**

การวิเคราะห์ของคุณในไฟล์เดียว หลักฐานที่ลงนามอยู่ข้างกัน

ข้อมูลที่บันทึกไว้ ข้อความที่ได้รับการระบุ และข้อสรุปของนักวิเคราะห์ จะถูกแยกไว้อย่างชัดเจน

## โหลดข้อความที่ผ่านมา

1. **แหล่งข้อมูล → แชทในขอบเขต**: ตรวจแชทที่เปิดใช้งาน แล้วเริ่มการสังเกต
2. **โหลดประวัติเต็ม** ใช้รายการแหล่งข้อมูลตามที่เป็นอยู่ ณ ขณะนั้น
3. **หยุดประวัติชั่วคราว** / **ดำเนินประวัติต่อ** ได้ทุกเมื่อ หลังรีสตาร์ต ให้ดำเนินต่อด้วยตนเอง
4. ตรวจผลลัพธ์ของแต่ละแหล่งและคิวดาวน์โหลด เก็บรายงานความคืบหน้าที่ลงนามไว้กับการส่งออก

ขั้นตอนนี้เติมข้อมูลในพื้นที่ทำงาน การส่งออก HTML/JSON ของแชทเดียวเป็นคนละเรื่องกัน [รายละเอียด](https://phishdestroy.github.io/TgWitness/th/docs/reference/history/)

## ค้นหาข้อมูลก่อน แล้วจึงตัดสินใจเกี่ยวกับ AI

1. **บันทึก** ค้นหาในเครื่อง กรองตามแหล่งข้อมูลและเวลา
2. ค้นหาวลีหรือโดเมน เปิดรายการบันทึกและเวอร์ชันของมัน
3. สำหรับ AI ผู้ดูแลตั้งค่าผู้ให้บริการใน **การบูรณาการ** จากนั้น **ถามคลังข้อมูล** เลือกแชทและช่วงเวลา ดู **ข้อมูลที่ส่งไปยังโมเดล** และยกเลิกเครื่องหมายสิ่งที่ไม่ควรส่งออกไป
4. ตรวจการอ้างอิง บันทึกคำตอบเป็นรายงาน เพิ่มหมายเหตุของคุณ

การค้นหาไม่ต้องใช้ AI รายงานเก็บแหล่งที่มาและการแก้ไขของตัวเอง แยกจากบันทึกที่ลงนาม [การตั้งค่าผู้ให้บริการ](https://phishdestroy.github.io/TgWitness/th/docs/reference/analysis/)

## เลือกการเชื่อมต่อที่คุณต้องการ

| งาน | เปิด | การตั้งค่า |
| --- | --- | --- |
| ให้ไคลเอนต์ AI อ่านแชทที่เลือก | **การบูรณาการ → MCP** | [ติดตั้ง MCP สร้างโทเค็นแบบจำกัดขอบเขต แล้วเชื่อมต่อ](https://phishdestroy.github.io/TgWitness/th/docs/reference/mcp/) |
| ระบุข้อความในสื่อที่บันทึกไว้ | บันทึก`media.saved` → **ระบุไฟล์แนบ** | [ตั้งค่า Docker worker ในเครื่อง](https://phishdestroy.github.io/TgWitness/th/docs/reference/media-analysis/) |
| ส่งเหตุการณ์ไปยัง n8n หรือ SIEM | **การบูรณาการ → Webhooks ส่งออก** | [เพิ่มผู้รับ ตรวจ HMAC กรอง ID ซ้ำ](https://phishdestroy.github.io/TgWitness/th/docs/reference/webhooks/) |

**โทเค็นการเข้าถึงใดใช้สำหรับส่วนใด?**

การเข้าถึงแผงควบคุมมีไว้สำหรับคน MCP มีโทเค็นอ่านอย่างเดียวของตัวเอง webhook มีความลับ HMAC ของตัวเอง ไม่มีตัวใดต้องใช้เซสชัน Telegram

[แชร์สิทธิ์การเข้าถึงแผง](https://phishdestroy.github.io/TgWitness/th/docs/access/)ควบคุมหรือ[กำหนดค่าไคลเอนต์ MCP](https://phishdestroy.github.io/TgWitness/th/docs/reference/mcp/)
