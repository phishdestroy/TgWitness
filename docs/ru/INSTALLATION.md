<a id="install-with-one-command"></a>
## Установка одной командой

Официальный сервис загрузки проекта, `get.destroy.tools`, предоставляет интерактивный
установщик и подписанные файлы релиза. Он включает в себя закрытую среду выполнения Python и
проверяет хеши пакетов и подписи релизов перед установкой. Каждый релиз
обновляет одновременно скрипты запуска, хеши, подписи и информацию о сборке;
каждая сборка также имеет неизменяемый URL-адрес релиза.

Выберите мастер установки для быстрой настройки или воспользуйтесь
[релизами GitHub, исходным кодом или Docker](QUICKSTART.md)
. Это поддерживаемые способы установки
для одного и того же проекта с открытым исходным кодом. Для развертывания, требующего утверждения
конкретной сборки перед запуском, используйте [Проверить перед запуском](#verify-before-running)
с независимо сохраненным отпечатком ключа выпуска и неизменяемым
URL сборки. Обновление службы загрузки не приводит к автоматическому обновлению установленной панели.

**Linux / macOS (Bash):**

```sh
curl -fsSL https://get.destroy.tools/install.sh | bash
```

На сервере Ubuntu запустите программу от имени пользователя root, чтобы установить фоновый сервис. На настольном компьютере
запустите программу от имени обычного пользователя.

**Windows (PowerShell или командная строка):**

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -Command "irm https://get.destroy.tools/install.ps1 | iex"
```

В Windows права администратора не требуются. Дочерний процесс PowerShell оставляет ваш
терминал открытым с отображением результата. Python и зависимости остаются в папке установки.

В Ubuntu выберите **«Этот компьютер»**, **«Временная ссылка HTTPS»** или **«Собственный домен»**.
Программа установки выведет адрес панели и ключ доступа. Для временной ссылки откройте
этот HTTPS-адрес в браузере и введите ключ. При локальном доступе к удалённому
серверу используйте перенаправление SSH с вашего компьютера (`ssh -L 8787:127.0.0.1:8787 user@server`)
и откройте `http://127.0.0.1:8787`. В macOS и Windows локальная панель откроется в вашем
браузере; оставьте терминал запущенным.

Войдите в Telegram через панель и выберите, что хотите собирать. Сама по себе установка
не запускает сбор данных в Telegram.

<a id="where-everything-runs"></a>
## Где всё работает

`get.destroy.tools` — это **Worker от Cloudflare, обслуживающий статические загрузки**. У него нет
панели TgWitness, сеанса Telegram или базы данных с данными о пользователях. Он не направляется на
VPS проекта. Приложение работает на том компьютере, на котором вы выполняете команду.

| Установка | Программа | Данные |
| --- | --- | --- |
| Ubuntu с правами root | `/opt/tgwitness` | Системная служба: `/var/lib/tgwitness-<installation ID>`; для указания точного пути используйте `tgwitness paths`. |
| Пользователь Linux / macOS | `~/.local/share/tgwitness` | `data/live` в рамках этой установки. |
| Пользователь Windows | `%LOCALAPPDATA%\TgWitness` | `data\live` в рамках этой установки. |

Укажите `TGWITNESS_INSTALL_DIR`, чтобы выбрать другую папку. Установленные версии и данные
хранятся отдельно. Установщик не загружает ваши аккаунты, сообщения или ключи на
сайт загрузки. При выборе туннеля Cloudflare трафик панели проходит через
Cloudflare; при использовании собственного домена трафик направляется на ваш собственный сервер.

При наличии элемента `TGWITNESS_TRUSTED_PROXIES` панель принимает один элемент `X-Forwarded-Proto: https` от доверенного прокси-сервера для установки файлов cookie безопасной загрузки.

Каждая установка включает файлы **START-HERE.html** и **START-HERE.txt**, содержащие локальные
пути, команды и ссылки на репозиторий. Запустите `tgwitness guide`, чтобы открыть руководство.
В Windows используйте `& "$env:LOCALAPPDATA\TgWitness\bin\tgwitness.cmd" guide` в PowerShell.

<a id="full-text-search-settings"></a>
## Настройки полнотекстового поиска

[Полнотекстовый поиск](SEARCH.md) (предварительный просмотр) не требует настройки. Его индекс формируется в
фоновом режиме после обновления.

| Переменная или команда | Эффект |
| --- | --- |
| `TGWITNESS_FULLTEXT=disk` | По умолчанию: индекс хранится в элементе `search/fulltext.sqlite3` каждой рабочей области |
| `TGWITNESS_FULLTEXT=memory` | Файл индекса отсутствует; индекс перестраивается при каждом запуске |
| `TGWITNESS_FULLTEXT=off` | Без индекса; только поиск по точному тексту |
| `tgwitness index status` | Состояние индекса каждой рабочей области |
| `tgwitness stop`, `tgwitness index rebuild`, `tgwitness start` | Восстановить все индексы из подписанного журнала |

Настройка, выбранная администратором в разделе **Журнал → Фильтры → Индекс поиска**, переопределяет
переменную для данной рабочей области. Команды находят каталог данных той установки,
в которой они запускаются; в остальных случаях добавьте `--data-dir` с путем из `tgwitness paths`.
Для полного украинского словаря (данные под лицензией GPL-3.0) установите `pymorphy3-dicts-uk` в
среду Python данной установки.

<a id="command-line-access"></a>
## Доступ через командную строку

[Командная строка](CLI.md) (предварительный просмотр) сканирует архив на наличие скриптов и агентов.

| Переменная | Эффект |
| --- | --- |
| `TGWITNESS_URL` | Адрес панели для `tgwitness search`, `context`, `messages`, `stats` и `export`; по умолчанию — `http://127.0.0.1:8787`, если установлен токен |
| `TGWITNESS_MCP_TOKEN` | Токен подключения к архиву из раздела **«Дополнительные инструменты» → «Интеграции» → «MCP»**, общий для всех клиентов MCP; `--token-file`, напротив, считывает его из файла |
| `TGWITNESS_DATA` | Каталог данных считывается напрямую, если не указан элемент `--data-dir`, URL-адрес или токен |

<a id="verify-before-running"></a>
## Проверьте перед запуском

Установщик встраивает открытый ключ релиза проекта и проверяет SHA-256 и RSA-
подписи пакета приложения и списка зависимостей перед их установкой.
Как Bash, так и PowerShell останавливаются при сбое любой обязательной проверки. Исходный скрипт
доставляется по HTTPS и имеет собственную отдельную подпись; приведенные ниже команды также
позволяют проверить этот скрипт перед его выполнением.

Открытый ключ выпуска — [release-signing.pub](../../deploy/installer/release-signing.pub).
Его SHA-256:

```text
039d98a658ccda14253e45a00335b4a68d840976d8ec18b8d4355cc7c458447d
```

Сохраните этот отпечаток из ревизии репозитория, которому вы доверяете. Контрольная сумма с
того же сервера загрузки позволяет обнаружить несоответствие; независимый доверенный открытый
ключ служит для аутентификации подписи выпуска.

Используйте новый пустой каталог для загрузки файлов, необходимых для проверки, указанных ниже.

**Linux / macOS — запустить в новом пустом каталоге для загрузки** (требуется наличие curl и OpenSSL):

```sh
curl -fSLO https://get.destroy.tools/install.sh &&
curl -fSLO https://get.destroy.tools/install.sh.sig &&
curl -fSLO https://get.destroy.tools/release-signing.pub &&
test "$(openssl dgst -sha256 release-signing.pub | awk '{print $NF}')" = \
  '039d98a658ccda14253e45a00335b4a68d840976d8ec18b8d4355cc7c458447d' &&
openssl dgst -sha256 -verify release-signing.pub -signature install.sh.sig install.sh &&
bash install.sh
```

Цепочка `&&` останавливается до начала выполнения, если загрузка, проверка отпечатка ключа или проверка подписи
завершились неудачно. Если между загрузкой скрипта и проверкой его
подписи произошла публикация, необходимо заново загрузить и то, и другое. Старые установщики сохраняют неизменяемые URL-адреса пакетов.

**Windows — перед запуском проверьте SHA-256:**

```powershell
Invoke-WebRequest https://get.destroy.tools/install.ps1 -OutFile install.ps1 -UseBasicParsing
Get-FileHash .\install.ps1 -Algorithm SHA256
Invoke-RestMethod https://get.destroy.tools/SHA256SUMS.txt
```

Сравните хеш со строкой `install.ps1`. Для независимой проверки подписи
воспользуйтесь OpenSSL (например, из Git Bash) и тем же отпечатком открытого ключа, что указан выше:

```sh
curl -fSLO https://get.destroy.tools/install.ps1 &&
curl -fSLO https://get.destroy.tools/install.ps1.sig &&
curl -fSLO https://get.destroy.tools/release-signing.pub &&
test "$(openssl dgst -sha256 release-signing.pub | awk '{print $NF}')" = \
  '039d98a658ccda14253e45a00335b4a68d840976d8ec18b8d4355cc7c458447d' &&
openssl dgst -sha256 -verify release-signing.pub -signature install.ps1.sig install.ps1 &&
powershell.exe -NoProfile -ExecutionPolicy Bypass -File install.ps1
```

Сама система установки Windows проверяет подписи пакетов с помощью .NET и не
требует использования OpenSSL. Речь идет об автономных подписях RSA-3072 / SHA-256, а не о подписях Authenticode.
В [манифесте](https://get.destroy.tools/manifest.json) указаны версия программного обеспечения,
точный коммит Git, неизменяемый идентификатор выпуска и SHA-256 каждого артефакта. На странице есть ссылки
на соответствующий исходный код. Манифест и список контрольных сумм также имеют отдельные
подписи (`manifest.json.sig` и `SHA256SUMS.txt.sig`).

<a id="update-an-existing-installation"></a>
## Обновление существующей установки

**При выходе новой версии обновляется сайт загрузки; установленные программы обновляются при
повторном запуске установщика.** Автоматического обновления или автоматического перезапуска
работающей коллекции не предусмотрено. Текущий канал установщика — **preview**; он следует за
опубликованными и проверенными сборками с `main`, коммит которых может быть более новым, чем последний
пронумерованный релиз на GitHub. Версия страницы берется с `pyproject.toml`; её коммит
и идентификатор сборки позволяют различать обновления в рамках одной и той же предварительной версии.

Публикация происходит автоматически после того, как данный коммит пройдет проверку приложения и
безопасности, а подписанный пакет будет аутентифицирован, установлен и проверен в
Ubuntu и Windows. Пулл-реквесты, изменяющие установщик, также дважды запускают команды `install.sh`
и `install.ps1` на локальной копии сайта. Во время выполнения проверок
или в случае их сбоя эти же команды продолжают устанавливать предыдущую проверенную сборку.
Манифест сборки показывает, какой коммит доступен в данный момент; сам номер версии
может оставаться неизменным между обновлениями предварительной версии.

Используйте ту же папку установки и того же пользователя ОС, что и ранее. Сделайте резервную копию всего каталога данных
при остановленном сборе данных; он обозначен значком `tgwitness paths`. Подписанный экспорт
не является полной резервной копией установки.

**Установка Ubuntu с правами root на `/opt/tgwitness`:**

```sh
curl -fsSL https://get.destroy.tools/install.sh | TGWITNESS_INSTALL_DIR=/opt/tgwitness bash -s -- --no-start
```

После успешной установки:

```sh
/opt/tgwitness/bin/tgwitness restart
/opt/tgwitness/bin/tgwitness status
/opt/tgwitness/bin/tgwitness open
```

При установке для пользователя Linux/macOS используйте исходную команду `TGWITNESS_INSTALL_DIR` или
команду по умолчанию и повторно выполните первую команду установки. Перед обновлением закройте панель,
работающую в фоновом режиме, а после обновления запустите её заново. Для настроенной пользовательской
службы Linux выполните команду `tgwitness restart`.

**Windows:** закройте открытую панель, запустите команду установки Windows ещё раз,
затем откройте `bin\tgwitness.cmd` в рамках той же установки. Установщик сохраняет данные,
сессии, настройки доступа и ключи подписи. Он переключает программу запуска только после того, как
новая среда пройдёт все проверки; в случае неудачной установки предыдущая
программа запуска остаётся на месте. Сохраните резервную копию, созданную до обновления, на случай изменения формата хранения.

<a id="everyday-commands-on-ubuntu"></a>
## Повседневные команды в Ubuntu

| Команда | Результат |
| --- | --- |
| `tgwitness open` | Текущий URL-адрес панели и ключ доступа. |
| `tgwitness paths` | Точные траектории программы, данных и направляющих. |
| `tgwitness guide --print` | Руководство по эксплуатации в автономном режиме. |
| `tgwitness status` / `tgwitness logs` | Журналы доступности / обслуживания. |
| `tgwitness stop` / `tgwitness start` | Остановить / возобновить работу службы; сохранить данные. |
| `tgwitness token rotate` | Замените ключ администратора и завершите сеансы работы в браузере. |
| `tgwitness tunnel off` | Отключить общедоступный быстрый туннель; оставить локальную панель. |
| `tgwitness tunnel on` / `tgwitness tunnel restart` | Создать ссылку на быстрый туннель / заменить её адрес. |

См. [Доступ](ACCESS.md)
— информация о токенах сотрудников, сессиях и ограничениях по IP-адресам, а также
[Публикация установщика](../../deploy/installer/README.md#automatic-publication-from-github)
— информация о рабочем процессе выпуска с GitHub в Cloudflare.

<a id="remove-tgwitness"></a>
## Удалить TgWitness

Деинсталлятора нет: нужно остановить работу панели и удалить её папки. Удаление папки «data»
приведёт к безвозвратной потере журналов, ключей подписи, сеансов Telegram и сохраненных файлов.
Перед этим:

1. Экспортируйте необходимые данные (**Экспорт → Скачать подписанный ZIP-файл**) и храните отпечаток ключа подписи
   и контрольные точки за пределами этого компьютера. Чтобы сохранить само рабочее пространство, скопируйте
   всю папку с данными после остановки сбора.
2. Удалите серверы, созданные в разделе **Дополнительные инструменты → Дополнительные функции → Сервер 24/7** из списка **Ваши серверы** или с помощью
   `python -m tgwitness.cloud destroy`; провайдер будет выставлять счета за них до тех пор, пока они не будут удалены.
3. Завершите сессию каждой учётной записи в Telegram в разделе **Настройки → Устройства**. Удаление
   файлов не приводит к выходу из сессии на стороне Telegram.

**Установка Ubuntu с правами root.** Обратите внимание на папку с данными, остановите службу, а затем удалите
службу, папки и ярлык:

```sh
/opt/tgwitness/bin/tgwitness paths
/opt/tgwitness/bin/tgwitness stop
systemctl list-unit-files 'tgwitness-*'
systemctl disable tgwitness-<ID>
rm /etc/systemd/system/tgwitness-<ID>.service
systemctl daemon-reload
rm -rf /opt/tgwitness /var/lib/tgwitness-<ID> /usr/local/bin/tgwitness
```

**Установка для пользователей Linux или macOS.** Закройте панель. Настроенная служба пользователя Linux
остановлена с помощью `systemctl --user disable --now tgwitness-<ID>`; её модуль находится в
`~/.config/systemd/user/`. Затем удалите `~/.local/share/tgwitness` (или ваш
`TGWITNESS_INSTALL_DIR`) и ярлык `~/.local/bin/tgwitness`.

**Windows.** Закройте панель и удалите `%LOCALAPPDATA%\TgWitness` (или ваш
`TGWITNESS_INSTALL_DIR`). Установщик не добавляет ни служб, ни запланированных задач, ни ярлыков.
