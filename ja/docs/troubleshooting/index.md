# Telegram · 何が問題だったのかを確認する

Canonical page: https://phishdestroy.github.io/TgWitness/ja/docs/troubleshooting/

症状から始め、1 つずつ確認してください。

## パネルからトークンの入力が求められます

求められているのは、ランチャーが表示したファイルにあるパネルトークンです。Docker：`docker compose exec tgwitness cat /data/panel-token.txt`。Telegram のコードでも、ボットのトークンでも、証人のトークンでもありません。

## Telegramは接続されません

接続チェックを実行します。公開プロキシなら別のものを選んで保存します。プロキシの種類とシークレットの形式を確認します。リストを更新しただけではルートは切り替わりません。

## 接続されていますが、新しいメッセージはありません

1. 観察は正しいワークスペースで動いていますか？
2. ソースは選択されていて、そのアカウントから見えていますか？
3. テストグループで固有のメッセージを送り、それを検索します。
4. ジャーナルで中断や Telegram のエラーを探します。

静かなチャットは単に新しいものがないだけです。完全性が重要なら、管理された配信テストを行ってください。

## 再起動後のFloodWaitまたは間隔

FloodWait は Telegram からの「ゆっくり」という合図です。過ぎるのを待って負荷を下げてください。再接続しても効果はありません。再起動後、TgWitness は Telegram にまだ残っているものを取り戻します。残りは欠落なので、書き留めてください。

## ボットは設定済みですが、何も投稿していません

証人は動いていますか、ボットはチャンネルに投稿できますか、コレクターと Bot API に届きますか？証人のジャーナルで失敗した投稿を探してください。コレクター側にポーリングがあっても、投稿が送られたとは限りません。

## GitHubトークンの連携機能はどこにありますか？

**計画中。**「Extras」セクションでは、提案されているフォークおよびビルド検証のワークフローについて説明しています。現在、GitHubトークン入力フォームや、稼働中のインストール環境がリポジトリと一致していることを自動的に確認する機能はありません。[現在の機能状況](https://phishdestroy.github.io/TgWitness/ja/docs/reference/features/)については、こちらをご覧ください。

バグを報告する場合は、バージョン、OS、手順、個人情報を伏せたエラーを添えてください。セッション、トークン、個人的なメッセージ、データディレクトリを公開の issue に載せないでください。
