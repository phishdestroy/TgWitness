# З’ясуйте, що пішло не так

Canonical page: https://phishdestroy.github.io/TgWitness/uk/docs/troubleshooting/

Почніть із симптому. Перевіряйте по одному шару за раз.

## Панель запитує токен

Використовуйте токен панелі з локального файлу, який відображає програма-запускач. Для Docker запустіть `docker compose exec tgwitness cat /data/panel-token.txt`. Код входу в Telegram, токен BotFather та токен свідка з правом лише на читання служать різним цілям.

## Telegram не підключається

Відкрийте налаштування з’єднання та запустіть перевірку з’єднання. Якщо ви використовуєте публічний проксі-сервер, спробуйте інший запис і явно збережіть маршрут. Перевірте тип проксі-сервера та підтримуваний формат секретного ключа. Оновлення публічного списку не змінює маршрут облікового запису.

## Є з'єднання, але нових повідомлень немає

1. Перевірте, чи спостереження працює у правильному робочому просторі.
2. Переконайтеся, що джерело вибрано та є видимим для цього облікового запису.
3. Надішліть нове унікальне повідомлення в контрольованій групі та знайдіть саме цей текст.
4. Перегляньте журнал роботи на наявність перебоїв, затримок у роботі або помилок Telegram.

Історичні знімки та події, пов’язані з новими повідомленнями, — це різні речі. «Тихе» джерело можна підключити без створення нових повідомлень. Якщо важлива повнота даних, використовуйте тест контрольованої доставки.

## FloodWait або затримка після перезапуску

Повідомлення «FloodWait» означає, що Telegram вимагає паузи. Зачекайте вказаний проміжок часу та перегляньте обсяг зібраних даних; повторні спроби підключення не скасовують обмеження. Збережений стан оновлення допомагає наздогнати пропущене після перезапуску, але оновлення, термін дії яких закінчився, та деякі періоди переривання залишаються обмеженнями. Зафіксуйте прогалину, а не вважайте журнал повним.

## Бот налаштований, але нічого не публікує

Переконайтеся, що процес Witness дійсно працює, що бот може публікувати повідомлення в каналі, а Witness має доступ до колектора та Bot API. Перевірте журнал на наявність невдалих публікацій. Сам по собі успішний запит до колектора ще не підтверджує публікацію в каналі.

## Де знаходиться інтеграція з токенами GitHub?

**У стадії планування. У розділі** «Додаткова інформація» описано запропонований робочий процес розгалуження та перевірки збірки. Наразі немає форми для отримання токена GitHub або автоматизованої перевірки відповідності запущеної інсталяції репозиторію. Дивіться [поточний стан функціоналу](https://phishdestroy.github.io/TgWitness/uk/docs/reference/features/).

Повідомляючи про проблему, вкажіть версію, операційну систему, послідовність дій та відредагований текст помилки. Не публікуйте у відкритих зверненнях інформацію про сесії, токени, приватні повідомлення та каталог даних.
