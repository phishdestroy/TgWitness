# Экспорт данных распределенного чата

При повторной проверке отсутствующих чисел пробелы учитываются как интервалы, без выделения каждого отсутствующего
числа в памяти. По умолчанию выборка остается ограниченной; явная полная повторная проверка считывает
последовательные партии и может быть отменена. Непроверенные числа остаются видимыми в
результате и не рассматриваются как доказательство удаления.

Откройте чат и выберите **«Экспорт чата»**. Выберите рабочие пространства аккаунтов, которые уже имеют доступ к источнику; участвовать может даже учетная запись, имеющая только статус наблюдателя. Каждая учетная запись сохраняет свои настроенные параметры подключения. Эта функция не изменяет настройки WARP и не выбирает IP-адрес выхода.

В разделе **«Главная» → «Экспорт чата по ссылке»** введите общедоступное имя пользователя или ссылку для приглашения, чтобы просмотреть
доступные данные о чате и подходящие аккаунты; для каждой исключенной учетной записи указывается причина. Проверка
на короткое время резервирует неактивного читателя; она не присоединяет его к чату и не запускает экспорт. Оценки времени
охватывают одну учетную запись, выбранные аккаунты, а также, в случае каналов и супергрупп,
десять аккаунтов; они отражают измеренные или стандартные скорости чтения и не учитывают вложения
и ожидания в Telegram. Запустите экспорт явно.

<a id="history-acquisition"></a>
## Сбор исторических данных

Флажок **Скачать выбранные вложения с учётом лимитов аккаунта** в диалоговом окне экспорта по умолчанию
установлен, если рабочая область загружает мультимедиа, и снят, если не загружает; при необходимости измените его настройку для отдельного экспорта.
Если флажок снят, при распределенной загрузке также пропускается загрузка
аватарки чата. Доступный идентификатор фотографии и другие метаданные профиля остаются
в экспорте. Для извлечения фотографии требуется как эта опция, так и соответствующие
настройки мультимедиа/аватаров в рабочей среде. Повторная проверка идентификаторов сообщений использует те же ограничения по скорости для общей учетной записи, что и
чтение истории; любое ожидание, запрашиваемое сервером, по-прежнему применяется ко всем вызывающим сторонам.

**Обычная сессия** сохраняет существующий путь получения данных. **Сеанс Telegram Takeout** — это опциональный путь для публичных каналов и супергрупп. Она открывает сессию экспорта для каждого участвующего аккаунта, использует последний диапазон разбиения Telegram для этой области, доступной только публично, и считывает историю без дополнительной задержки итератора Telethon. Собственная функция Telegram FloodWait по-прежнему применяется в полном объёме. Takeout использует тот же ограниченный канал запросов к истории, что и обычное чтение; переключение транспорта не создаёт дополнительных слотов и не обходит общие интервалы между запросами.

Начальные границы источника/даты определяются с помощью обычных запросов и фиксируются в подписанном плане. Takeout считывает эти запланированные диапазоны. Для профилей, журналов администрирования, дополнительного контекста и извлечения вложений по-прежнему используются обычные запросы; архив определяет эту область. Флаги Takeout запрашивают выбранный тип чата без контактов или экспорта файлов. Частные чаты и частные группы остаются доступными через обычный путь или [экспорт учетной записи](ACCOUNT-EXPORT.md).

Если Telegram требует подтверждения экспорта, задание приостанавливается, и отображается возвращенный срок выполнения. Подтвердите в Telegram или подождите, а затем явно возобновите задание. Автоматического перехода к выполнению со стандартной скоростью не происходит. Приостановка/отмена сохраняют частный идентификатор Takeout для задания, которое можно возобновить; они не выходят из учетной записи и не отзывают авторизацию. При возобновлении происходит проверка учетной записи, идентификатора и диапазона разделения. Идентификатор с истекшим сроком действия приводит к приостановке задания; последующее возобновление создает новое поколение. Измененный диапазон разделения требует нового экспорта, а не смешивания несовместимой пагинации.

Идентификаторы Takeout остаются в зашифрованном хранилище. Квитанции фрагментов позволяют определить транспорт и момент создания без использования идентификатора. В подписанном архиве фиксируются время создания, открытия, повторного использования и закрытия, а также любые ошибки финализации. Финализация истории происходит после выбора и выполнения сетевых операций, но до упаковки; при повторной попытке упаковки можно повторно использовать подписанные фрагменты. Старые планы сохраняют исходные размеры транспорта и фрагментов.

<a id="exclusive-account-ownership"></a>
## Исключительное право владения счетом

Один аккаунт может одновременно выполнять один прогон истории или один экспорт, наряду с наблюдением в режиме реального времени. Элементы управления паузой работают независимо друг от друга. Бронирования получаются до запросов Telegram и освобождаются по завершении, в случае сбоя или при приостановке. История считывает до трёх чатов одновременно с одним курсором на каждый чат. Запросы к истории и запросы на файлы имеют отдельные ограничения по три активных запроса каждый; интервал между запросами остаётся общим для каждой учётной записи. Другие RPC-запросы поочерёдно обрабатываются в отдельных потоках для обновлений в реальном времени, оператора, фоновых проверок и экспорта. Медленный ответ освобождает другие каналы для продолжения работы; темп обработки по-прежнему распределяется на одну учетную запись. Отдельные аккаунты работают одновременно. Сохраненные сроки FloodWait проверяются повторно перед отправкой запросов из очереди, в том числе после перезапуска. Повторные попытки экспорта приостанавливают данный экспорт; сохраненный срок для затронутого метода Telegram по-прежнему применяется к другим вызывающим сторонам, использующим его.

<a id="selection"></a>
## Выбор

- Вся доступная история: скользящий период 7/30 дней, предыдущий календарный месяц или пользовательские границы. Даты в интерфейсе используют часовой пояс браузера и при запуске фиксируются в формате UTC `[from, until)`.
- Включаются сообщения, отправленные ровно в момент, указанный в поле **Из**, включая несколько сообщений, отправленных в течение одной секунды. Telegram может возвращать само сообщение со смещением по дате, поэтому при сборе данных учитывается время, немного предшествующее нижней границе, а точный период применяется локально. Поле **«До»** остаётся исключительным.
- Определение языка сообщений в автономном режиме с помощью Lingua. Для коротких, неоднозначных и многоязычных сообщений предусмотрена отдельная опция включения/исключения. К оцененным выбранным сообщениям прилагаются версия детектора, принятые решения и показатели достоверности.
- **«Сообщения, являющиеся ответами»** выбирает прямые ответы. **Сообщения, на которые ответили** выбирает исходные сообщения, на которые был зафиксирован прямой входящий ответ. Взаимосвязи устанавливаются до фильтрации по языку/тексту, поэтому ответ на русском языке может соответствовать исходному сообщению на английском. Простое размещение сообщения в теме форума не считается прямым ответом.
- Ответы можно искать в пределах выбранного периода или с момента начала сбора данных. Последний вариант может потребовать сканирования более поздней истории.
- Ограниченный контекст «исходного сообщения/ответа» с отдельным ограничением на количество сообщений. Контекст может выходить за пределы фильтров и помечается как `selection.role=context`. Для отсутствующих исходных сообщений сохраняется причина; связанные обсуждения за пределами выбранного источника не просматриваются. Контекст расширяется на всю собранную историю и извлекает отсутствующие исходные сообщения из того же источника; он не обнаруживает все ответы, выходящие за пределы просканированного периода.
- Буквальная текстовая фраза; фильтрация по ID отправителя через API. Дополнительные вложения извлекаются после выбора в соответствии с политикой сбора данных ведущей учетной записи, независимо от того, какая учетная запись их просматривает. Измененное сообщение не заменяется автоматически во время извлечения вложений.

<a id="chunking-and-continuation"></a>
## Разбиение на фрагменты и продолжение

Для супергруппы/канала в ходе предварительной проверки источник обрабатывается отдельно для каждой учетной записи, при этом фиксируются видимые границы дат и идентификаторов. Общая очередь распределяет непересекающиеся фрагменты между подходящими аккаунтами. Как обычное, так и Takeout-приобретение начинаются с 2 000 числовых ID на фрагмент и могут расширяться до максимум 100 000 ID с использованием оценки количества записей во всей истории, доступной для аккаунта с наибольшей плотностью участия. Это сокращает количество пустых запросов в разреженных историях; при этом из подписанного плана не исключаются никакие ID и не изменяется темп RPC. Подсчёты являются оценкой для планирования, а не подсчётом за выбранный период или результатом удаления. Диапазон идентификаторов не является количеством сообщений. Обычные группы и приватные чаты используют одну учётную запись, поскольку идентификаторы не могут объединяться между учётными записями таким же образом.

`distributed-exports/<job-id>/` хранит подписанный неизменяемый план, подписанные квитанции о получении фрагментов, полученные фрагменты JSONL, восстанавливаемые индексы SQLite и итоговый ZIP-архив. Новые планы используют контрольные точки `tgwitness-distributed-pages-v2` внутри каждого фрагмента; планы, запущенные ранее, сохраняют `tgwitness-distributed-pages-v1`. Перед контрольной точкой в буфере хранится не более 100 декодированных сообщений; при целевом значении 4 MiB также сбрасываются более мелкие партии (размер отдельной записи может достигать 64 MiB). Речь идет о локальных партиях записей, а не о необработанных ответах RPC от Telegram. Каждое подтверждение связывает хеш плана, чат, ключ учетной записи/подписи, диапазон ID, курсор «до» и «после», интервал в байтах, хеш данных, время локального получения, генерацию транспорта и хеш предыдущего подтверждения.

Данные сбрасываются и синхронизируются до того, как их получение будет атомарно записано и синхронизировано. Только после этого курсор с гарантией сохранности продвигается вперед. Приостановка сбрасывает незавершённую запись перед освобождением учётной записи. Возобновление проверяет каждую сохраненную контрольную точку перед подключением, игнорирует конечные байты без знака и усекает этот хвост перед продолжением с последнего зафиксированного курсора. Может потребоваться повторное чтение до 99 сообщений из буфера или текущей записи без знака. Зафиксированные страницы сохраняются без изменений. В плане v1 частично приобретённый диапазон остаётся при своей исходной учетной записи. В плане v2, когда Telegram просит учетную запись подождать 15 секунд или более, либо если учетная запись читает заметно медленнее, чем учетная запись, у которой больше нет дел, диапазон освобождается на последней подписанной странице, и другая подходящая учетная запись продолжает с этого курсора. Первая подписанная страница указывает в поле `handover_from` аккаунт, у которого был взят диапазон; страницы, подписанные ранее, сохраняют свой аккаунт. Смена аккаунта без этого поля отклоняется верификатором, поэтому ни один аккаунт не может незаметно завершить диапазон другого. Архив относит каждое сообщение к тому аккаунту, который подписал его страницу. Пустые конечные квитанции указывают на исчерпание итератора для данного наблюдателя, а не на его полное отсутствие. Истекший Takeout может возобновиться в новом поколении, что фиксируется отдельно в последующих квитанциях.

После завершения диапазона его подтверждение получения фрагмента фиксирует конечную контрольную точку. Перед повторным использованием Resume проверяет подписи, хеши, диапазоны, порядок, идентификацию учетной записи и сохраненный прогресс. Старые планы без `checkpoint_format` сохраняют исходный путь восстановления всего фрагмента; их не переносят автоматически. Приостановленные задания можно возобновить из раздела **Сохранённые экспорты** в диалоговом окне экспорта. Несколько заданий могут выполняться одновременно, если они используют отдельные аккаунты. Каждое задание имеет собственные рабочие процессы, контрольные точки и временные параметры; учетная запись, зарезервированная одним заданием, не может присоединиться к другому, пока не будет освобождена.

Просмотрите **приостановленный или неудавшийся** рабочий каталог нового формата без приложения, индекса SQLite или хранилища:

```bash
python tgwitness/verify.py /path/to/distributed-exports/JOB_ID --fingerprint RETAINED_FINGERPRINT --json
```

Эта проверка в режиме «только для чтения» выявляет зафиксированные сообщения/страницы, завершенные диапазоны и неподписанные байты конца цепочки. Необходимо независимо зафиксировать отпечаток начала цепочки. Как и в случае с любой локальной цепочкой квитанций, удаление её конца и всех соответствующих локальных данных о ходе обработки невозможно обнаружить без отдельно сохраненного начала цепочки квитанций. Верификатор проверяет зафиксированные записи о получении данных. При сравнении собранных данных следует учитывать их интервалы и охват.

Промежуточные фрагменты включают сообщения, необходимые для оценки фильтров, в том числе отклоненные сообщения. Фильтры ограничивают окончательный архив. Приостановленное, отмененное или завершившееся с ошибкой задание сохраняет эти фрагменты и квитанции контрольных точек для восстановления. Экспорт, завершившийся сбоем по причине, отличной от отклоненного запроса или настройки, также записывается в журнал процесса вместе с трассировкой в логгере `tgwitness.export`; на панели отображается только текст ошибки. После успешной проверки архива и завершения задания приложение удаляет фрагменты, квитанции, временные носители и индексы. В каталоге задания сохраняются `export.zip`, подписанный план `job.json` и `status.json`; для завершенных заданий используйте средство проверки ZIP-архивов. Перед добавлением новых фрагментов и созданием каждой контрольной точки проверяется наличие настроенного резерва свободного места.

Использование более широких диапазонов по-прежнему позволяет сократить количество запросов при работе с разреженными историческими данными. Новые контрольные точки ограничивают повторное чтение прерванных диапазонов независимо от их ширины. Проверка перекрытия данных между аккаунтами остаётся отдельной темой для будущих исследований. Более частая подпись и синхронизация увеличивают нагрузку на локальный ввод-вывод; создание контрольных точек улучшает восстановление, но не скорость успешного непрерывного чтения данных по сети.

Планы, созданные до исправления «inclusive-start», при возобновлении сохраняют свои исходные диапазоны подписанных идентификаторов. Запустите новый экспорт с фильтрацией по дате, чтобы восстановить все сообщения, исключенные в поле **Из** в рамках более старого плана.

<a id="result-and-limits"></a>
## Результаты и ограничения

<a id="performance-measurements"></a>
### Измерение производительности

Панель экспорта и API статуса отображают время, прошедшее с момента **текущего запуска или возобновления**, с использованием монотонных часов. Подготовка включает установку соединения, проверку границ, верификацию сохраненных фрагментов и метаданные чата. При сборе данных измеряется совокупная производительность параллельных процессов, включая ожидание ответов от Telegram, запись фрагментов и подписание квитанций. Выбор и извлечение вложений, а затем упаковка и проверка имеют отдельные таймеры. Приостановка или завершение процесса приостанавливают измерения; возобновление запускает новое измерение и исключает ранее зафиксированные сообщения из числителя пропускной способности.

Пропускная способность при сборе данных — это количество новых зафиксированных сообщений, деленное на время сбора данных. Новые задания обновляются при фиксации страницы, включая прогресс внутри незавершённого диапазона; старые задания обновляются при фиксации блока. Это среднее значение, а не мгновенная скорость сети. Оно не включает отбор, вложения или создание ZIP/PDF-файлов. Статус задания с подписью сохраняет эти показатели; при успешном выполнении они также записываются в `chat_export.completed`. Задания, созданные до появления этой функции, не имеют записей о производительности до момента возобновления. Количество оставшихся сообщений неизвестно, поэтому панель не рассчитывает предполагаемое время завершения (ETA) на основе числовых диапазонов ID. Сравнивайте запуски с одинаковым фиксированным объемом, настройками вложений и доступом к аккаунтам; выигрыш от большего количества аккаунтов зависит от диапазонов ID в чате и ограничений Telegram.

При обнаружении больших списков состав запросов отличается от того, что наблюдается при сборе исторических данных. Перед тем как экстраполировать результаты тестирования небольшого набора источников на тысячи новых источников, ознакомьтесь с [сравнением источников экспортера и ограничениями](EXPORT-LIMITS.md).

[Квалификационное тестирование в режиме реального времени с 50 источниками](../EXPORT-BENCHMARK-2026-11-06.md), проведённое 06.11.2026,
позволило получить 48 проверенных архивов, содержащих 3 598 381 запись. Одно задание в обычном режиме с восемью аккаунтами

В ходе запуска также были выявлены накладные расходы при работе с разреженными диапазонами, таймауты соединений и замедление работы последующих

### Архив

В ZIP-архиве используется существующий формат экспорта чата, поддающийся независимой проверке, с подписанными частями для каждой учетной записи, выбранными сообщениями, контекстными метками, настройками выбора и объемом сбора данных. Авторитетным является файл `chat.json`. В форматах HTML и PDF номера сообщений, пропущенных в результате выбора, отличаются от доказательств удаления. Приложение проверяет ZIP-архив перед тем, как пометить его как готовый; после этого загруженные файлы остаются доступными.

В манифесте указываются формат контрольных точек и их количество, используемые локально. Данные невыбранных контрольных точек и соответствующие квитанции не добавляются в отфильтрованный ZIP-архив. Проверка архива продолжается с проверкой выбранных сообщений и подписей аккаунтов; проверка локальных контрольных точек представляет собой отдельную проверку каталогов, описанную выше. Старые ZIP-архивы по-прежнему поддерживаются.

В разделе «Охват» перечислены доступные диапазоны, данные из которых были фактически прочитаны. У разных аккаунтов может быть разный уровень доступа; при распределенном или возобновленном сборе данных каждый диапазон считывается в своё время. Информация об участниках, причинах удаления, блокировках и идентификационных данных модераторов предоставляется только на основе данных Telegram, в которых они указаны.

API: `POST /api/multi-export/plan` принимает `link` и перед чтением фактов проверяет права доступа к рабочей области/чату. `POST /api/multi-export/start` принимает `chat_id`, `lead`, `profiles`, `selection`, необязательный `username` и `transport` (`regular`, значение по умолчанию или `takeout`); `GET /api/multi-export/jobs` отображает список видимых сохраненных заданий. Маршруты для отдельных заданий поддерживают опрос: `pause`, `resume`, `cancel` и `download`. Проверяется доступ ко всем участвующим рабочим областям/источникам.
