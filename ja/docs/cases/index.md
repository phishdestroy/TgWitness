# Telegram · すべてのチャットを横断的に調査する

Canonical page: https://phishdestroy.github.io/TgWitness/ja/docs/cases/

チャンネル、グループ、個人チャット、ボットにまたがる 1 つのケース：収集し、点と点をつなぎ、時系列を再構成して、引き渡します。

架空のインシデントを最初から最後まで。収集、検索、人物プロフィールで記録を見つけ、[Case Board](https://phishdestroy.github.io/TgWitness/ja/docs/case-board/) で整理し、[Report studio](https://phishdestroy.github.io/TgWitness/ja/docs/reports/) で提示します。

実例／支払い先が変更されたケース

### 1件のインシデント。4つの会話。再構築すべき痕跡。

チャンネルの投稿がボットを指しています。グループでは新しい支払いリンクが話題になり、ボットもそれを表示します。投稿が編集され、個人チャットでリンクが繰り返され、グループのメッセージが消えます。

各バージョンは誰が投稿したのでしょうか？そのリンクはどこに表示されましたか？どのファイルが保存されましたか？何が、いつ変更されましたか？

履歴の読み込み、AI、MCP、OCR、webhook：[アーカイブを活用する](https://phishdestroy.github.io/TgWitness/ja/docs/archive/)。

## 1. アカウント全体を網羅するように設定する

アカウント全体の範囲は専用アカウントでのみ使います。メインのアカウントでは、選んだチャットかフォルダーにします。

1. 専用のワークスペースで[アカウントを接続](https://phishdestroy.github.io/TgWitness/ja/docs/accounts/)します。ケース番号、アカウント ID、ワークスペース、鍵のフィンガープリントを控えます。
2. **ソース → 観察範囲 → 調査モード**：**アカウント全体**、4 種類すべてのソース、**自身のアクション**。新しいチャットごとにプロフィールと**最新200件の表示可能なメッセージ**が保存されます。**範囲を保存**して確認します。
3. **チャットを読み込む**を実行し、アカウントのチャット一覧と比べます。上限は 1,000 件の会話です（**パラメータ → アカウントの一覧から読み込むチャット**で最大 20,000）。それを超えるチャットは、動きがあった時点で表示されます。
4. **記録設定** → **表示されているすべてのアクティビティ**を選び、添付ファイルの上限とディスク容量を確認します。開始したら、メッセージ、編集、削除を 1 つずつ試します。

チャンネルグループプライベートチャットボット

1つのアカウント／1つの署名鍵**選択されたアカウントの公開アクティビティすべて → 1つのジャーナル**

メッセージ・編集・削除通知・表示されたリアクション・メンバーシップのイベント・自身のアクション

「アカウント全体」とは、このアカウントが開けるすべてのチャットから除外分を引いたものです。シークレットチャットは含みません。新しいチャットは現れた時点で加わり、古い履歴は自動ではダウンロードされません。

## 2. 履歴を取得し、ファイルを保存する

Case Board のコレクションを作り、重要なものをブックマークします。ソース台帳を付けてください：チャット ID、タイトル、アカウント、役割、ライブ記録の開始、履歴の結果、メディアの結果、欠落。

| 要件 | パネルでの操作 | 提供内容 |
| --- | --- | --- |
| 有効化されたチャット全体の履歴 | 出典 → 履歴をすべて読み込む | 利用可能な過去のメッセージはワークスペースのジャーナルに記録され、一時停止・再開機能や署名付きの進捗レポートが利用可能です。[履歴ガイド](https://phishdestroy.github.io/TgWitness/ja/docs/reference/history/)。 |
| ジャーナル内の既存のチャット履歴 | ソース → 記録設定 → 履歴スナップショット | 最近のメッセージを署名付き記録として保存します。既定は 500 件、**パラメータ → 最大履歴スナップショット**で最大 10,000 件。 |
| 1つのチャットにおける、現在表示されている履歴のすべて | チャット全体のエクスポート → チャット全体をエクスポート、または チャット → チャットをエクスポート | `chat.json` と `chat.html` を含む別の署名付きバンドルを、チャットごとに 1 つ作ります。 |
| 新しいチャットが表示された際の状況 | 監視範囲 → 新しいチャットやボットが出現したとき | プロフィールと最大 1,000 件の最近のメッセージ（調査モードでは 200 件）。既存のチャットには適用されません。 |
| 添付ファイルのバイト数 | 表示可能な添付ファイルのダウンロード + ファイル種別ごとの制限 | SHA-256 とサイズ付きの `media.saved` を探してください。キュー待ち、スキップ、失敗は保存されていないという意味です。 |

チャットのエクスポートは、ジャーナルや人物プロフィールには入りません。TgWitness 内で古い履歴を検索するには、**全履歴を読み込む**かスナップショットを使ってください。

ここでは：チャンネル、グループ、ボットとのチャット、個人チャット、それに請求書ファイルとそのハッシュ。記録開始前に削除されたものは失われています。

## 3. 展開する会話と自身の行動を記録する

動かし続けてください。注目のチャットにはスターを付けて優先し、**記録設定 → 再確認**で再確認を調整し、`recheck.completed`、FloodWait、メディアの結果に注意します。

**チャット → プロフィール → プロフィールを今すぐ保存**で、チャットの説明、ボットのコマンド、その他のメタデータを保存します。

**事件調査の一環として、ボットをフォローするか、招待を受け入れること**

1. **チャット → Telegram リンクを開く**では、まずプレビューを保存します。リンクとプレビューは署名付き記録になります。
2. 必要なら、**参加 / 開いて観察**でチャットに参加するか、開始パラメータ付きでボットを起動します。
3. 操作を記録に残すには、パネルから返信するか**ボタンを押す**を使います。`interaction.requested` と `interaction.result` が、ボットの応答と一緒に記録されます。

これらは実際の操作です。別のアプリで押したボタンは見えず、見えるのはボットの返信だけです。Web アプリ、支払い、電話番号/位置情報は対象外です。

## 4. チャット間の人物、リンク、ファイルを追跡する

1. **ジャーナル**、**すべてのソース**で、フレーズ、ドメイン、ユーザー名を検索します。ヒットを開いて**ボードへ**送ります。
2. **チャット → ユーザー → プロフィールを表示**で人物を選びます：名前の履歴、返信、アクティビティ、**関連項目…**、リンク、ウォレット、電話番号。引用された記録を開きます。
3. 同じ数値のユーザー ID を他のチャットでも追います。名前、ウォレット、アバターの一致は手がかりであって、証拠ではありません。
4. ファイルのハッシュを比べます。SHA-256 が同じ = バイトが同じ。誰が共有したかは別の問題です。

ケースマップ / 参照先を追跡する架空の事例・実際のグラフではありません

チャンネル / お知らせ**原文 → 編集後の翻訳文**

記録 #101、#188 メッセージ #84 · 送信者不明

グループ / 運用**ユーザー71001が新しいリンクを投稿しました**

記録 #146 · メッセージ #309 保存済みファイル受領確認 #151

BOT / 注文に関する会話**そのリンク先へ移動するボタンがあります**

記録 #173 · メッセージ #12 「戻る」ボタンのメタデータ

非公開 / フォローアップ**ユーザー71001が宛先を繰り返し入力しています**

4つのチャットから、それぞれ異なる観察結果が得られています。すべての接続についてソース記録を追跡してください。チャンネルの投稿には送信者の情報が記載されていません。

数値 ID およびレコード参照番号は、この手順説明のために架空のものであり、実際のものとは異なります。この説明図は、検索結果、プロフィール、および調査済みレコードをどのように関連付けるかを示しています。「Case Board」には、対応するカードとソース参照が保存されます。

| 接続 | 補足情報 | 維持すべき結論 |
| --- | --- | --- |
| 同じTelegramアカウント | グループ #146 およびプライベートチャット #205 のユーザー ID 71001 | 両方のチャットで送信者 ID が同じです。それが現実の誰なのかは別の問題です。 |
| 繰り返し先 | #146の`pay.example.invalid/new`、ボタンのメタデータ #173、編集された投稿 #188 および #205 | 同じリンクが 4 か所にあります。誰が管理しているかは他のソースが必要です。 |
| 同じファイルのバイト数 | 完了したメディア受信記録 #151 および #209 における SHA-256 値が完全に一致しています。 | 2 つのファイルはバイト単位で同一です。 |

プロフィールの対象は*このワークスペース*で何かを書いた人だけで、メンバー一覧ではありません。事実ごとの引用数：**パラメータ → 事実ごとの引用記録数**。

## 5. 時系列を再構築し、欠落部分を明記する

**チャット**で版を確認し、次に**ジャーナル**で**すべてのソース** + **編集**、**削除**、**カバレッジ**を選びます。時系列には 2 つの時刻を書きます：Telegram の日付と、観察された時刻です。

1. 09:00 · #101**キャプチャされたチャンネルの投稿**

   元のリンク先はそのまま維持されています。
2. 09:12 · #146 / #151**グループが別のリンクを紹介しています**

   ユーザー71001が投稿し、添付ファイルのダウンロードが完了しました。
3. 09:16 · #173**ボットは同じ宛先を表示します**

   保存されたキーボードのメタデータには、そのリンクが含まれています。
4. 09:20 · #188**チャンネルの告知の変更点**

   元の記録と編集後の記録の両方が残されます。
5. 09:24 · #205 / #209**非公開のフォローアップでも同様の内容が繰り返されています**

   保存された添付ファイルのSHA-256ハッシュ値は、#151と同じです。
6. 09:28 · #231**グループ削除の通知が届きました**

   以前の指摘は依然として当てはまります。削除者や正確な削除時刻は提供されていません。

観察時間や参照情報の例を示しています。これらのエントリの間には、その他のジャーナル記録が存在します。

ジャーナルの順序は届いた順で、起きた順とは限りません。ライブの記録、スナップショット、復元したメッセージ、削除、「再確認で見つからない」は分けておき、欠落はすべて不明として印を付けてください。

## 6. 他の収集用アカウントにも適用する

アカウントごとに 1 つのワークスペースで、同じ手順です。それぞれの役割とフィンガープリントを控えます。メッセージ番号はアカウントごとなので、必ずワークスペースとチャットを明記してください。

[アカウントグループ](https://phishdestroy.github.io/TgWitness/ja/docs/groups/)は状態を表示し、設定を共有し、全員をまとめてエクスポートします。それぞれが自分のジャーナルと鍵を持ちます。アカウントをまたぐ時系列は、メモの中で自分で組み立てます。

長いケースですか？[独立した証人](https://phishdestroy.github.io/TgWitness/ja/docs/witness/)を加え、各アカウントが実際に何を記録しているかを試してください。

## 7. 検証可能なケースパッケージの提出

各ワークスペースの署名付き ZIP（常にジャーナル全体で、フィルターは関係しません）、それに人物プロフィール、チャットエクスポート、ファイル。

```
CASE-001/                         # assembled by the analyst
  case-notes.md                   # question, findings, alternative explanations
  sources.csv                     # every chat, role, acquisition result and gap
  timeline.csv                    # account + chat + message + seq + both times
  workspace-A/
    evidence.zip                  # complete signed observation journal
    retained-checkpoint.json
    profiles-operations.json      # separately signed people profiles
    history-channel.zip           # signed current-history export
    history-group.zip
    verification.txt
  workspace-B/                    # separate journal and trusted fingerprint
  witness/                        # retained checks, journal and signed posts
  SHA256SUMS                      # hashes of the delivered files
```

フィンガープリントは別経路で送ります。それぞれを自分のワークスペースと照合して検証します：

```
python -m tgwitness.verify evidence.zip --fingerprint TRUSTED_PUBLIC_KEY_SHA256 --checkpoint retained-checkpoint.json
python -m tgwitness.verify profiles-operations.json --fingerprint TRUSTED_PUBLIC_KEY_SHA256 --evidence evidence.zip
python -m tgwitness.verify history-channel.zip --fingerprint TRUSTED_PUBLIC_KEY_SHA256
```

検証ツールの出力、原本、カバレッジ、引き渡しの記録を調査結果と一緒に保管します。まとめは Report studio で書きます。相手に必要な量が少なければ、[最小化した引き渡し](https://phishdestroy.github.io/TgWitness/ja/docs/handover/)を作ってください。
