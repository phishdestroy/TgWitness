# รักษาความปลอดภัย

Canonical page: https://phishdestroy.github.io/TgWitness/th/docs/security/

อะไรออกจากเครื่องของคุณ ความลับแต่ละอย่างเปิดอะไรได้ และการป้องกันครอบคลุมอะไรเทียบกับสิ่งที่เป็นความรับผิดชอบของคุณ

**256 บิต**token แผงสุ่ม

**0**CDN, ระบบวิเคราะห์ข้อมูล หรือฟอนต์จากระยะไกล

**Ed25519**ลายเซ็นบนทุกบันทึก

## ที่เก็บรวบรวมทุกสิ่ง

เครื่องเก็บข้อมูล แผงควบคุม และทุกรายการอยู่บนเครื่องของคุณ โดยค่าเริ่มต้นติดต่อเฉพาะ Telegram อย่างอื่นทั้งหมดเป็นสวิตช์แยก

06 / สิ่งที่เครื่องทิ้งไว้การติดตั้งของคุณ

คอมพิวเตอร์หรือเซิร์ฟเวอร์ของคุณ

**Panel**127.0.0.1:8787 · โทเค็น bearer

**Collector**ใช้ Telegram client หนึ่งตัวต่อพื้นที่ทำงาน

ไดเรกทอรีข้อมูล

**บันทึก**SQLite · เชื่อมต่อด้วยแฮช · ลงนาม

**สื่อ**ไฟล์ที่มีชื่อตาม SHA-256

**Vault**Fernet · session, คู่ API, กุญแจลงนาม, proxy

- **Telegram**เสมอ · ผ่านเส้นทางของคุณ

  การเชื่อมต่อ MTProto ของบัญชี: แบบตรง, SOCKS5, HTTP หรือ MTProxy โหมดซ่อน IP จะรอจนกว่าจะมีพร็อกซีที่ทำงานได้ ส่วนการเปลี่ยนไปใช้การเชื่อมต่อแบบตรง (Direct fallback) ต้องใช้โหมดที่อนุญาตอย่างชัดเจน
- **เนื้อหาบนเว็บไซต์อื่น**เลือกได้ · ปิดตามค่าเริ่มต้น

  บันทึก ไฟล์ และจุดตรวจสอบถูกเข้ารหัสด้วย AES-GCM ก่อนอัปโหลดไปยังพื้นที่จัดเก็บข้อมูลที่รองรับ S3 กุญแจจะอยู่กับคุณเสมอ; ไฟล์แนบถูกตั้งชื่อด้วยแฮชที่มีกุญแจ ไม่ใช่แฮชของเนื้อหา
- **การแจ้งเตือน**เลือกได้ · ปิดตามค่าเริ่มต้น

  แสดงปัญหาและจำนวนการเปลี่ยนแปลงพร้อมชื่อหัวข้อการสนทนา ส่วนข้อความตัวอย่างจะถูกส่งไปเพียงเมื่อคุณเปิดฟังก์ชันนี้ไว้
- **ความน่าเชื่อถือของเวลา**เลือกได้ · ปิดตามค่าเริ่มต้น

  มีเพียง SHA-256 ของจุดตรวจสอบที่ลงนามและ nonce แบบสุ่มเท่านั้น ไม่มีข้อความหรือชื่อผู้สนทนา
- **Witness**เลือกได้ · ปิดตามค่าเริ่มต้น

  ดึงจุดตรวจสอบที่ลงนามและตัวนับการบันทึกด้วยโทเค็นแบบอ่านอย่างเดียว ไม่สามารถอ่านการสนทนาหรือเปลี่ยนแปลงการตั้งค่าได้

ค่าเริ่มต้น: มีเพียงการเชื่อมต่อ Telegram เท่านั้นที่ออกจากเครื่องนี้

จุดหมายปลายทางที่เลือกได้จะถูกกำหนดตามพื้นที่ทำงาน ข้อความและสื่อในข้อความจะถูกเก็บไว้ในไดเรกทอรีข้อมูลโดยไม่เข้ารหัส: โปรดปกป้องข้อมูลด้วยระบบเข้ารหัสดิสก์และสิทธิ์การเข้าถึงไฟล์

## สิ่งที่ความลับแต่ละข้อเปิดเผย

| ลับ | สถานที่จัดเก็บ | ประโยชน์ที่ได้รับ | หากข้อมูลรั่วไหล |
| --- | --- | --- | --- |
| **โทเค็นของแผง** | `panel-token.txt` ในไดเรกทอรีข้อมูล เบราว์เซอร์เก็บไว้ต่อแท็บ | ทุกอย่างในทุกพื้นที่ทำงาน | หยุด TgWitness ลบ `panel-token.txt` เริ่มใหม่: คุณจะได้โทเค็นใหม่ |
| **เซสชัน Telegram** | Vault, เข้ารหัส (`credentials.enc`) | บัญชี Telegram เอง | ปิดเซสชันใน Telegram โดยไปที่ *การตั้งค่า → อุปกรณ์* |
| **กุญแจการลงนาม** | Vault, เข้ารหัส (`signing.enc`) | การลงนามรายการภายใต้ลายนิ้วมือของคุณ | checkpoint ที่เก็บไว้ที่อื่น พยาน และการประทับเวลายังแสดงสิ่งที่มีอยู่ก่อนหน้า |
| **กุญแจ Vault** | `vault.key` ข้างข้อมูล หรือคีย์หลักภายนอก | ห้องนิรภัย | ให้ถือว่าเซสชันและคีย์ลงนามรั่วไหลด้วย |
| **โทเค็น Witness** | บนเซิร์ฟเวอร์ของ TgWitness | อ่านอย่างเดียว: checkpoint และสถานะ | ลบในหน้าพยาน แล้วสร้างใหม่ |
| **ข้อความหลักสำหรับใช้ภายนอกเว็บไซต์** | Vault; ดาวน์โหลดเพียงครั้งเดียวเพื่อกู้คืนข้อมูล | สำเนานอกสถานที่ | ใครก็ตามที่มี bucket ด้วยจะถอดรหัสได้: ให้ถือว่าสำเนาถูกเปิดเผย |

## สิ่งที่การคุ้มครองครอบคลุม

### ได้รับการครอบคลุม

- รายการที่ถูกเปลี่ยน ลบ หรือเรียงใหม่: สายแฮชหรือลายเซ็นจะขาด
- บันทึกที่ถูกตัดหรือสร้างใหม่หลังจากคุณเก็บ checkpoint ไว้ที่อื่น: checkpoint จะไม่ตรงกันอีก
- การเดาโทเค็น: สุ่ม 256 บิต เปรียบเทียบแบบเวลาคงที่ ล้มเหลว 15 ครั้งต่อนาทีที่อยู่นั้นจะถูกบล็อก
- เนื้อหาแชทที่เป็นอันตราย: ข้อความยังคงเป็นข้อความ ไม่เคยเป็น HTML ไฟล์แนบดาวน์โหลดเป็นไฟล์ แผงควบคุมไม่โหลดอะไรจากเว็บไซต์อื่น
- ไดเรกทอรีข้อมูลที่ถูกขโมยโดยใช้คีย์ห้องนิรภัยภายนอก: เซสชันและคีย์ยังคงเข้ารหัส

### ขึ้นอยู่กับคุณ

- โทเค็นหลักทำได้ทุกอย่าง ให้สิทธิ์แบบจำกัดขอบเขตแก่ผู้อื่นและเก็บโทเค็นหลักไว้กับตัวเอง
- ใครก็ตามที่เป็นผู้ดูแลเครื่องอ่านได้ทุกอย่างและลงนามบันทึกใหม่ได้ เก็บลายนิ้วมือและ checkpoint ไว้ที่อื่น
- TgWitness ไม่เข้ารหัสข้อความและสื่อ เข้ารหัสดิสก์ และจำกัดสิทธิ์ให้แน่นหนา
- HTTP ธรรมดานอก localhost ทำให้โทเค็นรั่ว ใช้ HTTPS หรือ SSH tunnel
- ลายเซ็นไม่บอกว่าพลาดอะไรไป ตรวจความครอบคลุมและทดสอบการส่งถึงบนบัญชีและแหล่งข้อมูลของคุณเอง

[แชร์สิทธิ์เข้าถึงคดี](https://phishdestroy.github.io/TgWitness/th/docs/access/) พร้อมสิทธิ์ วันหมดอายุ และขีดจำกัดเซสชัน

## เสริมความปลอดภัยให้ระบบติดตั้ง

เสร็จแล้ว 0 จาก 8

1. **ใช้บัญชี Telegram เฉพาะ** อย่าใช้บัญชีหลักเด็ดขาด
2. **ให้แผงควบคุมอยู่ที่ 127.0.0.1** การเข้าถึงระยะไกลผ่าน HTTPS (Caddy ที่มาพร้อมกัน) หรือ SSH tunnel เท่านั้น
3. **เข้ารหัสดิสก์** ที่มีไดเรกทอรีข้อมูล ข้อความและสื่อถูกเก็บตามสภาพ
4. **จำกัดไดเรกทอรีข้อมูล** ให้บัญชีบริการเท่านั้น (0700 บน Unix สิทธิ์โฟลเดอร์บน Windows)
5. **เก็บคีย์ห้องนิรภัยไว้ที่อื่น** บนเซิร์ฟเวอร์: ตั้ง `TGWITNESS_VAULT_KEY_FILE` ก่อนเริ่มครั้งแรก
6. **บันทึกลายนิ้วมือและ checkpoint** ไว้บนระบบอื่น และรันพยานบนโฮสต์อื่น
7. **ห้ามอัปโหลด**กุญแจ`data/`, กุญแจเซสชัน, `panel-token.txt` หรือกุญแจ vault ไปยัง GitHub หรือในห้องแชท
8. **อย่าบันทึก**ส่วนหัว`Authorization` หรือเนื้อหาคำขอที่พร็อกซีแบบย้อนกลับ

**สามารถเปลี่ยนโทเค็นของแผงควบคุมได้โดยไม่สูญเสียข้อมูลหรือไม่?**

ได้ มันเปิดได้แค่แผงควบคุม หยุด TgWitness ลบ `panel-token.txt` แล้วเริ่มใหม่ บันทึก เซสชัน และคีย์ยังอยู่ หากตั้ง `TGWITNESS_TOKEN` ไว้ ค่านั้นจะมีผลเหนือไฟล์

**ทำไมข้อความจึงไม่ได้รับการเข้ารหัสเมื่ออยู่ในระบบ?**

เครื่องเก็บข้อมูลต้องอ่านข้อมูลเหล่านี้เพื่อค้นหา เปรียบเทียบ และส่งออก คีย์บนเครื่องเดียวกันไม่ได้หยุดคนที่อ่านเครื่องนั้นได้อยู่แล้ว การเข้ารหัสดิสก์ป้องกันดิสก์ที่ถูกขโมย สิทธิ์ป้องกันระบบที่กำลังทำงาน

## รายงานช่องโหว่

**Security → Report a vulnerability** บน GitHub ระบุเวอร์ชัน ผลกระทบ และขั้นตอนจำลองขั้นต่ำด้วยข้อมูลสมมติ อย่าส่งข้อมูลรับรอง โฟลเดอร์บัญชี หรือหลักฐานจริง หากปิดการรายงานแบบส่วนตัว ให้เปิด issue เพื่อขอช่องทางส่วนตัว โดยไม่ใส่รายละเอียดการโจมตี
